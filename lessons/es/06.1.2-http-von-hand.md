# HTTP a mano

:::sim

:::

Si HTTP es texto plano, ¿se puede hablar también uno mismo con un servidor web, sin ningún navegador? Sí: con `telnet` estableces una conexión TCP con cualquier puerto y escribes tú mismo el texto.

## El experimento

1. Cambia al modo de ejecución :fa-play: **Ejecutar** y abre la :fa-terminal: **Terminal** en el **Client-PC**.
2. Conéctate al puerto 80 del servidor:
   ```
   $ telnet 192.168.0.20 80
   ```
3. Escribe la solicitud línea por línea y termínala con una **línea vacía** (simplemente pulsa **Enter** una vez más):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

El servidor responde con la línea de estado, las cabeceras y la página de contacto, como texto, igual que la recibe el navegador.

:::quiz mc
¿Cómo sabe el servidor que tu solicitud ha terminado?
- [ ] Por un comando especial `END`
- [x] Por la línea vacía
- [ ] Después de un tiempo determinado
:::

:::quiz short
¿Qué valor aparece en la respuesta en la cabecera `Content-Type`? (solo la primera parte, antes del `;`)
= text/html
:::

:::evaluate
Comprobar respuestas
:::

## Provocar errores

Una herramienta más cómoda es `curl`: realiza la solicitud por ti. Con `-v` (*verbose*, detallado) muestra todo lo que se envía y se recibe: las líneas con `>` las ha enviado `curl`, las líneas con `<` proceden del servidor.

Pruébalo:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
¿Qué código de estado obtienes para `/gibtsnicht.html`?
= 404
:::

:::quiz short
¿Y cuál para la solicitud con el método `POST`?
= 405
:::

:::evaluate
Comprobar respuestas
:::

:::note
El servidor web de BeaverTracer solo puede entregar archivos, por eso solo permite `GET` y `HEAD`. Los servidores web reales aceptan con `POST`, por ejemplo, formularios y pasan los datos a un programa.
:::

:::tip Recuerda
Muchos protocolos de la capa de aplicación están **basados en texto**: HTTP, pero también SMTP, POP3 e IMAP. Por eso se pueden «hablar» a mano con `telnet` y leer en el Tracer. Esto es práctico para la resolución de problemas, pero también supone un problema de seguridad: cualquiera que capture el tráfico puede leerlo todo. En el capítulo 8 aprenderás cómo ayuda el cifrado (HTTPS).
:::
