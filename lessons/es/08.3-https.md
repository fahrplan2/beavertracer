# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) es HTTP completamente normal, solo que no funciona directamente sobre TCP, sino a través de una capa cifrada intermedia: **TLS** (*Transport Layer Security*). El predecesor de TLS se llamaba **SSL**; por eso todavía se habla a menudo de «certificados SSL».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP no se entera de nada: envía sus solicitudes como siempre, TLS las cifra y TCP las transporta. En el modelo OSI, TLS se sitúa entre la capa de transporte y la capa de aplicación, es decir, en la capa 4/5: se apoya en TCP y gestiona una sesión segura.

| | HTTP | HTTPS |
|---|---|---|
| Puerto | 80 | **443** |
| Dirección | `http://…` | `https://…` |
| ¿Contenido legible en el Tracer? | sí | no |
| El navegador muestra | «no seguro» | candado |

TLS se encarga durante el establecimiento de conexión de todo lo que has aprendido en este capítulo:

- El servidor se identifica con su **certificado** (**autenticidad**).
- Ambas partes negocian con **Diffie-Hellman** una **clave de sesión**; el servidor **firma** su parte.
- Después, todos los datos se cifran con **AES** (**confidencialidad**) y se protegen frente a modificaciones (**integridad**).

El principio no se limita a la web: también el correo electrónico (sección 8.4) y muchos otros protocolos funcionan de la misma manera a través de TLS.
