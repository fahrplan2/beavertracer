Al switch están conectados un **Servidor DHCP** y dos portátiles. Los portátiles todavía tienen direcciones fijas.

## El experimento

1. Cambia al modo de ejecución :fa-play: **Ejecutar**, haz clic en **Laptop 1** y abre la :fa-gear: **Configuración IP**.
2. Cambia el **Modo** de **Estático** a **DHCP** y haz clic en **Aplicar**.
3. Espera unos segundos: los campos se rellenan solos.
4. En el modo :fa-magnifying-glass: **Rastreo**, abre un trace para **Laptop 1**.

| Gateway | {192.168.0.1} |

## Qué hay detrás: DORA

Un dispositivo sin dirección no sabe dónde está el servidor DHCP y tampoco tiene una dirección de remitente propia. Por eso llama a la red mediante **broadcast**. El proceso tiene cuatro pasos, llamado **DORA** por sus letras iniciales:

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | „¿Hay aquí algún servidor DHCP?“
DHCP-Server -> Laptop 1: DHCP Offer | „Puedes quedarte con 192.168.0.100.“
Laptop 1 -> DHCP-Server: DHCP Request | „Me quedo con 192.168.0.100.“
DHCP-Server -> Laptop 1: DHCP ACK | „Confirmado — válido durante 3600 segundos.“
:::

La dirección solo se **presta** (*lease*): al terminar el **tiempo de concesión** (*lease time*), el dispositivo debe renovarla; de lo contrario, el servidor puede asignarla de nuevo. Las direcciones que están prestadas en este momento las ves en el **Servidor DHCP**, en la pestaña **Leases**.

:::tip Pruébalo
Configura también **Laptop 2** con DHCP. ¿Qué dirección obtiene? Después mira los **Leases** del servidor DHCP.
:::

:::tip Recuerda
**DHCP** reparte automáticamente la dirección IP, la máscara de red, el gateway y el servidor DNS. El proceso se llama **DORA**: **D**iscover (el cliente busca mediante broadcast), **O**ffer (el servidor ofrece), **R**equest (el cliente acepta), **A**CK (el servidor confirma). La dirección se presta durante el **tiempo de concesión**. DHCP utiliza **UDP**, puerto 67 (servidor) y 68 (cliente).
:::

:::quiz match
Discover -> El cliente busca un servidor DHCP mediante broadcast
Offer -> El servidor ofrece una dirección
Request -> El cliente solicita la dirección ofrecida
ACK -> El servidor confirma la asignación
:::
