# Resolución de problemas: falta la página de contacto

:::sim
url=/sims/lesson-6.1.3.btsim
:::

La secretaría informa: «En nuestra página web, el enlace **Kontakt** solo lleva a un mensaje de error». La página de contacto debería estar disponible en `http://192.168.0.20/kontakt.html`. Encuentra el error y corrígelo.

<details>
<summary>Pista 1: ¿Qué informa el servidor?</summary>

Abre la página de contacto en el navegador o con `curl -v`. ¿Qué código de estado devuelve? La página de error también revela dónde buscó el servidor el archivo.
</details>

<details>
<summary>Pista 2: ¿Dónde están los archivos?</summary>

El servidor web solo entrega archivos de su **Raíz de Documentos** (*Document Root*); esto aparece en la aplicación **Servidor HTTP**. En el **Server**, mira con `ls` en la terminal qué hay allí y busca también la página de contacto en `/home`.
</details>

<details>
<summary>Pista 3: Mover el archivo</summary>

Con `mv` mueves un archivo: `mv <origen> <carpeta de destino>`.
</details>

:::task
title: ¿Página de contacto reparada?
Comprueba si la página de contacto está en la Raíz de Documentos del servidor web.
check: fileExists(2, "/var/www/kontakt.html")
:::

## ¿Qué pasaba?

:::quiz multi
¿Qué afirmaciones son correctas?
- [x] El servidor respondió con `404 Not Found`
- [x] El archivo estaba en `/home` en lugar de en la Raíz de Documentos `/var/www`
- [ ] El servidor web no estaba iniciado
- [ ] El navegador usó la dirección IP equivocada
:::

:::evaluate
Comprobar respuesta
:::

:::tip Recuerda
Un **404** significa: el servidor web está en funcionamiento y es accesible, pero el **archivo** solicitado no existe en esa ruta. El servidor solo busca en su **Raíz de Documentos** (*Document Root*, aquí `/var/www`). Compara: si el servidor no responde en absoluto o responde con `RST`, el problema es más profundo: está en la red o en el propio servicio (capítulo 5.3.2).
:::
