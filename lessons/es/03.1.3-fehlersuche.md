# Resolución de problemas en la red con switch

:::sim
url=/sims/lesson-3.1.3.btsim
:::

Desde que **David** se ha incorporado a la red, hay problemas: Clara no es accesible para nadie y algo no funciona bien con Ben. Como profesional de redes, tienes que arreglarlo.

## El plano de red

Así *debería* ser la red:

| Dispositivo | Dirección IP | Puerto del switch |
|---|---|---|
| Anna | `192.168.0.10/24` | 1 |
| Ben | `192.168.0.11/24` | 2 |
| Clara | `192.168.0.12/24` | 3 |
| David | `192.168.0.13/24` | 4 |

Compara el plano con la simulación: ¿qué es diferente? Corrige todos los errores que encuentres.

<details>
<summary>Pista 1: ¿Por dónde empiezo?</summary>

Mira primero los cables: ¿está cada PC conectado al puerto correcto? Después comprueba la configuración IP de cada PC.
</details>

<details>
<summary>Pista 2: Ben sí responde a los ping …?</summary>

Haz ping a Ben desde Anna (`ping 192.168.0.11`) y abre un trace para Anna. Fíjate bien en las respuestas ARP: ¿cuántas hay y con qué direcciones MAC?
</details>

:::task
title: ¿Red reparada?
Comprueba si todos los dispositivos tienen las direcciones del plano de red y si se pueden alcanzar entre sí. Para ello, la simulación debe estar en modo de ejecución.
check: ip(3, "192.168.0.10/32")
check: ip(5, "192.168.0.11/32")
check: ip(7, "192.168.0.12/32")
check: ip(11, "192.168.0.13/32")
check: pingOk(3, 7)
check: pingOk(3, 11)
check: pingOk(5, 7)
:::

## ¿Qué pasaba?

- [ ] El ping siempre falla
- [x] A una solicitud ARP llegan dos respuestas con direcciones MAC diferentes
- [ ] El switch muestra un mensaje de error

:::evaluate
Comprobar respuesta

:::tip Recuerda
En la **resolución de problemas** comparas el **estado deseado** (plano de red) con el **estado real** (cables, configuración, Tracer). Cuidado: un ping correcto no significa automáticamente que todo esté bien; con una dirección IP duplicada, quizá simplemente responda el dispositivo equivocado.
:::
