# Resolución de problemas: el nombre no funciona

:::sim
url=/sims/lesson-6.2.3.btsim
:::

Una profesora informa: «`www.beaver-schule.de` no me carga. ¡Pero con `http://192.168.0.20` sí funciona!». Así *debería* estar configurado:

| Qué | Debería ser |
|---|---|
| Servidor DNS en el Client-PC | `192.168.0.53` (DNS-Resolver) |
| Entrada en el Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Encuentra los errores y corrígelos.

<details>
<summary>Pista 1: ¿Qué dice nslookup?</summary>

Introduce `nslookup www.beaver-schule.de` en el Client-PC. ¿A qué servidor preguntó `nslookup` y qué respondió? (La respuesta tarda unos segundos.)
</details>

<details>
<summary>Pista 2: ¿Y ahora qué?</summary>

Si obtienes una respuesta, compara la dirección con el plano. ¿Dónde está registrado este nombre?
</details>

:::task
title: ¿Resolución de nombres reparada?
Comprueba si el Client-PC resuelve www.beaver-schule.de a la dirección correcta. Para ello, la simulación debe estar en modo de ejecución.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## ¿Qué pasaba?

:::quiz multi
¿Qué afirmaciones son correctas?
- [x] En el Client-PC estaba configurado `192.168.0.35` como servidor DNS: allí no responde nadie
- [x] En el Schul-DNS, `www.beaver-schule.de` apuntaba a `192.168.0.21` en lugar de a `192.168.0.20`
- [ ] El servidor web estaba apagado
- [ ] El servidor raíz no conocía el dominio `.de`
:::

:::evaluate
Comprobar respuesta
:::

:::tip Recuerda
Si una conexión funciona con la **dirección IP**, pero no con el **nombre**, el problema está en el **DNS**. Comprueba primero el **servidor DNS configurado** (¿responde siquiera?) y después la **entrada** en sí (¿es correcta la dirección?). `nslookup` muestra ambas cosas: a qué servidor se preguntó y qué respondió.
:::
