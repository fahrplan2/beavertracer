# El diagrama de secuencia

:::sim
url=/sims/lesson-5.1.btsim
:::

El desarrollo de una conexión se dibuja como un **diagrama de secuencia**: el cliente y el servidor tienen cada uno una línea vertical, y el tiempo corre de arriba hacia abajo. Cada flecha es un paquete. Está dibujada en diagonal porque cada paquete tarda un poco en llegar.

Así se ve tu conexión de la página anterior — compárala línea por línea con el trace:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Encima de cada flecha están los **flags**, debajo los números `SEQ` y `ACK`. **DATA** marca los paquetes con datos útiles. Los números rojos pertenecen al cliente, los azules al servidor — qué significan se explica en la página siguiente.

## Los flags

| Flag | significa | Significado |
|---|---|---|
| **SYN** | *synchronize* | establecer la conexión, fijar el número inicial |
| **ACK** | *acknowledge* | confirma los datos recibidos |
| **PSH** | *push* | entregar los datos de inmediato al programa |
| **FIN** | *finish* | «He terminado» — cerrar la conexión |
| **RST** | *reset* | interrumpir o rechazar la conexión (más sobre esto en 5.3.2) |

## Tres fases

**Establecimiento:** el cliente envía `SYN`, el servidor responde con `SYN, ACK` y el cliente confirma con `ACK`. Como se necesitan exactamente tres paquetes, se llama **acuerdo de tres vías** (*three-way handshake*).

**Datos:** el destinatario confirma con un `ACK` cada paquete que contiene datos. Aquí el servidor devuelve el eco — y el cliente también lo confirma.

**Cierre:** cada lado termina su sentido de envío por separado: `FIN` del cliente, `ACK` del servidor — después `FIN` del servidor, `ACK` del cliente. Son cuatro paquetes.

:::tip Recuerda
Una conexión TCP transcurre en tres fases: **establecimiento** con el **acuerdo de tres vías** (`SYN` → `SYN, ACK` → `ACK`), **transferencia de datos** (cada paquete de datos se confirma con `ACK`) y **cierre** (cada lado envía `FIN` y recibe un `ACK`).
:::
