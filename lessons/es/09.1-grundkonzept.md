# Filtro de paquetes: reglas

El tipo de firewall más sencillo e importante es el **filtro de paquetes**. Examina cada paquete que pasa por él y decide, según una **lista de reglas**, si puede continuar. Para ello solo lee las cabeceras de las capas 3 y 4; el contenido (por ejemplo, la página web) no lo examina.

## De qué se compone una regla

| Campo | Significado | Ejemplo |
|---|---|---|
| **Dirección** | ¿De qué lado viene el paquete? | A → B (desde Internet hacia la red del colegio) |
| **Protocolo** | TCP, UDP, ICMP o cualquiera | TCP |
| **IP de origen** | Dirección o red del remitente | cualquiera |
| **Puerto de origen** | Puerto del remitente | cualquiera |
| **IP de destino** | Dirección o red del destinatario | `198.51.100.10` |
| **Puerto de destino** | Puerto del destinatario, es decir, el servicio | `80` |
| **Acción** | ¿Qué ocurre con los paquetes que coinciden? | Permitir |

Un campo vacío significa «cualquiera». Las redes se escriben en notación CIDR, como `198.51.100.0/24`, y los rangos de puertos con guion, como `1024-65535`.

## El orden es decisivo

El firewall comprueba las reglas **de arriba abajo**. Decide la **primera regla que coincide**; las siguientes ya no se miran para ese paquete. Si no coincide ninguna regla, se aplica la **política predeterminada** (*Default Policy*).

## Tres acciones posibles

| Acción | Qué hace el firewall | Qué percibe el remitente |
|---|---|---|
| **Permitir** (*Allow*) | El paquete se reenvía | — |
| **Descartar** (*Drop*) | El paquete se tira sin avisar | nada en absoluto: espera hasta que vence un timeout |
| **Rechazar** (*Reject*) | El paquete se tira y el remitente recibe una negativa: en TCP un **RST**, en otros casos un ICMP «destino inalcanzable» | un mensaje de error inmediato |

¿Qué es mejor? **Descartar** revela menos información a un atacante y le hace perder tiempo, porque tiene que esperar en cada intento. **Rechazar** es más amable con los propios usuarios: un programa recibe un mensaje de error de inmediato en lugar de quedarse colgado mucho tiempo. En la práctica, por eso se suelen descartar los paquetes que vienen de fuera y se rechazan los paquetes de la propia red.

:::quiz match
Permitir -> El paquete se reenvía
Descartar -> El paquete desaparece, el remitente espera en vano una respuesta
Rechazar -> El paquete no se reenvía, pero el remitente recibe de inmediato una negativa
Política predeterminada -> Se aplica cuando no coincide ninguna regla
:::

:::tip Recuerda
Un **filtro de paquetes** comprueba cada paquete frente a una **lista de reglas** según la dirección, el protocolo, las direcciones y los puertos. La **primera regla que coincide** decide la acción: **Permitir**, **Descartar** (en silencio) o **Rechazar** (con negativa). Si no coincide ninguna regla, se aplica la **política predeterminada**.
:::
