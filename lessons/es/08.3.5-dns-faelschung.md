# Ataque: falsificación de DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna quiere abrir su banca en línea de la **Biberbank** en el **Client-PC**. Lo que ella no sabe: alguien ha conseguido acceso al **DNS-Server** y ha modificado una entrada.

En el área de trabajo ves el servidor web real **www.biberbank.de** y el equipo de un **atacante**. En él se ejecuta una copia de la página web del banco.

## Parte 1: sin cifrado

Cambia al modo de ejecución :fa-play: **Ejecutar** y abre `http://www.biberbank.de/` en el :fa-globe: **Navegador** del **Client-PC**.

:::quiz mc
¿Qué ves?
- [x] La página de inicio de sesión de la Biberbank, sin ninguna advertencia
- [ ] Una advertencia de que la página es falsa
- [ ] Un mensaje de error
:::

:::evaluate
Verificar respuesta
:::

Todo parece normal. Pero ¿con qué servidor habla realmente el navegador? Abre el :fa-terminal: **Terminal** en el Client-PC:

```
$ nslookup www.biberbank.de
```

:::quiz short
¿Qué dirección IP devuelve el servidor DNS para `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
¿A quién pertenece esta dirección? (En el modo de edición, haz clic en los dispositivos o consulta su :fa-gear: **Configuración IP**.)
- [ ] Al servidor web real de la Biberbank
- [x] Al atacante
- [ ] Al servidor DNS
:::

:::evaluate
Verificar respuestas
:::

Si Anna hubiera introducido ahora su número de cuenta y su PIN, habrían ido a parar directamente al atacante. Con **HTTP** no tiene **ninguna posibilidad** de darse cuenta del fraude: la barra de direcciones muestra el nombre correcto y la página parece auténtica.

## Parte 2: con HTTPS

Ahora abre `https://www.biberbank.de/`.

:::quiz mc
¿Qué ocurre?
- [ ] Aparece la página falsa con un candado
- [x] El navegador advierte: el certificado se emitió para otro nombre
- [ ] Aparece la página real de la Biberbank
:::

:::quiz short
¿Para qué nombre está emitido el certificado del atacante (sin `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Verificar respuestas
:::

El atacante tiene incluso un certificado **auténtico** de una CA de confianza, pero para su propio dominio `www.biber-gewinnspiel.de`. Ninguna CA le dará un certificado para `www.biberbank.de`, porque ese dominio no le pertenece. Y sin la **clave privada** de la Biberbank tampoco puede usar el certificado real de esta: en el handshake tendría que firmar con ella el Server Key Exchange.

:::quiz multi
¿De qué protege HTTPS aquí y de qué no?
- [x] HTTPS revela que el servidor no es el auténtico
- [ ] HTTPS impide que se falsifique el servidor DNS
- [x] HTTPS solo ayuda si el usuario se toma en serio la advertencia
- [ ] Con HTTPS la página falsa ni siquiera es accesible
:::

:::evaluate
Verificar respuestas
:::

## Parte 3: reparar el servidor DNS

Abre el **DNS-Server** y corrige la entrada de `www.biberbank.de`. La dirección correcta la encuentras en la :fa-gear: **Configuración IP** del servidor web **www.biberbank.de**. No olvides hacer clic en **Guardar**.

:::note
El Client-PC recuerda las respuestas DNS durante un tiempo para no tener que preguntar de nuevo en cada acceso (**caché DNS**). Cuánto tiempo, lo indica la columna **TTL** (*Time to Live*) en segundos. Si justo después de tu corrección `nslookup` sigue devolviendo la dirección antigua, espera a que pase el TTL e inténtalo de nuevo.
:::

:::task
title: ¿Biberbank vuelve a ser auténtica?
Comprueba si el Client-PC resuelve www.biberbank.de a la dirección correcta y puede abrir la página mediante HTTPS sin advertencia.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
En la realidad, un atacante rara vez falsifica el propio servidor DNS. Con más frecuencia introduce sus respuestas en una red WiFi pública, modifica la configuración de un router doméstico o atrae a la víctima con una dirección de aspecto similar, como `www.biberbank-login.de` (**phishing**). Contra un nombre parecido, HTTPS tampoco ayuda: el atacante obtiene para él un certificado válido. Por eso: ¡lee la dirección con atención!
:::

:::tip Recuerda
En una **falsificación de DNS**, el servidor DNS devuelve para un nombre la dirección de un atacante. Con **HTTP** no se nota nada. Con **HTTPS**, el certificado del atacante no coincide con el nombre solicitado y el navegador **advierte**, porque ninguna CA emite un certificado para dominios ajenos y el atacante no tiene la clave privada del servidor real.
:::
