# El problema de las respuestas

:::sim
url=/sims/lesson-9.2.btsim
:::

El cortafuegos ahora funciona según el principio de lista blanca: política predeterminada **Descartar todo**. Una única regla permite a la red de la escuela navegar: **B → A, TCP, puerto de destino 80, Permitir**. El modo está en **Stateless**.

## El experimento

1. Cambia al modo de ejecución :fa-play: **Ejecutar** y abre en el **Lehrer-PC** la dirección `http://203.0.113.80/` en el :fa-globe: **Navegador**.
2. Mira en el **Firewall** el **Protokoll** y los **Treffer**.

:::quiz mc
¿Qué ocurre en el navegador?
- [ ] Aparece la página de www.beispiel.de
- [x] La página no carga, el navegador espera y finalmente muestra un error
:::

:::quiz mc
¿Qué paquetes aparecen en el registro del cortafuegos como descartados (`DROP`)?
- [ ] Las solicitudes del Lehrer-PC al puerto 80
- [x] Las respuestas de `203.0.113.80` con **puerto de origen 80** hacia el Lehrer-PC
- [ ] Ninguno
:::

:::quiz short
¿En qué dirección (A→B o B→A) circulan los paquetes descartados?
= A→B
= A → B
= AtoB
:::

:::evaluate
Comprobar respuestas
:::

La solicitud del Lehrer-PC puede salir, pero ya el `SYN, ACK` del servidor web no vuelve, porque para la dirección A → B no hay ninguna regla adecuada y, por tanto, se aplica **Descartar todo**.

## La solución ingenua

Se podría añadir una segunda regla: **A → B, TCP, puerto de origen 80, Permitir**, es decir, «todo lo que venga del puerto 80 puede entrar». Entonces la navegación funciona de verdad.

:::quiz mc
¿Por qué es peligrosa esta regla?
- [ ] Porque los servidores web nunca usan el puerto 80 como puerto de origen
- [x] Un atacante puede enviar sus paquetes simplemente con puerto de origen 80, y entonces el cortafuegos los deja pasar a **cualquier** puerto de la red de la escuela
- [ ] Porque entonces las páginas web cargan más despacio
:::

:::evaluate
Comprobar respuesta
:::

El puerto de origen lo establece el propio remitente, así que un cortafuegos no puede fiarse de él. Un cortafuegos sin estado, en cambio, no sabe si un paquete es la **respuesta a una solicitud** o un **nuevo intento de conexión** desde el exterior. Justamente eso es lo que cambia el modo con estado.

:::tip Recuerda
Un filtro de paquetes **sin estado** examina cada paquete por separado. Las respuestas necesitan entonces reglas propias para el sentido contrario, y esas reglas (p. ej., «el puerto de origen 80 puede entrar») pueden ser aprovechadas por atacantes, porque el remitente puede elegir libremente el puerto de origen.
:::
