# Números de secuencia y de confirmación

:::sim
url=/sims/lesson-5.1.btsim
:::

¿Cómo sabe TCP si todo ha llegado — y en qué orden? Cada lado **numera los bytes** que envía:

- El **número de secuencia** (`SEQ`) es el número del primer byte que va en este paquete.
- El **número de confirmación** (`ACK`) dice: «Hasta aquí lo he recibido todo — a continuación espero el byte n.º …»

Además, dos reglas: `SYN` y `FIN` cuentan como un byte, aunque no transporten datos. Y cada lado cuenta por separado — por eso hay dos series de números, en rojo (cliente) y en azul (servidor) en el diagrama.

## Comprobar los cálculos

Aquí tienes otra vez tu conexión. Los números de las líneas muestran el contador del equipo en ese punto:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Repasa la serie de números rojos:

1. El cliente empieza con `SEQ=0`. Su `SYN` consume un número — el servidor confirma con `ACK=1`.
2. El mensaje empieza en `SEQ=1` y tiene 13 bytes de longitud (bytes 1 a 13). El servidor confirma con `ACK=14`: «A continuación espero el byte 14.»
3. Por eso el `FIN` del cliente tiene `SEQ=14` y se confirma con `ACK=15`.

La serie azul del servidor funciona exactamente igual.

:::tip Recuerda
El **número de secuencia** (`SEQ`) es el número del primer byte del paquete. El **número de confirmación** (`ACK`) es el número del siguiente byte que espera el destinatario — todo lo anterior ha llegado. Se cumple: **ACK = SEQ + longitud** de los datos recibidos; `SYN` y `FIN` cuentan como un byte. Cada lado cuenta sus propios bytes.
:::

:::tip Pruébalo
Vuelve a establecer la conexión en el **Cliente TCP Simple** y envía dos mensajes seguidos. Antes, di qué `Seq` y `Ack` aparecerán en la columna **Info** — y compruébalo en el trace.
:::

## Practica

:::note
En las redes reales la cuenta no empieza en 0: cada lado elige un **número inicial aleatorio** (*Initial Sequence Number*, ISN) entre 0 y unos 4300 millones. Cuando se alcanza el número más alto, la cuenta vuelve a empezar en 0. El Tracer resta el número inicial y muestra números **relativos** — igual que Wireshark. Por eso ves `Seq=0` y `Seq=1`.

Además, en cada paquete aparece `Win=` — el **tamaño de ventana**: esta es la cantidad de bytes que el destinatario puede aceptar en ese momento. Así frena a un remitente demasiado rápido (*control de flujo*). En BeaverTracer la ventana siempre tiene el mismo tamaño.
:::
