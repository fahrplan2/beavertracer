# ¿TCP o UDP?

| | TCP | UDP |
|---|---|---|
| Conexión | establecimiento con acuerdo de tres vías, cierre ordenado | ninguna — cada datagrama es independiente |
| Confirmaciones | sí (`ACK`) | no |
| Datos perdidos | se reenvían | se pierden definitivamente |
| Orden | se restablece | no está garantizado |
| Cabecera | al menos 20 bytes | 8 bytes |
| Velocidad | algo más lento, más paquetes | rápido, poca sobrecarga |

¿Cuándo es menos más?

- **Tiempo real:** en videollamadas, telefonía por internet o juegos en línea cuenta cada milisegundo. Un fragmento de audio perdido que se entrega un segundo después ya no le sirve a nadie — mejor un breve chasquido que un retraso.
- **Consultas cortas:** una consulta **DNS** („¿Qué dirección IP tiene `www.beispiel.de`?“) cabe en un único datagrama, y la respuesta también. Un establecimiento de conexión triplicaría el esfuerzo. Si no llega respuesta, el programa simplemente vuelve a preguntar.

En cambio, en todos los casos en que cada byte tiene que llegar — páginas web, correos electrónicos, descargas —, TCP es la opción correcta.

:::tip Recuerda
**TCP** es fiable, pero más costoso — para todo lo que debe llegar **completo** (web, correo electrónico, archivos). **UDP** es rápido y ligero, pero sin garantías — para **tiempo real** (telefonía, vídeo, juegos) y **consultas cortas** como DNS.
:::
