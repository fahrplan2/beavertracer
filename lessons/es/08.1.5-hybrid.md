# Cifrado híbrido

Resumamos:

| | simétrico (p. ej. AES) | asimétrico (p. ej. RSA) |
|---|---|---|
| Clave | una clave secreta compartida | par de claves: pública + privada |
| Velocidad | muy rápido | lento |
| Intercambio de claves | Problema: ¿cómo llega la clave al destinatario? | sin problema: la clave pública puede enviarse abiertamente |

Cada método tiene, por tanto, una fortaleza de la que carece el otro. La solución: combinar ambos. Esto se llama **cifrado híbrido**.

1. Al comienzo de una conexión, ambas partes se ponen de acuerdo, con ayuda de un método **asimétrico**, en una clave secreta común: la **clave de sesión**. Esto tarda un momento, pero sucede **una sola vez**.
2. Después, todos los datos se cifran **simétricamente** con la clave de sesión — de forma rápida.
3. Al final de la conexión, la clave de sesión se descarta. La siguiente conexión recibe una nueva.

Así funcionan **HTTPS**, las conexiones de correo electrónico cifradas, **WLAN** con WPA3, **SSH** y **VPN**.

## Secreto compartido mediante la mezcla de colores

Una forma elegante de acordar una clave de sesión es el **intercambio de claves Diffie-Hellman** (1976). Se puede imaginar con colores. El truco: mezclar colores es fácil, pero separar un color mezclado en sus componentes es prácticamente imposible.

1. Anna y Ben acuerdan **públicamente** un color base común, p. ej. **amarillo**. Cualquiera puede conocerlo.
2. Cada uno elige en secreto un **color secreto**: Anna **rojo**, Ben **azul**.
3. Cada uno mezcla su color secreto con el color base y envía el resultado **abiertamente** al otro: Anna envía **amarillo + rojo** (naranja), Ben envía **amarillo + azul** (verde).
4. Ahora cada uno mezcla su propio color secreto con la mezcla del otro:
    - Anna: verde + rojo = **amarillo + azul + rojo**
    - Ben: naranja + azul = **amarillo + rojo + azul**
5. Ambos tienen ahora **el mismo** color (marrón) — la clave compartida.

Alguien que escuche habrá visto amarillo, naranja y verde. Pero para llegar al marrón necesitaría el rojo o el azul — y Anna y Ben nunca los enviaron.

En la realidad, por supuesto, no se calcula con colores, sino con números muy grandes. En el Tracer volverás a ver pronto este intercambio como **Server Key Exchange** y **Client Key Exchange** — la «**DHE**» de **ECDHE** significa *Diffie-Hellman Ephemeral*, es decir, Diffie-Hellman con claves desechables.

:::warning
Diffie-Hellman por sí solo no protege frente a un atacante que se coloca en medio y negocia una clave propia con Anna **y** otra con Ben. Por tanto, Anna también debe estar segura de que realmente habla con Ben. Para ello se necesitan **firmas** y **certificados** — el siguiente tema.
:::

:::tip Recuerda
El **cifrado híbrido** combina ambos mundos: con un método **asimétrico** (p. ej. Diffie-Hellman) ambas partes acuerdan una **clave de sesión** secreta; los datos en sí se cifran después de forma **simétrica** (p. ej. con AES). Así funcionan HTTPS, el cifrado WLAN, SSH y VPN.
:::
