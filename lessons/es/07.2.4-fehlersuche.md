# Resolución de problemas: ayer aún funcionaba

:::sim
url=/sims/lesson-7.2.4.btsim
:::

Ayer el servidor web doméstico era accesible desde fuera: el reenvío de puertos `TCP 80 → 192.168.178.10:80` está configurado. Tras un corte de luz esta mañana, Clara ya no puede acceder a la página. Encuentra el error y corrígelo de forma permanente.

<details>
<summary>Pista 1: ¿A dónde apunta la regla?</summary>

Compara la IP de la LAN en **Port FW** del router doméstico con la dirección que el **Heim-Webserver** tiene realmente ahora (:fa-gear: **Configuración IP**).
</details>

<details>
<summary>Pista 2: ¿Por qué tiene otra dirección?</summary>

¿Está el Heim-Webserver configurado en **DHCP**? Entonces, después de cada reinicio recibe una dirección libre cualquiera del rango del router doméstico (en la pestaña **DHCP**). ¿Cómo consigues que siempre tenga la misma dirección?
</details>

:::task
title: ¿Servidor web doméstico accesible de nuevo?
Comprueba si el servidor web doméstico tiene su dirección fija y si Clara llega a él mediante el reenvío de puertos. Para ello, la simulación debe estar en modo de ejecución.
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## ¿Qué pasó?

:::quiz multi
¿Qué afirmaciones son correctas?
- [x] El Heim-Webserver obtuvo su dirección por DHCP y tras el reinicio tenía una distinta
- [x] Por eso el reenvío de puertos apuntaba a una dirección en la que ya no había ningún servidor
- [x] Una dirección fija fuera del rango DHCP resuelve el problema de forma permanente
- [ ] El proveedor había bloqueado la dirección WAN
:::

:::evaluate
Comprobar respuesta
:::

:::tip Recuerda
Los dispositivos a los que apunta un **reenvío de puertos** (servidores, impresoras, cámaras) necesitan una **dirección fija**: o bien introducida de forma estática y **fuera del rango DHCP**, o bien como asignación fija en el servidor DHCP del router. De lo contrario, tras un reinicio pueden recibir otra dirección, y la regla no lleva a ninguna parte.
:::
