# Cómo está organizado DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Ningún servidor por sí solo puede conocer todos los nombres del mundo. Por eso DNS está construido de forma **jerárquica**, igual que los nombres mismos. Se leen de derecha a izquierda:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

El servidor que es responsable de un dominio y que realmente conoce la respuesta se llama **autoritativo**. Del camino hasta él se encarga, para el PC, un **resolver**, aquí el equipo **DNS-Resolver**.

## El experimento

1. Cambia al modo de ejecución :fa-play: **Ejecutar** y escribe en el **Client-PC**, en el :fa-terminal: **Terminal**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. En el modo :fa-magnifying-glass: **Rastreo**, abre un trace para el **DNS-Resolver**.

El resolver ha realizado por ti toda una serie de consultas. Asocia quién dio cada respuesta:

:::quiz match
Root-Server (192.168.0.101) -> Referencia: para .de es responsable ns.nic.de
de-Server (192.168.0.102) -> Referencia: para beaver-schule.de es responsable ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Respuesta: www.beaver-schule.de tiene la dirección 192.168.0.20
:::

:::quiz mc
¿A quién pregunta primero el resolver?
- [x] Al Root-Server
- [ ] Al Schul-DNS
- [ ] Al Client-PC
:::

:::evaluate
Comprobar respuestas
:::

:::note
Entre medias, el resolver también pregunta por las direcciones de los servidores a los que fue remitido (`A ns.nic.de`). Los servidores DNS reales suelen enviar estas direcciones directamente. Además, los resolvers recuerdan cada respuesta durante un tiempo (**caché**): la siguiente consulta del mismo nombre la responden ellos mismos de inmediato. Cuánto tiempo, lo indica el registro como **TTL** (*Time to Live*) en segundos.
:::

## Los tipos de registro más importantes

| Tipo | Significado | Ejemplo |
|---|---|---|
| **A** | nombre → dirección IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | nombre → dirección IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | nombre → otro nombre (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | servidor de correo responsable de un dominio | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | servidor DNS responsable de un dominio | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Recuerda
DNS es **jerárquico**: los **Root-Server** remiten a los servidores de los **dominios de nivel superior** (p. ej. `.de`), y estos a los servidores de cada **dominio**. El servidor **autoritativo** responsable conoce la respuesta. Un **resolver** recorre este camino por el PC y recuerda las respuestas (**caché**). Tipos de registro importantes: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Crear un registro

La escuela quiere que su página web también sea accesible en `intranet.beaver-schule.de`.

1. En el modo de ejecución :fa-play: **Ejecutar**, haz clic en el **Schul-DNS** y abre la aplicación **DNS-Server**.
2. Abre la pestaña **A**. Haz clic en **+** e introduce en la nueva fila el nombre `intranet.beaver-schule.de` y la dirección `192.168.0.20`.
3. Haz la prueba en el Client-PC con `nslookup intranet.beaver-schule.de`.
