# Por qué una red no basta

:::sim
url=/sims/lesson-4.1.btsim
:::

En el área de trabajo ves dos pequeñas redes de empresa: **Firma A** con Anna (`192.168.0.10`) y Ben (`192.168.0.11`), **Firma B** con Clara (`172.16.0.10`) y David (`172.16.0.11`). Los dos switches están incluso conectados directamente con un cable.

## Un ping en la propia red

1. Cambia al modo de ejecución :fa-play: **Ejecutar**, abre en **Anna** la :fa-terminal: **Terminal** y haz ping a Ben:
   ```
   $ ping 192.168.0.11
   ```
2. Cambia al modo :fa-magnifying-glass: **Rastreo**, abre un trace para **Anna** y haz clic en un `Echo (ping) request`.
3. Despliega en el árbol de protocolos la línea **Internet Protocol Version 4**. Esa es la parte IP del paquete, la parte de la que trata este capítulo.

:::quiz match
Source Address -> Dirección IP del remitente
Destination Address -> Dirección IP del destinatario
Time to Live -> Por cuántos routers puede pasar todavía el paquete
Protocol -> Qué protocolo va dentro del paquete (aquí ICMP, es decir, el ping)
:::

:::evaluate
Comprobar emparejamiento
:::

## Un ping a la otra red

Vuelve al modo de ejecución :fa-play: **Ejecutar** y haz ping desde **Anna** a Clara (`ping 172.16.0.10`). Después, mira otra vez el trace de Anna.

:::quiz mc
¿Qué ocurre?
- [ ] El ping funciona: los switches están conectados
- [x] No llega ningún ping, y en el trace de Anna no aparece ni un solo paquete hacia Clara, ni siquiera una solicitud ARP
- [ ] Anna envía una solicitud ARP, pero Clara no responde
:::

:::quiz mc
¿Por qué Anna no envía absolutamente nada?
- [ ] El cable entre los switches está roto
- [ ] Clara está apagada
- [x] Anna reconoce por la dirección IP de Clara que esta se encuentra en otra red, y no conoce ningún camino hacia ella
:::

:::evaluate
Comprobar respuestas
:::

## Qué hay detrás

Una dirección IP funciona de forma similar a una dirección postal: una parte indica en qué **red** se encuentra un dispositivo (como la calle) y la otra parte indica de qué **dispositivo** de esa red se trata (como el número de la casa). Anna está en la red `192.168.0…` y Clara en la red `172.16.0…`: dos «calles» distintas.

A los dispositivos de su *propia* red, un PC envía los paquetes directamente (mediante ARP y el switch, como ya conoces). Para una red *ajena* necesita un dispositivo que conecte las redes entre sí y reenvíe los paquetes: un **router**. Aquí todavía no hay ninguno, por eso tampoco sirve de nada el cable entre los switches.

:::tip Recuerda
El **Internet Protocol** (**IP**) de la capa 3 se encarga de que los paquetes lleguen también entre redes distintas. Una **dirección IP** se compone de una **parte de red** (¿en qué red?) y una **parte de host** (¿qué dispositivo?). Los dispositivos de la misma red se alcanzan directamente; para otras redes se necesita un **router**.
:::
