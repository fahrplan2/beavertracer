# Introducir rutas estáticas

:::sim
url=/sims/lesson-4.5.2.btsim
:::

Esta vez hay **dos** routers entre la empresa A y la empresa B. Están conectados a través de una pequeña red propia, la **red intermedia** `10.0.0.0/30`:

| Router | Interfaz | Dirección IP | Red |
|---|---|---|---|
| Router A | `eth0` | `192.168.0.1/24` | Empresa A (Anna) |
| Router A | `eth1` | `10.0.0.1/30` | Red intermedia |
| Router B | `eth0` | `10.0.0.2/30` | Red intermedia |
| Router B | `eth1` | `172.16.0.1/24` | Empresa B (Clara) |

:::note
Una red `/30` tiene exactamente dos direcciones utilizables, perfecto para conectar dos routers (consulta la sección 4.2.3).
:::

## El problema

Cambia al modo de ejecución :fa-play: **Ejecutar** y haz ping desde **Anna** a Clara (`ping 172.16.0.10`). Clara no responde; en su lugar, responde el Router A (`192.168.0.1`) con «Red de destino inalcanzable».

Echa un vistazo a la **Tabla de enrutamiento IPv4** del **Router A**.

:::quiz mc
¿Por qué el ping de Anna no llega a Clara?
- [ ] Anna no tiene configurada una puerta de enlace
- [x] El Router A no conoce la red `172.16.0.0/24`: no está conectada directamente a él y no hay ninguna ruta hacia ella
- [ ] La red intermedia es demasiado pequeña
:::

:::evaluate
Comprobar respuesta
:::

## Introducir la ruta

El Router A tiene que aprender lo siguiente: los paquetes para `172.16.0.0/24` van al Router B (`10.0.0.2`), y lo hacen a través de `eth1`.

1. En el **Router A**, abre la pestaña **Tabla de enrutamiento IPv4** y haz clic en **+ hinzufügen**.
2. En la nueva fila, introduce: **Ziel** `172.16.0.0`, **máscara de red** `255.255.255.0`, **Siguiente salto** `10.0.0.2`, **Iface** `eth1`.
3. Guarda la fila con la marca de verificación :fa-check:. En la columna **Quelle** aparece ahora **Estático**.

Vuelve a hacer ping a Clara: ahora llega la respuesta.

:::note
Por cierto, el Router B ya conoce el camino de vuelta a la empresa A: en su tabla de enrutamiento ya hay una ruta estática para `192.168.0.0/24` a través de `10.0.0.1`. En la página siguiente verás por qué este camino de vuelta es igual de importante.
:::

## Seguir el camino: traceroute

Con `traceroute` puedes ver por qué routers pasa un paquete. Escribe en **Anna**:

```
$ traceroute 172.16.0.10
```

:::quiz short
¿Por cuántos routers pasa el paquete de Anna a Clara?
= 2
= dos
:::

:::quiz mc
¿Qué dirección muestra `traceroute` para el Router B?
- [x] `10.0.0.2`: su dirección en la red intermedia, por la que entra el paquete
- [ ] `172.16.0.1`: su dirección en la empresa B
- [ ] `192.168.0.1`
:::

:::evaluate
Comprobar respuestas
:::

`traceroute` aprovecha un truco con el **Time to Live** de la sección 4.3.1: primero envía un paquete con TTL 1. El primer router resta 1, llega a 0, descarta el paquete y se lo notifica al remitente; así Anna conoce el primer router. Después envía TTL 2 para el segundo router, y así sucesivamente hasta que el destino responde.

:::tip Recuerda
Una **ruta estática** la introduce el administrador a mano: red de destino, máscara de red, siguiente salto e interfaz. Con **traceroute** se puede seguir el camino de un paquete router por router.
:::
