# Todo junto: ¿qué ocurre al abrir una página web?

:::goal
**Objetivo de aprendizaje:** Puedes explicar paso a paso qué protocolos participan, y en qué capa, cuando un portátil recién encendido abre una página web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Ahora se junta todo lo que has aprendido en este curso. Al switch están conectados un **DHCP-Server**, un **DNS-Server**, un **Webserver** y un **Laptop** que acaba de encenderse: todavía no tiene dirección IP y está configurado en DHCP.

## El experimento

1. Cambia al modo de ejecución :fa-play: **Ejecutar** y espera unos segundos.
2. Haz clic en el **Laptop**, abre el :fa-globe: **Navegador** y accede a `http://www.beaver-schule.de/`.
3. En el modo :fa-magnifying-glass: **Rastreo**, abre un trace para el **Laptop**. Aquí está toda la historia, desde el primer paquete.

Ordena los pasos correctamente, tal como aparecen en el trace:

:::quiz match
1. Schritt -> DHCP: El portátil obtiene dirección IP, gateway y servidor DNS
2. Schritt -> ARP: El portátil pregunta por la dirección MAC del servidor DNS
3. Schritt -> DNS: El portátil pregunta por la dirección IP de www.beaver-schule.de
4. Schritt -> ARP: El portátil pregunta por la dirección MAC del servidor web
5. Schritt -> TCP: Acuerdo de tres vías con el servidor web
6. Schritt -> HTTP: GET / y la respuesta 200 OK
:::

:::evaluate
Comprobar el orden
:::

<tr class="osi-l7"><td>7</td><td>1</td><td><strong>DHCP</strong></td><td>UDP 67/68</td><td>obtener la dirección propia, el gateway y el servidor DNS</td></tr>
<tr class="osi-l2-3"><td>2/3</td><td>2</td><td><strong>ARP</strong></td><td>—</td><td>encontrar la dirección MAC correspondiente a la dirección IP del servidor DNS</td></tr>
<tr class="osi-l7"><td>7</td><td>3</td><td><strong>DNS</strong></td><td>UDP 53</td><td>traducir el nombre a una dirección IP</td></tr>
<tr class="osi-l2-3"><td>2/3</td><td>4</td><td><strong>ARP</strong></td><td>—</td><td>encontrar la dirección MAC del servidor web</td></tr>
<tr class="osi-l4"><td>4</td><td>5</td><td><strong>TCP</strong></td><td>Puerto 80</td><td>establecer una conexión fiable</td></tr>

Y debajo de todo están **IP** (capa 3), que direcciona cada uno de estos paquetes, y **Ethernet** (capa 2), que lo lleva hasta el siguiente dispositivo. Si el servidor web estuviera en otra red, intervendría además el **router**: entonces el portátil preguntaría por la dirección MAC de su **gateway**, no por la del servidor web.

:::quiz mc
¿Por qué el portátil solo puede hacer la consulta DNS después de DHCP?
- [ ] Porque DNS solo funciona sobre TCP
- [x] Porque solo gracias a DHCP obtiene una dirección IP propia y se entera de qué servidor DNS es el responsable
- [ ] Porque el servidor DNS arranca solo después del servidor DHCP
:::

:::quiz mc
¿Cuántas conexiones TCP establece el navegador con el servidor web y por qué?
- [ ] Una, para todo junto
- [x] Dos: una para la página y otra para la hoja de estilos
- [ ] Ninguna, HTTP no necesita TCP
:::

:::evaluate
Verificar respuestas
:::

:::tip Recuerda
Detrás de un solo clic trabajan juntas todas las capas: **DHCP** proporciona la configuración básica, **ARP** encuentra las direcciones MAC en la red local, **DNS** traduce el nombre, **TCP** establece una conexión fiable y **HTTP** obtiene la página, todo ello empaquetado en paquetes **IP** y tramas **Ethernet**.
:::

Con esto puedes explicar la apertura de una página web desde el primer hasta el último paquete. Para cerrar el capítulo sigue un breve avance sobre otros protocolos. En los próximos capítulos trataremos la red doméstica con NAT, la seguridad y el cifrado, y con ello la pregunta de cómo se puede evitar que alguien lea todos estos paquetes.
