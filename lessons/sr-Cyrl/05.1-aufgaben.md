# Шта мора да обезбеди транспортни слој?

:::sim
url=/sims/lesson-5.1.btsim
:::

На **Server**-у истовремено раде две услуге: **веб сервер** и мала **Echo услуга**, која одмах враћа сваку поруку коју прими. Помоћу два експеримента сазнаћеш шта сам IP не може да обезбеди.

## Експеримент 1: Два програма истовремено

1. Пређи у :fa-play: **Режим извршавања** и кликни на **Client-PC**.
2. Отвори :fa-globe: **Прегледач** и позови `http://192.168.0.20/`.
3. Кликни на врху прозора на **Назад** и отвори **Једноставан TCP клијент**. У поље **Host** унеси `192.168.0.20`, а у поље **Port** унеси `5000` и кликни на **Повежи се**.
4. Пређи у :fa-magnifying-glass: **Трага** режим и помоћу **+** отвори траг за **Client-PC**, прикључак `eth0`.

Кликни на један пакет прегледача (нпр. `GET /`) и на један пакет TCP клијента и у оба случаја раширити **Internet Protocol Version 4**.

:::quiz mc
Које IP адресе носе пакети прегледача и TCP клијента?
- [x] Код оба исте: са `192.168.0.10` на `192.168.0.20`
- [ ] Прегледач користи другу одредишну IP адресу него TCP клијент
- [ ] Пакети TCP клијента немају IP адресу
:::

:::quiz mc
Да ли је, дакле, одредишна IP адреса довољна да сервер зна да ли пакет припада веб серверу или Echo услузи?
- [ ] Да
- [x] Не — оба пакета имају исту одредишну IP адресу
:::

Нешто друго мора да раздваја те две везе. Погледај у колону **Info** код пакета са `[SYN]` — то је у оба случаја први пакет једне везе:

:::quiz short
Који број стоји код **прегледача** иза стрелице `→`?
= 80
:::

:::quiz short
А код **TCP клијента**?
= 5000
:::

:::evaluate
Провери одговоре
:::

О овим бројевима — **портовима** — сазнаћеш више у одељку 5.3. За сада је довољно да знаш: тек транспортни слој омогућава да више програма истовремено комуницира преко *једне* IP адресе и да сваки пакет стигне до правог програма. То се зове **мултиплексирање**.

## Експеримент 2: Када се пакет изгуби

1. Пређи у :fa-play: **Режим извршавања** и кликни на **кабл** између Client-PC-ја и Server-а.
2. У прозору **Веза** подеси **Конфигурисани губитак пакета** на `25%`.
3. На **Client-PC**-ју отвори :fa-terminal: **Терминал** и пошаљи шест пингова:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Ово траје око пола минута — сачекај док се не појави статистика.

:::quiz mc
Шта се дешава?
- [ ] На свих шест пингова стиже одговор
- [x] Неки пингови остају без одговора — и нико их не шаље поново
- [ ] Изгубљени пингови се аутоматски понављају док не стигну
:::

:::evaluate
Провери одговор
:::

Код пинга то није проблем — он управо треба да покаже да ли се нешто губи. Међутим, код веб странице, е-поруке или преузимања недостајући део био би кобан: датотека би била оштећена.

## Четири задатка транспортног слоја

| Задатак | Шта то значи |
|---|---|
| **Мултиплексирање** | Више програма и веза дели једну IP адресу; сваки пакет стиже до правог програма. |
| **Успостављање везе** | Пре него што подаци потекну, обе стране се договоре да ће међусобно комуницирати. |
| **Поуздан пренос** | Прималац потврђује шта је стигло. Оно што недостаје се поново шаље, а редослед се успоставља. |
| **Прекид везе** | На крају обе стране уређено завршавају везу. |

:::tip Запамти
**Транспортни слој** (слој 4) брине да подаци стигну до правог **програма** (**мултиплексирање**). Протокол **TCP** додатно брине да стигну **потпуно** и **правилним редоследом** — уз успостављање везе, потврде, поновно слање и прекид везе.
:::

:::quiz match
На једном рачунару истовремено раде прегледач, програм за пошту и месинџер. -> Мултиплексирање
Пре него што подаци потекну, обе стране утврде да је друга спремна. -> Успостављање везе
Део датотеке не стигне и шаље се још једном. -> Поуздан пренос
Након преузимања обе стране поново ослобађају везу. -> Прекид везе
:::

Провери повезивање
:::
