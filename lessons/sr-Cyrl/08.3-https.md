# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) је сасвим обичан HTTP — само што не ради директно преко TCP-а, већ кроз шифровани слој између: **TLS** (*Transport Layer Security*). Претходник TLS-а звао се **SSL**; зато се још увек често говори о „SSL сертификатима“.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP то не примећује: шаље своје захтеве као и обично, TLS их шифрује, TCP их преноси. У OSI моделу TLS се налази између транспортног и апликативног слоја, дакле у слоју 4/5 — надограђује се на TCP и управља заштићеном сесијом.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Адреса | `http://…` | `https://…` |
| Садржај читљив у Tracer-у? | да | не |
| Прегледач приказује | „није безбедно“ | катанац |

TLS при успостављању везе обавља све што си научио/ла у овом поглављу:

- Сервер се легитимише својим **сертификатом** (**аутентичност**).
- Обе стране договарају **сесијски кључ** помоћу **Diffie-Hellman**-а — сервер **потписује** свој удео.
- Након тога се сви подаци шифрују помоћу **AES**-а (**поверљивост**) и штите од измена (**интегритет**).

Принцип није ограничен на веб: и е-пошта (одељак 8.4) и многи други протоколи раде на исти начин кроз TLS.

У следећим одељцима посматраш HTTPS у Tracer-у, сам/сама га подешаваш и истражујеш када прегледач упозорава — и зашто.
