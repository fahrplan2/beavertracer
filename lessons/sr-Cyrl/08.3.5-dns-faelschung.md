# Напад: лажирање DNS-а

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Ана жели да на **Client-PC** рачунару отвори свој онлајн банкарство код **Biberbank**. Оно што она не зна: неко је добио приступ **DNS-серверу** и изменио један унос.

На Радној површини видиш прави веб-сервер **www.biberbank.de** и рачунар **нападача**. На њему је покренута копија веб-сајта банке.

## Део 1: Без шифровања

Пређи у :fa-play: **Режим извршавања** и на **Client-PC** рачунару у :fa-globe: **Прегледачу** отвори `http://www.biberbank.de/`.

:::quiz mc
Шта видиш?
- [x] Страницу за пријаву Biberbank, без икаквог упозорења
- [ ] Упозорење да је страница лажна
- [ ] Поруку о грешци
:::

:::evaluate
Провери одговор
:::

Све изгледа нормално. Али са којим сервером прегледач стварно комуницира? Отвори на Client-PC рачунару :fa-terminal: **Терминал**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Коју IP адресу враћа DNS сервер за `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Коме припада ова адреса? (У Режиму уређивања кликни на уређаје или погледај њихова :fa-gear: **IP подешавања**.)
- [ ] Правом веб-серверу Biberbank
- [x] Нападачу
- [ ] DNS серверу
:::

:::evaluate
Провери одговоре
:::

Да је Ана сада унела број рачуна и PIN, они би завршили директно код нападача. Код **HTTP**-а она **нема никакве шансе** да примети превару: адресна трака приказује исправно име, а страница изгледа аутентично.

## Део 2: Са HTTPS-ом

Сада отвори `https://www.biberbank.de/`.

:::quiz mc
Шта се дешава?
- [ ] Појављује се лажна страница са катанцем
- [x] Прегледач упозорава: Сертификат је издат за друго име
- [ ] Појављује се права страница Biberbank
:::

:::quiz short
За које име је издат сертификат нападача (без `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Провери одговоре
:::

Нападач има чак и **прави** сертификат поузданог CA-а — али за свој домен `www.biber-gewinnspiel.de`. Сертификат за `www.biberbank.de` не може да добије ни од једног CA-а, јер тај домен не припада њему. А без **приватног кључа** банке Biberbank не може да употреби ни њен прави сертификат: у handshake-у би морао да њиме потпише Server Key Exchange.

:::quiz multi
Од чега HTTPS овде штити — а од чега не?
- [x] HTTPS открива да сервер није прави
- [ ] HTTPS спречава да се DNS сервер лажира
- [x] HTTPS помаже само ако корисник озбиљно схвати упозорење
- [ ] Са HTTPS-ом лажна страница уопште није доступна
:::

:::evaluate
Провери одговоре
:::

## Део 3: Поправка DNS сервера

Отвори **DNS-сервер** и исправи унос за `www.biberbank.de`. Праву адресу налазиш у :fa-gear: **IP подешавањима** веб-сервера **www.biberbank.de**. Не заборави да кликнеш на **Сачувај**.

:::note
Client-PC памти DNS одговоре извесно време да не би морао при сваком позиву поново да пита (**DNS кеш**). Колико дуго, пише у колони **TTL** (*Time to Live*) у секундама. Ако `nslookup` одмах после твоје исправке и даље враћа стару адресу, сачекај да истекне TTL и покушај поново.
:::

:::task
title: Да ли је Biberbank поново прави?
Проверава да ли Client-PC разрешава www.biberbank.de на праву адресу и да ли може да отвори страницу преко HTTPS-а без упозорења.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
У стварности нападач ретко лажира сам DNS сервер. Чешће подмеће своје одговоре у јавној WiFi мрежи, мења подешавања Кућног рутера или мами адресом која личи на праву, као што је `www.biberbank-login.de` (**фишинг**). Против имена које звучи слично HTTPS не помаже — нападач за њега добија важећи сертификат. Зато: пажљиво читај адресу!
:::

:::tip Запамти
Код **лажирања DNS-а** DNS сервер за неко име враћа адресу нападача. Код **HTTP**-а се то не примећује. Код **HTTPS**-а сертификат нападача не одговара позваном имену и прегледач **упозорава** — јер сертификат за туђе домене не издаје ниједан CA, а приватни кључ правог сервера нападач нема.
:::
