# Секвенцијални и потврдни бројеви

:::sim
url=/sims/lesson-5.1.btsim
:::

Како TCP зна да ли је све стигло — и којим редоследом? Свака страна **нумерише бајтове** које шаље:

- **Редни број секвенце** (`SEQ`) је број првог бајта који се налази у овом пакету.
- **Број потврде** (`ACK`) каже: „Све до овде сам примио — следеће очекујем бајт бр. …“

Уз то важе два правила: `SYN` и `FIN` рачунају се као један бајт, иако не носе податке. И свака страна броји за себе — зато постоје два низа бројева, на дијаграму црвени (клијент) и плави (сервер).

## Проверавање рачуном

Овде је поново твоја веза. Бројеви на линијама показују бројач рачунара на том месту:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Прође кроз црвени низ бројева:

1. Клијент почиње од `SEQ=0`. Његов `SYN` троши један број — сервер потврђује са `ACK=1`.
2. Порука почиње на `SEQ=1` и дугачка је 13 бајтова (бајтови од 1 до 13). Сервер потврђује са `ACK=14`: „Следеће очекујем бајт 14.“
3. `FIN` клијента зато има `SEQ=14` и потврђује се са `ACK=15`.

Плави низ сервера функционише потпуно исто.

:::tip Запамти
**Редни број секвенце** (`SEQ`) је број првог бајта у пакету. **Број потврде** (`ACK`) је број следећег бајта који прималац очекује — све пре њега је стигло. Важи: **ACK = SEQ + дужина** примљених података; `SYN` и `FIN` рачунају се као један бајт. Свака страна броји своје бајтове.
:::

:::tip Пробај сам
Поново успостави везу у **Једноставан TCP клијент** и пошаљи две поруке једну за другом. Унапред реци које ће вредности `Seq` и `Ack` стајати у колони **Info** — а онда провери у трагу.
:::

## Вежбање

:::quiz short
Клијент шаље пакет са `Seq=1` и `Len=13`. Који број потврде сервер шаље назад?
= 14
:::

:::quiz short
Након тога клијент шаље своју следећу поруку. Којим редним бројем секвенце она почиње?
= 14
:::

:::quiz short
Стиже пакет са `Seq=40` и `Len=25`. Који број потврде шаље прималац?
= 65
:::

:::evaluate
Провери одговоре
:::

Унеси бројеве који недостају. Клијент шаље `Hallo`, а затим `Tschau` (сваку са крајем реда):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
Провери дијаграм
:::

:::note
У стварним мрежама бројање не почиње од 0: свака страна бира **насумичан почетни број** (*Initial Sequence Number*, ISN) између 0 и око 4,3 милијарде. Када се достигне највећи број, наставља се поново од 0. Tracer одузима почетни број и приказује **релативне** бројеве — баш као Wireshark. Зато видиш `Seq=0` и `Seq=1`.

Осим тога, у сваком пакету стоји `Win=` — **величина прозора**: толико бајтова прималац тренутно може да прихвати. Тиме он успорава пребрзог пошиљаоца (*контрола тока*). У BeaverTracer-у је прозор увек исте величине.
:::
