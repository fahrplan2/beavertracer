# TLS handshake

:::sim
url=/sims/lesson-8.2.1.btsim

Пре него што се пошаље први шифровани захтев, клијент и сервер морају да се договоре: о поступку, о кључу сесије — а клијент мора да провери са ким комуницира. Ово успостављање везе зове се **TLS handshake**.

## Ток у дијаграму

Без TCP потврда (`ACK`) handshake изгледа овако:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Шта се ту дешава — и који градивни елемент из одељка 8.1 стоји иза тога:

1. **Client Hello / Server Hello:** Клијент и сервер се поздрављају, размењују случајне бројеве и договарају се о поступцима (у програму BeaverTracer: размена кључева помоћу **ECDHE**, потпис помоћу **ECDSA**, шифровање помоћу **AES**).
2. **Certificate:** Сервер шаље свој **сертификат**. Клијент проверава потпис CA, важење и име. Ако то не успе, прекида везу већ овде — а прегледач приказује упозорење.
3. **Server Key Exchange:** Сервер шаље свој **Diffie-Hellman део** — и **потписује** га својим приватним кључем. Клијент проверава потпис јавним кључем из сертификата. Тако зна: овај део заиста потиче од власника сертификата, а не од нападача Man-in-the-Middle.
4. **Client Key Exchange:** Клијент шаље свој Diffie-Hellman део. Сада обе стране могу да израчунају исти **кључ сесије** — а да он никада није пренет.
5. **Change Cipher Spec:** „Од сада шифрујем.“
6. **Encrypted Handshake Message (Finished):** Обе стране шаљу — већ шифровано — контролни збир свих дотадашњих handshake порука. Ако је нападач успут нешто изменио, контролни збирови се неће поклапати и веза се прекида.
7. **Application Data:** Одавде теку HTTP подаци — симетрично шифровани помоћу AES.

:::quiz match
Certificate -> Сервер се легитимише својим сертификатом
Server Key Exchange -> Потписани Diffie-Hellman део сервера
Client Key Exchange -> Diffie-Hellman део клијента
Change Cipher Spec -> Од сада се шифрује
Application Data -> Шифровани HTTP подаци
:::

:::note
У траси видиш **две** TLS везе једну за другом: прегледач прво преузима страницу, а затим успоставља нову везу за стилску датотеку `style.css`. Свака веза добија свој handshake и свој кључ сесије. Прави прегледачи држе везе отвореним и тако штеде део тог напора. Новија верзија **TLS 1.3** осим тога користи мање порука од овде приказаног TLS 1.2.
:::

:::tip Запамти
При **TLS handshake-у** сервер се легитимише својим **сертификатом**, обе стране договарају **кључ сесије** помоћу **Diffie-Hellman** размене (сервер **потписује** свој део), а помоћу **Finished** обе стране проверавају да нико није изменио handshake. Након тога се подаци преносе као **Application Data**, симетрично шифровани.
:::
