# Повезивање две мреже

:::sim
url=/sims/lesson-4.3.1.btsim
:::

Рутер има два прикључка:

| Прикључак | IP адреса | Мрежа |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Фирма A |
| `eth1` | `172.16.0.1/24` | Фирма B |

Да би рачунари користили рутер, на сваком од њих је унет **гејтвеј**: на рачунарима Anna и Ben то је `192.168.0.1`, а на рачунарима Clara и David `172.16.0.1`. Налази се у :fa-gear: **IP подешавања** у пољу **Gateway**.

:::tip Запамти
**Гејтвеј** (прецизније: *подразумевани гејтвеј*) је IP адреса рутера **у сопственој мрежи**. Рачунар на гејтвеј шаље све пакете чије се одредиште налази у страној мрежи.
:::

## Експеримент

1. Пређи у режим :fa-play: **Покрени** и пингуј Clara са рачунара **Anna** (`ping 172.16.0.10`). Овога пута успева — обрати пажњу на вредност `ttl=` у излазу.
2. Пређи у режим :fa-magnifying-glass: **Трага** и отвори трасу за **Anna**.

Погледај први пакет (ARP захтев):

:::quiz multi
Које тврдње о првом пакету су тачне?
- [x] Anna већ познаје IP адресу рачунара Clara пре него што пошаље пакет
- [ ] Anna тражи MAC адресу рачунара Clara
- [x] Anna тражи од свих уређаја у мрежи MAC адресу рутера
- [ ] Anna пита свич за IP адресу рачунара Clara
:::

Сада кликни на први `Echo (ping) request` и отвори **Ethernet II** и **Internet Protocol Version 4**. Упореди MAC адресе са ARP одговором пре њега.

:::quiz multi
Које тврдње о пингу су тачне?
- [x] Као одредишна IP адреса стоји рачунар Clara (`172.16.0.10`)
- [ ] Као одредишна IP адреса стоји рутер (`192.168.0.1`)
- [x] Као одредишна MAC адреса стоји MAC адреса рутера
- [ ] Anna шаље пинг директно на MAC адресу рачунара Clara
:::

## Шта рутер ради са пакетом

Рутер прима оквир од рачунара Anna, распакује IP пакет и погледа **одредишну IP адресу**. По њој закључује: Clara се налази у мрежи на `eth1`. Зато пакет пакује у **нови** оквир — са сопственом MAC адресом као пошиљаоцем и MAC адресом рачунара Clara као одредиштем — и шаље га тамо.

| Шта се дешава на рутеру са … | |
|---|---|
| MAC адресама (слој 2)? | постављају се **изнова** — важе само у одговарајућој мрежи |
| IP адресама (слој 3)? | **остају исте** — од рачунара Anna до рачунара Clara |
| Time to Live? | смањује се за **1** |

:::tip Запамти
**Рутер** ради на **слоју 3**: пакете прослеђује у друге мреже на основу **одредишне IP адресе**. IP адресе остају исте на целом путу, а MAC адресе се у свакој мрежи постављају изнова. Сваки рутер смањује **Time to Live (TTL)** за 1 — када достигне 0, пакет се одбацује. Тако пакет не може бескрајно да кружи.
:::

:::note
Сећаш се броадкаст олује из поглавља 3.4? Ethernet оквири немају TTL — IP пакети имају.
:::

## Кога познаје Anna? ARP кеш

Сећаш се поглавља 1.2.3? Тамо се ARP појављивао само пре *првог* пинга, јер је рачунар запамтио одговор. Та листа за памћење зове се **ARP кеш** (такође *ARP табела*). Упит се назива **ARP-Request**, а одговор **ARP-Reply** (или *ARP-Response*).

Пређи у режим :fa-play: **Покрени**, отвори :fa-terminal: **Терминал** на рачунару **Anna** и прикажи његов ARP кеш:

```
$ arp
```

:::quiz mc
Шта стоји у ARP кешу рачунара Anna?
- [x] Само IP адреса рутера (`192.168.0.1`) са његовом MAC адресом
- [ ] IP адреса рачунара Clara са MAC адресом рачунара Clara
- [ ] Адресе рутера и рачунара Clara
:::

:::evaluate
Провери одговор
:::

Anna никада не треба MAC адресу рачунара Clara: све што је намењено фирми B шаље рутеру. MAC адресу рачунара Clara зна само рутер — њу је на својој страни сам затражио путем ARP-а.

:::tip Запамти
У **ARP кешу** уређај памти која MAC адреса припада којој IP адреси — тако не мора пре сваког пакета да шаље ARP-Request. Може се приказати командом `arp`. Рачунар познаје само MAC адресе из **сопствене** мреже: за сва одредишта у страним мрежама користи MAC адресу рутера.
:::

:::note
У правим мрежама уноси у ARP кешу се после неког времена поново бришу и по потреби изнова траже — на пример, ако је уређај у међувремену добио другу мрежну картицу. У BeaverTracer-у остају сачувани док симулација траје.
:::
