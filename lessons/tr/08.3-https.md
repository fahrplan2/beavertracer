# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*), aslında sıradan HTTP'dir — tek fark, doğrudan TCP üzerinden çalışmayıp araya giren şifreli bir katmandan geçmesidir: **TLS** (*Transport Layer Security*). TLS'nin öncülünün adı **SSL**'di; bu yüzden hâlâ sık sık "SSL sertifikaları"ndan söz edilir.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP bunun hiçbirini fark etmez: İsteklerini her zamanki gibi gönderir, TLS bunları şifreler, TCP de taşır. OSI modelinde TLS, taşıma katmanı ile uygulama katmanı arasında yer alır, yani 4/5. katmandadır — TCP üzerine kurulur ve güvenli bir oturumu yönetir.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adres | `http://…` | `https://…` |
| İçerik Tracer'da okunabiliyor mu? | evet | hayır |
| Tarayıcı gösterir | "güvenli değil" | kilit |

TLS, bağlantı kurulumu sırasında bu bölümde öğrendiğin her şeyi yerine getirir:

- Sunucu, **sertifikasıyla** kimliğini kanıtlar (**kimlik doğrulama**).
- İki taraf **Diffie-Hellman** ile bir **oturum anahtarı** üzerinde anlaşır — sunucu kendi payını **imzalar**.
- Bundan sonra tüm veriler **AES** ile şifrelenir (**gizlilik**) ve değiştirilmeye karşı korunur (**bütünlük**).

Bu ilke yalnızca web ile sınırlı değildir: E-posta (bölüm 8.4) ve diğer birçok protokol de aynı şekilde TLS üzerinden çalışır.

Sonraki bölümlerde HTTPS'i Tracer'da gözlemleyecek, kendin kuracak ve tarayıcının ne zaman, neden uyarı verdiğini inceleyeceksin.
