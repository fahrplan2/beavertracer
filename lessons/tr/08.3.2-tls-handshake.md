# TLS el sıkışması

:::sim
url=/sims/lesson-8.2.1.btsim
:::

İlk şifreli istek gönderilmeden önce istemci ile sunucunun anlaşması gerekir: bir yöntem üzerinde, bir oturum anahtarı üzerinde — ve istemci kiminle konuştuğunu doğrulamalıdır. Bu bağlantı kurulumuna **TLS el sıkışması (TLS handshake)** denir.

## Akışın diyagramı

TCP onayları (`ACK`) olmadan el sıkışma şöyle görünür:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Bu sırada neler olur — ve bunun arkasında 8.1 bölümündeki hangi yapı taşı yer alır:

1. **Client Hello / Server Hello:** İstemci ile sunucu birbirini selamlar, rastgele sayılar değiş tokuş eder ve yöntemler üzerinde anlaşır (BeaverTracer'da: anahtar değişimi **ECDHE** ile, imza **ECDSA** ile, şifreleme **AES** ile).
2. **Certificate:** Sunucu **sertifikasını** gönderir. İstemci, CA'nın imzasını, geçerlilik süresini ve adı kontrol eder. Bu başarısız olursa burada işlemi keser — ve tarayıcı bir uyarı gösterir.
3. **Server Key Exchange:** Sunucu **Diffie-Hellman payını** gönderir — ve bunu özel anahtarıyla **imzalar**. İstemci imzayı, sertifikadaki açık anahtarla doğrular. Böylece şunu bilir: Bu pay gerçekten sertifika sahibinden gelmiştir, bir ortadaki adamdan (man-in-the-middle) değil.
4. **Client Key Exchange:** İstemci kendi Diffie-Hellman payını gönderir. Artık her ikisi de aynı **oturum anahtarını** hesaplayabilir — üstelik bu anahtar hiç iletilmeden.
5. **Change Cipher Spec:** „Şu andan itibaren şifreliyorum.“
6. **Encrypted Handshake Message (Finished):** Her iki taraf — artık şifreli olarak — o ana kadarki tüm el sıkışma mesajlarının bir sağlama toplamını gönderir. Bir saldırgan yolda bir şeyi değiştirdiyse sağlama toplamları uyuşmaz ve bağlantı kesilir.
7. **Application Data:** Buradan itibaren HTTP verileri akar — AES ile simetrik olarak şifrelenmiş şekilde.

:::quiz match
Certificate -> Sunucu, sertifikasıyla kimliğini kanıtlar
Server Key Exchange -> Sunucunun imzalı Diffie-Hellman payı
Client Key Exchange -> İstemcinin Diffie-Hellman payı
Change Cipher Spec -> Şu andan itibaren şifreleme yapılır
Application Data -> Şifreli HTTP verileri
:::

:::note
İzde art arda **iki** TLS bağlantısı görürsün: Tarayıcı önce sayfayı alır, ardından `style.css` stil dosyası için yeni bir bağlantı kurar. Her bağlantı kendi el sıkışmasını ve kendi oturum anahtarını alır. Gerçek tarayıcılar bağlantıları açık tutar ve bu sayede bu yükün bir kısmından tasarruf eder. Daha yeni sürüm olan **TLS 1.3** ayrıca burada gösterilen TLS 1.2'den daha az mesajla çalışır.
:::

:::tip Anahtar nokta
**TLS el sıkışmasında** sunucu **sertifikasıyla** kimliğini kanıtlar, her iki taraf **Diffie-Hellman** ile bir **oturum anahtarı** üzerinde anlaşır (sunucu kendi payını **imzalar**) ve **Finished** ile her ikisi de el sıkışmanın kimse tarafından değiştirilmediğini doğrular. Ardından veriler **Application Data** olarak simetrik şifrelenmiş biçimde iletilir.
:::
