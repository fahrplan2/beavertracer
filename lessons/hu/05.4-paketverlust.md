# Amikor csomagok vesznek el

:::goal
**Tanulási cél:** Meg tudod figyelni a Tracerben, és el tudod magyarázni, hogyan veszi észre a TCP az elveszett adatokat, hogyan küldi el őket újra, és hogyan állítja vissza a sorrendet.
:::

Ebben a szimulációban a kábel előkészített: a Client-PC-ről a Serverre tartó **második adatcsomag** elvész. (A beállítást úgy találod meg, ha Futtatás módban a kábelre kattintasz: **Célzott csomagvesztés**.)

## A kísérlet

1. Válts :fa-play: **Futtatás** módba, nyisd meg a **Client-PC**-n az **Egyszerű TCP kliens** alkalmazást, és csatlakozz a `192.168.0.20` címhez, `5000`-es porton.
2. Küldj egymás után három üzenetet: `Hallo`, majd `Welt`, majd `!`.
3. Figyeld a csevegőablakot: a `Hallo` visszhangja azonnal megérkezik. És a másik kettőé?
4. Várj néhány másodpercet. Ezután nyiss :fa-magnifying-glass: **Nyomkövetés** módban egy trace-t a **Server** (a címzett) `eth0` csatlakozójához.

:::quiz mc
Mi történik a `Welt` és a `!` visszhangjával?
- [ ] A `!` visszhangja azonnal megérkezik, a `Welt` örökre hiányzik
- [x] Mindkettő csak néhány másodperc után érkezik meg — együtt és a helyes sorrendben
- [ ] Egyik sem érkezik meg soha
:::

## Amit a Tracer mutat

A Servernél hiányzik a `Welt` csomagja — hiszen elveszett. Helyette az **Info** oszlopban három szögletes zárójeles jelzést találsz:

| Jelzés | Mi történt |
|---|---|
| `[TCP Previous segment not captured]` | A `!` csomagja megérkezik, de előtte bájtok hiányoznak — egy **hézag**. |
| `[TCP Dup ACK …]` | A szerver ismét ugyanazt a számot nyugtázza, mint korábban (*duplicate ACK*): „Még mindig a 8. bájtra várok.” |
| `[TCP Retransmission]` | A kliens **még egyszer** elküldi a `Welt` üzenetet. |

:::quiz short
Milyen sorszáma (`Seq`) van a `[TCP Retransmission]` jelzéssel megjelölt csomagnak?
= 8
:::

:::quiz short
Milyen nyugtaszámot (`Ack`) küld a szerver közvetlenül az újraküldés után?
= 17
:::

:::quiz mc
Miért nyugtáz a szerver az újraküldés után rögtön a 17. bájtig — és nem csak a `Welt` végéig?
- [x] A `!` üzenetet már megkapta és visszatartotta — a `Welt` megérkezésével a hézag bezárult, így most már a 16. bájtig minden megvan
- [ ] A kliens a `Welt` és a `!` üzenetet együtt küldte el még egyszer
- [ ] A nyugtaszámokat mindig felkerekítik
:::

Válaszok ellenőrzése

Az üzenetváltási diagramon ez így néz ki — a ✕ jelű szaggatott nyíl az elveszett csomag:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hallo" len=7
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=7
Client-PC -> Server: ACK
Client-PC -x Server: PSH, ACK "Welt" len=6
Client-PC -> Server: PSH, ACK "!" len=3
Server -> Client-PC: ACK
Client-PC -> Server: PSH, ACK "Welt" len=6 seq=8
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=9
Client-PC -> Server: ACK
:::

## Mi áll a háttérben

A kliens minden elküldött csomagot megőriz, amíg nyugtázzák, és ehhez elindít egy **időzítőt**. Ha a nyugta túl sokáig késik, újra elküldi az adatokat — ez az **újraküldés** (*retransmission*).

A szerver mindig csak az **első hézagig** nyugtáz. Az utána érkező adatokat (itt a `!`) visszatartja, amíg a hézag be nem telik. Csak ezután adja tovább az egészet a programnak a helyes sorrendben — ezért érkezett meg együtt a `Welt` és a `!` visszhangja.

:::tip Jegyezd meg!
A TCP a veszteségeket a **hiányzó nyugtákról** ismeri fel: a címzett mindig csak az első hézagig nyugtáz. Ha elmarad a nyugta, a feladó egy időzítő lejárta után **újra** elküldi az adatokat (*retransmission*). Ami a hézag után érkezik, azt a címzett visszatartja — így az adatok **hiánytalanul és a helyes sorrendben** jutnak el a programhoz.
:::

:::tip Elmélyítés: Fast Retransmit
Küldj a `Hallo` után gyorsan egymás után négy vagy több üzenetet. Az elveszett csomag után a kliens ekkor egymás után három *Dup ACK*-t kap — és azonnal újraküld, anélkül hogy az időzítőjére várna. Ezt az eljárást **Fast Retransmit**-nek hívják.
:::

:::note
A valódi TCP-implementációk emellett a küldési sebességüket is igazítják: ha csomagok vesznek el, a hálózat valószínűleg túlterhelt, és a feladó lassít (*torlódáskezelés*). Ez túlmutat ezen a tananyagon.
:::
