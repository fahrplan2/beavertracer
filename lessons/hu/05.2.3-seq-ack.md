# Sorszámok és nyugtaszámok

:::sim
url=/sims/lesson-5.1.btsim
:::

Honnan tudja a TCP, hogy minden megérkezett-e — és milyen sorrendben? Mindkét fél **megszámozza a bájtokat**, amelyeket küld:

- A **sorszám** (`SEQ`) az a szám, amely ebben a csomagban az első bájthoz tartozik.
- A **nyugtaszám** (`ACK`) azt mondja: „Idáig mindent megkaptam — legközelebb a(z) … sorszámú bájtot várom."

Ehhez két szabály: a `SYN` és a `FIN` egy bájtnak számít, pedig nem visznek adatot. És mindkét fél a sajátját számolja — ezért van két számtartomány, a diagramon pirossal (kliens) és kékkel (szerver).

## Számoljuk végig

Itt van még egyszer a kapcsolatod. A vonalakon látható számok az adott gép számlálóját mutatják az adott pontban:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Menj végig a piros számsoron:

1. A kliens `SEQ=0`-val kezd. A `SYN` elfogyaszt egy számot — a szerver `ACK=1`-gyel nyugtáz.
2. Az üzenet `SEQ=1`-nél kezdődik, és 13 bájt hosszú (az 1. – 13. bájt). A szerver `ACK=14`-gyel nyugtáz: „Legközelebb a 14. bájtot várom."
3. A kliens `FIN`-je ezért `SEQ=14`-et kap, és `ACK=15`-tel nyugtázzák.

A szerver kék számsora pontosan ugyanígy működik.

:::tip Jegyezd meg!
A **sorszám** (`SEQ`) a csomag első bájtjának a száma. A **nyugtaszám** (`ACK`) a következő bájt száma, amelyet a címzett vár — minden előtte lévő megérkezett. Érvényes: **ACK = SEQ + a fogadott adatok hossza**; a `SYN` és a `FIN` egy bájtnak számít. Mindkét fél a saját bájtjait számolja.
:::

:::tip Próbáld ki
Építsd fel újra a kapcsolatot az **Egyszerű TCP kliens** segítségével, és küldj két üzenetet egymás után. Mondd meg előre, milyen `Seq` és `Ack` értékek fognak megjelenni az **Info** oszlopban — és ellenőrizd a nyomkövetésben.
:::

## Gyakorlás

:::quiz short

= 14
:::

Írd be a hiányzó számokat. A kliens elküldi a `Hallo` üzenetet, majd a `Tschau` üzenetet (mindkettő sorvéggel):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::note
Valódi hálózatokban a számolás nem 0-nál kezdődik: mindkét fél egy **véletlenszerű kezdőszámot** (*Initial Sequence Number*, ISN) választ 0 és nagyjából 4,3 milliárd között. Ha elérik a legmagasabb számot, a számolás újra 0-tól folytatódik. A Tracer levonja a kezdőszámot, és **relatív** számokat jelenít meg — pontosan úgy, mint a Wireshark. Ezért látsz `Seq=0` és `Seq=1` értékeket.

Ezenkívül minden csomagban szerepel a `Win=` — az **ablakméret**: ennyi bájtot tud a címzett éppen fogadni. Ezzel lassítja le a túl gyors küldőt (*forgalomszabályozás*). A BeaverTracerben az ablak mindig ugyanakkora.
:::
