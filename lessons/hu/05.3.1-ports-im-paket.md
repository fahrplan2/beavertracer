## A kísérlet

1. Válts :fa-play: **Futtatás** módba, kattints a **Client-PC**-re, és nyisd meg a :fa-globe: **Böngésző**t. Nyisd meg a `http://192.168.0.20/` címet.
2. Kattints az ablak tetején a **Vissza** gombra, nyisd meg az **Egyszerű TCP kliens**t, és csatlakoztasd a `192.168.0.20` címhez, az `5000`-es porton. Hagyd nyitva a kapcsolatot.
3. Válts :fa-magnifying-glass: **Nyomkövetés** módba, nyiss egy trace-t a **Client-PC**-hez, és kattints egy `[SYN]` csomagra. Nyisd le a **Transmission Control Protocol** elemet.

A TCP-fejrész legtetején két port áll: a **Source Port** (forrásport) és a **Destination Port** (célport).

:::quiz table
| Kapcsolat | Forrásport | Célport |
|---|---|---|
| Böngésző → webszerver | {49152} | {80} |
| TCP kliens → Echo-szolgáltatás | {49153} | {5000} |
:::

## Kétféle port

**Célport – a szolgáltatás:** Egy szerverprogram egy rögzített porton várja a kapcsolatokat – úgy mondjuk, hogy ott **figyel**. Az ismert szolgáltatások számai világszerte rögzítettek, ezek a **well-known portok** (0-tól 1023-ig). A böngésző ezért kérdezés nélkül tudja: a webszerverek a 80-as porton figyelnek.

**Forrásport – a feladó:** A kliensoldali portot az operációs rendszer minden új kapcsolathoz maga választja ki egy magas tartományból (a BeaverTracerben 49152-től). Ebből ismeri fel a kliens, hogy egy válasz a kapcsolatai közül melyikhez tartozik.

Egy kapcsolatot tehát négy adat határoz meg egyértelműen: **az IP-cím és a port mindkét oldalon**. Az IP-cím és a port párosát **socketnek** nevezzük, pl. `192.168.0.20:80`.

## Egy pillantás a szerverre

Válts vissza :fa-play: **Futtatás** módba, nyisd meg a **Server** gépen a :fa-terminal: **Terminál**t, és add meg:

```
$ ss
```

Az `ss` megmutatja a gép összes socketjét. A `LISTEN` sorok olyan programok, amelyek egy porton figyelnek. Az `ESTABLISHED` sorok létező kapcsolatok – a saját sockettel (*Local Address:Port*) és a másik oldal socketjével (*Peer Address:Port*).

:::quiz multi
Mely portokon figyel a szerver?
- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc
Melyik kapcsolatot mutatja az `ss` `ESTABLISHED` állapotúként?
- [x] `192.168.0.20:5000` a `192.168.0.10:49153` címmel – a TCP kliens nyitott kapcsolata
- [ ] `192.168.0.20:80` a `192.168.0.10:49152` címmel – a böngésző kapcsolata
- [ ] Mindkettőt
:::

:::

:::note
A böngésző kapcsolata már le is bomlott – az oldal betöltése után `FIN`-nel lezárult. Az `ss` még egy rövid ideig `TIME-WAIT` állapotban mutatja: a szerver egy ideig vár, hogy nem érkeznek-e még elkésett csomagok ebből a kapcsolatból. A TCP kliens kapcsolata ezzel szemben még nyitva van, mert még nem kattintottál a **Leválasztás** gombra.
:::

## A legfontosabb well-known portok

| Port | Protokoll | Szolgáltatás |
|---|---|---|
| 22 | SSH | biztonságos távkarbantartás (titkosított parancssor) |
| 25 | SMTP | e-mailek küldése |
| 53 | DNS | nevek lefordítása IP-címekre (többnyire UDP-n keresztül) |
| 80 | HTTP | weboldalak |
| 110 | POP3 | e-mailek letöltése |
| 143 | IMAP | e-mailek kezelése a szerveren |
| 443 | HTTPS | titkosított weboldalak |

:::tip Jegyezd meg!
A **portok** (0-tól 65535-ig) választják szét egymástól egy gépen a kapcsolatokat. A szerverszolgáltatások rögzített **well-known portokon** **figyelnek** (pl. HTTP 80, HTTPS 443), a kliensek minden kapcsolathoz kapnak egy szabad, magas **forrásportot**. Egy kapcsolatot egyértelműen határoz meg **mindkét oldal IP-címe és portja**.
:::

:::quiz match
22 -> SSH
25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
