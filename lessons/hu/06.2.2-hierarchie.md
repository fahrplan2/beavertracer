# Hogyan épül fel a DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Egyetlen szerver sem ismerheti a világ összes nevét. A DNS ezért **hierarchikusan** épül fel — éppúgy, mint maguk a nevek. Jobbról balra olvassuk őket:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Azt a szervert, amely egy tartományért felelős, és valóban ismeri a választ, **autoritatívnak** nevezzük. Az odavezető utat a PC helyett egy **resolver** járja be — itt ez a **DNS-Resolver** nevű gép.

## A kísérlet

1. Válts :fa-play: **Futtatás** módba, és írd be a **Client-PC** :fa-terminal: **Terminál**jában:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Nyiss meg a :fa-magnifying-glass: **Nyomkövetés** módban egy nyomkövetést a **DNS-Resolver** számára.

A resolver egy egész sor kérést intézett helyetted. Párosítsd össze, ki melyik választ adta:

:::quiz match
Root-Server (192.168.0.101) -> Hivatkozás: A .de-ért ns.nic.de felelős
de-Server (192.168.0.102) -> Hivatkozás: A beaver-schule.de-ért ns.beaver-schule.de felelős
Schul-DNS (192.168.0.103) -> Válasz: A www.beaver-schule.de címe 192.168.0.20
:::

:::quiz mc
Kit kérdez meg a resolver először?
- [x] A root szervert
- [ ] A Schul-DNS-t
- [ ] A Client-PC-t
:::

:::evaluate
Válaszok ellenőrzése
:::

:::note
Közben a resolver azoknak a szervereknek a címét is lekérdezi, amelyekre hivatkozást kapott (`A ns.nic.de`). A valódi DNS-szerverek ezeket a címeket általában rögtön elküldik a válasszal együtt. Emellett a resolverek egy ideig megjegyzik minden választ (**gyorsítótár**, *cache*) — az ugyanarra a névre érkező következő kérdésre azonnal maguk válaszolnak. Hogy meddig, azt a bejegyzés **TTL** (*Time to Live*) értéke mutatja másodpercben.
:::

## A legfontosabb bejegyzéstípusok

| Típus | Jelentés | Példa |
|---|---|---|
| **A** | név → IPv4-cím | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | név → IPv6-cím | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | név → másik név (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | egy tartomány felelős levelezőszervere | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | egy tartomány felelős DNS-szervere | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Jegyezd meg!
A DNS **hierarchikus**: a **root szerverek** a **legfelső szintű tartományok** (**Top-Level-Domain**, pl. `.de`) szervereire hivatkoznak, azok pedig az egyes **tartományok** szervereire. A felelős **autoritatív** szerver ismeri a választ. A **resolver** a PC helyett bejárja ezt az utat, és megjegyzi a válaszokat (**cache**). Fontos bejegyzéstípusok: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Bejegyzés létrehozása

Az iskola azt szeretné, hogy a weboldala az `intranet.beaver-schule.de` címen is elérhető legyen.

1. Kattints :fa-play: **Futtatás** módban a **Schul-DNS**-re, és nyisd meg a **DNS-Server** alkalmazást.
2. Nyisd meg az **A** fület. Kattints a **+** gombra, és írd be az új sorba az `intranet.beaver-schule.de` nevet és a `192.168.0.20` címet.
3. Tesztelj a Client-PC-n az `nslookup intranet.beaver-schule.de` paranccsal.

:::task
title: Bekerült az új név?
Ellenőrzi, hogy a Client-PC az intranet.beaver-schule.de nevet a webszerver címére oldja-e fel. Ehhez a szimulációnak Futtatás módban kell futnia.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
