# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) je sasvim običan HTTP — samo što se ne izvršava direktno preko TCP-a, već kroz šifrovani sloj između njih: **TLS** (*Transport Layer Security*). Prethodnik TLS-a zvao se **SSL**; zato se i dalje često govori o „SSL sertifikatima“.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP ništa od toga ne primećuje: šalje svoje zahteve kao i obično, TLS ih šifruje, a TCP ih prenosi. U OSI modelu TLS se nalazi između transportnog i aplikativnog sloja, dakle u sloju 4/5 — nadovezuje se na TCP i upravlja zaštićenom sesijom.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresa | `http://…` | `https://…` |
| Sadržaj čitljiv u Tracer-u? | da | ne |
| Pregledač prikazuje | „nije bezbedno“ | katanac |

TLS pri uspostavljanju veze obavlja sve što si naučio/naučila u ovom poglavlju:

- Server se predstavlja svojim **sertifikatom** (**autentičnost**).
- Obe strane pomoću **Diffie-Hellmana** dogovaraju **ključ sesije** — server svoj deo **potpisuje**.
- Nakon toga se svi podaci šifruju pomoću **AES-a** (**poverljivost**) i štite od izmena (**integritet**).

Princip nije ograničen na web: i e-pošta (odeljak 8.4) i mnogi drugi protokoli na isti način rade preko TLS-a.

U narednim odeljcima posmatraš HTTPS u Tracer-u, sam/sama ga podešavaš i istražuješ kada pregledač upozorava — i zašto.
