# TLS handshake

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Pre nego što se pošalje prvi šifrovani zahtev, klijent i server moraju da se dogovore: o postupku, o ključu sesije — a klijent mora da proveri sa kim razgovara. Ovo uspostavljanje veze zove se **TLS handshake**.

## Tok u dijagramu

Bez TCP potvrda (`ACK`) handshake izgleda ovako:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Šta se pritom događa — i koji element iz odeljka 8.1 stoji iza toga:

1. **Client Hello / Server Hello:** Klijent i server se pozdravljaju, razmenjuju slučajne brojeve i dogovaraju se o postupcima (u BeaverTracer: razmena ključeva pomoću **ECDHE**, potpis pomoću **ECDSA**, šifrovanje pomoću **AES**).
2. **Certificate:** Server šalje svoj **sertifikat**. Klijent proverava potpis CA, važenje i imena. Ako to ne uspe, ovde prekida vezu — a pregledač prikazuje upozorenje.
3. **Server Key Exchange:** Server šalje svoj **Diffie-Hellman deo** — i **potpisuje** ga svojim privatnim ključem. Klijent proverava potpis javnim ključem iz sertifikata. Tako zna: ovaj deo zaista potiče od vlasnika sertifikata, a ne od napadača koji se nalazi u sredini (Man-in-the-Middle).
4. **Client Key Exchange:** Klijent šalje svoj Diffie-Hellman deo. Sada obe strane mogu da izračunaju isti **ključ sesije** — a da on nikada nije prenet.
5. **Change Cipher Spec:** „Od sada šifrujem.“
6. **Encrypted Handshake Message (Finished):** Obe strane šalju — već šifrovano — kontrolni zbir svih dosadašnjih poruka handshake-a. Ako je napadač nešto izmenio usput, kontrolni zbirovi se ne poklapaju i veza se prekida.
7. **Application Data:** Odavde teku HTTP podaci — simetrično šifrovani pomoću AES.

:::quiz match
Certificate -> Server se predstavlja svojim sertifikatom
Server Key Exchange -> Potpisani Diffie-Hellman deo servera
Client Key Exchange -> Diffie-Hellman deo klijenta
Change Cipher Spec -> Od sada se šifruje
Application Data -> Šifrovani HTTP podaci
:::

:::note
U tragu vidiš **dve** TLS veze jednu za drugom: pregledač prvo učitava stranicu, a zatim uspostavlja novu vezu za stilsku datoteku `style.css`. Svaka veza dobija sopstveni handshake i sopstveni ključ sesije. Pravi pregledači drže veze otvorenim i tako štede deo ovog napora. Novija verzija **TLS 1.3** pored toga zahteva manje poruka od ovde prikazanog TLS 1.2.
:::

:::tip Zapamti
Kod **TLS handshake-a** server se predstavlja svojim **sertifikatom**, obe strane dogovaraju **ključ sesije** pomoću **Diffie-Hellmana** (server **potpisuje** svoj deo), a pomoću poruke **Finished** obe strane proveravaju da niko nije izmenio handshake. Zatim se podaci prenose kao **Application Data**, simetrično šifrovani.
:::
