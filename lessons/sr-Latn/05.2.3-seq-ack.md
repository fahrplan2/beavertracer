# Redni brojevi i brojevi potvrde

:::sim
url=/sims/lesson-5.1.btsim
:::

Kako TCP zna da li je sve stiglo — i kojim redosledom? Svaka strana **numeriše bajtove** koje šalje:

- **Redni broj** (`SEQ`) je broj prvog bajta koji se nalazi u ovom paketu.
- **Broj potvrde** (`ACK`) kaže: „Do ovde sam sve primio — sledeći očekujem bajt br. …"

Uz to važe dva pravila: `SYN` i `FIN` se računaju kao jedan bajt, iako ne nose podatke. I svaka strana broji za sebe — zato postoje dva niza brojeva, na dijagramu crveni (klijent) i plavi (server).

## Proveri računom

Evo još jednom tvoje veze. Brojevi na linijama prikazuju brojač računara na tom mestu:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Prođi kroz crveni niz brojeva:

1. Klijent počinje od `SEQ=0`. Njegov `SYN` troši jedan broj — server potvrđuje sa `ACK=1`.
2. Poruka počinje od `SEQ=1` i dugačka je 13 bajtova (bajtovi od 1 do 13). Server potvrđuje sa `ACK=14`: „Sledeći očekujem bajt 14."
3. `FIN` klijenta zato ima `SEQ=14` i potvrđuje se sa `ACK=15`.

Plavi niz servera funkcioniše na potpuno isti način.

:::tip Zapamti
**Redni broj** (`SEQ`) je broj prvog bajta u paketu. **Broj potvrde** (`ACK`) je broj sledećeg bajta koji primalac očekuje — sve pre njega je stiglo. Važi: **ACK = SEQ + dužina** primljenih podataka; `SYN` i `FIN` se računaju kao jedan bajt. Svaka strana broji sopstvene bajtove.
:::

:::tip Probaj sam
Ponovo uspostavi vezu u **Jednostavni TCP klijent** i pošalji dve poruke jednu za drugom. Unapred reci koji će `Seq` i `Ack` stajati u koloni **Info** — i proveri to u tragu.
:::

:::note
U pravim mrežama brojanje ne počinje od 0: svaka strana bira **nasumičan početni broj** (*Initial Sequence Number*, ISN) između 0 i oko 4,3 milijarde. Kada se dostigne najveći broj, nastavlja se ponovo od 0. Tracer oduzima početni broj i prikazuje **relativne** brojeve — baš kao Wireshark. Zato vidiš `Seq=0` i `Seq=1`.

Osim toga, u svakom paketu stoji `Win=` — **veličina prozora**: toliko bajtova primalac trenutno može da prihvati. Time koči prebrzog pošiljaoca (*kontrola protoka*). U BeaverTracer-u je prozor uvek iste veličine.
:::
