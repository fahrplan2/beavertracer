# Tutto insieme: cosa succede quando si apre una pagina web?

:::goal
**Obiettivo di apprendimento:** Sai spiegare passo dopo passo quali protocolli sono coinvolti, e a quale livello, quando un laptop appena acceso apre una pagina web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Ora mettiamo insieme tutto quello che hai imparato in questo corso. Allo switch sono collegati un **DHCP-Server**, un **DNS-Server**, un **Webserver** e un **Laptop** appena acceso: non ha ancora un indirizzo IP ed è impostato su DHCP.

## L'esperimento

1. Passa alla modalità di esecuzione con :fa-play: **Esegui** e attendi qualche secondo.
2. Clicca sul **Laptop**, apri il :fa-globe: **Browser** e apri `http://www.beaver-schule.de/`.
3. Nella modalità :fa-magnifying-glass: **Traccia**, apri una traccia per il **Laptop**. Qui c'è tutta la storia, a partire dal primo pacchetto.

Metti i passi nell'ordine corretto, così come compaiono nella traccia:

:::quiz match
Passo 1 -> DHCP: il laptop ottiene indirizzo IP, gateway e server DNS
Passo 2 -> ARP: il laptop chiede l'indirizzo MAC del server DNS
Passo 3 -> DNS: il laptop chiede l'indirizzo IP di www.beaver-schule.de
Passo 4 -> ARP: il laptop chiede l'indirizzo MAC del web server
Passo 5 -> TCP: three-way handshake con il web server
Passo 6 -> HTTP: GET / e la risposta 200 OK
:::

:::evaluate
Verifica l'ordine
:::

E sotto a tutto ci sono **IP** (livello 3), che indirizza ciascuno di questi pacchetti, ed **Ethernet** (livello 2), che lo porta al dispositivo successivo. Se il web server si trovasse in un'altra rete, entrerebbe in gioco anche il **router**: in quel caso il laptop chiederebbe l'indirizzo MAC del suo **gateway**, non quello del web server.

:::quiz mc
Perché il laptop può inviare la richiesta DNS solo dopo il DHCP?
- [ ] Perché il DNS funziona solo tramite TCP
- [x] Perché solo tramite il DHCP ottiene un proprio indirizzo IP e scopre quale server DNS è competente
- [ ] Perché il server DNS si avvia solo dopo il server DHCP
:::

:::quiz mc
Quante connessioni TCP instaura il browser verso il web server, e perché?
- [ ] Una, per tutto quanto
- [x] Due: una per la pagina e una per il foglio di stile
- [ ] Nessuna, HTTP non ha bisogno di TCP
:::

:::evaluate
Verifica le risposte
:::

:::tip Punto chiave
Dietro un singolo clic lavorano insieme tutti i livelli: **DHCP** fornisce le impostazioni di base, **ARP** trova gli indirizzi MAC nella rete locale, **DNS** traduce il nome, **TCP** instaura una connessione affidabile e **HTTP** recupera la pagina, il tutto impacchettato in pacchetti **IP** e frame **Ethernet**.
:::

Ora sai spiegare l'apertura di una pagina web dal primo all'ultimo pacchetto. A conclusione del capitolo segue ancora una breve panoramica su altri protocolli. Nei prossimi capitoli si parlerà della rete domestica con NAT, di sicurezza e crittografia, e quindi della domanda su come impedire che qualcuno possa leggere tutti questi pacchetti.
