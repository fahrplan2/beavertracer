# Configurare HTTPS

:::sim
url=/sims/lesson-8.3.3.btsim
:::

Qui riprendiamo da dove si era fermata la sezione 8.2.2: sul web server **www.beaver-schule.de** si trovano la **Schul-CA** e un certificato server da essa emesso, e il **Client-PC** si fida della Schul-CA. Il web server però non parla ancora HTTPS.

## Prima

Passa alla :fa-play: modalità **Esegui** e, sul **Client-PC**, apri `https://www.beaver-schule.de/` nel :fa-globe: **Browser**.

:::quiz mc
Che cosa succede?
- [x] La connessione non si stabilisce: nessun servizio è in ascolto sulla porta 443
- [ ] Il browser avverte che il certificato non è sicuro
- [ ] La pagina viene visualizzata senza lucchetto
:::

:::evaluate
Verifica la risposta
:::

## Attivare HTTPS

1. Sul web server apri il **Server HTTP** e clicca su **Arresta**: finché il server è in esecuzione, le impostazioni non si possono modificare.
2. Passa alla scheda **HTTPS**:
    - Spunta **Abilita HTTPS**, **Porta HTTPS** `443`
    - In **Certificato** seleziona il certificato server `www.beaver-schule.de`, non la Schul-CA!
    - Clicca su **Usa**
3. Clicca su **Avvia**.

Apri di nuovo la pagina sul Client-PC tramite `https://`. Clicca sul lucchetto e controlla l'emittente e la validità.

:::task
title: HTTPS configurato?
Verifica se il Client-PC riesce ad aprire https://www.beaver-schule.de/ senza avvisi relativi al certificato. Per farlo, la simulazione deve essere in modalità di esecuzione.
check: httpsOk(2, "https://www.beaver-schule.de/")
:::

:::quiz mc
Perché nel Server HTTP non devi selezionare il certificato della **Schul-CA**?
- [ ] Perché i certificati delle CA non possono cifrare
- [x] Perché è emesso per il nome `Schul-CA`, non per `www.beaver-schule.de`: il browser mostrerebbe un avviso
- [ ] Perché la Schul-CA non ha una chiave privata
:::

:::quiz mc
Che cosa vedrebbe un dispositivo che **non** si fida della Schul-CA, ad esempio lo smartphone di un ospite?
- [ ] La pagina normalmente, con il lucchetto
- [x] Un avviso sul certificato, perché non riesce a risalire la catena di fiducia fino a una CA conosciuta
- [ ] Niente, perché la connessione viene rifiutata
:::

:::evaluate
Verifica le risposte
:::

:::note
Per i siti web pubblici serve un certificato di una CA preinstallata in tutti i browser. Dal 2015 esiste **Let's Encrypt**, una CA che emette questi certificati gratuitamente e in modo automatico: è uno dei motivi principali per cui oggi quasi tutti i siti web usano HTTPS.
:::

:::tip Punto chiave
Per **HTTPS** il web server ha bisogno di un **certificato server con chiave privata**, il cui nome corrisponda all'indirizzo, e deve essere in ascolto sulla **porta 443**. Il client si fida del sito solo se conosce la **CA** che ha emesso il certificato.
:::
