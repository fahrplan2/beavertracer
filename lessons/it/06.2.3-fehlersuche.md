# Risoluzione dei problemi: il nome non funziona

:::sim
url=/sims/lesson-6.2.3.btsim
:::

Un'insegnante segnala: «`www.beaver-schule.de` non si carica sul mio computer. Con `http://192.168.0.20` invece funziona!» Ecco come *dovrebbe* essere configurato:

| Cosa | Valore previsto |
|---|---|
| Server DNS sul Client-PC | `192.168.0.53` (DNS-Resolver) |
| Voce nello Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Trova gli errori e correggili.

<details>
<summary>Suggerimento 1: che cosa dice nslookup?</summary>

Sul Client-PC digita `nslookup www.beaver-schule.de`. Quale server ha interrogato `nslookup` e che cosa ha ricevuto come risposta? (La risposta richiede qualche secondo.)
</details>

<details>
<summary>Suggerimento 2: e adesso?</summary>

Se ricevi una risposta, confronta l'indirizzo con lo schema. Dove è registrato questo nome?
</details>

:::task
title: Risoluzione dei nomi riparata?
Verifica se il Client-PC risolve www.beaver-schule.de nell'indirizzo corretto. Per questo la simulazione deve essere in esecuzione nella Modalità di esecuzione.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Che cosa era successo?

:::quiz multi
Quali affermazioni sono corrette?
- [x] Sul Client-PC era impostato `192.168.0.35` come server DNS, ma a quell'indirizzo non risponde nessuno
- [x] Nello Schul-DNS `www.beaver-schule.de` puntava a `192.168.0.21` invece che a `192.168.0.20`
- [ ] Il server web era spento
- [ ] Il root server non conosceva il dominio `.de`
:::

:::evaluate
Controlla la risposta
:::

:::tip Punto chiave
Se una connessione funziona con l'**indirizzo IP** ma non con il **nome**, il problema riguarda il **DNS**. Controlla prima il **server DNS impostato** (risponde almeno?), poi la **voce** stessa (l'indirizzo è corretto?). `nslookup` mostra entrambe le cose: quale server è stato interrogato e che cosa ha risposto.
:::
