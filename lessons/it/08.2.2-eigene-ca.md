# Creare una propria CA

:::sim
url=/sims/lesson-8.2.2.btsim
:::

Per `www.beaver-schule.de` non esiste ancora un certificato. Invece di richiederne uno a una CA commerciale, la scuola crea una **propria CA**: la **Schul-CA**. Molte aziende e scuole fanno così per i loro server interni.

Nella realtà la Schul-CA girerebbe su un computer dedicato e particolarmente ben protetto. Qui invece interpreti tu stesso tutti i ruoli direttamente sul server web.

## Passo 1: creare la Schul-CA

1. Passa alla :fa-play: modalità **Esegui** e apri sul server web **www.beaver-schule.de** la :fa-shield-halved: **Gestione certificati**.
2. Nella scheda **Genera**:
    - **Common Name:** `Schul-CA`
    - **Tipo:** Autofirmato
    - Spunta **Questo è un certificato CA**
    - **Salva come:** `schul-ca.cert.json`
3. Clicca su **Genera certificato**.

In questo modo viene creata una nuova **coppia di chiavi**. Il certificato contiene la chiave pubblica; la chiave privata resta nel file sul server web.

## Passo 2: emettere il certificato del server

Di nuovo nella scheda **Genera**:

- **Common Name:** `www.beaver-schule.de`, cioè esattamente il nome che si digita nel browser
- **Tipo:** Firmato da CA, **CA firmataria:** Schul-CA
- **Salva come:** ad es. `www.beaver-schule.de.cert.json`

Nella scheda **I miei certificati** ora vedi entrambi i certificati. Clicca sul nuovo certificato del server:

:::quiz short
Chi è l'**emittente** del certificato del server (senza `CN=`)?
= Schul-CA
:::

:::quiz mc
Qual è la sua **catena**?
- [x] `www.beaver-schule.de ← Schul-CA`
- [ ] `Schul-CA ← www.beaver-schule.de`
- [ ] `www.beaver-schule.de` (autofirmato)
:::

:::evaluate
Verifica le risposte
:::

## Passo 3: far conoscere la Schul-CA al client

Il Client-PC non conosce ancora la Schul-CA: nel suo browser non è preinstallata. Devi fornirgli il suo certificato, e precisamente **senza chiave privata**:

1. Sul server web, in **I miei certificati**, seleziona la **Schul-CA** e clicca su **Copia** (non su *Copia + chiave*!).
2. Sul **Client-PC** apri la :fa-shield-halved: **Gestione certificati**, scheda **CA attendibili**.
3. Clicca su **Incolla: Schul-CA**.

:::warning
La **chiave privata della CA** è il segreto più prezioso dell'intero sistema: chi la possiede può emettere certificati per **qualsiasi** nome, di cui poi tutti i client si fideranno. Non deve mai lasciare il computer della CA.
:::

:::task
title: Schul-CA configurata?
Verifica se sul server web esiste un certificato per www.beaver-schule.de emesso dalla Schul-CA e se il Client-PC si fida della Schul-CA.
check: hasCert(4, "www.beaver-schule.de", "Schul-CA")
check: trusts(2, "Schul-CA")
:::

Perché per il client copi solo il certificato **senza** chiave privata?

- [x] Per verificare le firme basta la chiave pubblica; con la chiave privata chiunque sul client potrebbe emettere certificati da sé
- [ ] Perché altrimenti il client non può stabilire una connessione
:::

:::evaluate
Verifica la risposta
:::

Il server web vero e proprio non l'hai ancora riconfigurato: continua a parlare solo HTTP. Come attivare HTTPS lo imparerai nella sezione 8.3.3.

:::tip Punto chiave
Una **propria CA** è costituita da un **certificato CA autofirmato** con chiave privata. Con esso si emettono **certificati server** il cui Common Name corrisponde al nome del server. Affinché i client si fidino di questi certificati, ricevono il **certificato CA senza chiave privata** nel loro elenco di **CA attendibili**.
:::
