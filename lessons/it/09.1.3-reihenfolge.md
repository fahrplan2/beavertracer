# Ordine e approccio di base

## Prima l'eccezione, poi la regola

Poiché vince la **prima regola corrispondente**, l'ordine è importante. Osserva questo elenco di regole (tutte le regole valgono per la direzione A → B, criterio predefinito: Consenti tutto):

| N. | Protocollo | Porta di destinazione | Azione |
|---|---|---|---|
| 1 | TCP | qualsiasi | Scarta |
| 2 | TCP | 80 | Consenti |

:::quiz mc
Arriva un pacchetto da Internet diretto alla porta TCP 80. Che cosa succede?
- [ ] Viene consentito, perché la regola 2 permette proprio la porta 80
- [x] Viene scartato, perché corrisponde già la regola 1: la regola 2 non viene mai raggiunta
- [ ] Il firewall chiede conferma all'amministratore
:::

:::evaluate
Controlla risposta
:::

In generale vale: **regole specifiche in alto, regole generali in basso.** Una regola che copre molti casi «oscura» tutte le regole sottostanti. La colonna **Corrispondenze** rivela queste regole morte: restano a 0.

## Blacklist o whitelist?

Nella sezione 9.1.2 hai **vietato** singole porte e consentito tutto il resto. Questo si chiama **blacklist** («lista nera»). L'opposto è la **whitelist**: si **consente** solo ciò che è necessario e si vieta tutto il resto, con una regola finale «scarta tutto» oppure con il criterio predefinito **Scarta tutto**.

| | Blacklist | Whitelist |
|---|---|---|
| Approccio di base | tutto consentito, eccezioni vietate | tutto vietato, eccezioni consentite |
| Criterio predefinito | Consenti | Scarta |
| Nuovo servizio sul server | è subito raggiungibile dall'esterno | resta bloccato finché qualcuno non lo abilita |

:::quiz mc
Domani un insegnante installa sul server della scuola un database in ascolto sulla porta 3306. Che cosa succede con il firewall della sezione 9.1.2 (blacklist)?
- [x] Il database è subito raggiungibile da Internet
- [ ] Il database viene bloccato automaticamente
- [ ] Il firewall segnala il nuovo servizio
:::

:::evaluate
Controlla risposta
:::

Per questo i buoni firewall funzionano secondo il **principio della whitelist** («Default Deny»): tutto ciò che non è esplicitamente consentito è vietato. Una whitelist per il server della scuola sarebbe così:

:::quiz table
| N. | Direzione | Protocollo | Porta di destinazione | Azione |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {Consenti} |
| 2 | A → B | TCP | {25} | Consenti |
| 3 | A → B | qualsiasi | qualsiasi | {Scarta} |
:::

:::evaluate
Controlla tabella
:::

:::quiz mc
Che cosa succede se si sposta la regola 3 in cima all'elenco?
- [ ] Niente, l'ordine non conta
- [x] Da Internet non passa più nulla, nemmeno il web e la posta
- [ ] Passano solo il web e la posta
:::

:::evaluate
Controlla risposta
:::

:::tip Punto chiave
Poiché vince la **prima regola corrispondente**, le **regole specifiche vanno in alto** e quelle generali in basso. Più sicura di una **blacklist** (tutto consentito tranne …) è una **whitelist** (tutto vietato tranne …, *Default Deny*): i servizi dimenticati o nuovi restano così bloccati automaticamente.
:::
