# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) è semplicemente HTTP. L'unica differenza è che non passa direttamente su TCP, ma attraverso un livello cifrato intermedio: **TLS** (*Transport Layer Security*). Il predecessore di TLS si chiamava **SSL**; per questo si parla ancora spesso di «certificati SSL».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP non si accorge di nulla: invia le sue richieste come al solito, TLS le cifra e TCP le trasporta. Nel modello OSI, TLS si colloca tra il livello di trasporto e il livello di applicazione, quindi al livello 4/5. Si basa su TCP e gestisce una sessione protetta.

| | HTTP | HTTPS |
|---|---|---|
| Porta | 80 | **443** |
| Indirizzo | `http://…` | `https://…` |
| Contenuto leggibile nel Tracer? | sì | no |
| Il browser mostra | «non sicuro» | lucchetto |

Durante l'instaurazione della connessione, TLS svolge tutto ciò che hai imparato in questo capitolo:

- Il server si identifica con il suo **certificato** (**autenticità**).
- Le due parti negoziano una **chiave di sessione** con **Diffie-Hellman**, e il server **firma** la propria parte.
- Poi tutti i dati vengono cifrati con **AES** (**riservatezza**) e protetti da modifiche (**integrità**).

Il principio non si limita al web: anche l'e-mail (sezione 8.4) e molti altri protocolli passano attraverso TLS allo stesso modo.
