# Aprire una pagina web e osservarla

In questa parte non devi costruire nulla: nell'area di lavoro trovi una simulazione già pronta con un **Client-PC** e un **Webserver**.

## Aprire la pagina

1. Passa alla modalità :fa-play: **Esegui**.
2. Sul **Client-PC** apri l'app :fa-globe: **Browser** e digita l'indirizzo del web server: `http://192.168.0.20/`.
3. Passa alla modalità :fa-magnifying-glass: **Traccia** e, con **+**, apri una traccia per il **Client-PC**, porta `eth0`, esattamente come per il ping.

:::note
Per una sola richiesta di pagina sono sorprendentemente tanti pacchetti, molti di più che con il ping. Scaricare una pagina web è un processo in più fasi, non un'azione singola.
:::

## Leggere l'elenco dei pacchetti

Non devi ancora sapere che cosa fa esattamente ciascun protocollo. Tutto ciò che ti serve per le domande seguenti si trova nelle colonne **Protocollo** e **Info**.

:::quiz mc
Quale protocollo compare in cima all'elenco?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Conta: quanti pacchetti **TCP** ci sono prima del primo pacchetto **HTTP**?
= 3
= tre
:::

:::quiz mc
Che cosa risponde il web server alla richiesta del browser? Guarda la colonna Info del secondo pacchetto HTTP.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Controlla le risposte
:::

## Individuare i protocolli coinvolti

Dalle tue osservazioni puoi ora ricavare di che cosa si occupava ciascun protocollo.

:::tip Suggerimento
Rileggi le colonne **Info**: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` e `200 OK` rivelano già quasi tutto.
:::

:::quiz match
ARP -> Chiede a tutti nella rete: “Chi ha l'indirizzo IP 192.168.0.20?”
TCP -> Instaura una connessione con tre brevi pacchetti prima che inizi il flusso dei dati
HTTP -> Richiede la pagina web (GET) e la restituisce (200 OK)
:::

:::evaluate
Controlla gli abbinamenti
:::

:::tip Punto chiave
L'apertura di una pagina web avviene per fasi: prima si **trova** il server nella rete (ARP), poi si **instaura** una connessione (TCP), quindi la pagina viene **richiesta e consegnata** (HTTP) e, alla fine, la connessione viene di nuovo **chiusa** (i pacchetti TCP con `[FIN]` in fondo all'elenco).
:::

:::note
Questa volta hai inserito direttamente l'indirizzo IP del server, quindi il **DNS** (la "traduzione" di nomi come `www.beispiel.de` in un indirizzo IP) non è ancora entrato in gioco. Lo recupereremo nel capitolo 6.
:::

Hai notato che i protocolli nella struttura del pacchetto hanno delle etichette colorate con dei numeri? Che cosa significano lo chiariremo nel capitolo 2. Lì vedremo come classificare in modo sistematico i tanti protocolli, con il modello di riferimento OSI e quello TCP/IP. E con questo hai concluso il capitolo 1.
