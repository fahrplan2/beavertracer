# Risoluzione dei problemi: manca la pagina dei contatti

:::sim
url=/sims/lesson-6.1.3.btsim
:::

La segreteria segnala: «Sul nostro sito web il link **Kontakt** porta ormai solo a un messaggio di errore.» La pagina dei contatti dovrebbe essere raggiungibile all'indirizzo `http://192.168.0.20/kontakt.html`. Trova l'errore e correggilo.

<details>
<summary>Suggerimento 1: cosa risponde il server?</summary>

Apri la pagina dei contatti nel browser oppure con `curl -v`. Quale codice di stato ricevi? La pagina di errore ti dice anche dove il server ha cercato il file.
</details>

<details>
<summary>Suggerimento 2: dove si trovano i file?</summary>

Il web server fornisce solo i file presenti nella sua **Radice Documenti** (*Document Root*), indicata nell'app **Server HTTP**. Sul **Server**, usa `ls` nel terminale per vedere cosa contiene e cerca la pagina dei contatti anche in `/home`.
</details>

<details>
<summary>Suggerimento 3: spostare un file</summary>

Con `mv` sposti un file: `mv <Quelle> <Zielordner>`.
</details>

:::task
title: Pagina dei contatti riparata?
Verifica se la pagina dei contatti si trova nella Radice Documenti del web server.
check: fileExists(2, "/var/www/kontakt.html")
:::

## Che cosa era successo?

:::quiz multi
Quali affermazioni sono corrette?
- [x] Il server ha risposto con `404 Not Found`
- [x] Il file si trovava in `/home` invece che nella Radice Documenti `/var/www`
- [ ] Il web server non era nemmeno avviato
- [ ] Il browser ha usato l'indirizzo IP sbagliato
:::

:::evaluate
Controlla la risposta
:::

:::tip Punto chiave
Un **404** significa che il web server è in funzione ed è raggiungibile, ma il **file** richiesto non esiste in quel percorso. Il server cerca solo nella sua **Radice Documenti** (*Document Root*, qui `/var/www`). Confronta: se il server non risponde affatto o risponde con `RST`, il problema è più profondo, nella rete o nel servizio stesso (capitolo 5.3.2).
:::
