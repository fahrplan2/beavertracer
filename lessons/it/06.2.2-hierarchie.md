# Come è organizzato il DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Nessun singolo server può conoscere tutti i nomi del mondo. Per questo il DNS ha una struttura **gerarchica**, proprio come i nomi stessi. I nomi si leggono da destra verso sinistra:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Il server che è responsabile di un dominio e conosce davvero la risposta si chiama **autoritativo**. Il percorso fino a lui lo compie per conto del PC un **resolver**: qui è il computer **DNS-Resolver**.

## L'esperimento

1. Passa alla modalità :fa-play: **Esegui** e digita nel :fa-terminal: **Terminale** del **Client-PC**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Nella modalità :fa-magnifying-glass: **Traccia**, apri una traccia per il **DNS-Resolver**.

Il resolver ha inviato per te tutta una serie di richieste. Abbina chi ha dato quale risposta:

:::quiz match
Root-Server (192.168.0.101) -> Rimando: per .de è responsabile ns.nic.de
de-Server (192.168.0.102) -> Rimando: per beaver-schule.de è responsabile ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Risposta: www.beaver-schule.de ha l'indirizzo 192.168.0.20
:::

:::quiz mc
A chi chiede per primo il resolver?
- [x] Al root server
- [ ] Allo Schul-DNS
- [ ] Al Client-PC
:::

:::evaluate
Controlla le risposte
:::

:::note
Nel frattempo il resolver chiede anche gli indirizzi dei server a cui è stato rimandato (`A ns.nic.de`). I server DNS reali di solito inviano subito anche questi indirizzi. Inoltre i resolver memorizzano ogni risposta per un certo tempo (**cache**): alla richiesta successiva per lo stesso nome rispondono subito da soli. Per quanto tempo è indicato nel record come **TTL** (*Time to Live*), in secondi.
:::

## I tipi di record più importanti

| Tipo | Significato | Esempio |
|---|---|---|
| **A** | Nome → indirizzo IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | Nome → indirizzo IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | Nome → altro nome (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | Server di posta responsabile di un dominio | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | Server DNS responsabile di un dominio | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Punto chiave
Il DNS è **gerarchico**: i **root server** rimandano ai server dei **domini di primo livello** (*top-level domain*, ad es. `.de`), e questi ai server dei singoli **domini**. Il server **autoritativo** responsabile conosce la risposta. Un **resolver** compie questo percorso per conto del PC e memorizza le risposte (**cache**). Tipi di record importanti: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Creare un record

La scuola vuole che il suo sito web sia raggiungibile anche all'indirizzo `intranet.beaver-schule.de`.

1. Nella modalità :fa-play: **Esegui**, clicca sullo **Schul-DNS** e apri l'app **Server DNS**.
2. Apri la scheda **A**. Clicca su **+** e inserisci nella nuova riga il nome `intranet.beaver-schule.de` e l'indirizzo `192.168.0.20`.
3. Verifica sul Client-PC con `nslookup intranet.beaver-schule.de`.
