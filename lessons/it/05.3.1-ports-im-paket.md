## L'esperimento

1. Passa alla modalità :fa-play: **Esegui**, clicca sul **Client-PC** e apri il :fa-globe: **Browser**. Apri `http://192.168.0.20/`.
2. Clicca su **Indietro** in alto nella finestra, apri il **Client TCP Semplice** e collegalo a `192.168.0.20`, porta `5000`. Lascia la connessione aperta.
3. Passa alla modalità :fa-magnifying-glass: **Traccia**, apri una traccia per il **Client-PC** e clicca su un pacchetto con `[SYN]`. Espandi **Transmission Control Protocol**.

Proprio in cima all'intestazione TCP ci sono due porte: **Source Port** (porta sorgente) e **Destination Port** (porta di destinazione).

## Due tipi di porte

**Porta di destinazione — il servizio:** un programma server attende le connessioni su una porta fissa: si dice che è **in ascolto** su quella porta. Per i servizi più noti i numeri sono stabiliti a livello mondiale: sono le **porte well-known** (da 0 a 1023). Per questo un browser sa senza dover chiedere che i server web sono in ascolto sulla porta 80.

**Porta sorgente — il mittente:** la porta sul lato client viene scelta autonomamente dal sistema operativo per ogni nuova connessione, all'interno di un intervallo alto (in BeaverTracer a partire da 49152). Grazie a essa il client riconosce a quale delle sue connessioni appartiene una risposta.

Una connessione è quindi identificata in modo univoco da quattro informazioni: **indirizzo IP e porta su entrambi i lati**. La coppia formata da indirizzo IP e porta si chiama **socket**, ad es. `192.168.0.20:80`.

## Uno sguardo al server

Torna alla modalità :fa-play: **Esegui**, apri il :fa-terminal: **Terminale** sul **Server** e digita:

```
$ ss
```

`ss` mostra tutti i socket del computer. Le righe con `LISTEN` sono programmi in ascolto su una porta. Le righe con `ESTABLISHED` sono connessioni attive, con il proprio socket (*Local Address:Port*) e il socket dell'altro lato (*Peer Address:Port*).

:::

:::note
La connessione del browser è già stata chiusa: dopo il caricamento della pagina è stata terminata con `FIN`. `ss` la mostra ancora per poco come `TIME-WAIT`: il server attende un po' nel caso in cui arrivino ancora pacchetti in ritardo appartenenti a questa connessione. La connessione del client TCP, invece, è ancora aperta, perché non hai ancora cliccato su **Disconnetti**.
:::

## Le porte well-known più importanti

| Porta | Protocollo | Servizio |
|---|---|---|
| 22 | SSH | amministrazione remota sicura (riga di comando cifrata) |
| 25 | SMTP | invio di e-mail |
| 53 | DNS | traduzione di nomi in indirizzi IP (per lo più tramite UDP) |
| 80 | HTTP | pagine web |
| 110 | POP3 | scaricamento di e-mail |
| 143 | IMAP | gestione delle e-mail sul server |
| 443 | HTTPS | pagine web cifrate |

:::tip Punto chiave
Le **porte** (da 0 a 65535) tengono distinte le connessioni su un computer. I servizi server sono **in ascolto** su **porte well-known** fisse (ad es. HTTP 80, HTTPS 443), mentre i client ricevono per ogni connessione una **porta sorgente** alta libera. Una connessione è identificata in modo univoco dall'**indirizzo IP e dalla porta di entrambi i lati**.
:::

:::quiz match
22 -> SSH
25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
