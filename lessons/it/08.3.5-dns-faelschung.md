# Attacco: falsificazione DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna vuole aprire sul **Client-PC** il suo home banking della **Biberbank**. Quello che non sa è che qualcuno ha ottenuto l'accesso al **DNS-Server** e ha modificato una voce.

Nell'area di lavoro vedi il vero server web **www.biberbank.de** e il computer di un attaccante (**Angreifer**), sul quale gira una copia del sito della banca.

## Parte 1: senza crittografia

Passa alla modalità :fa-play: **Esegui** e sul **Client-PC** apri `http://www.biberbank.de/` nel :fa-globe: **Browser**.

:::quiz mc
Che cosa vedi?
- [x] La pagina di accesso della Biberbank, senza alcun avviso
- [ ] Un avviso che la pagina è falsa
- [ ] Un messaggio di errore
:::

:::evaluate
Controlla la risposta
:::

Sembra tutto normale. Ma con quale server sta comunicando davvero il browser? Apri il :fa-terminal: **Terminale** sul Client-PC:

```
$ nslookup www.biberbank.de
```

:::quiz short
Quale indirizzo IP restituisce il DNS-Server per `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
A chi appartiene questo indirizzo? (In modalità di modifica, clicca sui dispositivi oppure guarda le loro :fa-gear: **Impostazioni IP**.)
- [ ] Al vero server web della Biberbank
- [x] All'attaccante
- [ ] Al DNS-Server
:::

:::evaluate
Controlla le risposte
:::

Se Anna avesse inserito numero di conto e PIN, questi sarebbero finiti direttamente all'attaccante. Con **HTTP** non ha **nessuna possibilità** di accorgersi della truffa: la barra degli indirizzi mostra il nome corretto e la pagina sembra autentica.

## Parte 2: con HTTPS

Ora apri `https://www.biberbank.de/`.

:::quiz mc
Che cosa succede?
- [ ] Compare la pagina falsa con il lucchetto
- [x] Il browser avvisa che il certificato è stato rilasciato per un altro nome
- [ ] Compare la vera pagina della Biberbank
:::

:::quiz short
Per quale nome è stato rilasciato il certificato dell'attaccante (senza `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Controlla le risposte
:::

L'attaccante possiede addirittura un certificato **autentico** di una CA affidabile, ma per il suo dominio `www.biber-gewinnspiel.de`. Un certificato per `www.biberbank.de` non glielo rilascia nessuna CA, perché quel dominio non è suo. E senza la **chiave privata** della Biberbank non può nemmeno usare il vero certificato della banca: durante l'handshake dovrebbe firmare con essa il Server Key Exchange.

:::quiz multi
Da che cosa protegge HTTPS in questo caso, e da che cosa no?
- [x] HTTPS rivela che il server non è quello autentico
- [ ] HTTPS impedisce che il DNS-Server venga falsificato
- [x] HTTPS è utile solo se l'utente prende sul serio l'avviso
- [ ] Con HTTPS la pagina falsa non è affatto raggiungibile
:::

:::evaluate
Controlla le risposte
:::

## Parte 3: riparare il DNS-Server

Apri il **DNS-Server** e correggi la voce per `www.biberbank.de`. L'indirizzo corretto lo trovi nelle :fa-gear: **Impostazioni IP** del server web **www.biberbank.de**. Non dimenticare di cliccare su **Salva**.

:::note
Il Client-PC memorizza per un certo tempo le risposte DNS, così non deve chiedere di nuovo a ogni richiesta (**cache DNS**). Per quanto tempo lo indica la colonna **TTL** (*Time to Live*), in secondi. Se subito dopo la tua correzione `nslookup` restituisce ancora il vecchio indirizzo, aspetta che scada il TTL e riprova.
:::

:::task
title: La Biberbank è di nuovo autentica?
Verifica se il Client-PC risolve www.biberbank.de nell'indirizzo corretto e se può caricare la pagina tramite HTTPS senza avvisi.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Nella realtà un attaccante raramente falsifica il DNS-Server stesso. Più spesso inserisce le proprie risposte in una rete WLAN pubblica, modifica le impostazioni di un router domestico oppure attira le vittime con un indirizzo dall'aspetto simile, come `www.biberbank-login.de` (**phishing**). Contro un nome simile nemmeno HTTPS aiuta: l'attaccante ottiene per quel nome un certificato valido. Perciò: leggi attentamente l'indirizzo!
:::

:::tip Punto chiave
In una **falsificazione DNS** il DNS-Server restituisce per un nome l'indirizzo di un attaccante. Con **HTTP** non ci si accorge di nulla. Con **HTTPS** il certificato dell'attaccante non corrisponde al nome richiesto e il browser **avvisa**: nessuna CA rilascia infatti un certificato per domini altrui, e l'attaccante non possiede la chiave privata del server autentico.
:::
