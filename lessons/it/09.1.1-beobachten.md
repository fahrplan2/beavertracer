## Port scan: scartato o rifiutato?

Ora esegui una scansione mirata di cinque porte. La porta 3306 (un database) non è affatto in uso sul server Schulserver.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (scartato) -> filtered
25 (consentito, il servizio è attivo) -> open
110 (rifiutato) -> closed
3306 (consentito, nessun servizio) -> closed
:::

:::evaluate
Controlla gli abbinamenti
:::

:::quiz multi
Che cosa può dedurre un attaccante dal risultato?
- [x] Con `filtered` sa che lì c'è un firewall che fa sparire i pacchetti
- [x] Con `closed` non può distinguere se un firewall rifiuta i pacchetti o se semplicemente non è attivo alcun servizio
- [ ] Con `filtered` sa quale servizio è attivo dietro la porta
- [ ] Con `closed` il servizio è comunque raggiungibile
:::

:::evaluate
Controlla le risposte
:::

Infine guarda la colonna **Corrispondenze** nell'elenco delle regole: lì il firewall conta quanti pacchetti ha già gestito ciascuna regola. Il valore accanto alla **Policy predefinita** conta tutti i pacchetti a cui non si è applicata nessuna regola.

:::tip Punto chiave
I pacchetti **scartati** spariscono senza lasciare traccia: `ping` segnala un timeout, `nmap` segnala `filtered`. Ai pacchetti **rifiutati** il firewall risponde con un rifiuto (con TCP un RST): dall'esterno sembra una porta chiusa. Il **Log** del firewall mostra quali pacchetti ha bloccato, la colonna **Corrispondenze** quale regola è stata applicata.
:::
