# Il diagramma di sequenza

:::sim
url=/sims/lesson-5.1.btsim
:::

Lo svolgimento di una connessione si rappresenta con un **diagramma di sequenza**: client e server hanno ciascuno una linea verticale e il tempo scorre dall'alto verso il basso. Ogni freccia è un pacchetto. È disegnata obliqua perché ogni pacchetto impiega un po' di tempo per arrivare a destinazione.

Ecco la tua connessione della pagina precedente: confrontala riga per riga con la traccia.

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Sopra ogni freccia ci sono i **flag**, sotto i numeri `SEQ` e `ACK`. **DATA** indica i pacchetti che contengono dati utili. I numeri rossi appartengono al client, quelli blu al server: il loro significato lo vedrai nella prossima pagina.

## I flag

| Flag | sta per | Significato |
|---|---|---|
| **SYN** | *synchronize* | instaurare la connessione, stabilire il numero iniziale |
| **ACK** | *acknowledge* | conferma i dati ricevuti |
| **PSH** | *push* | passare subito i dati al programma |
| **FIN** | *finish* | «Ho finito» — chiudere la connessione |
| **RST** | *reset* | interrompere o rifiutare la connessione (ne parliamo in 5.3.2) |

## Tre fasi

**Instaurazione:** il client invia `SYN`, il server risponde con `SYN, ACK`, il client conferma con `ACK`. Poiché servono esattamente tre pacchetti, questo processo si chiama **handshake a tre vie**.

**Dati:** ogni pacchetto con dati viene confermato dal destinatario con un `ACK`. Qui il server rimanda indietro l'eco, e anche questo viene confermato dal client.

**Chiusura:** ogni lato chiude separatamente la propria direzione di invio: `FIN` dal client, `ACK` dal server, poi `FIN` dal server, `ACK` dal client. In tutto sono quattro pacchetti.

:::tip Punto chiave
Una connessione TCP si svolge in tre fasi: **instaurazione** con l'**handshake a tre vie** (`SYN` → `SYN, ACK` → `ACK`), **trasferimento dei dati** (ogni pacchetto di dati viene confermato con `ACK`) e **chiusura** (ogni lato invia `FIN` e riceve un `ACK`).
:::

## Tocca a te

Questa volta il client invia solo `Hi` (4 byte con il carattere di fine riga). Inserisci i flag mancanti: l'ordine all'interno di un campo non ha importanza.

Server -> Client-PC: ? SYN, ACK
Client-PC -> Server: ? ACK

Server -> Client-PC: ? ACK
Client-PC -> Server: ? FIN, ACK
Server -> Client-PC: ? ACK
Server -> Client-PC: ? FIN, ACK
Client-PC -> Server: ? ACK
