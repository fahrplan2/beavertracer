Prieš išsiunčiant pirmąją užšifruotą užklausą, klientas ir serveris turi susitarti: dėl metodo, dėl sesijos rakto — o klientas turi patikrinti, su kuo kalbasi. Šis ryšio užmezgimas vadinamas **TLS pasisveikinimu (TLS handshake)**.

## Eigos diagrama

Be TCP patvirtinimų (`ACK`) pasisveikinimas atrodo taip:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Kas čia vyksta — ir kuris 8.1 skyriaus elementas už to slypi:

1. **Client Hello / Server Hello:** klientas ir serveris pasisveikina, apsikeičia atsitiktiniais skaičiais ir susitaria dėl metodų (BeaverTracer: raktų mainai su **ECDHE**, parašas su **ECDSA**, šifravimas su **AES**).
2. **Certificate:** serveris siunčia savo **sertifikatą**. Klientas patikrina CA parašą, galiojimą ir vardą. Jei patikra nepavyksta, jis čia nutraukia ryšį — o naršyklė parodo įspėjimą.
3. **Server Key Exchange:** serveris siunčia savo **Diffie-Hellman dalį** — ir **pasirašo** ją savo privačiuoju raktu. Klientas patikrina parašą viešuoju raktu iš sertifikato. Taip jis žino: ši dalis tikrai atkeliavo iš sertifikato savininko, o ne iš „žmogaus viduryje“ (Man-in-the-Middle).
4. **Client Key Exchange:** klientas siunčia savo Diffie-Hellman dalį. Dabar abu gali apskaičiuoti tą patį **sesijos raktą** — jo niekada neperdavus.
5. **Change Cipher Spec:** „Nuo šiol aš šifruoju.“
6. **Encrypted Handshake Message (Finished):** abi pusės siunčia — jau užšifruotą — visų ankstesnių pasisveikinimo pranešimų kontrolinę sumą. Jei užpuolikas pakeitė ką nors pakeliui, kontrolinės sumos nesutaps ir ryšys bus nutrauktas.
7. **Application Data:** nuo čia teka HTTP duomenys — simetriškai užšifruoti AES.

:::quiz match
Certificate -> Serveris identifikuojasi savo sertifikatu
Server Key Exchange -> Pasirašyta serverio Diffie-Hellman dalis
Client Key Exchange -> Kliento Diffie-Hellman dalis
Change Cipher Spec -> Nuo šiol šifruojama
Application Data -> Užšifruoti HTTP duomenys
:::

:::note
Pėdsake matai **du** TLS ryšius paeiliui: naršyklė pirmiausia gauna puslapį, o paskui užmezga naują ryšį stiliaus failui `style.css`. Kiekvienas ryšys turi savo pasisveikinimą ir savo sesijos raktą. Tikros naršyklės laiko ryšius atvirus ir taip sutaupo dalį šių sąnaudų. Naujesnė versija **TLS 1.3** be to apsieina su mažiau pranešimų nei čia parodyta TLS 1.2.
:::

:::tip Svarbu įsiminti
Per **TLS pasisveikinimą** serveris identifikuojasi savo **sertifikatu**, abi pusės per **Diffie-Hellman** susitaria dėl **sesijos rakto** (serveris **pasirašo** savo dalį), o su **Finished** abi patikrina, kad niekas nepakeitė pasisveikinimo. Po to duomenys perduodami kaip **Application Data**, simetriškai užšifruoti.
:::
