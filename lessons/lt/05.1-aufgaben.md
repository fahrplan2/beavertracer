# Ką turi užtikrinti transporto lygmuo?

:::sim
url=/sims/lesson-5.1.btsim
:::

**Serveryje** vienu metu veikia dvi paslaugos: **žiniatinklio serveris** ir nedidelė **echo paslauga**, kuri iš karto grąžina kiekvieną gautą žinutę. Atlikdamas du eksperimentus sužinosi, ko vien IP padaryti negali.

## 1 eksperimentas: dvi programos vienu metu

1. Persijunk į :fa-play: **Vykdymo režimas** — tiksliau, į :fa-play: **Paleisti** režimą — ir spustelėk **Client-PC**.
2. Atidaryk :fa-globe: **Naršyklė** ir įvesk `http://192.168.0.20/`.
3. Lango viršuje spustelėk **Atgal** ir atidaryk **Paprastas TCP klientas**. Laukelyje **Host** įvesk `192.168.0.20`, laukelyje **Port** – `5000` ir spustelėk **Prisijungti**.
4. Persijunk į :fa-magnifying-glass: **Sekti** režimą ir spustelėjęs **+** atidaryk **Client-PC** trasą (angl. *trace*), jungtis `eth0`.

Spustelėk naršyklės paketą (pvz., `GET /`) ir TCP kliento paketą ir abiejuose išskleisk **Internet Protocol Version 4**.

:::quiz mc
Kokius IP adresus turi naršyklės ir TCP kliento paketai?
- [x] Abiejų tie patys: iš `192.168.0.10` į `192.168.0.20`
- [ ] Naršyklė naudoja kitą paskirties IP adresą nei TCP klientas
- [ ] TCP kliento paketai neturi IP adreso
:::

:::quiz mc
Ar tada paskirties IP adreso pakanka, kad serveris žinotų, ar paketas skirtas žiniatinklio serveriui, ar echo paslaugai?
- [ ] Taip
- [x] Ne — abu paketai turi tą patį paskirties IP adresą
:::

Kažkas kita turi atskirti šiuos du ryšius. Pažiūrėk į paketų su `[SYN]` stulpelį **Info** — tai pirmasis kiekvieno ryšio paketas:

:::quiz short
Koks skaičius yra **naršyklės** atveju už rodyklės `→`?
= 80
:::

:::quiz short
O **TCP kliento** atveju?
= 5000
:::

:::evaluate
Patikrinti atsakymus
:::

Daugiau apie šiuos skaičius — **prievadus** (angl. *ports*) — sužinosi 5.3 skyriuje. Kol kas pakanka žinoti: tik transporto lygmuo leidžia kelioms programoms vienu metu bendrauti per *vieną* IP adresą ir užtikrina, kad kiekvienas paketas pasiektų tinkamą programą. Tai vadinama **multipleksavimu**.

## 2 eksperimentas: kai paketas pradingsta

1. Persijunk į :fa-play: **Vykdymo režimas** ir spustelėk **kabelį** tarp Client-PC ir Server.
2. Lange **Verbindung** nustatyk **Konfigurierter Paketverlust** reikšmę `25%`.
3. **Client-PC** atidaryk :fa-terminal: **Terminalas** ir išsiųsk šešis ping paketus:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Tai trunka apie pusę minutės — palauk, kol pasirodys statistika.

:::quiz mc
Kas nutinka?
- [ ] Atsakoma į visus šešis ping paketus
- [x] Kai kurie ping paketai lieka be atsakymo — ir niekas jų nesiunčia iš naujo
- [ ] Prarasti ping paketai automatiškai kartojami, kol pasiekia tikslą
:::

:::evaluate
Patikrinti atsakymą
:::

Ping atveju tai ne problema — juk jis ir skirtas parodyti, ar kas nors prarandama. Tačiau svetainės, el. laiško ar atsisiuntimo atveju trūkstama dalis būtų lemtinga: failas būtų sugadintas.

## Keturios transporto lygmens užduotys

| Užduotis | Ką tai reiškia |
|---|---|
| **Multipleksavimas** | Kelios programos ir ryšiai dalijasi vienu IP adresu; kiekvienas paketas patenka pas tinkamą programą. |
| **Ryšio užmezgimas** | Prieš pradedant siųsti duomenis, abi pusės susitaria, kad kalbėsis tarpusavyje. |
| **Patikimas perdavimas** | Gavėjas patvirtina, kas atkeliavo. Trūkstami duomenys siunčiami iš naujo, eiliškumas atkuriamas. |
| **Ryšio nutraukimas** | Pabaigoje abi pusės tvarkingai užbaigia ryšį. |

:::tip Svarbu įsiminti
**Transporto lygmuo** (4 lygmuo) užtikrina, kad duomenys pasiektų tinkamą **programą** (**multipleksavimas**). Protokolas **TCP** papildomai užtikrina, kad jie atkeliautų **pilni** ir **tinkama tvarka** — naudojant ryšio užmezgimą, patvirtinimus, pakartotinį siuntimą ir ryšio nutraukimą.
:::

:::quiz match
Kompiuteryje vienu metu veikia naršyklė, pašto programa ir susirašinėjimo programa. -> Multipleksavimas
Prieš pradedant siųsti duomenis, abi pusės įsitikina, kad kita pusė pasirengusi. -> Ryšio užmezgimas
Dalis failo nepasiekia tikslo ir siunčiama dar kartą. -> Patikimas perdavimas
Po atsisiuntimo abi pusės vėl atlaisvina ryšį. -> Ryšio nutraukimas
:::
