# Comment le DNS est organisé

:::sim
url=/sims/lesson-6.2.btsim
:::

Aucun serveur ne peut connaître à lui seul tous les noms du monde. C'est pourquoi le DNS est organisé de manière **hiérarchique**, tout comme les noms eux-mêmes. On les lit de droite à gauche :

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Le serveur qui est responsable d'un domaine et qui connaît réellement la réponse est dit **faisant autorité**. Pour le PC, c'est un **résolveur** qui se charge de trouver le chemin jusqu'à lui : ici, l'ordinateur **DNS-Resolver**.

## L'expérience

1. Passe en mode :fa-play: **Exécuter** et saisis dans le :fa-terminal: **Terminal** du **Client-PC** :
   ```
   $ nslookup www.beaver-schule.de
   ```
2. En mode :fa-magnifying-glass: **Trace**, ouvre une trace pour le **DNS-Resolver**.

Le résolveur a envoyé toute une série de requêtes pour toi. Associe chaque serveur à la réponse qu'il a donnée :

:::quiz match
Root-Server (192.168.0.101) -> Renvoi : ns.nic.de est responsable de .de
de-Server (192.168.0.102) -> Renvoi : ns.beaver-schule.de est responsable de beaver-schule.de
Schul-DNS (192.168.0.103) -> Réponse : www.beaver-schule.de a l'adresse 192.168.0.20
:::

:::quiz mc
Qui le résolveur interroge-t-il en premier ?
- [x] Le serveur racine
- [ ] Le Schul-DNS
- [ ] Le Client-PC
:::

:::evaluate
Vérifier les réponses
:::

:::note
Entre-temps, le résolveur demande aussi les adresses des serveurs vers lesquels il a été renvoyé (`A ns.nic.de`). Les vrais serveurs DNS envoient généralement ces adresses directement avec le renvoi. De plus, les résolveurs gardent chaque réponse en mémoire pendant un certain temps (**cache**) : ils répondent eux-mêmes immédiatement à la prochaine requête portant sur le même nom. La durée de conservation figure dans l'enregistrement sous la forme du **TTL** (*Time to Live*), en secondes.
:::

## Les principaux types d'enregistrements

| Type | Signification | Exemple |
|---|---|---|
| **A** | nom → adresse IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | nom → adresse IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | nom → autre nom (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | serveur de messagerie responsable d'un domaine | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | serveur DNS responsable d'un domaine | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip À retenir
Le DNS est **hiérarchique** : les **serveurs racine** renvoient vers les serveurs des **domaines de premier niveau** (par ex. `.de`), qui renvoient à leur tour vers les serveurs des différents **domaines**. Le serveur responsable, **faisant autorité**, connaît la réponse. Un **résolveur** parcourt ce chemin pour le PC et garde les réponses en mémoire (**cache**). Types d'enregistrements importants : **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Créer un enregistrement

L'école souhaite que son site web soit aussi accessible à l'adresse `intranet.beaver-schule.de`.

1. En mode :fa-play: **Exécuter**, clique sur le **Schul-DNS** et ouvre l'application **Serveur DNS**.
2. Ouvre l'onglet **A**. Clique sur **+** et saisis dans la nouvelle ligne le nom `intranet.beaver-schule.de` et l'adresse `192.168.0.20`.
3. Teste sur le Client-PC avec `nslookup intranet.beaver-schule.de`.
