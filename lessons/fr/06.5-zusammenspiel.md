# Tout ensemble : que se passe-t-il quand on ouvre une page web ?

:::goal
**Objectif d'apprentissage :** Tu sais expliquer étape par étape quels protocoles interviennent, et sur quelle couche, lorsqu'un ordinateur portable qui vient d'être allumé ouvre une page web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Tout ce que tu as appris dans ce cours se rejoint maintenant. Au switch sont reliés un **DHCP-Server**, un **DNS-Server**, un **Webserver** et un **Laptop** qui vient d'être allumé. Ce dernier n'a pas encore d'adresse IP et est configuré en DHCP.

## L'expérience

1. Passe en mode :fa-play: **Exécuter** et attends quelques secondes.
2. Clique sur le **Laptop**, ouvre le :fa-globe: **Navigateur** et accède à `http://www.beaver-schule.de/`.
3. En mode :fa-magnifying-glass: **Trace**, ouvre une trace pour le **Laptop**. Tu y trouveras toute l'histoire, dès le premier paquet.

Remets les étapes dans le bon ordre, tel qu'il apparaît dans la trace :

:::quiz match
Étape 1 -> DHCP : l'ordinateur portable obtient son adresse IP, sa passerelle et son serveur DNS
Étape 2 -> ARP : l'ordinateur portable demande l'adresse MAC du serveur DNS
Étape 3 -> DNS : l'ordinateur portable demande l'adresse IP de www.beaver-schule.de
Étape 4 -> ARP : l'ordinateur portable demande l'adresse MAC du serveur web
Étape 5 -> TCP : poignée de main en trois temps avec le serveur web
Étape 6 -> HTTP : GET / et la réponse 200 OK
:::

:::evaluate
Vérifier l'ordre
:::

Et sous tout cela se trouvent **IP** (couche 3), qui adresse chacun de ces paquets, et **Ethernet** (couche 2), qui l'achemine jusqu'à l'appareil suivant. Si le serveur web se trouvait dans un autre réseau, le **routeur** entrerait aussi en jeu : l'ordinateur portable demanderait alors l'adresse MAC de sa **passerelle**, et non celle du serveur web.

:::quiz mc
Pourquoi l'ordinateur portable ne peut-il envoyer la requête DNS qu'après DHCP ?
- [ ] Parce que DNS ne fonctionne que sur TCP
- [x] Parce que c'est DHCP qui lui attribue sa propre adresse IP et lui indique quel serveur DNS utiliser
- [ ] Parce que le serveur DNS ne démarre qu'après le serveur DHCP
:::

:::quiz mc
Combien de connexions TCP le navigateur établit-il avec le serveur web, et pourquoi ?
- [ ] Une seule, pour tout
- [x] Deux : une pour la page et une pour la feuille de style
- [ ] Aucune, HTTP n'a pas besoin de TCP
:::

:::evaluate
Vérifier les réponses
:::

:::tip À retenir
Derrière un simple clic, toutes les couches travaillent ensemble : **DHCP** fournit les paramètres de base, **ARP** trouve les adresses MAC dans le réseau local, **DNS** traduit le nom, **TCP** établit une connexion fiable et **HTTP** récupère la page, le tout emballé dans des paquets **IP** et des trames **Ethernet**.
:::

Tu es maintenant capable d'expliquer l'ouverture d'une page web du premier au dernier paquet. Pour clore ce chapitre, un bref aperçu d'autres protocoles va suivre.
