# Le problème des réponses

:::sim
url=/sims/lesson-9.2.btsim
:::

Le pare-feu fonctionne désormais selon le principe de la liste blanche : politique par défaut **Tout rejeter**. Une seule règle permet au réseau de l'école de naviguer sur le Web : **B → A, TCP, port de destination 80, Autoriser**. Le mode est réglé sur **Stateless**.

## L'expérience

1. Passe en mode :fa-play: **Exécuter** et ouvre `http://203.0.113.80/` dans le :fa-globe: **Navigateur** du **Lehrer-PC**.
2. Dans le **pare-feu**, regarde le **journal** et les **correspondances**.

:::quiz mc
Que se passe-t-il dans le navigateur ?
- [ ] La page de www.beispiel.de s'affiche
- [x] La page ne se charge pas, le navigateur attend et finit par signaler une erreur
:::

:::quiz mc
Quels paquets figurent comme rejetés (`DROP`) dans le journal du pare-feu ?
- [ ] Les requêtes du Lehrer-PC vers le port 80
- [x] Les réponses de `203.0.113.80` avec le **port source 80** à destination du Lehrer-PC
- [ ] Aucun
:::

:::quiz short
Dans quel sens (A→B ou B→A) circulent les paquets rejetés ?
= A→B
= A → B
= AtoB
:::

:::evaluate
Vérifier les réponses
:::

La requête du Lehrer-PC a le droit de sortir — mais dès le `SYN, ACK` du serveur Web, rien ne revient, car il n'existe aucune règle correspondante pour le sens A → B : c'est donc **Tout rejeter** qui s'applique.

## La solution naïve

On pourrait ajouter une deuxième règle : **A → B, TCP, port source 80, Autoriser** — « tout ce qui vient du port 80 a le droit d'entrer ». La navigation fonctionne alors effectivement.

:::quiz mc
Pourquoi cette règle est-elle dangereuse ?
- [ ] Parce que les serveurs Web n'utilisent jamais le port 80 comme port source
- [x] Un attaquant peut tout simplement envoyer ses paquets avec le port source 80 — le pare-feu les laisse alors passer vers **n'importe quel** port du réseau de l'école
- [ ] Parce que les pages Web se chargent alors plus lentement
:::

:::evaluate
Vérifier la réponse
:::

C'est l'expéditeur lui-même qui fixe le port source — un pare-feu ne doit donc pas s'y fier. Or, un pare-feu sans état ne sait pas si un paquet est la **réponse à une requête** ou une **nouvelle tentative de connexion** venant de l'extérieur. C'est précisément ce que change le mode avec état.

:::tip À retenir
Un filtre de paquets **sans état** examine chaque paquet individuellement. Les réponses nécessitent alors leurs propres règles pour le sens retour — et de telles règles (par ex. « le port source 80 a le droit d'entrer ») peuvent être exploitées par des attaquants, car l'expéditeur peut choisir librement le port source.
:::
