# Attaque : usurpation DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna veut ouvrir sa banque en ligne à la **Biberbank** sur le **Client-PC**. Ce qu'elle ne sait pas : quelqu'un a obtenu un accès au **DNS-Server** et a modifié une entrée.

Dans l'espace de travail, tu vois le vrai serveur web **www.biberbank.de** et l'ordinateur d'un attaquant (**Angreifer**). Une copie du site web de la banque tourne sur cet ordinateur.

## Partie 1 : sans chiffrement

Passe en mode :fa-play: **Exécution** et, sur le **Client-PC**, ouvre `http://www.biberbank.de/` dans le :fa-globe: **Navigateur**.

:::quiz mc
Que vois-tu ?
- [x] La page de connexion de la Biberbank, sans aucun avertissement
- [ ] Un avertissement indiquant que la page est falsifiée
- [ ] Un message d'erreur
:::

:::evaluate
Vérifier la réponse
:::

Tout semble normal. Mais avec quel serveur le navigateur communique-t-il vraiment ? Sur le Client-PC, ouvre le :fa-terminal: **Terminal** :

```
$ nslookup www.biberbank.de
```

:::quiz short
Quelle adresse IP le serveur DNS renvoie-t-il pour `www.biberbank.de` ?
= 192.168.0.66
:::

:::quiz mc
À qui appartient cette adresse ? (En mode Édition, clique sur les appareils ou consulte leurs :fa-gear: **Paramètres IP**.)
- [ ] Au vrai serveur web de la Biberbank
- [x] À l'attaquant
- [ ] Au serveur DNS
:::

:::evaluate
Vérifier les réponses
:::

Si Anna avait saisi son numéro de compte et son code PIN, ils seraient arrivés directement chez l'attaquant. Avec **HTTP**, elle n'a **aucune chance** de remarquer l'arnaque : la barre d'adresse affiche le bon nom et la page a l'air authentique.

## Partie 2 : avec HTTPS

Ouvre maintenant `https://www.biberbank.de/`.

:::quiz mc
Que se passe-t-il ?
- [ ] La fausse page s'affiche avec un cadenas
- [x] Le navigateur avertit : le certificat a été délivré pour un autre nom
- [ ] La vraie page de la Biberbank s'affiche
:::

:::quiz short
Pour quel nom le certificat de l'attaquant a-t-il été délivré (sans `CN=`) ?
= www.biber-gewinnspiel.de
:::

:::evaluate
Vérifier les réponses
:::

L'attaquant possède même un **vrai** certificat délivré par une CA de confiance — mais pour son propre domaine `www.biber-gewinnspiel.de`. Aucune CA ne lui délivrera de certificat pour `www.biberbank.de`, car ce domaine ne lui appartient pas. Et sans la **clé privée** de la Biberbank, il ne peut pas non plus utiliser son vrai certificat : lors du handshake, il devrait signer le Server Key Exchange avec cette clé.

:::quiz multi
Contre quoi HTTPS protège-t-il ici — et contre quoi ne protège-t-il pas ?
- [x] HTTPS révèle que le serveur n'est pas le vrai
- [ ] HTTPS empêche que le serveur DNS soit falsifié
- [x] HTTPS n'aide que si l'utilisateur prend l'avertissement au sérieux
- [ ] Avec HTTPS, la fausse page n'est pas du tout accessible
:::

:::evaluate
Vérifier les réponses
:::

## Partie 3 : réparer le serveur DNS

Ouvre le **DNS-Server** et corrige l'entrée pour `www.biberbank.de`. Tu trouveras la bonne adresse dans les :fa-gear: **Paramètres IP** du serveur web **www.biberbank.de**. N'oublie pas de cliquer sur **Enregistrer**.

:::note
Le Client-PC garde en mémoire les réponses DNS pendant un certain temps pour ne pas avoir à redemander à chaque accès (**cache DNS**). La durée, en secondes, est indiquée dans la colonne **TTL** (*Time to Live*). Si `nslookup` renvoie encore l'ancienne adresse juste après ta correction, attends que le TTL soit écoulé et réessaie.
:::

:::task
title: La Biberbank est-elle de nouveau authentique ?
Vérifie si le Client-PC résout www.biberbank.de vers la bonne adresse et peut récupérer la page via HTTPS sans avertissement.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Dans la réalité, un attaquant falsifie rarement le serveur DNS lui-même. Le plus souvent, il glisse ses propres réponses sur un Wi-Fi public, modifie les paramètres d'un routeur domestique ou attire ses victimes avec une adresse ressemblante comme `www.biberbank-login.de` (**hameçonnage**, ou *phishing*). Contre un nom ressemblant, même HTTPS n'aide pas — l'attaquant obtient pour celui-ci un certificat valide. Donc : lis attentivement l'adresse !
:::

:::tip À retenir
Lors d'une **usurpation DNS**, le serveur DNS renvoie pour un nom l'adresse d'un attaquant. Avec **HTTP**, on ne remarque rien. Avec **HTTPS**, le certificat de l'attaquant ne correspond pas au nom demandé, et le navigateur **avertit** — car aucune CA ne délivre de certificat pour des domaines appartenant à d'autres, et l'attaquant ne possède pas la clé privée du vrai serveur.
:::
