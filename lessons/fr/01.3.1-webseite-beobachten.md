# Charger une page web et observer

Pour cette partie, tu ne construis rien toi-même : dans l'espace de travail se trouve une simulation préparée avec un **Client-PC** et un **Webserver**.

## Charger la page

1. Passe en mode :fa-play: **Exécution**.
2. Sur le **Client-PC**, ouvre l'application :fa-globe: **Navigateur** et saisis l'adresse du serveur web : `http://192.168.0.20/`.
3. Passe en mode :fa-magnifying-glass: **Trace** et utilise **+** pour ouvrir une trace pour le **Client-PC**, interface `eth0` — exactement comme pour le ping.

:::note
Cela fait étonnamment beaucoup de paquets pour un seul chargement de page — nettement plus que pour le ping. Récupérer une page web est un processus en plusieurs étapes, pas une action unique.
:::

## Lire la liste des paquets

Tu n'as pas encore besoin de savoir ce que fait exactement chaque protocole. Tout ce qu'il te faut pour les questions suivantes se trouve dans les colonnes **Protocole** et **Info**.

:::quiz mc
Quel protocole se trouve tout en haut de la liste ?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Compte : combien de paquets **TCP** y a-t-il avant le premier paquet **HTTP** ?
= 3
= trois
:::

:::quiz mc
Que répond le serveur web à la requête du navigateur ? Regarde dans la colonne Info du deuxième paquet HTTP.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Vérifier les réponses
:::

## Identifier les protocoles impliqués

À partir de tes observations, tu peux maintenant déduire quel protocole était responsable de quoi.

:::tip Astuce
Relis encore une fois les colonnes **Info** : `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` et `200 OK` en disent déjà presque tout.
:::

:::quiz match
ARP -> Demande à tout le monde dans le réseau : « Qui a l'adresse IP 192.168.0.20 ? »
TCP -> Établit une connexion avec trois courts paquets avant que les données ne circulent
HTTP -> Demande la page web (GET) et la renvoie (200 OK)
:::

:::evaluate
Vérifier les associations
:::

:::tip À retenir
Le chargement d'une page web se déroule par étapes : d'abord **trouver** le serveur dans le réseau (ARP), puis **établir** une connexion (TCP), ensuite **demander et livrer** la page (HTTP) — et pour finir **fermer** la connexion (les paquets TCP avec `[FIN]` à la fin de la liste).
:::

:::note
Cette fois, tu as saisi directement l'adresse IP du serveur, c'est pourquoi le **DNS** (la « traduction » de noms comme `www.beispiel.de` en adresse IP) n'a pas encore été utilisé. Nous y reviendrons au chapitre 6.
:::

As-tu remarqué que les protocoles dans la structure des paquets portent des repères colorés avec des numéros ? Ce que cela signifie, nous le verrons au chapitre 2. Nous y verrons comment classer systématiquement tous ces protocoles — avec le modèle de référence OSI et le modèle TCP/IP. Et voilà, le chapitre 1 est terminé.
