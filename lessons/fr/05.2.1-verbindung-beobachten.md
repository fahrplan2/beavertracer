# Une connexion du début à la fin

:::sim
url=/sims/lesson-5.1.btsim
:::

Sur le **Server**, le service d'écho tourne sur le port `5000` : il renvoie immédiatement chaque message. Avec le **Client TCP simple**, tu peux piloter une connexion étape par étape — chaque bouton correspond à une phase.

## L'expérience

1. Passe en mode :fa-play: **Exécuter**, clique sur le **Client-PC** et ouvre le **Client TCP simple**.
2. Saisis `192.168.0.20` dans **Host** et `5000` dans **Port**.
3. Clique sur **Connecter**.
4. Tape `Hello World` dans le champ de message et clique sur **Envoyer**. Juste après, tu vois l'écho du serveur dans la fenêtre de chat.
5. Clique sur **Déconnecter**.
6. Passe en mode :fa-magnifying-glass: **Trace** et ouvre avec **+** une trace pour le **Client-PC**, interface `eth0`.

:::note
Tu connais déjà les deux paquets ARP du début grâce au chapitre 1. Dans la colonne **Info** des paquets TCP figure d'abord `49152 → 5000` (de quel port vers quel port), puis entre crochets les **flags** et ensuite des nombres comme `Seq=`, `Ack=` et `Len=`. Les nombres seront abordés à partir de la page 5.2.3 — ici, tu t'intéresses aux flags et à `Len`.
:::

## Phase 1 : connexion

:::quiz short
Combien de paquets TCP ont été échangés après que tu as cliqué sur **Connecter** — avant que ton message ne parte ?
= 3
= trois
:::

:::quiz mc
Qui envoie le premier paquet avec `[SYN]` ?
- [x] Le Client-PC
- [ ] Le Server
:::

:::quiz mc
Avec quels flags le serveur y répond-il ?
- [ ] `[SYN]`
- [x] `[SYN, ACK]`
- [ ] `[ACK]`
- [ ] `[FIN, ACK]`
:::

## Phase 2 : envoi

`Len` indique combien d'octets de données utiles un paquet transporte.

:::quiz short
Combien d'octets transporte le paquet contenant ton message (`Len`) ?
= 13
:::

:::note
`Hello World` ne compte que 11 caractères. Mais le client TCP ajoute une fin de ligne (2 octets, `\r\n`) — c'est ce qu'attendent de nombreux protocoles Internet comme SMTP ou HTTP.
:::

:::quiz mc
Qu'est-ce que le serveur renvoie juste après ton message — avant même l'écho ?
- [x] Un paquet avec `[ACK]` et `Len=0` — un acquittement sans données
- [ ] Rien du tout
- [ ] Un nouveau `[SYN]`
:::

## Où se cachent les quatre tâches ?

Associe chacune des tâches de la section 5.1 à l'endroit où tu la retrouves dans la trace :

:::quiz match
Établissement de la connexion -> Les trois paquets [SYN], [SYN, ACK] et [ACK]
Transmission fiable -> Les paquets avec [ACK] et Len=0 qui acquittent la réception
Fermeture de la connexion -> Les paquets avec FIN et leurs acquittements
Multiplexage -> Les numéros de port 49152 → 5000 avant les crochets
:::
