1. Passe en mode :fa-play: **Exécuter**, clique sur le **Client-PC** et ouvre le :fa-globe: **Navigateur**. Ouvre `http://192.168.0.20/`.
2. Clique sur **Retour** en haut de la fenêtre, ouvre le **Client TCP simple** et connecte-le à `192.168.0.20`, port `5000`. Laisse la connexion ouverte.

Tout en haut de l'en-tête TCP figurent deux ports : **Source Port** (port source) et **Destination Port** (port de destination).

## Deux sortes de ports

**Port de destination — le service :** un programme serveur attend des connexions sur un port fixe — on dit qu'il y est **en écoute**. Pour les services connus, les numéros sont fixés dans le monde entier : ce sont les **ports bien connus** (well-known ports, de 0 à 1023). C'est pourquoi un navigateur sait sans avoir à demander que les serveurs web écoutent sur le port 80.

**Port source — l'expéditeur :** le port côté client est choisi par le système d'exploitation lui-même pour chaque nouvelle connexion, dans une plage élevée (dans BeaverTracer à partir de 49152). Grâce à lui, le client reconnaît à laquelle de ses connexions appartient une réponse.

Une connexion est donc définie de manière unique par quatre informations : **l'adresse IP et le port des deux côtés**. Le couple adresse IP et port s'appelle un **socket**, par exemple `192.168.0.20:80`.

## Un coup d'œil sur le serveur

Repasse en mode :fa-play: **Exécuter**, ouvre le :fa-terminal: **Terminal** sur le **Server** et saisis :

```
$ ss
```

`ss` affiche tous les sockets de l'ordinateur. Les lignes avec `LISTEN` correspondent à des programmes en écoute sur un port. Les lignes avec `ESTABLISHED` sont des connexions établies — avec le socket local (*Local Address:Port*) et le socket de l'autre côté (*Peer Address:Port*).

:::quiz multi

- [ ] 443
:::

- [ ] `192.168.0.20:80` avec `192.168.0.10:49152` — la connexion du navigateur

:::note
La connexion du navigateur est déjà fermée — après le chargement de la page, elle a été terminée avec `FIN`. `ss` l'affiche encore brièvement comme `TIME-WAIT` : le serveur attend un moment au cas où des paquets retardés de cette connexion arriveraient encore. La connexion du client TCP, en revanche, est toujours ouverte, car tu n'as pas encore cliqué sur **Déconnecter**.
:::

## Les principaux ports bien connus

| Port | Protocole | Service |
|---|---|---|
| 22 | SSH | administration à distance sécurisée (ligne de commande chiffrée) |
| 25 | SMTP | envoyer des e-mails |
| 53 | DNS | traduire des noms en adresses IP (généralement via UDP) |
| 80 | HTTP | pages web |
| 110 | POP3 | récupérer des e-mails |
| 143 | IMAP | gérer des e-mails sur le serveur |
| 443 | HTTPS | pages web chiffrées |

:::tip À retenir
Les **ports** (de 0 à 65535) permettent de distinguer les connexions sur un ordinateur. Les services serveur sont **en écoute** sur des **ports bien connus** fixes (par exemple HTTP 80, HTTPS 443), tandis que les clients reçoivent pour chaque connexion un **port source** élevé libre. Une connexion est définie de manière unique par **l'adresse IP et le port des deux côtés**.
:::

:::
