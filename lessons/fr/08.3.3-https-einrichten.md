# Configurer HTTPS

:::sim
url=/sims/lesson-8.3.3.btsim
:::

On reprend ici là où la section 8.2.2 s'est arrêtée : sur le serveur web **www.beaver-schule.de** se trouvent la **Schul-CA** et un certificat serveur qu'elle a émis, et le **Client-PC** fait confiance à la Schul-CA. Seulement, le serveur web ne parle pas encore HTTPS.

## Avant

Passe en mode :fa-play: **Exécuter** et, sur le **Client-PC**, ouvre `https://www.beaver-schule.de/` dans le :fa-globe: **Navigateur**.

:::quiz mc
Que se passe-t-il ?
- [x] La connexion n'aboutit pas — aucun service n'écoute sur le port 443
- [ ] Le navigateur affiche un avertissement concernant un certificat non sécurisé
- [ ] La page s'affiche sans cadenas
:::

:::evaluate
Vérifier la réponse
:::

## Activer HTTPS

1. Sur le serveur web, ouvre le **Serveur HTTP** et clique sur **Arrêter** — tant que le serveur tourne, les paramètres ne peuvent pas être modifiés.
2. Passe dans l'onglet **HTTPS** :
    - Coche **Activer HTTPS**, **Port HTTPS** `443`
    - Dans **Certificat**, sélectionne le certificat serveur `www.beaver-schule.de` — pas la Schul-CA !
    - Clique sur **Utiliser**
3. Clique sur **Démarrer**.

Ouvre à nouveau la page sur le Client-PC via `https://`. Clique sur le cadenas et vérifie l'émetteur et la validité.

:::quiz mc
Pourquoi ne dois-tu pas sélectionner le certificat de la **Schul-CA** dans le serveur HTTP ?
- [ ] Parce que les certificats de CA ne peuvent pas chiffrer
- [x] Parce qu'il est émis pour le nom `Schul-CA` et non pour `www.beaver-schule.de` — le navigateur afficherait un avertissement
- [ ] Parce que la Schul-CA n'a pas de clé privée
:::

:::quiz mc
Que verrait un appareil qui ne fait **pas** confiance à la Schul-CA, par exemple le téléphone d'un invité ?
- [ ] La page tout à fait normalement, avec le cadenas
- [x] Un avertissement de certificat, car il ne peut pas remonter la chaîne de confiance jusqu'à une CA connue
- [ ] Rien du tout, car la connexion est refusée
:::

Vérifier les réponses
:::

:::note
Pour les sites web publics, il faut un certificat émis par une CA préinstallée dans tous les navigateurs. Depuis 2015, **Let's Encrypt** est une CA qui délivre ce type de certificats gratuitement et automatiquement — l'une des principales raisons pour lesquelles presque tous les sites web utilisent aujourd'hui HTTPS.
:::

:::tip À retenir
Pour **HTTPS**, le serveur web a besoin d'un **certificat serveur avec sa clé privée**, dont le nom correspond à l'adresse, et il doit écouter sur le **port 443**. Le client ne fait confiance au site que s'il connaît la **CA** émettrice.
:::
