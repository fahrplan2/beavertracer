# Numéros de séquence et d'acquittement

:::sim
url=/sims/lesson-5.1.btsim
:::

Comment TCP sait-il si tout est arrivé, et dans quel ordre ? Chaque côté **numérote les octets** qu'il envoie :

- Le **numéro de séquence** (`SEQ`) est le numéro du premier octet contenu dans ce paquet.
- Le **numéro d'acquittement** (`ACK`) dit : « J'ai tout reçu jusqu'ici ; j'attends maintenant l'octet n° … »

Deux règles s'y ajoutent : `SYN` et `FIN` comptent comme un octet, même s'ils ne transportent pas de données. Et chaque côté compte de son côté : c'est pourquoi il y a deux séries de numéros, en rouge (client) et en bleu (serveur) dans le diagramme.

## Faire le calcul

Voici encore une fois ta connexion. Les nombres sur les lignes indiquent le compteur de l'ordinateur à cet endroit :

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Parcours la série de nombres en rouge :

1. Le client commence à `SEQ=0`. Son `SYN` consomme un numéro : le serveur acquitte avec `ACK=1`.
2. Le message commence à `SEQ=1` et fait 13 octets (octets 1 à 13). Le serveur acquitte avec `ACK=14` : « J'attends maintenant l'octet 14. »
3. Le `FIN` du client a donc `SEQ=14` et est acquitté avec `ACK=15`.

La série bleue du serveur fonctionne exactement de la même manière.

:::tip À retenir
Le **numéro de séquence** (`SEQ`) est le numéro du premier octet du paquet. Le **numéro d'acquittement** (`ACK`) est le numéro du prochain octet attendu par le destinataire : tout ce qui précède est arrivé. La règle est : **ACK = SEQ + longueur** des données reçues ; `SYN` et `FIN` comptent comme un octet. Chaque côté compte ses propres octets.
:::

:::tip Essaie
Établis à nouveau la connexion dans le **Client TCP simple** et envoie deux messages l'un après l'autre. Prédis à l'avance quels `Seq` et `Ack` apparaîtront dans la colonne **Info**, puis vérifie-le dans la trace.
:::

:::note
Dans les vrais réseaux, le comptage ne commence pas à 0 : chaque côté choisit un **numéro de départ aléatoire** (*Initial Sequence Number*, ISN) compris entre 0 et environ 4,3 milliards. Une fois le numéro le plus élevé atteint, on repart de 0. Le traceur soustrait le numéro de départ et affiche des numéros **relatifs**, exactement comme Wireshark. C'est pourquoi tu vois `Seq=0` et `Seq=1`.

De plus, chaque paquet contient `Win=` : la **taille de fenêtre**, c'est-à-dire le nombre d'octets que le destinataire peut recevoir en ce moment. Il peut ainsi freiner un expéditeur trop rapide (*contrôle de flux*). Dans BeaverTracer, la fenêtre a toujours la même taille.
:::
