# Dépannage : le nom ne fonctionne pas

:::sim
url=/sims/lesson-6.2.3.btsim
:::

Une enseignante signale : « `www.beaver-schule.de` ne se charge pas chez moi. Mais avec `http://192.168.0.20`, ça marche ! » Voici comment la configuration *devrait* être :

| Quoi | Valeur attendue |
|---|---|
| Serveur DNS sur le Client-PC | `192.168.0.53` (DNS-Resolver) |
| Entrée dans le Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Trouve les erreurs et corrige-les.

<details>
<summary>Astuce 1 : que dit nslookup ?</summary>

Saisis `nslookup www.beaver-schule.de` sur le Client-PC. Quel serveur `nslookup` a-t-il interrogé, et qu'est-ce qui est revenu ? (La réponse met quelques secondes à arriver.)
</details>

<details>
<summary>Astuce 2 : et maintenant ?</summary>

Si tu obtiens une réponse, compare l'adresse avec le plan. Où ce nom est-il enregistré ?
</details>

:::task
title: Résolution de noms réparée ?
Vérifie que le Client-PC résout www.beaver-schule.de vers la bonne adresse. Pour cela, la simulation doit tourner en mode Exécution.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Que s'est-il passé ?

:::quiz multi
Quelles affirmations sont exactes ?
- [x] Sur le Client-PC, `192.168.0.35` était configuré comme serveur DNS ; personne ne répond à cette adresse
- [x] Dans le Schul-DNS, `www.beaver-schule.de` pointait vers `192.168.0.21` au lieu de `192.168.0.20`
- [ ] Le serveur web était éteint
- [ ] Le serveur racine ne connaissait pas le domaine `.de`
:::

:::evaluate
Vérifier la réponse
:::

:::tip À retenir
Si une connexion fonctionne avec l'**adresse IP** mais pas avec le **nom**, le problème vient du **DNS**. Vérifie d'abord le **serveur DNS configuré** (répond-il seulement ?), puis l'**entrée** elle-même (l'adresse est-elle correcte ?). `nslookup` montre les deux : quel serveur a été interrogé et ce qu'il a répondu.
:::
