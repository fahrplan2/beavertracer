# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) est tout simplement du HTTP normal, sauf qu'il ne passe pas directement par TCP : il traverse une couche chiffrée intermédiaire, **TLS** (*Transport Layer Security*). Le prédécesseur de TLS s'appelait **SSL** ; c'est pourquoi on parle encore souvent de « certificats SSL ».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP ne s'en rend pas compte : il envoie ses requêtes comme d'habitude, TLS les chiffre et TCP les transporte. Dans le modèle OSI, TLS se situe entre la couche transport et la couche application, donc aux couches 4/5. Il s'appuie sur TCP et gère une session sécurisée.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresse | `http://…` | `https://…` |
| Contenu lisible dans le Tracer ? | oui | non |
| Le navigateur affiche | « non sécurisé » | un cadenas |

Lors de l'établissement de la connexion, TLS s'occupe de tout ce que tu as appris dans ce chapitre :

- Le serveur s'identifie avec son **certificat** (**authenticité**).
- Les deux parties négocient une **clé de session** avec **Diffie-Hellman**, et le serveur **signe** sa part.
- Ensuite, toutes les données sont chiffrées avec **AES** (**confidentialité**) et protégées contre toute modification (**intégrité**).

Le principe ne se limite pas au Web : l'e-mail (section 8.4) et de nombreux autres protocoles passent eux aussi par TLS de la même manière.
