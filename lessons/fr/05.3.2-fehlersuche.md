# Dépannage : le service ne répond pas

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Après une mise à jour, l'école signale : « Le service d'écho refuse toutes les connexions, et la page web ne se charge plus non plus. » D'après le plan, le **serveur web** doit écouter sur le port `80` et le **service d'écho** (Serveur TCP d'écho) sur le port `5000`. Trouve les erreurs et corrige-les.

<details>
<summary>Indice 1 : que répond le serveur ?</summary>

Essaie de te connecter à `192.168.0.20`, port `5000`, avec le **Client TCP simple**, et ouvre une trace pour le Client-PC. Que répond le serveur à ton `[SYN]` ?
</details>

<details>
<summary>Indice 2 : quels ports sont ouverts ?</summary>

Sur le Client-PC, saisis `nmap -p 80,5000 192.168.0.20` dans le terminal. `nmap` teste les ports les uns après les autres et indique lesquels sont ouverts. Avec `ss` sur le serveur, tu vois sur quels ports un programme écoute réellement.
</details>

<details>
<summary>Indice 3 : où cela se règle-t-il ?</summary>

Sur le **Server**, ouvre les applications **Serveur TCP d'écho** et **Serveur HTTP**. Le service est-il en cours d'exécution ? Et sur quel port ?
</details>

:::task
title: Services joignables ?
Vérifie si le Client-PC peut joindre le service d'écho sur le port 5000 et le serveur web sur le port 80. Pour cela, la simulation doit tourner en mode Exécution.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Que s'est-il passé ?

:::quiz multi
Quelles affirmations sont vraies ?
- [x] Au `[SYN]` envoyé sur le port 5000, le serveur a répondu par `[RST, ACK]`
- [x] Le service d'écho écoutait sur le port 5050 au lieu du port 5000
- [x] Le serveur web n'était pas du tout démarré
- [ ] Le câble entre le Client-PC et le Server était défectueux
:::

:::evaluate
Vérifier la réponse
:::

:::tip À retenir
Si un `SYN` reçoit un **`RST`** en réponse, **aucun programme** n'écoute sur ce port : l'ordinateur est joignable, mais pas le service. Causes typiques : le service **n'est pas démarré** ou écoute sur un **autre port**. Un coup d'œil avec `ss` sur le serveur montre quels ports sont réellement ouverts.
:::
