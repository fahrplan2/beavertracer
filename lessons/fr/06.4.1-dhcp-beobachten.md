# Obtenir une adresse automatiquement

:::sim
url=/sims/lesson-6.4.btsim
:::

Un **DHCP-Server** et deux ordinateurs portables sont connectés au switch. Pour l'instant, les portables ont encore des adresses fixes.

## L'expérience

1. Passe en mode :fa-play: **Exécuter**, clique sur **Laptop 1** et ouvre les :fa-gear: **Paramètres IP**.
2. Fais passer le **Mode** de **Statique** à **DHCP** et clique sur **Appliquer**.
3. Attends quelques secondes : les champs se remplissent tout seuls.
4. En mode :fa-magnifying-glass: **Trace**, ouvre une trace pour **Laptop 1**.

:::quiz table
| Paramètre | reçu du serveur DHCP |
|---|---|
| Adresse IP | {192.168.0.100} |
| Passerelle | {192.168.0.1} |
| Serveur DNS | {192.168.0.53} |
:::

:::quiz short
Combien de paquets DHCP trouves-tu dans la trace ?
= 4
= quatre
:::

:::quiz mc

- [ ] Au serveur DHCP `192.168.0.2`
- [x] À `255.255.255.255` — à tout le monde (diffusion/broadcast)

## Ce qui se cache derrière : DORA

Un appareil sans adresse ne sait pas où se trouve le serveur DHCP et n'a pas non plus sa propre adresse d'expéditeur. Il lance donc un appel dans le réseau par **diffusion** (*broadcast*). Le déroulement comporte quatre étapes — appelées **DORA** d'après leurs initiales :

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | « Y a-t-il un serveur DHCP ici ? »
DHCP-Server -> Laptop 1: DHCP Offer | « Tu peux avoir 192.168.0.100. »
Laptop 1 -> DHCP-Server: DHCP Request | « Je prends 192.168.0.100. »
DHCP-Server -> Laptop 1: DHCP ACK | « Confirmé — valable 3600 secondes. »
:::

L'adresse n'est que **prêtée** (*lease*, ou bail) : à l'expiration de la **durée du bail**, l'appareil doit la renouveler, sinon le serveur a le droit de l'attribuer à nouveau. Tu peux voir quelles adresses sont actuellement attribuées dans le **Serveur DHCP**, dans l'onglet **Leases**.

:::tip Essaie
Configure aussi **Laptop 2** en DHCP. Quelle adresse obtient-il ? Regarde ensuite les **Leases** du serveur DHCP.
:::

:::tip À retenir
**DHCP** distribue automatiquement l'adresse IP, le masque de sous-réseau, la passerelle et le serveur DNS. Le déroulement s'appelle **DORA** : **D**iscover (le client cherche par diffusion), **O**ffer (le serveur fait une offre), **R**equest (le client accepte), **A**CK (le serveur confirme). L'adresse est prêtée pour la **durée du bail**. DHCP utilise **UDP**, port 67 (serveur) et 68 (client).
:::

:::quiz match
Discover -> Le client cherche un serveur DHCP par diffusion
Offer -> Le serveur propose une adresse
Request -> Le client demande l'adresse proposée
ACK -> Le serveur confirme l'attribution
:::
