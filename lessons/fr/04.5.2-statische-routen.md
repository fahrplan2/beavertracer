# Ajouter des routes statiques

:::sim
url=/sims/lesson-4.5.2.btsim
:::

Cette fois, il y a **deux** routeurs entre l'entreprise A et l'entreprise B. Ils sont reliés par leur propre petit réseau, le **réseau intermédiaire** `10.0.0.0/30` :

| Routeur | Interface | Adresse IP | Réseau |
|---|---|---|---|
| Router A | `eth0` | `192.168.0.1/24` | Entreprise A (Anna) |
| Router A | `eth1` | `10.0.0.1/30` | Réseau intermédiaire |
| Router B | `eth0` | `10.0.0.2/30` | Réseau intermédiaire |
| Router B | `eth1` | `172.16.0.1/24` | Entreprise B (Clara) |

:::note
Un réseau `/30` possède exactement deux adresses utilisables, ce qui est parfait pour relier deux routeurs (voir la section 4.2.3).
:::

## Le problème

Passe en mode Exécution avec :fa-play: **Exécuter** et, depuis **Anna**, envoie un ping à Clara (`ping 172.16.0.10`). Clara ne répond pas. C'est Router A (`192.168.0.1`) qui répond à sa place avec le message « Réseau de destination inaccessible ».

Regarde la **Table de routage IPv4** de **Router A**.

:::quiz mc
Pourquoi le ping d'Anna n'arrive-t-il pas jusqu'à Clara ?
- [ ] Anna n'a pas de passerelle configurée
- [x] Router A ne connaît pas le réseau `172.16.0.0/24` : il n'y est pas directement connecté et aucune route n'y mène
- [ ] Le réseau intermédiaire est trop petit
:::

:::evaluate
Vérifier la réponse
:::

## Ajouter la route

Router A doit apprendre que les paquets destinés à `172.16.0.0/24` doivent être envoyés à Router B (`10.0.0.2`), via `eth1`.

1. Sur **Router A**, ouvre l'onglet **Table de routage IPv4** et clique sur **+ ajouter**.
2. Remplis la nouvelle ligne : **Destination** `172.16.0.0`, **Masque de sous-réseau** `255.255.255.0`, **Prochain saut** `10.0.0.2`, **Iface** `eth1`.
3. Enregistre la ligne avec la coche :fa-check:. La colonne **Source** affiche maintenant **Statique**.

Envoie à nouveau un ping à Clara : cette fois, la réponse arrive.

:::note
Router B connaît d'ailleurs déjà le chemin du retour vers l'entreprise A : sa table de routage contient déjà une route statique vers `192.168.0.0/24` via `10.0.0.1`. Tu verras à la page suivante pourquoi ce chemin de retour est tout aussi important.
:::

## Suivre le chemin : traceroute

La commande `traceroute` affiche les routeurs par lesquels passe un paquet. Saisis sur **Anna** :

```
$ traceroute 172.16.0.10
```

:::quiz short
Par combien de routeurs passe le paquet entre Anna et Clara ?
= 2
= deux
:::

:::quiz mc
Quelle adresse `traceroute` affiche-t-il pour Router B ?
- [x] `10.0.0.2` : son adresse dans le réseau intermédiaire, par laquelle le paquet arrive
- [ ] `172.16.0.1` : son adresse dans l'entreprise B
- [ ] `192.168.0.1`
:::

:::evaluate
Vérifier les réponses
:::

`traceroute` exploite une astuce liée au **Time to Live** vu dans la section 4.3.1. Il envoie d'abord un paquet avec un TTL de 1. Le premier routeur retire 1 et arrive à 0. Il rejette alors le paquet et le signale à l'expéditeur, ce qui permet à Anna de connaître le premier routeur. Il envoie ensuite un paquet avec un TTL de 2 pour le deuxième routeur, et ainsi de suite, jusqu'à ce que la destination réponde.

:::tip À retenir
Une **route statique** est ajoutée manuellement par l'administrateur. Elle comprend le réseau de destination, le masque de sous-réseau, le prochain saut et l'interface. Avec **traceroute**, on peut suivre le chemin d'un paquet, routeur par routeur.
:::
