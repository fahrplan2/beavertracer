# HTTP à la main

:::sim
url=/sims/lesson-6.1.btsim
:::

Si HTTP n'est que du texte, peut-on aussi parler soi-même à un serveur web, sans aucun navigateur ? Oui : avec `telnet`, tu établis une connexion TCP vers n'importe quel port et tu tapes le texte toi-même.

## L'expérience

1. Passe en mode :fa-play: **Exécution** et ouvre le :fa-terminal: **Terminal** sur le **Client-PC**.
2. Connecte-toi au port 80 du serveur :
   ```
   $ telnet 192.168.0.20 80
   ```
3. Tape la requête ligne par ligne et termine-la par une **ligne vide** (appuie simplement encore une fois sur **Entrée**) :
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

Le serveur répond avec une ligne de statut, des en-têtes et la page de contact, sous forme de texte, exactement comme le navigateur la reçoit.

:::quiz mc
À quoi le serveur reconnaît-il que ta requête est terminée ?
- [ ] À une commande spéciale `END`
- [x] À la ligne vide
- [ ] Au bout d'un certain temps
:::

:::quiz short
Quelle valeur figure dans l'en-tête `Content-Type` de la réponse ? (seulement la première partie avant le `;`)
= text/html
:::

## Provoquer des erreurs

`curl` est un outil plus pratique : il envoie la requête à ta place. Avec `-v` (*verbose*, détaillé), il affiche tout ce qui transite dans les deux sens : les lignes commençant par `>` ont été envoyées par `curl`, celles commençant par `<` viennent du serveur.

Essaie :

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
Quel code de statut obtiens-tu pour `/gibtsnicht.html` ?
= 404
:::

:::quiz short
Et lequel pour la requête avec la méthode `POST` ?
= 405
:::

:::evaluate
Vérifier les réponses
:::

:::note
Le serveur web de BeaverTracer ne peut que fournir des fichiers ; c'est pourquoi il n'autorise que `GET` et `HEAD`. Les vrais serveurs web reçoivent par exemple des formulaires avec `POST` et transmettent les données à un programme.
:::

:::tip À retenir
De nombreux protocoles de la couche application sont **textuels** : HTTP, mais aussi SMTP, POP3 et IMAP. On peut donc les parler à la main avec `telnet` et les lire en direct dans le traceur. C'est pratique pour le dépannage, mais c'est aussi un problème de sécurité : quiconque intercepte le trafic peut tout lire. Tu découvriras au chapitre 8 comment le chiffrement (HTTPS) y remédie.
:::
