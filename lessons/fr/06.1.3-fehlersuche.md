# Dépannage : la page de contact a disparu

:::sim
url=/sims/lesson-6.1.3.btsim
:::

Le secrétariat signale : « Sur notre site web, le lien **Kontakt** (contact) ne mène plus qu'à un message d'erreur. » La page de contact doit être accessible à l'adresse `http://192.168.0.20/kontakt.html`. Trouve l'erreur et corrige-la.

<details>
<summary>Astuce 1 : que répond le serveur ?</summary>

Ouvre la page de contact dans le navigateur ou avec `curl -v`. Quel code de statut est renvoyé ? La page d'erreur indique aussi où le serveur a cherché le fichier.
</details>

<details>
<summary>Astuce 2 : où se trouvent les fichiers ?</summary>

Le serveur web ne fournit que les fichiers de sa **Racine des documents** (*Document Root*) : elle est indiquée dans l'application **Serveur HTTP**. Sur le **Server**, regarde dans le terminal avec `ls` ce qui s'y trouve, et cherche aussi la page de contact dans `/home`.
</details>

<details>
<summary>Astuce 3 : déplacer un fichier</summary>

Avec `mv`, tu déplaces un fichier : `mv <Quelle> <Zielordner>` (source, dossier de destination).
</details>

:::task
title: Page de contact réparée ?
Vérifie si la page de contact se trouve dans la racine des documents du serveur web.
check: fileExists(2, "/var/www/kontakt.html")
:::

## Que s'est-il passé ?

:::quiz multi
Quelles affirmations sont correctes ?
- [x] Le serveur a répondu avec `404 Not Found`
- [x] Le fichier se trouvait dans `/home` au lieu de la racine des documents `/var/www`
- [ ] Le serveur web n'était pas du tout démarré
- [ ] Le navigateur a utilisé la mauvaise adresse IP
:::

:::evaluate
Vérifier la réponse
:::

:::tip À retenir
Un **404** signifie : le serveur web fonctionne et est joignable, mais le **fichier** demandé n'existe pas à cet emplacement. Le serveur ne cherche que dans sa **racine des documents** (*Document Root*, ici `/var/www`). Compare : si le serveur ne répond pas du tout ou répond avec `RST`, le problème se situe plus profondément — au niveau du réseau ou du service lui-même (chapitre 5.3.2).
:::
