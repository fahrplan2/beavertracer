# Qui reçoit quel paquet ?

:::sim
url=/sims/lesson-3.1.2.btsim
:::

Maintenant, Anna, Ben et Clara sont connectés au switch (ports 1, 2 et 3). Quand Anna envoie un paquet à Ben, est-ce que seul Ben le reçoit, ou Clara aussi ?

Réfléchis un instant à ce que tu supposes. Ensuite, tu vérifies.

## L'expérience

1. Passe en :fa-play: mode **Exécuter**, ouvre le :fa-terminal: **Terminal** sur **Anna** et envoie un ping à Ben :
   ```
   $ ping 192.168.0.11
   ```
2. Passe en :fa-magnifying-glass: mode **Trace** et ouvre avec **+** une trace pour **Clara**, interface `eth0`.
3. Ouvre avec **+** une deuxième trace pour **Ben**, interface `eth0`. En haut, tu peux basculer entre les deux traces.

:::quiz short
Combien de paquets sont arrivés chez **Clara** ?
= 1
= un
= un paquet
:::

:::quiz mc

- [x] La requête ARP « Who has 192.168.0.11? » envoyée à tous (broadcast)
- [ ] Un ping (Echo Request) d'Anna
- [ ] La réponse ARP de Ben
:::

:::quiz mc
Et qu'est-ce qui est arrivé chez **Ben** ?
- [ ] Seulement la requête ARP
- [ ] Seulement les pings
- [x] La requête ARP et tous les pings
:::

## Ce qui se cache derrière

La requête ARP a pour destination **Broadcast** : elle s'adresse à *tous*. C'est pourquoi le switch l'a transmise sur chaque port, y compris celui de Clara. Les pings, en revanche, n'étaient adressés qu'à Ben. Le switch les a envoyés uniquement sur le port de Ben : Clara ne s'est rendu compte de rien.

:::tip À retenir
Un **broadcast** s'adresse à tous les appareils du réseau local : le switch le distribue sur tous les ports. Un **unicast** s'adresse à un seul appareil : le switch l'envoie uniquement sur le port auquel cet appareil est connecté.
:::

## Un coup d'œil dans le switch

Mais comment le switch sait-il à quel port Ben est connecté ? Repasse en :fa-play: mode **Exécuter** et clique sur le **Switch**. Dans l'onglet **SAT**, tu vois sa table d'adresses avec deux colonnes : **MAC** et **Port**.

:::quiz mc
Quels appareils figurent dans la table d'adresses ?
- [ ] Anna, Ben et Clara
- [x] Seulement Anna et Ben
- [ ] Seulement Ben
:::

:::quiz short
D'après la table, à quel port Ben est-il connecté ? Astuce : tu trouves l'adresse MAC de Ben dans la trace, dans sa réponse ARP `192.168.0.11 is at …`.
= 2
= port 2
:::

:::quiz mc
Pourquoi Clara ne figure-t-elle pas dans la table ?
- [ ] Son câble est défectueux
- [x] Elle n'a encore envoyé aucun paquet
- [ ] Le switch enregistre au maximum deux entrées
:::

:::evaluate
Vérifier les réponses
:::

Le switch **apprend** au fur et à mesure : pour chaque trame qui lui parvient, il regarde l'adresse MAC de l'**expéditeur** et retient à quel port cet appareil est connecté. Quand la requête ARP d'Anna est arrivée, il a noté « Anna → port 1 », et avec la réponse de Ben « Ben → port 2 ». Clara n'a rien envoyé, donc il ne la connaît pas encore.

:::tip À retenir
Dans sa **table d'adresses** (**SAT**, *Source Address Table*), un switch retient sous quelle adresse MAC quel appareil est joignable sur quel port : il l'apprend à partir des adresses des expéditeurs. S'il connaît la destination d'une trame, il l'envoie uniquement sur ce port. S'il ne la connaît pas (ou s'il s'agit d'un broadcast), il l'envoie sur tous les ports.
:::
