# Créer ta propre AC

:::sim
url=/sims/lesson-8.2.2.btsim
:::

Il n'existe pas encore de certificat pour `www.beaver-schule.de`. Au lieu d'en demander un à une AC (autorité de certification) commerciale, l'école crée sa **propre AC** : la **Schul-CA**. Beaucoup d'entreprises et d'écoles font cela pour leurs serveurs internes.

En réalité, la Schul-CA fonctionnerait sur un ordinateur dédié et particulièrement bien protégé. Ici, tu joues toi-même tous les rôles sur le serveur web.

## Étape 1 : créer la Schul-CA

1. Passe en mode :fa-play: **Exécution** et ouvre la :fa-shield-halved: **Gestion des certificats** sur le serveur web **www.beaver-schule.de**.
2. Dans l'onglet **Générer** :
    - **Common Name :** `Schul-CA`
    - **Type :** Auto-signé
    - Coche **Ceci est un certificat d'AC**
    - **Enregistrer sous :** `schul-ca.cert.json`
3. Clique sur **Générer le certificat**.

Cela crée une nouvelle **paire de clés**. Le certificat contient la clé publique ; la clé privée reste dans le fichier sur le serveur web.

## Étape 2 : émettre le certificat du serveur

De nouveau dans l'onglet **Générer** :

- **Common Name :** `www.beaver-schule.de` — exactement le nom que l'on tape dans le navigateur
- **Type :** Signé par une AC, **AC signataire :** Schul-CA
- **Enregistrer sous :** par exemple `www.beaver-schule.de.cert.json`

Dans l'onglet **Mes certificats**, tu vois maintenant les deux certificats. Clique sur le nouveau certificat du serveur :

:::quiz short
Qui est l'**émetteur** du certificat du serveur (sans `CN=`) ?
= Schul-CA
:::

:::quiz mc
Quelle est sa **chaîne** ?
- [x] `www.beaver-schule.de ← Schul-CA`
- [ ] `Schul-CA ← www.beaver-schule.de`
- [ ] `www.beaver-schule.de` (auto-signé)
:::

:::evaluate
Vérifier les réponses
:::

## Étape 3 : faire connaître la Schul-CA au client

Le Client-PC ne connaît pas encore la Schul-CA — elle n'est pas préinstallée dans son navigateur. Tu dois lui donner son certificat, et cela **sans la clé privée** :

1. Sur le serveur web, sélectionne la **Schul-CA** dans **Mes certificats** et clique sur **Copier** (et non sur *Copier + clé* !).
2. Sur le **Client-PC**, ouvre la :fa-shield-halved: **Gestion des certificats**, onglet **AC de confiance**.
3. Clique sur **Coller : Schul-CA**.

:::warning
La **clé privée de l'AC** est le secret le plus précieux de toute l'installation : celui qui la possède peut émettre des certificats pour **n'importe quel** nom, auxquels tous les clients feront alors confiance. Elle ne doit jamais quitter l'ordinateur de l'AC.
:::

:::task
title: La Schul-CA est-elle configurée ?
Vérifie si le serveur web possède un certificat pour www.beaver-schule.de émis par la Schul-CA et si le Client-PC fait confiance à la Schul-CA.
check: hasCert(4, "www.beaver-schule.de", "Schul-CA")
check: trusts(2, "Schul-CA")
:::

:::quiz mc
Pourquoi ne copies-tu pour le client que le certificat **sans** la clé privée ?
- [ ] Parce que la copie avec la clé prend plus de temps
- [x] La clé publique suffit pour vérifier les signatures ; avec la clé privée, n'importe qui sur le client pourrait émettre lui-même des certificats
- [ ] Parce que sinon le client ne peut pas établir de connexion
:::

:::

Tu n'as pas encore reconfiguré le serveur web lui-même — il ne parle toujours que HTTP. Tu apprendras à activer HTTPS dans la section 8.3.3.

:::tip À retenir
Une **AC propre** se compose d'un **certificat d'AC auto-signé** avec sa clé privée. Grâce à lui, on émet des **certificats de serveur** dont le Common Name correspond au nom du serveur. Pour que les clients fassent confiance à ces certificats, ils reçoivent le **certificat de l'AC sans clé privée** dans leur liste d'**AC de confiance**.
:::
