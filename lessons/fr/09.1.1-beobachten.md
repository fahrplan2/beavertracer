Dans cette simulation, quelqu'un a déjà saisi trois règles dans le pare-feu. Clique sur la **Firewall** et regarde l'onglet **Règles**. Le **Port A** du pare-feu est relié à Internet, le **Port B** au Schulrouter. « A → B » signifie donc « depuis Internet vers le réseau de l'école ».

:::quiz table
| Règle | Sens | Protocole | Port de destination | Action |
|---|---|---|---|---|
| 1 | A → B | {TCP} | {22} | {Abandonner} |
| 2 | A → B | TCP | {110} | {Rejeter} |
| 3 | A → B | {ICMP} | quelconque | Abandonner |
:::

## Ping depuis l'extérieur

Passe en mode Exécution avec :fa-play: **Exécuter** et, depuis l'**Internet-PC**, envoie un ping au Schulserver :

```
$ ping -c 2 198.51.100.10
```

Ouvre ensuite l'onglet **Journal** du pare-feu.

- [ ] `Paket gefiltert`
- [ ] Deux réponses du Schulserver
:::

## Scan de ports : abandonné ou rejeté ?

Scanne maintenant cinq ports précis. Le port 3306 (une base de données) n'est pas du tout en service sur le Schulserver.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (abandonné) -> filtered
25 (autorisé, service actif) -> open
110 (rejeté) -> closed
3306 (autorisé, aucun service) -> closed
:::

:::evaluate
Vérifier les associations
:::

:::quiz multi
Que peut déduire un attaquant de ce résultat ?
- [x] Avec `filtered`, il sait qu'il y a un pare-feu qui fait disparaître les paquets
- [x] Avec `closed`, il ne peut pas savoir si un pare-feu rejette les paquets ou si aucun service n'est simplement actif
- [ ] Avec `filtered`, il sait quel service tourne derrière le port
- [ ] Avec `closed`, le service est quand même joignable
:::

:::evaluate
Vérifier les réponses
:::

Pour finir, regarde la colonne **Correspondances** dans la liste des règles : le pare-feu y compte le nombre de paquets sur lesquels chaque règle a déjà statué. La valeur à côté de la **Politique par défaut** compte tous les paquets auxquels aucune règle ne s'est appliquée.

:::tip À retenir
Les paquets **abandonnés** disparaissent sans laisser de trace : `ping` signale un délai dépassé, `nmap` affiche `filtered`. Aux paquets **rejetés**, le pare-feu répond par un refus (un RST pour TCP) : vu de l'extérieur, cela ressemble à un port fermé. Le **Journal** du pare-feu montre quels paquets il a bloqués, la colonne **Correspondances** indique quelle règle s'est appliquée.
:::
