# Le diagramme de séquence

:::sim
url=/sims/lesson-5.1.btsim
:::

On représente le déroulement d'une connexion sous forme de **diagramme de séquence** : le client et le serveur reçoivent chacun une ligne verticale, et le temps s'écoule de haut en bas. Chaque flèche est un paquet. Elle est tracée en oblique, car chaque paquet met un peu de temps pour arriver.

Voici ta connexion de la page précédente. Compare-la ligne par ligne avec la trace :

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Au-dessus de chaque flèche figurent les **flags**, et en dessous les numéros `SEQ` et `ACK`. **DATA** signale les paquets qui contiennent des données utiles. Les nombres rouges appartiennent au client, les bleus au serveur. Leur signification est expliquée à la page suivante.

## Les flags

| Flag | signifie | Rôle |
|---|---|---|
| **SYN** | *synchronize* | établir la connexion, fixer le numéro de départ |
| **ACK** | *acknowledge* | acquitte les données reçues |
| **PSH** | *push* | transmettre immédiatement les données au programme |
| **FIN** | *finish* | « J'ai terminé » : fermer la connexion |
| **RST** | *reset* | interrompre ou refuser la connexion (plus de détails en 5.3.2) |

## Trois phases

**Établissement :** le client envoie `SYN`, le serveur répond par `SYN, ACK` et le client confirme par `ACK`. Comme il faut exactement trois paquets, on parle de **poignée de main en trois temps** (*three-way handshake*).

**Données :** chaque paquet contenant des données est acquitté par le destinataire avec un `ACK`. Ici, le serveur renvoie l'écho, et le client l'acquitte lui aussi.

**Fermeture :** chaque côté ferme séparément son propre sens d'émission : `FIN` du client, `ACK` du serveur, puis `FIN` du serveur, `ACK` du client. Cela fait quatre paquets.

:::tip À retenir
Une connexion TCP se déroule en trois phases : l'**établissement** avec la **poignée de main en trois temps** (`SYN` → `SYN, ACK` → `ACK`), le **transfert de données** (chaque paquet de données est acquitté par un `ACK`) et la **fermeture** (chaque côté envoie `FIN` et reçoit un `ACK`).
:::
