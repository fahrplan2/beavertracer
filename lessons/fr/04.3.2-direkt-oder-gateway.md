# Directement ou via la passerelle ?

:::sim
url=/sims/lesson-4.3.2.btsim
:::

Avant d'envoyer un paquet, un PC doit décider si la destination se trouve dans son **propre réseau**. Pour cela, il compare la partie réseau de sa propre adresse avec la partie réseau de l'adresse de destination, à l'aide de son masque de sous-réseau.

## Le déroulement

1. **L'IP de destination se trouve-t-elle dans le propre réseau ?**
   - **Oui :** le PC envoie le paquet **directement** à la destination. Il a besoin de l'adresse MAC de la destination.
   - **Non :** le PC envoie le paquet à la **passerelle**. Il a besoin de l'adresse MAC du routeur. Si aucune passerelle n'est configurée, il ne peut pas du tout envoyer le paquet.
2. **Connaît-il déjà l'adresse MAC dont il a besoin** (figure-t-elle dans son cache ARP) ? Sinon, il la demande via **ARP**.
3. Il envoie la trame à cette adresse MAC. Dans les deux cas, l'**adresse IP de destination** dans le paquet est la destination réelle.

| | directement (propre réseau) | via la passerelle (réseau étranger) |
|---|---|---|
| ARP demande … | la MAC de la destination | la MAC du routeur |
| MAC de destination dans la trame | destination | routeur |
| IP de destination dans le paquet | destination | destination |

## Dépannage : l'entreprise B est injoignable

Depuis hier, Anna n'arrive plus à joindre les PC de l'entreprise B. Voici comment le réseau *devrait* être configuré :

| Appareil | Adresse IP | Passerelle |
|---|---|---|
| Anna | `192.168.0.10/24` | `192.168.0.1` |
| Ben | `192.168.0.11/24` | `192.168.0.1` |
| Clara | `172.16.0.10/24` | `172.16.0.1` |
| David | `172.16.0.11/24` | `172.16.0.1` |

Trouve les erreurs et corrige-les.

:::tip À retenir
Un PC a besoin de la bonne passerelle non seulement pour envoyer, mais aussi pour **répondre** : sans passerelle, le ping arrive bien, mais la réponse ne trouve pas le chemin du retour. Si une **mauvaise adresse de passerelle** est configurée, le PC demande en vain via ARP un routeur qui n'existe pas.
:::
