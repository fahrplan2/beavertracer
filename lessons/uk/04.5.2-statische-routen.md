# Додавання статичних маршрутів

:::sim
url=/sims/lesson-4.5.2.btsim
:::

Цього разу між фірмою A та фірмою B розташовано **два** маршрутизатори. Вони з'єднані між собою окремою невеликою мережею — **транзитною мережею** `10.0.0.0/30`:

| Маршрутизатор | Інтерфейс | IP-адреса | Мережа |
|---|---|---|---|
| Router A | `eth0` | `192.168.0.1/24` | Фірма A (Anna) |
| Router A | `eth1` | `10.0.0.1/30` | Транзитна мережа |
| Router B | `eth0` | `10.0.0.2/30` | Транзитна мережа |
| Router B | `eth1` | `172.16.0.1/24` | Фірма B (Clara) |

:::note
Мережа `/30` має рівно дві придатні для використання адреси — ідеально для з'єднання двох маршрутизаторів (див. розділ 4.2.3).
:::

## Проблема

Перейди в :fa-play: **режим виконання** і пінгуй Clara з **Anna** (`ping 172.16.0.10`). Clara не відповідає — натомість озивається Router A (`192.168.0.1`) з повідомленням «Цільова мережа недосяжна».

Подивися на **Таблицю маршрутизації IPv4** маршрутизатора **Router A**.

:::quiz mc
Чому пінг від Anna не доходить до Clara?
- [ ] В Anna не вказано шлюз
- [x] Router A не знає мережі `172.16.0.0/24` — вона не підключена до нього безпосередньо, і маршруту туди немає
- [ ] Транзитна мережа занадто мала
:::

:::evaluate
Перевірити відповідь
:::

## Додавання маршруту

Router A має дізнатися: пакети для `172.16.0.0/24` потрібно відправляти на Router B (`10.0.0.2`), причому через `eth1`.

1. На **Router A** відкрий вкладку **Таблиця маршрутизації IPv4** і натисни **+ hinzufügen**.
2. У новому рядку вкажи: **Ziel** `172.16.0.0`, **Netzmaske** `255.255.255.0`, **Наступний стрибок** `10.0.0.2`, **Iface** `eth1`.
3. Збережи рядок за допомогою галочки :fa-check:. У стовпці **Quelle** тепер стоїть **Статична**.

Пінгуй Clara ще раз — тепер відповідь приходить.

:::note
Router B, до речі, вже знає дорогу назад до фірми A: у його таблиці маршрутизації вже є статичний маршрут для `192.168.0.0/24` через `10.0.0.1`. Чому цей зворотний шлях такий же важливий, ти побачиш на наступній сторінці.
:::

## Відстеження шляху: traceroute

За допомогою `traceroute` можна побачити, через які маршрутизатори проходить пакет. Введи на **Anna**:

```
$ traceroute 172.16.0.10
```

:::quiz short
Через скільки маршрутизаторів проходить пакет від Anna до Clara?
= 2
= два
= дві
:::

:::quiz mc
Яку адресу показує `traceroute` для Router B?
- [x] `10.0.0.2` — його адреса в транзитній мережі, через яку пакет надходить
- [ ] `172.16.0.1` — його адреса у фірмі B
- [ ] `192.168.0.1`
:::

:::evaluate
Перевірити відповіді
:::

`traceroute` використовує хитрість із **часом життя (Time to Live)** з розділу 4.3.1: спочатку він надсилає пакет із TTL 1. Перший маршрутизатор віднімає 1, отримує 0, відкидає пакет і повідомляє про це відправнику — так Anna дізнається про перший маршрутизатор. Потім TTL 2 для другого маршрутизатора і так далі, доки не відповість пункт призначення.

:::tip Запам'ятай
**Статичний маршрут** адміністратор вносить вручну: мережа призначення, маска мережі, наступний стрибок та інтерфейс. За допомогою **traceroute** можна відстежити шлях пакета маршрутизатор за маршрутизатором.
:::
