# Підсумок і перспективи

## Складові безпеки: огляд

| Складова | Мета захисту | Приклад |
|---|---|---|
| **Симетричне шифрування** | Конфіденційність | AES шифрує дані HTTPS-з'єднання |
| **Асиметричне шифрування** | Конфіденційність, обмін ключами | Diffie-Hellman, RSA |
| **Хеш-значення** | Цілісність | Контрольна сума SHA-256 завантаженого файлу |
| **Цифровий підпис** | Автентичність, цілісність | Сервер підписує свою частку Diffie-Hellman |
| **Сертифікат** | Автентичність | підтверджує: цей ключ належить `www.biberbank.de` |

## Один і той самий принцип у багатьох місцях

Те, що ти дізнався про HTTPS, використовується і в багатьох інших технологіях:

- **WLAN (WPA2/WPA3):** У розділі 3.3.2 будь-який пристрій у зоні дії міг читати чужий трафік. У WPA2 або WPA3 кожен радіокадр шифрується за допомогою AES; крім того, WPA3 узгоджує ключ так, що навіть зловмисник, який знає пароль WLAN, не зможе розшифрувати старі перехоплені записи.
- **SSH:** Шифроване віддалене керування з розділу 6.6. Замість сертифікатів клієнт під час першого підключення запам'ятовує **відбиток** ключа сервера й попереджає, якщо пізніше він змінюється.
- **VPN:** Шифрований тунель через інтернет, наприклад до шкільної чи корпоративної мережі. Йому присвячено розділ 10.
- **Месенджери:** Signal, WhatsApp та інші використовують **наскрізне шифрування**: навіть оператор сервісу не може прочитати повідомлення.

:::note
Великі **квантові комп'ютери** одного дня могли б зламати розкладання великих чисел на прості множники — а разом з тим RSA і Diffie-Hellman. Тому вже сьогодні впроваджують нові, **квантово стійкі** алгоритми. Симетричні алгоритми, як-от AES із довгими ключами, і надалі вважаються безпечними.
:::

## Перевір себе

:::quiz mc
У HTTPS самі дані шифруються за допомогою …
- [ ] RSA, бо він найнадійніший
- [x] симетричного алгоритму, як-от AES, і узгодженого сеансового ключа
- [ ] приватного ключа сервера
:::

:::quiz mc
Ти відкриваєш `https://www.biberbank.de/`, а браузер повідомляє: «Сертифікат видано для `www.gewinn-biber.de`». Що ти робиш?
- [ ] Натискаю «Все одно продовжити» — адже з'єднання все одно шифроване
- [x] Перериваю з'єднання — можливо, браузер взагалі спілкується не з банком
- [ ] Відкриваю сторінку через `http://`, тоді попередження не буде
:::

:::quiz multi
Які твердження правильні?
- [x] Хеш-значення повністю змінюється, навіть якщо дані змінилися зовсім трохи
- [x] Підпис створюється приватним ключем, а перевіряється відкритим
- [x] Кореневі CA попередньо встановлені в браузері або операційній системі
- [ ] У HTTPS зловмисник, що прослуховує трафік, не може побачити навіть IP-адресу сервера
- [ ] SMTPS шифрує лист також на поштовому сервері
:::

:::quiz fill
HTTPS — це HTTP поверх {TLS}, який за замовчуванням використовує порт {443}. Сервер підтверджує свою особу за допомогою {сертифіката}, який підписав {CA|центр сертифікації}.
:::
