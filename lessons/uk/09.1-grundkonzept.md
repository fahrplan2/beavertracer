# Пакетний фільтр: правила

Найпростіший і найважливіший вид брандмауера — **пакетний фільтр**. Він перевіряє кожен пакет, що проходить через нього, і за **списком правил** вирішує, чи можна його пропустити. Для цього він читає лише заголовки рівнів 3 і 4 — вміст (наприклад, вебсторінку) він не розглядає.

## З чого складається правило

| Поле | Значення | Приклад |
|---|---|---|
| **Напрямок** | З якого боку надходить пакет? | A → B (з інтернету в шкільну мережу) |
| **Протокол** | TCP, UDP, ICMP або будь-який | TCP |
| **IP джерела** | Адреса або мережа відправника | будь-яка |
| **Порт джерела** | Порт відправника | будь-який |
| **IP призначення** | Адреса або мережа одержувача | `198.51.100.10` |
| **Порт призначення** | Порт одержувача, тобто служба | `80` |
| **Дія** | Що відбувається з пакетами, які підходять під правило? | Дозволити |

Порожнє поле означає «будь-який». Мережі записують у CIDR-нотації, наприклад `198.51.100.0/24`, діапазони портів — через дефіс, наприклад `1024-65535`.

## Порядок має значення

Брандмауер перевіряє правила **згори донизу**. Рішення приймає **перше правило, яке підходить** — усі наступні для цього пакета вже не розглядаються. Якщо жодне правило не підходить, діє **типова політика** (*Default Policy*).

## Три можливі дії

| Дія | Що робить брандмауер | Що помічає відправник |
|---|---|---|
| **Дозволити** (*Allow*) | Пакет пересилається далі | — |
| **Відкинути** (*Drop*) | Пакет мовчки відкидається | нічого — він чекає, доки мине тайм-аут |
| **Відхилити** (*Reject*) | Пакет відкидається, відправник отримує відмову: для TCP — **RST**, в інших випадках — ICMP «недосяжний» | одразу повідомлення про помилку |

Що краще? **Відкидання** видає зловмиснику менше інформації та забирає в нього час, бо йому доводиться чекати після кожної спроби. **Відхилення** привітніше до власних користувачів: програма одразу отримує повідомлення про помилку, а не зависає надовго. Тому на практиці пакети ззовні зазвичай відкидають, а пакети зі своєї мережі відхиляють.

:::quiz match
Дозволити -> Пакет пересилається далі
Відкинути -> Пакет зникає, відправник марно чекає на відповідь
Відхилити -> Пакет не пересилається далі, але відправник одразу отримує відмову
Типова політика -> Діє, якщо жодне правило не підходить
:::

:::tip Запам'ятай
**Пакетний фільтр** перевіряє кожен пакет за **списком правил** на основі напрямку, протоколу, адрес і портів. Про дію вирішує **перше правило, що підходить**: **дозволити**, **відкинути** (мовчки) або **відхилити** (з відмовою). Якщо жодне правило не підходить, діє **типова політика**.
:::
