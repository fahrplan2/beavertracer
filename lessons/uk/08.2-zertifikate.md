# Сертифікати: кому належить цей ключ?

З асиметричним шифруванням і підписами начебто все вирішено: вебсервер твого банку надсилає тобі свій відкритий ключ — і готово. Але звідки ти знаєш, що цей відкритий ключ **справді належить банку**?

Зловмисник, який перенаправляє твоє з'єднання, може просто надіслати тобі **власний** відкритий ключ і стверджувати, що він — банк. Тоді твій браузер слухняно шифруватиме дані для зловмисника, а той прочитає все. Такий зловмисник посередині називається **Man-in-the-Middle** (людина посередині).

## Сертифікат: посвідчення особи для ключів

У реальному житті ти показуєш **посвідчення особи**, щоб довести, хто ти. Посвідченню вірять, бо його видав **надійний орган** — міська адміністрація — і бо його складно підробити.

У мережі це робить **сертифікат**. Він містить, зокрема:

| Поле | Значення | у посвідченні особи |
|---|---|---|
| **Суб'єкт** (*Subject*, часто `CN=…`) | Для кого призначений сертифікат? Для вебсерверів: ім'я, напр. `CN=www.biberbank.de` | ім'я власника |
| **Відкритий ключ** | Ключ власника | фотографія |
| **Емітент** (*Issuer*) | Хто видав сертифікат? | орган, що видав документ |
| **Строк дії** | від … до … | дійсне до |
| **Підпис** емітента | Доводить, що емітент справді видав сертифікат саме таким | печатка, голограма |

`CN` означає *Common Name* (загальне ім'я).

Установа, що видає сертифікати, називається **центром сертифікації** (*Certificate Authority*, скорочено **CA**). Перш ніж підписати сертифікат для `www.biberbank.de`, вона перевіряє, що заявник справді володіє цим доменом.

## Кому довіряє браузер?

Для кожного сертифіката твій браузер перевіряє:

1. Чи справжній **підпис** CA? (Для цього йому потрібен відкритий ключ CA.)
2. Чи сертифікат ще **дійсний**?
3. Чи **ім'я** в сертифікаті збігається з введеною адресою?

Але звідки браузер знає CA? У кожній операційній системі та кожному браузері **попередньо встановлено** список приблизно зі 150 **кореневих CA** (*Root-CA*). Їхні сертифікати **самопідписані** — вони підтверджують самі себе; їм довіряють, бо вони постачаються разом із програмним забезпеченням.

Часто кореневий CA підписує не напряму, а через **проміжний CA**. Так виникає **ланцюжок довіри**:

```
Root-CA (vorinstalliert, vertraut)
  └─ signiert → Zwischen-CA
                  └─ signiert → www.biberbank.de
```

Браузер проходить ланцюжок знизу вгору, доки не дійде до кореневого CA, якому довіряє. Якщо це не вдається — або строк дії чи ім'я не збігаються — він показує **попередження**.

:::quiz match
Суб'єкт (CN) -> Для якого імені дійсний сертифікат
Емітент -> Який CA підписав сертифікат
Відкритий ключ -> Потрібен для перевірки підписів сервера
Кореневий CA -> Попередньо встановлений у браузері та є початком ланцюжка довіри
:::

Перевірити відповідність
:::

:::tip Запам'ятай
**Сертифікат** підтверджує, що **відкритий ключ** належить певному **імені**. Його підписує **центр сертифікації (CA)**. Браузер довіряє сертифікату, якщо через **ланцюжок довіри** доходить до попередньо встановленого **кореневого CA**, сертифікат **дійсний**, а **ім'я** збігається з адресою.
:::
