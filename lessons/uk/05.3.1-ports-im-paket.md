## Експеримент

1. Перейди в :fa-play: **режим виконання**, клікни на **Client-PC** і відкрий :fa-globe: **Браузер**. Відкрий `http://192.168.0.20/`.
2. Клікни вгорі вікна на **Назад**, відкрий **Простий TCP-клієнт** і підключи його до `192.168.0.20`, порт `5000`. Залиш з'єднання відкритим.
3. Перейди в :fa-magnifying-glass: режим **Трасування**, відкрий трасу для **Client-PC** і клікни на пакет з `[SYN]`. Розгорни **Transmission Control Protocol**.

Найвище в заголовку TCP стоять два порти: **Source Port** (порт джерела) і **Destination Port** (порт призначення).

:::quiz table
| З'єднання | Порт джерела | Порт призначення |
|---|---|---|
| Браузер → вебсервер | {49152} | {80} |
| TCP-клієнт → Echo-служба | {49153} | {5000} |
:::

## Два види портів

**Порт призначення — служба:** серверна програма очікує на з'єднання на фіксованому порту — кажуть, що вона **прослуховує** його. Для відомих служб номери визначені в усьому світі — це **Well-known Ports** (від 0 до 1023). Тому браузер без жодних запитів знає: вебсервери прослуховують порт 80.

**Порт джерела — відправник:** порт на стороні клієнта операційна система для кожного нового з'єднання сама вибирає з високого діапазону (у BeaverTracer — від 49152). За ним клієнт розпізнає, до якого з його з'єднань належить відповідь.

Отже, з'єднання однозначно визначається чотирма значеннями: **IP-адресою та портом з обох боків**. Пару з IP-адреси та порту називають **сокетом**, наприклад `192.168.0.20:80`.

## Погляд на сервер

Повернися в :fa-play: **режим виконання**, відкрий на **Server** :fa-terminal: **Термінал** і введи:

```
$ ss
```

`ss` показує всі сокети комп'ютера. Рядки з `LISTEN` — це програми, які прослуховують певний порт. Рядки з `ESTABLISHED` — це наявні з'єднання — зі своїм сокетом (*Local Address:Port*) і сокетом протилежної сторони (*Peer Address:Port*).

:::quiz multi
Які порти прослуховує сервер?
- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc

- [ ] `192.168.0.20:80` з `192.168.0.10:49152` — з'єднання браузера

:::

:::note
З'єднання браузера вже розірване — після завантаження сторінки його завершено за допомогою `FIN`. `ss` ще ненадовго показує його як `TIME-WAIT`: сервер певний час чекає, чи не надійдуть ще запізнілі пакети цього з'єднання. З'єднання TCP-клієнта, навпаки, ще відкрите, бо ти ще не клікнув на **Відключитися**.
:::

## Найважливіші Well-known Ports

| Порт | Протокол | Служба |
|---|---|---|
| 22 | SSH | безпечне віддалене адміністрування (зашифрований командний рядок) |
| 25 | SMTP | надсилання електронних листів |
| 53 | DNS | перетворення імен на IP-адреси (здебільшого через UDP) |
| 80 | HTTP | вебсторінки |
| 110 | POP3 | отримання електронних листів |
| 143 | IMAP | керування електронними листами на сервері |
| 443 | HTTPS | зашифровані вебсторінки |

:::tip Запам'ятай
**Порти** (від 0 до 65535) розрізняють з'єднання на одному комп'ютері. Серверні служби **прослуховують** фіксовані **Well-known Ports** (наприклад, HTTP 80, HTTPS 443), а клієнти для кожного з'єднання отримують вільний високий **порт джерела**. З'єднання однозначно визначається **IP-адресою та портом обох сторін**.
:::

:::quiz match

25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
