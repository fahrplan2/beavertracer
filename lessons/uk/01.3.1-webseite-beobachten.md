# Виклик та спостереження веб-сторінки

У цій частині ти нічого не будуєш сам: на робочій області вже лежить підготовлена симуляція з **Client-PC** та **Webserver**.

## Виклик сторінки

1. Перейди в режим виконання :fa-play: **Запустити**.
2. Відкрий на **Client-PC** застосунок :fa-globe: **Браузер** і введи адресу вебсервера: `http://192.168.0.20/`.
3. Перейди в режим :fa-magnifying-glass: **Трасування** і за допомогою **+** відкрий трасу для **Client-PC**, інтерфейс `eth0` — так само, як і під час ping.

:::note
Для одного-єдиного звернення до сторінки це напрочуд багато пакетів — значно більше, ніж під час ping. Отримання веб-сторінки — це багатоетапний процес, а не одна дія.
:::

## Читання списку пакетів

Тобі ще не потрібно знати, що саме робить кожен протокол. Усе, що потрібно для наступних запитань, є в стовпцях **Протокол** та **Інфо**.

:::quiz mc
Який протокол стоїть на самому початку списку?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Порахуй: скільки пакетів **TCP** стоїть перед першим пакетом **HTTP**?
= 3
= три
:::

:::quiz mc
Що відповідає вебсервер на запит браузера? Подивись у стовпець «Інфо» другого пакета HTTP.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Перевірити відповіді
:::

## Назви задіяних протоколів

Із твоїх спостережень тепер можна визначити, який протокол за що відповідав.

:::tip Підказка
Ще раз прочитай стовпці **Інфо**: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` та `200 OK` майже все підказують.
:::

:::quiz match
ARP -> Питає всіх у мережі: «Хто має IP-адресу 192.168.0.20?»
TCP -> Встановлює з'єднання трьома короткими пакетами, перш ніж почнуть передаватися дані
HTTP -> Запитує веб-сторінку (GET) і повертає її (200 OK)
:::

:::evaluate
Перевірити відповідність
:::

:::tip Запам'ятай
Виклик веб-сторінки відбувається поетапно: спочатку **знайти** сервер у мережі (ARP), потім **встановити** з'єднання (TCP), потім **запитати й отримати** сторінку (HTTP) — і наприкінці знову **розірвати** з'єднання (пакети TCP з `[FIN]` в кінці списку).
:::

:::note
Цього разу ти ввів IP-адресу сервера безпосередньо, тому **DNS** («переклад» імен на кшталт `www.beispiel.de` в IP-адресу) ще не використовувався. Ми надолужимо це в розділі 6.
:::

Чи помітив ти, що протоколи в структурі пакета мають кольорові позначки з цифрами? Що це означає, з'ясуємо в розділі 2. Там ми розглянемо, як систематично класифікувати багато протоколів, — за допомогою еталонних моделей OSI та TCP/IP. На цьому розділ 1 завершено.
