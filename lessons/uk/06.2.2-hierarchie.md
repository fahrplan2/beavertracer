# Як організовано DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Жоден окремий сервер не може знати всі імена у світі. Тому DNS побудовано **ієрархічно** — так само, як і самі імена. Читати їх потрібно справа наліво:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Сервер, який відповідає за домен і справді знає відповідь, називається **авторитетним**. Шлях до нього для ПК проходить **резолвер** — тут це комп'ютер **DNS-Resolver**.

## Експеримент

1. Перейди в :fa-play: режим виконання і введи на **Client-PC** у :fa-terminal: **Термінал**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. У режимі :fa-magnifying-glass: **Трасування** відкрий трасування для **DNS-Resolver**.

Резолвер надіслав для тебе цілу низку запитів. Визнач, хто яку відповідь дав:

:::quiz match
Root-Server (192.168.0.101) -> Переадресація: за .de відповідає ns.nic.de
de-Server (192.168.0.102) -> Переадресація: за beaver-schule.de відповідає ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Відповідь: www.beaver-schule.de має адресу 192.168.0.20
:::

:::quiz mc
Кого резолвер запитує першим?
- [x] Root-сервер
- [ ] Schul-DNS
- [ ] Client-PC
:::

:::evaluate
Перевірити відповіді
:::

:::note
Попутно резолвер також запитує адреси серверів, на які його переадресували (`A ns.nic.de`). Справжні DNS-сервери зазвичай одразу надсилають ці адреси разом із відповіддю. Крім того, резолвери певний час запам'ятовують кожну відповідь (**кеш**) — на наступний запит щодо того самого імені вони відповідають одразу самі. Як довго — вказано в записі як **TTL** (*Time to Live*) у секундах.
:::

## Найважливіші типи записів

| Тип | Значення | Приклад |
|---|---|---|
| **A** | ім'я → адреса IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | ім'я → адреса IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | ім'я → інше ім'я (псевдонім) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | відповідальний поштовий сервер домену | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | відповідальний DNS-сервер домену | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Запам'ятай
DNS є **ієрархічним**: **кореневі сервери** (Root) вказують на сервери **доменів верхнього рівня** (наприклад, `.de`), а ті — на сервери окремих **доменів**. Відповідальний **авторитетний** сервер знає відповідь. **Резолвер** проходить цей шлях за ПК і запам'ятовує відповіді (**кеш**). Важливі типи записів: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Створення запису

Школа хоче, щоб її вебсайт був доступний також за адресою `intranet.beaver-schule.de`.

1. У :fa-play: режимі виконання клікни на **Schul-DNS** і відкрий застосунок **DNS-Server**.
2. Відкрий вкладку **A**. Клікни на **+** і впиши в новий рядок ім'я `intranet.beaver-schule.de` та адресу `192.168.0.20`.
3. Перевір на Client-PC командою `nslookup intranet.beaver-schule.de`.

:::task
title: Нове ім'я внесено?
Перевіряє, чи Client-PC зіставляє ім'я intranet.beaver-schule.de з адресою вебсервера. Для цього симуляція має працювати в режимі виконання.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
