# Спостерігаємо за UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

На **сервері** цього разу працює **UDP Echo-Server** на порту `5000`. Кабель знову «підготовлений»: **друга датаграма** від клієнтського ПК до сервера губиться.

## Експеримент

1. Перейди в :fa-play: режим виконання (**Запустити**) і відкрий :fa-terminal: **Термінал** на **Client-PC**.
2. За допомогою `nc` встанови UDP-«з'єднання» із сервером (`-u` означає UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Введи по черзі `eins`, `zwei` і `drei`, щоразу натискаючи **Enter**. Кожен рядок, що повертається, — це відлуння від сервера.
4. Зачекай кілька секунд, а потім у режимі :fa-magnifying-glass: **Трасування** відкрий трасування для **Client-PC**.

:::quiz mc
Які відлуння повертаються?
- [ ] Усі три, `zwei` трохи пізніше
- [x] Лише `eins` і `drei` — `zwei` відсутнє і повторно не надсилається
- [ ] Жодного
:::

:::quiz multi
Які пакети, відомі тобі з TCP, повністю відсутні в UDP?
- [x] Встановлення з'єднання (`SYN`)
- [x] Підтвердження (`ACK`)
- [x] Розірвання з'єднання (`FIN`)
- [ ] Пакети з номерами портів
:::

:::evaluate
Перевірити відповіді
:::

Клацни на одному з UDP-пакетів і розгорни **User Datagram Protocol**. Порівняно із заголовком TCP заголовок UDP крихітний: **Source Port**, **Destination Port**, **Length** (довжина) і **Checksum** (контрольна сума) — разом лише 8 байтів. Заголовок TCP має щонайменше 20 байтів, із порядковим номером і номером підтвердження, прапорцями та розміром вікна.

- [ ] Встановлення з'єднання
- [ ] Надійне передавання
:::

:::evaluate
Перевірити відповідь
:::

:::tip Запам'ятай
**UDP** — **протокол без встановлення з'єднання**: ні встановлення, ні підтвердження, ні повторного передавання, ні дотримання порядку. Він пропонує лише **порти** (мультиплексування) і **контрольну суму**. Натомість він швидкий і легкий — заголовок UDP має лише 8 байтів. Якщо датаграма губиться, програма має сама про це подбати — або їй байдуже.
:::
