# TLS-рукостискання

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Перш ніж буде надіслано перший зашифрований запит, клієнт і сервер мають домовитися: про метод, про сеансовий ключ — а клієнт має перевірити, з ким він спілкується. Це встановлення з'єднання називається **TLS-рукостисканням** (TLS handshake).

## Перебіг на діаграмі

Без TCP-підтверджень (`ACK`) рукостискання виглядає так:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Що при цьому відбувається — і який складник із розділу 8.1 за цим стоїть:

1. **Client Hello / Server Hello:** клієнт і сервер вітають одне одного, обмінюються випадковими числами та домовляються про методи (у BeaverTracer: обмін ключами за допомогою **ECDHE**, підпис за допомогою **ECDSA**, шифрування за допомогою **AES**).
2. **Certificate:** сервер надсилає свій **сертифікат**. Клієнт перевіряє підпис CA, строк дії та імена. Якщо перевірка не вдається, він перериває з'єднання — і браузер показує попередження.
3. **Server Key Exchange:** сервер надсилає свою **частку Діффі-Геллмана** — і **підписує** її своїм приватним ключем. Клієнт перевіряє підпис за допомогою відкритого ключа із сертифіката. Так він знає: ця частка справді походить від власника сертифіката, а не від Man-in-the-Middle.
4. **Client Key Exchange:** клієнт надсилає свою частку Діффі-Геллмана. Тепер обидві сторони можуть обчислити один і той самий **сеансовий ключ** — без того, щоб його коли-небудь передавали.
5. **Change Cipher Spec:** «Відтепер я шифрую».
6. **Encrypted Handshake Message (Finished):** обидві сторони надсилають — уже зашифровану — контрольну суму всіх попередніх повідомлень рукостискання. Якщо зловмисник щось змінив дорогою, контрольні суми не збігаються, і з'єднання розривається.
7. **Application Data:** відтепер передаються HTTP-дані — симетрично зашифровані за допомогою AES.

:::quiz match
Certificate -> Сервер підтверджує свою особу за допомогою сертифіката
Server Key Exchange -> Підписана частка Діффі-Геллмана сервера
Client Key Exchange -> Частка Діффі-Геллмана клієнта
Change Cipher Spec -> Відтепер дані шифруються
Application Data -> Зашифровані HTTP-дані
:::

:::note
У трасуванні ти бачиш **два** TLS-з'єднання одне за одним: браузер спочатку отримує сторінку, а потім встановлює нове з'єднання для таблиці стилів `style.css`. Кожне з'єднання отримує власне рукостискання та власний сеансовий ключ. Справжні браузери тримають з'єднання відкритими й так економлять частину цих витрат. Новіша версія **TLS 1.3** до того ж обходиться меншою кількістю повідомлень, ніж показаний тут TLS 1.2.
:::

:::tip Запам'ятай
Під час **TLS-рукостискання** сервер підтверджує свою особу за допомогою **сертифіката**, обидві сторони домовляються про **сеансовий ключ** за допомогою **Діффі-Геллмана** (сервер **підписує** свою частку), а за допомогою **Finished** обидві перевіряють, що ніхто не змінив рукостискання. Після цього дані передаються як **Application Data**, симетрично зашифровані.
:::
