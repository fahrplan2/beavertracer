# Діаграма послідовності

:::sim
url=/sims/lesson-5.1.btsim
:::

Перебіг з'єднання зображують у вигляді **діаграми послідовності**: клієнт і сервер отримують по вертикальній лінії (лінії життя), час тече згори вниз. Кожна стрілка — це один пакет. Її намальовано похило, тому що кожен пакет якийсь час перебуває в дорозі.

Так виглядає твоє з'єднання з попередньої сторінки — порівняй його рядок за рядком із трасуванням:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Над кожною стрілкою вказано **прапорці**, під нею — номери `SEQ` і `ACK`. **DATA** позначає пакети з корисними даними. Червоні числа належать клієнту, сині — серверу; що вони означають, поясниться на наступній сторінці.

## Прапорці

| Прапорець | Розшифровка | Значення |
|---|---|---|
| **SYN** | *synchronize* | встановити з'єднання, визначити початковий номер |
| **ACK** | *acknowledge* | підтверджує отримані дані |
| **PSH** | *push* | негайно передати дані програмі |
| **FIN** | *finish* | «Я закінчив» — розірвати з'єднання |
| **RST** | *reset* | перервати або відхилити з'єднання (докладніше в 5.3.2) |

## Три фази

**Встановлення:** клієнт надсилає `SYN`, сервер відповідає `SYN, ACK`, клієнт підтверджує `ACK`. Оскільки потрібно рівно три пакети, це називають **триетапним рукостисканням** (three-way handshake).

**Дані:** кожен пакет із даними одержувач підтверджує пакетом `ACK`. Тут сервер надсилає назад луну (echo) — і її клієнт також підтверджує.

**Розірвання:** кожна сторона завершує свій напрямок передавання окремо: `FIN` від клієнта, `ACK` від сервера — потім `FIN` від сервера, `ACK` від клієнта. Це чотири пакети.

:::tip Запам'ятай
TCP-з'єднання проходить три фази: **встановлення** за допомогою **триетапного рукостискання** (`SYN` → `SYN, ACK` → `ACK`), **передавання даних** (кожен пакет із даними підтверджується пакетом `ACK`) і **розірвання** (кожна сторона надсилає `FIN` і отримує `ACK`).
:::

## Тепер ти

Цього разу клієнт надсилає лише `Hi` (4 байти разом із кінцем рядка). Встав пропущені прапорці — порядок усередині одного поля не має значення.

:::quiz seq
hide: counters
Client-PC -> Server: ? SYN
Server -> Client-PC: ? SYN, ACK
Client-PC -> Server: ? ACK
Client-PC -> Server: PSH, ACK "Hi" len=4
Server -> Client-PC: ? ACK
Client-PC -> Server: ? FIN, ACK
Server -> Client-PC: ? ACK
Server -> Client-PC: ? FIN, ACK
Client-PC -> Server: ? ACK
:::
