# TCP чи UDP?

| | TCP | UDP |
|---|---|---|
| З'єднання | встановлення за допомогою триетапного рукостискання, впорядковане розривання | немає — кожна датаграма самодостатня |
| Підтвердження | так (`ACK`) | ні |
| Втрачені дані | передаються повторно | залишаються втраченими |
| Порядок | відновлюється | не гарантується |
| Заголовок | щонайменше 20 байт | 8 байт |
| Швидкість | трохи повільніше, більше пакетів | швидко, мало накладних витрат |

Коли менше означає більше?

- **Реальний час:** під час відеодзвінків, інтернет-телефонії чи онлайн-ігор важлива кожна мілісекунда. Втрачений фрагмент звуку, який надійде секундою пізніше, нікому вже не потрібен — краще короткий тріск, ніж затримка.
- **Короткі запити:** запит **DNS** («Яку IP-адресу має `www.beispiel.de`?») вміщується в одну датаграму, відповідь так само. Встановлення з'єднання потроїло б витрати. Якщо відповіді немає, програма просто робить запит ще раз.

Натомість скрізь, де має дійти кожен байт — вебсторінки, електронні листи, завантаження файлів, — правильний вибір це TCP.

:::tip Запам'ятай
**TCP** надійний, але вимагає більше ресурсів — для всього, що має дійти **повністю** (веб, електронна пошта, файли). **UDP** швидкий і легкий, але без гарантій — для **реального часу** (телефонія, відео, ігри) та **коротких запитів**, як-от DNS.
:::

Отже, ти знаєш інструменти транспортного рівня. У наступному розділі ти ознайомишся з протоколами, які на ньому ґрунтуються: HTTP, DNS, електронна пошта та DHCP.
