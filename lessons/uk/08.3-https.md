# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) — це звичайний HTTP, тільки він працює не безпосередньо поверх TCP, а через проміжний зашифрований рівень: **TLS** (*Transport Layer Security*). Попередник TLS називався **SSL**; саме тому досі часто говорять про «SSL-сертифікати».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP про це нічого не знає: він надсилає свої запити як завжди, TLS їх шифрує, а TCP передає. У моделі OSI TLS розташований між транспортним і прикладним рівнями, тобто на рівні 4/5 — він спирається на TCP і керує захищеним сеансом.

| | HTTP | HTTPS |
|---|---|---|
| Порт | 80 | **443** |
| Адреса | `http://…` | `https://…` |
| Вміст можна прочитати в Tracer? | так | ні |
| Браузер показує | «не захищено» | замок |

Під час встановлення з'єднання TLS виконує все, чого ти навчився в цьому розділі:

- Сервер підтверджує свою особу за допомогою **сертифіката** (**автентичність**).
- Обидві сторони за допомогою **Діффі-Геллмана** узгоджують **сеансовий ключ** — сервер **підписує** свою частину.
- Після цього всі дані шифруються за допомогою **AES** (**конфіденційність**) і захищаються від змін (**цілісність**).

Цей принцип не обмежується вебом: електронна пошта (розділ 8.4) та багато інших протоколів так само працюють через TLS.

У наступних розділах ти спостерігатимеш HTTPS у Tracer, самостійно налаштуєш його та дослідиш, коли браузер попереджає — і чому.
