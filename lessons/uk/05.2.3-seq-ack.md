# Порядкові номери та номери підтвердження

:::sim
url=/sims/lesson-5.1.btsim
:::

Звідки TCP знає, чи все дійшло — і в якому порядку? Кожна сторона **нумерує байти**, які надсилає:

- **Порядковий номер** (`SEQ`) — це номер першого байта, який міститься в цьому пакеті.
- **Номер підтвердження** (`ACK`) говорить: «Усе до цього місця я отримав — наступним очікую байт № …»

До цього додаються два правила: `SYN` і `FIN` вважаються за один байт, хоча даних не несуть. І кожна сторона веде лік окремо — тому існують два незалежні ряди номерів, на діаграмі червоний (клієнт) і синій (сервер).

## Перевіряємо розрахунком

Ось знову твоє з'єднання. Числа біля ліній показують лічильник відповідного комп'ютера в цей момент:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Пройдися по червоному ряду чисел:

1. Клієнт починає з `SEQ=0`. Його `SYN` займає один номер — сервер підтверджує з `ACK=1`.
2. Повідомлення починається з `SEQ=1` і має довжину 13 байтів (байти з 1 по 13). Сервер підтверджує з `ACK=14`: «Наступним очікую байт 14».
3. Тому `FIN` клієнта має `SEQ=14` і підтверджується з `ACK=15`.

Синій ряд сервера працює так само.

:::tip Запам'ятай
**Порядковий номер** (`SEQ`) — це номер першого байта в пакеті. **Номер підтвердження** (`ACK`) — це номер наступного байта, який очікує одержувач; усе, що було перед ним, дійшло. Діє правило: **ACK = SEQ + довжина** отриманих даних; `SYN` і `FIN` вважаються за один байт. Кожна сторона рахує власні байти.
:::

:::tip Спробуй сам
Ще раз встанови з'єднання в **Простий TCP-клієнт** і надішли два повідомлення поспіль. Наперед скажи, які `Seq` і `Ack` будуть у стовпці **Info** — і перевір це в трасуванні.
:::

## Практика

:::quiz short
Клієнт надсилає пакет із `Seq=1` і `Len=13`. Який номер підтвердження надсилає сервер у відповідь?
= 14
:::

:::quiz short
Після цього клієнт надсилає наступне повідомлення. З якого порядкового номера воно починається?
= 14
:::

:::quiz short
Надходить пакет із `Seq=40` і `Len=25`. Який номер підтвердження надсилає одержувач?
= 65
:::

Server -> Client-PC: ACK ack=?

:::note
У реальних мережах лічба починається не з 0: кожна сторона обирає **випадковий початковий номер** (*Initial Sequence Number*, ISN) від 0 до приблизно 4,3 мільярда. Коли досягнуто найбільшого номера, відлік знову продовжується з 0. Трасувальник віднімає початковий номер і показує **відносні** номери — так само, як Wireshark. Тому ти бачиш `Seq=0` і `Seq=1`.

Крім того, в кожному пакеті є `Win=` — **розмір вікна**: стільки байтів одержувач може прийняти зараз. Так він стримує надто швидкого відправника (*керування потоком*). У BeaverTracer вікно завжди має однаковий розмір.
:::
