# Handshake-u TLS

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Para se të dërgohet kërkesa e parë e enkriptuar, klienti dhe serveri duhet të bien dakord: për një metodë, për një çelës sesioni — dhe klienti duhet të verifikojë me kë po komunikon. Kjo ngritje e lidhjes quhet **handshake TLS**.

## Rrjedha në diagram

Pa konfirmimet TCP (`ACK`), handshake duket kështu:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Çfarë ndodh këtu — dhe cili element nga seksioni 8.1 qëndron pas tij:

1. **Client Hello / Server Hello:** Klienti dhe serveri përshëndeten, shkëmbejnë numra të rastësishëm dhe bien dakord për metodat (në BeaverTracer: shkëmbimi i çelësave me **ECDHE**, nënshkrimi me **ECDSA**, enkriptimi me **AES**).
2. **Certificate:** Serveri dërgon **certifikatën** e tij. Klienti kontrollon nënshkrimin e CA-së, vlefshmërinë dhe emrat. Nëse kjo dështon, ai ndërpret këtu — dhe shfletuesi shfaq një paralajmërim.
3. **Server Key Exchange:** Serveri dërgon **pjesën e tij Diffie-Hellman** — dhe e **nënshkruan** me çelësin e tij privat. Klienti kontrollon nënshkrimin me çelësin publik nga certifikata. Kështu ai e di: kjo pjesë vjen vërtet nga zotëruesi i certifikatës, jo nga një Man-in-the-Middle.
4. **Client Key Exchange:** Klienti dërgon pjesën e tij Diffie-Hellman. Tani të dy mund të llogarisin të njëjtin **çelës sesioni** — pa u transmetuar ai kurrë.
5. **Change Cipher Spec:** „Nga tani e tutje po enkriptoj.“
6. **Encrypted Handshake Message (Finished):** Të dyja palët dërgojnë — tashmë të enkriptuar — një shumë kontrolli mbi të gjitha mesazhet e handshake deri atëherë. Nëse një sulmues ka ndryshuar diçka gjatë rrugës, shumat e kontrollit nuk përputhen dhe lidhja ndërpritet.
7. **Application Data:** Nga këtu rrjedhin të dhënat HTTP — të enkriptuara në mënyrë simetrike me AES.

:::quiz match
Certificate -> Serveri legjitimohet me certifikatën e tij
Server Key Exchange -> Pjesa Diffie-Hellman e nënshkruar e serverit
Client Key Exchange -> Pjesa Diffie-Hellman e klientit
Change Cipher Spec -> Nga tani e tutje enkriptohet
Application Data -> Të dhëna HTTP të enkriptuara
:::

:::note
Në trace shikon **dy** lidhje TLS njëra pas tjetrës: Shfletuesi merr fillimisht faqen dhe pastaj ngre një lidhje të re për stilin `style.css`. Çdo lidhje merr handshake-un e vet dhe çelësin e vet të sesionit. Shfletuesit e vërtetë i mbajnë lidhjet të hapura dhe kështu kursejnë një pjesë të kësaj mundi. Versioni më i ri **TLS 1.3** del gjithashtu me më pak mesazhe se TLS 1.2 i shfaqur këtu.
:::

:::tip Mbaj mend
Në **handshake-un TLS** serveri legjitimohet me **certifikatën** e tij, të dyja palët bien dakord për një **çelës sesioni** përmes **Diffie-Hellman** (serveri **nënshkruan** pjesën e tij), dhe me **Finished** të dyja verifikojnë që askush nuk e ka ndryshuar handshake-un. Pas kësaj, të dhënat transmetohen si **Application Data**, të enkriptuara në mënyrë simetrike.
:::
