# Atac: falsificació de DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

L'Anna vol obrir la seva banca en línia de la **Biberbank** des del **Client-PC**. Allò que ella no sap: algú ha aconseguit accedir al **DNS-Server** i ha modificat una entrada.

A l'espai de treball hi veus el servidor web real **www.biberbank.de** i l'ordinador d'un **atacant**. En aquest ordinador s'hi executa una còpia de la pàgina web del banc.

## Part 1: sense xifratge

Canvia al mode d'execució :fa-play: **Executar** i, al **Client-PC**, obre al :fa-globe: **Navegador** l'adreça `http://www.biberbank.de/`.

:::quiz mc
Què veus?
- [x] La pàgina d'inici de sessió de la Biberbank, sense cap advertència
- [ ] Una advertència que la pàgina és falsa
- [ ] Un missatge d'error
:::

:::evaluate
Comprova la resposta
:::

Tot sembla normal. Però amb quin servidor parla realment el navegador? Al Client-PC, obre el :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Quina adreça IP retorna el servidor DNS per a `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
De qui és aquesta adreça? (Al mode d'edició, fes clic als dispositius o consulta la seva :fa-gear: **Configuració IP**.)
- [ ] Del servidor web real de la Biberbank
- [x] De l'atacant
- [ ] Del servidor DNS
:::

:::evaluate
Comprova les respostes
:::

Si l'Anna ara hagués introduït el número de compte i el PIN, haurien acabat directament a mans de l'atacant. Amb **HTTP** no té **cap possibilitat** de detectar l'engany: la barra d'adreces mostra el nom correcte i la pàgina sembla autèntica.

## Part 2: amb HTTPS

Ara obre `https://www.biberbank.de/`.

:::quiz mc
Què passa?
- [ ] Apareix la pàgina falsa amb un cadenat
- [x] El navegador avisa: el certificat s'ha emès per a un altre nom
- [ ] Apareix la pàgina real de la Biberbank
:::

:::quiz short
Per a quin nom està emès el certificat de l'atacant (sense `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Comprova les respostes
:::

L'atacant fins i tot té un certificat **real** d'una CA de confiança, però per al seu propi domini `www.biber-gewinnspiel.de`. Cap CA no li donarà un certificat per a `www.biberbank.de`, perquè aquest domini no és seu. I sense la **clau privada** de la Biberbank tampoc no pot utilitzar el seu certificat real: durant l'handshake hauria de signar-hi el Server Key Exchange.

:::quiz multi
De què protegeix HTTPS aquí, i de què no?
- [x] HTTPS descobreix que el servidor no és el real
- [ ] HTTPS impedeix que es falsifiqui el servidor DNS
- [x] HTTPS només ajuda si l'usuari pren seriosament l'advertència
- [ ] Amb HTTPS la pàgina falsa ni tan sols és accessible
:::

:::evaluate
Comprova les respostes
:::

## Part 3: reparar el servidor DNS

Obre el **DNS-Server** i corregeix l'entrada de `www.biberbank.de`. L'adreça correcta la trobaràs a la :fa-gear: **Configuració IP** del servidor web **www.biberbank.de**. No oblidis fer clic a **Guardar**.

:::note
El Client-PC recorda les respostes DNS durant un temps perquè no hagi de tornar a preguntar cada vegada que accedeix a una pàgina (**memòria cau DNS**). Quant de temps, ho indica la columna **TTL** (*Time to Live*) en segons. Si just després de la teva correcció `nslookup` encara retorna l'adreça antiga, espera que passi el TTL i torna-ho a provar.
:::

:::task
title: La Biberbank torna a ser real?
Comprova que el Client-PC resol www.biberbank.de a l'adreça correcta i que pot obtenir la pàgina per HTTPS sense cap advertència.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
A la realitat, un atacant poques vegades falsifica el servidor DNS en si. Més sovint hi introdueix les seves respostes en una xarxa WiFi pública, modifica la configuració d'un encaminador domèstic o atrau amb una adreça d'aspecte semblant, com `www.biberbank-login.de` (**pesca de dades**, *phishing*). Contra un nom que s'assembla, HTTPS tampoc no ajuda: l'atacant n'obté un certificat vàlid. Per això: llegeix bé l'adreça!
:::

:::tip Idea clau
En una **falsificació de DNS**, el servidor DNS retorna per a un nom l'adreça d'un atacant. Amb **HTTP** no se n'adona ningú. Amb **HTTPS**, el certificat de l'atacant no coincideix amb el nom sol·licitat i el navegador **avisa**: cap CA no emet un certificat per a dominis aliens, i l'atacant no té la clau privada del servidor real.
:::
