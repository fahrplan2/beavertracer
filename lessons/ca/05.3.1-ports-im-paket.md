## L'experiment

1. Canvia al mode d'execució :fa-play: **Executar**, fes clic al **Client-PC** i obre el :fa-globe: **Navegador**. Accedeix a `http://192.168.0.20/`.
2. Fes clic a **Zurück** a la part superior de la finestra, obre el **Client TCP simple** i connecta'l a `192.168.0.20`, port `5000`. Deixa la connexió oberta.
3. Canvia al mode :fa-magnifying-glass: **Traça**, obre una traça per al **Client-PC** i fes clic en un paquet amb `[SYN]`. Desplega **Transmission Control Protocol**.

A la part superior de la capçalera TCP hi ha dos ports: **Source Port** (port d'origen) i **Destination Port** (port de destinació).

:::quiz table
| Connexió | Port d'origen | Port de destinació |
|---|---|---|
| Navegador → servidor web | {49152} | {80} |
| Client TCP → servei d'eco | {49153} | {5000} |
:::

## Dos tipus de ports

**Port de destinació — el servei:** un programa servidor espera connexions en un port fix; es diu que hi **escolta**. Per als serveis coneguts, els números estan establerts a tot el món: són els **Well-known Ports** (de 0 a 1023). Per això un navegador sap, sense haver de preguntar, que els servidors web escolten al port 80.

**Port d'origen — el remitent:** el port del costat del client el tria el mateix sistema operatiu per a cada connexió nova dins d'un rang alt (a BeaverTracer, a partir del 49152). Gràcies a aquest port, el client reconeix a quina de les seves connexions pertany una resposta.

Així doncs, una connexió queda determinada de manera unívoca per quatre dades: **l'adreça IP i el port de cada un dels dos costats**. El parell format per l'adreça IP i el port s'anomena **socket**, p. ex. `192.168.0.20:80`.

## Una ullada al servidor

Torna al mode d'execució :fa-play: **Executar**, obre el :fa-terminal: **Terminal** al **Server** i escriu:

```
$ ss
```

`ss` mostra tots els sockets de l'ordinador. Les línies amb `LISTEN` són programes que escolten en un port. Les línies amb `ESTABLISHED` són connexions establertes, amb el socket propi (*Local Address:Port*) i el socket de l'altre costat (*Peer Address:Port*).

:::

:::note
La connexió del navegador ja s'ha tancat: després de carregar la pàgina es va finalitzar amb `FIN`. `ss` encara la mostra breument com a `TIME-WAIT`: el servidor espera una estona per si arriben paquets endarrerits d'aquesta connexió. La connexió del client TCP, en canvi, encara és oberta perquè encara no has fet clic a **Desconnectar**.
:::

## Els Well-known Ports més importants

| Port | Protocol | Servei |
|---|---|---|
| 22 | SSH | administració remota segura (línia d'ordres xifrada) |
| 25 | SMTP | enviament de correus electrònics |
| 53 | DNS | traducció de noms a adreces IP (normalment per UDP) |
| 80 | HTTP | pàgines web |
| 110 | POP3 | recollida de correus electrònics |
| 143 | IMAP | gestió de correus electrònics al servidor |
| 443 | HTTPS | pàgines web xifrades |

:::tip Idea clau
Els **ports** (de 0 a 65535) mantenen separades les connexions dins d'un ordinador. Els serveis de servidor **escolten** en **Well-known Ports** fixos (p. ex. HTTP 80, HTTPS 443); els clients reben per a cada connexió un **port d'origen** alt i lliure. Una connexió queda determinada de manera unívoca per l'**adreça IP i el port dels dos costats**.
:::

:::quiz match
22 -> SSH
25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
