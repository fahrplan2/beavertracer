# Com s'organitza el DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Cap servidor pot conèixer tots els noms del món. Per això el DNS està construït de manera **jeràrquica**, igual que els noms mateixos. Es llegeixen de dreta a esquerra:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

El servidor que és responsable d'un domini i que realment coneix la resposta s'anomena **autoritatiu**. Del camí fins a ell se n'encarrega, per al PC, un **resolutor**; aquí, l'ordinador **DNS-Resolver**.

## L'experiment

1. Canvia al mode d'execució :fa-play: **Executar** i escriu al :fa-terminal: **Terminal** del **Client-PC**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Al mode :fa-magnifying-glass: **Traça**, obre una traça per al **DNS-Resolver**.

El resolutor ha fet per tu tot un seguit de consultes. Relaciona qui ha donat cada resposta:

:::quiz match
Root-Server (192.168.0.101) -> Referència: ns.nic.de és responsable de .de
de-Server (192.168.0.102) -> Referència: ns.beaver-schule.de és responsable de beaver-schule.de
Schul-DNS (192.168.0.103) -> Resposta: www.beaver-schule.de té l'adreça 192.168.0.20
:::

:::quiz mc
A qui pregunta primer el resolutor?
- [x] Al servidor arrel (root)
- [ ] Al Schul-DNS
- [ ] Al Client-PC
:::

:::evaluate
Comprova les respostes
:::

:::note
Entremig, el resolutor també pregunta per les adreces dels servidors als quals se l'ha adreçat (`A ns.nic.de`). Els servidors DNS reals solen enviar aquestes adreces juntament amb la resposta. A més, els resolutors recorden cada resposta durant un temps (**memòria cau**); la consulta següent del mateix nom la responen ells mateixos a l'instant. Quant de temps es conserva consta a l'entrada com a **TTL** (*Time to Live*) en segons.
:::

## Els tipus d'entrada més importants

| Tipus | Significat | Exemple |
|---|---|---|
| **A** | nom → adreça IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | nom → adreça IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | nom → un altre nom (àlies) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | servidor de correu responsable d'un domini | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | servidor DNS responsable d'un domini | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Idea clau
El DNS és **jeràrquic**: els **servidors arrel** remeten als servidors dels **dominis de primer nivell** (p. ex. `.de`), i aquests, als servidors dels **dominis** individuals. El servidor **autoritatiu** responsable coneix la resposta. Un **resolutor** fa aquest camí per al PC i recorda les respostes (**memòria cau**). Tipus d'entrada importants: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Crear una entrada

L'escola vol que el seu lloc web sigui accessible també a `intranet.beaver-schule.de`.

1. Al mode d'execució :fa-play: **Executar**, fes clic al **Schul-DNS** i obre l'aplicació **DNS-Server**.
2. Obre la pestanya **A**. Fes clic a **+** i escriu a la fila nova el nom `intranet.beaver-schule.de` i l'adreça `192.168.0.20`.
3. Prova-ho al Client-PC amb `nslookup intranet.beaver-schule.de`.

:::task
title: Has registrat el nom nou?
Comprova si el Client-PC resol el nom intranet.beaver-schule.de a l'adreça del servidor web. Per a això, la simulació ha d'estar en marxa en mode d'execució.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
