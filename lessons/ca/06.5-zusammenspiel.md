# Tot plegat: què passa quan s'obre una pàgina web?

:::goal
**Objectiu d'aprenentatge:** Pots explicar pas a pas quins protocols intervenen i en quina capa quan un portàtil acabat d'engegar obre una pàgina web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Ara es ajunta tot el que has après en aquest curs. Al switch hi ha connectats un **DHCP-Server**, un **DNS-Server**, un **Webserver** i un **Laptop** que s'acaba d'engegar: encara no té cap adreça IP i està configurat amb DHCP.

## L'experiment

1. Canvia al mode d'execució :fa-play: **Executar** i espera uns segons.
2. Fes clic al **Laptop**, obre el :fa-globe: **Navegador** i accedeix a `http://www.beaver-schule.de/`.
3. Al mode :fa-magnifying-glass: **Traça**, obre una traça per al **Laptop**. Aquí hi ha tota la història, des del primer paquet.

Ordena els passos tal com apareixen a la traça:

:::quiz match
1. Schritt -> DHCP: El portàtil obté l'adreça IP, la passarel·la i el servidor DNS
2. Schritt -> ARP: El portàtil pregunta per l'adreça MAC del servidor DNS
3. Schritt -> DNS: El portàtil pregunta per l'adreça IP de www.beaver-schule.de
4. Schritt -> ARP: El portàtil pregunta per l'adreça MAC del servidor web
5. Schritt -> TCP: Salutació de tres vies amb el servidor web
6. Schritt -> HTTP: GET / i la resposta 200 OK
:::

:::evaluate
Comprova l'ordre
:::

I sota de tot hi ha **IP** (capa 3), que adreça cadascun d'aquests paquets, i **Ethernet** (capa 2), que el porta fins al dispositiu següent. Si el servidor web fos en una altra xarxa, hi intervindria també l'**encaminador**: aleshores el portàtil preguntaria per l'adreça MAC del seu **gateway**, no per la del servidor web.

:::quiz mc
Per què el portàtil no pot fer la consulta DNS fins després de DHCP?
- [ ] Perquè DNS només funciona sobre TCP
- [x] Perquè només mitjançant DHCP obté una adreça IP pròpia i sap quin servidor DNS és el responsable
- [ ] Perquè el servidor DNS només s'inicia després del servidor DHCP
:::

:::quiz mc
Quantes connexions TCP estableix el navegador amb el servidor web, i per què?
- [ ] Una, per a tot plegat
- [x] Dues: una per a la pàgina i una per al full d'estil
- [ ] Cap, HTTP no necessita TCP
:::

:::evaluate
Comprova les respostes
:::

:::tip Idea clau
Darrere d'un sol clic, totes les capes treballen conjuntament: **DHCP** proporciona la configuració bàsica, **ARP** troba les adreces MAC a la xarxa local, **DNS** tradueix el nom, **TCP** estableix una connexió fiable i **HTTP** obté la pàgina; tot empaquetat en paquets **IP** i trames **Ethernet**.
:::

Així ja pots explicar l'obertura d'una pàgina web des del primer fins a l'últim paquet. Per acabar el capítol, tot seguit hi ha una breu mirada a altres protocols. Als capítols següents tractarem la xarxa domèstica amb NAT, la seguretat i el xifratge, i, per tant, la qüestió de com evitar que algú pugui llegir tots aquests paquets.
