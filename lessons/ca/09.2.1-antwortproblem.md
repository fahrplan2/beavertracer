# El problema de la resposta

:::sim
url=/sims/lesson-9.2.btsim
:::

El tallafoc ara treballa segons el principi de llista blanca: política per defecte **Alle verwerfen**. Una sola regla permet a la xarxa de l'escola navegar: **B → A, TCP, Ziel-Port 80, Zulassen**. El mode està en **Stateless**.

## L'experiment

1. Canvia al mode d'execució :fa-play: **Executar** i obre `http://203.0.113.80/` al **Lehrer-PC** amb el :fa-globe: **Navegador**.
2. Mira el **Protokoll** i els **Treffer** al **Firewall**.

:::quiz mc
Què passa al navegador?
- [ ] Apareix la pàgina de www.beispiel.de
- [x] La pàgina no es carrega, el navegador espera i finalment mostra un error
:::

:::quiz mc
Quins paquets apareixen com a descartats (`DROP`) al registre del tallafoc?
- [ ] Les peticions del Lehrer-PC al port 80
- [x] Les respostes de `203.0.113.80` amb **port d'origen 80** cap al Lehrer-PC
- [ ] Cap
:::

:::quiz short
En quin sentit (A→B o B→A) circulen els paquets descartats?
= A→B
= A → B
= AtoB
:::

:::evaluate
Comprova les respostes
:::

La petició del Lehrer-PC pot sortir, però el `SYN, ACK` del servidor web ja no torna, perquè per al sentit A → B no hi ha cap regla adequada i, per tant, s'aplica **Alle verwerfen**.

## La solució ingènua

Es podria afegir una segona regla: **A → B, TCP, port d'origen 80, Zulassen** — «tot el que ve del port 80 pot entrar». Aleshores navegar funciona de debò.

:::quiz mc
Per què és perillosa aquesta regla?
- [ ] Perquè els servidors web mai no fan servir el port 80 com a port d'origen
- [x] Un atacant pot enviar els seus paquets simplement amb port d'origen 80, i llavors el tallafoc els deixa passar cap a **qualsevol** port de la xarxa de l'escola
- [ ] Perquè llavors les pàgines web es carreguen més lentament
:::

:::evaluate
Comprova la resposta
:::

El port d'origen el determina el mateix remitent, i un tallafoc no s'hi pot refiar. Però un tallafoc sense estat no sap si un paquet és la **resposta a una petició** o un **nou intent de connexió** des de l'exterior. Això és justament el que canvia el mode amb estat.

:::tip Idea clau
Un filtre de paquets **sense estat** comprova cada paquet per separat. Les respostes necessiten llavors regles pròpies per al sentit invers, i aquestes regles (p. ex. «el port d'origen 80 pot entrar») poden ser aprofitades pels atacants, perquè el remitent pot triar lliurement el port d'origen.
:::
