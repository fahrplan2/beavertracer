# Resolució de problemes: el servei no respon

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Després d'una actualització, l'escola informa: «El servei d'eco rebutja totes les connexions i la pàgina web tampoc no es carrega». Segons el pla, el **servidor web** ha d'escoltar al port `80` i el **servei d'eco** (servidor d'eco TCP) al port `5000`. Troba els errors i soluciona'ls.

<details>
<summary>Pista 1: Què respon el servidor?</summary>

Prova de connectar-te amb el **Client TCP simple** a `192.168.0.20`, port `5000`, i obre una traça per al PC client. Amb què respon el servidor al teu `[SYN]`?
</details>

<details>
<summary>Pista 2: Quins ports són oberts?</summary>

Al PC client, escriu al terminal `nmap -p 80,5000 192.168.0.20`. `nmap` prova els ports un darrere l'altre i mostra quins són oberts. Amb `ss` al servidor veuràs a quins ports hi escolta realment un programa.
</details>

<details>
<summary>Pista 3: On es configura això?</summary>

Al **servidor**, obre les aplicacions **Servidor d'eco TCP** i **Servidor HTTP**. El servei s'està executant? I a quin port?
</details>

:::task
title: Serveis accessibles?
Comproveu si el PC client arriba al servei d'eco al port 5000 i al servidor web al port 80. Per això, la simulació s'ha d'estar executant en el mode d'execució.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Què passava?

:::quiz multi
Quines afirmacions són correctes?
- [x] Al `[SYN]` cap al port 5000, el servidor va respondre amb `[RST, ACK]`
- [x] El servei d'eco escoltava al port 5050 en lloc del port 5000
- [x] El servidor web no estava iniciat en absolut
- [ ] El cable entre el PC client i el servidor estava defectuós
:::

:::evaluate
Comprova la resposta
:::

:::tip Idea clau
Si en resposta a un `SYN` torna un **`RST`**, en aquest port **no hi escolta cap programa**: l'ordinador és accessible, però el servei no. Causes típiques: el servei **no està iniciat** o escolta en un **altre port**. Una ullada amb `ss` al servidor mostra quins ports són realment oberts.
:::
