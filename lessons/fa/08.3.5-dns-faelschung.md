# حمله: جعل DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

آنا می‌خواهد روی **Client-PC** وارد بانکداری آنلاین خود در **Biberbank** شود. چیزی که او نمی‌داند: کسی به **DNS-Server** دسترسی پیدا کرده و یک رکورد را تغییر داده است.

روی فضای کار، وب‌سرور واقعی **www.biberbank.de** و رایانه‌ی یک **مهاجم** را می‌بینی. روی رایانه‌ی مهاجم یک کپی از وب‌سایت بانک اجرا می‌شود.

## بخش ۱: بدون رمزگذاری

به :fa-play: حالت **اجرا** برو و روی **Client-PC** در :fa-globe: **مرورگر** آدرس `http://www.biberbank.de/` را باز کن.

:::quiz mc
چه چیزی می‌بینی؟
- [x] صفحه‌ی ورود Biberbank، بدون هیچ هشداری
- [ ] هشداری که می‌گوید صفحه جعلی است
- [ ] یک پیام خطا
:::

:::evaluate
بررسی پاسخ
:::

همه‌چیز عادی به نظر می‌رسد. اما مرورگر واقعاً با کدام سرور صحبت می‌کند؟ روی Client-PC :fa-terminal: **ترمینال** را باز کن:

```
$ nslookup www.biberbank.de
```

:::quiz short
سرور DNS برای `www.biberbank.de` چه آدرس IP‌ای برمی‌گرداند؟
= 192.168.0.66
:::

:::quiz mc
این آدرس به چه کسی تعلق دارد؟ (در حالت ویرایش روی دستگاه‌ها کلیک کن یا :fa-gear: **تنظیمات IP** آن‌ها را ببین.)
- [ ] به وب‌سرور واقعی Biberbank
- [x] به مهاجم
- [ ] به سرور DNS
:::

:::evaluate
بررسی پاسخ‌ها
:::

اگر آنا حالا شماره حساب و PIN را وارد می‌کرد، مستقیم به دست مهاجم می‌رسید. در **HTTP** او **هیچ شانسی** برای تشخیص این کلاهبرداری ندارد: نوار آدرس نام درست را نشان می‌دهد و صفحه واقعی به نظر می‌رسد.

## بخش ۲: با HTTPS

حالا `https://www.biberbank.de/` را باز کن.

:::quiz mc
چه اتفاقی می‌افتد؟
- [ ] صفحه‌ی جعلی همراه با قفل نمایش داده می‌شود
- [x] مرورگر هشدار می‌دهد: گواهی برای نام دیگری صادر شده است
- [ ] صفحه‌ی واقعی Biberbank نمایش داده می‌شود
:::

:::quiz short
گواهی مهاجم برای چه نامی صادر شده است (بدون `CN=`)؟
= www.biber-gewinnspiel.de
:::

:::evaluate
بررسی پاسخ‌ها
:::

مهاجم حتی یک گواهی **واقعی** از یک CA معتبر دارد — اما برای دامنه‌ی خودش، یعنی `www.biber-gewinnspiel.de`. هیچ CA‌ای برای `www.biberbank.de` به او گواهی نمی‌دهد، چون این دامنه مال او نیست. و بدون **کلید خصوصی** Biberbank هم نمی‌تواند از گواهی واقعی آن استفاده کند: در handshake باید Server Key Exchange را با آن امضا کند.

:::quiz multi

- [x] HTTPS آشکار می‌کند که سرور، سرور واقعی نیست
- [ ] HTTPS جلوی جعل شدن سرور DNS را می‌گیرد
- [x] HTTPS فقط وقتی کمک می‌کند که کاربر هشدار را جدی بگیرد
- [ ] با HTTPS اصلاً نمی‌توان به صفحه‌ی جعلی دسترسی پیدا کرد
:::

:::evaluate

## بخش ۳: تعمیر سرور DNS

**DNS-Server** را باز کن و رکورد `www.biberbank.de` را اصلاح کن. آدرس درست را در :fa-gear: **تنظیمات IP** وب‌سرور **www.biberbank.de** پیدا می‌کنی. فراموش نکن روی **ذخیره** کلیک کنی.

:::note
Client-PC پاسخ‌های DNS را مدتی به خاطر می‌سپارد تا در هر بار دسترسی مجبور نباشد دوباره بپرسد (**DNS-Cache**). مدت آن در ستون **TTL** (*Time to Live*) بر حسب ثانیه آمده است. اگر `nslookup` درست بعد از اصلاح تو هنوز آدرس قدیمی را برمی‌گرداند، تا پایان TTL صبر کن و دوباره امتحان کن.
:::

:::task
title: Biberbank دوباره واقعی است؟
بررسی می‌کند که Client-PC نام www.biberbank.de را به آدرس درست تبدیل کند و بتواند صفحه را از طریق HTTPS بدون هشدار دریافت کند.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
در دنیای واقعی مهاجم به‌ندرت خود سرور DNS را جعل می‌کند. بیشتر پاسخ‌های خود را در یک Wi-Fi عمومی جا می‌زند، تنظیمات یک مسیریاب خانگی را تغییر می‌دهد یا با آدرسی شبیه `www.biberbank-login.de` فریب می‌دهد (**فیشینگ**). در برابر یک نام شبیه، HTTPS هم کمکی نمی‌کند — مهاجم برای آن گواهی معتبر می‌گیرد. بنابراین: آدرس را دقیق بخوان!
:::

:::tip نکته کلیدی
در **جعل DNS**، سرور DNS برای یک نام، آدرس مهاجم را برمی‌گرداند. در **HTTP** کسی متوجه این موضوع نمی‌شود. در **HTTPS** گواهی مهاجم با نام واردشده نمی‌خواند و مرورگر **هشدار** می‌دهد — چون هیچ CA‌ای برای دامنه‌های بیگانه گواهی صادر نمی‌کند و مهاجم کلید خصوصی سرور واقعی را ندارد.
:::
