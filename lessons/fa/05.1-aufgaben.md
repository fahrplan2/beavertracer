# لایه انتقال باید چه کارهایی انجام دهد؟

:::sim
url=/sims/lesson-5.1.btsim
:::

روی **Server** دو سرویس هم‌زمان اجرا می‌شود: یک **وب‌سرور** و یک **سرویس بازتاب** کوچک که هر پیامی را که دریافت می‌کند بلافاصله پس می‌فرستد. با دو آزمایش متوجه می‌شوی که IP به‌تنهایی چه کارهایی را نمی‌تواند انجام دهد.

## آزمایش ۱: دو برنامه هم‌زمان

1. به حالت :fa-play: **اجرا** برو و روی **Client-PC** کلیک کن.
2. :fa-globe: **مرورگر** را باز کن و `http://192.168.0.20/` را فراخوانی کن.
3. بالای پنجره روی **Zurück** کلیک کن و **کلاینت TCP ساده** را باز کن. در **Host** مقدار `192.168.0.20` و در **Port** مقدار `5000` را وارد کن و روی **اتصال** کلیک کن.
4. به حالت :fa-magnifying-glass: **ردیابی** برو و با **+** یک ردیابی (Trace) برای **Client-PC** و درگاه `eth0` باز کن.

روی یکی از بسته‌های مرورگر (مثلاً `GET /`) و روی یکی از بسته‌های کلاینت TCP کلیک کن و هر بار **Internet Protocol Version 4** را باز کن.

:::quiz mc
بسته‌های مرورگر و کلاینت TCP چه آدرس‌های IP ای دارند؟
- [x] در هر دو یکسان است: از `192.168.0.10` به `192.168.0.20`
- [ ] مرورگر آدرس IP مقصد متفاوتی نسبت به کلاینت TCP به کار می‌برد
- [ ] بسته‌های کلاینت TCP هیچ آدرس IP ای ندارند
:::

:::quiz mc
پس آیا آدرس IP مقصد کافی است تا سرور بداند یک بسته به وب‌سرور تعلق دارد یا به سرویس بازتاب؟
- [ ] بله
- [x] خیر — هر دو بسته آدرس IP مقصد یکسانی دارند
:::

چیز دیگری باید این دو اتصال را از هم تشخیص دهد. به ستون **Info** در بسته‌های دارای `[SYN]` نگاه کن — این بسته، اولین بسته هر اتصال است:

در مورد **مرورگر**، چه عددی بعد از فلش `→` آمده است؟
= 80
:::

:::quiz short
و در مورد **کلاینت TCP**؟
= 5000
:::

:::evaluate
بررسی پاسخ‌ها
:::

درباره‌ی این اعداد — یعنی **پورت‌ها** — در بخش ۵٫۳ بیشتر خواهی آموخت. فعلاً همین کافی است: فقط لایه انتقال باعث می‌شود چند برنامه بتوانند هم‌زمان از طریق *یک* آدرس IP ارتباط برقرار کنند و هر بسته به برنامه درست برسد. به این کار **چندسازی** می‌گویند.

## آزمایش ۲: وقتی یک بسته گم می‌شود

1. به حالت :fa-play: **اجرا** برو و روی **کابل** بین Client-PC و Server کلیک کن.
2. در پنجره **Verbindung** مقدار **Konfigurierten Paketverlust** را روی `25%` بگذار.
3. روی **Client-PC** :fa-terminal: **ترمینال** را باز کن و شش پینگ بفرست:
   ```
   $ ping -c 6 192.168.0.20
   ```
   این کار حدود نیم دقیقه طول می‌کشد — صبر کن تا آمار نمایش داده شود.

:::quiz mc
چه اتفاقی می‌افتد؟
- [ ] به هر شش پینگ پاسخ داده می‌شود
- [x] به برخی پینگ‌ها پاسخی داده نمی‌شود — و هیچ‌کس آن‌ها را دوباره نمی‌فرستد
- [ ] پینگ‌های گم‌شده به‌طور خودکار تکرار می‌شوند تا برسند
:::

:::evaluate
بررسی پاسخ
:::

در مورد پینگ این مشکلی نیست — چون هدفش دقیقاً این است که نشان دهد آیا چیزی گم می‌شود یا نه. اما در یک صفحه وب، یک ایمیل یا یک دانلود، نبودِ یک قطعه فاجعه‌بار خواهد بود: فایل خراب می‌شود.

## چهار وظیفه لایه انتقال

| وظیفه | معنی آن |
|---|---|
| **چندسازی** | چند برنامه و اتصال یک آدرس IP را بین خود تقسیم می‌کنند؛ هر بسته به برنامه درست می‌رسد. |
| **برقراری اتصال** | پیش از جریان یافتن داده‌ها، هر دو طرف توافق می‌کنند که با یکدیگر گفتگو کنند. |
| **انتقال قابل اطمینان** | گیرنده آنچه را رسیده است تأیید می‌کند. داده‌های ناقص دوباره ارسال می‌شوند و ترتیب بازسازی می‌شود. |
| **قطع اتصال** | در پایان، هر دو طرف اتصال را به‌صورت منظم پایان می‌دهند. |

:::tip نکته کلیدی
**لایه انتقال** (لایه ۴) تضمین می‌کند که داده‌ها به **برنامه** درست برسند (**چندسازی**). پروتکل **TCP** علاوه بر این تضمین می‌کند که داده‌ها **کامل** و به **ترتیب درست** برسند — با برقراری اتصال، تصدیق‌ها، ارسال مجدد و قطع اتصال.
:::

:::quiz match
روی یک کامپیوتر، مرورگر، برنامه ایمیل و پیام‌رسان هم‌زمان اجرا می‌شوند. -> چندسازی
پیش از جریان یافتن داده‌ها، هر دو طرف مطمئن می‌شوند که طرف مقابل آماده است. -> برقراری اتصال
بخشی از یک فایل نمی‌رسد و دوباره فرستاده می‌شود. -> انتقال قابل اطمینان
پس از دانلود، هر دو طرف اتصال را دوباره آزاد می‌کنند. -> قطع اتصال
:::
