# مشاهدهٔ UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

این بار روی **Server** یک **سرور UDP Echo** روی پورت `5000` اجرا می‌شود. این بار هم کابل دستکاری شده است: **دیتاگرام دوم** از Client-PC به سمت Server گم می‌شود.

## آزمایش

1. به حالت :fa-play: **اجرا** برو و روی **Client-PC** :fa-terminal: **ترمینال** را باز کن.
2. با `nc` یک «اتصال» UDP به سرور شروع کن (`-u` مخفف UDP است):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. به‌ترتیب `eins`، `zwei` و `drei` را تایپ کن و هر بار **Enter** را بزن. هر خطی که برمی‌گردد، بازتابی از سمت سرور است.
4. چند ثانیه صبر کن و سپس در حالت :fa-magnifying-glass: **ردیابی** یک Trace برای **Client-PC** باز کن.

- [x] فقط `eins` و `drei` — `zwei` نیست و دوباره هم فرستاده نمی‌شود

روی یکی از بسته‌های UDP کلیک کن و **User Datagram Protocol** را باز کن. در مقایسه با سرآیند TCP، سرآیند UDP بسیار کوچک است: **Source Port**، **Destination Port**، **Length** (طول) و **Checksum** (مجموع کنترلی) — روی‌هم فقط ۸ بایت. سرآیند TCP دست‌کم ۲۰ بایت است، با شمارهٔ توالی و شمارهٔ تصدیق، پرچم‌ها و اندازهٔ پنجره.

:::tip نکتهٔ کلیدی
**UDP** **بدون اتصال** است: بدون برقراری اتصال، بدون تصدیق، بدون ارسال مجدد، بدون ترتیب. فقط **پورت‌ها** (چندسازی) و یک **مجموع کنترلی** ارائه می‌دهد. در عوض سریع و سبک است — سرآیند UDP فقط ۸ بایت است. اگر یک دیتاگرام گم شود، خود برنامه باید به آن رسیدگی کند — یا برایش مهم نیست.
:::
