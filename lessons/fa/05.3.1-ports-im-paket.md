## آزمایش

1. به حالت :fa-play: **اجرا** برو، روی **Client-PC** کلیک کن و :fa-globe: **مرورگر** را باز کن. آدرس `http://192.168.0.20/` را باز کن.
2. بالای پنجره روی **Zurück** کلیک کن، **کلاینت TCP ساده** را باز کن و آن را به `192.168.0.20` و پورت `5000` وصل کن. اتصال را باز بگذار.
3. به حالت :fa-magnifying-glass: **ردیابی** برو، یک Trace برای **Client-PC** باز کن و روی بسته‌ای با `[SYN]` کلیک کن. **Transmission Control Protocol** را باز کن.

در بالاترین بخش سرآیند TCP دو پورت قرار دارد: **Source Port** (پورت مبدأ) و **Destination Port** (پورت مقصد).

## دو نوع پورت

**پورت مقصد — سرویس:** یک برنامه سرور روی یک پورت ثابت منتظر اتصال‌ها می‌ماند — می‌گویند روی آن پورت **گوش می‌دهد**. برای سرویس‌های شناخته‌شده، شماره‌ها در سراسر جهان مشخص شده‌اند؛ این‌ها **Well-known Ports** (پورت‌های شناخته‌شده، ۰ تا ۱۰۲۳) هستند. به همین دلیل مرورگر بدون پرسیدن می‌داند که وب‌سرورها روی پورت ۸۰ گوش می‌دهند.

**پورت مبدأ — فرستنده:** پورت سمت کلاینت را سیستم‌عامل برای هر اتصال جدید خودش از یک محدوده بالا انتخاب می‌کند (در BeaverTracer از ۴۹۱۵۲ به بعد). کلاینت از روی آن تشخیص می‌دهد که یک پاسخ به کدام‌یک از اتصال‌هایش تعلق دارد.

بنابراین یک اتصال به‌طور یکتا با چهار مقدار مشخص می‌شود: **آدرس IP و پورت در هر دو طرف**. به جفتِ آدرس IP و پورت **سوکت** (Socket) می‌گویند، مثلاً `192.168.0.20:80`.

## نگاهی به سرور

دوباره به حالت :fa-play: **اجرا** برگرد، روی **Server** :fa-terminal: **ترمینال** را باز کن و این دستور را وارد کن:

```
$ ss
```

`ss` همه سوکت‌های رایانه را نشان می‌دهد. خط‌هایی با `LISTEN` برنامه‌هایی هستند که روی یک پورت گوش می‌دهند. خط‌هایی با `ESTABLISHED` اتصال‌های برقرارشده‌اند — با سوکت خودی (*Local Address:Port*) و سوکت طرف مقابل (*Peer Address:Port*).

:::note
اتصال مرورگر دوباره قطع شده است — پس از بارگذاری صفحه با `FIN` پایان یافته است. `ss` آن را هنوز برای مدت کوتاهی به‌صورت `TIME-WAIT` نشان می‌دهد: سرور مدتی صبر می‌کند تا ببیند آیا بسته‌های دیررسیده‌ای از این اتصال می‌رسند یا نه. اما اتصال کلاینت TCP هنوز باز است، چون هنوز روی **قطع اتصال** کلیک نکرده‌ای.
:::

## مهم‌ترین پورت‌های شناخته‌شده

| پورت | پروتکل | سرویس |
|---|---|---|
| 22 | SSH | مدیریت از راه دور به‌صورت امن (خط فرمان رمزنگاری‌شده) |
| 25 | SMTP | ارسال ایمیل |
| 53 | DNS | تبدیل نام به آدرس IP (بیشتر از طریق UDP) |
| 80 | HTTP | صفحات وب |
| 110 | POP3 | دریافت ایمیل |
| 143 | IMAP | مدیریت ایمیل‌ها روی سرور |
| 443 | HTTPS | صفحات وبِ رمزنگاری‌شده |

:::tip نکته کلیدی
**پورت‌ها** (۰ تا ۶۵۵۳۵) اتصال‌های روی یک رایانه را از هم جدا نگه می‌دارند. سرویس‌های سرور روی **پورت‌های شناخته‌شده** ثابت **گوش می‌دهند** (مثلاً HTTP ۸۰، HTTPS ۴۴۳)، و کلاینت‌ها برای هر اتصال یک **پورت مبدأ** آزاد و بالا می‌گیرند. یک اتصال به‌طور یکتا با **آدرس IP و پورت هر دو طرف** مشخص می‌شود.
:::
