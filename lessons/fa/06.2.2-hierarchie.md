# DNS چگونه سازمان‌دهی شده است

:::sim

:::

هیچ سرور تکی نمی‌تواند همه نام‌های دنیا را بشناسد. به همین دلیل DNS به‌صورت **سلسله‌مراتبی** ساخته شده است — درست مثل خود نام‌ها. نام‌ها را از راست به چپ می‌خوانند:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

سروری که مسئول یک دامنه است و پاسخ را واقعاً می‌داند، **معتبر** (authoritative) نامیده می‌شود. پیمودن مسیر رسیدن به آن سرور را برای PC یک **ریزالور** (Resolver) انجام می‌دهد — در اینجا رایانهٔ **DNS-Resolver**.

## آزمایش

1. به حالت :fa-play: **اجرا** برو و روی **Client-PC** در :fa-terminal: **ترمینال** این دستور را وارد کن:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. در حالت :fa-magnifying-glass: **ردیابی** یک ردیابی (Trace) برای **DNS-Resolver** باز کن.

ریزالور برای تو یک سری کامل درخواست فرستاده است. مشخص کن هر پاسخ را چه کسی داده است:

:::quiz match
Root-Server (192.168.0.101) -> ارجاع: برای .de سرور ns.nic.de مسئول است
de-Server (192.168.0.102) -> ارجاع: برای beaver-schule.de سرور ns.beaver-schule.de مسئول است
Schul-DNS (192.168.0.103) -> پاسخ: www.beaver-schule.de آدرس 192.168.0.20 را دارد
:::

:::quiz mc
ریزالور اول از چه کسی می‌پرسد؟
- [x] از سرور ریشه (Root-Server)
- [ ] از Schul-DNS
- [ ] از Client-PC
:::

:::evaluate
بررسی پاسخ‌ها
:::

:::note
در این میان ریزالور آدرس سرورهایی را هم که به آن‌ها ارجاع داده شده است می‌پرسد (`A ns.nic.de`). سرورهای DNS واقعی معمولاً این آدرس‌ها را همان ابتدا همراه پاسخ می‌فرستند. علاوه بر این، ریزالورها هر پاسخ را برای مدتی به خاطر می‌سپارند (**کش**) — درخواست بعدی برای همان نام را خودشان فوراً پاسخ می‌دهند. اینکه این مدت چقدر است، در خود رکورد به‌صورت **TTL** (*Time to Live*) بر حسب ثانیه آمده است.
:::

## مهم‌ترین انواع رکورد

| نوع | معنا | مثال |
|---|---|---|
| **A** | نام ← آدرس IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | نام ← آدرس IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | نام ← نام دیگر (نام مستعار) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | سرور ایمیل مسئول یک دامنه | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | سرور DNS مسئول یک دامنه | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip نکته کلیدی
DNS **سلسله‌مراتبی** است: **سرورهای ریشه** به سرورهای **دامنه‌های سطح بالا** (مثلاً `.de`) ارجاع می‌دهند و این‌ها به سرورهای هر **دامنه**. سرور **معتبر** مسئول، پاسخ را می‌داند. یک **ریزالور** این مسیر را برای PC می‌پیماید و پاسخ‌ها را به خاطر می‌سپارد (**کش**). انواع مهم رکورد: **A**، **AAAA**، **CNAME**، **MX**، **NS**.
:::

## ایجاد یک رکورد

مدرسه می‌خواهد وب‌سایتش علاوه بر آدرس فعلی، از طریق `intranet.beaver-schule.de` هم در دسترس باشد.

1. در حالت :fa-play: **اجرا** روی **Schul-DNS** کلیک کن و برنامهٔ **DNS-Server** را باز کن.
2. زبانهٔ **A** را باز کن. روی **+** کلیک کن و در ردیف جدید نام `intranet.beaver-schule.de` و آدرس `192.168.0.20` را وارد کن.
3. روی Client-PC با `nslookup intranet.beaver-schule.de` آزمایش کن.

:::task
title: نام جدید ثبت شد؟
بررسی می‌کند که آیا Client-PC نام intranet.beaver-schule.de را به آدرس وب‌سرور تبدیل می‌کند. شبیه‌سازی باید برای این کار در حالت اجرا در حال اجرا باشد.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
