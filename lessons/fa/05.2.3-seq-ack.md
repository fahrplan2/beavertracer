# شماره‌های توالی و تصدیق

:::sim
url=/sims/lesson-5.1.btsim
:::

TCP از کجا می‌داند که همه‌چیز رسیده است — و به چه ترتیبی؟ هر طرف **بایت‌هایی را که می‌فرستد شماره‌گذاری می‌کند**:

- **شماره توالی** (`SEQ`) شماره‌ی اولین بایتی است که در این بسته قرار دارد.
- **شماره تصدیق** (`ACK`) می‌گوید: «تا اینجا همه‌چیز را دریافت کرده‌ام — بایت بعدی که انتظار دارم، بایت شماره …»

دو قاعده‌ی دیگر هم وجود دارد: `SYN` و `FIN` مثل یک بایت شمرده می‌شوند، با اینکه داده‌ای حمل نمی‌کنند. و هر طرف برای خودش می‌شمارد — به همین دلیل دو دنباله‌ی شماره‌گذاری وجود دارد، در نمودار با رنگ قرمز (کلاینت) و آبی (سرور).

## محاسبه‌ی دوباره

اینجا دوباره اتصال خودت را می‌بینی. اعداد روی خط‌ها، شمارنده‌ی هر رایانه را در آن نقطه نشان می‌دهند:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

ردیف اعداد قرمز را مرحله به مرحله بررسی کن:

1. کلاینت از `SEQ=0` شروع می‌کند. `SYN` آن یک شماره مصرف می‌کند — سرور با `ACK=1` تصدیق می‌کند.
2. پیام از `SEQ=1` شروع می‌شود و ۱۳ بایت طول دارد (بایت‌های ۱ تا ۱۳). سرور با `ACK=14` تصدیق می‌کند: «بایت بعدی که انتظار دارم، بایت ۱۴ است.»
3. بنابراین `FIN` کلاینت مقدار `SEQ=14` دارد و با `ACK=15` تصدیق می‌شود.

ردیف آبی سرور هم دقیقاً به همین شکل کار می‌کند.

:::tip نکته کلیدی
**شماره توالی** (`SEQ`) شماره‌ی اولین بایت در بسته است. **شماره تصدیق** (`ACK`) شماره‌ی بایت بعدی است که گیرنده انتظار دارد — هرچه قبل از آن بوده، رسیده است. قاعده این است: **ACK = SEQ + طول** داده‌های دریافت‌شده؛ `SYN` و `FIN` مثل یک بایت شمرده می‌شوند. هر طرف بایت‌های خودش را می‌شمارد.
:::

:::tip امتحان کن
اتصال را یک بار دیگر با **کلاینت TCP ساده** برقرار کن و دو پیام پشت‌سر هم بفرست. قبل از آن پیش‌بینی کن که چه `Seq` و `Ack` ای در ستون **Info** نمایش داده می‌شود — و بعد در ردیابی بررسی کن.
:::

## تمرین

:::quiz short
کلاینت بسته‌ای با `Seq=1` و `Len=13` می‌فرستد. سرور چه شماره تصدیقی پس می‌فرستد؟
= 14
:::

:::quiz short
پس از آن کلاینت پیام بعدی‌اش را می‌فرستد. این پیام با چه شماره توالی‌ای شروع می‌شود؟
= 14
:::

:::quiz short
بسته‌ای با `Seq=40` و `Len=25` می‌رسد. گیرنده چه شماره تصدیقی می‌فرستد؟

شماره‌های جاافتاده را وارد کن. کلاینت `Hallo` و بعد از آن `Tschau` را می‌فرستد (هر کدام با پایان خط):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::

:::note
در شبکه‌های واقعی شمارش از ۰ شروع نمی‌شود: هر طرف یک **شماره‌ی شروع تصادفی** (*Initial Sequence Number*، به‌اختصار ISN) بین ۰ و حدود ۴٫۳ میلیارد انتخاب می‌کند. وقتی به بالاترین شماره برسد، دوباره از ۰ ادامه می‌یابد. ردیاب شماره‌ی شروع را کم می‌کند و شماره‌های **نسبی** را نشان می‌دهد — درست مثل Wireshark. برای همین `Seq=0` و `Seq=1` را می‌بینی.

علاوه بر این، در هر بسته `Win=` وجود دارد — **اندازه‌ی پنجره**: یعنی گیرنده در حال حاضر می‌تواند این تعداد بایت را بپذیرد. با این مقدار، گیرنده فرستنده‌ای را که بیش‌ازحد سریع است کند می‌کند (*کنترل جریان*). در BeaverTracer پنجره همیشه اندازه‌ی ثابتی دارد.
:::
