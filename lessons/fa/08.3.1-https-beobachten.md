# مقایسهٔ HTTP و HTTPS

:::sim
url=/sims/lesson-8.2.1.btsim
:::

وب‌سرور **www.beaver-schule.de** پورتال نمرات مدرسه را هم از طریق HTTP و هم از طریق HTTPS ارائه می‌دهد. یک شنودکننده چه چیزی می‌بیند؟

## آزمایش

1. به :fa-play: **حالت اجرا** برو و روی **Client-PC** در :fa-globe: **مرورگر** ابتدا `http://www.beaver-schule.de/` و سپس `https://www.beaver-schule.de/` را باز کن.
2. در حالت :fa-magnifying-glass: **ردیابی** یک Trace برای **Client-PC** باز کن.
3. ابتدا بستهٔ `HTTP/1.1 200 OK` را پیدا کن و روی آن کلیک کن. در جزئیات پایین، محتوای صفحه را پیدا می‌کنی.

:::quiz mc
یک شنودکننده در **HTTP** چه چیزی می‌تواند ببیند؟
- [x] کل صفحهٔ وب، حتی نمرات Anna
- [ ] فقط آدرس سرور
- [ ] هیچ چیز، چون HTTP روی TCP اجرا می‌شود
:::

:::quiz short
Anna در ریاضی چه نمره‌ای دارد؟
= 2
:::

:::evaluate
بررسی پاسخ‌ها
:::

حالا بخش HTTPS. بستهٔ `[SYN]` را پیدا کن که کلاینت با آن اتصال دوم را آغاز می‌کند.

:::quiz short
اتصال HTTPS چه پورت مقصدی دارد (ستون **Info**، `… → ???`)؟
= 443
:::

حالا در بالای Trace، در کادر فیلتر، عبارت `tls` را وارد کن — آن‌وقت فقط بسته‌های TLS را می‌بینی.

:::quiz mc
در ستون **Info** برای بسته‌هایی که صفحهٔ وب را دربردارند چه نوشته شده است؟
- [ ] `HTTP/1.1 200 OK`
- [x] `Application Data`
- [ ] `Encrypted HTML`
:::

:::quiz multi
یک شنودکننده در **HTTPS** باز هم چه چیزهایی می‌تواند ببیند؟
- [x] آدرس‌های IP کلاینت و سرور
- [x] اینکه از پورت 443 استفاده می‌شود، یعنی احتمالاً HTTPS
- [x] تقریباً چه مقدار داده منتقل می‌شود
- [ ] چه صفحه‌ای باز شده و چه چیزی روی آن نوشته شده است
:::

:::evaluate
بررسی پاسخ‌ها
:::

:::note
روی یک بستهٔ **Application Data** کلیک کن: داده‌های کاربر فقط دنباله‌ای از بایت‌های ظاهراً تصادفی هستند. Tracer نمی‌تواند آن‌ها را رمزگشایی کند — کلید نشست را به همان اندازهٔ یک مهاجم نمی‌شناسد.
:::

:::tip نکته کلیدی
در **HTTP** هر شنودکننده‌ای می‌تواند کل صفحهٔ وب را بخواند. در **HTTPS** او فقط می‌بیند که **چه کسی با چه کسی** صحبت می‌کند (آدرس‌های IP، پورت 443) و **چه مقدار** — محتوا به‌صورت رمزگذاری‌شده در بسته‌های **Application Data** قرار دارد.
:::
