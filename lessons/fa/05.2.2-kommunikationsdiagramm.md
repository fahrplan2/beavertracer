# نمودار ارتباط

:::sim
url=/sims/lesson-5.1.btsim
:::

روند یک اتصال را به شکل **نمودار ارتباط** رسم می‌کنند: کلاینت و سرور هر کدام یک خط عمودی دارند و زمان از بالا به پایین پیش می‌رود. هر پیکان یک بسته است. پیکان‌ها مورب کشیده می‌شوند، چون هر بسته مدتی در مسیر است.

اتصال تو از صفحهٔ قبل این‌گونه به نظر می‌رسد — آن را خط‌به‌خط با ردیابی مقایسه کن:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

بالای هر پیکان **فلگ‌ها** قرار دارند و زیر آن شماره‌های `SEQ` و `ACK`. **DATA** بسته‌هایی را که داده‌ٔ مفید دارند مشخص می‌کند. اعداد قرمز متعلق به کلاینت و اعداد آبی متعلق به سرور هستند — معنای آن‌ها را صفحهٔ بعد روشن می‌کند.

## فلگ‌ها

| فلگ | مخفف | معنی |
|---|---|---|
| **SYN** | *synchronize* | برقراری اتصال، تعیین شمارهٔ شروع |
| **ACK** | *acknowledge* | تأیید داده‌های دریافت‌شده |
| **PSH** | *push* | تحویل فوری داده به برنامه |
| **FIN** | *finish* | «کارم تمام شد» — پایان دادن به اتصال |
| **RST** | *reset* | لغو یا رد اتصال (توضیح بیشتر در 5.3.2) |

## سه مرحله

**برقراری:** کلاینت `SYN` می‌فرستد، سرور با `SYN, ACK` پاسخ می‌دهد و کلاینت با `ACK` تأیید می‌کند. چون دقیقاً سه بسته لازم است، به آن **دست‌دهی سه‌مرحله‌ای** (Three-Way Handshake) می‌گویند.

**داده:** گیرنده هر بسته‌ای را که داده دارد با یک `ACK` تأیید می‌کند. اینجا سرور بازتاب را پس می‌فرستد — کلاینت آن را هم تأیید می‌کند.

**قطع:** هر طرف جهت ارسال خود را جداگانه می‌بندد: `FIN` از کلاینت، `ACK` از سرور — سپس `FIN` از سرور و `ACK` از کلاینت. این‌ها چهار بسته هستند.

:::tip نکته کلیدی
یک اتصال TCP در سه مرحله انجام می‌شود: **برقراری** با **دست‌دهی سه‌مرحله‌ای** (`SYN` ← `SYN, ACK` ← `ACK`)، **انتقال داده** (هر بستهٔ داده با `ACK` تأیید می‌شود) و **قطع اتصال** (هر طرف `FIN` می‌فرستد و یک `ACK` می‌گیرد).
:::
