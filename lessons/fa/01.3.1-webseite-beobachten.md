# فراخوانی و مشاهده یک صفحه وب

برای این بخش خودت چیزی نمی‌سازی: روی فضای کار یک شبیه‌سازی آماده با یک **Client-PC** و یک **Webserver** قرار دارد.

## فراخوانی صفحه

1. به حالت :fa-play: **اجرا** برو.
2. روی **Client-PC** برنامه :fa-globe: **مرورگر** را باز کن و آدرس وب‌سرور را وارد کن: `http://192.168.0.20/`.
3. به حالت :fa-magnifying-glass: **ردیابی** برو و با **+** یک Trace برای **Client-PC** و درگاه `eth0` باز کن — دقیقاً مثل ping.

:::note
برای فراخوانی یک تک صفحه، این تعداد بسته به‌طرز شگفت‌آوری زیاد است — بسیار بیشتر از ping. دریافت یک صفحه وب یک فرایند چندمرحله‌ای است، نه یک عمل واحد.
:::

## خواندن فهرست بسته‌ها

هنوز لازم نیست بدانی هر پروتکل دقیقاً چه کاری انجام می‌دهد. هر چیزی که برای سؤال‌های بعدی نیاز داری در ستون‌های **Protokoll** و **Info** آمده است.

:::quiz mc
کدام پروتکل در بالاترین قسمت فهرست قرار دارد؟
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
بشمار: چند بسته **TCP** قبل از اولین بسته **HTTP** قرار دارد؟
= 3
= سه
:::

:::quiz mc
وب‌سرور به درخواست مرورگر چه پاسخی می‌دهد؟ به ستون Info دومین بسته HTTP نگاه کن.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

## نام‌بردن پروتکل‌های درگیر

از مشاهدات خودت اکنون می‌توانی استنباط کنی که هر پروتکل مسئول چه کاری بود.

:::tip نکته
ستون‌های **Info** را یک بار دیگر بخوان: `Who has …?`، `[SYN]`، `[SYN, ACK]`، `[ACK]`، `GET /` و `200 OK` تقریباً همه‌چیز را لو می‌دهند.
:::

:::quiz match
ARP -> از همه در شبکه می‌پرسد: «چه کسی آدرس IP ‏192.168.0.20 را دارد؟»
TCP -> پیش از جاری‌شدن داده‌ها، با سه بسته کوتاه یک اتصال برقرار می‌کند
HTTP -> صفحه وب را درخواست می‌کند (GET) و آن را برمی‌گرداند (200 OK)
:::

:::evaluate
بررسی تطبیق
:::

:::tip نکته کلیدی
فراخوانی یک صفحه وب در چند مرحله انجام می‌شود: ابتدا **پیدا کردن** سرور در شبکه (ARP)، سپس **برقراری** اتصال (TCP)، بعد **درخواست و ارسال** صفحه (HTTP) — و در پایان دوباره **قطع کردن** اتصال (بسته‌های TCP با `[FIN]` در انتهای فهرست).
:::

:::note
این بار آدرس IP سرور را مستقیم وارد کردی، به همین دلیل **DNS** (یعنی «ترجمه» نام‌هایی مانند `www.beispiel.de` به یک آدرس IP) هنوز به کار نیامد. این موضوع را در فصل ۶ جبران می‌کنیم.
:::

متوجه شدی که پروتکل‌ها در ساختار بسته نشانه‌های رنگی همراه با عدد دارند؟ توضیح این موضوع را در فصل ۲ می‌دهیم. آنجا بررسی می‌کنیم که چگونه می‌شود پروتکل‌های متعدد را به‌صورت نظام‌مند دسته‌بندی کرد — با مدل مرجع OSI و TCP/IP. با این کار، فصل ۱ به پایان رسیده است.
