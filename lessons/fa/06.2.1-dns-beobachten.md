## آزمایش

1. به حالت :fa-play: **اجرا** برو، روی **Client-PC** کلیک کن و :fa-globe: **مرورگر** را باز کن.
2. این بار `http://www.beaver-schule.de/` را باز کن — با نام به‌جای آدرس IP.
3. به حالت :fa-magnifying-glass: **ردیابی** برو و یک Trace برای **Client-PC** باز کن.

درست در ابتدا — حتی پیش از برقراری اتصال با `[SYN]` — دو بسته با پروتکل **DNS** قرار دارند.

:::quiz short
Client-PC درخواست DNS خود را به کدام آدرس IP می‌فرستد؟
= 192.168.0.53
:::

:::quiz short
در پاسخ برای `www.beaver-schule.de` کدام آدرس IP آمده است؟
= 192.168.0.20
:::

:::quiz mc

- [ ] TCP، پورت 80
- [x] UDP، پورت 53

:::evaluate
بررسی پاسخ‌ها

فقط پس از آنکه Client-PC آدرس IP را شناخت، اتصال TCP را با وب‌سرور برقرار می‌کند — دقیقاً مانند فصل ۵.

:::seq
mode: text
Client-PC -> DNS-Resolver: DNS-Anfrage | A www.beaver-schule.de?
DNS-Resolver -> Client-PC: DNS-Antwort | A 192.168.0.20
:::

## کامپیوتر سرور DNS را از کجا می‌شناسد؟

در **Client-PC** پنجرهٔ :fa-gear: **تنظیمات IP** را باز کن: در فیلد **DNS-Server** مقدار `192.168.0.53` نوشته شده است — همان کامپیوتر **DNS-Resolver**. کامپیوتر هر درخواست نام را به آن می‌فرستد.

می‌توانی سرور DNS را مستقیماً و بدون مرورگر هم بپرسی. :fa-terminal: **ترمینال** را باز کن و این را وارد کن:

```
$ nslookup www.beaver-schule.de
```

`nslookup` ابتدا نشان می‌دهد از کدام سرور پرسیده است، سپس پاسخ را. برای مقایسه، نامی را بپرس که وجود ندارد، مثلاً `nslookup gibtsnicht.beaver-schule.de`.

:::quiz mc
سرور DNS به نام ناشناخته چه پاسخی می‌دهد؟
- [ ] یک آدرس IP تصادفی
- [x] `NXDOMAIN` — چنین نامی وجود ندارد
- [ ] هیچ پاسخی
:::

:::evaluate
بررسی پاسخ
:::

:::tip نکتهٔ کلیدی
**DNS** نام‌ها (مثلاً `www.beaver-schule.de`) را به آدرس‌های IP تبدیل می‌کند. پیش از آنکه یک کامپیوتر بتواند به یک نام متصل شود، از **سرور DNS** که در تنظیمات IP او ثبت شده می‌پرسد — معمولاً از طریق **UDP، پورت 53**. با `nslookup` می‌توانی درخواست‌های DNS را دستی بفرستی.
:::
