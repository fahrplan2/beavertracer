# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) همان HTTP معمولی است — با این تفاوت که مستقیم روی TCP اجرا نمی‌شود، بلکه از میان یک لایهٔ رمزگذاری‌شده در بین آن‌ها عبور می‌کند: **TLS** (*Transport Layer Security*). پیشینِ TLS **SSL** نام داشت؛ به همین دلیل هنوز هم اغلب از «گواهی‌های SSL» صحبت می‌شود.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP از این موضوع چیزی متوجه نمی‌شود: درخواست‌هایش را مثل همیشه می‌فرستد، TLS آن‌ها را رمزگذاری می‌کند و TCP آن‌ها را منتقل می‌کند. در مدل OSI، TLS میان لایه انتقال و لایه کاربرد قرار می‌گیرد، یعنی در لایهٔ ۴/۵ — روی TCP بنا می‌شود و یک نشست امن را مدیریت می‌کند.

| | HTTP | HTTPS |
|---|---|---|
| پورت | 80 | **443** |
| آدرس | `http://…` | `https://…` |
| محتوا در Tracer قابل خواندن است؟ | بله | خیر |
| مرورگر نشان می‌دهد | «ناامن» | قفل |

TLS هنگام برقراری اتصال همهٔ کارهایی را که در این فصل یاد گرفتی انجام می‌دهد:

- سرور با **گواهی** خود هویتش را اثبات می‌کند (**اصالت**).
- هر دو طرف با **Diffie-Hellman** یک **کلید نشست** را توافق می‌کنند — سرور سهم خود را **امضا** می‌کند.
- پس از آن، همهٔ داده‌ها با **AES** رمزگذاری می‌شوند (**محرمانگی**) و در برابر تغییر محافظت می‌شوند (**یکپارچگی**).

این اصل به وب محدود نیست: ایمیل (بخش ۸.۴) و بسیاری از پروتکل‌های دیگر نیز به همین شیوه از TLS استفاده می‌کنند.

در بخش‌های بعدی HTTPS را در Tracer مشاهده می‌کنی، خودت آن را راه‌اندازی می‌کنی و بررسی می‌کنی که مرورگر چه زمانی هشدار می‌دهد — و چرا.
