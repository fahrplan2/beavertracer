# Fehlersuche: Seit den neuen Regeln geht nichts mehr

:::sim
url=/sims/lesson-9.4.btsim
:::

Herr Biber, der Administrator der Beaver-Schule, hat gestern die Firewall auf das Whitelist-Prinzip umgestellt. Seitdem beschweren sich alle: Die **Webseite der Schule** ist von außen nicht mehr erreichbar, und es kommen **keine Mails aus dem Internet** mehr an. Immerhin: SSH ist jetzt von außen gesperrt, wie gewünscht.

Finde die Fehler in den Regeln der **Firewall** und behebe sie.

<details>
<summary>Tipp 1: Kommt das Paket überhaupt an die richtige Regel?</summary>

Teste vom **Internet-PC** aus mit `nmap -p 22,25,80 198.51.100.10` und sieh dir danach in der Firewall die Spalte **Treffer** an. Eine Regel, die bei 0 bleibt, obwohl Pakete für sie kommen müssten, wird von einer anderen Regel verdeckt — oder passt nie.
</details>

<details>
<summary>Tipp 2: Genau hinsehen</summary>

Vergleiche jede Zahl in den Regeln mit den Ports aus Kapitel 5: Welcher Port gehört zu HTTP, welcher zu SMTP? Und denk an die Reihenfolge: Die erste passende Regel gewinnt.
</details>

:::task
title: Web und Mail wieder erreichbar?
Prüft, ob Web und Mail des Schulservers aus dem Internet erreichbar sind und SSH gesperrt bleibt.
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## Was war los?

:::quiz multi
Welche Fehler steckten in den Regeln?
- [x] Die Web-Regel erlaubte Port 8080 statt 80
- [x] Die Mail-Regel stand unter der Regel „alles verwerfen“ und wurde nie erreicht
- [ ] Die Firewall stand auf Stateful
- [ ] Port 25 ist für Mail der falsche Port
:::

:::evaluate
Antworten prüfen
:::

:::tip Merksatz
Typische Fehler in Firewall-Regeln: ein **Zahlendreher** im Port, die falsche **Richtung** und eine falsche **Reihenfolge**, bei der eine allgemeine Regel eine spezielle verdeckt. Bei der Fehlersuche helfen ein **Portscan** von außen, das **Protokoll** der Firewall und die **Trefferzähler** der Regeln.
:::
