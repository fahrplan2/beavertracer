# Zertifikate: Wem gehört dieser Schlüssel?

Mit asymmetrischer Verschlüsselung und Signaturen scheint alles gelöst: Der Webserver deiner Bank schickt dir seinen öffentlichen Schlüssel, und los geht's. Aber woher weißt du, dass dieser öffentliche Schlüssel **wirklich der Bank gehört**?

Ein Angreifer, der deine Verbindung umleitet, könnte dir einfach **seinen eigenen** öffentlichen Schlüssel schicken und behaupten, er sei die Bank. Dein Browser würde dann brav mit dem Angreifer verschlüsseln — und der liest alles mit. So ein Angreifer in der Mitte heißt **Man-in-the-Middle**.

## Das Zertifikat: ein Ausweis für Schlüssel

Im echten Leben zeigst du deinen **Personalausweis**, um zu beweisen, wer du bist. Dem Ausweis glaubt man, weil ihn eine **vertrauenswürdige Stelle** ausgestellt hat — die Stadtverwaltung — und weil er schwer zu fälschen ist.

Im Netz übernimmt das ein **Zertifikat**. Es enthält unter anderem:

| Feld | Bedeutung | beim Personalausweis |
|---|---|---|
| **Betreff** (*Subject*, oft `CN=…`) | Für wen ist das Zertifikat? Bei Webservern: der Name, z.B. `CN=www.biberbank.de` | Name des Inhabers |
| **Öffentlicher Schlüssel** | Der Schlüssel des Inhabers | Foto |
| **Aussteller** (*Issuer*) | Wer hat das Zertifikat ausgestellt? | ausstellende Behörde |
| **Gültigkeit** | von … bis … | gültig bis |
| **Signatur** des Ausstellers | Beweist, dass der Aussteller das Zertifikat wirklich so ausgestellt hat | Siegel, Hologramm |

`CN` steht für *Common Name*.

Die Stelle, die Zertifikate ausstellt, heißt **Zertifizierungsstelle** (*Certificate Authority*, kurz **CA**). Bevor sie ein Zertifikat für `www.biberbank.de` signiert, prüft sie, dass der Antragsteller diese Domain wirklich besitzt.

## Wem vertraut der Browser?

Dein Browser prüft bei jedem Zertifikat:

1. Ist die **Signatur** der CA echt? (Dafür braucht er den öffentlichen Schlüssel der CA.)
2. Ist das Zertifikat noch **gültig**?
3. Passt der **Name** im Zertifikat zur aufgerufenen Adresse?

Aber woher kennt der Browser die CA? In jedem Betriebssystem und Browser ist eine Liste von rund 150 **Wurzel-CAs** (*Root-CAs*) **vorinstalliert**. Deren Zertifikate sind **selbstsigniert** — sie bestätigen sich selbst; ihnen vertraut man, weil sie mit der Software geliefert werden.

Oft signiert eine Root-CA nicht direkt, sondern über eine **Zwischen-CA**. So entsteht eine **Vertrauenskette**:

```
Root-CA (vorinstalliert, vertraut)
  └─ signiert → Zwischen-CA
                  └─ signiert → www.biberbank.de
```

Der Browser folgt der Kette von unten nach oben, bis er bei einer Root-CA ankommt, der er vertraut. Klappt das nicht — oder stimmt Gültigkeit oder Name nicht —, zeigt er eine **Warnung**.

:::quiz match
Betreff (CN) -> Für welchen Namen das Zertifikat gilt
Aussteller -> Welche CA das Zertifikat signiert hat
Öffentlicher Schlüssel -> Wird zum Prüfen von Signaturen des Servers gebraucht
Root-CA -> Ist im Browser vorinstalliert und bildet den Anfang der Vertrauenskette
:::

:::tip Merksatz
Ein **Zertifikat** bestätigt, dass ein **öffentlicher Schlüssel** zu einem bestimmten **Namen** gehört. Es wird von einer **Zertifizierungsstelle (CA)** signiert. Der Browser vertraut einem Zertifikat, wenn er über eine **Vertrauenskette** bei einer vorinstallierten **Root-CA** ankommt, das Zertifikat **gültig** ist und der **Name** zur Adresse passt.
:::
