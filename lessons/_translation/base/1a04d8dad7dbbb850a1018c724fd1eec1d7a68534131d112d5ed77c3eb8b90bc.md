## Ping von außen

Wechsle in den :fa-play: **Ausführen**-Modus und pinge vom **Internet-PC** aus den Schulserver an:

```
$ ping -c 2 198.51.100.10
```

Öffne danach in der Firewall den Reiter **Protokoll**.

## Portscan: verworfen oder zurückgewiesen?

Scanne nun gezielt fünf Ports. Port 3306 (eine Datenbank) ist auf dem Schulserver gar nicht in Betrieb.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (verworfen) -> filtered
25 (erlaubt, Dienst läuft) -> open
110 (zurückgewiesen) -> closed
3306 (erlaubt, kein Dienst) -> closed
:::

:::evaluate
Zuordnung prüfen
:::

:::quiz multi
Was kann ein Angreifer aus dem Ergebnis schließen?
- [x] Bei `filtered` weiß er: Da sitzt eine Firewall, die Pakete verschluckt
- [x] Bei `closed` kann er nicht unterscheiden, ob eine Firewall zurückweist oder einfach kein Dienst läuft
- [ ] Bei `filtered` weiß er, welcher Dienst hinter dem Port läuft
- [ ] Bei `closed` ist der Dienst trotzdem erreichbar
:::

:::evaluate
Antworten prüfen
:::

Sieh dir zum Schluss die Spalte **Treffer** in der Regelliste an: Dort zählt die Firewall, wie viele Pakete jede Regel schon entschieden hat. Der Wert neben der **Standardrichtlinie** zählt alle Pakete, auf die keine Regel gepasst hat.

:::tip Merksatz
**Verworfene** Pakete verschwinden spurlos: `ping` meldet ein Timeout, `nmap` meldet `filtered`. **Zurückgewiesene** Pakete beantwortet die Firewall mit einer Absage (bei TCP ein RST) — von außen sieht das aus wie ein geschlossener Port. Das **Protokoll** der Firewall zeigt, welche Pakete sie aufgehalten hat, die Spalte **Treffer**, welche Regel gegriffen hat.
:::
