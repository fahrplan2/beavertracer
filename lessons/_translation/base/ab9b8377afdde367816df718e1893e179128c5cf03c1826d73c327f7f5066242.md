# Fehlersuche: Der Name funktioniert nicht

:::sim
url=/sims/lesson-6.2.3.btsim
:::

Eine Lehrerin meldet: „`www.beaver-schule.de` lädt bei mir nicht. Mit `http://192.168.0.20` klappt es aber!“ So *soll* es eingerichtet sein:

| Was | Soll |
|---|---|
| DNS-Server am Client-PC | `192.168.0.53` (DNS-Resolver) |
| Eintrag im Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Finde die Fehler und behebe sie.

<details>
<summary>Tipp 1: Was sagt nslookup?</summary>

Gib auf dem Client-PC `nslookup www.beaver-schule.de` ein. Welchen Server hat `nslookup` gefragt — und was kam zurück? (Die Antwort dauert ein paar Sekunden.)
</details>

<details>
<summary>Tipp 2: Und jetzt?</summary>

Bekommst du eine Antwort, vergleiche die Adresse mit dem Plan. Wo ist dieser Name eingetragen?
</details>

:::task
title: Namensauflösung repariert?
Prüft, ob der Client-PC www.beaver-schule.de zur richtigen Adresse auflöst. Die Simulation muss dafür im Ausführen-Modus laufen.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Was war los?

:::quiz multi
Welche Aussagen stimmen?
- [x] Am Client-PC war `192.168.0.35` als DNS-Server eingetragen — dort antwortet niemand
- [x] Im Schul-DNS zeigte `www.beaver-schule.de` auf `192.168.0.21` statt auf `192.168.0.20`
- [ ] Der Webserver war ausgeschaltet
- [ ] Der Root-Server kannte die Domain `.de` nicht
:::

:::evaluate
Antwort prüfen
:::

:::tip Merksatz
Klappt eine Verbindung mit der **IP-Adresse**, aber nicht mit dem **Namen**, liegt das Problem bei **DNS**. Prüfe zuerst den **eingetragenen DNS-Server** (antwortet er überhaupt?), dann den **Eintrag** selbst (stimmt die Adresse?). `nslookup` zeigt beides: welcher Server gefragt wurde und was er geantwortet hat.
:::
