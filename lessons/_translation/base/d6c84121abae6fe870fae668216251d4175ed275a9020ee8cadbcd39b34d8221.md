# Sequenz- und Bestätigungsnummern

:::sim
url=/sims/lesson-5.1.btsim
:::

Woher weiß TCP, ob alles angekommen ist — und in welcher Reihenfolge? Jede Seite **nummeriert die Bytes**, die sie sendet:

- Die **Sequenznummer** (`SEQ`) ist die Nummer des ersten Bytes, das in diesem Paket steckt.
- Die **Bestätigungsnummer** (`ACK`) sagt: „Bis hierher habe ich alles bekommen — als Nächstes erwarte ich Byte Nr. …“

Dazu zwei Regeln: `SYN` und `FIN` zählen wie ein Byte, obwohl sie keine Daten tragen. Und jede Seite zählt für sich — deshalb gibt es zwei Nummernkreise, im Diagramm rot (Client) und blau (Server).

## Nachrechnen

Hier noch einmal deine Verbindung. Die Zahlen an den Linien zeigen jeweils den Zähler des Rechners an dieser Stelle:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Geh die rote Zahlenreihe durch:

1. Der Client beginnt bei `SEQ=0`. Sein `SYN` verbraucht eine Nummer — der Server bestätigt mit `ACK=1`.
2. Die Nachricht beginnt bei `SEQ=1` und ist 13 Byte lang (Bytes 1 bis 13). Der Server bestätigt mit `ACK=14`: „Als Nächstes erwarte ich Byte 14.“
3. Das `FIN` des Clients hat deshalb `SEQ=14` und wird mit `ACK=15` bestätigt.

Die blaue Reihe des Servers funktioniert genauso.

:::tip Merksatz
Die **Sequenznummer** (`SEQ`) ist die Nummer des ersten Bytes im Paket. Die **Bestätigungsnummer** (`ACK`) ist die Nummer des nächsten Bytes, das der Empfänger erwartet — alles davor ist angekommen. Es gilt: **ACK = SEQ + Länge** der empfangenen Daten; `SYN` und `FIN` zählen wie ein Byte. Jede Seite zählt ihre eigenen Bytes.
:::

:::tip Probier es aus
Bau die Verbindung im **Einfachen TCP-Client** noch einmal auf und schick zwei Nachrichten hintereinander. Sag vorher, welche `Seq` und `Ack` in der **Info**-Spalte stehen werden — und prüf es im Trace nach.
:::

:::note
In echten Netzen beginnt die Zählung nicht bei 0: Jede Seite wählt eine **zufällige Startnummer** (*Initial Sequence Number*, ISN) zwischen 0 und rund 4,3 Milliarden. Ist die höchste Nummer erreicht, geht es wieder bei 0 weiter. Der Tracer zieht die Startnummer ab und zeigt **relative** Nummern — genau wie Wireshark. Deshalb siehst du `Seq=0` und `Seq=1`.

Außerdem steht in jedem Paket `Win=` — die **Fenstergröße**: So viele Bytes kann der Empfänger gerade aufnehmen. Damit bremst er einen zu schnellen Sender (*Flusskontrolle*). In BeaverTracer ist das Fenster immer gleich groß.
:::
