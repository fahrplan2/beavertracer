# Warum ein Netz nicht reicht

:::sim
url=/sims/lesson-4.1.btsim
:::

Auf der Arbeitsfläche siehst du zwei kleine Firmennetze: **Firma A** mit Anna (`192.168.0.10`) und Ben (`192.168.0.11`), **Firma B** mit Clara (`172.16.0.10`) und David (`172.16.0.11`). Die beiden Switches sind sogar direkt mit einem Kabel verbunden.

## Ein Ping im eigenen Netz

1. Wechsle in den :fa-play: **Ausführen**-Modus, öffne auf **Anna** das :fa-terminal: **Terminal** und pinge Ben an:
   ```
   $ ping 192.168.0.11
   ```
2. Wechsle in den :fa-magnifying-glass: **Verfolgung**-Modus, öffne einen Trace für **Anna** und klicke auf einen `Echo (ping) request`.
3. Klappe im Protokollbaum die Zeile **Internet Protocol Version 4** auf. Das ist der IP-Teil des Pakets — der Teil, um den es in diesem Kapitel geht.

:::quiz match
Source Address -> IP-Adresse des Absenders
Destination Address -> IP-Adresse des Empfängers
Time to Live -> Wie viele Router das Paket noch passieren darf
Protocol -> Welches Protokoll im Paket steckt (hier ICMP, also der Ping)
:::

:::evaluate
Zuordnung prüfen
:::

## Ein Ping ins andere Netz

Wechsle zurück in den :fa-play: **Ausführen**-Modus und pinge von **Anna** aus Clara an (`ping 172.16.0.10`). Schau dir danach Annas Trace noch einmal an.

:::quiz mc
Was passiert?
- [ ] Der Ping klappt — die Switches sind ja verbunden
- [x] Kein Ping kommt an, und in Annas Trace taucht kein einziges Paket an Clara auf — nicht einmal eine ARP-Anfrage
- [ ] Anna schickt eine ARP-Anfrage, aber Clara antwortet nicht
:::

:::quiz mc
Warum schickt Anna überhaupt nichts los?
- [ ] Das Kabel zwischen den Switches ist kaputt
- [ ] Clara ist ausgeschaltet
- [x] Anna erkennt an Claras IP-Adresse, dass Clara in einem anderen Netz liegt — und kennt keinen Weg dorthin
:::

Antworten prüfen
:::

## Was dahintersteckt

Eine IP-Adresse funktioniert ähnlich wie eine Postanschrift: Ein Teil sagt, in welchem **Netz** ein Gerät liegt (wie die Straße), der andere Teil, welches **Gerät** in diesem Netz gemeint ist (wie die Hausnummer). Anna liegt im Netz `192.168.0…`, Clara im Netz `172.16.0…` — zwei verschiedene „Straßen“.

An Geräte im *eigenen* Netz schickt ein PC Pakete direkt (über ARP und den Switch, wie du es kennst). Für ein *fremdes* Netz braucht er ein Gerät, das die Netze miteinander verbindet und Pakete weiterreicht: einen **Router**. Den gibt es hier noch nicht — deshalb hilft auch das Kabel zwischen den Switches nichts.

:::tip Merksatz
Das **Internet Protocol** (**IP**) auf Schicht 3 sorgt dafür, dass Pakete auch zwischen verschiedenen Netzen ankommen. Eine **IP-Adresse** besteht aus einem **Netzteil** (in welchem Netz?) und einem **Hostteil** (welches Gerät?). Geräte im selben Netz erreichen sich direkt — für andere Netze braucht man einen **Router**.
:::

Damit stellen sich zwei Fragen, um die es in den nächsten Abschnitten geht: Woher weiß ein PC, *wo genau* in der Adresse der Netzteil aufhört? Und wie funktioniert ein Router?
