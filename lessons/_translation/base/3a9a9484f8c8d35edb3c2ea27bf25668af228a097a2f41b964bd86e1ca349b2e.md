NAT ist eine geniale Notlösung für den Mangel an IPv4-Adressen — aber eben eine Notlösung. Zwei Entwicklungen solltest du kennen.

## IPv6: kein NAT mehr nötig

Bei **IPv6** gibt es Adressen im Überfluss (Kapitel 4.6). Der Provider gibt dem Heimrouter deshalb nicht nur eine Adresse, sondern ein ganzes **Präfix** — oft ein `/56` oder `/48`, also Milliarden von Adressen. Das nennt man **Präfix-Delegation** (DHCPv6-PD). Der Heimrouter verteilt daraus per SLAAC an jedes Gerät eine eigene, **weltweit eindeutige** Adresse.

NAT ist dann nicht mehr nötig: Jedes Gerät ist direkt adressierbar. Das ist praktisch, verlangt aber eine gute **Firewall** im Router — denn der „Nebeneffekt“ von NAT, dass niemand von außen eine Verbindung beginnen kann, fällt weg. Darum geht es in Kapitel 9.

## Carrier-Grade-NAT: NAT beim Provider

Viele Provider haben selbst zu wenige IPv4-Adressen. Dann bekommt nicht einmal mehr der Heimrouter eine öffentliche Adresse, sondern nur eine aus einem speziellen Bereich (`100.64.0.0/10`), und der Provider macht **noch einmal NAT** für viele Kunden gemeinsam. Das heißt **Carrier-Grade-NAT** (CGNAT); oft gibt es dann für IPv4 nur noch diesen Weg, für IPv6 dagegen echte öffentliche Adressen (*DS-Lite*).

Die Folge: Eine **Portweiterleitung** im eigenen Router nützt bei IPv4 nichts mehr — die Pakete von außen bleiben schon beim Provider hängen. Wer zu Hause einen Server betreiben will, braucht dann IPv6 oder einen anderen Anschluss.
