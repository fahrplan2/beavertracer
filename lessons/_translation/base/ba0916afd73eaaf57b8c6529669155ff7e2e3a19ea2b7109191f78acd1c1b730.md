# Fehlersuche: Der Dienst antwortet nicht

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Nach einem Update meldet die Schule: „Der Echo-Dienst lehnt jede Verbindung ab, und die Webseite lädt auch nicht mehr.“ Laut Plan soll der **Webserver** an Port `80` lauschen und der **Echo-Dienst** (TCP-Echo-Server) an Port `5000`. Finde die Fehler und behebe sie.

<details>
<summary>Tipp 1: Was antwortet der Server?</summary>

Versuche dich mit dem **Einfachen TCP-Client** zu `192.168.0.20`, Port `5000` zu verbinden, und öffne einen Trace für den Client-PC. Womit antwortet der Server auf dein `[SYN]`?
</details>

<details>
<summary>Tipp 2: Welche Ports sind offen?</summary>

Gib auf dem Client-PC im Terminal `nmap -p 80,5000 192.168.0.20` ein. `nmap` probiert die Ports der Reihe nach aus und zeigt, welche offen sind. Mit `ss` auf dem Server siehst du, an welchen Ports dort wirklich ein Programm lauscht.
</details>

<details>
<summary>Tipp 3: Wo stellt man das ein?</summary>

Öffne auf dem **Server** die Apps **TCP-Echo-Server** und **HTTP-Server**. Läuft der Dienst? Und an welchem Port?
</details>

:::task
title: Dienste erreichbar?
Prüft, ob der Client-PC den Echo-Dienst an Port 5000 und den Webserver an Port 80 erreicht. Die Simulation muss dafür im Ausführen-Modus laufen.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Was war los?

:::quiz multi
Welche Aussagen stimmen?
- [x] Auf das `[SYN]` an Port 5000 antwortete der Server mit `[RST, ACK]`
- [x] Der Echo-Dienst lauschte an Port 5050 statt an Port 5000
- [x] Der Webserver war gar nicht gestartet
- [ ] Das Kabel zwischen Client-PC und Server war defekt
:::

:::evaluate
Antwort prüfen
:::

:::tip Merksatz
Kommt auf ein `SYN` ein **`RST`** zurück, lauscht an diesem Port **kein Programm**: Der Rechner ist erreichbar, aber der Dienst nicht. Typische Ursachen: Der Dienst ist **nicht gestartet** oder lauscht an einem **anderen Port**. Ein Blick mit `ss` auf den Server zeigt, welche Ports wirklich offen sind.
:::
