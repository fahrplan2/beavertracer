# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) is ganz normales HTTP — nur dass es net direkt iwwer TCP läuft, sondern dorch e verschlüsselte Schicht dezwische: **TLS** (*Transport Layer Security*). De Vorgänger vun TLS hat **SSL** gehaaße; deshalb redd mer oft noch vun „SSL-Zertifikate“.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP merkt devon nix: Es schickt seine Anfroge wie gewohnt, TLS verschlüsselt se, TCP transportiert se. Im OSI-Modell sitzt TLS zwische Transport- und Anwendungsschicht, also in Schicht 4/5 — es baut uff TCP uff un verwaltet e gesicherte Sitzung.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresse | `http://…` | `https://…` |
| Inhalt im Tracer lesbar? | ja | nee |
| Browser zeigt | „nicht sicher“ | Schloss |

TLS erledigt beim Verbindungsaufbau alles, was du in dem Kapitel gelernt hast:

- De Server weist sich mit seim **Zertifikat** aus (**Authentizität**).
- Beide Seite handele mit **Diffie-Hellman** en **Sitzungsschlüssel** aus — de Server **signiert** sein Anteil.
- Danach werre alle Daten mit **AES** verschlüsselt (**Vertraulichkeit**) un gege Veränderung gesichert (**Integrität**).

Des Prinzip is net uff des Web beschränkt: Aach E-Mail (Abschnitt 8.4) un viele annere Protokolle laufe uff die selbe Art dorch TLS.
