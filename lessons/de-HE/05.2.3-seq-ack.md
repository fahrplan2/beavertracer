# Sequenz- und Bestätigungsnummern

:::sim
url=/sims/lesson-5.1.btsim
:::

Woher weiß TCP, ob alles aagekomme is — und in welcher Reihefolg? Jede Seit **nummeriert die Bytes**, die se schickt:

- Die **Sequenznummer** (`SEQ`) is die Nummer vom erste Byte, des in dem Paket drinsteckt.
- Die **Bestätigungsnummer** (`ACK`) sagt: „Bis hierher hab isch alles kriegt — als Nächstes erwart isch Byte Nr. …“

Dazu zwei Regele: `SYN` und `FIN` zähle wie ein Byte, obwohl se kaa Date trage. Und jede Seit zählt für sich — deswege gibt's zwaa Nummernkreise, im Diagramm rot (Client) und blau (Server).

## Nachrechne

Hier nomol deine Verbindung. Die Zahle an de Linie zeige jeweils de Zähler vom Rechner an dere Stell:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Geh die rote Zahlereih emol durch:

1. De Client fängt bei `SEQ=0` aa. Sei `SYN` verbraucht eine Nummer — de Server bestätigt mit `ACK=1`.
2. Die Nachricht fängt bei `SEQ=1` aa und is 13 Byte lang (Bytes 1 bis 13). De Server bestätigt mit `ACK=14`: „Als Nächstes erwart isch Byte 14.“
3. Des `FIN` vom Client hat deshalb `SEQ=14` und werd mit `ACK=15` bestätigt.

Die blau Reih vom Server funktioniert genauso.

:::tip Merksatz
Die **Sequenznummer** (`SEQ`) is die Nummer vom erste Byte im Paket. Die **Bestätigungsnummer** (`ACK`) is die Nummer vom nächste Byte, des de Empfänger erwartet — alles davor is aagekomme. Es gilt: **ACK = SEQ + Läng** von de empfangene Date; `SYN` und `FIN` zähle wie ein Byte. Jede Seit zählt ihre eigene Bytes.
:::

:::tip Probier's aus
Bau die Verbindung im **Einfacher TCP-Client** nomol uff und schick zwaa Nachrichte hinnerenanner. Sag vorher, welche `Seq` und `Ack` in de **Info**-Spalt stehe werde — und prüf's im Trace nach, gell?
:::

:::note
In echte Netze fängt die Zählung net bei 0 aa: Jede Seit wählt e **zufällige Startnummer** (*Initial Sequence Number*, ISN) zwische 0 und ungefähr 4,3 Milliarde. Is die höchste Nummer erreicht, geht's widder bei 0 weiter. Der Tracer zieht die Startnummer ab und zeigt **relative** Nummere — genau wie Wireshark. Deshalb siehste `Seq=0` und `Seq=1`.

Außerdem steht in jedem Paket `Win=` — die **Fenstergröße**: So viel Bytes kann de Empfänger grad aufnemme. Domit bremst er en zu schnelle Sender (*Flusskontrolle*). In BeaverTracer is des Fenster immer gleich groß.
:::
