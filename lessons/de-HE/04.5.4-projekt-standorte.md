# Projekt: Ei Firma mit vier Standorte

:::sim
url=/sims/lesson-4.5.4.btsim
:::

Ei Firma hat ihrn Hauptsitz in **Hanau** unn Filiale in **Kassel**, **Gießen** unn **Darmstadt**. Jeder Standort hat e eigenes Netz unn e eigene Router. Alle Router sin iwwer Standleitunge mit eme **zentrale Netz** verbunne, in dem aach de Hauptserver vun de Firma steht.

## De Adressplan

De Administrator hat die Adresse nach dem folgende Schema vergewwe — se sin in de Simulation schon eingetraache:

| Netz | Adressbereich |
|---|---|
| Zentrales Netz | `10.19.0.0/24` |
| Hanau | `10.19.1.0/24` |
| Kassel | `10.19.2.0/24` |
| Gießen | `10.19.3.0/24` |
| Darmstadt | `10.19.4.0/24` |

| Gerät | im zentrale Netz | im Standortnetz |
|---|---|---|
| Server | `10.19.0.10` | — |
| Router Hanau | `10.19.0.1` | `10.19.1.1` |
| Router Kassel | `10.19.0.2` | `10.19.2.1` |
| Router Gießen | `10.19.0.3` | `10.19.3.1` |
| Router Darmstadt | `10.19.0.4` | `10.19.4.1` |
| PC am Standort | — | jeweils `.2` (z.B. PC Kassel `10.19.2.2`) |

Bei alle Router zeigt `eth0` ins zentrale Netz unn `eth1` ins Standortnetz.

## Dei Uffdrag

Damit alle Rechner vun de Firma sich gegeseitich unn de Server erreiche, fehle noch zwei Sache:

1. **Gateways:** Trag bei alle vier PCs unn beim Server e Gateway ei. Die PCs nutze de Router vun ihrm Standort; de Server nutzt de **Router Hanau**.
2. **Routing-Tabelle:** Ergänz bei alle vier Router die Route, die noch fehle. Jeder Router muss die Netze vun de **drei annern** Standorte kenne.

Test zwischedurch mit `ping` unn `traceroute`.

<details>
<summary>Tipp: Wie sieht e Route hier aus?</summary>

E Beispiel für **Router Kassel**: Pakete für Gießen (`10.19.3.0/24`) gehn an de Router Gießen in seim zentrale Netz — also **Nächster Hop** `10.19.0.3`, **Iface** `eth0`. Nach dem Muster braucht jeder Router drei Route.
</details>
