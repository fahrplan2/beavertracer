Op de **Server** draait deze keer een **UDP Echo-server** op poort `5000`. Ook hier is de kabel voorbereid: het **tweede datagram** van de client-pc naar de server gaat verloren.

## Het experiment

1. Schakel over naar de :fa-play: **Uitvoeren**-modus en open op de **Client-PC** het :fa-terminal: **Terminal**.
2. Start met `nc` een UDP-"verbinding" met de server (`-u` staat voor UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Typ na elkaar `eins`, `zwei` en `drei` en druk telkens op **Enter**. Elke regel die terugkomt, is een echo van de server.
4. Wacht een paar seconden en open dan in de :fa-magnifying-glass: **Tracering**-modus een trace voor de **Client-PC**.

:::quiz mc
Welke echo's komen terug?
- [ ] Alle drie, `zwei` iets later
- [x] Alleen `eins` en `drei` — `zwei` ontbreekt en wordt ook niet opnieuw verzonden
- [ ] Geen enkele
:::

:::quiz multi
Welke pakketten die je van TCP kent, ontbreken bij UDP helemaal?
- [x] Verbindingsopbouw (`SYN`)
- [x] Bevestigingen (`ACK`)
- [x] Verbindingsafbouw (`FIN`)
- [ ] Pakketten met poortnummers
:::

:::evaluate
Antwoorden controleren
:::

Klik op een van de UDP-pakketten en klap **User Datagram Protocol** open. Vergeleken met de TCP-header is de UDP-header piepklein: **Source Port**, **Destination Port**, **Length** (lengte) en **Checksum** (controlesom) — samen slechts 8 byte. Een TCP-header heeft minstens 20 byte, met volgnummer en bevestigingsnummer, flags en venstergrootte.

:::quiz mc
Welke taak uit paragraaf 5.1 voert UDP toch uit?
- [x] Multiplexen — via de poorten
- [ ] Verbindingsopbouw
- [ ] Betrouwbare overdracht
:::

:::evaluate
Antwoord controleren
:::

:::tip Onthoud
**UDP** is **verbindingsloos**: geen opbouw, geen bevestiging, geen hertransmissie, geen volgorde. Het biedt alleen **poorten** (multiplexen) en een **controlesom**. Daarvoor is het snel en slank — de UDP-header is slechts 8 byte. Gaat een datagram verloren, dan moet het programma dat zelf oplossen — of het maakt het niet uit.
:::
