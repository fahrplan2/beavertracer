# Het sequentiediagram

:::sim
url=/sims/lesson-5.1.btsim
:::

Het verloop van een verbinding teken je als **sequentiediagram**: client en server krijgen elk een verticale lijn, de tijd loopt van boven naar beneden. Elke pijl is een pakket. Hij is schuin getekend, omdat elk pakket even onderweg is.

Zo ziet jouw verbinding van de vorige pagina eruit — vergelijk het regel voor regel met de trace:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Boven elke pijl staan de **flags**, eronder de nummers `SEQ` en `ACK`. **DATA** markeert pakketten met nuttige lading. De rode getallen horen bij de client, de blauwe bij de server — wat ze betekenen, wordt op de volgende pagina uitgelegd.

## De flags

| Flag | staat voor | Betekenis |
|---|---|---|
| **SYN** | *synchronize* | verbinding opbouwen, beginnummer vastleggen |
| **ACK** | *acknowledge* | bevestigt ontvangen data |
| **PSH** | *push* | data direct doorgeven aan het programma |
| **FIN** | *finish* | „Ik ben klaar” — verbinding verbreken |
| **RST** | *reset* | verbinding afbreken of weigeren (meer hierover in 5.3.2) |

## Drie fasen

**Opbouw:** de client stuurt `SYN`, de server antwoordt met `SYN, ACK`, de client bevestigt met `ACK`. Omdat er precies drie pakketten nodig zijn, heet dit de **three-way handshake**.

**Data:** elk pakket met data wordt door de ontvanger met een `ACK` bevestigd. Hier stuurt de server de echo terug — ook dat bevestigt de client.

**Afbouw:** elke kant beëindigt zijn eigen zendrichting afzonderlijk: `FIN` van de client, `ACK` van de server — daarna `FIN` van de server, `ACK` van de client. Dat zijn vier pakketten.

:::tip Onthoud
Een TCP-verbinding verloopt in drie fasen: **opbouw** met de **three-way handshake** (`SYN` → `SYN, ACK` → `ACK`), **datatransport** (elk datapakket wordt met `ACK` bevestigd) en **afbouw** (elke kant stuurt `FIN` en krijgt een `ACK`).
:::
