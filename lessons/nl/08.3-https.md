# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) is gewoon HTTP — alleen loopt het niet rechtstreeks over TCP, maar via een versleutelde laag daartussen: **TLS** (*Transport Layer Security*). De voorganger van TLS heette **SSL**; daarom spreekt men vaak nog van "SSL-certificaten".

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP merkt hier niets van: het verstuurt zijn verzoeken zoals gewoonlijk, TLS versleutelt ze, TCP transporteert ze. In het OSI-model zit TLS tussen de transportlaag en de applicatielaag, dus in laag 4/5 — het bouwt voort op TCP en beheert een beveiligde sessie.

| | HTTP | HTTPS |
|---|---|---|
| Poort | 80 | **443** |
| Adres | `http://…` | `https://…` |
| Inhoud leesbaar in de tracer? | ja | nee |
| Browser toont | "niet veilig" | slotje |

TLS doet bij de verbindingsopbouw alles wat je in dit hoofdstuk hebt geleerd:

- De server legitimeert zich met zijn **certificaat** (**authenticiteit**).
- Beide kanten onderhandelen met **Diffie-Hellman** over een **sessiesleutel** — de server **ondertekent** zijn deel.
- Daarna worden alle gegevens met **AES** versleuteld (**vertrouwelijkheid**) en beveiligd tegen wijziging (**integriteit**).

Het principe is niet beperkt tot het web: ook e-mail (paragraaf 8.4) en veel andere protocollen lopen op dezelfde manier via TLS.
