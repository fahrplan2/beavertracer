# Samenvatting en vooruitblik

## De bouwstenen in een overzicht

| Bouwsteen | Beveiligingsdoel | Voorbeeld |
|---|---|---|
| **Symmetrische versleuteling** | Vertrouwelijkheid | AES versleutelt de gegevens van een HTTPS-verbinding |
| **Asymmetrische versleuteling** | Vertrouwelijkheid, sleuteluitwisseling | Diffie-Hellman, RSA |
| **Hashwaarden** | Integriteit | SHA-256-controlesom van een download |
| **Digitale handtekening** | Authenticiteit, integriteit | Server ondertekent zijn Diffie-Hellman-deel |
| **Certificaat** | Authenticiteit | bevestigt: deze sleutel hoort bij `www.biberbank.de` |

## Hetzelfde principe op veel plaatsen

Wat je bij HTTPS hebt geleerd, zit ook in veel andere technieken:

- **wifi (WPA2/WPA3):** In hoofdstuk 3.3.2 kon elk apparaat binnen bereik meelezen. Met WPA2 of WPA3 wordt elk radioframe met AES versleuteld; WPA3 onderhandelt de sleutel bovendien zo, dat een luistervink zelfs met het wifi-wachtwoord oude opnamen niet kan ontsleutelen.
- **SSH:** Het versleutelde beheer op afstand uit hoofdstuk 6.6. In plaats van certificaten onthoudt de client bij de eerste verbinding de **vingerafdruk** van de serversleutel en waarschuwt hij als die later verandert.
- **VPN:** Een versleutelde tunnel door het internet, bijvoorbeeld naar het netwerk van school of van een bedrijf. Daar gaat hoofdstuk 10 over.
- **Messengers:** Signal, WhatsApp en andere diensten versleutelen **end-to-end**: zelfs de beheerder van de dienst kan de berichten niet lezen.

:::note
Grote **kwantumcomputers** zouden op een dag het ontbinden van grote getallen in priemfactoren — en daarmee RSA en Diffie-Hellman — kunnen kraken. Daarom worden nu al nieuwe, **kwantumveilige** methoden ingevoerd. Symmetrische methoden zoals AES met lange sleutels gelden nog steeds als veilig.
:::

## Test jezelf

:::quiz mc
Bij HTTPS worden de eigenlijke gegevens versleuteld met …
- [ ] RSA, omdat dat het veiligst is
- [x] een symmetrische methode zoals AES en een onderhandelde sessiesleutel
- [ ] de privésleutel van de server
:::

:::quiz mc
Je opent `https://www.biberbank.de/` en de browser meldt: "Het certificaat is uitgegeven voor `www.gewinn-biber.de`". Wat doe je?
- [ ] Op "Toch doorgaan" klikken — de verbinding is toch versleuteld
- [x] Afbreken — mogelijk praat de browser helemaal niet met de bank
- [ ] De pagina via `http://` openen, dan komt er geen waarschuwing
:::

:::quiz multi
Welke uitspraken kloppen?
- [x] Een hashwaarde verandert volledig als de gegevens ook maar minimaal veranderen
- [x] Een handtekening wordt met de privésleutel gemaakt en met de openbare sleutel gecontroleerd
- [x] Root-CA's zijn vooraf geïnstalleerd in de browser of het besturingssysteem
- [ ] Bij HTTPS kan een luistervink niet eens het IP-adres van de server zien
- [ ] SMTPS versleutelt de mail ook op de mailserver
:::
