## Het experiment

1. Schakel over naar de :fa-play: **Uitvoeren**-modus, klik op de **Client-PC** en open de :fa-globe: **Browser**. Roep `http://192.168.0.20/` op.
2. Klik bovenin het venster op **Terug**, open de **Eenvoudige TCP-client** en verbind deze met `192.168.0.20`, poort `5000`. Laat de verbinding open.
3. Schakel over naar de :fa-magnifying-glass: **Tracering**-modus, open een trace voor de **Client-PC** en klik op een pakket met `[SYN]`. Klap **Transmission Control Protocol** open.

Helemaal bovenaan de TCP-header staan twee poorten: **Source Port** (bronpoort) en **Destination Port** (doelpoort).

:::quiz table
| Verbinding | Bronpoort | Doelpoort |
|---|---|---|
| Browser → webserver | {49152} | {80} |
| TCP-client → echo-dienst | {49153} | {5000} |
:::

## Twee soorten poorten

**Doelpoort — de dienst:** Een serverprogramma wacht op een vaste poort op verbindingen — men zegt dat het daar **luistert**. Voor bekende diensten liggen de nummers wereldwijd vast, de **well-known ports** (0 tot 1023). Een browser weet daarom zonder te vragen: webservers luisteren op poort 80.

**Bronpoort — de afzender:** De poort aan de clientzijde kiest het besturingssysteem voor elke nieuwe verbinding zelf uit een hoog bereik (in BeaverTracer vanaf 49152). Hieraan herkent de client bij welke van zijn verbindingen een antwoord hoort.

Een verbinding wordt dus eenduidig bepaald door vier gegevens: **IP-adres en poort aan beide zijden**. Het paar van IP-adres en poort heet een **socket**, bijv. `192.168.0.20:80`.

## Een blik op de server

Schakel terug naar de :fa-play: **Uitvoeren**-modus, open op de **Server** het :fa-terminal: **Terminal** en voer in:

```
$ ss
```

`ss` toont alle sockets van de computer. Regels met `LISTEN` zijn programma's die op een poort luisteren. Regels met `ESTABLISHED` zijn bestaande verbindingen — met de eigen socket (*Local Address:Port*) en de socket van de andere kant (*Peer Address:Port*).

:::quiz multi
Op welke poorten luistert de server?
- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc

- [ ] `192.168.0.20:80` met `192.168.0.10:49152` — de verbinding van de browser
- [ ] Beide
:::

:::note
De verbinding van de browser is alweer afgebroken — na het laden van de pagina is ze met `FIN` beëindigd. `ss` toont haar nog even als `TIME-WAIT`: de server wacht een tijdje of er nog vertraagde pakketten van deze verbinding aankomen. De verbinding van de TCP-client is daarentegen nog open, omdat je nog niet op **Verbreken** hebt geklikt.
:::

## De belangrijkste well-known ports

| Poort | Protocol | Dienst |
|---|---|---|
| 22 | SSH | veilig beheer op afstand (versleutelde opdrachtregel) |
| 25 | SMTP | e-mails verzenden |
| 53 | DNS | namen omzetten naar IP-adressen (meestal via UDP) |
| 80 | HTTP | webpagina's |
| 110 | POP3 | e-mails ophalen |
| 143 | IMAP | e-mails op de server beheren |
| 443 | HTTPS | versleutelde webpagina's |

:::tip Onthoud
**Poorten** (0 tot 65535) houden de verbindingen op een computer uit elkaar. Serverdiensten **luisteren** op vaste **well-known ports** (bijv. HTTP 80, HTTPS 443), clients krijgen voor elke verbinding een vrije hoge **bronpoort**. Een verbinding wordt eenduidig bepaald door **IP-adres en poort van beide zijden**.
:::

:::quiz match
22 -> SSH
25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
