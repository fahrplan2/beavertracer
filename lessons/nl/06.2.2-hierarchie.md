# Hoe DNS is georganiseerd

:::sim
url=/sims/lesson-6.2.btsim
:::

Geen enkele server kan alle namen ter wereld kennen. DNS is daarom **hiërarchisch** opgebouwd — net als de namen zelf. Je leest ze van rechts naar links:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

De server die verantwoordelijk is voor een domein en het antwoord echt kent, heet **autoritatief**. De weg ernaartoe wordt voor de pc afgelegd door een **resolver** — hier de computer **DNS-Resolver**.

## Het experiment

1. Schakel over naar de :fa-play: **Uitvoermodus** en voer op de **Client-PC** in het :fa-terminal: **Terminal** in:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Open in de :fa-magnifying-glass: **Tracering**-modus een trace voor de **DNS-Resolver**.

De resolver heeft voor jou een hele reeks aanvragen gedaan. Wijs toe wie welk antwoord heeft gegeven:

:::quiz match
Root-Server (192.168.0.101) -> Verwijzing: Voor .de is ns.nic.de verantwoordelijk
de-Server (192.168.0.102) -> Verwijzing: Voor beaver-schule.de is ns.beaver-schule.de verantwoordelijk
Schul-DNS (192.168.0.103) -> Antwoord: www.beaver-schule.de heeft het adres 192.168.0.20
:::

:::quiz mc
Wie vraagt de resolver als eerste?
- [x] De root-server
- [ ] De Schul-DNS
- [ ] De Client-PC
:::

:::evaluate
Antwoorden controleren
:::

:::note
Tussendoor vraagt de resolver ook naar de adressen van de servers waarnaar hij verwezen werd (`A ns.nic.de`). Echte DNS-servers sturen deze adressen meestal meteen mee. Bovendien onthouden resolvers elk antwoord een tijdje (**cache**) — de volgende aanvraag naar dezelfde naam beantwoorden ze direct zelf. Hoe lang dat is, staat in het record als **TTL** (*Time to Live*) in seconden.
:::

## De belangrijkste recordtypen

| Type | Betekenis | Voorbeeld |
|---|---|---|
| **A** | naam → IPv4-adres | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | naam → IPv6-adres | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | naam → andere naam (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | verantwoordelijke mailserver van een domein | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | verantwoordelijke DNS-server van een domein | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Onthoud
DNS is **hiërarchisch**: **root-servers** verwijzen naar de servers van de **top-level domains** (bijv. `.de`), en die weer naar de servers van de afzonderlijke **domeinen**. De verantwoordelijke **autoritatieve** server kent het antwoord. Een **resolver** legt deze weg voor de pc af en onthoudt de antwoorden (**cache**). Belangrijke recordtypen: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Een record aanmaken

De school wil dat haar website ook bereikbaar is via `intranet.beaver-schule.de`.

1. Klik in de :fa-play: **Uitvoermodus** op de **Schul-DNS** en open de app **DNS-Server**.
2. Open het tabblad **A**. Klik op **+** en vul in de nieuwe regel de naam `intranet.beaver-schule.de` en het adres `192.168.0.20` in.
3. Test op de Client-PC met `nslookup intranet.beaver-schule.de`.

:::task
title: Nieuwe naam ingevoerd?
Controleer of de Client-PC de naam intranet.beaver-schule.de omzet naar het adres van de webserver. De simulatie moet daarvoor in de Uitvoermodus draaien.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
