# Volgnummers en bevestigingsnummers

:::sim
url=/sims/lesson-5.1.btsim
:::

Hoe weet TCP of alles is aangekomen — en in welke volgorde? Elke kant **nummert de bytes** die hij verzendt:

- Het **volgnummer** (`SEQ`) is het nummer van de eerste byte die in dit pakket zit.
- Het **bevestigingsnummer** (`ACK`) zegt: „Tot hier heb ik alles ontvangen — als volgende verwacht ik byte nr. …"

Daarbij gelden twee regels: `SYN` en `FIN` tellen als één byte, hoewel ze geen gegevens bevatten. En elke kant telt voor zichzelf — daarom zijn er twee nummerreeksen, in het diagram rood (client) en blauw (server).

## Narekenen

Hier is je verbinding nog een keer. De getallen bij de lijnen geven telkens de teller van de computer op dat punt weer:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Loop de rode getallenreeks door:

1. De client begint bij `SEQ=0`. Zijn `SYN` verbruikt één nummer — de server bevestigt met `ACK=1`.
2. Het bericht begint bij `SEQ=1` en is 13 byte lang (bytes 1 tot en met 13). De server bevestigt met `ACK=14`: „Als volgende verwacht ik byte 14."
3. De `FIN` van de client heeft daarom `SEQ=14` en wordt bevestigd met `ACK=15`.

De blauwe reeks van de server werkt precies hetzelfde.

:::tip Onthoud
Het **volgnummer** (`SEQ`) is het nummer van de eerste byte in het pakket. Het **bevestigingsnummer** (`ACK`) is het nummer van de volgende byte die de ontvanger verwacht — alles daarvoor is aangekomen. Er geldt: **ACK = SEQ + lengte** van de ontvangen gegevens; `SYN` en `FIN` tellen als één byte. Elke kant telt zijn eigen bytes.
:::

:::tip Probeer het uit
Bouw de verbinding in de **Eenvoudige TCP-client** nog een keer op en stuur twee berichten achter elkaar. Zeg vooraf welke `Seq` en `Ack` in de kolom **Info** zullen staan — en controleer het in de tracering.
:::

:::note
In echte netwerken begint het tellen niet bij 0: elke kant kiest een **willekeurig beginnummer** (*Initial Sequence Number*, ISN) tussen 0 en ongeveer 4,3 miljard. Is het hoogste nummer bereikt, dan gaat het weer verder bij 0. De tracer trekt het beginnummer af en toont **relatieve** nummers — net als Wireshark. Daarom zie je `Seq=0` en `Seq=1`.

Bovendien staat in elk pakket `Win=` — de **venstergrootte**: zoveel bytes kan de ontvanger op dit moment aannemen. Daarmee remt hij een te snelle zender af (*flowcontrol*). In BeaverTracer is het venster altijd even groot.
:::
