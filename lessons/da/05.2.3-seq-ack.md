# Sekvens- og kvitteringsnumre

:::sim
url=/sims/lesson-5.1.btsim
:::

Hvordan ved TCP, om alt er nået frem — og i hvilken rækkefølge? Hver side **nummererer de bytes**, den sender:

- **Sekvensnummeret** (`SEQ`) er nummeret på den første byte i denne pakke.
- **Kvitteringsnummeret** (`ACK`) siger: "Indtil hertil har jeg modtaget alt — som det næste forventer jeg byte nr. …"

Dertil to regler: `SYN` og `FIN` tæller som én byte, selvom de ikke indeholder data. Og hver side tæller for sig — derfor er der to nummerrækker, i diagrammet rød (klient) og blå (server).

## Regn efter

Her er din forbindelse igen. Tallene ved linjerne viser computerens tæller på det pågældende tidspunkt:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Gå den røde talrække igennem:

1. Klienten begynder ved `SEQ=0`. Dens `SYN` bruger ét nummer — serveren kvitterer med `ACK=1`.
2. Beskeden begynder ved `SEQ=1` og er 13 byte lang (byte 1 til 13). Serveren kvitterer med `ACK=14`: "Som det næste forventer jeg byte 14."
3. Klientens `FIN` har derfor `SEQ=14` og kvitteres med `ACK=15`.

Serverens blå række fungerer på præcis samme måde.

:::tip Husk
**Sekvensnummeret** (`SEQ`) er nummeret på den første byte i pakken. **Kvitteringsnummeret** (`ACK`) er nummeret på den næste byte, som modtageren forventer — alt før den er nået frem. Det gælder: **ACK = SEQ + længde** af de modtagne data; `SYN` og `FIN` tæller som én byte. Hver side tæller sine egne bytes.
:::

:::tip Prøv det selv
Opbyg forbindelsen i **Simpel TCP-klient** igen, og send to beskeder efter hinanden. Sig på forhånd, hvilke `Seq` og `Ack` der vil stå i kolonnen **Info** — og tjek det i sporingen.
:::

:::note
I rigtige netværk begynder tællingen ikke ved 0: Hver side vælger et **tilfældigt startnummer** (*Initial Sequence Number*, ISN) mellem 0 og omkring 4,3 milliarder. Når det højeste nummer er nået, fortsætter det igen ved 0. Traceren trækker startnummeret fra og viser **relative** numre — præcis som Wireshark. Derfor ser du `Seq=0` og `Seq=1`.

Desuden står der i hver pakke `Win=` — **vinduesstørrelsen**: Så mange bytes kan modtageren lige nu tage imod. Dermed bremser den en afsender, der sender for hurtigt (*flowkontrol*). I BeaverTracer er vinduet altid lige stort.
:::
