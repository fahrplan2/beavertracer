# Observer UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

På **Server** kører der denne gang en **UDP Echo-Server** på port `5000`. Også her er kablet manipuleret: Det **andet datagram** fra klient-pc'en til serveren går tabt.

## Eksperimentet

1. Skift til :fa-play: **Kør**-tilstand, og åbn :fa-terminal: **Terminal** på **Client-PC**.
2. Start en UDP-"forbindelse" til serveren med `nc` (`-u` står for UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Skriv efter hinanden `eins`, `zwei` og `drei`, og tryk på **Enter** hver gang. Hver linje, der kommer tilbage, er et ekko fra serveren.
4. Vent nogle sekunder, og åbn derefter et trace for **Client-PC** i :fa-magnifying-glass: **Spor**-tilstand.

:::quiz mc
Hvilke ekkoer kommer tilbage?
- [ ] Alle tre, `zwei` lidt senere
- [x] Kun `eins` og `drei` — `zwei` mangler og bliver heller ikke sendt igen
- [ ] Slet ingen
:::

:::quiz multi
Hvilke pakker, som du kender fra TCP, mangler helt ved UDP?
- [x] Opbygning af forbindelse (`SYN`)
- [x] Kvitteringer (`ACK`)
- [x] Nedlæggelse af forbindelse (`FIN`)
- [ ] Pakker med portnumre
:::

:::evaluate
Tjek svar
:::

Klik på en af UDP-pakkerne, og fold **User Datagram Protocol** ud. Sammenlignet med TCP-headeren er UDP-headeren lillebitte: **Source Port**, **Destination Port**, **Length** (længde) og **Checksum** (kontrolsum) — tilsammen kun 8 byte. En TCP-header er mindst 20 byte og indeholder sekvensnummer og kvitteringsnummer, flag og vinduesstørrelse.

:::quiz mc
Hvilken opgave fra afsnit 5.1 løser UDP alligevel?
- [x] Multipleksing — via portene
- [ ] Opbygning af forbindelse
- [ ] Pålidelig overførsel
:::

:::tip Husk
**UDP** er **forbindelsesløst**: ingen opbygning, ingen kvittering, ingen gensendelse, ingen rækkefølge. Det tilbyder kun **porte** (multipleksing) og en **kontrolsum**. Til gengæld er det hurtigt og slankt — UDP-headeren er kun 8 byte. Hvis et datagram går tabt, må programmet selv tage sig af det — eller også er det ligegyldigt.
:::
