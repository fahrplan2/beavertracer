# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) er helt almindelig HTTP — bortset fra at det ikke kører direkte over TCP, men gennem et krypteret lag imellem: **TLS** (*Transport Layer Security*). Forgængeren til TLS hed **SSL**; derfor taler man stadig ofte om "SSL-certifikater".

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP mærker intet til det: Det sender sine forespørgsler som sædvanligt, TLS krypterer dem, og TCP transporterer dem. I OSI-modellen sidder TLS mellem transportlaget og applikationslaget, altså i lag 4/5 — det bygger på TCP og administrerer en sikret session.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresse | `http://…` | `https://…` |
| Indhold læsbart i Tracer? | ja | nej |
| Browseren viser | "ikke sikker" | hængelås |

TLS klarer under opbygningen af forbindelsen alt det, du har lært i dette kapitel:

- Serveren legitimerer sig med sit **certifikat** (**autenticitet**).
- Begge sider forhandler en **sessionsnøgle** på plads med **Diffie-Hellman** — serveren **signerer** sin andel.
- Derefter bliver alle data krypteret med **AES** (**fortrolighed**) og sikret mod ændring (**integritet**).

Princippet er ikke begrænset til nettet: Også e-mail (afsnit 8.4) og mange andre protokoller kører på samme måde gennem TLS.

I de følgende afsnit observerer du HTTPS i Tracer, opsætter det selv og undersøger, hvornår browseren advarer — og hvorfor.
