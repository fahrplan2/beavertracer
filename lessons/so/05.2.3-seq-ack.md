# Sequence iyo Acknowledgement numbers

:::sim
url=/sims/lesson-5.1.btsim
:::

Sidee TCP u ogaadaa in wax walba yimaadeen — iyo in ay u kala horreeyaan sidee? Dhinac kasta wuxuu **tirinayaa bytes-ka** uu dirayo:

- **Sequence number** (`SEQ`) waa lambarka byte-ka ugu horreeya ee ku jira packet-kan.
- **Acknowledgement number** (`ACK`) wuxuu leeyahay: „Ilaa halkan wax walba waan helay — marka xigta waxaan filayaa byte lambarkiisu yahay …“

Intaas waxaa dheer laba xeerood: `SYN` iyo `FIN` waxay u tirsamaan sida hal byte, inkastoo aysan xog sidan. Dhinac kastana wuxuu tiriyaa naftiisa — sidaas darteed waxaa jira laba silsilad oo lambaro ah, jaaniska sawirka ku jira (casaan = client, buluug = server).

## Dib u xisaabi

Halkan waa mar kale xiriirkaagii. Lambarada khadadka kuyaalla waxay muujinayaan tirinta kombiyuutarka goobtaas:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Raac silsiladda lambarrada casaanka ah:

1. Client-ku wuxuu ka bilaabmaa `SEQ=0`. `SYN`-kiisu wuxuu isticmaalaa hal lambar — server-ku wuxuu ku xaqiijiyaa `ACK=1`.
2. Fariintu waxay ka bilaabmaysaa `SEQ=1` waxayna dhererkeedu yahay 13 byte (bytes 1 ilaa 13). Server-ku wuxuu ku xaqiijiyaa `ACK=14`: „Marka xigta waxaan filayaa byte 14.“
3. Sidaas darteed `FIN`-ka client-ku wuxuu leeyahay `SEQ=14` waxaana lagu xaqiijiyaa `ACK=15`.

Silsiladda buluuga ah ee server-ku sidaas oo kale ayay u shaqeysaa.

:::tip Qodob muhiim ah
**Sequence number** (`SEQ`) waa lambarka byte-ka ugu horreeya ee ku jira packet-ka. **Acknowledgement number** (`ACK`) waa lambarka byte-ka xiga ee receiver-ku filayo — wax kasta oo ka horreeya waa yimaadeen. Xeerku waa: **ACK = SEQ + dhererka** xogta la helay; `SYN` iyo `FIN` waxay u tirsamaan sida hal byte. Dhinac kastaa wuxuu tiriyaa bytes-kiisa.
:::

:::tip Tijaabi
Mar kale ku dhis xiriirka **Simple TCP Client** oo dir laba fariin oo isku xigta. Hore u sheeg `Seq` iyo `Ack` noocee ah ayaa ka muuqan doona tiirka **Info** — kadibna ku hubi Trace-ka.
:::

## Layli

:::quiz short
Client-ku wuxuu diraa packet leh `Seq=1` iyo `Len=13`. Acknowledgement number noocee ah ayuu server-ku soo celiyaa?
= 14
:::

:::quiz short
Kadib client-ku wuxuu diraa fariintiisa xigta. Sequence number noocee ah ayay ka bilaabmaysaa?
= 14
:::

:::quiz short
Packet leh `Seq=40` iyo `Len=25` ayaa yimaada. Acknowledgement number noocee ah ayuu receiver-ku dirayaa?
= 65
:::

:::evaluate
Hubi jawaabaha
:::

Geli lambarrada maqan. Client-ku wuxuu diraa `Hallo` kadibna `Tschau` (mid kasta wuxuu leeyahay dhamaadka safka):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
Hubi sawirka
:::

:::note
Shabakadaha dhabta ah, tirintu uma bilaabmo 0: dhinac kastaa wuxuu doortaa **lambar bilow ah oo random ah** (*Initial Sequence Number*, ISN) oo u dhexeeya 0 iyo ilaa 4,3 bilyan. Marka lambarka ugu sarreeya la gaaro, waxay mar kale ka sii wadataa 0. Tracer-ku wuxuu ka dhimaa lambarka bilowga wuxuuna muujiyaa lambaro **relative** ah — sida Wireshark oo kale. Sidaas darteed ayaad u aragtaa `Seq=0` iyo `Seq=1`.

Intaas waxaa dheer, packet kasta wuxuu ka kooban yahay `Win=` — **window size**: tani waa bytes-ka receiver-ku hadda qaadan karo. Taas wuxuu ku hoos dhigaa sender aad u dheereeya (*flow control*). Gudaha BeaverTracer, window-gu mar walba waa isku cabbir.
:::
