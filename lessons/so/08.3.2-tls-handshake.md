# TLS-Handshake

:::sim

Intaan codsigii ugu horreeyay ee encrypted ah la dirin, Client iyo Server waa inay isku raacaan: habka la isticmaalayo iyo session key. Sidoo kale, Client-ku waa inuu hubiyaa cidda uu la hadlayo. Xidhiidhkan dhisidiisa waxaa la yiraahdaa **TLS-Handshake**.

## Socodka ee jaantuska

Iyadoo aan la tusin TCP acknowledgements-ka (`ACK`), handshake-ku waa sidan:

:::seq
mode: text
Client -> Server: Client Hello | lambar random ah, habab suurtagal ah
Server -> Client: Server Hello | habka la doortay, lambar random ah
Server -> Client: Certificate | certificate-ka Server-ka
Server -> Client: Server Key Exchange | qaybta DH, signed
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | qaybta DH ee Client-ka
Client -> Server: Change Cipher Spec | hadda ka dib waa encrypted
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | hadda ka dib waa encrypted
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (encrypted)
Server -> Client: Application Data | bogga web-ka (encrypted)
:::

Waxa halkan ka dhacaya, iyo qaybta ka timid qaybta 8.1 ee ka dambeysa:

1. **Client Hello / Server Hello:** Client iyo Server way isu salaamaan, way kala beddelan lambarro random ah, waxayna isku raacaan hababka (gudaha BeaverTracer: key exchange oo la sameeyo **ECDHE**, signature **ECDSA**, encryption **AES**).
2. **Certificate:** Server-ku wuxuu soo diraa **certificate**-kiisa. Client-ku wuxuu hubiyaa signature-ka CA, taariikhda ansaxnimada iyo magaca. Haddii ay tani fashilanto, halkaas ayuu joojiyaa — Browser-kuna wuxuu muujiyaa digniin.
3. **Server Key Exchange:** Server-ku wuxuu soo diraa **qaybtiisa Diffie-Hellman** — wuxuuna **sign** ku sameeyaa private key-giisa. Client-ku wuxuu signature-ka ku hubiyaa public key-ga ku jira certificate-ka. Sidaas ayuu u ogaadaa: qaybtan runtii waxay ka timid milkiilaha certificate-ka, ma aha Man-in-the-Middle.
4. **Client Key Exchange:** Client-ku wuxuu soo diraa qaybtiisa Diffie-Hellman. Hadda labadooduba waxay xisaabin karaan isla **session key** — iyadoo aan weligiis la gudbin.
5. **Change Cipher Spec:** „Hadda ka dib waan encrypt-gareynayaa.“
6. **Encrypted Handshake Message (Finished):** Labada dhinacba — hadda encrypted ah — waxay dirayaan checksum ku saabsan dhammaan fariimihii handshake-ka ee hore. Haddii weeraryahan wax ka beddelay jidka, checksum-yadu isma waafaqayaan, xidhiidhkana waa la jaraa.
7. **Application Data:** Halkan ka dib, xogta HTTP ayaa socota — oo symmetric ahaan lagu encrypt-gareeyay AES.

:::quiz match
Certificate -> Server-ku wuxuu isku aqoonsadaa certificate-kiisa
Server Key Exchange -> Qaybta Diffie-Hellman ee Server-ka oo signed ah
Client Key Exchange -> Qaybta Diffie-Hellman ee Client-ka
Change Cipher Spec -> Hadda ka dib waa la encrypt-gareynayaa
Application Data -> Xogta HTTP ee encrypted ah
:::

:::note
Trace-ka waxaad ku arkaysaa **laba** xidhiidh oo TLS ah oo isku xigta: Browser-ku marka hore wuxuu soo qaataa bogga, kadibna wuxuu dhisaa xidhiidh cusub stylesheet-ka `style.css`. Xidhiidh kasta wuxuu helaa handshake u gaar ah iyo session key u gaar ah. Browser-yada dhabta ahi xidhiidhada ayay furan hayaan, sidaasna waxay ka badbaadiyaan qayb ka mid ah dadaalkan. Nooca cusub ee **TLS 1.3** wuxuu sidoo kale u baahan yahay fariimo ka yar TLS 1.2 ee halkan lagu muujiyay.
:::

:::tip Qodob muhiim ah
Inta lagu jiro **TLS-Handshake**, Server-ku wuxuu isku aqoonsadaa **certificate**-kiisa, labada dhinacba waxay isku raacaan **session key** iyagoo isticmaalaya **Diffie-Hellman** (Server-ku wuxuu **sign** ku sameeyaa qaybtiisa), **Finished** ayaana labadooduba ku hubiyaan in cidina handshake-ka wax ka beddelin. Kadib xogta waxaa loo gudbiyaa sidii **Application Data** oo symmetric ahaan encrypted ah.
:::
