# Marka packets lumo

:::goal
**Hadafka waxbarashada:** Waxaad awooddaa inaad ka daawato tracer-ka oo aad sharaxdo sida TCP u dareemo xogta lumay, mar kale u dirto, una soo celiso kala horreynta.
:::

Simulation-kan xadhigga waa la diyaariyey: **packet-ka labaad ee xogta leh** ee ka socda Client-PC una socda Server wuu lumayaa. (Goobta aad ka heli lahayd waa marka aad Habka Socodsiinta ku riixdo xadhigga: **Targeted packet loss**.)

## Tijaabada

1. U gudub habka :fa-play: **Run**, ka fur **Client-PC** **Simple TCP Client**, kuna xidh `192.168.0.20`, port `5000`.
2. Isku xigsiin u dir saddex fariin: `Hallo`, kaddib `Welt`, kaddib `!`.
3. Eeg daaqadda chat-ka: Echo-ga `Hallo` isla markiiba wuu yimaadaa. Laba kalena?
4. Sug dhowr ilbiriqsi. Kaddib, habka :fa-magnifying-glass: **Raad** ka fur trace **Server**-ka (receiver-ka), anshaxa `eth0`.

:::quiz mc
Maxaa ku dhaca echo-yada `Welt` iyo `!`?
- [ ] Echo-ga `!` isla markiiba wuu yimaadaa, `Welt` weligiis wuu maqan yahay
- [x] Labadaba waxay yimaadaan dhowr ilbiriqsi kaddib — si wada jir ah oo kala horreyn sax ah
- [ ] Midkoodna weligii ma yimaado
:::

## Waxa tracer-ku muujiyo

Server-ka, packet-ka `Welt` wuu ka maqan yahay — waa lumay. Haddana **Info** column-ka waxaad ka heli doontaa saddex tilmaamood oo ku jira qaybo laba-xagal ah:

| Tilmaame | Waxa dhacay |
|---|---|
| `[TCP Previous segment not captured]` | Packet-ka `!` wuu yimaadaa, laakiin bytes ka horreeya way maqan yihiin — **farqi**. |
| `[TCP Dup ACK …]` | Server-ku mar kale wuu xaqiijiyaa lambarkii hore (*duplicate ACK*): „Wali waxaan sugayaa byte 8.“ |
| `[TCP Retransmission]` | Client-ku `Welt` **mar kale** ayuu dirayaa. |

:::quiz short
Waa maxay sequence number (`Seq`) ee packet-ka lagu calaamadeeyey `[TCP Retransmission]`?
= 8
:::

:::quiz short
Waa maxay acknowledgement number (`Ack`) ee server-ku soo diro isla markiiba retransmission-ka kaddib?
= 17
:::

:::quiz mc
Why ma u xaqiijiyaa server-ku retransmission-ka kaddib ilaa byte 17 — oo ma aha kaliya ilaa dhamaadka `Welt`?
- [x] Horeba wuu u helay `!` wuuna hayay — marka `Welt` yimaado farqigii waa xirmay, hadda wax kasta ilaa byte 16 waa jiraan
- [ ] Client-ku `Welt` iyo `!` mar kale ayuu si wada jir ah u diray
- [ ] Acknowledgement numbers had iyo jeer waa la dhawray
:::

:::evaluate
Hubi jawaabaha
:::

Sequence diagram-ka waxay u eegtaa sidan — fallaadha xariijimaha leh ee ✕ leh waa packet-ka lumay:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hallo" len=7
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=7
Client-PC -> Server: ACK
Client-PC -x Server: PSH, ACK "Welt" len=6
Client-PC -> Server: PSH, ACK "!" len=3
Server -> Client-PC: ACK
Client-PC -> Server: PSH, ACK "Welt" len=6 seq=8
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=9
Client-PC -> Server: ACK

## Waxa ka dambeeya

Client-ku packet kasta oo uu diray wuu keydiyaa ilaa la xaqiijiyo, wuxuuna u bilaabaa **timer**. Haddii acknowledgement-ku aad u daahdo, xogta mar kale ayuu dirayaa — **retransmission**.

Server-ku had iyo jeer wuxuu xaqiijiyaa kaliya ilaa **farqiga ugu horreeya**. Xogta ka timaadda kaddib (halkan `!`) wuu hayaa ilaa farqiga la buuxiyo. Kaddib bay wax kasta u gudbiyaa barnaamijka si kala horreyn sax ah — taasi waa sababta echo-yada `Welt` iyo `!` si wada jir ah u yimaadeen.

:::tip Qodob muhiim ah
TCP wuxuu lumitaanka ku garanayaa **acknowledgements maqan**: receiver-ku had iyo jeer wuxuu xaqiijiyaa kaliya ilaa farqiga ugu horreeya. Haddii acknowledgement-ku imaan waayo, sender-ku xogta wuu **mar kale** dirayaa marka timer dhammaado (*retransmission*). Waxa farqiga ka dambeeya ee yimaadda receiver-ku wuu hayaa — sidaas darteed xogtu waxay gaadhaa barnaamijka **si dhamaystiran oo kala horreyn sax ah**.
:::

:::tip Qoto dheer: Fast Retransmit
`Hallo` kaddib u dir afar fariin ama ka badan si degdeg ah isku xigsiin. Packet-ka lumay kaddib, client-ku wuxuu helayaa saddex *Dup ACKs* oo isku xigta — isla markiiba mar kale ayuu dirayaa isagoo aan sugin timer-kiisa. Habkan waxaa la yiraahdaa **Fast Retransmit**.
:::

:::note
Dhaqangelinta TCP ee dhabta ah waxay sidoo kale hagaajiyaan xawaaraha dirista: Haddii packets lumaan, network-ku waxa laga yaabaa inuu buux dhaafay, sender-kuna wuu gaabiyaa (*Staukontrolle*). Taasi way ka baxsan tahay koorsadan.
:::
