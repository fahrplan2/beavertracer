# Sekvens- och bekräftelsenummer

:::sim
url=/sims/lesson-5.1.btsim
:::

Hur vet TCP om allt har kommit fram — och i vilken ordning? Varje sida **numrerar de byte** den skickar:

- **Sekvensnumret** (`SEQ`) är numret på den första byten i det här paketet.
- **Bekräftelsenumret** (`ACK`) säger: "Jag har fått allt fram till hit — nästa byte jag förväntar mig är nr …"

Dessutom gäller två regler: `SYN` och `FIN` räknas som en byte, trots att de inte bär någon data. Och varje sida räknar för sig — därför finns det två nummerserier, röd (klient) och blå (server) i diagrammet.

## Räkna efter

Här är din uppkoppling en gång till. Siffrorna vid linjerna visar datorns räknare vid just den punkten:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Gå igenom den röda talserien:

1. Klienten börjar på `SEQ=0`. Dess `SYN` förbrukar ett nummer — servern bekräftar med `ACK=1`.
2. Meddelandet börjar på `SEQ=1` och är 13 byte långt (byte 1 till 13). Servern bekräftar med `ACK=14`: "Nästa byte jag förväntar mig är byte 14."
3. Klientens `FIN` har därför `SEQ=14` och bekräftas med `ACK=15`.

Serverns blå serie fungerar på exakt samma sätt.

:::tip Att komma ihåg
**Sekvensnumret** (`SEQ`) är numret på den första byten i paketet. **Bekräftelsenumret** (`ACK`) är numret på nästa byte som mottagaren förväntar sig — allt före det har kommit fram. Det gäller: **ACK = SEQ + längd** på den mottagna datan; `SYN` och `FIN` räknas som en byte. Varje sida räknar sina egna byte.
:::

:::tip Testa själv
Bygg upp uppkopplingen i **Enkel TCP-klient** en gång till och skicka två meddelanden efter varandra. Säg i förväg vilka `Seq` och `Ack` som kommer att stå i kolumnen **Info** — och kontrollera det i spårningen.
:::

:::note
I verkliga nätverk börjar räkningen inte på 0: varje sida väljer ett **slumpmässigt startnummer** (*Initial Sequence Number*, ISN) mellan 0 och ungefär 4,3 miljarder. När det högsta numret är nått fortsätter det från 0 igen. Tracern drar bort startnumret och visar **relativa** nummer — precis som Wireshark. Därför ser du `Seq=0` och `Seq=1`.

Dessutom finns `Win=` i varje paket — **fönsterstorleken**: så många byte kan mottagaren ta emot just nu. På så sätt bromsar mottagaren en avsändare som är för snabb (*flödeskontroll*). I BeaverTracer är fönstret alltid lika stort.
:::
