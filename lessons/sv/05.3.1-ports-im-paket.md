## Experimentet

1. Växla till :fa-play: **Kör**-läge, klicka på **Client-PC** och öppna :fa-globe: **Webbläsare**. Öppna `http://192.168.0.20/`.
2. Klicka på **Zurück** högst upp i fönstret, öppna **Enkel TCP-klient** och anslut den till `192.168.0.20`, port `5000`. Låt anslutningen vara öppen.
3. Växla till :fa-magnifying-glass: **Spårning**-läge, öppna en trace för **Client-PC** och klicka på ett paket med `[SYN]`. Fäll ut **Transmission Control Protocol**.

Högst upp i TCP-headern finns två portar: **Source Port** (källport) och **Destination Port** (målport).

:::quiz table
| Anslutning | Källport | Målport |
|---|---|---|
| Webbläsare → webbserver | {49152} | {80} |
| TCP-klient → echo-tjänst | {49153} | {5000} |
:::

## Två sorters portar

**Målport — tjänsten:** Ett serverprogram väntar på anslutningar vid en fast port — man säger att det **lyssnar** där. För välkända tjänster är numren fastställda globalt, de så kallade **Well-known Ports** (0 till 1023). En webbläsare vet därför utan att fråga: webbservrar lyssnar på port 80.

**Källport — avsändaren:** Porten på klientsidan väljer operativsystemet själv för varje ny anslutning ur ett högt intervall (i BeaverTracer från 49152). Med hjälp av den ser klienten vilken av sina anslutningar ett svar hör till.

En anslutning bestäms alltså entydigt av fyra uppgifter: **IP-adress och port på båda sidor**. Paret av IP-adress och port kallas **socket**, t.ex. `192.168.0.20:80`.

## En titt på servern

Växla tillbaka till :fa-play: **Kör**-läge, öppna :fa-terminal: **Terminal** på **Server** och skriv:

```
$ ss
```

`ss` visar alla sockets på datorn. Rader med `LISTEN` är program som lyssnar på en port. Rader med `ESTABLISHED` är befintliga anslutningar — med den egna socketen (*Local Address:Port*) och motpartens socket (*Peer Address:Port*).

:::quiz multi
På vilka portar lyssnar servern?

- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc

- [ ] `192.168.0.20:80` med `192.168.0.10:49152` — webbläsarens anslutning

:::note
Webbläsarens anslutning har redan avslutats — efter att sidan laddats stängdes den med `FIN`. `ss` visar den fortfarande en kort stund som `TIME-WAIT`: Servern väntar en stund för att se om det kommer fler försenade paket från den anslutningen. TCP-klientens anslutning är däremot fortfarande öppen, eftersom du ännu inte har klickat på **Koppla från**.
:::

## De viktigaste Well-known Ports

| Port | Protokoll | Tjänst |
|---|---|---|
| 22 | SSH | säker fjärradministration (krypterad kommandorad) |
| 25 | SMTP | skicka e-post |
| 53 | DNS | översätta namn till IP-adresser (oftast över UDP) |
| 80 | HTTP | webbsidor |
| 110 | POP3 | hämta e-post |
| 143 | IMAP | hantera e-post på servern |
| 443 | HTTPS | krypterade webbsidor |

:::tip Att komma ihåg
**Portar** (0 till 65535) håller isär anslutningarna på en dator. Servertjänster **lyssnar** på fasta **Well-known Ports** (t.ex. HTTP 80, HTTPS 443), klienter får för varje anslutning en ledig hög **källport**. En anslutning bestäms entydigt av **IP-adress och port på båda sidor**.
:::

:::
