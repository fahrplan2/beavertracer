# TCP eller UDP?

| | TCP | UDP |
|---|---|---|
| Förbindelse | uppkoppling med trevägshandskakning, ordnad nedkoppling | ingen — varje datagram står för sig själv |
| Bekräftelser | ja (`ACK`) | nej |
| Förlorad data | skickas på nytt | förblir förlorad |
| Ordningsföljd | återställs | garanteras inte |
| Header | minst 20 byte | 8 byte |
| Hastighet | något långsammare, fler paket | snabb, litet merarbete |

När är mindre mer?

- **Realtid:** Vid videosamtal, internettelefoni eller onlinespel räknas varje millisekund. Ett förlorat ljudstycke som levereras en sekund senare är till ingen nytta längre — hellre ett kort knaster än en fördröjning.
- **Korta förfrågningar:** En **DNS**-förfrågan (”Vilken IP-adress har `www.beispiel.de`?”) ryms i ett enda datagram, och svaret också. En uppkoppling skulle tredubbla arbetsinsatsen. Kommer inget svar frågar programmet helt enkelt igen.

Överallt där varje byte måste komma fram — webbsidor, e-post, nedladdningar — är TCP däremot det rätta valet.

:::tip Att komma ihåg
**TCP** är tillförlitligt men mer krävande — för allt som måste komma fram **fullständigt** (webb, e-post, filer). **UDP** är snabbt och slimmat men utan garantier — för **realtid** (telefoni, video, spel) och **korta förfrågningar** som DNS.
:::
