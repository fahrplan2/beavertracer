# Vad måste transportlagret klara av?

:::sim
url=/sims/lesson-5.1.btsim
:::

På **Server** körs två tjänster samtidigt: en **webbserver** och en liten **echo-tjänst** som omedelbart skickar tillbaka varje meddelande den får. Med två experiment tar du reda på vad IP ensamt inte kan klara av.

## Experiment 1: Två program samtidigt

1. Växla till :fa-play: **Kör**-läget (Körläge) och klicka på **Client-PC**.
2. Öppna :fa-globe: **Webbläsare** och gå till `http://192.168.0.20/`.
3. Klicka på **Zurück** högst upp i fönstret och öppna **Enkel TCP-klient**. Fyll i `192.168.0.20` vid **Host** och `5000` vid **Port** och klicka på **Anslut**.
4. Växla till :fa-magnifying-glass: **Spårning**-läget och öppna med **+** en trace för **Client-PC**, anslutning `eth0`.

Klicka på ett paket från webbläsaren (t.ex. `GET /`) och på ett från TCP-klienten och fäll ut **Internet Protocol Version 4** för vart och ett.

:::quiz mc
Vilka IP-adresser har paketen från webbläsaren och TCP-klienten?
- [x] Samma för båda: från `192.168.0.10` till `192.168.0.20`
- [ ] Webbläsaren använder en annan mål-IP-adress än TCP-klienten
- [ ] TCP-klientens paket har ingen IP-adress
:::

:::quiz mc
Räcker alltså mål-IP-adressen för att servern ska veta om ett paket hör till webbservern eller till echo-tjänsten?
- [ ] Ja
- [x] Nej — båda paketen har samma mål-IP-adress
:::

Något annat måste skilja de två förbindelserna åt. Titta i kolumnen **Info** för paketen med `[SYN]` — det är det första paketet i varje förbindelse:

:::quiz short
Vilket tal står efter pilen `→` för **webbläsaren**?
= 80
:::

:::quiz short
Och för **TCP-klienten**?
= 5000
:::

:::evaluate
Kontrollera svar
:::

Du får veta mer om dessa tal — **portarna** — i avsnitt 5.3. För tillfället räcker det att veta: Först transportlagret gör det möjligt för flera program att kommunicera samtidigt via *en* IP-adress och att varje paket hamnar hos rätt program. Det kallas **multiplexering**.

## Experiment 2: När ett paket går förlorat

1. Växla till :fa-play: **Kör**-läget (Körläge) och klicka på **kabeln** mellan Client-PC och Server.
2. Ställ i fönstret **Verbindung** in **Konfigurierter Paketverlust** på `25%`.
3. Öppna :fa-terminal: **Terminal** på **Client-PC** och skicka sex pingar:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Det tar ungefär en halv minut — vänta tills statistiken visas.

:::quiz mc
Vad händer?
- [ ] Alla sex pingar besvaras
- [x] Vissa pingar förblir obesvarade — och ingen skickar dem igen
- [ ] Förlorade pingar upprepas automatiskt tills de når fram
:::

:::evaluate
Kontrollera svar
:::

För en ping är det inget problem — den ska ju just visa om något går förlorat. För en webbsida, ett e-postmeddelande eller en nedladdning vore en saknad bit däremot förödande: filen skulle vara trasig.

## Transportlagrets fyra uppgifter

| Uppgift | Vad det innebär |
|---|---|
| **Multiplexering** | Flera program och förbindelser delar på en IP-adress; varje paket hamnar hos rätt program. |
| **Uppkoppling** | Innan data flödar kommer båda sidor överens om att de ska kommunicera med varandra. |
| **Tillförlitlig överföring** | Mottagaren bekräftar vad som har kommit fram. Det som saknas skickas om och ordningsföljden återställs. |
| **Nedkoppling** | Till sist avslutar båda sidor förbindelsen på ett ordnat sätt. |

:::tip Att komma ihåg
**Transportlagret** (lager 4) ser till att data kommer fram till rätt **program** (**multiplexering**). Protokollet **TCP** ser dessutom till att de kommer fram **fullständigt** och i **rätt ordning** — med uppkoppling, bekräftelser, omsändning och nedkoppling.
:::

:::quiz match
På en PC körs webbläsare, e-postprogram och chattprogram samtidigt. -> Multiplexering
Innan data flödar kontrollerar båda sidor att den andra är redo. -> Uppkoppling
En del av en fil kommer inte fram och skickas en gång till. -> Tillförlitlig överföring
Efter nedladdningen frigör båda sidor förbindelsen igen. -> Nedkoppling
:::
