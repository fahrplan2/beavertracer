# Direkt eller via gatewayen?

:::sim
url=/sims/lesson-4.3.2.btsim
:::

Innan en dator skickar ett paket avgör den: Finns målet i det **egna nätverket**? För att ta reda på det jämför den nätverksdelen i sin egen adress med nätverksdelen i måladressen — med hjälp av sin nätmask.

## Förloppet

1. **Finns mål-IP-adressen i det egna nätverket?**
   - **Ja:** Datorn skickar paketet **direkt** till målet. Den behöver målets MAC-adress.
   - **Nej:** Datorn skickar paketet till **gatewayen**. Den behöver routerns MAC-adress. Om ingen gateway är angiven kan den inte skicka paketet alls.
2. **Känner den redan till den MAC-adress som behövs** (finns den i dess ARP-cache)? Om inte frågar den efter den via **ARP**.
3. Den skickar ramen till den här MAC-adressen. **Mål-IP-adressen** i paketet är i båda fallen det egentliga målet.

| | direkt (eget nätverk) | via gatewayen (annat nätverk) |
|---|---|---|
| ARP frågar efter … | målets MAC | routerns MAC |
| Mål-MAC i ramen | mål | router |
| Mål-IP i paketet | mål | mål |

## Felsökning: Företag B går inte att nå

Sedan i går når Anna inte längre datorerna i företag B. Så *ska* nätverket vara konfigurerat:

| Enhet | IP-adress | Gateway |
|---|---|---|
| Anna | `192.168.0.10/24` | `192.168.0.1` |
| Ben | `192.168.0.11/24` | `192.168.0.1` |
| Clara | `172.16.0.10/24` | `172.16.0.1` |
| David | `172.16.0.11/24` | `172.16.0.1` |

Hitta felen och åtgärda dem.

</details>

:::tip Att komma ihåg
En dator behöver rätt gateway inte bara för att skicka, utan också för att **svara**: Utan gateway kommer pingen visserligen fram, men svaret hittar ingen väg tillbaka. Om en **felaktig gateway-adress** är angiven frågar datorn förgäves via ARP efter en router som inte finns.
:::
