# Felsökning: Namnet fungerar inte

:::sim
url=/sims/lesson-6.2.3.btsim
:::

En lärare rapporterar: ”`www.beaver-schule.de` laddas inte hos mig. Med `http://192.168.0.20` fungerar det däremot!” Så *ska* det vara konfigurerat:

| Vad | Ska vara |
|---|---|
| DNS-server på klient-PC:n | `192.168.0.53` (DNS-Resolver) |
| Post i Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Hitta felen och åtgärda dem.

<details>
<summary>Tips 1: Vad säger nslookup?</summary>

Skriv `nslookup www.beaver-schule.de` på klient-PC:n. Vilken server frågade `nslookup` – och vad kom tillbaka? (Svaret tar några sekunder.)
</details>

<details>
<summary>Tips 2: Och nu då?</summary>

Om du får ett svar, jämför adressen med planen. Var är det här namnet registrerat?
</details>

:::task
title: Är namnuppslagningen reparerad?
Kontrollerar om klient-PC:n löser upp www.beaver-schule.de till rätt adress. Simuleringen måste köra i Körläge för detta.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Vad var det som hände?

:::quiz multi
Vilka påståenden stämmer?
- [x] På klient-PC:n var `192.168.0.35` angiven som DNS-server – där svarar ingen
- [x] I Schul-DNS pekade `www.beaver-schule.de` på `192.168.0.21` i stället för på `192.168.0.20`
- [ ] Webbservern var avstängd
- [ ] Root-servern kände inte till domänen `.de`
:::

:::evaluate
Kontrollera svar
:::

:::tip Att komma ihåg
Fungerar en anslutning med **IP-adressen** men inte med **namnet**, ligger problemet hos **DNS**. Kontrollera först den **angivna DNS-servern** (svarar den överhuvudtaget?) och därefter själva **posten** (stämmer adressen?). `nslookup` visar båda: vilken server som tillfrågades och vad den svarade.
:::
