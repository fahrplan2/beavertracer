# Attack: DNS-förfalskning

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna vill öppna sin internetbank hos **Biberbank** på **Client-PC**. Vad hon inte vet: Någon har tagit sig in på **DNS-servern** och ändrat en post.

På arbetsytan ser du den riktiga webbservern **www.biberbank.de** och en **angripares** dator. På den körs en kopia av bankens webbplats.

## Del 1: Utan kryptering

Byt till :fa-play: **Kör**-läge och öppna `http://www.biberbank.de/` i :fa-globe: **Webbläsare** på **Client-PC**.

:::quiz mc
Vad ser du?
- [x] Biberbankens inloggningssida, utan någon varning
- [ ] En varning om att sidan är förfalskad
- [ ] Ett felmeddelande
:::

:::evaluate
Kontrollera svar
:::

Allt ser normalt ut. Men vilken server pratar webbläsaren egentligen med? Öppna :fa-terminal: **Terminal** på Client-PC:

```
$ nslookup www.biberbank.de
```

:::quiz short
Vilken IP-adress returnerar DNS-servern för `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Vem tillhör den här adressen? (Klicka på enheterna i redigeringsläge eller titta på deras :fa-gear: **IP-inställningar**.)
- [ ] Biberbankens riktiga webbserver
- [x] Angriparen
- [ ] DNS-servern
:::

:::evaluate
Kontrollera svar
:::

Om Anna nu hade skrivit in kontonummer och PIN-kod hade de hamnat direkt hos angriparen. Med **HTTP** har hon **ingen chans** att upptäcka bedrägeriet: Adressfältet visar rätt namn och sidan ser äkta ut.

## Del 2: Med HTTPS

Öppna nu `https://www.biberbank.de/`.

:::quiz mc
Vad händer?
- [ ] Den förfalskade sidan visas med ett hänglås
- [x] Webbläsaren varnar: Certifikatet har utfärdats för ett annat namn
- [ ] Biberbankens riktiga sida visas
:::

:::quiz short
För vilket namn har angriparens certifikat utfärdats (utan `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Kontrollera svar
:::

Angriparen har till och med ett **äkta** certifikat från en betrodd CA — men för sin egen domän `www.biber-gewinnspiel.de`. Ett certifikat för `www.biberbank.de` får han inte av någon CA, eftersom den domänen inte tillhör honom. Och utan Biberbankens **privata nyckel** kan han inte heller använda bankens riktiga certifikat: I handshaken skulle han behöva signera Server Key Exchange med den.

:::quiz multi
Vad skyddar HTTPS mot här — och vad skyddar det inte mot?
- [x] HTTPS avslöjar att servern inte är den riktiga
- [ ] HTTPS förhindrar att DNS-servern förfalskas
- [x] HTTPS hjälper bara om användaren tar varningen på allvar
- [ ] Med HTTPS går det inte alls att nå den förfalskade sidan
:::

:::evaluate
Kontrollera svar
:::

## Del 3: Reparera DNS-servern

Öppna **DNS-servern** och rätta posten för `www.biberbank.de`. Den rätta adressen hittar du i **IP-inställningar** för webbservern **www.biberbank.de**. Glöm inte att klicka på **Spara**.

:::note
Client-PC kommer ihåg DNS-svar en stund, så att den inte behöver fråga på nytt vid varje anrop (**DNS-cache**). Hur länge anges i kolumnen **TTL** (*Time to Live*) i sekunder. Om `nslookup` direkt efter din rättning fortfarande ger den gamla adressen, vänta tills TTL har gått ut och försök igen.
:::

:::task
title: Är Biberbank äkta igen?
Prüft, ob der Client-PC www.biberbank.de zur richtigen Adresse auflöst und die Seite über HTTPS ohne Warnung abrufen kann.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
I verkligheten förfalskar en angripare sällan själva DNS-servern. Oftare smugglar han in sina svar i ett öppet WLAN, ändrar inställningarna i en hemmarouter eller lockar med en adress som ser lik ut, till exempel `www.biberbank-login.de` (**nätfiske**). Mot ett liknande namn hjälper inte heller HTTPS — angriparen får ett giltigt certifikat för det. Därför: Läs adressen noga!
:::

:::tip Att komma ihåg
Vid en **DNS-förfalskning** returnerar DNS-servern angriparens adress för ett namn. Med **HTTP** märker man ingenting av det. Med **HTTPS** stämmer angriparens certifikat inte överens med det namn som anropades, och webbläsaren **varnar** — för ingen CA utfärdar certifikat för andras domäner, och den riktiga serverns privata nyckel har angriparen inte.
:::
