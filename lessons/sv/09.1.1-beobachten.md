## Ping utifrån

Växla till :fa-play: **Kör**-läget och pinga skolservern från **Internet-PC**:

```
$ ping -c 2 198.51.100.10
```

Öppna sedan fliken **Logg** i brandväggen.

:::quiz mc
Vad rapporterar `ping`?
- [x] `Anfrage abgelaufen` — ingenting kommer tillbaka
- [ ] `Paket gefiltert`
- [ ] Två svar från skolservern
:::

## Portscan: förkastad eller avvisad?

Skanna nu fem portar på ett riktat sätt. Port 3306 (en databas) används inte alls på skolservern.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (förkastad) -> filtered
25 (tillåten, tjänsten körs) -> open
110 (avvisad) -> closed
3306 (tillåten, ingen tjänst) -> closed
:::

:::evaluate
Kontrollera sammankopplingen
:::

:::quiz multi
Vad kan en angripare dra för slutsatser av resultatet?
- [x] Vid `filtered` vet angriparen: Där finns en brandvägg som sväljer paket
- [x] Vid `closed` kan angriparen inte avgöra om en brandvägg avvisar paketen eller om det helt enkelt inte körs någon tjänst
- [ ] Vid `filtered` vet angriparen vilken tjänst som finns bakom porten
- [ ] Vid `closed` går tjänsten ändå att nå
:::

:::evaluate
Kontrollera svaren
:::

Titta till sist på kolumnen **Träffar** i regellistan: Där räknar brandväggen hur många paket varje regel redan har avgjort. Värdet bredvid **Standardpolicy** räknar alla paket som ingen regel passade in på.

:::tip Att komma ihåg
**Förkastade** paket försvinner spårlöst: `ping` rapporterar en timeout och `nmap` rapporterar `filtered`. **Avvisade** paket besvarar brandväggen med ett avslag (vid TCP en RST). Utifrån ser det ut som en stängd port. Brandväggens **logg** visar vilka paket den har stoppat, och kolumnen **Träffar** visar vilken regel som har slagit till.
:::
