# När paket går förlorade

:::goal
**Lärandemål:** Du kan i tracern observera och förklara hur TCP upptäcker förlorad data, skickar den igen och återställer ordningen.
:::

:::sim
url=/sims/lesson-5.4.btsim
:::

I den här simulationen är kabeln preparerad: Det **andra paketet med data** från Client-PC till Server går förlorat. (Du hittar inställningen när du klickar på kabeln i Körläge: **Målinriktad paketförlust**.)

## Experimentet

1. Byt till :fa-play: **Kör**-läge, öppna **Enkel TCP-klient** på **Client-PC** och anslut den till `192.168.0.20`, port `5000`.
2. Skicka tre meddelanden efter varandra: `Hallo`, sedan `Welt`, sedan `!`.
3. Titta på chattfönstret: Ekot av `Hallo` kommer direkt. Och de andra två?
4. Vänta några sekunder. Öppna sedan i :fa-magnifying-glass: **Spårning**-läge en trace för **Server** (mottagaren), port `eth0`.

:::quiz mc
Vad händer med ekona av `Welt` och `!`?
- [ ] Ekot av `!` kommer direkt, `Welt` saknas för alltid
- [x] Båda kommer först efter några sekunder — tillsammans och i rätt ordning
- [ ] Ingen av dem kommer någonsin fram
:::

## Vad tracern visar

Hos servern saknas paketet med `Welt` — det har ju gått förlorat. I stället hittar du i **Info**-kolumnen tre noteringar inom hakparenteser:

| Notering | Vad som har hänt |
|---|---|
| `[TCP Previous segment not captured]` | Paketet med `!` kommer fram, men innan det saknas byte — ett **glapp**. |
| `[TCP Dup ACK …]` | Servern bekräftar samma nummer som tidigare en gång till (*duplicate ACK*): "Jag väntar fortfarande på byte 8." |
| `[TCP Retransmission]` | Klienten skickar `Welt` **en gång till**. |

:::quiz short
Vilket sekvensnummer (`Seq`) har paketet som är markerat med `[TCP Retransmission]`?
= 8
:::

:::quiz short
Vilket bekräftelsenummer (`Ack`) skickar servern direkt efter omsändningen?
= 17
:::

:::quiz mc
Varför bekräftar servern efter omsändningen direkt till och med byte 17 — och inte bara till slutet av `Welt`?
- [x] Den hade redan tagit emot `!` och hållit kvar det — med `Welt` är glappet stängt, nu finns allt till och med byte 16
- [ ] Klienten skickade `Welt` och `!` tillsammans en gång till
- [ ] Bekräftelsenummer avrundas alltid
:::

:::evaluate
Kontrollera svaren
:::

I sekvensdiagrammet ser det ut så här — den streckade pilen med ✕ är det förlorade paketet:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hallo" len=7
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=7
Client-PC -> Server: ACK
Client-PC -x Server: PSH, ACK "Welt" len=6
Client-PC -> Server: PSH, ACK "!" len=3
Server -> Client-PC: ACK
Client-PC -> Server: PSH, ACK "Welt" len=6 seq=8
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=9
Client-PC -> Server: ACK
:::

## Vad som ligger bakom

Klienten sparar varje skickat paket tills det är bekräftat och startar en **timer** för det. Om bekräftelsen dröjer för länge skickar klienten datan igen — en **omsändning** (*retransmission*).

Servern bekräftar alltid bara till och med det **första glappet**. Data som kommer fram efter det (här `!`) håller servern kvar tills glappet är fyllt. Först då lämnar den över allt till programmet i rätt ordning — därför kom ekona av `Welt` och `!` tillsammans.

:::tip Att komma ihåg
TCP upptäcker förluster genom **uteblivna bekräftelser**: Mottagaren bekräftar alltid bara till det första glappet. Uteblir bekräftelsen skickar avsändaren datan **igen** när en timer löpt ut (*retransmission*). Det som kommer fram efter ett glapp håller mottagaren kvar — så når datan programmet **fullständigt och i rätt ordning**.
:::

:::tip Fördjupning: Fast Retransmit
Skicka fyra eller fler meddelanden snabbt efter varandra efter `Hallo`. Efter det förlorade paketet får klienten då tre *Dup ACK* i rad — och skickar direkt om, utan att vänta på sin timer. Det här förfarandet kallas **Fast Retransmit**.
:::

:::note
Verkliga TCP-implementeringar anpassar dessutom sin sändningstakt: Går paket förlorade är nätverket sannolikt överbelastat, och avsändaren blir långsammare (*överbelastningskontroll*). Det går utanför den här kursen.
:::
