# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) är alldeles vanligt HTTP – men det körs inte direkt över TCP, utan genom ett krypterat lager emellan: **TLS** (*Transport Layer Security*). Föregångaren till TLS hette **SSL**, och därför pratar man ofta fortfarande om ”SSL-certifikat”.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP märker ingenting av detta: Det skickar sina förfrågningar som vanligt, TLS krypterar dem och TCP transporterar dem. I OSI-modellen sitter TLS mellan transportlagret och applikationslagret, alltså i lager 4/5 – det bygger på TCP och hanterar en säkrad session.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adress | `http://…` | `https://…` |
| Innehållet läsbart i Tracer? | ja | nej |
| Webbläsaren visar | ”inte säker” | hänglås |

Vid uppkopplingen sköter TLS allt det du har lärt dig i det här kapitlet:

- Servern legitimerar sig med sitt **certifikat** (**autenticitet**).
- Båda sidor kommer överens om en **sessionsnyckel** med **Diffie-Hellman** – servern **signerar** sin del.
- Därefter krypteras all data med **AES** (**konfidentialitet**) och skyddas mot förändring (**integritet**).

Principen är inte begränsad till webben: Även e-post (avsnitt 8.4) och många andra protokoll går genom TLS på samma sätt.

I de följande avsnitten observerar du HTTPS i Tracer, ställer själv in det och undersöker när webbläsaren varnar – och varför.
