# Läs e-post i tracern

:::sim
url=/sims/lesson-6.3.btsim

Precis som HTTP är SMTP ett **textprotokoll**. Titta på allt som skickas i klartext över ledningen.

## Experimentet

1. Skicka i :fa-play: **Kör**-läge, som på förra sidan, ett mejl från **Anna** till `ben@biber-mail.de`.
2. Öppna i :fa-magnifying-glass: **Spårning**-läge en trace för **Anna**. I kolumnen **Info** står SMTP-dialogen: rader med `C:` skickas av klienten, rader med `S:` av servern.

:::quiz short
Vilken adress står efter `MAIL FROM:`?
= anna@beaver-schule.de
= <anna@beaver-schule.de>
:::

:::quiz short
Och vilken står efter `RCPT TO:`?
= ben@biber-mail.de
= <ben@biber-mail.de>
:::

:::quiz mc
Vilken sifferkod skickar servern när den accepterar ett kommando?
- [x] `250`
- [ ] `200`
- [ ] `404`
:::

:::evaluate
Kontrollera svaren
:::

## Och lösenordet?

Före `MAIL FROM` loggar Annas program in med `AUTH PLAIN` och en teckensträng som `AGFubmEAZ2VoZWlt`. Det ser krypterat ut, men det är det inte: det är bara **Base64**, en kodning som vem som helst direkt kan översätta tillbaka — där finns `anna` och hennes lösenord `geheim`.

Hämta nu posten hos **Ben** (**Hämta**) och öppna en trace för **Ben**. Vid hämtning via IMAP syns det ännu tydligare:

:::quiz short
Vilket lösenord skickar Bens e-postprogram i klartext till servern? (Titta på raden med `LOGIN`.)
= biber123
:::

:::evaluate
Kontrollera svaret
:::

:::warning
Utan kryptering kan alla som fångar upp trafiken läsa **innehåll, avsändare, mottagare och lösenord**. Därför använder man idag krypterade varianter (t.ex. SMTP med STARTTLS, IMAPS på port 993). Hur det fungerar får du lära dig i kapitel 8.
:::

:::tip Att komma ihåg
**SMTP**, **POP3** och **IMAP** är textprotokoll: kommandon som `MAIL FROM`, `RCPT TO`, `DATA` (SMTP) eller `LOGIN` (IMAP) och svaren är läsbara. Utan kryptering skickas även **lösenord** i klartext (eller bara Base64-kodade) över ledningen.
:::
