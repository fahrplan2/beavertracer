# Felsökning: tjänsten svarar inte

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Efter en uppdatering meddelar skolan: ”Echo-tjänsten avvisar alla anslutningar, och webbsidan laddas inte heller längre.” Enligt planen ska **webbservern** lyssna på port `80` och **echo-tjänsten** (TCP Echo-Server) på port `5000`. Hitta felen och åtgärda dem.

<details>
<summary>Tips 1: Vad svarar servern?</summary>

Försök ansluta till `192.168.0.20`, port `5000` med **Enkel TCP-klient** och öppna en trace för Client-PC. Vad svarar servern på ditt `[SYN]`?
</details>

<details>
<summary>Tips 2: Vilka portar är öppna?</summary>

Skriv `nmap -p 80,5000 192.168.0.20` i terminalen på Client-PC. `nmap` provar portarna en efter en och visar vilka som är öppna. Med `ss` på servern ser du på vilka portar ett program verkligen lyssnar där.
</details>

<details>
<summary>Tips 3: Var ställer man in det?</summary>

Öppna apparna **TCP Echo-Server** och **HTTP-Server** på **Server**. Körs tjänsten? Och på vilken port?
</details>

:::task
title: Går tjänsterna att nå?
Kontrollera om Client-PC når echo-tjänsten på port 5000 och webbservern på port 80. Simuleringen måste köra i Körläge för detta.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Vad var det som hände?

:::quiz multi
Vilka påståenden stämmer?
- [x] På `[SYN]` till port 5000 svarade servern med `[RST, ACK]`
- [x] Echo-tjänsten lyssnade på port 5050 i stället för port 5000
- [x] Webbservern var inte startad alls
- [ ] Kabeln mellan Client-PC och Server var trasig
:::

:::evaluate
Kontrollera svar
:::

:::tip Att komma ihåg
Om ett `SYN` får ett **`RST`** till svar lyssnar **inget program** på den porten: datorn går att nå, men tjänsten gör det inte. Typiska orsaker: tjänsten är **inte startad** eller lyssnar på en **annan port**. En titt med `ss` på servern visar vilka portar som verkligen är öppna.
:::
