# 非対称暗号

## 基本の考え方:開いた南京錠

ベンが、自分に手紙を書きたい人全員に**開いた南京錠**を配るところを想像してみよう。対応する**鍵**は自分だけが持っておく。

1. アンナはメッセージを箱に入れ、ベンの南京錠の1つをパチンと閉める。
2. これでもう、誰もその箱を開けられない。アンナ自身も開けられない。
3. ベンだけが、自分の鍵で箱を開けられる。

南京錠は誰が持っていてもよい。持っていても、開けるのには役に立たない。**非対称暗号**もまったく同じ仕組みで動く。参加者はそれぞれ**鍵ペア**を持つ。

| | **公開鍵**(*Public Key*) | **秘密鍵**(*Private Key*) |
|---|---|---|
| 例えると | 開いた南京錠 | 南京錠を開ける鍵 |
| 誰が知っている? | **全員**:公開してよい | **持ち主だけ**:持ち主のコンピューターの外には出ない |
| 何のため? | 持ち主**宛ての**メッセージを**暗号化**する | そのメッセージを**復号**する |

2つの鍵は数学的に対になっている。公開鍵で暗号化されたものは、対応する秘密鍵**だけ**で復号できる。これで鍵交換問題が解決する。ベンは公開鍵を堂々と送ってよい。盗聴者がそれを手に入れても、何も復号できないからだ。

## なぜ秘密鍵を計算で求められないのか?

公開鍵は秘密鍵から計算して作られる。逆向きの計算は、現実的にはできない。最もよく知られている方式である **RSA**(1977年にRivest、Shamir、Adlemanが考案し、その名にちなんで命名)では、**大きな数を素因数に分解するのが非常に難しい**ことがその根拠になっている。巨大な素数を2つ掛け合わせるのは一瞬でできる。しかし、600桁を超える積から2つの因数を見つけ出すことは、現在のどんなコンピューターにもできない。

:::note
RSAのほかに、**楕円曲線**(略称 **EC**、例:**ECDHE**、**ECDSA**)を使う方式もある。これは別の難しい計算問題を根拠にしていて、ずっと短い鍵で済む。公開鍵と秘密鍵を使うという原理は同じだ。現代のHTTPS接続やBeaverTracerも楕円曲線を使っているので、これらの略称はトレースでまた目にするだろう。
:::

## 欠点:遅い

非対称方式はとても手間のかかる計算が必要で、AESより**約1000倍遅い**。Webページ全体や動画をこれで暗号化するのは、あまりに遅すぎる。それでも両方をうまく組み合わせる方法は、**ハイブリッド暗号**のセクションで見よう。

:::tip ポイント
**非対称暗号**では、全員が**鍵ペア**を持つ。**公開鍵**は誰が知っていてもよく、持ち主**宛ての**メッセージを暗号化するのに使う。それを復号できるのは、持ち主の**秘密鍵**だけだ。**RSA**のような方式は、大きな数をほとんど素因数分解できないことを根拠にしている。非対称方式は鍵交換問題を解決するが、処理は遅い。
:::
