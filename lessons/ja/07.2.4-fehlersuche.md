# トラブルシューティング：昨日までは動いていたのに

:::sim
url=/sims/lesson-7.2.4.btsim
:::

昨日は、Heim-Webserver に外部からアクセスできていました。ポートフォワーディング `TCP 80 → 192.168.178.10:80` が設定されています。今朝の停電のあと、Clara がそのページにアクセスできなくなりました。原因を見つけて、恒久的に直しましょう。

<details>
<summary>ヒント1：ルールはどこを指している？</summary>

ホームルーターの **Port FW** にある LAN の IP アドレスと、**Heim-Webserver** が現在実際に持っているアドレス（:fa-gear: **IP設定**）を比べてみましょう。
</details>

<details>
<summary>ヒント2：なぜ別のアドレスになっているの？</summary>

Heim-Webserver は **DHCP** になっていませんか？ その場合、再起動のたびに、ホームルーターの範囲（**DHCP** タブ）から空いている適当なアドレスが割り当てられます。常に同じアドレスにするには、どうすればよいでしょうか？
</details>

:::task
title: Heim-Webserver に再びアクセスできる？
Heim-Webserver が固定アドレスを持っていて、Clara がポートフォワーディング経由でアクセスできるかを確認します。そのためには、シミュレーションが実行モードで動いている必要があります。
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## 何が起きていたのか

:::quiz multi
正しい記述はどれですか？
- [x] Heim-Webserver は DHCP でアドレスを取得していたため、再起動後に別のアドレスになった
- [x] そのため、ポートフォワーディングは、すでにサーバーが動いていないアドレスを指していた
- [x] DHCP の範囲外の固定アドレスにすれば、問題は恒久的に解決する
- [ ] プロバイダーが WAN アドレスをブロックしていた
:::

:::evaluate
回答を確認
:::

:::tip ポイント
**ポートフォワーディング**の転送先となる機器（サーバー、プリンター、カメラなど）には**固定アドレス**が必要です。固定アドレスにするには、**DHCP の範囲外**のアドレスを静的に設定するか、ルーターの DHCPサーバーで固定的に割り当てます。そうしないと、再起動後に別のアドレスが割り当てられてしまうことがあり、ルールが何も指さなくなってしまいます。
:::
