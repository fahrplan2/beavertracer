# ブロードキャストストーム

:::sim
url=/sims/lesson-3.4.1.btsim
:::

3台のスイッチ(A、B、C)がリング状に接続されています。スイッチAには **Anna**(`192.168.0.10`)が、スイッチBには **Ben**(`192.168.0.11`)が接続されています。

## 実験

1. :fa-play: **実行**モードに切り替え、**Anna** で :fa-terminal: **ターミナル**を開き、Ben に ping を送ります:
   ```
   $ ping 192.168.0.11
   ```
2. Anna のウィンドウを閉じて、しばらくワークスペースを観察しましょう。パケットがリングの中をひっきりなしに回り続けています。
3. :fa-magnifying-glass: **トレース**モードに切り替え、**+** で **Ben** のポート `eth0` のトレースを開きます。右上に、これまでに記録されたパケットの数が表示されます。
4. **実行**と**トレース**を何度か行き来して、その数字を見ていましょう。

:::quiz mc
Ben のパケット一覧には何が表示されていますか?
- [ ] Anna の ping と Ben の応答が、いつもどおりに表示される
- [x] 同じ ARP 要求「Who has 192.168.0.11?」が何度も繰り返し表示され、パケットの数が増え続ける
- [ ] 何も表示されない。リングがすべてをブロックしている
:::

:::quiz mc
では、Anna のターミナルには何が表示されますか?
- [ ] すべての ping が届く
- [x] ping はどれも届かない
:::

:::evaluate
答えを確認
:::

## 背後で起きていること

Anna の ARP 要求はブロードキャストです。スイッチAはこれをすべてのポートに送ります。つまりスイッチBにも、スイッチCにも送られます。この2台もそれぞれ、すべてのポートにもう一度転送します。そのため、もう一方のスイッチにも、Aにも送り返されます。Aはそれをまた転送して…。ブロードキャストはリングの中をいつまでも回り続け、新しい要求が出るたびにコピーがさらに増えていきます。

同じフレームがさまざまな方向から次々とスイッチに届くため、スイッチのアドレステーブルもかき乱されます。Anna があるときはこのポートに、あるときはあのポートにいることになってしまうのです。そのため、ping すら届かなくなります。

:::tip ポイント
スイッチ間に**ループ**があると、ブロードキャストがネットワーク内をいつまでも回り続けて増殖します。これが**ブロードキャストストーム**です。ネットワークは機能不全に陥ります。IP パケットとは異なり、イーサネットフレームには、いずれ転送を止めてくれる「有効期限」がありません。
:::
