# IPv6アドレスの読み方と書き方

## 16進数

0と1が128個並んでいても誰も読めませんし、10進数で16グループに分けたとしても、あまり変わりません。そこで、IPv6アドレスは**16進数**(略して*Hex*)で書きます。16進数には**16個の数字**があり、0〜9と、10〜15の値を表す a〜f を使います。

大きな利点があります。16進数の1桁は、ちょうど**4ビット**を表します。

| 10進数 | 16進数 | 2進数 | | 10進数 | 16進数 | 2進数 |
|---|---|---|---|---|---|---|
| 0 | 0 | 0000 | | 8 | 8 | 1000 |
| 1 | 1 | 0001 | | 9 | 9 | 1001 |
| 2 | 2 | 0010 | | 10 | a | 1010 |
| 3 | 3 | 0011 | | 11 | b | 1011 |
| 4 | 4 | 0100 | | 12 | c | 1100 |
| 5 | 5 | 0101 | | 13 | d | 1101 |
| 6 | 6 | 0110 | | 14 | e | 1110 |
| 7 | 7 | 0111 | | 15 | f | 1111 |

つまり、1バイト(8ビット)はちょうど16進数の2桁です。`11111111` = `ff` = 255 となります。実はこれはすでに知っていますね。`aa:28:39:e2:41:82` のようなMACアドレスも16進数で書かれています。

## IPv6アドレスの構成

IPv6アドレスは、それぞれ**16ビット**(つまり16進数4桁)の**8つのブロック**からなり、コロンで区切られます。

```
2001:0db8:0000:0000:0000:0000:0000:0001
```

IPv4と同様に、ネットワーク部とホスト部があります。IPv6では、ネットワーク部を**プレフィックス**、ホスト部を**インターフェースID**と呼びます。ほとんどの場合、プレフィックスの長さは**64ビット**(`/64`)で、最初の4ブロックにあたります。

<pre class="bits-block">
[[n|2001:0db8:0001:0000]]:[[h|a828:39ff:fee2:4182]]
[[n|プレフィックス (64ビット)]]      [[h|インターフェースID (64ビット)]]
</pre>

## 短縮表記

IPv6アドレスはとても長いため、短縮して書くことができます。そのための規則が2つあります。

1. **ブロック先頭の0は省略できます:** `0db8` → `db8`、`0001` → `1`、`0000` → `0`。
2. **連続する0のブロック**は `::` に置き換えられます。ただし、1つのアドレスにつき**1回だけ**です。連続する部分が複数ある場合は、最も長いものを短縮します。

例:

```
2001:0db8:0000:0000:0000:0000:0000:0001   完全表記
2001:db8:0:0:0:0:0:1                      規則1
2001:db8::1                               規則2
```

なぜ `::` は1回だけなのでしょうか。`2001::1::5` では、どこにいくつの0のブロックが省略されているのか、誰にも判断できません。`::` が1つだけなら一意に決まります。省略されているのは、全体でふたたび8ブロックになるのに必要な数だけです。

:::tip ポイント
**IPv6アドレス**は**128ビット**で、**4桁の16進数**からなる**8つのブロック**として書かれます。最初の64ビットは多くの場合**プレフィックス**(ネットワーク部)、残りの64ビットは**インターフェースID**(ホスト部)です。短縮するには、先頭の0を省略し、連続する0のブロックを**1か所だけ** `::` に置き換えます。
:::
