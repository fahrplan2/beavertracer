このように、Web ページはテキスト、スタイルシート、画像など、多くのファイルで構成されていることがよくあります。ブラウザはそれぞれのファイルごとに、個別のリクエストを送ります。

## リクエストの形式

トレースで `GET / HTTP/1.1` のパケットをクリックし、**Hypertext Transfer Protocol** を展開します。HTTP リクエストはただのテキストです。

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

サーバーのレスポンスも同じ構造です。ステータス行、ヘッダー、空行、そして本来のファイルの順に続きます。

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP-Anfrage
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP-Anfrage
Server -> Client-PC: 200 OK | style.css
:::

## メソッドとステータスコード

**メソッド**は、クライアントが何をしたいのかを表します。

| メソッド | 意味 |
|---|---|
| **GET** | ファイルを取得する |
| **POST** | サーバーにデータを送る(例:入力済みのフォーム) |
| **HEAD** | ファイルは取得せず、ヘッダーだけを取得する |

**ステータスコード**は、処理の結果を表します。最初の数字でレスポンスの種類が分かります。

| コード | テキスト | 意味 |
|---|---|---|
| **200** | OK | すべて問題なし |
| **301** | Moved Permanently | ページが恒久的に移転した |
| **404** | Not Found | そのファイルは存在しない |
| **405** | Method Not Allowed | このメソッドはここでは許可されていない |
| **500** | Internal Server Error | サーバー側のエラー |

`2xx` は成功、`3xx` はリダイレクト、`4xx` はクライアント側のエラー(誤ったリクエスト)、`5xx` はサーバー側のエラーを表します。

:::tip ポイント
**HTTP** は**リクエスト・レスポンス方式**で動作します。クライアントは**リクエスト**(`GET` などのメソッド、パス、ヘッダー)を送り、サーバーは**ステータスコード**(例:`200 OK`、`404 Not Found`)、ヘッダー、ファイルを返します。Web ページの各ファイルごとに、個別のリクエストが発生します。
:::

:::quiz match
200 -> すべて問題なし
301 -> ページが恒久的に移転した
404 -> 要求されたファイルは存在しない
500 -> サーバーでエラーが発生した
:::
