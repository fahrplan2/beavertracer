# ハイブリッド暗号方式

ここまでをまとめましょう。

| | 共通鍵暗号（例：AES） | 公開鍵暗号（例：RSA） |
|---|---|---|
| 鍵 | 共有する1つの秘密鍵 | 鍵ペア：公開鍵＋秘密鍵 |
| 速度 | 非常に高速 | 低速 |
| 鍵の交換 | 問題あり：鍵をどうやって受信者に届けるのか？ | 問題なし：公開鍵は公開したまま送ってよい |

つまり、それぞれの方式には、もう一方に欠けている長所があります。そこで解決策として、両方を組み合わせます。これを**ハイブリッド暗号方式**と呼びます。

1. 接続の開始時に、双方が**公開鍵暗号**の方式を使って、共通の秘密鍵である**セッション鍵**を取り決めます。これには少し時間がかかりますが、行うのは**1回だけ**です。
2. その後、すべてのデータをセッション鍵で**共通鍵暗号**により暗号化します。こちらは高速です。
3. 接続の終了時に、セッション鍵は破棄されます。次の接続では新しい鍵が使われます。

**HTTPS**、暗号化されたメール接続、WPA3 を使う **WLAN**、**SSH**、**VPN** は、このように動作しています。

## 色の混ぜ合わせによる共通の秘密

セッション鍵を取り決めるエレガントな方法が、**Diffie-Hellman 鍵交換**（1976年）です。これは色にたとえて考えることができます。ポイントは、色を混ぜるのは簡単でも、混ざった色を元の成分に分けるのは事実上不可能だということです。

1. Anna と Ben は、共通の基本色、たとえば**黄色**を**公開で**取り決めます。この色は誰が知っていてもかまいません。
2. それぞれが**秘密の色**をこっそり選びます。Anna は**赤**、Ben は**青**です。
3. それぞれが自分の秘密の色を基本色に混ぜ、その結果を相手に**そのまま公開で**送ります。Anna は**黄色＋赤**（オレンジ）を、Ben は**黄色＋青**（緑）を送ります。
4. 次に、それぞれが相手から届いた混合色に、自分の秘密の色を混ぜます。
    - Anna：緑＋赤＝**黄色＋青＋赤**
    - Ben：オレンジ＋青＝**黄色＋赤＋青**
5. これで2人とも**同じ**色（茶色）を手にしました。これが共通の鍵です。

盗聴者が見たのは黄色、オレンジ、緑です。しかし茶色を作るには赤か青が必要で、これらは Anna も Ben も一度も送っていません。

実際には、もちろん色ではなく非常に大きな数で計算します。トレースでは、この鍵交換を **Server Key Exchange** と **Client Key Exchange** としてまもなく目にすることになります。**ECDHE** の「**DHE**」は *Diffie-Hellman Ephemeral*、つまり使い捨ての鍵を使う Diffie-Hellman という意味です。

:::warning
Diffie-Hellman だけでは、攻撃者が間に入り込み、Anna **とも** Ben **とも**それぞれ別の鍵を取り決めてしまうことは防げません。そのため、Anna は本当に Ben と通信しているのだと確信できる必要があります。そのために**署名**と**証明書**が必要になります。これが次のテーマです。
:::

:::tip ポイント
**ハイブリッド暗号方式**は両方の長所を組み合わせます。**公開鍵暗号**の方式（例：Diffie-Hellman）で双方が秘密の**セッション鍵**を取り決め、データ自体はその鍵で**共通鍵暗号**（例：AES）により暗号化します。HTTPS、WLAN の暗号化、SSH、VPN はこのように動作しています。
:::
