# シーケンス番号と確認応答番号

:::sim
url=/sims/lesson-5.1.btsim
:::

TCP は、すべてのデータが届いたかどうか、そしてどの順番で届いたかを、どうやって知るのでしょうか。それぞれの側が、自分が送る**バイトに番号を付けます**。

- **シーケンス番号**(`SEQ`)は、このパケットに含まれる最初のバイトの番号です。
- **確認応答番号**(`ACK`)は「ここまではすべて受け取ったよ。次は○番のバイトを待っているよ」という意味です。

さらに2つのルールがあります。`SYN` と `FIN` は、データを運ばないにもかかわらず1バイトとして数えます。そして、それぞれの側が自分で数えます。そのため、番号の系列は2つあり、図では赤(クライアント)と青(サーバー)で表されます。

## 計算して確かめよう

先ほどの接続をもう一度見てみましょう。線の上の数字は、その時点でのそれぞれのコンピューターのカウンターを表しています。

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

赤い数字の並びを順にたどってみましょう。

1. クライアントは `SEQ=0` から始めます。`SYN` が番号を1つ消費するので、サーバーは `ACK=1` で確認応答します。
2. メッセージは `SEQ=1` から始まり、長さは13バイト(1~13バイト目)です。サーバーは `ACK=14` で確認応答します。「次は14バイト目を待っているよ」という意味です。
3. したがって、クライアントの `FIN` は `SEQ=14` となり、`ACK=15` で確認応答されます。

サーバー側の青い数字の並びも、まったく同じように動作します。

:::tip ポイント
**シーケンス番号**(`SEQ`)は、パケット内の最初のバイトの番号です。**確認応答番号**(`ACK`)は、受信者が次に待っているバイトの番号であり、それより前のものはすべて届いています。**ACK = SEQ + 受信したデータの長さ**という関係が成り立ちます。`SYN` と `FIN` は1バイトとして数えます。それぞれの側が、自分のバイトを数えます。
:::

:::tip 試してみよう
**シンプル TCP クライアント**でもう一度接続を作り、続けて2つのメッセージを送ってみましょう。その前に、**Info** 列にどんな `Seq` と `Ack` が表示されるか予想し、トレースで確かめてみましょう。
:::

足りない番号を入力しましょう。クライアントは `Hallo` を送り、その後 `Tschau` を送ります(どちらも行末の改行付き)。

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
図を確認
:::

:::note
実際のネットワークでは、番号は 0 から数え始めるわけではありません。それぞれの側が、0 から約43億の間でランダムな**開始番号**(*Initial Sequence Number*、ISN)を選びます。最大の番号に達すると、再び 0 から続きます。トレーサーは開始番号を差し引いて**相対的な**番号を表示します。これは Wireshark と同じです。そのため、`Seq=0` や `Seq=1` と表示されます。

また、どのパケットにも `Win=` が含まれています。これは**ウィンドウサイズ**で、受信者が今受け取れるバイト数を表します。これによって、送信が速すぎる送信元にブレーキをかけます(*フロー制御*)。BeaverTracer では、ウィンドウは常に同じ大きさです。
:::
