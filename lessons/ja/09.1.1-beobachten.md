## 外部からの ping

:fa-play: **実行**モードに切り替えて、**Internet-PC** から学校のサーバーに ping を送ります。

```
$ ping -c 2 198.51.100.10
```

その後、ファイアウォールの **Protokoll** タブを開きましょう。

:::quiz mc
`ping` は何と報告しますか？
- [x] `Anfrage abgelaufen` — 何も返ってこない
- [ ] `Paket gefiltert`
- [ ] 学校のサーバーからの2つの応答
:::

:::

## ポートスキャン：破棄か拒否か？

次に、5つのポートを狙ってスキャンします。ポート3306(データベース)は、学校のサーバーでは稼働していません。

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (破棄) -> filtered
25 (許可、サービス稼働中) -> open
110 (拒否) -> closed
3306 (許可、サービスなし) -> closed
:::

:::evaluate
対応関係を確認
:::

:::quiz multi
攻撃者はこの結果から何を推測できますか？
- [x] `filtered` の場合、パケットを飲み込むファイアウォールがそこにあるとわかる
- [x] `closed` の場合、ファイアウォールが拒否しているのか、単にサービスが動いていないのかを区別できない
- [ ] `filtered` の場合、そのポートの先でどのサービスが動いているかがわかる
- [ ] `closed` の場合でも、そのサービスには到達できる
:::

:::evaluate
回答を確認
:::

最後に、ルール一覧の **Treffer** 列を見てみましょう。ここでは、各ルールがこれまでにいくつのパケットを処理したかをファイアウォールが数えています。**Standardrichtlinie** の横の値は、どのルールにも一致しなかったすべてのパケットの数です。

:::tip ポイント
**破棄された**パケットは跡形もなく消えます。`ping` はタイムアウトを報告し、`nmap` は `filtered` と報告します。**拒否された**パケットには、ファイアウォールが拒否の応答を返します(TCP では RST)。外から見ると、閉じたポートのように見えます。ファイアウォールの **Protokoll** は、どのパケットを止めたかを示し、**Treffer** 列は、どのルールが適用されたかを示します。
:::
