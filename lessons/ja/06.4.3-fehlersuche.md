# トラブルシューティング: ノートPCがネットワークにつながらない

:::sim
url=/sims/lesson-6.4.3.btsim
:::

休暇明け、先生たちから連絡が入ります。「ノートPCがネットワークにつながらなくなりました!」 2台のノートPCはどちらも **DHCP** に設定されています。計画では、DHCPサーバーが `192.168.0.100` から `192.168.0.120` までのアドレスを配布し、ゲートウェイは `192.168.0.1`、DNSサーバーは `192.168.0.53` となっているはずです。

原因を見つけて修正しましょう。

<details>
<summary>ヒント1: ノートPCにはどのアドレスが付いている?</summary>

ノートPCの :fa-gear: **IP設定** を見てみましょう。`169.254` で始まるアドレスは、DHCPサーバーから応答がなかったために、機器が**自分で**付けたアドレスです。
</details>

<details>
<summary>ヒント2: DHCPサーバーは応答している?</summary>

ノートPCのトレースを開きましょう。`DHCP Discover` しか見えませんか。それとも応答も見えますか。次に **DHCPサーバー** アプリを確認します。動作していますか。そして、どの範囲を配布していますか。
</details>

<details>
<summary>ヒント3: 新しいアドレスを取得する</summary>

サーバー側で何か変更した場合は、ノートPCのIP設定でモードをいったん **静的** にしてから **DHCP** に戻し、**適用** をクリックします。すると、あらためて要求を送ります。
</details>

:::task
title: ノートPCはネットワークに戻れた?
2台のノートPCが、計画した範囲のアドレスを持ち、DHCPサーバーに到達できるかを確認します。そのためにはシミュレーションが実行モードで動いている必要があります。
check: ip(3, "192.168.0.96/27")
check: ip(4, "192.168.0.96/27")
check: pingOk(3, 2)
check: pingOk(4, 2)
:::

## 何が起きていたのか?

:::quiz multi
正しい記述はどれですか?
- [x] DHCPサーバーが開始されていなかった。そのためノートPCは自分で `169.254` のアドレスを付けた
- [x] アドレス範囲が間違ったネットワークにあった(`192.168.0.…` ではなく `192.168.1.…`)
- [ ] ノートPCが固定アドレスに設定されていた
- [ ] スイッチにゲートウェイがなかった
:::

:::evaluate
回答を確認
:::

:::tip ポイント
機器が **`169.254.0.0/16`** のアドレスを持っている場合、その機器は **DHCPサーバーから応答を得られず**、自分でアドレスを付けています(**APIPA**)。このアドレスでは、同じ状況にある他の機器としか通信できません。その場合は次を確認しましょう。DHCPサーバーは動いていますか。到達可能ですか。そして、**正しいネットワーク**のアドレスを配布していますか。
:::
