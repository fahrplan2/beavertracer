# 独自のCAを構築する

:::sim
url=/sims/lesson-8.2.2.btsim
:::

`www.beaver-schule.de` にはまだ証明書がありません。学校は商用CAに申請する代わりに、**独自のCA**である**Schul-CA**を構築します。多くの企業や学校が、社内向けのサーバーのためにこの方法をとっています。

実際には、Schul-CAは専用の特に厳重に保護されたコンピューターで動かします。ここでは、すべての役割をWebサーバー上で自分で演じます。

## ステップ1: Schul-CAを作成する

1. :fa-play: **実行**モードに切り替えて、Webサーバー **www.beaver-schule.de** の :fa-shield-halved: **Zertifikatverwaltung** を開きます。
2. タブ **Generieren** で次のように設定します。
    - **Common Name:** `Schul-CA`
    - **Typ:** Selbstsigniert
    - **Dies ist ein CA-Zertifikat** にチェックを入れる
    - **Speichern unter:** `schul-ca.cert.json`
3. **Zertifikat generieren** をクリックします。

このとき、新しい**鍵ペア**が作成されます。証明書には公開鍵が含まれ、秘密鍵はWebサーバー上のファイルに残ります。

## ステップ2: サーバー証明書を発行する

もう一度、タブ **Generieren** で次のように設定します。

- **Common Name:** `www.beaver-schule.de` — ブラウザに入力するのとまったく同じ名前
- **Typ:** Von CA signiert、**Signierende CA:** Schul-CA
- **Speichern unter:** たとえば `www.beaver-schule.de.cert.json`

タブ **Meine Zertifikate** に、これで2つの証明書が表示されます。新しいサーバー証明書をクリックしてください。

:::quiz short
サーバー証明書の**発行者**(**Aussteller**)は誰ですか(`CN=` は除く)?
= Schul-CA
:::

:::quiz mc
その**チェーン**(**Kette**)はどう表示されていますか?
- [x] `www.beaver-schule.de ← Schul-CA`
- [ ] `Schul-CA ← www.beaver-schule.de`
- [ ] `www.beaver-schule.de`(自己署名)
:::

:::evaluate
答えを確認
:::

## ステップ3: クライアントにSchul-CAを教える

クライアントPCはまだSchul-CAを知りません。ブラウザにはあらかじめインストールされていないからです。クライアントにはその証明書を渡す必要がありますが、渡すのは**秘密鍵なし**のものです。

1. Webサーバーの **Meine Zertifikate** で **Schul-CA** を選び、**Kopieren** をクリックします(*Kopieren + Schlüssel* ではありません!)。
2. **クライアントPC**で :fa-shield-halved: **Zertifikatverwaltung** を開き、タブ **Vertrauenswürdige CAs** に移動します。
3. **Einfügen: Schul-CA** をクリックします。

:::warning
**CAの秘密鍵**は、システム全体で最も重要な秘密です。これを持っている人は、**任意の**名前の証明書を発行でき、すべてのクライアントがそれを信頼してしまいます。秘密鍵はCAのコンピューターから決して持ち出してはいけません。
:::

:::task
title: Schul-CAを設定できましたか?
Webサーバーに、Schul-CAが発行した www.beaver-schule.de の証明書があること、そしてクライアントPCがSchul-CAを信頼していることを確認します。
check: hasCert(4, "www.beaver-schule.de", "Schul-CA")
check: trusts(2, "Schul-CA")
:::

:::quiz mc
クライアントには、なぜ秘密鍵**なし**の証明書だけをコピーするのですか?
- [ ] 鍵付きでコピーすると時間がかかるから
- [x] 署名の検証には公開鍵で十分であり、秘密鍵があるとクライアント側で誰でも証明書を発行できてしまうから
- [ ] そうしないとクライアントが接続を確立できないから
:::

:::evaluate
答えを確認
:::

Webサーバー自体はまだ切り替えていないので、引き続きHTTPだけで通信します。HTTPSを有効にする方法は、8.3.3節で学びます。

:::tip ポイント
**独自のCA**は、秘密鍵を持つ**自己署名のCA証明書**でできています。これを使って、Common Nameがサーバー名と一致する**サーバー証明書**を発行します。クライアントがこれらの証明書を信頼するには、**秘密鍵なしのCA証明書**を**信頼できるCA**のリストに追加します。
:::
