# トラブルシューティング: 証明書の警告

:::sim
url=/sims/lesson-8.3.4.btsim
:::

学校のネットワークには、ほかにも3台のWebサーバーがあります。**Mensa**、**Bibliothek**、**Sport-AG** です。3台ともHTTPSで通信しますが、それでも **Client-PC** のブラウザはどのサーバーでも警告を表示します。Client-PCは **Schul-CA** を信頼しています。

## 調べてみよう

:fa-play: **実行**モードに切り替えて、**Client-PC** で次のURLを順番に開いてみましょう。

- `https://mensa.beaver-schule.de/`
- `https://bibliothek.beaver-schule.de/`
- `https://sport.beaver-schule.de/`

それぞれの警告と証明書の情報(サブジェクト、発行者、有効期限)を読み取りましょう。

:::quiz match
mensa.beaver-schule.de -> 証明書の有効期限が切れている
bibliothek.beaver-schule.de -> 証明書が自己署名で、クライアントがそれを信頼していない
sport.beaver-schule.de -> 証明書が別の名前に対して発行されている
:::

:::evaluate
対応を確認
:::

:::quiz short
Sport-AGの証明書は、どの名前に対して発行されていますか(`CN=` は除く)?
= www.beaver-schule.de
:::

:::evaluate
答えを確認
:::

## Mensaを修復する

Mensaは最も簡単に修復できます。証明書はもともとSchul-CAが発行したもので、有効期限が切れているだけです。簡略化のため、Schul-CAはここではMensaサーバー上に直接置かれています。

<details>
<summary>ヒント1: 新しい証明書を発行する</summary>

**mensa.beaver-schule.de** で :fa-shield-halved: **Zertifikatverwaltung** を開きます。**Signieren** タブで、既存の証明書をSchul-CAに**再署名**してもらえます。このとき新しい有効期間が設定されます。新しいファイル名、たとえば `mensa-neu.cert.json` で保存しましょう。
</details>

<details>
<summary>ヒント2: 新しい証明書を使う</summary>

Mensaの**HTTPサーバー**で、**Stoppen** をクリックし、**HTTPS** タブで新しい証明書を選択し(ファイル名で見分けられます)、**Verwenden**、**開始** の順にクリックします。
</details>

:::warning
証明書の警告が出たときに**「このまま続行」**を選ぶのは、ほとんどの場合よい考えではありません。攻撃者が自分の証明書をすり替えた場合も、まったく同じ表示になるからです。`curl -k` も同様です。これは証明書の検証を無効にするもので、テストには便利ですが、実運用では危険です。
:::

:::tip ポイント
ブラウザが警告を出すのは、証明書の**有効期限が切れている**とき、発行元の**CAを知らない**とき(たとえば**自己署名**証明書の場合)、または証明書の**名前**がアクセスしたアドレスと一致しないときです。解決策は常に、信頼できるCAが発行した、適切で有効な証明書を用意することです。警告をクリックして消すことではありません。
:::
