## 実験

1. :fa-play: **実行**モードに切り替え、**Client-PC** をクリックして :fa-globe: **ブラウザ**を開きます。
2. 今回は `http://www.beaver-schule.de/` にアクセスします。IPアドレスではなく名前を使います。
3. :fa-magnifying-glass: **トレース**モードに切り替え、**Client-PC** のトレースを開きます。

いちばん最初、`[SYN]` による接続確立よりも前に、プロトコルが **DNS** の2つのパケットがあります。

:::quiz short
Client-PC は DNS クエリをどの IP アドレスに送信していますか?
= 192.168.0.53
:::

:::quiz short
`www.beaver-schule.de` の応答には、どの IP アドレスが入っていますか?
= 192.168.0.20
:::

:::quiz mc
DNS クエリをクリックして、プロトコルツリーを展開しましょう。どのトランスポートプロトコルと宛先ポートが使われていますか?
- [ ] TCP、ポート 80
- [x] UDP、ポート 53
- [ ] UDP、ポート 67
:::

:::evaluate
答えを確認
:::

Client-PC は IP アドレスがわかってから初めて、Webサーバーへの TCP 接続を確立します。第5章とまったく同じです。

:::seq
mode: text
Client-PC -> DNS-Resolver: DNS-Anfrage | A www.beaver-schule.de?
DNS-Resolver -> Client-PC: DNS-Antwort | A 192.168.0.20
:::

## PC はどうして DNS サーバーを知っているのか?

**Client-PC** の :fa-gear: **IP設定**を開きましょう。**DNS-Server** フィールドには `192.168.0.53` と入っています。これは **DNS-Resolver** というコンピューターです。PC はすべての名前解決の問い合わせをここに送ります。

ブラウザを使わずに、DNS サーバーに直接問い合わせることもできます。:fa-terminal: **ターミナル**を開いて、次のように入力します。

```
$ nslookup www.beaver-schule.de
```

`nslookup` は、まずどのサーバーに問い合わせたかを表示し、その後に応答を表示します。比較のために、存在しない名前、たとえば `nslookup gibtsnicht.beaver-schule.de` も問い合わせてみましょう。

:::quiz mc
存在しない名前に対して、DNS サーバーはどう応答しますか?
- [ ] ランダムな IP アドレス
- [x] `NXDOMAIN`(その名前は存在しない)
- [ ] 何も応答しない
:::

:::evaluate
答えを確認
:::

:::tip ポイント
**DNS** は名前(例:`www.beaver-schule.de`)を IP アドレスに変換します。PC は名前に対して接続を確立する前に、IP設定に登録されている **DNSサーバー**に問い合わせます。たいていは **UDP のポート 53** を使います。`nslookup` を使えば、DNS クエリを手動で送れます。
:::
