# アドレスを自動で取得する

:::sim
url=/sims/lesson-6.4.btsim
:::

スイッチには **DHCPサーバー** と2台のノートPCがつながっています。ノートPCにはまだ固定のアドレスが設定されています。

## 実験

1. :fa-play: **実行**モードに切り替え、**Laptop 1** をクリックして :fa-gear: **IP設定** を開きます。
2. **モード** を **静的** から **DHCP** に変更し、**適用** をクリックします。
3. 数秒待ちます。各欄が自動的に埋まります。
4. :fa-magnifying-glass: **トレース**モードで、**Laptop 1** のトレースを開きます。

:::quiz table
| 設定項目 | DHCPサーバーから取得した値 |
|---|---|
| IPアドレス | {192.168.0.100} |
| ゲートウェイ | {192.168.0.1} |
| DNSサーバー | {192.168.0.53} |
:::

## 仕組み：DORA

アドレスのない機器は、DHCPサーバーがどこにいるかも分からず、自分の送信元アドレスも持っていません。そのため、**ブロードキャスト**でネットワークに呼びかけます。この手順は4つのステップから成り、その頭文字をとって **DORA** と呼ばれます。

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | 「ここにDHCPサーバーはいますか？」
DHCP-Server -> Laptop 1: DHCP Offer | 「192.168.0.100 を使っていいですよ。」
Laptop 1 -> DHCP-Server: DHCP Request | 「192.168.0.100 をもらいます。」
DHCP-Server -> Laptop 1: DHCP ACK | 「確認しました。3600秒間有効です。」
:::

このアドレスは**借りている**だけです（*リース*）。**リース時間**が過ぎる前に機器はそれを更新しなければならず、更新しないとサーバーはそのアドレスを再び別の機器に割り当ててよいことになります。現在どのアドレスが貸し出されているかは、**DHCPサーバー**の **Leases** タブで確認できます。

:::tip 試してみよう
**Laptop 2** もDHCPに設定してみましょう。どのアドレスがもらえるでしょうか？そのあと、DHCPサーバーの **Leases** を見てみましょう。
:::

:::tip ポイント
**DHCP** は、IPアドレス、サブネットマスク、ゲートウェイ、DNSサーバーを自動的に配布します。手順は **DORA** と呼ばれます。**D**iscover（クライアントがブロードキャストで探す）、**O**ffer（サーバーが提示する）、**R**equest（クライアントが受け入れる）、**A**CK（サーバーが確認する）の4つです。アドレスは**リース時間**のあいだ貸し出されます。DHCPは **UDP** を使い、ポートはサーバーが67番、クライアントが68番です。
:::

:::quiz match
Discover -> クライアントがブロードキャストでDHCPサーバーを探す
Offer -> サーバーがアドレスを提示する
Request -> クライアントが提示されたアドレスを要求する
ACK -> サーバーが割り当てを確認する
:::
