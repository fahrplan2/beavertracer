# 応答の問題

:::sim
url=/sims/lesson-9.2.btsim
:::

ファイアウォールはいま、ホワイトリスト方式で動作しています。デフォルトポリシーは **Alle verwerfen** です。ルールは1つだけで、学校ネットワークからのWebブラウジングを許可しています: **B → A, TCP, 宛先ポート 80, Zulassen**。モードは **Stateless** になっています。

## 実験

1. :fa-play: **実行**モードに切り替え、**Lehrer-PC** の :fa-globe: **ブラウザ** で `http://203.0.113.80/` を開きます。
2. **Firewall** の **Protokoll** と **Treffer** を確認します。

:::quiz mc
ブラウザでは何が起こる?
- [ ] www.beispiel.de のページが表示される
- [x] ページが読み込まれず、ブラウザは待ち続け、最終的にエラーを表示する
:::

:::quiz mc
ファイアウォールのプロトコルで破棄(`DROP`)と記録されているパケットはどれ?
- [ ] Lehrer-PC からポート80へのリクエスト
- [x] `203.0.113.80` から Lehrer-PC への、**送信元ポート 80** の応答
- [ ] 1つもない
:::

:::quiz short
破棄されたパケットは、どちらの方向(A→B または B→A)に流れている?
= A→B
= A → B
= AtoB
:::

:::evaluate
回答を確認
:::

Lehrer-PC のリクエストは外へ出られます。しかし、Webサーバーの `SYN, ACK` はすでに戻ってこられません。A → B の方向に合致するルールがないため、**Alle verwerfen** が適用されるからです。

## 単純な解決策

2つ目のルールを追加することもできます: **A → B, TCP, 送信元ポート 80, Zulassen**。つまり「ポート80から来るものは何でも入ってよい」というルールです。これで確かにWebブラウジングはできるようになります。

:::quiz mc
このルールはなぜ危険?
- [ ] Webサーバーは送信元ポートとしてポート80を決して使わないから
- [x] 攻撃者は送信元ポートを80にしてパケットを送り出すだけで、ファイアウォールはそれを学校ネットワーク内の**あらゆる**ポートへ通してしまうから
- [ ] Webページの読み込みが遅くなるから
:::

:::evaluate
回答を確認
:::

送信元ポートは送信元自身が決めるため、ファイアウォールはそれに頼ってはいけません。ところがステートレスなファイアウォールは、パケットが**リクエストへの応答**なのか、外部からの**新しい接続の試み**なのかを判別できません。まさにこの点を変えるのが、ステートフルモードです。

:::tip ポイント
**ステートレス**なパケットフィルタは、パケットを1つ1つ個別に検査します。そのため応答には戻り方向専用のルールが必要になります。しかも、そのようなルール(例:「送信元ポート80は入ってよい」)は、送信元が送信元ポートを自由に選べるため、攻撃者に悪用されかねません。
:::
