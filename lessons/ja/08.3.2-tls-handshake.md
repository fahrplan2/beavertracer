# TLS ハンドシェイク

:::sim
url=/sims/lesson-8.2.1.btsim
:::

最初の暗号化されたリクエストが送られる前に、クライアントとサーバーは合意しておく必要があります。使う方式とセッション鍵について合意し、さらにクライアントは通信相手が誰なのかを確認しなければなりません。この接続確立を **TLS ハンドシェイク** と呼びます。

## 図で見る流れ

TCP の確認応答(`ACK`)を除くと、ハンドシェイクは次のようになります。

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

ここで何が起きているのか、そしてセクション 8.1 のどの構成要素が使われているのかを見てみましょう。

1. **Client Hello / Server Hello:** クライアントとサーバーがあいさつを交わし、乱数を交換して、使う方式に合意します(BeaverTracer では、鍵交換に **ECDHE**、署名に **ECDSA**、暗号化に **AES** を使います)。
2. **Certificate:** サーバーが自分の**証明書**を送ります。クライアントは CA の署名、有効性、名前を確認します。これに失敗するとここで中断され、ブラウザは警告を表示します。
3. **Server Key Exchange:** サーバーが自分の **Diffie-Hellman の値**を送り、秘密鍵で**署名**します。クライアントは証明書に含まれる公開鍵で署名を確認します。これにより、この値が確かに証明書の所有者から来たものであり、中間者攻撃者(Man-in-the-Middle)によるものではないことがわかります。
4. **Client Key Exchange:** クライアントが自分の Diffie-Hellman の値を送ります。これで双方が同じ**セッション鍵**を計算できます。その鍵自体は一度も送信されていません。
5. **Change Cipher Spec:** 「ここから先は暗号化します。」
6. **Encrypted Handshake Message (Finished):** 双方が、それまでのすべてのハンドシェイクメッセージに対するチェックサムを、すでに暗号化した状態で送ります。途中で攻撃者が何かを改ざんしていれば、チェックサムが一致せず、接続は中断されます。
7. **Application Data:** ここから HTTP データが流れます。AES による共通鍵暗号で暗号化されています。

:::quiz match
Certificate -> サーバーが証明書で身元を証明する
Server Key Exchange -> サーバーの署名付き Diffie-Hellman の値
Client Key Exchange -> クライアントの Diffie-Hellman の値
Change Cipher Spec -> ここから暗号化が始まる
Application Data -> 暗号化された HTTP データ
:::

:::note
トレースには、TLS 接続が**2つ**続けて表示されます。ブラウザはまずページを取得し、次にスタイルシート `style.css` のために新しい接続を確立します。接続ごとに独自のハンドシェイクと独自のセッション鍵が用意されます。実際のブラウザは接続を開いたままにしておくことで、この手間の一部を省いています。また、新しいバージョンの **TLS 1.3** は、ここで示した TLS 1.2 よりも少ないメッセージで済みます。
:::

:::tip ポイント
**TLS ハンドシェイク**では、サーバーが**証明書**で身元を証明し、双方が **Diffie-Hellman** で**セッション鍵**を取り決めます(サーバーは自分の値に**署名**します)。そして **Finished** によって、誰もハンドシェイクを改ざんしていないことを双方が確認します。その後、データは **Application Data** として共通鍵暗号で暗号化されて送信されます。
:::
