さっきと同じリングです。今回は先に**スパニングツリープロトコル**（**STP**）を有効にします。

## STPを有効にする

**3台すべて**のスイッチで次の操作をします。

1. :fa-play: **実行**モードに切り替えて、スイッチをクリックします。
2. **STP** タブを開き、モードで **STP (802.1D)** を選びます。

その後、約**15秒**待ちます。この間にスイッチ同士が小さなメッセージ（*BPDU*と呼ばれます）をやり取りして、共通の構造を決めます。

## スイッチが取り決めた内容

各スイッチの **STP** タブを開いて、表を見てみましょう。接続されている各ポートには **State**（状態）があります。

- [ ] Switch C
:::

では **Anna** から Ben に ping を送ってみましょう（`ping 192.168.0.11`）。今回は ping が届き、リングの中をパケットがぐるぐる回り続けることもありません。

STP は1台のスイッチをルートに選び、そこから**ツリー**を作りました。どのスイッチにも、ちょうど1本の経路でたどり着けます。ループを作ってしまう1本の接続は**ブロック**されます。ケーブルは挿さったままですが、スイッチはそこを通して通常のフレームを送りません。

## ケーブルが故障したらどうなる？

1. :fa-pencil: **編集**モードに切り替え、:fa-ban: **削除**ツールを選んで、**Switch A** と **Switch B** の間のケーブルをクリックします。
2. :fa-play: **実行**モードに戻り、再び約15秒待ちます。
3. **Switch B** の **STP** タブを見てから、もう一度 Anna から Ben に ping を送ります。

:::quiz mc
何が起こりましたか？
- [ ] Ben に到達できなくなった
- [x] それまでブロックされていた Switch B のポートが転送を始め、ping は Switch C を経由する回り道を通る
- [ ] Switch B がルートになった
:::

:::evaluate
答えを確認
:::

:::tip ポイント
**スパニングツリープロトコル**（**STP**）は、スイッチ間のループを防ぎます。スイッチは**ルートブリッジ**を選出し、どのスイッチにもちょうど1本の経路でたどり着けるように、一部のポートを**ブロック**します。接続が切れると、STP はブロックしていたポートを再び開放します。そのため、障害が起きてもネットワークには到達できるままです。
:::

:::task
title: リングは保護できた？
Anna が Ben に到達できるかを確認します。STP がなければ、ping はブロードキャストストームに飲み込まれてしまいます。そのため、シミュレーションを実行モードで動かしておく必要があります。
check: pingOk(5, 7)
:::

## 発展：STP にはほかにもできることがある

ここで見たのは基本原理にすぎません。実際のネットワークには、もっと多くの要素があります。

- **さまざまな種類：** 従来の STP のほかに、改良された方式があります。たとえば障害後にずっと速く復旧できる **RSTP**（*Rapid* STP）や、**MSTP**（*Multiple* STP）です。
- **STP と VLAN：** スイッチ間で複数の VLAN が動いている場合は、VLAN ごとにツリーをどう作るかを別途決める必要があります。そのための専用の方式や設定があります。
- **ルートブリッジの選出：** どのスイッチがルートになるかは、厳密に定められた独自の手順で決まります。この例では、常に Switch A が選ばれるようにあらかじめ設定してあります。

:::note
これらのテーマはこのコースの範囲を超えています。大切なのは、実際のネットワークで STP を設定するには、この節で学ぶよりずっと多くの知識が必要になる、ということだけです。
:::
