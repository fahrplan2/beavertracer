# HTTPSの設定

:::sim
url=/sims/lesson-8.3.3.btsim
:::

ここでは、セクション8.2.2の続きから始めます。Webserver **www.beaver-schule.de** には **Schul-CA** と、その CA が発行したサーバー証明書があり、**Client-PC** は Schul-CA を信頼しています。ただし、このWebサーバーはまだ HTTPS を話せません。

## 設定前の確認

:fa-play: **実行**モードに切り替え、**Client-PC** の :fa-globe: **ブラウザ**で `https://www.beaver-schule.de/` を開きましょう。

:::quiz mc
何が起こるでしょうか？
- [x] 接続できない — ポート443で待ち受けているサービスがない
- [ ] ブラウザが安全でない証明書について警告する
- [ ] 鍵マークなしでページが表示される
:::

:::evaluate
答えを確認
:::

## HTTPSを有効にする

1. Webserver で **HTTPサーバー**を開き、**停止** をクリックします。サーバーが動いている間は設定を変更できません。
2. **HTTPS** タブに切り替えます:
    - **HTTPSを有効にする** にチェックを入れ、**HTTPSポート** を `443` にします
    - **証明書** では、サーバー証明書 `www.beaver-schule.de` を選びます。Schul-CA ではありません！
    - **使用** をクリックします
3. **開始** をクリックします。

Client-PC で、もう一度 `https://` でページを開きましょう。鍵マークをクリックして、発行者と有効期間を確認します。

:::task
title: HTTPSを設定できましたか？
Client-PC が https://www.beaver-schule.de/ を証明書の警告なしで取得できるかを確認します。そのためには、シミュレーションを実行モードで動かしておく必要があります。
check: httpsOk(2, "https://www.beaver-schule.de/")
:::

:::quiz mc
HTTPサーバーで **Schul-CA** の証明書を選んではいけないのはなぜですか？
- [ ] CA証明書では暗号化ができないから
- [x] その証明書は `www.beaver-schule.de` ではなく `Schul-CA` という名前に対して発行されており、ブラウザが警告するから
- [ ] Schul-CA は秘密鍵を持っていないから
:::

:::quiz mc
Schul-CA を信頼して**いない**機器、たとえばゲストのスマートフォンでは、何が表示されるでしょうか？
- [ ] 鍵マーク付きで、ごく普通にページが表示される
- [x] 既知のCAまで信頼の連鎖をたどれないため、証明書の警告が表示される
- [ ] 接続が拒否されるため、何も表示されない
:::

:::evaluate
答えを確認
:::

:::note
公開Webサイトでは、すべてのブラウザにあらかじめインストールされているCAの証明書が必要です。2015年以降は、**Let's Encrypt** というCAが、こうした証明書を無料かつ自動で発行しています。これが、現在ほとんどすべてのWebサイトが HTTPS を使っている大きな理由の一つです。
:::

:::tip ポイント
**HTTPS** を使うには、Webサーバーに**秘密鍵付きのサーバー証明書**(名前がアドレスと一致するもの)が必要で、**ポート443**で待ち受けている必要があります。クライアントは、証明書を発行した **CA** を知っている場合にだけ、そのサイトを信頼します。
:::
