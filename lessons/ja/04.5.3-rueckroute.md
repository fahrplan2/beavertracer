# トラブルシューティング: 戻りのルート

:::sim
url=/sims/lesson-4.5.3.btsim
:::

先ほどと同じ構成です。会社A — Router A — 中間ネットワーク — Router B — 会社B。管理者は **Router A** に、会社Bへのルート（`172.16.0.0/24`、`10.0.0.2` 経由）を登録しました。それでもAnnaは「Claraから応答がない」と報告しています。

原因を見つけて修正しましょう。

<details>
<summary>ヒント1: Annaのpingはそもそも届いている?</summary>

AnnaからClaraにpingを送り、**Clara** のトレースを開きましょう。pingはClaraに届いているでしょうか。そして、Claraは応答しているでしょうか。
</details>

<details>
<summary>ヒント2: tracerouteはどこまで進む?</summary>

Annaで `traceroute 172.16.0.10` を入力しましょう。どのルーターまでは応答が返ってくるでしょうか。そして、ClaraからAnnaへの応答を転送しなければならないのはどのルーターでしょうか。
</details>

<details>
<summary>ヒント3: どのルーターがどのネットワークを知っている?</summary>

**Router B** のルーティングテーブルを見てみましょう。`192.168.0.0/24` 宛てのパケットをどこへ送ればよいか、知っているでしょうか。
</details>

:::task
title: 接続は修復できた?
Router Bが会社Aへの経路を知っていて、AnnaがClaraに到達できるかを確認します。そのためには、シミュレーションを実行モードで動かしておく必要があります。
check: hasRoute(5, "192.168.0.0/24")
check: pingOk(9, 11)
:::

## 何が起きていたのか

:::quiz multi
トラブルシューティングで、何を観察しましたか?
- [x] AnnaのpingはClaraに届き、Claraは応答した
- [x] Router Bが会社Aを知らなかったため、応答はRouter Bで止まってしまった
- [ ] Router AがAnnaのpingを破棄した
- [x] 行きの経路は機能していたのに、`traceroute` はRouter Aの先で `*` しか表示しなかった
:::

:::evaluate
回答を確認
:::

:::tip ポイント
どの通信にも**行きの経路と戻りの経路**が必要です。経路上のすべてのルーターが、宛先のネットワークと送信元のネットワークという*両方*のネットワークを知っていなければなりません。**戻りのルート**の欠落は、ルーティングで最もよくある障害の一つです。注意: `traceroute` が示すのは、どこから先で応答が返ってこなくなるかだけです。原因が戻りの経路にある場合もあります。
:::
