# トランスポート層には何が求められるのか?

:::sim
url=/sims/lesson-5.1.btsim
:::

**Server** では2つのサービスが同時に動いています。**Webサーバー**と、受け取ったメッセージをすぐに送り返す小さな**エコーサービス**です。2つの実験を通して、IPだけでは何ができないのかを調べてみましょう。

## 実験1: 2つのプログラムを同時に使う

1. :fa-play: **実行**モードに切り替えて、**Client-PC** をクリックします。
2. :fa-globe: **ブラウザ**を開いて `http://192.168.0.20/` にアクセスします。
3. ウィンドウ上部の **Zurück** をクリックして、**シンプル TCP クライアント**を開きます。**Host** に `192.168.0.20`、**Port** に `5000` を入力して、**接続**をクリックします。
4. :fa-magnifying-glass: **トレース**モードに切り替えて、**+** で **Client-PC** のポート `eth0` のトレースを開きます。

ブラウザのパケット(例: `GET /`)とTCPクライアントのパケットをそれぞれクリックして、どちらも **Internet Protocol Version 4** を展開してみましょう。

:::quiz mc
ブラウザとTCPクライアントのパケットには、どのIPアドレスが入っていますか?
- [x] どちらも同じ: `192.168.0.10` から `192.168.0.20`
- [ ] ブラウザはTCPクライアントとは別の宛先IPアドレスを使っている
- [ ] TCPクライアントのパケットにはIPアドレスがない
:::

:::quiz mc
では、パケットがWebサーバー宛てなのかエコーサービス宛てなのかをサーバーが知るのに、宛先IPアドレスだけで足りるでしょうか?
- [ ] 足りる
- [x] 足りない — どちらのパケットも宛先IPアドレスが同じだから
:::

2つの接続を区別するために、何か別のものが必要です。`[SYN]` の付いたパケットの **Info** 列を見てみましょう。これは、それぞれの接続の最初のパケットです。

:::quiz short
**ブラウザ**の矢印 `→` の後ろにある数字は何ですか?
= 80
:::

:::quiz short
**TCPクライアント**ではどうですか?
= 5000
:::

:::evaluate
答えを確認
:::

これらの数字、つまり**ポート**については、5.3節で詳しく学びます。ここではまず、次のことを押さえておけば十分です。トランスポート層があって初めて、複数のプログラムが*1つの* IPアドレスを使って同時に通信でき、どのパケットも正しいプログラムに届きます。これを**多重化**と呼びます。

## 実験2: パケットが失われたとき

1. :fa-play: **実行**モードに切り替えて、Client-PC と Server の間の**ケーブル**をクリックします。
2. **Verbindung** ウィンドウで、**Konfigurierter Paketverlust** を `25%` に設定します。
3. **Client-PC** で :fa-terminal: **ターミナル**を開いて、pingを6回送ります。
   ```
   $ ping -c 6 192.168.0.20
   ```
   30秒ほどかかります。統計が表示されるまで待ちましょう。

:::quiz mc
何が起こりますか?
- [ ] 6回のpingすべてに応答がある
- [x] 応答のないpingがいくつかある — しかも、誰もそれを再送しない
- [ ] 失われたpingは、届くまで自動的に繰り返される
:::

:::evaluate
答えを確認
:::

pingの場合は問題ありません。そもそも、何かが失われていないかを確かめるためのものだからです。しかし、Webページやメール、ダウンロードで一部が欠けてしまうと致命的です。ファイルが壊れてしまいます。

## トランスポート層の4つの役割

| 役割 | その意味 |
|---|---|
| **多重化** | 複数のプログラムや接続が1つのIPアドレスを共有し、どのパケットも正しいプログラムに届く。 |
| **接続確立** | データを流す前に、双方が互いに通信することを取り決める。 |
| **信頼性のある転送** | 受信者が届いたものを確認応答する。欠けたものは再送され、順序が復元される。 |
| **接続切断** | 最後に、双方が接続を順序正しく終了する。 |

:::tip ポイント
**トランスポート層**(第4層)は、データが正しい**プログラム**に届くようにします(**多重化**)。さらに、プロトコル **TCP** は、データが**欠けることなく**、**正しい順序**で届くようにします。そのために、接続確立、確認応答、再送、接続切断を行います。
:::

:::quiz match
1台のPCでブラウザ、メールソフト、メッセンジャーが同時に動いている。 -> 多重化
データを流す前に、双方が相手の準備ができていることを確認する。 -> 接続確立
ファイルの一部が届かず、もう一度送られる。 -> 信頼性のある転送
ダウンロードが終わったあと、双方が接続を解放する。 -> 接続切断
:::
