HTTP、DNS、電子メール、DHCP は、日常生活で絶えず出会うプロトコルです。このほかにも多くのプロトコルがあります。ここでは、特に重要なものを簡単に紹介します。そのうちいくつかは BeaverTracer の中で自分で試すことができ、:fa-flask: で示されています。

| プロトコル | ポート | トランスポート | 用途 |
|---|---|---|---|
| **SSH** | 22 | TCP | 暗号化されたリモート保守 |
| **Telnet** :fa-flask: | 23 | TCP | 暗号化されないリモート保守（旧式） |
| **FTP** / **SFTP** | 21 / 22 | TCP | ファイル転送 |
| **NTP** :fa-flask: | 123 | UDP | 時刻の同期 |
| **IRC** :fa-flask: | 6667 | TCP | テキストチャット |
| **SIP** / **RTP** :fa-flask: | 5060 / 可変 | UDP | インターネット電話 |
| **SNMP** | 161 | UDP | ネットワーク機器の監視 |
| **SMB** | 445 | TCP | ネットワーク上のファイル共有 |
| **MQTT** | 1883 | TCP | IoT（モノのインターネット）でのメッセージ交換 |
| **QUIC** / **HTTP/3** | 443 | UDP | より高速で暗号化されたウェブ |

## SSH と Telnet

**SSH**（*Secure Shell*）を使うと、まるで目の前に座っているかのように、別のコンピューターをコマンドラインから操作できます。管理者はこの方法でサーバーやルーターを保守します。パスワードも含め、すべてが暗号化されて送信されます。その前身である **Telnet** は同じことを平文で行うため、今日では安全でないとされています。ただし、テキストベースのプロトコルをテストするためのツールとしては、セクション 6.1.2 で見たように今でも役に立ちます。

## FTP と SFTP

**File Transfer Protocol**（**FTP**）は最も古いインターネットプロトコルの一つで、ファイルのアップロードとダウンロードに使われます。パスワードやデータを暗号化せずに送信するため、使われることはだんだん少なくなっています。多くの場合、SSH 接続を通じてファイルを転送する **SFTP** に置き換えられています。

## NTP

**Network Time Protocol**（**NTP**）は、コンピューターの時計を時刻サーバーと同期させます。精度はミリ秒単位です。これは思う以上に重要です。証明書、ログファイル、認証方式は、すべての機器が同じ時刻を持っている場合にのみ正しく動作するからです。BeaverTracer には、そのためのアプリ **NTP-Server** と **Uhrzeit**、そしてコマンド `ntpdate` があります。

## IRC

**Internet Relay Chat**（**IRC**）は 1988 年に登場したチャットプロトコルです。サーバーに接続し、`#schule` のようなチャンネルに入って、チャンネル内の全員にテキストメッセージを書き込みます。HTTP や SMTP と同様に、IRC は純粋なテキストプロトコルなので、トレースですべてのメッセージを読むことができます。現在のメッセンジャーも基本原理は同じですが、暗号化されています。BeaverTracer では、アプリ **IRC-Server** と **IRC** を使います。

## SIP と RTP

**インターネット電話**（*Voice over IP*）では、2 つのプロトコルが連携して動作します。**SIP**（*Session Initiation Protocol*）は通話の確立と終了を担当し、相手の電話を鳴らします。音声そのものは、多数の小さな **RTP** パケットとして UDP で送られます。電話ではミリ秒単位の遅れが重要になるからです（セクション 5.5.2 を参照）。BeaverTracer では、アプリ **SIP-Server** と **Softphone** を使います。

## SNMP

**Simple Network Management Protocol**（**SNMP**）では、監視プログラムがルーター、スイッチ、プリンターに問い合わせを行います。ポートの負荷はどのくらいか、機器が故障していないか、トナーが空になっていないか、といったことです。こうして管理者は、大規模なネットワークでも状況を把握し続けられます。

## SMB

**Server Message Block** プロトコル（**SMB**）は、Windows ネットワークでおなじみのネットワークドライブや共有フォルダーの裏側で動いています。たとえば学校の共有ドライブがそうです。ネットワーク上のプリンターも、多くの場合 SMB で呼び出されます。

## MQTT

**MQTT** は、**IoT（モノのインターネット）** 向けの非常に軽量なプロトコルです。センサー、スマートサーモスタット、工場の機械などが測定値を中央の仲介役（*ブローカー*）に送り、その情報に関心のあるプログラムはブローカーから受け取ります。処理能力の低い機器や不安定な接続を想定して設計されています。

## QUIC と HTTP/3

**QUIC** は Google が開発した比較的新しいトランスポートプロトコルで、現在では多くの大手ウェブサイトが利用しています。**UDP** の上に構築され、信頼性と暗号化を自前で備えています。そのため、TCP と TLS を使う場合よりも早く接続が確立します。**HTTP/3** は、QUIC の上で動作するバージョンの HTTP です。

:::quiz match
SSH -> 別のコンピューターを暗号化してコマンドラインから操作する
NTP -> 時刻サーバーと時刻を同期する
SIP -> インターネット経由で通話を確立する
SNMP -> ルーター、スイッチ、プリンターを監視する
MQTT -> IoT のセンサーの測定値を配信する
:::
