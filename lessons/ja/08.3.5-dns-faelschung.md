# 攻撃: DNS偽装

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna は **Client-PC** から **Biberbank** のオンラインバンキングを開こうとしています。彼女が知らないのは、誰かが **DNS-Server** に侵入し、エントリを書き換えてしまったことです。

ワークスペースには、本物のWebサーバー **www.biberbank.de** と、**攻撃者** のコンピューターが表示されています。攻撃者のコンピューターでは、銀行のWebサイトのコピーが動いています。

## パート1: 暗号化なし

:fa-play: **実行**モードに切り替えて、**Client-PC** の :fa-globe: **ブラウザ** で `http://www.biberbank.de/` を開きましょう。

:::quiz mc
何が表示されますか？
- [x] 警告なしで、Biberbank のログインページが表示される
- [ ] サイトが偽物であるという警告が表示される
- [ ] エラーメッセージが表示される
:::

:::evaluate
答えを確認
:::

すべて普通に見えます。しかし、ブラウザは実際にどのサーバーと通信しているのでしょうか。Client-PC で :fa-terminal: **ターミナル** を開きましょう。

```
$ nslookup www.biberbank.de
```

:::quiz short
DNS-Server は `www.biberbank.de` に対してどのIPアドレスを返しますか？
= 192.168.0.66
:::

:::quiz mc
このアドレスは誰のものですか？（編集モードでデバイスをクリックするか、:fa-gear: **IP設定** を見てみましょう。）
- [ ] Biberbank の本物のWebサーバー
- [x] 攻撃者
- [ ] DNS-Server
:::

:::evaluate
答えを確認
:::

もし Anna がここで口座番号とPINを入力していたら、それらはそのまま攻撃者に渡っていたでしょう。**HTTP** では、詐欺に気づく**可能性はありません**。アドレスバーには正しい名前が表示され、ページも本物のように見えるからです。

## パート2: HTTPS を使う

次は `https://www.biberbank.de/` を開いてみましょう。

:::quiz mc
何が起こりますか？
- [ ] 偽のページが鍵マーク付きで表示される
- [x] ブラウザが警告を出す。証明書が別の名前に対して発行されている
- [ ] Biberbank の本物のページが表示される
:::

:::quiz short
攻撃者の証明書は、どの名前に対して発行されていますか（`CN=` は除く）？
= www.biber-gewinnspiel.de
:::

:::evaluate
答えを確認
:::

攻撃者は、信頼できる CA が発行した**本物の**証明書さえ持っています。ただし、それは自分自身のドメイン `www.biber-gewinnspiel.de` に対するものです。`www.biberbank.de` の証明書は、そのドメインが攻撃者のものではないため、どの CA からも発行されません。また、Biberbank の**秘密鍵**がなければ、本物の証明書を使うこともできません。ハンドシェイクでは、それを使って Server Key Exchange に署名しなければならないからです。

:::quiz multi
HTTPS はここで何から守ってくれて、何から守ってくれないでしょうか？
- [x] HTTPS は、サーバーが本物ではないことを明らかにする
- [ ] HTTPS は、DNS-Server が偽装されるのを防ぐ
- [x] HTTPS は、ユーザーが警告を真剣に受け止めた場合にのみ役立つ
- [ ] HTTPS を使えば、偽のページにはまったくアクセスできない
:::

:::evaluate
答えを確認
:::

## パート3: DNS-Server を修復する

**DNS-Server** を開き、`www.biberbank.de` のエントリを修正しましょう。正しいアドレスは、Webサーバー **www.biberbank.de** の :fa-gear: **IP設定** で確認できます。**保存** をクリックするのを忘れないでください。

:::note
Client-PC は、問い合わせのたびに新しく尋ねなくて済むように、DNS の応答をしばらく記憶しています（**DNSキャッシュ**）。その期間は **TTL** 列（*Time to Live*）に秒単位で書かれています。修正した直後に `nslookup` がまだ古いアドレスを返す場合は、TTL が過ぎるまで待ってから、もう一度試しましょう。
:::

:::task
title: Biberbank は再び本物に？
Client-PC が www.biberbank.de を正しいアドレスに名前解決でき、HTTPS で警告なしにページを取得できるかを確認します。
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
現実の世界では、攻撃者が DNS サーバーそのものを偽装することはまれです。もっと多いのは、公衆Wi-Fiで偽の応答を差し込んだり、ホームルーターの設定を書き換えたり、`www.biberbank-login.de` のようにそっくりなアドレスで誘い込んだりする手口です（**フィッシング**）。似た響きの名前に対しては HTTPS も役に立ちません。攻撃者はその名前に対して有効な証明書を取得できるからです。だから、アドレスはよく読みましょう！
:::

:::tip ポイント
**DNS偽装** では、DNS-Server がある名前に対して攻撃者のアドレスを返します。**HTTP** ではそれに気づけません。**HTTPS** では、攻撃者の証明書がアクセスした名前と一致しないため、ブラウザが**警告**を出します。他人のドメインの証明書はどの CA も発行しませんし、攻撃者は本物のサーバーの秘密鍵を持っていないからです。
:::
