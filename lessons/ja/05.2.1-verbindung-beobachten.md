# 最初から最後までの1つの接続

:::sim
url=/sims/lesson-5.1.btsim
:::

**Server** ではポート `5000` でエコーサービスが動いています。受け取ったメッセージはすぐにそのまま送り返されます。**シンプル TCP クライアント**を使うと、接続を一段階ずつ操作できます。それぞれのボタンが1つのフェーズに対応しています。

## 実験

1. :fa-play: **実行**モードに切り替えて、**Client-PC** をクリックし、**シンプル TCP クライアント**を開きます。
2. **Host** に `192.168.0.20`、**Port** に `5000` を入力します。
3. **接続**をクリックします。
4. メッセージ欄に `Hello World` と入力して、**送信**をクリックします。すぐにチャットウィンドウにサーバーからのエコーが表示されます。
5. **切断**をクリックします。
6. :fa-magnifying-glass: **トレース**モードに切り替えて、**+** で **Client-PC** のポート `eth0` のトレースを開きます。

:::note
最初の2つの ARP パケットは、第1章ですでに学びました。TCP パケットの **Info** 列には、まず `49152 → 5000`（どのポートからどのポートへか）が表示され、続いて角括弧の中に**フラグ**、その後に `Seq=`、`Ack=`、`Len=` などの数値が表示されます。数値については 5.2.3 ページ以降で扱います。ここではフラグと `Len` に注目しましょう。
:::

## フェーズ2: 送信

`Len` は、パケットが運ぶペイロード(データ)が何バイトかを表します。

:::quiz short
あなたのメッセージを運ぶパケットは何バイトですか(`Len`)?
= 13
:::

:::note
`Hello World` は11文字しかありません。しかし TCP クライアントは行末(2バイト、`\r\n`)を付け加えます。SMTP や HTTP など、多くのインターネットプロトコルがこの形式を前提としているためです。
:::

:::quiz mc
サーバーは、あなたのメッセージの直後、エコーよりも前に何を送り返しますか?
- [x] `[ACK]` と `Len=0` のパケット。データを含まない確認応答
- [ ] 何も送り返さない
- [ ] 新しい `[SYN]`
:::

## 4つの役割はどこにある?

5.1 節で学んだ4つの役割が、トレースのどこにあるかを対応付けましょう。

:::quiz match
接続確立 -> [SYN]、[SYN, ACK]、[ACK] の3つのパケット
信頼性のある転送 -> 受信を確認する、[ACK] と Len=0 のパケット
接続の終了 -> FIN 付きのパケットとその確認応答
多重化 -> 角括弧の前にあるポート番号 49152 → 5000
:::

:::
