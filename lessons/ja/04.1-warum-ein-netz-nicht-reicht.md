# ネットワークが1つでは足りない理由

:::sim
url=/sims/lesson-4.1.btsim
:::

ワークスペースには、小さな会社のネットワークが2つあります。**Firma A** には Anna (`192.168.0.10`) と Ben (`192.168.0.11`)、**Firma B** には Clara (`172.16.0.10`) と David (`172.16.0.11`) がいます。2台のスイッチは、ケーブルで直接つながっています。

## 同じネットワーク内でのping

1. :fa-play: **実行**モードに切り替え、**Anna** の :fa-terminal: **ターミナル**を開いて Ben にpingを送ります。
   ```
   $ ping 192.168.0.11
   ```
2. :fa-magnifying-glass: **トレース**モードに切り替え、**Anna** のトレースを開いて `Echo (ping) request` をクリックします。
3. プロトコルツリーで **Internet Protocol Version 4** の行を展開します。これはパケットのIP部分で、この章で扱う部分です。

:::quiz match
Source Address -> 送信元のIPアドレス
Destination Address -> 受信者のIPアドレス
Time to Live -> パケットがあと何台のルーターを通過できるか
Protocol -> パケットの中身がどのプロトコルか（ここではICMP、つまりping）
:::

:::evaluate
対応を確認
:::

## 別のネットワークへのping

:fa-play: **実行**モードに戻り、**Anna** から Clara にpingを送ります（`ping 172.16.0.10`）。そのあと、Anna のトレースをもう一度見てみましょう。

:::quiz mc
何が起こるでしょうか？
- [ ] pingは成功する。スイッチはつながっているから
- [x] pingは届かず、Anna のトレースには Clara 宛てのパケットが1つも現れない。ARPリクエストすらない
- [ ] Anna はARPリクエストを送るが、Clara が応答しない
:::

:::quiz mc
なぜ Anna は何も送信しないのでしょうか？
- [ ] スイッチ間のケーブルが壊れている
- [ ] Clara の電源が切れている
- [x] Anna は Clara のIPアドレスから、Clara が別のネットワークにいると判断できるが、そこへ向かう経路を知らない
:::

:::evaluate
回答を確認
:::

## 背景にある仕組み

IPアドレスは、郵便の住所に似た働きをします。一方の部分はデバイスがどの**ネットワーク**にあるかを示し（通りにあたる）、もう一方の部分はそのネットワークの中のどの**デバイス**かを示します（番地にあたる）。Anna はネットワーク `192.168.0…` に、Clara はネットワーク `172.16.0…` にいます。つまり、2つの異なる「通り」にいるわけです。

PCは、*同じ*ネットワーク内のデバイスにはパケットを直接送ります（これまで学んだとおり、ARPとスイッチを使います）。*別の*ネットワークに送るには、ネットワーク同士をつないでパケットを中継する装置、つまり**ルーター**が必要です。ここにはまだルーターがありません。だから、スイッチ間のケーブルがあっても役に立たないのです。

:::tip ポイント
第3層の**インターネットプロトコル**（**IP**）は、異なるネットワークの間でもパケットが届くようにします。**IPアドレス**は**ネットワーク部**（どのネットワークか）と**ホスト部**（どのデバイスか）から成ります。同じネットワーク内のデバイス同士は直接通信できますが、別のネットワークと通信するには**ルーター**が必要です。
:::

ここで2つの疑問が生まれます。次の節では、これらを扱います。PCは、アドレスの*どこで*ネットワーク部が終わるのかをどうやって知るのでしょうか。そして、ルーターはどのように動くのでしょうか。
