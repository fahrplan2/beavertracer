# メールを暗号化して送信する

:::sim
url=/sims/lesson-8.4.btsim
:::

セクション 6.3.2 で、SMTP や POP3 では送信元、受信者、本文、さらにはパスワードまでもが、読み取れる状態で回線上を流れることを見ました。TLS を使えば、HTTP と同じようにこれらも保護できます。メールには次の2つの方法があります。

| | **暗黙的 TLS** | **STARTTLS** |
|---|---|---|
| 流れ | 接続は最初の1秒から暗号化されている。 | 接続は暗号化なしで始まる。クライアントが `STARTTLS` コマンドを送り、その後に暗号化される。 |
| ポート | 専用のポート: **SMTPS 465**、**POP3S 995**、**IMAPS 993** | 通常のポート(例: SMTP 25 または 587) |

SMTPS、POP3S、IMAPS の「S」は、HTTPS と同じく *Secure* を表します。

## 変更前: すべて読み取れる

**Mailserver Schule** にはすでに TLS が設定されています。このサーバーは `mail.beaver-schule.de` 用の証明書を持っていて、さらにポート 465、995、993 でも待ち受けています。ところが、Anna のメールプログラムはまだ暗号化されていないポート 25 と 110 を使っています。

## 暗号化されたポートへの切り替え

Anna のメールプログラムで **Einstellungen**(設定)を開きます。

- **Eingehend(受信):** ポート `995` にして、**TLS** にチェックを入れる
- **Ausgehend (SMTP)(送信):** ポート `465` にして、暗号化を **Implizites TLS** にする

設定を保存し、もう一度メールを送ってから、もう一度取得します。トレースを見てみましょう(フィルター `tls`)。

:::tip 試してみよう
送信をポート `25` にして、暗号化を **STARTTLS** に切り替え、メールを送ってみましょう。トレースでは、接続がまず暗号化なしで始まる様子が見えます。サーバーは `EHLO` への応答で `STARTTLS` を提示し、`STARTTLS` コマンドの後にはじめて TLS ハンドシェイクが続きます。

## トランスポート暗号化が守らないもの

TLS が暗号化するのは、2台のコンピューター間の**経路**だけです。つまり Anna からメールサーバーまで、そして両方のメールサーバーが対応していればメールサーバー間も暗号化されます。しかし**メールサーバー上**では、メールは平文のまま置かれています。メールサーバーにアクセスできる人は、そこにあるすべてのメールを読めてしまいます。

受信者だけがメールを読めるようにしたい場合は、**エンドツーエンド**で暗号化する必要があります。送信元が受信者の公開鍵で暗号化し、受信者だけがそれを復号します。メールにはそのための方式として **S/MIME** と **OpenPGP** があります。Signal や WhatsApp のようなメッセンジャーでは、これが自動的に行われます。

:::tip ポイント
メールは **TLS** で暗号化して送信されます。専用ポートでの**暗黙的 TLS**(**SMTPS 465**、**POP3S 995**、**IMAPS 993**)か、通常のポートでの **STARTTLS** のどちらかです。これは**トランスポート暗号化**で、経路は守りますが、サーバー上のメールは守りません。そのためには**エンドツーエンド暗号化**が必要です。
:::
