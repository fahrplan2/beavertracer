# まとめと今後の展望

## 各構成要素の概要

| 構成要素 | 保護目標 | 例 |
|---|---|---|
| **共通鍵暗号方式** | 機密性 | AES が HTTPS 接続のデータを暗号化する |
| **公開鍵暗号方式** | 機密性、鍵交換 | Diffie-Hellman、RSA |
| **ハッシュ値** | 完全性 | ダウンロードファイルの SHA-256 チェックサム |
| **デジタル署名** | 真正性、完全性 | サーバーが自分の Diffie-Hellman の値に署名する |
| **証明書** | 真正性 | 「この鍵は `www.biberbank.de` のものである」ことを保証する |

## 同じ原理がさまざまな場面で使われている

HTTPS で学んだことは、他の多くの技術にも使われています。

- **無線LAN(WPA2/WPA3):** 3.3.2 章では、電波の届く範囲にあるどの機器でも通信内容を読み取ることができました。WPA2 や WPA3 では、すべての無線フレームが AES で暗号化されます。さらに WPA3 は、盗聴者が無線LANのパスワードを知っていても過去に記録した通信を復号できないように鍵をネゴシエーションします。
- **SSH:** 6.6 章で学んだ、暗号化されたリモートメンテナンスです。証明書の代わりに、クライアントは最初の接続時にサーバー鍵の**フィンガープリント**を記憶し、後で変わった場合には警告を出します。
- **VPN:** インターネットを通る暗号化されたトンネルで、たとえば学校や会社のネットワークへの接続に使われます。これについては 10 章で扱います。
- **メッセンジャー:** Signal、WhatsApp などは**エンドツーエンド**で暗号化します。サービスの運営者でさえメッセージを読むことはできません。

:::note
大規模な**量子コンピューター**が実現すれば、いつの日か大きな数の素因数分解を解読でき、それによって RSA や Diffie-Hellman が破られる可能性があります。そのため、新しい**耐量子**方式がすでに導入され始めています。長い鍵を使った AES などの共通鍵方式は、引き続き安全と考えられています。
:::

## 理解度チェック

:::quiz mc

- [ ] RSA。最も安全だから
- [x] AES のような共通鍵方式と、ネゴシエーションで決めたセッション鍵
- [ ] サーバーの秘密鍵
:::

:::quiz mc
`https://www.biberbank.de/` にアクセスしたところ、ブラウザが「証明書は `www.gewinn-biber.de` に対して発行されています」と表示しました。あなたはどうしますか?
- [ ] 「このまま続行」をクリックする。接続は暗号化されているから
- [x] 中止する。ブラウザが銀行と通信していない可能性がある
- [ ] `http://` でアクセスする。そうすれば警告は出ない
:::

:::quiz multi
正しい記述はどれですか?
- [x] ハッシュ値は、データがわずかに変わっただけでも完全に変わる
- [x] 署名は秘密鍵で作成され、公開鍵で検証される
- [x] ルートCAはブラウザやOSにあらかじめインストールされている
- [ ] HTTPS では、盗聴者はサーバーの IP アドレスすら見ることができない
- [ ] SMTPS はメールサーバー上でもメールを暗号化する
:::
