# トラブルシューティング: 新しいルールにしてから何も通らない

:::sim
url=/sims/lesson-9.4.btsim
:::

Beaver-Schule の管理者であるBiberさん(Herr Biber)は、昨日ファイアウォールをホワイトリスト方式に切り替えました。それ以来、みんなが文句を言っています。**学校のWebサイト**が外部からアクセスできなくなり、**インターネットからのメールが1通も届かなく**なりました。ただし、SSHは希望どおり外部からブロックされています。

**ファイアウォール**のルールにある誤りを見つけて、修正しましょう。

<details>
<summary>ヒント1: パケットはそもそも正しいルールに届いている?</summary>

**Internet-PC** から `nmap -p 22,25,80 198.51.100.10` を実行し、そのあとファイアウォールの **Treffer** 列を見てみましょう。本来ならパケットが当てはまるはずなのに 0 のままのルールは、別のルールに隠されているか、そもそも一致しないルールです。
</details>

<details>
<summary>ヒント2: よく見比べる</summary>

ルールの数字を1つずつ、第5章で学んだポート番号と照らし合わせましょう。HTTP はどのポートで、SMTP はどのポートでしょうか? 順番にも注意しましょう。最初に一致したルールが適用されます。
</details>

:::task
title: WebとメールはもうOK?
学校サーバーのWebとメールがインターネットから到達でき、SSHはブロックされたままであることを確認しましょう。
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## 何が起きていたのか

:::quiz multi
ルールにはどのような誤りがあったでしょうか?
- [x] Webのルールがポート80ではなく8080を許可していた
- [x] メールのルールが「すべて破棄」のルールより下にあり、一度も評価されなかった
- [ ] ファイアウォールがステートフルになっていた
- [ ] メールにポート25を使うのは間違いである
:::

:::evaluate
回答を確認
:::

:::tip ポイント
ファイアウォールのルールでよくある誤りは、ポート番号の**数字の入れ違い**、**方向**の間違い、そして一般的なルールが特殊なルールを隠してしまう**順番**の誤りです。トラブルシューティングでは、外部からの**ポートスキャン**、ファイアウォールの**ログ**、ルールの**ヒットカウンター**が役に立ちます。
:::
