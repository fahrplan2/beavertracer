# Ping を実行してトレースで確認する

:::sim
url=/sims/lesson-1.2.3.btsim
:::

2台のPCには、それぞれ `192.168.0.10` と `192.168.0.11` のアドレスが設定されました。さっそく最初のテストをしてみましょう。**Ping** を使うと、PCは別のPCに小さなリクエストを送り、その返事を待ちます。

## Ping を実行する

:fa-play: **実行**モードに切り替えます。**Computer 1** で :fa-terminal: **ターミナル**を開き、次のように入力します。

```
$ ping 192.168.0.11
```

相手のPCが応答すると、送信したパケットごとに応答時間付きの行が表示されます。これが最初の Ping 成功です。

:::tip ポイント
**Ping** は、別の機器に到達できるかどうかを確認します。リクエストを送り、返事が届くまでの時間を測ります。
:::

## トレースで確認する

次に :fa-magnifying-glass: **トレース**モードに切り替えます。最初はまだ何も表示されていません。左上の **Traces:** の横にある **+** をクリックし、**Computer 1** を選んで、続けてそのポート `eth0` を選びます。

これで、このポートを通過したすべてのパケットの一覧が表示されます。先ほどの Ping も含まれています。パケットのひとつをクリックすると、その下に詳しい構造が層ごとに表示されます。

:::tip ポイント
ネットワークではデータを一度にまとめて送るのではなく、**パケット**という小さな単位に分けて送ります。各パケットには、送信元、受信者、そしてデータの一部が含まれています。
:::

:::tip
Ping は必ず、リクエスト（Echo Request）と返事（Echo Reply）で成り立っています。**Info** 列で、両方向のパケットを見つけられますか？
:::

## 最初の Ping の前に誰が尋ねている？

一覧のいちばん上、最初の Ping よりも前に、プロトコルが **ARP** のパケットが2つあります。その **Info** 列を読んでみましょう。たとえば次のように書かれています。

```
Who has 192.168.0.11? Tell 192.168.0.10
192.168.0.11 is at aa:fd:9f:a5:d2:89
```

Computer 1 は相手のPCの IP アドレスは知っていましたが、その**ハードウェアアドレス**（*MACアドレス*。ネットワークカードにはそれぞれ固有のものがあります）はまだ知りませんでした。これがないと何も送れません。そこでまず、ネットワークに向かって呼びかけます。*「192.168.0.11 を持っているのは誰？ 192.168.0.10 に教えて！」* 探されたPCは、自分のハードウェアアドレスを返します。これがまさに **ARP** の役割です。

その後、Computer 1 は受け取った返事を記憶します。そのため、ARP は最初の Ping の前にだけ現れ、毎回の Ping の前には現れません。

:::tip ポイント
**ARP** は、既知の IP アドレスに対応するハードウェアアドレス（**MACアドレス**）を見つけます。PCはネットワーク上の全員に尋ね、探されている機器だけが返事をします。
:::

:::quiz mc
Computer 1 は最初の ARP パケットを誰に送っていますか？ **Ziel** 列を見てみましょう。
- [ ] 相手のPCだけ
- [x] ネットワーク上のすべての機器（ブロードキャスト）
- [ ] インターネット上のサーバー
:::

:::quiz mc

- [ ] 相手のPCの IP アドレス
- [x] 相手のPCのハードウェアアドレス（MACアドレス）
- [ ] 相手のPCの名前
:::
