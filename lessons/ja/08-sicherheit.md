# セキュリティ: 暗号化と証明書

:::goal
**学習目標:** 機密性・完全性・真正性という3つの保護目標を説明できる。共通鍵暗号と公開鍵暗号を区別できる。ハッシュ値とデジタル署名を位置づけられる。証明書を読み、自分で発行できる。HTTPSを設定し、典型的な証明書の警告を読み解ける。
:::

これまでの章では、トレースを使ってほとんどすべての通信内容を読み取ることができました。

- **第3.3.2章:** Wi-Fiでは、電波の届く範囲にあるすべての機器が、すべての無線パケットを受信します。
- **第6.1.2章:** HTTPでは、リクエストもWebページも平文のままパケットに入っています。
- **第6.3.2章:** SMTPやPOP3では、ユーザー名とパスワードがほぼ平文のまま回線を流れます。`AUTH PLAIN` は単なるBase64です。

回線上や同じWi-Fi内で盗聴する人には、パスワード、成績、メッセージ、銀行情報が丸見えです。しかも、それだけではありません。パケットを**改ざん**したり、別の誰かに**なりすます**こともできます。

## 3つの保護目標

こうした脅威への対策として役立つのが暗号技術です。そこでは3つの**保護目標**を区別します。

| 保護目標 | 問い | 攻撃の例 |
|---|---|---|
| **機密性** | 正しい受信者だけがデータを読めるか? | 誰かがWi-Fiであなたのパスワードを盗み見る。 |
| **完全性** | データは変更されずに届いたか? | 誰かが振込の金額を書き換える。 |
| **真正性** | データは本当に名乗っている送信元から来たか? | 偽の銀行のWebページがあなたのPINを聞き出そうとする。 |

この章では、この3つの目標を達成するための道具と、それらが**HTTPS**(ブラウザに表示される鍵マーク)の中でどのように連携するかを学びます。

:::quiz match
誰かがWi-Fiであなたのパスワードを盗み見る -> 機密性
誰かが途中で振込の金額を書き換える -> 完全性
偽のWebページが銀行になりすます -> 真正性
:::
