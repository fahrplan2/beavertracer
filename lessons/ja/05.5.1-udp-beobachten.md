# UDPを観察する

:::sim
url=/sims/lesson-5.5.btsim
:::

今回は**Server**のポート `5000` で **UDP エコーサーバー**が動いています。ここでもケーブルに細工がしてあり、Client-PCからServerへの**2番目のデータグラム**が失われます。

## 実験

1. :fa-play: **実行**モードに切り替えて、**Client-PC**で :fa-terminal: **ターミナル**を開きます。
2. `nc` を使って、サーバーとのUDP「接続」を開始します(`-u` はUDPを表します):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. `eins`、`zwei`、`drei` を順番に入力し、そのつど **Enter** を押します。戻ってきた各行は、サーバーからのエコーです。
4. 数秒待ってから、:fa-magnifying-glass: **トレース**モードで **Client-PC** のトレースを開きます。

:::quiz mc
どのエコーが戻ってくるでしょうか?
- [ ] 3つすべて(`zwei` は少し遅れて)
- [x] `eins` と `drei` だけ — `zwei` は届かず、再送もされない
- [ ] 1つも戻ってこない
:::

:::quiz multi
TCPでは見かけたのに、UDPでは完全に欠けているパケットはどれでしょうか?
- [x] 接続確立(`SYN`)
- [x] 確認応答(`ACK`)
- [x] 接続終了(`FIN`)
- [ ] ポート番号を持つパケット
:::

:::evaluate
回答を確認
:::

UDPパケットのどれかをクリックして、**User Datagram Protocol** を展開してみましょう。TCPヘッダーと比べると、UDPヘッダーはとても小さいことがわかります。**Source Port**、**Destination Port**、**Length**(長さ)、**Checksum**(チェックサム)の4つで、合計わずか8バイトです。TCPヘッダーは最低でも20バイトあり、シーケンス番号、確認応答番号、フラグ、ウィンドウサイズを持っています。

:::quiz mc
5.1節の役割のうち、UDPがそれでも果たしているものはどれでしょうか?
- [x] 多重化 — ポートによって
- [ ] 接続確立
- [ ] 信頼性のある転送
:::

:::evaluate
回答を確認
:::

:::tip ポイント
**UDP** は**コネクションレス**です。接続確立も、確認応答も、再送も、順序制御もありません。提供するのは**ポート**(多重化)と**チェックサム**だけです。その代わり高速で軽量で、UDPヘッダーはわずか8バイトです。データグラムが失われた場合は、プログラム自身が対処する必要があります。あるいは、気にしないこともあります。
:::
