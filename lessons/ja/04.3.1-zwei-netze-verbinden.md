# 2つのネットワークを接続する

:::sim
url=/sims/lesson-4.3.1.btsim
:::

ルーターには2つのポートがあります。

| ポート | IPアドレス | ネットワーク |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

PCがルーターを使えるように、各PCには**ゲートウェイ**が設定されています。Anna と Ben は `192.168.0.1`、Clara と David は `172.16.0.1` です。ゲートウェイは :fa-gear: **IP設定**の**ゲートウェイ**欄で確認できます。

:::tip ポイント
**ゲートウェイ**(正確には*デフォルトゲートウェイ*)とは、**自分のネットワーク内**にあるルーターのIPアドレスのことです。PCは、宛先が別のネットワークにあるパケットをすべてゲートウェイに送ります。
:::

## ルーターはパケットをどう処理するか

ルーターは Anna からフレームを受け取り、IPパケットを取り出して**宛先IPアドレス**を調べます。それにより、Clara が `eth1` 側のネットワークにいることがわかります。そこでルーターは、パケットを**新しい**フレームに包み直します。送信元は自分自身のMACアドレス、宛先は Clara のMACアドレスにして、そちらへ送り出します。

| ルーターで次のものはどうなる? | |
|---|---|
| MACアドレス(レイヤー2)は? | **新しく**設定される。MACアドレスはそれぞれのネットワーク内でのみ有効 |
| IPアドレス(レイヤー3)は? | **そのまま**。Anna から Clara まで変わらない |
| Time to Live は? | **1 減る** |

:::tip ポイント
**ルーター**は**レイヤー3**で動作します。**宛先IPアドレス**をもとに、パケットを別のネットワークへ転送します。IPアドレスは経路全体を通して変わりませんが、MACアドレスはネットワークごとに新しく設定されます。ルーターは通過のたびに**Time to Live(TTL)**を1ずつ減らし、0になるとパケットは破棄されます。これにより、パケットが永遠にループし続けることはありません。
:::

:::note
第3.4章のブロードキャストストームを覚えていますか?Ethernetフレームには TTL がありませんが、IPパケットにはあります。
:::

## Anna は誰を知っている?ARPキャッシュ

第1.2.3章を覚えていますか?そこでは、ARP が*最初の* ping の前にしか現れませんでした。PCが応答を覚えていたからです。この覚え書きのことを**ARPキャッシュ**(*ARPテーブル*とも言います)と呼びます。問い合わせは **ARPリクエスト**、応答は **ARPリプライ**(または*ARPレスポンス*)と呼ばれます。

:fa-play: **実行**モードに切り替え、**Anna** の :fa-terminal: **ターミナル**を開いて、ARPキャッシュを表示しましょう。

```
$ arp
```

:::quiz mc
Anna のARPキャッシュには何が入っていますか?
- [x] ルーターのIPアドレス(`192.168.0.1`)とそのMACアドレスだけ
- [ ] Clara のIPアドレスと Clara のMACアドレス
- [ ] ルーターと Clara の両方のアドレス
:::

:::evaluate
答えを確認
:::

Anna は Clara のMACアドレスを必要としません。Firma B 宛てのものはすべてルーターに送るからです。Clara のMACアドレスを知っているのはルーターだけで、ルーターが自分の側でARPを使って自ら問い合わせたものです。

:::tip ポイント
機器は**ARPキャッシュ**に、どのMACアドレスがどのIPアドレスに対応するかを記憶します。そのため、パケットを送るたびにARPリクエストを送る必要はありません。内容は `arp` コマンドで表示できます。PCが知っているのは**自分の**ネットワーク内のMACアドレスだけです。別のネットワークにある宛先には、ルーターのMACアドレスを使います。
:::

:::note
実際のネットワークでは、ARPキャッシュのエントリは一定時間後に削除され、必要になったときに改めて問い合わせられます。たとえば、その間に機器のネットワークカードが交換された場合などに備えるためです。BeaverTracer では、シミュレーションが動いている間はエントリが保持されます。
:::
