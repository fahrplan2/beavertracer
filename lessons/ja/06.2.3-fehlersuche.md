# トラブルシューティング: 名前が機能しない

:::sim
url=/sims/lesson-6.2.3.btsim
:::

ある先生から報告がありました。「`www.beaver-schule.de` が私のところでは読み込まれません。でも `http://192.168.0.20` ならうまくいきます!」本来は次のように設定されているはずです。

| 項目 | 正しい設定 |
|---|---|
| Client-PC の DNSサーバー | `192.168.0.53` (DNS-Resolver) |
| Schul-DNS のエントリ | `www.beaver-schule.de` → `192.168.0.20` |

エラーを見つけて修正しましょう。

<details>
<summary>ヒント1: nslookup は何と言っている?</summary>

Client-PC で `nslookup www.beaver-schule.de` を入力しましょう。`nslookup` はどのサーバーに問い合わせたでしょうか。そして何が返ってきたでしょうか。(応答が返るまで数秒かかります。)
</details>

<details>
<summary>ヒント2: では次は?</summary>

応答が返ってきたら、そのアドレスを構成と見比べましょう。この名前はどこに登録されているでしょうか。
</details>

:::task
title: 名前解決は直った?
Client-PC が www.beaver-schule.de を正しいアドレスに解決できるかを確認します。そのためには、シミュレーションが実行モードで動作している必要があります。
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## 何が起きていたのか

:::quiz multi
正しい記述はどれですか?
- [x] Client-PC には DNSサーバーとして `192.168.0.35` が登録されていた。そこでは誰も応答しない
- [x] Schul-DNS では、`www.beaver-schule.de` が `192.168.0.20` ではなく `192.168.0.21` を指していた
- [ ] Webサーバーの電源が切れていた
- [ ] ルートサーバーがドメイン `.de` を知らなかった
:::

:::evaluate
回答を確認
:::

:::tip ポイント
接続が **IPアドレス**ではうまくいくのに**名前**ではうまくいかない場合、問題は **DNS** にあります。まず**登録されているDNSサーバー**(そもそも応答するか?)を確認し、次に**エントリ**そのもの(アドレスは正しいか?)を確認しましょう。`nslookup` なら両方わかります。どのサーバーに問い合わせたか、そしてそのサーバーが何を返したかです。
:::
