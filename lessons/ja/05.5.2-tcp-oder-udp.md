# TCP と UDP、どちらを使う?

| | TCP | UDP |
|---|---|---|
| 接続 | 3ウェイハンドシェイクで確立し、順序立てて終了する | なし — 各データグラムは独立している |
| 確認応答 | あり(`ACK`) | なし |
| 失われたデータ | 再送される | 失われたまま |
| 順序 | 復元される | 保証されない |
| ヘッダー | 最低20バイト | 8バイト |
| 速度 | やや遅く、パケット数が多い | 高速で、オーバーヘッドが少ない |

シンプルなほうが良いのはどんなときでしょうか?

- **リアルタイム通信:** ビデオ通話、インターネット電話、オンラインゲームでは1ミリ秒が重要です。1秒遅れて届く失われた音声の断片は、もはや誰の役にも立ちません。遅延するよりも、一瞬のノイズが入るほうがましです。
- **短い問い合わせ:** **DNS** の問い合わせ(「`www.beispiel.de` の IP アドレスは何ですか?」)は1つのデータグラムに収まり、応答も同じです。接続確立を行うと、手間が3倍になってしまいます。応答が来なければ、プログラムは単にもう一度問い合わせます。

一方、すべてのバイトが確実に届かなければならない場面 — Web ページ、メール、ダウンロード — では、TCP が正しい選択です。

:::tip ポイント
**TCP** は信頼性が高い反面、手間がかかります。**完全に**届く必要があるすべてのもの(Web、メール、ファイル)に使います。**UDP** は高速で軽量ですが、保証はありません。**リアルタイム通信**(電話、ビデオ、ゲーム)や、DNS のような**短い問い合わせ**に使います。
:::
