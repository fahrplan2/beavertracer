# 誰がどのパケットを受け取る？

:::sim
url=/sims/lesson-3.1.2.btsim
:::

今度は Anna、Ben、Clara がスイッチにつながっています（ポート 1、2、3）。Anna が Ben にパケットを送ると、受け取るのは Ben だけでしょうか。それとも Clara も受け取るでしょうか。

まず、どうなると思うか少し考えてみましょう。そのあとで実際に試します。

## 実験

1. :fa-play: **実行**モードに切り替え、**Anna** で :fa-terminal: **ターミナル**を開いて Ben に ping を送ります。
   ```
   $ ping 192.168.0.11
   ```
2. :fa-magnifying-glass: **トレース**モードに切り替え、**+** で **Clara** のポート `eth0` のトレースを開きます。
3. **+** で、**Ben** のポート `eth0` の 2 つ目のトレースを開きます。上部で 2 つのトレースを切り替えられます。

:::quiz short
**Clara** には何個のパケットが届きましたか？
= 1
= 1個
= 1つ
= いち
:::

:::quiz mc
それはどのパケットでしたか？
- [x] 全員宛て（ブロードキャスト）の ARP 要求「Who has 192.168.0.11?」
- [ ] Anna からの ping（Echo Request）
- [ ] Ben の ARP 応答
:::

:::quiz mc

## 背景にある仕組み

ARP 要求の宛先は**ブロードキャスト**で、*全員*に向けられています。そのためスイッチは、Clara のポートを含むすべてのポートにこれを転送しました。一方、ping は Ben だけに宛てられていました。スイッチはそれを Ben のポートにだけ送ったので、Clara は何も気づきません。

:::tip ポイント
**ブロードキャスト**は、ローカルネットワーク内のすべての機器に向けられます。スイッチはこれをすべてのポートに配信します。**ユニキャスト**は、特定の 1 台だけに向けられます。スイッチはこれを、その機器がつながっているポートにだけ送ります。
:::

## スイッチの中をのぞく

では、スイッチは Ben がどのポートにつながっているのをどうやって知るのでしょうか。:fa-play: **実行**モードに戻って、**スイッチ**をクリックしてください。**SAT** タブに、**MAC** と **Port** の 2 列からなるアドレステーブルが表示されます。

:::quiz mc
アドレステーブルに載っている機器はどれですか？
- [ ] Anna、Ben、Clara
- [x] Anna と Ben だけ
- [ ] Ben だけ
:::

:::quiz short
テーブルによると、Ben はどのポートにつながっていますか？ ヒント：Ben の MAC アドレスは、トレースの Ben の ARP 応答 `192.168.0.11 is at …` から分かります。
= 2
= ポート2
= ポート 2
= port 2
:::

:::quiz mc
Clara がテーブルにないのはなぜですか？
- [ ] ケーブルが壊れているから
- [x] まだ 1 つもパケットを送信していないから
- [ ] スイッチは最大 2 件しか記憶できないから
:::

:::evaluate
回答を確認
:::

スイッチは通信しながら**学習**します。届いたフレームごとに**送信元** MAC アドレスを確認し、その機器がどのポートにつながっているかを記憶するのです。Anna の ARP 要求が届いたときに「Anna → ポート 1」を、Ben の応答が届いたときに「Ben → ポート 2」を記録しました。Clara は何も送信していないので、スイッチはまだ Clara を知りません。

:::tip ポイント
スイッチは**アドレステーブル**（**SAT**、*Source Address Table*）に、どの MAC アドレスの機器がどのポートの先にいるかを記憶します。これは送信元アドレスから学習されます。フレームの宛先が分かっていれば、そのポートにだけ送ります。分からない場合（またはブロードキャストの場合）は、すべてのポートに送ります。
:::
