スイッチにはAnna、Ben、そしてルーターが接続されています。AnnaとBenでは、IPv6が**SLAAC (automatisch)** に設定されています。IPv6アドレスは誰も入力していません。ルーターはプレフィックス `2001:db8:1::/64` を知っています。

## アドレスはどこから来るの?

1. :fa-play: **実行**モードに切り替えて、数秒待ちます。
2. **Anna** で :fa-terminal: **ターミナル** を開き、`ip a` と入力します。

IPv4アドレスのほかに、`inet6` の行が2つ表示されます。`scope link` のアドレスと、`scope global` のアドレスです。

:::quiz mc
2つのIPv6アドレスのうち、リンクローカルアドレスはどちらですか?
- [x] 先頭が `fe80::` のもの (`scope link`)
- [ ] 先頭が `2001:db8:1:` のもの (`scope global`)
:::

:::quiz mc
グローバルアドレスのプレフィックス `2001:db8:1:0` はどこから来たのでしょうか?
- [ ] Annaが自分で勝手に決めた
- [x] ルーターから。ルーターがネットワーク内にプレフィックスを通知している
- [ ] スイッチから
:::

:::evaluate
回答を確認
:::

**インターフェースID** (最後の4ブロック) を、Annaの**MACアドレス**と比べてみましょう。MACアドレスは :fa-gear: **IP設定** のいちばん下にあります。たとえばMACアドレス `aa:28:39:e2:41:82` からは、インターフェースID `a828:39ff:fee2:4182` が作られます。中央に `ff:fe` が挿入され、先頭の1ビットが反転します (そのため `aa` が `a8` になります)。

この方式を**SLAAC** (*Stateless Address Autoconfiguration*) と呼びます。ルーターがプレフィックスを通知し、インターフェースIDは各デバイスが自分で作ります。

:::note
MACアドレスはデバイスを一意に識別するため、インターフェースIDからインターネット上のどこでもそのデバイスを見分けられてしまいます。そのため、実際のデバイスでは、定期的に変わるランダムなインターフェースIDも併用するのが一般的です (*プライバシー拡張*)。これもプライバシー保護の一つです。
:::

## 隣接ノードを見つける: ARPなしで

1. **Ben** で `ip a` と入力し、**グローバル**IPv6アドレスを控えます。
2. **Anna** からそのアドレスにpingを送ります。例: `ping 2001:db8:1:0:…` (Benの完全なアドレスを指定)。
3. :fa-magnifying-glass: **トレース**モードに切り替えて、**Anna** のトレースを開きます。

最初の `Echo (ping) request` の直前にあるパケットを見てみましょう。

:::quiz multi
正しい記述はどれですか?
- [x] ARP要求の代わりに、Annaは**Neighbor Solicitation** (「このアドレスを持っているのは誰?」) を送る
- [x] Benは**Neighbor Advertisement**で応答し、自分のMACアドレスを伝える
- [x] 要求はブロードキャストで全員にではなく、マルチキャストアドレス (`ff02::1:ff…`) に送られる
- [ ] AnnaはIPv4のときのようにARP要求を送る
- [x] ルーターは定期的に**Router Advertisement**を `ff02::1` に送信する。その中にプレフィックスが含まれている
:::

:::evaluate
回答を確認
:::

:::tip ポイント
IPv6では、**NDP** (*Neighbor Discovery Protocol*、ICMPv6の一部) がARPの役割を担います。**Neighbor Solicitation**と**Neighbor Advertisement**によって、デバイスは隣接ノードのMACアドレスを見つけます。**Router Advertisement**ではルーターがプレフィックスを通知し、デバイスはそこから**SLAAC**で自分のアドレスを作ります。
:::
