# トラブルシューティング: コンタクトページが見つからない

:::sim
url=/sims/lesson-6.1.3.btsim
:::

事務室から連絡が入りました。「ウェブサイトの **Kontakt** リンクをクリックすると、エラーメッセージが表示されるだけになってしまった」とのことです。コンタクトページは `http://192.168.0.20/kontakt.html` で表示できるはずです。原因を見つけて、修正しましょう。

<details>
<summary>ヒント 1: サーバーは何を返している?</summary>

ブラウザまたは `curl -v` でコンタクトページにアクセスしてみましょう。どんなステータスコードが返ってきますか? エラーページには、サーバーがどこでファイルを探したかも表示されています。
</details>

<details>
<summary>ヒント 2: ファイルはどこにある?</summary>

Webサーバーは、自分の**ドキュメントルート**（*Document Root*）にあるファイルだけを返します。これは **HTTPサーバー** アプリで確認できます。**Server** のターミナルで `ls` を使ってそこに何があるか確認し、`/home` にもコンタクトページがないか探してみましょう。
</details>

<details>
<summary>ヒント 3: ファイルを移動する</summary>

`mv` でファイルを移動できます: `mv <移動元> <移動先フォルダ>`。
</details>

:::task
title: コンタクトページは直った?
コンタクトページがWebサーバーのドキュメントルートにあるかどうかを確認します。
check: fileExists(2, "/var/www/kontakt.html")
:::

## 何が起きていたのか?

:::quiz multi
正しい記述はどれですか?
- [x] サーバーは `404 Not Found` で応答した
- [x] ファイルがドキュメントルートの `/var/www` ではなく `/home` にあった
- [ ] Webサーバーがそもそも起動していなかった
- [ ] ブラウザが間違ったIPアドレスを使っていた
:::

:::evaluate
答えを確認
:::

:::tip ポイント
**404** は、Webサーバーは動作していて接続もできるものの、要求された**ファイル**がそのパスには存在しない、という意味です。サーバーは自分の**ドキュメントルート**（*Document Root*、ここでは `/var/www`）の中だけを探します。比較してみましょう。サーバーがまったく応答しない、または `RST` で応答する場合は、問題はもっと深いところ、つまりネットワークやサービス自体にあります（5.3.2章）。
:::
