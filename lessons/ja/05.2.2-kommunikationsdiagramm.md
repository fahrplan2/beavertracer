# シーケンス図

:::sim
url=/sims/lesson-5.1.btsim
:::

接続の流れは**シーケンス図**で表します。クライアントとサーバーにそれぞれ縦の線(ライフライン)を割り当て、時間は上から下へ流れます。矢印1本が1つのパケットです。どのパケットも届くまでに少し時間がかかるため、矢印は斜めに描かれます。

前のページで行った接続はこのようになります。トレースと1行ずつ見比べてみましょう。

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

各矢印の上には**フラグ**、下には `SEQ` と `ACK` の番号が表示されます。**DATA** はペイロード(実データ)を含むパケットを示します。赤い数字はクライアント、青い数字はサーバーのものです。その意味は次のページで説明します。

## フラグ

| フラグ | 由来 | 意味 |
|---|---|---|
| **SYN** | *synchronize* | 接続を確立し、開始番号を決める |
| **ACK** | *acknowledge* | 受信したデータを確認する |
| **PSH** | *push* | データをすぐにプログラムへ渡す |
| **FIN** | *finish* | 「終わりました」— 接続を切断する |
| **RST** | *reset* | 接続を中断または拒否する(詳しくは 5.3.2 で扱います) |

## 3つのフェーズ

**接続確立:** クライアントが `SYN` を送り、サーバーが `SYN, ACK` で応答し、クライアントが `ACK` で確認します。ちょうど3つのパケットが必要なので、これを**3ウェイハンドシェイク**と呼びます。

**データ転送:** データを含むパケットは、受信側が `ACK` で確認します。ここではサーバーがエコーを返し、それもクライアントが確認します。

**切断:** 各側が自分の送信方向を個別に終了します。クライアントからの `FIN` にサーバーが `ACK` を返し、次にサーバーからの `FIN` にクライアントが `ACK` を返します。合計4つのパケットです。

:::tip ポイント
TCP接続は3つのフェーズで進みます。**3ウェイハンドシェイク**による**接続確立**(`SYN` → `SYN, ACK` → `ACK`)、**データ転送**(データパケットはすべて `ACK` で確認される)、そして**切断**(各側が `FIN` を送り、`ACK` を受け取る)です。
:::
