# 順序と基本方針

## 例外が先、ルールは後

**最初に一致したルール**が適用されるため、順序が重要になります。次のルール一覧を見てみましょう(すべてのルールは A → B の方向に適用され、デフォルトポリシーは「すべて許可」です)。

| No. | プロトコル | 宛先ポート | アクション |
|---|---|---|---|
| 1 | TCP | 任意 | 破棄 |
| 2 | TCP | 80 | 許可 |

:::quiz mc
インターネットから TCP ポート 80 宛のパケットが届きました。何が起こるでしょうか?
- [ ] ルール2がちょうどポート80を許可しているので、許可される
- [x] すでにルール1に一致するので破棄される。ルール2には到達しない
- [ ] ファイアウォールが管理者に問い合わせる
:::

:::evaluate
回答を確認
:::

一般に、**特定のルールを上に、一般的なルールを下に**置きます。広い範囲をカバーするルールは、その下にあるすべてのルールを「覆い隠して」しまいます。**ヒット数**の列を見ると、こうした役に立たないルールがわかります。ヒット数が 0 のままになるからです。

## ブラックリストかホワイトリストか?

9.1.2 節では、個々のポートを**禁止**し、それ以外をすべて許可しました。これを**ブラックリスト**(「黒いリスト」)と呼びます。その反対が**ホワイトリスト**です。必要なものだけを**許可**し、それ以外はすべて禁止します。最後に「すべて破棄」のルールを置くか、デフォルトポリシーを**すべて破棄**にします。

| | ブラックリスト | ホワイトリスト |
|---|---|---|
| 基本方針 | すべて許可、例外を禁止 | すべて禁止、例外を許可 |
| デフォルトポリシー | 許可 | 破棄 |
| サーバー上の新しいサービス | すぐに外部から到達可能になる | 誰かが許可するまでブロックされたまま |

:::quiz mc
明日、教師が学校のサーバーにポート 3306 で待ち受けるデータベースをインストールします。9.1.2 節のファイアウォール(ブラックリスト)では何が起こるでしょうか?
- [x] データベースにすぐインターネットから到達できる
- [ ] データベースは自動的にブロックされる
- [ ] ファイアウォールが新しいサービスを通知する
:::

:::evaluate
回答を確認
:::

そのため、優れたファイアウォールは**ホワイトリスト方式**(「デフォルト拒否」)で運用されます。明示的に許可されていないものは、すべて禁止です。学校のサーバー用のホワイトリストは次のようになります。

:::quiz table
| Nr. | Richtung | Protokoll | Ziel-Port | Aktion |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {Zulassen} |
| 2 | A → B | TCP | {25} | Zulassen |
| 3 | A → B | beliebig | beliebig | {Verwerfen} |
:::

:::evaluate
表を確認
:::

:::quiz mc
ルール3を一番上に移動すると、どうなるでしょうか?
- [ ] 何も起こらない。順序は関係ない
- [x] インターネットからは何も通過できなくなる。Web もメールも通らない
- [ ] Web とメールだけが通過できる
:::

:::

:::tip ポイント
**最初に一致したルール**が適用されるため、**特定のルールは上に**、一般的なルールは下に置きます。**ブラックリスト**(…以外はすべて許可)よりも、**ホワイトリスト**(…以外はすべて禁止、*デフォルト拒否*)のほうが安全です。設定を忘れたサービスや新しいサービスは、自動的にブロックされたままになります。
:::
