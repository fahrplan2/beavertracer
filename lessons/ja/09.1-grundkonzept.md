# パケットフィルター: ルール

ファイアウォールの中で最も単純で最も重要な種類が**パケットフィルター**です。パケットフィルターは通過するすべてのパケットを確認し、**ルールリスト**に基づいて通してよいかどうかを判断します。そのために読むのは層3と層4のヘッダーだけで、中身（たとえばWebページ）は見ません。

## ルールの構成要素

| フィールド | 意味 | 例 |
|---|---|---|
| **方向** | パケットはどちら側から来るか | A → B（インターネットから学校ネットワークへ） |
| **プロトコル** | TCP、UDP、ICMP、または任意 | TCP |
| **送信元IP** | 送信元のアドレスまたはネットワーク | 任意 |
| **送信元ポート** | 送信元のポート | 任意 |
| **宛先IP** | 受信者のアドレスまたはネットワーク | `198.51.100.10` |
| **宛先ポート** | 受信者のポート、つまりサービス | `80` |
| **アクション** | 条件に一致したパケットをどうするか | 許可 |

空欄は「任意」を意味します。ネットワークは `198.51.100.0/24` のようにCIDR表記で書き、ポート範囲は `1024-65535` のようにハイフンで書きます。

## 順番が結果を決める

ファイアウォールはルールを**上から下へ**順に確認します。**最初に一致したルール**が結果を決め、それ以降のルールはそのパケットについてはもう見られません。どのルールにも一致しない場合は、**デフォルトポリシー**（*Default Policy*）が適用されます。

## 3つのアクション

| アクション | ファイアウォールの動作 | 送信元に分かること |
|---|---|---|
| **許可**（*Allow*） | パケットを転送する | — |
| **破棄**（*Drop*） | パケットを何も通知せずに捨てる | 何も分からない。タイムアウトになるまで待ち続ける |
| **拒否**（*Reject*） | パケットを捨て、送信元に拒否を通知する。TCPでは **RST**、それ以外ではICMP「到達不能」 | すぐにエラーメッセージが届く |

どちらがよいのでしょうか。**破棄**は攻撃者に与える情報が少なく、試行のたびに待たされるので時間も無駄にさせられます。**拒否**は自分たちのユーザーに親切です。プログラムはすぐにエラーメッセージを受け取れるので、長時間止まったままになりません。そのため実際には、外部からのパケットは破棄し、自分のネットワーク内からのパケットは拒否するのが一般的です。

:::quiz match
許可 -> パケットが転送される
破棄 -> パケットは消え、送信元は応答をむなしく待ち続ける
拒否 -> パケットは転送されないが、送信元はすぐに拒否の通知を受け取る
デフォルトポリシー -> どのルールにも一致しないときに適用される
:::

:::tip ポイント
**パケットフィルター**は、すべてのパケットを方向・プロトコル・アドレス・ポートに基づいて**ルールリスト**と照合します。**最初に一致したルール**がアクションを決めます。アクションは**許可**、**破棄**（通知なし）、**拒否**（拒否を通知）のいずれかです。どのルールにも一致しない場合は**デフォルトポリシー**が適用されます。
:::
