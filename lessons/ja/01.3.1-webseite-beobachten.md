# Webページを開いて観察する

この部分では、自分で何かを構築する必要はありません。ワークスペースには、**Client-PC** と **Webserver** を含む準備済みのシミュレーションがあります。

## ページを開く

1. :fa-play: **実行**モードに切り替えます。
2. **Client-PC** で :fa-globe: **ブラウザ** アプリを開き、Webサーバーのアドレス `http://192.168.0.20/` にアクセスします。
3. :fa-magnifying-glass: **トレース**モードに切り替え、**+** で **Client-PC** のポート `eth0` のトレースを開きます。ping のときと同じ手順です。

:::note
1回のページ表示にしては、パケットの数が驚くほど多いですね。ping よりずっと多くなっています。Webページの取得は、1つの動作ではなく、複数の段階を踏む処理なのです。
:::

## パケットリストを読む

個々のプロトコルが具体的に何をしているのかは、まだ知らなくて大丈夫です。以下の問いに必要な情報は、すべて **Protokoll** 列と **Info** 列に載っています。

:::quiz mc
リストの一番上にあるプロトコルはどれですか？
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
数えてみましょう。最初の **HTTP** パケットより前に、**TCP** パケットはいくつありますか？
= 3
= 3つ
= 3個
= 三つ
:::

:::quiz mc
ブラウザの要求に対して、Webサーバーは何と返答していますか？ 2つ目のHTTPパケットのInfo列を見てください。
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
答えを確認
:::

## 関わっているプロトコルを挙げる

ここまでの観察から、どのプロトコルが何を担当していたのかを読み取れるようになりました。

:::tip ヒント
**Info** 列をもう一度読み返してみましょう。`Who has …?`、`[SYN]`、`[SYN, ACK]`、`[ACK]`、`GET /`、`200 OK` を見れば、ほとんど答えがわかります。
:::

:::quiz match
ARP -> ネットワーク内の全員に尋ねる：「IPアドレス 192.168.0.20 を持っているのは誰？」
TCP -> データが流れる前に、3つの短いパケットで接続を確立する
HTTP -> Webページを要求し（GET）、それを返送する（200 OK）
:::

:::evaluate
対応づけを確認
:::

:::tip ポイント
Webページの表示は、段階を踏んで進みます。まずネットワーク内でサーバーを**見つけ**（ARP）、次に接続を**確立**し（TCP）、それからページを**要求して受け取り**（HTTP）、最後に接続を**切断**します（リスト末尾の `[FIN]` を含むTCPパケット）。
:::

:::note
今回はサーバーのIPアドレスを直接入力したため、**DNS**（`www.beispiel.de` のような名前をIPアドレスに「変換」する仕組み）はまだ使われませんでした。これについては第6章で取り上げます。
:::

パケットの構造の中で、プロトコルに数字付きの色のマークが付いていることに気づきましたか？ それが何を意味するのかは、第2章で説明します。そこでは、数多くあるプロトコルを体系的に整理する方法を、OSI参照モデルとTCP/IP参照モデルを使って見ていきます。これで第1章は完了です。
