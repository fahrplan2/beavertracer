# 直接送る？それともゲートウェイ経由？

:::sim
url=/sims/lesson-4.3.2.btsim
:::

PCはパケットを送る前に判断します。宛先は**自分のネットワーク内**にあるか？ そのために、自分のアドレスのネットワーク部と宛先アドレスのネットワーク部を、サブネットマスクを使って比較します。

## 処理の流れ

1. **宛先IPは自分のネットワーク内にあるか？**
   - **はい:** PCはパケットを宛先に**直接**送ります。必要なのは宛先のMACアドレスです。
   - **いいえ:** PCはパケットを**ゲートウェイ**に送ります。必要なのはルーターのMACアドレスです。ゲートウェイが設定されていないと、パケットをまったく送れません。
2. **必要なMACアドレスをすでに知っているか**（ARPキャッシュに載っているか）？ 知らなければ、**ARP**で問い合わせます。
3. フレームをそのMACアドレスに送ります。パケット内の**宛先IPアドレス**は、どちらの場合も本来の宛先のままです。

| | 直接（自分のネットワーク） | ゲートウェイ経由（別のネットワーク） |
|---|---|---|
| ARPで問い合わせるもの … | 宛先のMAC | ルーターのMAC |
| フレームの宛先MAC | 宛先 | ルーター |
| パケットの宛先IP | 宛先 | 宛先 |

## トラブルシューティング：B社に届かない

昨日から、AnnaはB社のPCに接続できなくなりました。ネットワークは本来、次のように設定されているはずです。

| デバイス | IPアドレス | ゲートウェイ |
|---|---|---|
| Anna | `192.168.0.10/24` | `192.168.0.1` |
| Ben | `192.168.0.11/24` | `192.168.0.1` |
| Clara | `172.16.0.10/24` | `172.16.0.1` |
| David | `172.16.0.11/24` | `172.16.0.1` |

誤りを見つけて修正しましょう。

</details>

:::tip ポイント
PCに正しいゲートウェイが必要なのは、送信するときだけではなく、**応答する**ときも同じです。ゲートウェイがないと、pingは届いても、応答が戻る道を見つけられません。**間違ったゲートウェイアドレス**が設定されていると、PCは存在しないルーターをARPで問い合わせ続けますが、無駄に終わります。
:::
