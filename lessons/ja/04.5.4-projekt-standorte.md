# プロジェクト: 4つの拠点を持つ会社

:::sim
url=/sims/lesson-4.5.4.btsim
:::

ある会社は本社を **Hanau** に置き、支店を **Kassel**、**Gießen**、**Darmstadt** に構えています。各拠点にはそれぞれ独自のネットワークとルーターがあります。すべてのルーターは専用線で **中央ネットワーク** に接続されており、そこには会社のメインサーバーも置かれています。

## アドレス計画

管理者は次のようなスキームでアドレスを割り当てました。これらはすでにシミュレーションに入力されています。

| ネットワーク | アドレス範囲 |
|---|---|
| 中央ネットワーク | `10.19.0.0/24` |
| Hanau | `10.19.1.0/24` |
| Kassel | `10.19.2.0/24` |
| Gießen | `10.19.3.0/24` |
| Darmstadt | `10.19.4.0/24` |

| デバイス | 中央ネットワーク側 | 拠点ネットワーク側 |
|---|---|---|
| Server | `10.19.0.10` | — |
| Router Hanau | `10.19.0.1` | `10.19.1.1` |
| Router Kassel | `10.19.0.2` | `10.19.2.1` |
| Router Gießen | `10.19.0.3` | `10.19.3.1` |
| Router Darmstadt | `10.19.0.4` | `10.19.4.1` |
| 各拠点のPC | — | いずれも `.2`(例: PC Kassel `10.19.2.2`) |

すべてのルーターで、`eth0` は中央ネットワークに、`eth1` は拠点ネットワークにつながっています。

## あなたの課題

会社のすべてのコンピューターが互いに、そしてサーバーに到達できるようにするには、あと2つ足りないものがあります。

1. **ゲートウェイ:** 4台すべてのPCとサーバーにゲートウェイを設定します。PCは自分の拠点のルーターを使い、サーバーは **Router Hanau** を使います。
2. **ルーティングテーブル:** 4台すべてのルーターに、まだ足りていないルートを追加します。各ルーターは、**他の3つ** の拠点のネットワークを知っている必要があります。

途中で `ping` と `traceroute` を使ってテストしましょう。

<details>
<summary>ヒント: ここでのルートはどのようになる?</summary>

**Router Kassel** の例を示します。Gießen(`10.19.3.0/24`)宛てのパケットは、Router Gießen の中央ネットワーク側のアドレスに送られます。つまり **次ホップ** は `10.19.0.3`、**Iface** は `eth0` です。このパターンに従うと、各ルーターに必要なルートは3つです。
</details>
