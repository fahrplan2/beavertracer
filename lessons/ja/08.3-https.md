# HTTPS

:::osi 5
:::

**HTTPS**（*HTTP Secure*）は、ごく普通のHTTPです。ただし、TCPの上で直接動くのではなく、その間にある暗号化層、つまり **TLS**（*Transport Layer Security*）を通して動きます。TLSの前身は **SSL** と呼ばれていたため、今でも「SSL証明書」と言われることがよくあります。

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP自身はこのことに気づきません。HTTPはいつもどおりリクエストを送り、TLSがそれを暗号化し、TCPが運びます。OSI参照モデルでは、TLSはトランスポート層とアプリケーション層の間、つまり4/5層にあたります。TLSはTCPの上に構築され、保護されたセッションを管理します。

| | HTTP | HTTPS |
|---|---|---|
| ポート | 80 | **443** |
| アドレス | `http://…` | `https://…` |
| トレースで内容を読めるか | はい | いいえ |
| ブラウザの表示 | 「保護されていない通信」 | 鍵マーク |

TLSは、接続確立のときに、この章で学んだことをすべて行います。

- サーバーは自分の **証明書** を提示して身元を証明します（**真正性**）。
- 双方が **Diffie-Hellman** で **セッション鍵** を取り決めます。サーバーは自分の分に **署名** します。
- その後、すべてのデータは **AES** で暗号化され（**機密性**）、改ざんからも保護されます（**完全性**）。

この原理はWebだけに限りません。電子メール（8.4節）や他の多くのプロトコルも、同じ方法でTLSを通して動いています。
