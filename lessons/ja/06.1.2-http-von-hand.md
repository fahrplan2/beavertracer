# HTTPを手で打つ

:::sim
url=/sims/lesson-6.1.btsim
:::

HTTPがただのテキストなら、ブラウザなしで自分でWebサーバーと「会話」することもできるのでしょうか。できます。`telnet` を使えば、任意のポートにTCP接続を確立し、テキストを自分で入力できます。

## 実験

1. :fa-play: **実行**モードに切り替え、**Client-PC** で :fa-terminal: **ターミナル**を開きます。
2. サーバーのポート80に接続します:
   ```
   $ telnet 192.168.0.20 80
   ```
3. リクエストを1行ずつ入力し、最後に**空行**を入力して終了します(もう一度 **Enter** を押すだけです):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

サーバーはステータス行、ヘッダー、そしてお問い合わせページを返します。ブラウザが受け取るのと同じ、テキストの形でです。

:::quiz mc
サーバーは、あなたのリクエストが終わったことをどこで判断しますか?
- [ ] 特別なコマンド `END` で
- [x] 空行で
- [ ] 一定の時間が経った後で
:::

:::quiz short
レスポンスの `Content-Type` ヘッダーにはどの値が入っていますか?(`;` の前の最初の部分のみ)
= text/html
:::

:::evaluate
回答を確認
:::

## エラーを起こしてみる

もっと便利なツールが `curl` です。リクエストを代わりに作って送ってくれます。`-v`(*verbose*、詳細表示)を付けると、やり取りされる内容がすべて表示されます。`>` の行は `curl` が送信したもの、`<` の行はサーバーから届いたものです。

試してみましょう:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
`/gibtsnicht.html` に対して、どのステータスコードが返ってきますか?
= 404
:::

:::quiz short
では、メソッド `POST` を使ったリクエストではどうですか?
= 405
:::

:::evaluate
回答を確認
:::

:::note
BeaverTracerのWebサーバーはファイルを返すことしかできないため、`GET` と `HEAD` のみを許可しています。実際のWebサーバーでは、たとえば `POST` でフォームを受け取り、そのデータをプログラムに渡します。
:::

:::tip ポイント
アプリケーション層の多くのプロトコルは**テキストベース**です。HTTPはもちろん、SMTP、POP3、IMAPもそうです。そのため `telnet` で手入力して会話したり、トレースで内容を読み取ったりできます。これはトラブルシューティングには便利ですが、セキュリティ上の問題でもあります。通信をキャプチャした人は、誰でもすべてを読めてしまうからです。暗号化(HTTPS)がどう役立つかは、第8章で学びます。
:::
