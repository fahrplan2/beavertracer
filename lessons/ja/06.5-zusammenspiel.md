# すべてまとめて：Webページを開くと何が起こる？

:::goal
**学習目標:** 電源を入れたばかりのノートPCがWebページを開くとき、どの層のどのプロトコルが関わるのかを、順を追って説明できる。
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

このコースで学んだことが、ここですべてつながります。スイッチには **DHCP-Server**、**DNS-Server**、**Webserver**、そして電源を入れたばかりの **Laptop** がつながっています。Laptop にはまだIPアドレスがなく、DHCPを使う設定になっています。

## 実験

1. :fa-play: **実行**モードに切り替えて、数秒待ちます。
2. **Laptop** をクリックし、:fa-globe: **ブラウザ**を開いて `http://www.beaver-schule.de/` にアクセスします。
3. :fa-magnifying-glass: **トレース**モードで、**Laptop** のトレースを開きます。最初のパケットから、一部始終がここに記録されています。

トレースに表示される順番どおりに、手順を並べましょう。

:::quiz match
1. Schritt -> DHCP: ノートPCがIPアドレス、ゲートウェイ、DNSサーバーを取得する
2. Schritt -> ARP: ノートPCがDNSサーバーのMACアドレスを問い合わせる
3. Schritt -> DNS: ノートPCが www.beaver-schule.de のIPアドレスを問い合わせる
4. Schritt -> ARP: ノートPCがWebサーバーのMACアドレスを問い合わせる
5. Schritt -> TCP: Webサーバーとの3ウェイハンドシェイク
6. Schritt -> HTTP: GET / とその応答 200 OK
:::

:::evaluate
順序を確認
:::

そのすべての下には、各パケットにアドレスを付ける **IP**（第3層）と、パケットを次の機器まで届ける **Ethernet**（第2層）があります。Webサーバーが別のネットワークにある場合は、さらに**ルーター**が加わります。その場合、ノートPCが問い合わせるのはWebサーバーではなく、**ゲートウェイ**のMACアドレスです。

:::quiz mc
ノートPCは、なぜDHCPのあとでなければDNSの問い合わせができないのでしょうか？
- [ ] DNSはTCPでしか動作しないから
- [x] DHCPによって初めて自分のIPアドレスを取得し、どのDNSサーバーを使えばよいかを知るから
- [ ] DNSサーバーはDHCPサーバーより後に起動するから
:::

:::quiz mc
ブラウザはWebサーバーに対していくつTCP接続を確立するでしょうか？ それはなぜでしょうか？
- [ ] 1つ。すべてをまとめて扱う
- [x] 2つ。ページ用とスタイルシート用
- [ ] 1つもない。HTTPはTCPを必要としない
:::

:::evaluate
回答を確認
:::

:::tip ポイント
たった1回のクリックの裏で、すべての層が連携して働いています。**DHCP** が基本設定を渡し、**ARP** がローカルネットワーク内のMACアドレスを見つけ、**DNS** が名前を変換し、**TCP** が信頼性のある接続を確立し、**HTTP** がページを取得します。そのすべてが **IP** パケットと **Ethernet** フレームに包まれて運ばれます。
:::

これで、Webページを開く処理を最初のパケットから最後のパケットまで説明できるようになりました。この章の締めくくりとして、ほかのプロトコルについて簡単に紹介します。続く章では、NATを使った家庭内ネットワーク、セキュリティと暗号化を扱います。つまり、これらのパケットを誰かに盗み見られないようにするにはどうすればよいか、という問いです。
