# Povezovanje dveh omrežij

:::sim
url=/sims/lesson-4.3.1.btsim
:::

Usmerjevalnik ima dva priključka:

| Priključek | Naslov IP | Omrežje |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Da računalniki uporabljajo usmerjevalnik, je pri vsakem od njih vnesen **prehod** (*gateway*): pri Anni in Benu `192.168.0.1`, pri Clari in Davidu `172.16.0.1`. Najdeš ga v :fa-gear: **Nastavitve IP** v polju **Gateway**.

:::tip Zapomni si
**Prehod** (natančneje: *privzeti prehod*) je naslov IP usmerjevalnika **v lastnem omrežju**. Na prehod računalnik pošlje vse pakete, katerih cilj je v tujem omrežju.
:::

## Eksperiment

1. Preklopi v :fa-play: način **Zagon** in s computerja **Anna** pingaj Claro (`ping 172.16.0.10`). Tokrat deluje — v izpisu bodi pozoren na vrednost `ttl=`.
2. Preklopi v :fa-magnifying-glass: način **Sled** in odpri sled za **Anna**.

Poglej prvi paket (zahtevek ARP):

:::quiz multi
Katere trditve o prvem paketu so pravilne?
- [x] Anna že pozna naslov IP od Clare, preden pošlje paket
- [ ] Anna sprašuje po naslovu MAC od Clare
- [x] Anna vse naprave v omrežju sprašuje po naslovu MAC usmerjevalnika
- [ ] Anna vpraša stikalo po naslovu IP od Clare
:::

Zdaj klikni na prvi `Echo (ping) request` in razširi **Ethernet II** ter **Internet Protocol Version 4**. Primerjaj naslove MAC z odgovorom ARP pred tem.

:::quiz multi
Katere trditve o pingu so pravilne?
- [x] Kot ciljni naslov IP je vpisana Clara (`172.16.0.10`)
- [ ] Kot ciljni naslov IP je vpisan usmerjevalnik (`192.168.0.1`)
- [x] Kot ciljni naslov MAC je vpisan naslov MAC usmerjevalnika
- [ ] Anna pošlje ping neposredno na naslov MAC od Clare
:::

## Kaj usmerjevalnik naredi s paketom

Usmerjevalnik sprejme okvir od Anne, odpakira paket IP in pogleda **ciljni naslov IP**. Po tem prepozna: Clara je v omrežju na `eth1`. Zato paket zapakira v **nov** okvir — z lastnim naslovom MAC kot pošiljateljem in naslovom MAC od Clare kot ciljem — in ga pošlje ven na tisti strani.

| Kaj se zgodi na usmerjevalniku z …? | |
|---|---|
| naslovi MAC (plast 2)? | se nastavijo **na novo** — veljajo samo v posameznem omrežju |
| naslovi IP (plast 3)? | **ostanejo enaki** — od Anne do Clare |
| časom Time to Live? | se **zmanjša za 1** |

:::tip Zapomni si
**Usmerjevalnik** deluje na **plasti 3**: pakete na podlagi **ciljnega naslova IP** posreduje v druga omrežja. Naslovi IP ostanejo na celotni poti enaki, naslovi MAC se v vsakem omrežju nastavijo na novo. Vsak usmerjevalnik zmanjša **Time to Live (TTL)** za 1 — ko doseže 0, se paket zavrže. Tako paket ne more v nedogled krožiti.
:::

:::note
Se spomniš viharja razpošiljanja (broadcast storm) iz poglavja 3.4? Okvirji Ethernet nimajo TTL — paketi IP pa ga imajo.
:::

## Koga pozna Anna? Predpomnilnik ARP

Se spomniš poglavja 1.2.3? Tam se je ARP pojavil samo pred *prvim* pingom, ker si je računalnik odgovor zapomnil. Ta seznam za pomnjenje se imenuje **predpomnilnik ARP** (tudi *tabela ARP*). Poizvedbi pravimo **ARP-Request**, odgovoru **ARP-Reply** (ali *ARP-Response*).

Preklopi v :fa-play: način **Zagon**, na računalniku **Anna** odpri :fa-terminal: **Terminal** in si oglej njen predpomnilnik ARP:

```
$ arp
```

:::quiz mc
Kaj je v Annini predpomnilniku ARP?
- [x] Samo naslov IP usmerjevalnika (`192.168.0.1`) z njegovim naslovom MAC
- [ ] Naslov IP od Clare z naslovom MAC od Clare
- [ ] Naslova usmerjevalnika in Clare
:::

:::evaluate
Preveri odgovor
:::

Anna naslova MAC od Clare nikoli ne potrebuje: vse, kar je namenjeno firmi B, pošlje usmerjevalniku. Naslov MAC od Clare pozna samo usmerjevalnik — na svoji strani ga je sam poizvedel prek ARP.

:::tip Zapomni si
V **predpomnilniku ARP** si naprava zapomni, kateri naslov MAC pripada kateremu naslovu IP — tako ji pred vsakim paketom ni treba pošiljati zahtevka ARP. Prikaže se z ukazom `arp`. Računalnik pozna samo naslove MAC iz **lastnega** omrežja: za vse cilje v tujih omrežjih uporabi naslov MAC usmerjevalnika.
:::

:::note
V resničnih omrežjih se vnosi v predpomnilniku ARP čez nekaj časa spet izbrišejo in se po potrebi znova poizvedo — na primer, če ima naprava medtem drugo omrežno kartico. V BeaverTracer ostanejo ohranjeni, dokler simulacija teče.
:::
