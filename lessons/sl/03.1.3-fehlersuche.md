# Iskanje napak v omrežju s stikalom

:::sim
url=/sims/lesson-3.1.3.btsim
:::

Odkar se je v omrežje priključil **David**, so težave: Clare nihče ne more doseči in z Benom je nekaj narobe. Kot omrežni strokovnjak jih moraš odpraviti.

## Načrt omrežja

Tako *bi moralo* izgledati omrežje:

| Naprava | Naslov IP | Vrata stikala |
|---|---|---|
| Anna | `192.168.0.10/24` | 1 |
| Ben | `192.168.0.11/24` | 2 |
| Clara | `192.168.0.12/24` | 3 |
| David | `192.168.0.13/24` | 4 |

Primerjaj načrt s simulacijo: Kaj je drugače? Odpravi vse napake, ki jih najdeš.

<details>
<summary>Namig 1: Kje naj začnem?</summary>

Najprej si oglej kable: Je vsak računalnik priklopljen na pravilna vrata? Nato preveri nastavitve IP vsakega računalnika.
</details>

<details>
<summary>Namig 2: Ben vendar odgovarja na ping …?</summary>

Z Anninega računalnika pošlji ping Benu (`ping 192.168.0.11`) in odpri sled za Anno. Natančno si oglej odgovore ARP: Koliko jih je — in s katerimi naslovi MAC?
</details>

:::task
title: Je omrežje popravljeno?
Preveri, ali imajo vse naprave naslove iz načrta omrežja in ali se med seboj dosežejo. Simulacija mora biti za to v načinu izvajanja.
check: ip(3, "192.168.0.10/32")
check: ip(5, "192.168.0.11/32")
check: ip(7, "192.168.0.12/32")
check: ip(11, "192.168.0.13/32")
check: pingOk(3, 7)
check: pingOk(3, 11)
check: pingOk(5, 7)
:::

## Kaj se je zgodilo?

:::quiz mc
Po čem v sledilniku prepoznaš, da imata dve napravi enak naslov IP?
- [ ] Ping vedno spodleti
- [x] Na eno zahtevo ARP prideta dva odgovora z različnima naslovoma MAC
- [ ] Stikalo prikaže sporočilo o napaki
:::

:::evaluate
Preveri odgovor
:::

:::tip Zapomni si
Pri **iskanju napak** primerjaš **želeno stanje** (načrt omrežja) z **dejanskim stanjem** (kabli, nastavitve, sled). Previdno: uspešen ping še ne pomeni samodejno, da je vse v redu — pri podvojenem naslovu IP morda preprosto odgovarja napačna naprava.
:::
