# Opazovanje UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

Na **strežniku** (Server) tokrat teče **UDP Echo-Strežnik** na vratih `5000`. Tudi tukaj je kabel pripravljen: **drugi datagram** od odjemalskega računalnika (Client-PC) do strežnika (Server) se izgubi.

## Eksperiment

1. Preklopi v :fa-play: način **Zagon** in na računalniku **Client-PC** odpri :fa-terminal: **Terminal**.
2. Z ukazom `nc` začni UDP »povezavo« s strežnikom (`-u` pomeni UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Zaporedoma vtipkaj `eins`, `zwei` in `drei` ter vsakič pritisni **Enter**. Vsaka vrstica, ki se vrne, je odmev strežnika.
4. Počakaj nekaj sekund in nato v načinu :fa-magnifying-glass: **Sled** odpri sled za računalnik **Client-PC**.

:::quiz mc
Kateri odmevi se vrnejo?
- [ ] Vsi trije, `zwei` nekoliko pozneje
- [x] Samo `eins` in `drei` — `zwei` manjka in se tudi ne pošlje ponovno
- [ ] Noben
:::

:::quiz multi
Kateri paketi, ki jih poznaš iz TCP, pri UDP popolnoma manjkajo?
- [x] Vzpostavitev povezave (`SYN`)
- [x] Potrditve (`ACK`)
- [x] Prekinitev povezave (`FIN`)
- [ ] Paketi s številkami vrat
:::

:::evaluate
Preveri odgovore
:::

Klikni na enega od paketov UDP in razpri **User Datagram Protocol**. V primerjavi z glavo TCP je glava UDP drobna: **Source Port**, **Destination Port**, **Length** (dolžina) in **Checksum** (kontrolna vsota) — skupaj le 8 bajtov. Glava TCP ima vsaj 20 bajtov, z zaporedno in potrditveno številko, zastavicami in velikostjo okna.

:::quiz mc
Katero nalogo iz razdelka 5.1 UDP kljub temu opravlja?
- [x] Multipleksiranje — prek vrat
- [ ] Vzpostavitev povezave
- [ ] Zanesljiv prenos
:::

:::evaluate
Preveri odgovor
:::

:::tip Zapomni si
**UDP** je **brezpovezaven**: brez vzpostavitve, brez potrditve, brez ponovnega prenosa, brez vrstnega reda. Ponuja le **vrata** (multipleksiranje) in **kontrolno vsoto**. Zato pa je hiter in vitek — glava UDP ima le 8 bajtov. Če se datagram izgubi, mora program poskrbeti zanj sam — ali pa mu je vseeno.
:::
