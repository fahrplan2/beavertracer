# Zaporedne in potrditvene številke

:::sim
url=/sims/lesson-5.1.btsim
:::

Kako TCP ve, ali je vse prispelo — in v kakšnem vrstnem redu? Vsaka stran **oštevilči bajte**, ki jih pošlje:

- **Zaporedna številka** (`SEQ`) je številka prvega bajta, ki je v tem paketu.
- **Potrditvena številka** (`ACK`) pove: „Vse do sem sem prejel — naslednji bajt, ki ga pričakujem, je št. …"

K temu še dve pravili: `SYN` in `FIN` štejeta kot en bajt, čeprav ne prenašata podatkov. In vsaka stran šteje zase — zato obstajata dve zaporedji številk, na diagramu rdeče (odjemalec) in modro (strežnik).

## Preračunaj

Tu je še enkrat tvoja povezava. Številke ob črtah prikazujejo števec računalnika na tem mestu:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Preglej rdeče zaporedje številk:

1. Odjemalec začne pri `SEQ=0`. Njegov `SYN` porabi eno številko — strežnik potrdi z `ACK=1`.
2. Sporočilo se začne pri `SEQ=1` in je dolgo 13 bajtov (bajti od 1 do 13). Strežnik potrdi z `ACK=14`: „Naslednji pričakujem bajt 14."
3. `FIN` odjemalca ima zato `SEQ=14` in je potrjen z `ACK=15`.

Modro zaporedje strežnika deluje popolnoma enako.

:::tip Zapomni si
**Zaporedna številka** (`SEQ`) je številka prvega bajta v paketu. **Potrditvena številka** (`ACK`) je številka naslednjega bajta, ki ga prejemnik pričakuje — vse pred njo je prispelo. Velja: **ACK = SEQ + dolžina** prejetih podatkov; `SYN` in `FIN` štejeta kot en bajt. Vsaka stran šteje svoje bajte.
:::

:::tip Preizkusi
Ponovno vzpostavi povezavo v **Enostaven odjemalec TCP** in pošlji dve sporočili zaporedoma. Vnaprej povej, kateri `Seq` in `Ack` bosta v stolpcu **Info** — in to preveri v sledi.
:::

:::note
V resničnih omrežjih štetje ne steče pri 0: vsaka stran izbere **naključno začetno številko** (*Initial Sequence Number*, ISN) med 0 in približno 4,3 milijarde. Ko je dosežena najvišja številka, se štetje spet nadaljuje pri 0. Tracer začetno številko odšteje in prikaže **relativne** številke — prav tako kot Wireshark. Zato vidiš `Seq=0` in `Seq=1`.

Poleg tega je v vsakem paketu `Win=` — **velikost okna**: toliko bajtov lahko prejemnik trenutno sprejme. S tem upočasni prehitrega pošiljatelja (*nadzor pretoka*). V BeaverTracer je okno vedno enako veliko.
:::
