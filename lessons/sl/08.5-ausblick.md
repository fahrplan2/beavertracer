# Povzetek in pogled naprej

## Gradniki na kratko

| Gradnik | Zaščitni cilj | Primer |
|---|---|---|
| **Simetrično šifriranje** | Zaupnost | AES šifrira podatke povezave HTTPS |
| **Asimetrično šifriranje** | Zaupnost, izmenjava ključev | Diffie-Hellman, RSA |
| **Zgoščene vrednosti** | Celovitost | Kontrolna vsota SHA-256 prenesene datoteke |
| **Digitalni podpis** | Pristnost, celovitost | Strežnik podpiše svoj delež Diffie-Hellman |
| **Digitalno potrdilo** | Pristnost | potrjuje: ta ključ pripada naslovu `www.biberbank.de` |

## Isto načelo na mnogih mestih

Kar si spoznal pri HTTPS, najdeš tudi v mnogih drugih tehnologijah:

- **WLAN (WPA2/WPA3):** V poglavju 3.3.2 je lahko vsaka naprava v dosegu prebirala promet. Pri WPA2 ali WPA3 je vsak radijski okvir šifriran z AES; WPA3 pa ključ tudi dogovori tako, da prisluškovalec starih posnetkov ne more dešifrirati niti z geslom za WLAN.
- **SSH:** Šifrirano oddaljeno vzdrževanje iz poglavja 6.6. Namesto digitalnih potrdil si odjemalec ob prvi povezavi zapomni **prstni odtis** ključa strežnika in te opozori, če se pozneje spremeni.
- **VPN:** Šifriran tunel skozi internet, npr. v šolsko ali podjetniško omrežje. O tem govori poglavje 10.
- **Sporočilniki:** Signal, WhatsApp in drugi šifrirajo **od konca do konca**: niti upravljavec storitve ne more brati sporočil.

:::note
Veliki **kvantni računalniki** bi lahko nekoč razbili razstavljanje velikih števil na praštevilske faktorje — in s tem RSA ter Diffie-Hellman. Zato že danes uvajajo nove, **kvantno varne** postopke. Simetrični postopki, kot je AES z dolgimi ključi, še naprej veljajo za varne.
:::

## Preizkusi se

:::quiz mc
Pri HTTPS se dejanski podatki šifrirajo z …
- [ ] RSA, ker je najvarnejši
- [x] simetričnim postopkom, kot je AES, in dogovorjenim sejnim ključem
- [ ] zasebnim ključem strežnika
:::

:::quiz mc
Odpreš `https://www.biberbank.de/` in brskalnik javi: »Digitalno potrdilo je bilo izdano za `www.gewinn-biber.de`.« Kaj narediš?
- [ ] Kliknem »Vseeno nadaljuj« — povezava je vendarle šifrirana
- [x] Prekinem — brskalnik morda sploh ne komunicira z banko
- [ ] Odprem stran prek `http://`, potem opozorila ni
:::

:::quiz multi
Katere trditve so pravilne?
- [x] Zgoščena vrednost se popolnoma spremeni, tudi če se podatki spremenijo le minimalno
- [x] Podpis se ustvari z zasebnim ključem in preveri z javnim
- [x] Korenski overitelji (root CA) so vnaprej nameščeni v brskalniku oziroma operacijskem sistemu
- [ ] Pri HTTPS prisluškovalec ne vidi niti naslova IP strežnika
- [ ] SMTPS šifrira e-pošto tudi na poštnem strežniku
:::
