## Eksperiment

1. Preklopi v :fa-play: način izvajanja (**Zagon**), klikni na **Client-PC** in odpri :fa-globe: **Brskalnik**. Odpri `http://192.168.0.20/`.
2. Zgoraj v oknu klikni na **Nazaj**, odpri **Enostaven odjemalec TCP** in ga poveži z `192.168.0.20`, vrata `5000`. Pusti povezavo odprto.
3. Preklopi v :fa-magnifying-glass: način **Sled**, odpri sled za **Client-PC** in klikni na paket z `[SYN]`. Razširi **Transmission Control Protocol**.

Čisto na vrhu glave TCP sta dvoje vrat: **Source Port** (izvorna vrata) in **Destination Port** (ciljna vrata).

:::quiz table
| Povezava | Izvorna vrata | Ciljna vrata |
|---|---|---|
| Brskalnik → spletni strežnik | {49152} | {80} |
| Odjemalec TCP → storitev Echo | {49153} | {5000} |
:::

## Dve vrsti vrat

**Ciljna vrata — storitev:** Strežniški program čaka na povezave na stalnih vratih — pravimo, da tam **posluša**. Za znane storitve so številke določene po vsem svetu, imenujemo jih **dobro znana vrata** (angl. *well-known ports*, od 0 do 1023). Brskalnik zato brez spraševanja ve: spletni strežniki poslušajo na vratih 80.

**Izvorna vrata — pošiljatelj:** Vrata na strani odjemalca za vsako novo povezavo samodejno izbere operacijski sistem iz visokega območja (v BeaverTracer od 49152 naprej). Po njih odjemalec prepozna, kateri od njegovih povezav pripada odgovor.

Povezava je torej enolično določena s štirimi podatki: **naslov IP in vrata na obeh straneh**. Par naslova IP in vrat imenujemo **vtič** (angl. *socket*), npr. `192.168.0.20:80`.

## Pogled na strežnik

Preklopi nazaj v :fa-play: način izvajanja (**Zagon**), na **Server**ju odpri :fa-terminal: **Terminal** in vnesi:

```
$ ss
```

`ss` prikaže vse vtiče računalnika. Vrstice z `LISTEN` so programi, ki poslušajo na določenih vratih. Vrstice z `ESTABLISHED` so vzpostavljene povezave — z lastnim vtičem (*Local Address:Port*) in vtičem nasprotne strani (*Peer Address:Port*).

:::quiz multi
Na katerih vratih posluša strežnik?
- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc
Katero povezavo `ss` prikaže kot `ESTABLISHED`?
- [x] `192.168.0.20:5000` z `192.168.0.10:49153` — odprta povezava odjemalca TCP
- [ ] `192.168.0.20:80` z `192.168.0.10:49152` — povezava brskalnika
- [ ] Obe
:::

:::note
Povezava brskalnika je bila že prekinjena — po nalaganju strani je bila končana s `FIN`. `ss` jo še kratek čas prikazuje kot `TIME-WAIT`: strežnik nekaj časa čaka, ali bodo morda prispeli še zakasneli paketi te povezave. Povezava odjemalca TCP pa je še odprta, ker še nisi kliknil na **Prekinji povezavo**.
:::

## Najpomembnejša dobro znana vrata

| Vrata | Protokol | Storitev |
|---|---|---|
| 22 | SSH | varno oddaljeno upravljanje (šifrirana ukazna vrstica) |
| 25 | SMTP | pošiljanje e-pošte |
| 53 | DNS | pretvarjanje imen v naslove IP (običajno prek UDP) |
| 80 | HTTP | spletne strani |
| 110 | POP3 | prevzem e-pošte |
| 143 | IMAP | upravljanje e-pošte na strežniku |
| 443 | HTTPS | šifrirane spletne strani |

:::tip Zapomni si
**Vrata** (od 0 do 65535) ločujejo povezave na računalniku. Strežniške storitve **poslušajo** na stalnih **dobro znanih vratih** (npr. HTTP 80, HTTPS 443), odjemalci pa za vsako povezavo dobijo prosta visoka **izvorna vrata**. Povezava je enolično določena z **naslovom IP in vrati obeh strani**.
:::

:::quiz match
22 -> SSH
25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
