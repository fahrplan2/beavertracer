# Serangan: pemalsuan DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna ingin membuka layanan perbankan online **Biberbank** di **Client-PC**. Yang tidak ia ketahui: seseorang telah mendapatkan akses ke **DNS-Server** dan mengubah salah satu entri.

Di Area kerja kamu melihat server web asli **www.biberbank.de** dan komputer seorang **Angreifer**. Di komputer itu berjalan salinan situs web bank.

## Bagian 1: Tanpa enkripsi

Beralihlah ke Mode Jalankan (:fa-play: **Jalankan**) dan buka `http://www.biberbank.de/` di :fa-globe: **Peramban** pada **Client-PC**.

:::quiz mc
Apa yang kamu lihat?
- [x] Halaman login Biberbank, tanpa peringatan apa pun
- [ ] Peringatan bahwa situs ini palsu
- [ ] Pesan kesalahan
:::

:::evaluate
Periksa jawaban
:::

Semuanya tampak normal. Tetapi dengan server mana sebenarnya peramban berkomunikasi? Buka :fa-terminal: **Terminal** di Client-PC:

```
$ nslookup www.biberbank.de
```

:::quiz short
Alamat IP apa yang diberikan DNS-Server untuk `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Milik siapa alamat ini? (Klik perangkat di Mode Edit atau lihat :fa-gear: **Pengaturan IP** miliknya.)
- [ ] Server web Biberbank yang asli
- [x] Penyerang
- [ ] DNS-Server
:::

:::evaluate
Periksa jawaban
:::

Seandainya Anna sekarang memasukkan nomor rekening dan PIN, data itu akan langsung sampai ke penyerang. Pada **HTTP** ia **tidak punya kesempatan** untuk menyadari penipuan ini: bilah alamat menampilkan nama yang benar, dan halamannya tampak asli.

## Bagian 2: Dengan HTTPS

Sekarang buka `https://www.biberbank.de/`.

:::quiz mc
Apa yang terjadi?
- [ ] Halaman palsu muncul dengan ikon gembok
- [x] Peramban memperingatkan: sertifikat diterbitkan untuk nama lain
- [ ] Halaman asli Biberbank muncul
:::

:::quiz short
Untuk nama apa sertifikat penyerang diterbitkan (tanpa `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Periksa jawaban
:::

Penyerang bahkan memiliki sertifikat **asli** dari CA tepercaya — tetapi untuk domainnya sendiri, `www.biber-gewinnspiel.de`. Sertifikat untuk `www.biberbank.de` tidak akan ia dapatkan dari CA mana pun, karena domain itu bukan miliknya. Dan tanpa **kunci privat** Biberbank, ia juga tidak dapat menggunakan sertifikat asli milik bank: dalam handshake, ia harus menandatangani Server Key Exchange dengan kunci tersebut.

:::quiz multi
Dari apa HTTPS melindungi di sini — dan dari apa tidak?
- [x] HTTPS mengungkap bahwa server itu bukan server yang asli
- [ ] HTTPS mencegah DNS-Server dipalsukan
- [x] HTTPS hanya membantu jika pengguna menanggapi peringatan dengan serius
- [ ] Dengan HTTPS, halaman palsu sama sekali tidak dapat diakses
:::

:::evaluate
Periksa jawaban
:::

## Bagian 3: Memperbaiki DNS-Server

Buka **DNS-Server** dan perbaiki entri untuk `www.biberbank.de`. Alamat yang benar dapat kamu temukan di :fa-gear: **Pengaturan IP** milik server web **www.biberbank.de**. Jangan lupa mengklik **Simpan**.

:::note
Client-PC mengingat jawaban DNS untuk sementara waktu agar tidak perlu bertanya ulang setiap kali mengakses (**cache DNS**). Berapa lamanya tertera di kolom **TTL** (*Time to Live*) dalam detik. Jika `nslookup` langsung setelah perbaikanmu masih memberikan alamat lama, tunggu hingga TTL habis lalu coba lagi.
:::

:::task
title: Biberbank asli kembali?
Prüft, ob der Client-PC www.biberbank.de zur richtigen Adresse auflöst und die Seite über HTTPS ohne Warnung abrufen kann.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Di dunia nyata, penyerang jarang memalsukan DNS-Server itu sendiri. Lebih sering ia menyelipkan jawabannya di WLAN publik, mengubah pengaturan router rumah, atau memancing dengan alamat yang tampak mirip seperti `www.biberbank-login.de` (**phishing**). Terhadap nama yang terdengar mirip, HTTPS pun tidak membantu — penyerang bisa mendapatkan sertifikat yang valid untuknya. Karena itu: baca alamat dengan teliti!
:::

:::tip Poin penting
Pada **pemalsuan DNS**, DNS-Server memberikan alamat milik penyerang untuk sebuah nama. Pada **HTTP**, hal ini tidak terdeteksi. Pada **HTTPS**, sertifikat penyerang tidak cocok dengan nama yang diakses, dan peramban **memperingatkan** — karena tidak ada CA yang menerbitkan sertifikat untuk domain milik orang lain, dan penyerang tidak memiliki kunci privat server yang asli.
:::
