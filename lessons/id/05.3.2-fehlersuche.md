# Pemecahan masalah: layanan tidak merespons

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Setelah pembaruan, pihak sekolah melaporkan: "Layanan echo menolak setiap koneksi, dan halaman web juga tidak termuat lagi." Menurut rencana, **Webserver** seharusnya mendengarkan di port `80` dan **Echo-Dienst** (Server Echo TCP) di port `5000`. Temukan kesalahannya dan perbaiki.

<details>
<summary>Petunjuk 1: Apa balasan server?</summary>

Coba hubungkan ke `192.168.0.20`, port `5000` dengan **Klien TCP Sederhana**, lalu buka sebuah trace untuk Client-PC. Dengan apa server membalas `[SYN]` yang kamu kirim?
</details>

<details>
<summary>Petunjuk 2: Port mana saja yang terbuka?</summary>

Ketik `nmap -p 80,5000 192.168.0.20` di Terminal pada Client-PC. `nmap` mencoba port satu per satu dan menunjukkan port mana yang terbuka. Dengan `ss` di server, kamu bisa melihat di port mana sebuah program benar-benar mendengarkan.
</details>

<details>
<summary>Petunjuk 3: Di mana pengaturannya?</summary>

Buka aplikasi **Server Echo TCP** dan **Server HTTP** pada **Server**. Apakah layanannya berjalan? Dan di port berapa?
</details>

:::task
title: Layanan dapat dijangkau?
Periksa apakah Client-PC dapat menjangkau layanan echo di port 5000 dan webserver di port 80. Untuk itu, simulasi harus berjalan di Mode Jalankan.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Apa yang terjadi?

:::quiz multi
Pernyataan mana yang benar?
- [x] Terhadap `[SYN]` ke port 5000, server membalas dengan `[RST, ACK]`
- [x] Layanan echo mendengarkan di port 5050, bukan di port 5000
- [x] Webserver sama sekali belum dimulai
- [ ] Kabel antara Client-PC dan Server rusak
:::

:::evaluate
Periksa jawaban
:::

:::tip Poin penting
Jika sebuah `SYN` dibalas dengan **`RST`**, berarti **tidak ada program** yang mendengarkan di port tersebut: komputernya dapat dijangkau, tetapi layanannya tidak. Penyebab yang umum: layanan **belum dimulai** atau mendengarkan di **port lain**. Dengan `ss` di server, kamu bisa melihat port mana yang benar-benar terbuka.
:::
