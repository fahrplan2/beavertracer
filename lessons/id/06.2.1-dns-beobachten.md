## Eksperimen

1. Beralihlah ke Mode Jalankan :fa-play: **Jalankan**, klik **Client-PC**, lalu buka :fa-globe: **Peramban**.
2. Kali ini akses `http://www.beaver-schule.de/` — dengan nama, bukan alamat IP.
3. Beralihlah ke mode :fa-magnifying-glass: **Jejak** dan buka sebuah trace untuk **Client-PC**.

Tepat di awal — bahkan sebelum pembentukan koneksi dengan `[SYN]` — terdapat dua paket dengan protokol **DNS**.

:::quiz short

= 192.168.0.53
:::

:::quiz short

= 192.168.0.20
:::

Baru setelah Client-PC mengetahui alamat IP-nya, ia membentuk koneksi TCP ke server web — persis seperti di bab 5.

:::seq
mode: text
Client-PC -> DNS-Resolver: DNS-Anfrage | A www.beaver-schule.de?
DNS-Resolver -> Client-PC: DNS-Antwort | A 192.168.0.20
:::

## Dari mana PC mengetahui server DNS?

Buka :fa-gear: **Pengaturan IP** pada **Client-PC**: di kolom **DNS-Server** tertulis `192.168.0.53` — komputer **DNS-Resolver**. Ke komputer inilah PC mengirim setiap permintaan nama.

Kamu juga bisa menanyakan langsung ke server DNS, tanpa peramban. Buka :fa-terminal: **Terminal** dan ketik:

```
$ nslookup www.beaver-schule.de
```

`nslookup` pertama-tama menampilkan server mana yang ditanyainya, lalu jawabannya. Sebagai perbandingan, tanyakan sebuah nama yang tidak ada, misalnya `nslookup gibtsnicht.beaver-schule.de`.

:::quiz mc
Apa jawaban server DNS untuk nama yang tidak dikenal itu?
- [ ] Alamat IP acak
- [x] `NXDOMAIN` — nama ini tidak ada
- [ ] Tidak ada jawaban sama sekali
:::

:::evaluate
Periksa jawaban
:::

:::tip Poin penting
**DNS** menerjemahkan nama (misalnya `www.beaver-schule.de`) menjadi alamat IP. Sebelum sebuah PC dapat membentuk koneksi ke sebuah nama, ia bertanya kepada **server DNS** yang tercatat di pengaturan IP-nya — biasanya melalui **UDP, port 53**. Dengan `nslookup` kamu dapat membuat permintaan DNS secara manual.
:::
