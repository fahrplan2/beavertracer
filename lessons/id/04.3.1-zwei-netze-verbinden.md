# Menghubungkan dua jaringan

:::sim
url=/sims/lesson-4.3.1.btsim
:::

Router memiliki dua antarmuka:

| Antarmuka | Alamat IP | Jaringan |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Agar PC-PC menggunakan router, pada masing-masing PC dimasukkan sebuah **gateway**: pada Anna dan Ben `192.168.0.1`, pada Clara dan David `172.16.0.1`. Kamu bisa menemukannya di :fa-gear: **Pengaturan IP** pada kolom **Gateway**.

:::tip Poin penting
**Gateway** (lebih tepatnya: *default gateway*) adalah alamat IP router **di jaringan sendiri**. Ke gateway inilah PC mengirim semua paket yang tujuannya berada di jaringan lain.
:::

## Eksperimen

1. Beralihlah ke Mode Jalankan :fa-play: **Jalankan** dan ping Clara dari **Anna** (`ping 172.16.0.10`). Kali ini berhasil — perhatikan nilai `ttl=` pada keluarannya.
2. Beralihlah ke mode :fa-magnifying-glass: **Jejak** dan buka sebuah trace untuk **Anna**.

Lihat paket pertama (permintaan ARP):

:::quiz multi
Pernyataan mana tentang paket pertama yang benar?
- [x] Anna sudah mengetahui alamat IP Clara sebelum ia mengirim paket
- [ ] Anna menanyakan alamat MAC Clara
- [x] Anna menanyakan alamat MAC router kepada semua perangkat di jaringan
- [ ] Anna menanyakan alamat IP Clara kepada switch
:::

Sekarang klik `Echo (ping) request` yang pertama, lalu buka **Ethernet II** dan **Internet Protocol Version 4**. Bandingkan alamat MAC-nya dengan balasan ARP sebelumnya.

:::quiz multi
Pernyataan mana tentang ping tersebut yang benar?
- [x] Sebagai alamat IP tujuan tertera Clara (`172.16.0.10`)
- [ ] Sebagai alamat IP tujuan tertera router (`192.168.0.1`)
- [x] Sebagai alamat MAC tujuan tertera alamat MAC router
- [ ] Anna mengirim ping langsung ke alamat MAC Clara
:::

## Apa yang dilakukan router terhadap paket

Router menerima frame dari Anna, membuka paket IP-nya, lalu melihat **alamat IP tujuan**. Dari situ ia mengetahui: Clara berada di jaringan pada `eth1`. Maka ia membungkus paket tersebut ke dalam frame **baru** — dengan alamat MAC-nya sendiri sebagai pengirim dan alamat MAC Clara sebagai tujuan — lalu mengirimkannya ke sana.

| Apa yang terjadi pada router terhadap … | |
|---|---|
| alamat MAC (Lapisan 2)? | ditetapkan **ulang** — hanya berlaku di jaringan masing-masing |
| alamat IP (Lapisan 3)? | **tetap sama** — dari Anna sampai Clara |
| Time to Live? | berkurang **1** |

:::tip Poin penting
**Router** bekerja pada **Lapisan 3**: ia meneruskan paket ke jaringan lain berdasarkan **alamat IP tujuan**. Alamat IP tetap sama sepanjang perjalanan, sedangkan alamat MAC ditetapkan ulang di setiap jaringan. Setiap router mengurangi **Time to Live (TTL)** sebesar 1 — jika nilainya mencapai 0, paket dibuang. Dengan begitu, sebuah paket tidak bisa berputar-putar tanpa henti.
:::

:::note
Ingatkah kamu dengan badai broadcast dari bab 3.4? Frame Ethernet tidak memiliki TTL — paket IP memilikinya.
:::

## Siapa yang dikenal Anna? ARP cache

Ingatkah kamu dengan bab 1.2.3? Di sana ARP hanya muncul sebelum ping *pertama*, karena PC mengingat jawabannya. Daftar ingatan ini disebut **ARP cache** (juga *tabel ARP*). Pertanyaannya disebut **ARP request**, jawabannya **ARP reply** (atau *ARP response*).

Beralihlah ke Mode Jalankan :fa-play: **Jalankan**, buka :fa-terminal: **Terminal** pada **Anna**, lalu tampilkan ARP cache miliknya:

```
$ arp
```

:::quiz mc
Apa isi ARP cache Anna?
- [x] Hanya alamat IP router (`192.168.0.1`) beserta alamat MAC-nya
- [ ] Alamat IP Clara beserta alamat MAC Clara
- [ ] Alamat router dan alamat Clara
:::

:::evaluate
Periksa jawaban
:::

Anna tidak pernah membutuhkan alamat MAC Clara: semua yang ditujukan ke Firma B ia kirim ke router. Alamat MAC Clara hanya diketahui router — ia sendiri menanyakannya lewat ARP di sisinya.

:::tip Poin penting
Di dalam **ARP cache**, sebuah perangkat mengingat alamat MAC mana yang cocok dengan alamat IP mana — sehingga ia tidak perlu mengirim ARP request sebelum setiap paket. Isinya dapat ditampilkan dengan perintah `arp`. Sebuah PC hanya mengenal alamat MAC dari jaringannya **sendiri**: untuk semua tujuan di jaringan lain, ia menggunakan alamat MAC router.
:::

:::note
Di jaringan sungguhan, entri dalam ARP cache dihapus lagi setelah beberapa waktu dan ditanyakan ulang bila diperlukan — misalnya jika sebuah perangkat ternyata sudah memakai kartu jaringan yang lain. Di BeaverTracer, entri tetap tersimpan selama simulasi berjalan.
:::
