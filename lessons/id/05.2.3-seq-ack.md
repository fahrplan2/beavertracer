# Nomor urut dan nomor konfirmasi

:::sim
url=/sims/lesson-5.1.btsim
:::

Bagaimana TCP tahu apakah semuanya sudah sampai — dan dalam urutan apa? Setiap pihak **memberi nomor pada byte** yang dikirimnya:

- **Nomor urut** (`SEQ`) adalah nomor byte pertama yang ada di dalam paket ini.
- **Nomor konfirmasi** (`ACK`) berarti: "Sampai sini semuanya sudah kuterima — selanjutnya aku mengharapkan byte nomor …"

Ada dua aturan tambahan: `SYN` dan `FIN` dihitung sebagai satu byte, meskipun keduanya tidak membawa data. Dan setiap pihak menghitung sendiri-sendiri — karena itu ada dua rentang nomor, merah (klien) dan biru (server) di dalam diagram.

## Menghitung ulang

Berikut koneksimu sekali lagi. Angka-angka di garis menunjukkan nilai penghitung komputer pada titik tersebut:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Telusuri deretan angka merah:

1. Klien mulai dari `SEQ=0`. `SYN`-nya menghabiskan satu nomor — server mengonfirmasi dengan `ACK=1`.
2. Pesan dimulai dari `SEQ=1` dan panjangnya 13 byte (byte 1 sampai 13). Server mengonfirmasi dengan `ACK=14`: "Selanjutnya aku mengharapkan byte 14."
3. Karena itu `FIN` dari klien memiliki `SEQ=14` dan dikonfirmasi dengan `ACK=15`.

Deretan angka biru milik server bekerja dengan cara yang sama persis.

:::tip Poin penting
**Nomor urut** (`SEQ`) adalah nomor byte pertama di dalam paket. **Nomor konfirmasi** (`ACK`) adalah nomor byte berikutnya yang diharapkan oleh penerima — semua yang sebelumnya sudah sampai. Berlaku: **ACK = SEQ + panjang** data yang diterima; `SYN` dan `FIN` dihitung sebagai satu byte. Setiap pihak menghitung byte miliknya sendiri.
:::

:::tip Coba sendiri
Bangun koneksi sekali lagi di **Klien TCP Sederhana** dan kirim dua pesan berturut-turut. Tebak dulu `Seq` dan `Ack` apa yang akan muncul di kolom **Info** — lalu periksa di trace.
:::

:::note
Di jaringan sungguhan, penghitungan tidak dimulai dari 0: setiap pihak memilih **nomor awal acak** (*Initial Sequence Number*, ISN) antara 0 dan sekitar 4,3 miliar. Jika nomor tertinggi tercapai, penghitungan dilanjutkan lagi dari 0. Tracer mengurangi nomor awal tersebut dan menampilkan nomor **relatif** — persis seperti Wireshark. Karena itulah kamu melihat `Seq=0` dan `Seq=1`.

Selain itu, di setiap paket ada `Win=` — **ukuran jendela**: sebanyak inilah byte yang saat ini sanggup ditampung oleh penerima. Dengan itu penerima memperlambat pengirim yang terlalu cepat (*kontrol aliran*). Di BeaverTracer, ukuran jendela selalu sama.
:::
