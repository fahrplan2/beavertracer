# TCP atau UDP?

| | TCP | UDP |
|---|---|---|
| Koneksi | pembentukan dengan three-way handshake, pemutusan secara teratur | tidak ada — setiap datagram berdiri sendiri |
| Konfirmasi | ya (`ACK`) | tidak |
| Data yang hilang | dikirim ulang | tetap hilang |
| Urutan | dipulihkan | tidak dijamin |
| Header | minimal 20 byte | 8 byte |
| Kecepatan | agak lebih lambat, lebih banyak paket | cepat, overhead kecil |

Kapan lebih sedikit justru lebih baik?

- **Real-time:** Pada video call, telepon internet, atau game online, setiap milidetik sangat berarti. Potongan suara yang hilang lalu dikirim satu detik kemudian tidak berguna lagi bagi siapa pun — lebih baik ada bunyi gemeretak singkat daripada tertunda.
- **Permintaan singkat:** Sebuah permintaan **DNS** ("Alamat IP apa yang dimiliki `www.beispiel.de`?") muat dalam satu datagram saja, begitu juga jawabannya. Pembentukan koneksi akan melipattigakan usahanya. Jika tidak ada jawaban, program cukup bertanya sekali lagi.

Sebaliknya, di semua tempat yang mengharuskan setiap byte sampai — halaman web, e-mail, unduhan —, TCP adalah pilihan yang tepat.

:::tip Poin penting
**TCP** andal, tetapi lebih berat — untuk segala sesuatu yang harus sampai **secara utuh** (web, e-mail, file). **UDP** cepat dan ringan, tetapi tanpa jaminan — untuk **real-time** (telepon, video, game) dan **permintaan singkat** seperti DNS.
:::

Dengan ini kamu sudah mengenal perangkat di lapisan transport. Di bab berikutnya kamu akan mempelajari protokol-protokol yang dibangun di atasnya: HTTP, DNS, e-mail, dan DHCP.
