# Pemecahan masalah: nama tidak berfungsi

:::sim
url=/sims/lesson-6.2.3.btsim
:::

Seorang guru melaporkan: "`www.beaver-schule.de` tidak bisa dimuat di komputer saya. Tapi dengan `http://192.168.0.20` bisa!" Beginilah seharusnya konfigurasinya:

| Apa | Seharusnya |
|---|---|
| Server DNS di Client-PC | `192.168.0.53` (DNS-Resolver) |
| Entri di Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Temukan kesalahannya dan perbaiki.

<details>
<summary>Petunjuk 1: Apa kata nslookup?</summary>

Ketik `nslookup www.beaver-schule.de` di Client-PC. Server mana yang ditanya oleh `nslookup` — dan apa yang dikembalikan? (Jawabannya butuh beberapa detik.)
</details>

<details>
<summary>Petunjuk 2: Lalu bagaimana?</summary>

Jika kamu mendapat jawaban, bandingkan alamatnya dengan denah. Di mana nama ini didaftarkan?
</details>

:::task
title: Resolusi nama sudah diperbaiki?
Memeriksa apakah Client-PC me-resolve www.beaver-schule.de ke alamat yang benar. Simulasi harus berjalan dalam Mode Jalankan.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Apa yang terjadi?

:::quiz multi
Pernyataan mana yang benar?
- [x] Di Client-PC, `192.168.0.35` terdaftar sebagai server DNS — di sana tidak ada yang menjawab
- [x] Di Schul-DNS, `www.beaver-schule.de` mengarah ke `192.168.0.21`, bukan ke `192.168.0.20`
- [ ] Server web dalam keadaan mati
- [ ] Root server tidak mengenal domain `.de`
:::

:::evaluate
Periksa jawaban
:::

:::tip Poin penting
Jika koneksi berhasil dengan **alamat IP** tetapi tidak dengan **nama**, masalahnya ada di **DNS**. Periksa dulu **server DNS yang terdaftar** (apakah ia menjawab sama sekali?), lalu **entri** itu sendiri (apakah alamatnya benar?). `nslookup` menunjukkan keduanya: server mana yang ditanya dan apa jawabannya.
:::
