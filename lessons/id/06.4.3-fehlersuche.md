# Pemecahan masalah: laptop tidak terhubung ke jaringan

:::sim
url=/sims/lesson-6.4.3.btsim
:::

Setelah liburan, para guru melapor: "Laptop kami tidak bisa masuk ke jaringan lagi!" Kedua laptop diatur ke **DHCP**. Menurut rencana, server DHCP seharusnya membagikan alamat dari `192.168.0.100` sampai `192.168.0.120`, dengan gateway `192.168.0.1` dan server DNS `192.168.0.53`.

Temukan kesalahannya dan perbaiki.

<details>
<summary>Petunjuk 1: Alamat apa yang dimiliki laptop?</summary>

Lihat :fa-gear: **Pengaturan IP** pada salah satu laptop. Alamat yang diawali `169.254` diberikan oleh perangkat itu **kepada dirinya sendiri** — karena tidak ada server DHCP yang menjawab.
</details>

<details>
<summary>Petunjuk 2: Apakah server DHCP menjawab?</summary>

Buka sebuah jejak untuk salah satu laptop. Apakah kamu hanya melihat `DHCP Discover` — atau ada juga jawabannya? Lalu lihat aplikasi **Server DHCP**: Apakah sudah berjalan? Dan rentang mana yang dibagikannya?
</details>

<details>
<summary>Petunjuk 3: Mengambil alamat baru</summary>

Jika kamu mengubah sesuatu di server, atur sebentar mode laptop di Pengaturan IP ke **Statis** lalu kembali ke **DHCP**, kemudian klik **Terapkan** — setelah itu laptop akan meminta alamat lagi.
</details>

:::task
title: Laptop sudah terhubung ke jaringan lagi?
Periksa apakah kedua laptop memiliki alamat dari rentang yang direncanakan dan dapat menjangkau server DHCP. Untuk itu, simulasi harus berjalan di Mode Jalankan.
check: ip(3, "192.168.0.96/27")
check: ip(4, "192.168.0.96/27")
check: pingOk(3, 2)
check: pingOk(4, 2)
:::

## Apa yang terjadi?

:::quiz multi
Pernyataan mana yang benar?
- [x] Server DHCP belum dimulai — laptop memberi dirinya sendiri alamat `169.254`
- [x] Rentang alamat berada di jaringan yang salah (`192.168.1.…` bukan `192.168.0.…`)
- [ ] Laptop diatur ke alamat tetap
- [ ] Gateway tidak ada di switch
:::

:::evaluate
Periksa jawaban
:::

:::tip Poin penting
Jika sebuah perangkat memiliki alamat dari **`169.254.0.0/16`**, berarti perangkat itu **tidak mendapat jawaban dari server DHCP** dan memberi dirinya sendiri sebuah alamat (**APIPA**). Dengan alamat itu, ia hanya dapat menjangkau perangkat lain yang mengalami hal yang sama. Periksa kemudian: Apakah server DHCP berjalan? Apakah dapat dijangkau? Dan apakah ia membagikan alamat dari **jaringan yang benar**?
:::
