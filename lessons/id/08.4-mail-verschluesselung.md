# Mengirim e-mail secara terenkripsi

:::sim
url=/sims/lesson-8.4.btsim
:::

Di bagian 6.3.2 kamu sudah melihat bahwa pada SMTP dan POP3, pengirim, penerima, isi, bahkan kata sandi dikirim lewat kabel dalam bentuk yang bisa dibaca. Dengan TLS, hal ini bisa diamankan sama seperti HTTP. Untuk e-mail ada dua cara:

| | **TLS implisit** | **STARTTLS** |
|---|---|---|
| Alur | Koneksi sudah terenkripsi sejak detik pertama. | Koneksi dimulai tanpa enkripsi; klien mengirim perintah `STARTTLS`, setelah itu komunikasi dienkripsi. |
| Port | port tersendiri: **SMTPS 465**, **POP3S 995**, **IMAPS 993** | port biasa, misalnya SMTP 25 atau 587 |

Huruf "S" pada SMTPS, POP3S, dan IMAPS berarti *Secure* (aman), sama seperti pada HTTPS.

## Beralih ke port terenkripsi

Buka **Pengaturan** di program e-mail Anna:

- **Masuk:** port `995` dan centang **TLS**

Simpan, kirim satu e-mail lagi, lalu ambil e-mail sekali lagi. Lihat trace-nya (filter `tls`).

:::tip Coba sendiri
Ubah pengiriman ke port `25` dengan enkripsi **STARTTLS** lalu kirim e-mail. Di trace kamu bisa melihat bahwa koneksi awalnya tanpa enkripsi — server menawarkan `STARTTLS` dalam balasannya terhadap `EHLO` — dan baru setelah perintah `STARTTLS` TLS handshake dimulai.
:::

## Apa yang tidak dilindungi oleh enkripsi transport

TLS hanya mengenkripsi **jalur** antara dua komputer: dari Anna ke server e-mail dan — jika kedua server e-mail mendukungnya — dari server e-mail ke server e-mail. Namun **di dalam server e-mail** itu sendiri, e-mail tersimpan sebagai teks biasa. Siapa pun yang punya akses ke server e-mail dapat membaca semua e-mail di dalamnya.

Jika hanya penerima yang boleh membaca sebuah e-mail, e-mail harus dienkripsi **end-to-end**: pengirim mengenkripsi dengan kunci publik penerima, dan hanya penerima yang dapat mendekripsinya kembali. Untuk e-mail, ada metode **S/MIME** dan **OpenPGP**; aplikasi pesan seperti Signal atau WhatsApp melakukannya secara otomatis.

:::tip Poin penting
E-mail dikirim secara terenkripsi dengan **TLS** — baik dengan **TLS implisit** pada port tersendiri (**SMTPS 465**, **POP3S 995**, **IMAPS 993**) maupun dengan **STARTTLS** pada port biasa. Ini disebut **enkripsi transport**: enkripsi ini melindungi jalurnya, tetapi tidak melindungi e-mail yang tersimpan di server. Untuk itu diperlukan **enkripsi end-to-end**.
:::
