# Cara DNS diorganisasi

:::sim
url=/sims/lesson-6.2.btsim
:::

Tidak ada satu server pun yang bisa mengetahui semua nama di dunia. Karena itu DNS disusun secara **hierarkis** — sama seperti nama-namanya sendiri. Nama dibaca dari kanan ke kiri:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Server yang bertanggung jawab atas suatu domain dan benar-benar mengetahui jawabannya disebut **autoritatif**. Jalur menuju server tersebut ditempuh oleh **resolver** atas nama PC — di sini komputer **DNS-Resolver**.

## Eksperimen

1. Beralihlah ke Mode Jalankan :fa-play: dan ketik di :fa-terminal: **Terminal** pada **Client-PC**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Di mode :fa-magnifying-glass: **Jejak**, buka sebuah trace untuk **DNS-Resolver**.

Resolver telah mengirimkan serangkaian permintaan untukmu. Cocokkan siapa yang memberikan jawaban yang mana:

:::quiz match
Root-Server (192.168.0.101) -> Rujukan: Untuk .de, ns.nic.de yang bertanggung jawab
de-Server (192.168.0.102) -> Rujukan: Untuk beaver-schule.de, ns.beaver-schule.de yang bertanggung jawab
Schul-DNS (192.168.0.103) -> Jawaban: www.beaver-schule.de memiliki alamat 192.168.0.20
:::

:::quiz mc
Siapa yang pertama kali ditanya oleh resolver?
- [x] Root-Server
- [ ] Schul-DNS
- [ ] Client-PC
:::

:::evaluate
Periksa jawaban
:::

:::note
Di sela-sela proses, resolver juga menanyakan alamat server-server yang dirujuk kepadanya (`A ns.nic.de`). Server DNS sungguhan biasanya langsung menyertakan alamat-alamat ini. Selain itu, resolver mengingat setiap jawaban untuk beberapa waktu (**cache**) — permintaan berikutnya untuk nama yang sama langsung dijawab sendiri olehnya. Berapa lama jawaban disimpan tercantum dalam entri sebagai **TTL** (*Time to Live*) dalam detik.
:::

## Jenis entri yang terpenting

| Jenis | Arti | Contoh |
|---|---|---|
| **A** | Nama → alamat IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | Nama → alamat IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | Nama → nama lain (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | server email yang bertanggung jawab atas suatu domain | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | server DNS yang bertanggung jawab atas suatu domain | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Poin penting
DNS bersifat **hierarkis**: **root server** merujuk ke server **Top-Level Domain** (mis. `.de`), dan server TLD merujuk ke server tiap **domain**. Server **autoritatif** yang bertanggung jawab mengetahui jawabannya. **Resolver** menempuh jalur ini untuk PC dan mengingat jawaban-jawabannya (**cache**). Jenis entri penting: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Membuat sebuah entri

Sekolah ingin agar situs webnya juga dapat diakses melalui `intranet.beaver-schule.de`.

1. Di Mode Jalankan :fa-play:, klik **Schul-DNS** lalu buka aplikasi **DNS-Server**.
2. Buka tab **A**. Klik **+** dan masukkan nama `intranet.beaver-schule.de` serta alamat `192.168.0.20` pada baris baru.
3. Uji di Client-PC dengan `nslookup intranet.beaver-schule.de`.
