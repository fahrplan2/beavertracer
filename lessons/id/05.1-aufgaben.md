# Apa yang harus dilakukan lapisan transport?

:::sim
url=/sims/lesson-5.1.btsim
:::

Di **Server** berjalan dua layanan sekaligus: sebuah **server web** dan sebuah **layanan echo** kecil yang langsung mengirim kembali setiap pesan yang diterimanya. Dengan dua eksperimen, kamu akan mengetahui apa yang tidak bisa dilakukan oleh IP saja.

## Eksperimen 1: Dua program sekaligus

1. Beralihlah ke Mode Jalankan :fa-play: dan klik **Client-PC**.
2. Buka :fa-globe: **Peramban** dan akses `http://192.168.0.20/`.
3. Klik **Zurück** di bagian atas jendela, lalu buka **Klien TCP Sederhana**. Isikan `192.168.0.20` pada **Host** dan `5000` pada **Port**, lalu klik **Hubungkan**.
4. Beralihlah ke Mode :fa-magnifying-glass: **Jejak** dan buka trace untuk **Client-PC** dengan **+**, port `eth0`.

Klik sebuah paket dari peramban (misalnya `GET /`) dan satu paket dari klien TCP, lalu buka **Internet Protocol Version 4** pada masing-masing paket.

:::quiz mc
Alamat IP apa yang dibawa oleh paket peramban dan klien TCP?
- [x] Keduanya sama: dari `192.168.0.10` ke `192.168.0.20`
- [ ] Peramban menggunakan alamat IP tujuan yang berbeda dari klien TCP
- [ ] Paket klien TCP tidak memiliki alamat IP
:::

:::quiz mc
Jadi, apakah alamat IP tujuan sudah cukup bagi server untuk mengetahui apakah sebuah paket ditujukan ke server web atau ke layanan echo?
- [ ] Ya
- [x] Tidak — kedua paket memiliki alamat IP tujuan yang sama
:::

Sesuatu yang lain harus membedakan kedua koneksi itu. Lihat kolom **Info** pada paket dengan `[SYN]` — itu adalah paket pertama dari masing-masing koneksi:

:::quiz short
Angka berapa yang tertulis setelah tanda panah `→` pada **peramban**?
= 80
:::

:::quiz short
Dan pada **klien TCP**?
= 5000
:::

:::evaluate
Periksa jawaban
:::

Kamu akan mempelajari angka-angka ini — yaitu **port** — lebih lanjut di bagian 5.3. Untuk sementara cukup diketahui: hanya lapisan transport yang memungkinkan beberapa program berkomunikasi sekaligus melalui *satu* alamat IP, dan setiap paket sampai ke program yang tepat. Hal ini disebut **Multiplexing**.

## Eksperimen 2: Ketika sebuah paket hilang

1. Beralihlah ke Mode Jalankan :fa-play: dan klik **kabel** antara Client-PC dan Server.
2. Di jendela **Verbindung**, atur **Konfigurierter Paketverlust** ke `25%`.
3. Buka :fa-terminal: **Terminal** pada **Client-PC** dan kirim enam ping:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Ini memakan waktu sekitar setengah menit — tunggu sampai statistik muncul.

:::quiz mc
Apa yang terjadi?
- [ ] Keenam ping dibalas semuanya
- [x] Beberapa ping tidak dibalas — dan tidak ada yang mengirimnya lagi
- [ ] Ping yang hilang otomatis diulang sampai tiba
:::

:::evaluate
Periksa jawaban
:::

Pada ping, hal ini tidak masalah — justru tujuannya untuk menunjukkan apakah ada yang hilang. Namun pada halaman web, e-mail, atau unduhan, bagian yang hilang akan berakibat fatal: berkasnya menjadi rusak.

## Empat tugas lapisan transport

| Tugas | Artinya |
|---|---|
| **Multiplexing** | Beberapa program dan koneksi berbagi satu alamat IP; setiap paket sampai ke program yang tepat. |
| **Pembentukan koneksi** | Sebelum data mengalir, kedua pihak menyepakati bahwa mereka akan saling berkomunikasi. |
| **Pengiriman yang andal** | Penerima mengonfirmasi apa yang sudah tiba. Data yang hilang dikirim ulang, dan urutannya dipulihkan. |
| **Pemutusan koneksi** | Pada akhirnya, kedua pihak mengakhiri koneksi dengan tertib. |

:::tip Poin penting
**Lapisan transport** (lapisan 4) memastikan data sampai ke **program** yang tepat (**Multiplexing**). Protokol **TCP** juga memastikan data tiba secara **lengkap** dan dalam **urutan yang benar** — dengan pembentukan koneksi, konfirmasi, pengiriman ulang, dan pemutusan koneksi.
:::

:::quiz match
Di sebuah PC, peramban, program e-mail, dan messenger berjalan bersamaan. -> Multiplexing
Sebelum data mengalir, kedua pihak memastikan bahwa pihak lain sudah siap. -> Pembentukan koneksi
Sebagian berkas tidak tiba dan dikirim sekali lagi. -> Pengiriman yang andal
Setelah unduhan selesai, kedua pihak melepaskan koneksi kembali. -> Pemutusan koneksi
:::
