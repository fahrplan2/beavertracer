# Semuanya digabung: apa yang terjadi saat membuka halaman web?

:::goal
**Tujuan pembelajaran:** Kamu dapat menjelaskan langkah demi langkah protokol apa saja yang terlibat di lapisan mana, ketika laptop yang baru saja dinyalakan membuka sebuah halaman web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Sekarang semua yang sudah kamu pelajari di kursus ini digabungkan. Pada switch terhubung sebuah **DHCP-Server**, sebuah **DNS-Server**, sebuah **Webserver**, dan sebuah **Laptop** yang baru saja dinyalakan — laptop itu belum punya alamat IP dan diatur ke DHCP.

## Eksperimen

1. Beralihlah ke Mode Jalankan :fa-play: **Jalankan** dan tunggu beberapa detik.
2. Klik **Laptop**, buka :fa-globe: **Peramban**, lalu buka `http://www.beaver-schule.de/`.
3. Di Mode :fa-magnifying-glass: **Jejak**, buka sebuah trace untuk **Laptop**. Di sinilah seluruh ceritanya — mulai dari paket pertama.

Urutkan langkah-langkah berikut dengan benar, sesuai urutannya di trace:

:::quiz match
1. Schritt -> DHCP: Laptop mendapatkan alamat IP, gateway, dan server DNS
2. Schritt -> ARP: Laptop menanyakan alamat MAC server DNS
3. Schritt -> DNS: Laptop menanyakan alamat IP dari www.beaver-schule.de
4. Schritt -> ARP: Laptop menanyakan alamat MAC server web
5. Schritt -> TCP: Three-way handshake dengan server web
6. Schritt -> HTTP: GET / dan jawaban 200 OK
:::

:::evaluate
Periksa urutan
:::

Dan di bawah semuanya ada **IP** (Lapisan 3) yang menyalamatkan setiap paket ini, serta **Ethernet** (Lapisan 2) yang mengantarkannya ke perangkat berikutnya. Seandainya server web berada di jaringan lain, **router** akan ikut terlibat: Maka laptop akan menanyakan alamat MAC **gateway**-nya, bukan alamat MAC server web.

:::quiz mc
Mengapa laptop baru bisa mengirim permintaan DNS setelah DHCP?
- [ ] Karena DNS hanya berfungsi melalui TCP
- [x] Karena baru melalui DHCP ia mendapatkan alamat IP sendiri dan mengetahui server DNS mana yang bertanggung jawab
- [ ] Karena server DNS baru menyala setelah server DHCP
:::

:::quiz mc
Berapa banyak koneksi TCP yang dibangun peramban ke server web — dan mengapa?
- [ ] Satu, untuk semuanya sekaligus
- [x] Dua — satu untuk halaman dan satu untuk stylesheet
- [ ] Tidak ada sama sekali, HTTP tidak membutuhkan TCP
:::

:::tip Poin penting
Di balik satu klik, semua lapisan bekerja sama: **DHCP** menyediakan pengaturan dasar, **ARP** menemukan alamat MAC di jaringan lokal, **DNS** menerjemahkan nama, **TCP** membentuk koneksi yang andal, dan **HTTP** mengambil halaman — semuanya dibungkus dalam paket **IP** dan frame **Ethernet**.
:::

Dengan ini kamu dapat menjelaskan pembukaan sebuah halaman web dari paket pertama sampai paket terakhir. Sebagai penutup bab ini, menyusul gambaran singkat tentang protokol-protokol lainnya. Di bab-bab berikutnya kita membahas jaringan rumah dengan NAT, keamanan, dan enkripsi — dan dengan itu pertanyaan bagaimana mencegah agar tidak ada orang yang bisa membaca semua paket ini.
