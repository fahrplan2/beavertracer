# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) adalah HTTP biasa — hanya saja tidak berjalan langsung di atas TCP, melainkan melalui lapisan terenkripsi di antaranya: **TLS** (*Transport Layer Security*). Pendahulu TLS bernama **SSL**; karena itu orang sering masih menyebutnya "sertifikat SSL".

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP tidak menyadari hal ini: HTTP mengirim permintaannya seperti biasa, TLS mengenkripsinya, dan TCP mengangkutnya. Dalam model OSI, TLS berada di antara lapisan transport dan lapisan aplikasi, yaitu di lapisan 4/5 — TLS dibangun di atas TCP dan mengelola sesi yang diamankan.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Alamat | `http://…` | `https://…` |
| Isi dapat dibaca di Tracer? | ya | tidak |
| Peramban menampilkan | "tidak aman" | gembok |

Saat pembentukan koneksi, TLS menangani semua hal yang telah kamu pelajari di bab ini:

- Server membuktikan identitasnya dengan **sertifikat** (**autentisitas**).
- Kedua pihak menyepakati **kunci sesi** dengan **Diffie-Hellman** — server **menandatangani** bagiannya.
- Setelah itu, semua data dienkripsi dengan **AES** (**kerahasiaan**) dan diamankan dari perubahan (**integritas**).

Prinsip ini tidak terbatas pada web: E-mail (bagian 8.4) dan banyak protokol lain juga berjalan melalui TLS dengan cara yang sama.

Pada bagian-bagian berikut, kamu akan mengamati HTTPS di Tracer, menyiapkannya sendiri, dan menyelidiki kapan peramban memberi peringatan — dan mengapa.
