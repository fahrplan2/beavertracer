# TCP ili UDP?

| | TCP | UDP |
|---|---|---|
| Veza | uspostavljanje pomoću trostrukog handshakea, uredno prekidanje | nema — svaki datagram je samostalan |
| Potvrde | da (`ACK`) | ne |
| Izgubljeni podaci | šalju se ponovo | ostaju izgubljeni |
| Redoslijed | vraća se u ispravan redoslijed | nije zagarantovan |
| Zaglavlje | najmanje 20 bajtova | 8 bajtova |
| Brzina | nešto sporije, više paketa | brzo, malo dodatnog opterećenja |

Kada je manje više?

- **Stvarno vrijeme:** Kod video poziva, internetske telefonije ili online igara svaka milisekunda je bitna. Izgubljeni dio zvuka koji stigne sekundu kasnije više nikome ne koristi — bolje kratko pucketanje nego kašnjenje.
- **Kratki upiti:** **DNS** upit („Koju IP adresu ima `www.beispiel.de`?“) stane u jedan datagram, a isto vrijedi i za odgovor. Uspostavljanje veze utrostručilo bi trud. Ako odgovor ne stigne, program jednostavno pita ponovo.

Svuda gdje svaki bajt mora stići — web stranice, e-pošta, preuzimanja —, TCP je s druge strane pravi izbor.

:::tip Zapamti
**TCP** je pouzdan, ali zahtjevniji — za sve što mora stići **u cijelosti** (web, e-pošta, datoteke). **UDP** je brz i štedljiv, ali bez garancija — za **stvarno vrijeme** (telefonija, video, igre) i **kratke upite** poput DNS-a.
:::

Time poznaješ alate transportnog sloja. U sljedećem poglavlju upoznat ćeš protokole koji se na njemu zasnivaju: HTTP, DNS, e-poštu i DHCP.
