# Povezivanje dviju mreža

:::sim

Ruter ima dva priključka:

| Priključak | IP adresa | Mreža |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Da bi računari koristili ruter, na svakom od njih je upisan **gateway**: kod Anne i Bena `192.168.0.1`, a kod Clare i Davida `172.16.0.1`. Nalazi se u :fa-gear: **IP Postavke** u polju **Gateway**.

:::tip Zapamti
**Gateway** (preciznije: *podrazumijevani gateway*) je IP adresa rutera **u vlastitoj mreži**. Na gateway računar šalje sve pakete čije se odredište nalazi u stranoj mreži.
:::

## Eksperiment

1. Prebaci se u :fa-play: način rada **Pokretanje** i pingaj sa računara **Anna** računar Clara (`ping 172.16.0.10`). Ovaj put uspijeva — obrati pažnju na vrijednost `ttl=` u ispisu.
2. Prebaci se u :fa-magnifying-glass: način rada **Trag** i otvori trag za **Anna**.

Pogledaj prvi paket (ARP zahtjev):

:::quiz multi
Koje tvrdnje o prvom paketu su tačne?
- [x] Anna već poznaje Clarinu IP adresu prije nego što pošalje paket
- [ ] Anna pita za MAC adresu računara Clara
- [x] Anna pita sve uređaje u mreži za MAC adresu rutera
- [ ] Anna pita switch za Clarinu IP adresu
:::

Sada klikni na prvi `Echo (ping) request` i otvori **Ethernet II** i **Internet Protocol Version 4**. Uporedi MAC adrese sa ARP odgovorom koji je prije toga.

:::quiz multi

- [x] Kao odredišna IP adresa upisana je Clara (`172.16.0.10`)
- [ ] Kao odredišna IP adresa upisan je ruter (`192.168.0.1`)
- [x] Kao odredišna MAC adresa upisana je MAC adresa rutera
- [ ] Anna šalje ping direktno na Clarinu MAC adresu
:::

## Šta ruter radi s paketom

Ruter prima okvir od Anne, raspakuje IP paket i pogleda **odredišnu IP adresu**. Po njoj prepoznaje: Clara se nalazi u mreži na `eth1`. Zato paket pakuje u **novi** okvir — s vlastitom MAC adresom kao pošiljaocem i Clarinom MAC adresom kao odredištem — i šalje ga tamo.

| Šta se na ruteru događa s … | |
|---|---|
| MAC adresama (sloj 2)? | postavljaju se **iznova** — vrijede samo u dotičnoj mreži |
| IP adresama (sloj 3)? | **ostaju iste** — od Anne do Clare |
| Time to Live? | smanjuje se za **1** |

:::tip Zapamti
**Ruter** radi na **sloju 3**: pakete prosljeđuje u druge mreže na osnovu **odredišne IP adrese**. IP adrese ostaju iste na cijelom putu, a MAC adrese se u svakoj mreži postavljaju iznova. Svaki ruter smanjuje **Time to Live (TTL)** za 1 — kada dostigne 0, paket se odbacuje. Tako paket ne može beskonačno kružiti.
:::

:::note
Sjećaš li se broadcast oluje iz poglavlja 3.4? Ethernet okviri nemaju TTL — IP paketi imaju.
:::

## Koga Anna poznaje? ARP cache

Sjećaš li se poglavlja 1.2.3? Tamo se ARP pojavljivao samo prije *prvog* pinga, jer je računar zapamtio odgovor. Ta lista zapamćenih adresa zove se **ARP cache** (također *ARP tabela*). Upit se naziva **ARP-Request**, a odgovor **ARP-Reply** (ili *ARP-Response*).

Prebaci se u :fa-play: način rada **Pokretanje**, otvori na računaru **Anna** :fa-terminal: **Terminal** i daj da ti se prikaže njen ARP cache:

```
$ arp
```

:::quiz mc
Šta se nalazi u Anninom ARP cacheu?
- [x] Samo IP adresa rutera (`192.168.0.1`) s njegovom MAC adresom
- [ ] Clarina IP adresa s Clarinom MAC adresom
- [ ] Adrese rutera i računara Clara
:::

:::evaluate
Provjeri odgovor
:::

Anni Clarina MAC adresa nikada nije potrebna: sve što je namijenjeno firmi B šalje ruteru. Clarinu MAC adresu poznaje samo ruter — on ju je na svojoj strani sam saznao putem ARP-a.

:::tip Zapamti
U **ARP cacheu** uređaj pamti koja MAC adresa pripada kojoj IP adresi — tako ne mora prije svakog paketa slati ARP-Request. Prikazuje se naredbom `arp`. Računar poznaje samo MAC adrese iz **vlastite** mreže: za sva odredišta u stranim mrežama koristi MAC adresu rutera.
:::

:::note
U stvarnim mrežama se unosi u ARP cacheu nakon nekog vremena ponovo brišu i po potrebi iznova traže — na primjer ako je uređaj u međuvremenu dobio drugu mrežnu karticu. U BeaverTraceru ostaju sačuvani dok simulacija radi.
:::
