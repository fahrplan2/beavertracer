# Šta mora da obezbijedi transportni sloj?

:::sim
url=/sims/lesson-5.1.btsim
:::

Na **Serveru** istovremeno rade dvije usluge: **web server** i mali **echo servis**, koji odmah vraća svaku poruku koju primi. Pomoću dva eksperimenta otkrit ćeš šta sam IP ne može da obezbijedi.

## Eksperiment 1: Dva programa istovremeno

1. Prebaci se u :fa-play: **Način rada Pokretanje** i klikni na **Client-PC**.
2. Otvori :fa-globe: **Preglednik** i pozovi `http://192.168.0.20/`.
3. Klikni na **Zurück** na vrhu prozora i otvori **Jednostavni TCP klijent**. Pod **Host** upiši `192.168.0.20`, a pod **Port** `5000` i klikni na **Poveži se**.
4. Prebaci se u :fa-magnifying-glass: **Način rada Trag** i pomoću **+** otvori trag za **Client-PC**, priključak `eth0`.

Klikni na paket preglednika (npr. `GET /`) i na paket TCP klijenta te u oba slučaja otvori **Internet Protocol Version 4**.

:::quiz mc
Koje IP adrese nose paketi preglednika i TCP klijenta?
- [x] Kod oba iste: od `192.168.0.10` prema `192.168.0.20`
- [ ] Preglednik koristi drugu odredišnu IP adresu nego TCP klijent
- [ ] Paketi TCP klijenta nemaju IP adresu
:::

:::quiz mc
Je li, dakle, odredišna IP adresa dovoljna da server zna pripada li paket web serveru ili echo servisu?
- [ ] Da
- [x] Ne — oba paketa imaju istu odredišnu IP adresu
:::

Nešto drugo mora razlikovati ove dvije veze. Pogledaj kolonu **Info** kod paketa sa `[SYN]` — to je u svakom slučaju prvi paket jedne veze:

:::quiz short
Koji broj stoji iza strelice `→` kod **preglednika**?
= 80
:::

:::quiz short
A kod **TCP klijenta**?
= 5000
:::

:::evaluate
Provjeri odgovore
:::

Više o ovim brojevima — **portovima** — saznat ćeš u odjeljku 5.3. Za sada je dovoljno znati: tek transportni sloj omogućava da više programa istovremeno komunicira preko *jedne* IP adrese i da svaki paket stigne do pravog programa. To se zove **multipleksiranje**.

## Eksperiment 2: Kada se paket izgubi

1. Prebaci se u :fa-play: **Način rada Pokretanje** i klikni na **kabl** između Client-PC-a i Servera.
2. U prozoru **Verbindung** postavi **Konfigurierten Paketverlust** na `25%`.
3. Na **Client-PC-u** otvori :fa-terminal: **Terminal** i pošalji šest pingova:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Ovo traje otprilike pola minute — sačekaj dok se ne pojavi statistika.

:::quiz mc
Šta se dešava?
- [ ] Na svih šest pingova stiže odgovor
- [x] Neki pingovi ostaju bez odgovora — i niko ih ne šalje ponovo
- [ ] Izgubljeni pingovi se automatski ponavljaju dok ne stignu
:::

:::evaluate
Provjeri odgovor
:::

Kod pinga to nije problem — on upravo treba da pokaže da li se nešto gubi. Ali kod web stranice, e-pošte ili preuzimanja nedostajući dio bio bi fatalan: datoteka bi bila oštećena.

## Četiri zadatka transportnog sloja

| Zadatak | Šta to znači |
|---|---|
| **Multipleksiranje** | Više programa i veza dijeli jednu IP adresu; svaki paket stiže do pravog programa. |
| **Uspostavljanje veze** | Prije nego što podaci poteku, obje strane se dogovore da će međusobno komunicirati. |
| **Pouzdan prijenos** | Primalac potvrđuje šta je stiglo. Ono što nedostaje šalje se ponovo, a redoslijed se uspostavlja. |
| **Raskidanje veze** | Na kraju obje strane uredno prekidaju vezu. |

:::tip Zapamti
**Transportni sloj** (sloj 4) brine o tome da podaci stignu do pravog **programa** (**multipleksiranje**). Protokol **TCP** dodatno osigurava da stignu **potpuni** i **ispravnim redoslijedom** — uz uspostavljanje veze, potvrde, ponovno slanje i raskidanje veze.
:::

:::quiz match
Na jednom računaru istovremeno rade preglednik, program za e-poštu i messenger. -> Multipleksiranje
Prije nego što podaci poteku, obje strane utvrde da je druga spremna. -> Uspostavljanje veze
Dio datoteke ne stigne i šalje se još jednom. -> Pouzdan prijenos
Nakon preuzimanja obje strane ponovo oslobađaju vezu. -> Raskidanje veze
:::
