# TLS handshake

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Prije nego što se pošalje prvi šifrirani zahtjev, klijent i server moraju se dogovoriti: o postupku, o ključu sesije — a klijent mora provjeriti s kim razgovara. Ovo uspostavljanje veze zove se **TLS handshake**.

## Tok u dijagramu

Bez TCP potvrda (`ACK`) handshake izgleda ovako:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Šta se pri tome događa — i koji se gradivni blok iz odjeljka 8.1 krije iza toga:

1. **Client Hello / Server Hello:** Klijent i server se pozdravljaju, razmjenjuju slučajne brojeve i dogovaraju postupke (u BeaverTraceru: razmjena ključeva pomoću **ECDHE**, potpis pomoću **ECDSA**, šifriranje pomoću **AES**).
2. **Certificate:** Server šalje svoj **certifikat**. Klijent provjerava potpis CA, valjanost i ime. Ako to ne uspije, ovdje prekida vezu — a preglednik prikazuje upozorenje.
3. **Server Key Exchange:** Server šalje svoj **Diffie-Hellman dio** — i **potpisuje** ga svojim privatnim ključem. Klijent provjerava potpis javnim ključem iz certifikata. Tako zna: ovaj dio zaista dolazi od vlasnika certifikata, a ne od napadača koji se nalazi između (Man-in-the-Middle).
4. **Client Key Exchange:** Klijent šalje svoj Diffie-Hellman dio. Sada oboje mogu izračunati isti **ključ sesije** — a da on nikada nije bio prenesen.
5. **Change Cipher Spec:** „Od sada šifriram.“
6. **Encrypted Handshake Message (Finished):** Obje strane šalju — već šifriranu — kontrolnu sumu svih dosadašnjih poruka handshakea. Ako je napadač nešto promijenio na putu, kontrolne sume se ne podudaraju i veza se prekida.
7. **Application Data:** Od ovdje teku HTTP podaci — simetrično šifrirani pomoću AES-a.

:::quiz match
Certificate -> Server se predstavlja svojim certifikatom
Server Key Exchange -> Potpisani Diffie-Hellman dio servera
Client Key Exchange -> Diffie-Hellman dio klijenta
Change Cipher Spec -> Od sada se šifrira
Application Data -> Šifrirani HTTP podaci
:::

:::tip Zapamti
Pri **TLS handshakeu** server se predstavlja svojim **certifikatom**, obje strane dogovaraju **ključ sesije** putem **Diffie-Hellmana** (server svoj dio **potpisuje**), a pomoću **Finished** obje provjeravaju da niko nije promijenio handshake. Nakon toga se podaci prenose kao **Application Data**, simetrično šifrirani.
:::
