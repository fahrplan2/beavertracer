# Napad: krivotvorenje DNS-a

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna želi na **Client-PC** otvoriti svoje online bankarstvo kod **Biberbank**. Ono što ona ne zna: neko je dobio pristup **DNS-Server** i izmijenio jedan zapis.

Na radnoj površini vidiš pravi web server **www.biberbank.de** i računar jednog **napadača**. Na njemu radi kopija web stranice banke.

## Dio 1: Bez šifriranja

Pređi u :fa-play: **Način rada Pokretanje** i na **Client-PC** u :fa-globe: **Preglednik** otvori `http://www.biberbank.de/`.

:::quiz mc
Šta vidiš?
- [x] Stranicu za prijavu Biberbank, bez ikakvog upozorenja
- [ ] Upozorenje da je stranica lažna
- [ ] Poruku o grešci
:::

:::evaluate
Provjeri odgovor
:::

Sve izgleda normalno. Ali s kojim serverom preglednik zaista komunicira? Otvori na Client-PC :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Koju IP adresu DNS server vraća za `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Kome pripada ta adresa? (Klikni u načinu rada Uređivanje na uređaje ili pogledaj njihove :fa-gear: **IP Postavke**.)
- [ ] Pravom web serveru Biberbank
- [x] Napadaču
- [ ] DNS serveru
:::

:::evaluate
Provjeri odgovore
:::

Da je Anna sada unijela broj računa i PIN, oni bi završili direktno kod napadača. Kod **HTTP-a** nema **nikakve šanse** da primijeti prevaru: adresna traka prikazuje ispravno ime, a stranica izgleda pravo.

## Dio 2: Sa HTTPS-om

Sada otvori `https://www.biberbank.de/`.

:::quiz mc
Šta se dešava?
- [ ] Lažna stranica se pojavljuje s katancem
- [x] Preglednik upozorava: certifikat je izdat za drugo ime
- [ ] Pojavljuje se prava stranica Biberbank
:::

:::quiz short
Za koje ime je izdat napadačev certifikat (bez `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Provjeri odgovore
:::

Napadač čak ima **pravi** certifikat od pouzdane CA — ali za svoj vlastiti domen `www.biber-gewinnspiel.de`. Certifikat za `www.biberbank.de` ne može dobiti ni od jedne CA, jer taj domen nije njegov. A bez **privatnog ključa** Biberbank ne može koristiti ni njihov pravi certifikat: u handshakeu bi morao njime potpisati Server Key Exchange.

:::quiz multi
Od čega HTTPS ovdje štiti — a od čega ne?
- [x] HTTPS otkriva da server nije pravi
- [ ] HTTPS sprečava krivotvorenje DNS servera
- [x] HTTPS pomaže samo ako korisnik shvati upozorenje ozbiljno
- [ ] Uz HTTPS lažna stranica uopće nije dostupna
:::

:::evaluate
Provjeri odgovore
:::

## Dio 3: Popravak DNS servera

Otvori **DNS-Server** i ispravi zapis za `www.biberbank.de`. Ispravnu adresu nalaziš u :fa-gear: **IP Postavke** web servera **www.biberbank.de**. Ne zaboravi kliknuti na **Spremi**.

:::note
Client-PC pamti DNS odgovore neko vrijeme kako ne bi morao pitati iznova pri svakom pozivu (**DNS cache**). Koliko dugo, piše u koloni **TTL** (*Time to Live*) u sekundama. Ako `nslookup` odmah nakon tvoje ispravke još uvijek vrati staru adresu, sačekaj da istekne TTL i pokušaj ponovo.
:::

:::task
title: Je li Biberbank opet prava?
Provjerava razrješava li Client-PC www.biberbank.de na ispravnu adresu i može li preuzeti stranicu preko HTTPS-a bez upozorenja.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
U stvarnosti napadač rijetko krivotvori sam DNS server. Češće podmeće svoje odgovore u javnoj WLAN mreži, mijenja postavke kućnog rutera ili mami adresom koja izgleda slično, kao što je `www.biberbank-login.de` (**phishing**). Protiv imena koje sliči pravom ne pomaže ni HTTPS — za to napadač dobija valjan certifikat. Zato: pažljivo čitaj adresu!
:::

:::tip Zapamti
Kod **krivotvorenja DNS-a** DNS server za neko ime vraća adresu napadača. Kod **HTTP-a** se to ne primijeti. Kod **HTTPS-a** napadačev certifikat ne odgovara pozvanom imenu i preglednik **upozorava** — jer nijedna CA ne izdaje certifikat za tuđe domene, a privatni ključ pravog servera napadač nema.
:::
