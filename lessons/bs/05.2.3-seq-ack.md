# Sekvencijski i brojevi potvrde

:::sim
url=/sims/lesson-5.1.btsim
:::

Kako TCP zna da li je sve stiglo — i kojim redoslijedom? Svaka strana **numeriše bajtove** koje šalje:

- **Sekvencijski broj** (`SEQ`) je broj prvog bajta koji se nalazi u ovom paketu.
- **Broj potvrde** (`ACK`) kaže: „Do ovdje sam primio sve — sljedeći očekujem bajt br. …“

Uz to dva pravila: `SYN` i `FIN` se računaju kao jedan bajt, iako ne nose podatke. I svaka strana broji za sebe — zato postoje dva niza brojeva, na dijagramu crveni (klijent) i plavi (server).

## Provjera računom

Evo ponovo tvoje veze. Brojevi na linijama prikazuju brojač računara na tom mjestu:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Prođi kroz crveni niz brojeva:

1. Klijent počinje od `SEQ=0`. Njegov `SYN` troši jedan broj — server potvrđuje s `ACK=1`.
2. Poruka počinje od `SEQ=1` i duga je 13 bajtova (bajtovi od 1 do 13). Server potvrđuje s `ACK=14`: „Sljedeći očekujem bajt 14.“
3. `FIN` klijenta zato ima `SEQ=14` i potvrđuje se s `ACK=15`.

Plavi niz servera funkcioniše na isti način.

:::tip Zapamti
**Sekvencijski broj** (`SEQ`) je broj prvog bajta u paketu. **Broj potvrde** (`ACK`) je broj sljedećeg bajta koji primalac očekuje — sve prije toga je stiglo. Vrijedi: **ACK = SEQ + dužina** primljenih podataka; `SYN` i `FIN` se računaju kao jedan bajt. Svaka strana broji svoje vlastite bajtove.
:::

:::tip Isprobaj
Ponovo uspostavi vezu u **Jednostavni TCP klijent** i pošalji dvije poruke jednu za drugom. Prije toga reci koji će `Seq` i `Ack` biti u koloni **Info** — i provjeri to u tragu.
:::

:::note
U stvarnim mrežama brojanje ne počinje od 0: svaka strana bira **nasumični početni broj** (*Initial Sequence Number*, ISN) između 0 i otprilike 4,3 milijarde. Kada se dostigne najveći broj, nastavlja se ponovo od 0. Tracer oduzima početni broj i prikazuje **relativne** brojeve — baš kao Wireshark. Zato vidiš `Seq=0` i `Seq=1`.

Osim toga, u svakom paketu se nalazi `Win=` — **veličina prozora**: toliko bajtova primalac trenutno može primiti. Time koči prebrzog pošiljaoca (*kontrola toka*). U BeaverTraceru je prozor uvijek iste veličine.
:::
