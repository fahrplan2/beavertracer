# Rünne: DNS-i võltsimine

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna soovib **Client-PC** arvutis avada oma internetipanga **Biberbank**. Mida ta ei tea: keegi on pääsenud ligi **DNS-serverile** ja muutnud ühte kirjet.

Tööalal näed Biberbanki päris veebiserverit **www.biberbank.de** ja **ründaja** arvutit. Selles töötab pangaveebilehe koopia.

## Osa 1: Ilma krüpteerimiseta

Lülitu :fa-play: **Käivitusrežiimi** ja ava arvutis **Client-PC** :fa-globe: **Brauser** abil `http://www.biberbank.de/`.

:::quiz mc
Mida sa näed?
- [x] Biberbanki sisselogimislehte, ilma ühegi hoiatuseta
- [ ] Hoiatust, et leht on võltsitud
- [ ] Veateadet
:::

:::evaluate
Kontrolli vastust
:::

Kõik näeb normaalne välja. Aga millise serveriga brauser tegelikult suhtleb? Ava arvutis Client-PC :fa-terminal: **Terminalis**:

```
$ nslookup www.biberbank.de
```

:::quiz short

:::

:::quiz mc
Kellele see aadress kuulub? (Klõpsa redigeerimisrežiimis seadmetel või vaata nende :fa-gear: **IP-seadistusi**.)
- [ ] Biberbanki päris veebiserverile
- [x] Ründajale

:::

:::evaluate
Kontrolli vastuseid

Kui Anna oleks nüüd sisestanud kontonumbri ja PIN-koodi, oleksid need läinud otse ründajale. **HTTP** puhul pole tal **mingit võimalust** pettust märgata: aadressiribal on õige nimi ja leht näeb ehtne välja.

## Osa 2: HTTPS-iga

Ava nüüd `https://www.biberbank.de/`.

:::quiz mc
Mis juhtub?
- [ ] Võltsitud leht ilmub lukuga
- [x] Brauser hoiatab: sertifikaat on välja antud teisele nimele
- [ ] Ilmub Biberbanki päris leht
:::

:::quiz short
Millisele nimele on ründaja sertifikaat välja antud (ilma `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Kontrolli vastuseid
:::

Ründajal on isegi usaldusväärse CA **ehtne** sertifikaat – aga tema enda domeenile `www.biber-gewinnspiel.de`. Sertifikaati domeenile `www.biberbank.de` ei anna talle ükski CA, sest see domeen ei kuulu temale. Ja ilma Biberbanki **privaatvõtmeta** ei saa ta kasutada ka panga ehtsat sertifikaati: käepigistuses peaks ta selle abil Server Key Exchange'i allkirjastama.

:::quiz multi
Millise ohu eest HTTPS siin kaitseb – ja millise eest mitte?
- [x] HTTPS paljastab, et server ei ole ehtne
- [ ] HTTPS takistab DNS-serveri võltsimist
- [x] HTTPS aitab ainult siis, kui kasutaja võtab hoiatust tõsiselt
- [ ] HTTPS-i korral ei ole võltsitud leht üldse kättesaadav
:::

:::evaluate
Kontrolli vastuseid
:::

## Osa 3: DNS-serveri parandamine

Ava **DNS-server** ja paranda kirje nimele `www.biberbank.de`. Õige aadressi leiad veebiserveri **www.biberbank.de** :fa-gear: **IP-seadistustest**. Ära unusta klõpsata nupul **Salvesta**.

:::note
Client-PC jätab DNS-vastused mõneks ajaks meelde, et ei peaks igal päringul uuesti küsima (**DNS-vahemälu**). Kui kaua, näitab veerg **TTL** (*Time to Live*) sekundites. Kui `nslookup` annab pärast sinu parandust endiselt vana aadressi, oota TTL-i möödumist ja proovi uuesti.
:::

:::task
title: Kas Biberbank on jälle ehtne?
Kontrolli, kas Client-PC lahendab nime www.biberbank.de õigele aadressile ja kas lehte saab HTTPS-i kaudu ilma hoiatuseta laadida.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Päriselus võltsib ründaja harva DNS-serverit ennast. Sagedamini lisab ta oma vastuseid avalikus WiFi-võrgus, muudab kodise ruuteri seadistusi või meelitab ligi sarnase aadressiga, näiteks `www.biberbank-login.de` (**andmepüük**). Sarnaselt kõlava nime vastu ei aita ka HTTPS – ründaja saab selle jaoks kehtiva sertifikaadi. Seepärast: loe aadressi hoolikalt!
:::

:::tip Pea meeles
**DNS-i võltsimise** korral annab DNS-server nimele ründaja aadressi. **HTTP** puhul ei märka sellest midagi. **HTTPS** puhul ei sobi ründaja sertifikaat kutsutud nimega ja brauser **hoiatab** – sest võõraste domeenide sertifikaate ei anna välja ükski CA ning ehtsa serveri privaatvõtit ründajal ei ole.
:::
