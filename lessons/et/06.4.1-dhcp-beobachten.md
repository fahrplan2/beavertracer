## Mis selle taga on: DORA

Aadressita seade ei tea, kus DHCP-server asub, ning tal pole ka oma saatja aadressi. Seepärast hõikab ta **leviedastusega** (broadcast) võrku. Protsessil on neli sammu — nende algustähtede järgi **DORA**:

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | „Kas siin on DHCP-server?“
DHCP-Server -> Laptop 1: DHCP Offer | „Sa võid saada aadressi 192.168.0.100.“
Laptop 1 -> DHCP-Server: DHCP Request | „Ma võtan aadressi 192.168.0.100.“
DHCP-Server -> Laptop 1: DHCP ACK | „Kinnitatud — kehtib 3600 sekundit.“
:::

Aadress on ainult **laenatud** (*lease*): pärast **laenuaja** (lease-aja) lõppu peab seade seda pikendama, vastasel juhul tohib server selle uuesti välja anda. Millised aadressid on parajasti välja laenatud, näed **DHCP-serveris** vahelehel **Leases**.

:::tip Proovi järele
Sea ka **Laptop 2** DHCP peale. Millise aadressi ta saab? Vaata pärast DHCP-serveri **Leases** vahelehte.
:::

:::tip Pea meeles
**DHCP** jagab IP-aadressi, võrgumaski, lüüsi ja DNS-serveri automaatselt. Protsessi nimi on **DORA**: **D**iscover (klient otsib leviedastusega), **O**ffer (server pakub), **R**equest (klient võtab pakkumise vastu), **A**CK (server kinnitab). Aadress on laenatud **laenuajaks** (lease-ajaks). DHCP kasutab **UDP**-d, porti 67 (server) ja 68 (klient).
:::

:::quiz match
Discover -> Klient otsib leviedastusega DHCP-serverit
Offer -> Server pakub aadressi
Request -> Klient nõuab pakutud aadressi
ACK -> Server kinnitab aadressi andmise
:::
