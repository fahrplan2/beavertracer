## Milline päring välja näeb

Klõpsa jälgimises paketil `GET / HTTP/1.1` ja ava **Hypertext Transfer Protocol**. HTTP-päring on puhas tekst:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

Serveri vastus on üles ehitatud samamoodi — olekurea, päiste, tühja rea ja seejärel tegeliku failiga:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP-päring
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP-päring
Server -> Client-PC: 200 OK | style.css
:::

## Meetodid ja olekukoodid

**Meetod** ütleb, mida klient soovib:

| Meetod | Tähendus |
|---|---|
| **GET** | faili pärimine |
| **POST** | andmete saatmine serverisse, nt täidetud vorm |
| **HEAD** | ainult päiste pärimine ilma failita |

**Olekukood** ütleb, kuidas läks. Esimene number reedab vastuse liigi:

| Kood | Tekst | Tähendus |
|---|---|---|
| **200** | OK | kõik on korras |
| **301** | Moved Permanently | leht on jäädavalt ümber kolinud |
| **404** | Not Found | sellist faili pole |
| **405** | Method Not Allowed | see meetod pole siin lubatud |
| **500** | Internal Server Error | viga serveris |

`2xx` tähendab edu, `3xx` ümbersuunamist, `4xx` kliendi viga (vale päring), `5xx` serveri viga.

:::tip Pea meeles
**HTTP** töötab **päringu-vastuse põhimõttel**: klient saadab **päringu** (meetod nagu `GET`, tee, päised), server vastab **olekukoodiga** (nt `200 OK`, `404 Not Found`), päiste ja failiga. Veebilehe iga faili jaoks on eraldi päring.
:::
