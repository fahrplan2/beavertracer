# UDP jälgimine

:::sim
url=/sims/lesson-5.5.btsim
:::

**Serveris** töötab seekord **UDP Echo-Server** pordil `5000`. Ka siin on kaabel ette valmistatud: **teine datagramm** klient-arvutilt serverile läheb kaduma.

## Katse

1. Lülitu :fa-play: **Käivita**-režiimi (käivitusrežiimi) ja ava **Client-PC** peal :fa-terminal: **Terminalis**.
2. Loo `nc` abil UDP „ühendus“ serveriga (`-u` tähendab UDP-d):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Trüki järjest `eins`, `zwei` ja `drei` ning vajuta iga kord **Enter**. Iga tagasi tulev rida on serveri kaja.
4. Oota paar sekundit ja ava siis :fa-magnifying-glass: **Jälgi**-režiimis jälg **Client-PC** jaoks.

:::quiz mc
Millised kajad tulevad tagasi?
- [ ] Kõik kolm, `zwei` veidi hiljem
- [x] Ainult `eins` ja `drei` — `zwei` puudub ja seda ei saadeta ka uuesti
- [ ] Mitte ühtegi
:::

:::quiz multi
Millised TCP-st tuttavad paketid puuduvad UDP puhul täielikult?

:::evaluate
Kontrolli vastuseid
:::

Klõpsa ühel UDP-paketil ja ava **User Datagram Protocol**. TCP-päisega võrreldes on UDP-päis pisike: **Source Port**, **Destination Port**, **Length** (pikkus) ja **Checksum** (kontrollsumma) — kokku ainult 8 baiti. TCP-päis on vähemalt 20 baiti pikkune, sisaldades järje- ja kinnitusnumbrit, lippe ja akna suurust.

:::quiz mc

- [x] Multipleksimine — portide kaudu
- [ ] Ühenduse loomine
- [ ] Usaldusväärne edastus
:::

:::evaluate
Kontrolli vastust
:::

:::tip Pea meeles
**UDP** on **ühenduseta**: pole loomist, pole kinnitust, pole uuesti edastamist, pole järjekorda. See pakub ainult **porte** (multipleksimine) ja **kontrollsummat**. Selle eest on see kiire ja kerge — UDP-päis on ainult 8 baiti pikk. Kui datagramm läheb kaduma, peab programm sellega ise tegelema — või on see talle ükskõik.
:::
