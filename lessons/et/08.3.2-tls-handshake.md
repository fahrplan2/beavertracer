# TLS-handshake

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Enne kui esimene krüpteeritud päring saadetakse, peavad klient ja server omavahel kokku leppima: meetodis, seansivõtmes – ning klient peab kontrollima, kellega ta räägib. Seda ühenduse loomist nimetatakse **TLS-handshake'iks**.

## Kulg diagrammil

Ilma TCP kinnitusteta (`ACK`) näeb handshake välja selline:

:::seq
mode: text
Client -> Server: Client Hello | juhuarv, võimalikud meetodid
Server -> Client: Server Hello | valitud meetod, juhuarv
Server -> Client: Certificate | serveri sertifikaat
Server -> Client: Server Key Exchange | DH-osa, allkirjastatud
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | kliendi DH-osa
Client -> Server: Change Cipher Spec | edaspidi krüpteeritult
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | edaspidi krüpteeritult
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (krüpteeritud)
Server -> Client: Application Data | veebileht (krüpteeritud)
:::

Mis siin toimub – ja milline jaotise 8.1 ehituskivi selle taga on:

1. **Client Hello / Server Hello:** klient ja server tervitavad teineteist, vahetavad juhuarve ning lepivad kokku meetodites (BeaverTraceris: võtmevahetus **ECDHE**-ga, allkiri **ECDSA**-ga, krüpteerimine **AES**-iga).
2. **Certificate:** server saadab oma **sertifikaadi**. Klient kontrollib CA allkirja, kehtivust ja nime. Kui see ebaõnnestub, katkestab ta siin – ja brauser kuvab hoiatuse.
3. **Server Key Exchange:** server saadab oma **Diffie-Hellmani osa** – ja **allkirjastab** selle oma privaatvõtmega. Klient kontrollib allkirja sertifikaadis oleva avaliku võtmega. Nii teab ta: see osa tuleb tõepoolest sertifikaadi omanikult, mitte man-in-the-middle ründajalt.
4. **Client Key Exchange:** klient saadab oma Diffie-Hellmani osa. Nüüd saavad mõlemad arvutada sama **seansivõtme** – ilma et seda oleks kunagi edastatud.
5. **Change Cipher Spec:** „Edaspidi krüpteerin.“
6. **Encrypted Handshake Message (Finished):** mõlemad pooled saadavad – juba krüpteerituna – kontrollsumma kõigi seniste handshake'i sõnumite kohta. Kui ründaja on teel midagi muutnud, kontrollsummad ei klapi ja ühendus katkestatakse.
7. **Application Data:** siit alates liiguvad HTTP-andmed – sümmeetriliselt AES-iga krüpteeritult.

:::quiz match
Certificate -> Server tõendab end oma sertifikaadiga
Server Key Exchange -> Serveri allkirjastatud Diffie-Hellmani osa
Client Key Exchange -> Kliendi Diffie-Hellmani osa
Change Cipher Spec -> Edaspidi krüpteeritakse
Application Data -> Krüpteeritud HTTP-andmed
:::

:::note
Trace'is näed **kahte** TLS-ühendust üksteise järel: brauser laadib esmalt lehe ja loob siis uue ühenduse laadilehe `style.css` jaoks. Iga ühendus saab oma handshake'i ja oma seansivõtme. Päris brauserid hoiavad ühendusi lahti ja säästavad nii osa sellest vaevast. Uuem versioon **TLS 1.3** vajab lisaks vähem sõnumeid kui siin näidatud TLS 1.2.
:::

:::tip Pea meeles
**TLS-handshake'i** käigus tõendab server end oma **sertifikaadiga**, mõlemad pooled lepivad **Diffie-Hellmani** abil kokku **seansivõtmes** (server **allkirjastab** oma osa) ning **Finished**-sõnumiga kontrollivad mõlemad, et keegi pole handshake'i muutnud. Pärast seda edastatakse andmed **Application Data**-na sümmeetriliselt krüpteerituna.
:::
