# IPv6 võrgus

:::sim
url=/sims/lesson-4.6.3.btsim

Switchi küljes on Anna, Ben ja ruuter. Annal ja Benil on IPv6 seatud režiimile **SLAAC (automatisch)** — IPv6-aadressi pole neile keegi sisestanud. Ruuter tunneb prefiksit `2001:db8:1::/64`.

## Kust aadress tuleb?

1. Lülitu :fa-play: **Käivita**-režiimile ja oota paar sekundit.
2. Ava **Anna** juures :fa-terminal: **Terminalis** ja sisesta `ip a`.

IPv4-aadressi kõrval näed kahte `inet6`-rida: üks aadress on `scope link` ja teine `scope global`.

:::quiz mc
Kumb kahest IPv6-aadressist on lingikohalik aadress (link-local)?
- [x] See, mis algab `fe80::` (`scope link`)
- [ ] See, mis algab `2001:db8:1:` (`scope global`)
:::

:::quiz mc
Kust tuleb globaalse aadressi prefiks `2001:db8:1:0`?
- [ ] Anna mõtles selle ise välja
- [x] Ruuterilt — see kuulutab prefiksi võrgus välja
- [ ] Switchilt
:::

:::evaluate
Kontrolli vastuseid

Võrdle **liidese ID-d** (viimased neli plokki) Anna **MAC-aadressiga** — selle leiad :fa-gear: **IP-seadistused** kõige alt. MAC-aadressist `aa:28:39:e2:41:82` saab näiteks liidese ID `a828:39ff:fee2:4182`: keskele lisatakse `ff:fe` ja alguses pööratakse ümber üks bitt (seepärast saab `aa`-st `a8`).

Seda meetodit nimetatakse **SLAAC** (*Stateless Address Autoconfiguration*): ruuter kuulutab välja prefiksi, liidese ID moodustab iga seade ise.

:::note
Kuna MAC-aadress tähistab seadet üheselt, oleks seadet liidese ID järgi võimalik kõikjal internetis ära tunda. Päris seadmed kasutavad seetõttu tavaliselt lisaks juhuslikke liidese ID-sid, mis regulaarselt muutuvad (*Privacy Extensions*) — see on tükike andmekaitset.
:::

## Naabrite leidmine — ilma ARP-ita

1. Sisesta **Beni** juures `ip a` ja jäta meelde tema **globaalne** IPv6-aadress.
2. Tee **Anna** juurest talle ping, näiteks `ping 2001:db8:1:0:…` (Beni täieliku aadressiga).
3. Lülitu :fa-magnifying-glass: **Jälgi**-režiimile ja ava **Anna** jälg.

Vaata pakette vahetult enne esimest `Echo (ping) request`-i.

:::quiz multi
Millised väited on õiged?
- [x] ARP-päringu asemel saadab Anna **Neighbor Solicitation**-i („Kellel on see aadress?“)
- [x] Ben vastab **Neighbor Advertisement**-iga ja teatab oma MAC-aadressi
- [x] Päring läheb multicast-aadressile (`ff02::1:ff…`), mitte kõigile leviedastusena
- [ ] Anna saadab ARP-päringu nagu IPv4 puhul
- [x] Ruuter saadab regulaarselt **Router Advertisement**-e aadressile `ff02::1` — neis on prefiks
:::

:::tip Pea meeles
IPv6 puhul täidab ARP-i ülesandeid **NDP** (*Neighbor Discovery Protocol*, ICMPv6 osa): **Neighbor Solicitation**-i ja **Neighbor Advertisement**-i abil leiavad seadmed oma naabrite MAC-aadressid. **Router Advertisement**-idega kuulutab ruuter välja prefiksi — sellest moodustavad seadmed **SLAAC**-i abil ise oma aadressi.
:::
