# Reading e-mail in the tracer

:::sim
url=/sims/lesson-6.3.btsim
:::

Like HTTP, SMTP is a **text protocol**. Look at everything that goes over the line in plain text.

## The experiment

1. In :fa-play: **Run** mode, send a mail from **Anna** to `ben@biber-mail.de`, as on the last page.
2. In :fa-magnifying-glass: **Trace** mode, open a trace for **Anna**. The **Info** column shows the SMTP dialogue: lines with `C:` are sent by the client, lines with `S:` by the server.

:::quiz short
Which address comes after `MAIL FROM:`?
= anna@beaver-schule.de
= <anna@beaver-schule.de>
:::

:::quiz short
And which one after `RCPT TO:`?
= ben@biber-mail.de
= <ben@biber-mail.de>
:::

:::quiz mc
Which number code does the server send when it accepts a command?
- [x] `250`
- [ ] `200`
- [ ] `404`
:::

:::evaluate
Check answers
:::

## And the password?

Before `MAIL FROM`, Anna's program logs in with `AUTH PLAIN` and a string like `AGFubmEAZ2VoZWlt`. That looks encrypted, but it isn't: it's only **Base64**, an encoding that anyone can translate back immediately — inside are `anna` and her password `geheim`.

Now collect the mail at **Ben** (**Fetch**) and open a trace for **Ben**. When collecting via IMAP it's even more obvious:

:::quiz short
Which password does Ben's mail program send to the server in plain text? (Look at the line with `LOGIN`.)
= biber123
:::

:::evaluate
Check answer
:::

:::warning
Without encryption, anyone who records the traffic can read **content, sender, recipient and passwords**. That's why encrypted variants are used today (e.g. SMTP with STARTTLS, IMAPS on port 993). How that works you'll learn in chapter 8.
:::

:::tip Key point
**SMTP**, **POP3** and **IMAP** are text protocols: commands like `MAIL FROM`, `RCPT TO`, `DATA` (SMTP) or `LOGIN` (IMAP) and the answers are readable. Without encryption, even **passwords** go over the line in plain text (or only Base64-encoded).
:::
