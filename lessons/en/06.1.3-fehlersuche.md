# Troubleshooting: the contact page is missing

:::sim
url=/sims/lesson-6.1.3.btsim
:::

The school office reports: "On our website, the link **Kontakt** (contact) only leads to an error message." The contact page is supposed to be reachable at `http://192.168.0.20/kontakt.html`. Find the fault and fix it.

<details>
<summary>Tip 1: What does the server report?</summary>

Load the contact page in the browser or with `curl -v`. Which status code comes back? The error page also tells you where the server looked for the file.
</details>

<details>
<summary>Tip 2: Where are the files?</summary>

The web server only delivers files from its **Document Root** — that's shown in the **HTTP-Server** app. On the **Server**, use `ls` in the terminal to look at what's there, and look for the contact page in `/home` too.
</details>

<details>
<summary>Tip 3: Moving a file</summary>

With `mv` you move a file: `mv <source> <target folder>`.
</details>

:::task
title: Contact page repaired?
Checks whether the contact page is in the web server's Document Root.
check: fileExists(2, "/var/www/kontakt.html")
:::

## What was going on?

:::quiz multi
Which statements are true?
- [x] The server answered with `404 Not Found`
- [x] The file was in `/home` instead of the Document Root `/var/www`
- [ ] The web server wasn't started at all
- [ ] The browser used the wrong IP address
:::

:::evaluate
Check answer
:::

:::tip Key point
A **404** means: the web server is running and reachable, but the requested **file** doesn't exist under this path. The server only looks in its **Document Root** (here `/var/www`). Compare: if the server doesn't answer at all or answers with `RST`, the problem is deeper — with the network or with the service itself (chapter 5.3.2).
:::
