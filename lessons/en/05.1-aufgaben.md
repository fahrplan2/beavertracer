# What does the transport layer have to do?

:::sim
url=/sims/lesson-5.1.btsim
:::

Two services run on the **Server** at the same time: a **web server** and a small **echo service**, which immediately sends back every message it receives. With two experiments you'll find out what IP alone can't do.

## Experiment 1: Two programs at once

1. Switch to :fa-play: **Run** mode and click the **Client-PC**.
2. Open the :fa-globe: **Browser** and load `http://192.168.0.20/`.
3. Click **Back** at the top of the window and open the **Simple TCP Client**. Enter `192.168.0.20` under **Host** and `5000` under **Port** and click **Connect**.
4. Switch to :fa-magnifying-glass: **Trace** mode and use **+** to open a trace for the **Client-PC**, port `eth0`.

Click a packet from the browser (e.g. `GET /`) and one from the TCP client and expand **Internet Protocol Version 4** each time.

:::quiz mc
Which IP addresses do the packets of the browser and the TCP client carry?
- [x] The same for both: from `192.168.0.10` to `192.168.0.20`
- [ ] The browser uses a different destination IP address than the TCP client
- [ ] The TCP client's packets have no IP address
:::

:::quiz mc
So is the destination IP address enough for the server to know whether a packet belongs to the web server or to the echo service?
- [ ] Yes
- [x] No — both packets have the same destination IP address
:::

Something else has to tell the two connections apart. Look at the **Info** column of the packets with `[SYN]` — that's the first packet of each connection:

:::quiz short
Which number comes after the arrow `→` for the **browser**?
= 80
:::

:::quiz short
And for the **TCP client**?
= 5000
:::

:::evaluate
Check answers
:::

You'll learn more about these numbers — the **ports** — in section 5.3. For now it's enough to know: only the transport layer makes it possible for several programs to communicate over *one* IP address at the same time, with every packet ending up at the right program. This is called **multiplexing**.

## Experiment 2: When a packet gets lost

1. Switch to :fa-play: **Run** mode and click the **cable** between the Client-PC and the Server.
2. In the **Connection** window, set the **Configured packet loss** to `25%`.
3. Open the :fa-terminal: **Terminal** on the **Client-PC** and send six pings:
   ```
   $ ping -c 6 192.168.0.20
   ```
   This takes about half a minute — wait until the statistics appear.

:::quiz mc
What happens?
- [ ] All six pings are answered
- [x] Some pings stay unanswered — and nobody sends them again
- [ ] Lost pings are automatically repeated until they arrive
:::

:::evaluate
Check answer
:::

For a ping that's no problem — its very purpose is to show whether something gets lost. But for a web page, an e-mail or a download a missing piece would be fatal: the file would be broken.

## The four jobs of the transport layer

| Job | What it means |
|---|---|
| **Multiplexing** | Several programs and connections share one IP address; every packet ends up at the right program. |
| **Connection setup** | Before data flows, both sides agree that they're talking to each other. |
| **Reliable transmission** | The receiver confirms what has arrived. Missing data is sent again, the order is restored. |
| **Connection teardown** | At the end, both sides close the connection in an orderly way. |

:::tip Key point
The **transport layer** (layer 4) makes sure that data arrives at the right **program** (**multiplexing**). In addition, the protocol **TCP** makes sure that it arrives **completely** and in the **right order** — with connection setup, acknowledgements, retransmission and connection teardown.
:::

:::quiz match
A browser, a mail program and a messenger run on a PC at the same time. -> Multiplexing
Before data flows, both sides make sure the other one is ready. -> Connection setup
Part of a file doesn't arrive and is sent once more. -> Reliable transmission
After the download, both sides release the connection again. -> Connection teardown
:::
