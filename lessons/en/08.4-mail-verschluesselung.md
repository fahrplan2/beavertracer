# Sending E-Mail Encrypted

:::sim
url=/sims/lesson-8.4.btsim
:::

In section 6.3.2 you saw that with SMTP and POP3, sender, recipient, content and even the password travel readably over the wire. TLS can secure this just like HTTP. For e-mail there are two ways:

| | **Implicit TLS** | **STARTTLS** |
|---|---|---|
| Sequence | The connection is encrypted from the very first second. | The connection starts unencrypted; the client sends the command `STARTTLS`, then encryption begins. |
| Ports | own ports: **SMTPS 465**, **POP3S 995**, **IMAPS 993** | the normal ports, e.g. SMTP 25 or 587 |

The "S" in SMTPS, POP3S and IMAPS stands — as in HTTPS — for *secure*.

## Switching to encrypted ports

Open the **Settings** in Anna's mail program:

- **Incoming:** port `995` and tick **TLS**
- **Outgoing (SMTP):** port `465` and SMTP encryption **Implicit TLS**

## What transport encryption doesn't protect

TLS only encrypts the **path** between two computers: from Anna to the mail server and — if both mail servers support it — from mail server to mail server. **On the mail servers** themselves, however, the mail is stored in plain text. Anyone with access to a mail server can read all mails on it.

If only the recipient should be able to read a mail, it has to be encrypted **end-to-end**: the sender encrypts with the recipient's public key, and only the recipient decrypts it again. For e-mail there are the methods **S/MIME** and **OpenPGP**; messengers like Signal or WhatsApp do this automatically.

:::

:::tip Key point
E-mail is transferred encrypted with **TLS** — either with **implicit TLS** on its own ports (**SMTPS 465**, **POP3S 995**, **IMAPS 993**) or via **STARTTLS** on the normal ports. This is **transport encryption**: it protects the path, but not the mail on the server. That requires **end-to-end encryption**.
:::
