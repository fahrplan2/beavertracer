# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) is ordinary HTTP — except that it doesn't run directly over TCP but through an encrypted layer in between: **TLS** (*Transport Layer Security*). The predecessor of TLS was called **SSL**; that's why people often still speak of "SSL certificates".

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP doesn't notice any of this: it sends its requests as usual, TLS encrypts them, TCP transports them. In the OSI model TLS sits between the transport and application layers, i.e. in layer 4/5 — it builds on TCP and manages a secured session.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Address | `http://…` | `https://…` |
| Content readable in the tracer? | yes | no |
| Browser shows | "not secure" | padlock |

During connection setup, TLS does everything you've learned in this chapter:

- The server identifies itself with its **certificate** (**authenticity**).
- Both sides negotiate a **session key** with **Diffie-Hellman** — the server **signs** its share.
- After that, all data is encrypted with **AES** (**confidentiality**) and protected against changes (**integrity**).

The principle isn't limited to the web: e-mail (section 8.4) and many other protocols run through TLS in the same way.

In the following sections you observe HTTPS in the tracer, set it up yourself and examine when the browser warns — and why.
