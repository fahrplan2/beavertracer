# Observing UDP

:::sim

This time a **UDP Echo-Server** runs on port `5000` on the **Server**. Here too the cable is prepared: the **second datagram** from the Client-PC to the Server gets lost.

## The experiment

1. Switch to :fa-play: **Run** mode and open the :fa-terminal: **Terminal** on the **Client-PC**.
2. Use `nc` to start a UDP "connection" to the server (`-u` stands for UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Type `eins`, `zwei` and `drei` one after the other and press **Enter** each time. Every line that comes back is an echo from the server.
4. Wait a few seconds and then, in :fa-magnifying-glass: **Trace** mode, open a trace for the **Client-PC**.

:::quiz mc
Which echoes come back?
- [ ] All three, `zwei` a little later
- [x] Only `eins` and `drei` — `zwei` is missing and isn't sent again either
- [ ] None at all
:::

:::quiz multi
Which packets you know from TCP are completely missing with UDP?
- [x] Connection setup (`SYN`)
- [x] Acknowledgements (`ACK`)
- [x] Connection teardown (`FIN`)
- [ ] Packets with port numbers
:::

:::evaluate
Check answers
:::

Click one of the UDP packets and expand **User Datagram Protocol**. Compared to the TCP header, the UDP header is tiny: **Source Port**, **Destination Port**, **Length** and **Checksum** — just 8 bytes together. A TCP header has at least 20 bytes, with sequence and acknowledgement number, flags and window size.

:::quiz mc
Which job from section 5.1 does UDP still do?
- [x] Multiplexing — via the ports
- [ ] Connection setup
- [ ] Reliable transmission
:::

:::evaluate
Check answer
:::

:::tip Key point
**UDP** is **connectionless**: no setup, no acknowledgement, no retransmission, no order. It only offers **ports** (multiplexing) and a **checksum**. In return it's fast and lean — the UDP header has only 8 bytes. If a datagram gets lost, the program has to deal with it itself — or it doesn't care.
:::
