# Project: a company with four sites

:::sim
url=/sims/lesson-4.5.4.btsim
:::

A company has its headquarters in **Hanau** and branches in **Kassel**, **Gießen** and **Darmstadt**. Every site has its own network and its own router. All routers are connected via leased lines to a **central network**, where the company's main server also sits.

## The address plan

The administrator assigned the addresses according to the following scheme — they're already entered in the simulation:

| Network | Address range |
|---|---|
| Central network | `10.19.0.0/24` |
| Hanau | `10.19.1.0/24` |
| Kassel | `10.19.2.0/24` |
| Gießen | `10.19.3.0/24` |
| Darmstadt | `10.19.4.0/24` |

| Device | in the central network | in the site network |
|---|---|---|
| Server | `10.19.0.10` | — |
| Router Hanau | `10.19.0.1` | `10.19.1.1` |
| Router Kassel | `10.19.0.2` | `10.19.2.1` |
| Router Gießen | `10.19.0.3` | `10.19.3.1` |
| Router Darmstadt | `10.19.0.4` | `10.19.4.1` |
| PC at the site | — | `.2` each (e.g. PC Kassel `10.19.2.2`) |

On all routers, `eth0` points into the central network and `eth1` into the site network.

## Your assignment

For all the company's computers to reach each other and the server, two things are still missing:

1. **Gateways:** enter a gateway on all four PCs and on the server. The PCs use the router of their site; the server uses **Router Hanau**.
2. **Routing tables:** add the routes that are still missing on all four routers. Every router has to know the networks of the **three other** sites.

Test along the way with `ping` and `traceroute`.

<details>
<summary>Tip: What does a route look like here?</summary>

An example for **Router Kassel**: packets for Gießen (`10.19.3.0/24`) go to Router Gießen in its central network — so **Next Hop** `10.19.0.3`, **Iface** `eth0`. Following this pattern, every router needs three routes.
</details>
