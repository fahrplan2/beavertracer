# Troubleshooting: Certificate Warnings

:::sim
url=/sims/lesson-8.3.4.btsim
:::

The school network has three more web servers: the **canteen** (*Mensa*), the **library** (*Bibliothek*) and the **sports club** (*Sport-AG*). All three speak HTTPS — yet the **Client-PC**'s browser shows a warning for each of them. The Client-PC trusts the **Schul-CA**.

## Investigate

Switch to :fa-play: **Run** mode and load these one after the other on the **Client-PC**:

- `https://mensa.beaver-schule.de/`
- `https://bibliothek.beaver-schule.de/`
- `https://sport.beaver-schule.de/`

Read the warning and the certificate details each time (subject, issuer, valid until).

:::quiz match
mensa.beaver-schule.de -> The certificate has expired
bibliothek.beaver-schule.de -> The certificate is self-signed, the client doesn't trust it
sport.beaver-schule.de -> The certificate was issued for a different name
:::

:::evaluate
Check matches
:::

:::quiz short
Which name was the sports club's certificate issued for (without `CN=`)?
= www.beaver-schule.de
:::

:::evaluate
Check answer
:::

## Fixing the canteen

The canteen is fixed fastest: its certificate was issued by the Schul-CA — it has just expired. To keep things simple, the Schul-CA is stored right on the canteen server here.

<details>
<summary>Tip 1: Issue a new certificate</summary>

Open the :fa-shield-halved: **Certificate Manager** on **mensa.beaver-schule.de**. In the **Sign** tab you can have the Schul-CA **re-sign** the existing certificate — it gets a new validity period. Save it under a new file name, e.g. `mensa-neu.cert.json`.
</details>

<details>
<summary>Tip 2: Use the new certificate</summary>

In the canteen's **HTTP-Server**: **Stop**, select the new certificate in the **HTTPS** tab (recognisable by its file name), **Use**, **Start**.
</details>

:::task
title: Canteen securely reachable again?
Checks whether the Client-PC can fetch https://mensa.beaver-schule.de/ without a certificate warning.
check: httpsOk(2, "https://mensa.beaver-schule.de/")
:::

## And the other two?

:::quiz mc
How do you fix the **library**'s problem properly?
- [ ] Every student clicks "Proceed anyway"
- [x] The library gets a certificate for `bibliothek.beaver-schule.de` issued by the Schul-CA
- [ ] You add the library's self-signed certificate as a trusted CA on every device
:::

:::quiz mc
And for the **sports club**?
- [ ] Rename the sports club to `www.beaver-schule.de`
- [x] The sports club gets its own certificate for `sport.beaver-schule.de`
- [ ] Set the server's clock back
:::

:::evaluate
Check answers
:::

:::warning
**"Proceed anyway"** is almost never a good idea with a certificate warning. Because that's exactly what it would look like if an attacker slipped you their own certificate. The same goes for `curl -k`: it turns off certificate checking — handy for testing, dangerous in real use.
:::

:::tip Key point
The browser warns if a certificate has **expired**, if it **doesn't know the issuing CA** (e.g. with **self-signed** certificates) or if the **name** in the certificate doesn't match the address. The fix is always a matching, valid certificate from a trusted CA — not clicking the warning away.
:::
