# How DNS is organised

:::sim
url=/sims/lesson-6.2.btsim
:::

No single server can know all the names in the world. That's why DNS is built **hierarchically** — just like the names themselves. You read them from right to left:

```
www . beaver-schule . de . (root)
 │          │         │      └─ root servers: know the servers of all top-level domains
 │          │         └─ top-level domain (TLD): the de server knows all .de domains
 │          └─ domain: the Schul-DNS is responsible for beaver-schule.de
 └─ computer name within the domain
```

The server that is responsible for a domain and really knows the answer is called **authoritative**. The way there is handled for the PC by a **resolver** — here the computer **DNS-Resolver**.

## The experiment

1. Switch to :fa-play: **Run** mode and enter in the :fa-terminal: **Terminal** of the **Client-PC**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. In :fa-magnifying-glass: **Trace** mode, open a trace for the **DNS-Resolver**.

The resolver made a whole series of requests for you. Match who gave which answer:

:::quiz match
Root-Server (192.168.0.101) -> Referral: ns.nic.de is responsible for .de
de-Server (192.168.0.102) -> Referral: ns.beaver-schule.de is responsible for beaver-schule.de
Schul-DNS (192.168.0.103) -> Answer: www.beaver-schule.de has the address 192.168.0.20
:::

:::quiz mc
Whom does the resolver ask first?
- [x] The root server
- [ ] The Schul-DNS
- [ ] The Client-PC
:::

:::evaluate
Check answers
:::

:::note
In between, the resolver also asks for the addresses of the servers it was referred to (`A ns.nic.de`). Real DNS servers usually send these addresses along right away. Resolvers also remember every answer for a while (**cache**) — they answer the next request for the same name immediately themselves. For how long is stated in the entry as the **TTL** (*time to live*) in seconds.
:::

## The most important entry types

| Type | Meaning | Example |
|---|---|---|
| **A** | name → IPv4 address | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | name → IPv6 address | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | name → another name (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | responsible mail server of a domain | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | responsible DNS server of a domain | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Key point
DNS is **hierarchical**: **root servers** refer to the servers of the **top-level domains** (e.g. `.de`), these to the servers of the individual **domains**. The responsible **authoritative** server knows the answer. A **resolver** goes this way for the PC and remembers the answers (**cache**). Important entry types: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Creating an entry

The school wants its website to also be reachable at `intranet.beaver-schule.de`.

1. In :fa-play: **Run** mode, click the **Schul-DNS** and open the **DNS-Server** app.
2. Open the **A** tab. Click **+** and enter the name `intranet.beaver-schule.de` and the address `192.168.0.20` in the new row.
3. Test on the Client-PC with `nslookup intranet.beaver-schule.de`.
