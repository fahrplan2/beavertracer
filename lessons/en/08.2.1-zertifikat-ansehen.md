# Looking at a Certificate

:::sim
url=/sims/lesson-8.2.1.btsim
:::

On the canvas you see the **Client-PC**, a **DNS-Server** and the school's web server, `www.beaver-schule.de`. The web server also offers its pages over **HTTPS**.

## The padlock in the browser

1. Switch to :fa-play: **Run** mode, click the **Client-PC** and open the :fa-globe: **Browser**.
2. Load `https://www.beaver-schule.de/` — note the **https**.
3. A **padlock** appears to the left of the address. Click it.

:::quiz short
Which name was the certificate issued for (subject without `CN=`)?
= www.beaver-schule.de
:::

:::quiz short
Who issued the certificate (issuer without `CN=`)?
= Biber Root CA
:::

:::evaluate
Check answers
:::

## Why does the Client-PC trust the certificate?

On the **Client-PC**, open the :fa-shield-halved: **Certificate Manager** and switch to the **Trusted CAs** tab.

:::quiz mc
What do you find there?
- [x] The certificate of the **Biber Root CA**
- [ ] The certificate of `www.beaver-schule.de`
- [ ] No entries
:::

:::quiz mc
How can you tell that the Biber Root CA is a root CA?
- [x] It is **self-signed**: subject and issuer are the same
- [ ] Its name ends in "CA"
- [ ] It has no public key
:::

:::quiz mc
Does the Client-PC show "Yes" or "No" for **Private Key**?
- [ ] Yes — the client needs the CA's private key to verify signatures
- [x] No — the public key is enough for verifying; only the CA has the private key
:::

:::evaluate
Check answers
:::

## The other side: the web server

Now open the :fa-shield-halved: **Certificate Manager** on the web server **www.beaver-schule.de** (tab **My Certs**) and look at its certificate.

:::quiz multi
What is true for the certificate on the web server?
- [x] **Private Key** says "Yes" — the server needs it to set up connections
- [x] The **Chain** reads `www.beaver-schule.de ← Biber Root CA`
- [x] The **Fingerprint** is the same as in the browser's padlock window
- [ ] It is self-signed
:::

:::evaluate
Check answers
:::

:::note
The **fingerprint** is a hash over the certificate. It lets you compare two certificates quickly — without checking every field one by one.
:::

:::tip Key point
The **web server** owns its certificate **with the private key**. The **client** only knows the **root CA's certificate** (without private key) — that's enough to verify the signature on the server certificate. Clicking the **padlock** in the browser shows subject, issuer, fingerprint and validity.
:::
