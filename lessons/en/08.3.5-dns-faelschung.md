# Attack: DNS Spoofing

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna wants to open her online banking at the **Biberbank** on the **Client-PC**. What she doesn't know: someone has gained access to the **DNS-Server** and changed an entry.

On the canvas you see the real web server **www.biberbank.de** and the computer of an **attacker** (*Angreifer*). It runs a copy of the bank's website.

## Part 1: Without encryption

Switch to :fa-play: **Run** mode and load `http://www.biberbank.de/` in the :fa-globe: **Browser** on the **Client-PC**.

:::quiz mc
What do you see?
- [x] The Biberbank login page, without any warning
- [ ] A warning that the page is fake
- [ ] An error message
:::

:::evaluate
Check answer
:::

Everything looks normal. But which server is the browser really talking to? Open the :fa-terminal: **Terminal** on the Client-PC:

```
$ nslookup www.biberbank.de
```

:::quiz short
Which IP address does the DNS server return for `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Who does this address belong to? (Click the devices in Edit mode or look at their :fa-gear: **IP Settings**.)
- [ ] The Biberbank's real web server
- [x] The attacker
- [ ] The DNS server
:::

:::evaluate
Check answers
:::

Had Anna entered her account number and PIN now, they would have gone straight to the attacker. With **HTTP** she has **no chance** of noticing the fraud: the address bar shows the right name, the page looks genuine.

## Part 2: With HTTPS

Now load `https://www.biberbank.de/`.

:::quiz mc
What happens?
- [ ] The fake page appears with a padlock
- [x] The browser warns: the certificate was issued for a different name
- [ ] The real Biberbank page appears
:::

:::quiz short
Which name is the attacker's certificate issued for (without `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Check answers
:::

The attacker even has a **genuine** certificate from a trusted CA — but for their own domain `www.biber-gewinnspiel.de`. No CA will give them a certificate for `www.biberbank.de`, because that domain isn't theirs. And without the Biberbank's **private key** they can't use its real certificate either: in the handshake they would have to sign the Server Key Exchange with it.

:::quiz multi
What does HTTPS protect against here — and what not?
- [x] HTTPS reveals that the server isn't the real one
- [ ] HTTPS prevents the DNS server from being tampered with
- [x] HTTPS only helps if the user takes the warning seriously
- [ ] With HTTPS the fake page can't be reached at all
:::

:::evaluate
Check answers
:::

## Part 3: Repair the DNS server

Open the **DNS-Server** and correct the entry for `www.biberbank.de`. You find the right address in the :fa-gear: **IP Settings** of the web server **www.biberbank.de**. Don't forget to click **Save**.

:::note
The Client-PC remembers DNS answers for a while so that it doesn't have to ask again every time (**DNS cache**). How long is given in the **TTL** column (*time to live*) in seconds. If `nslookup` still returns the old address right after your correction, wait for the TTL and try again.
:::

:::task
title: Biberbank genuine again?
Checks whether the Client-PC resolves www.biberbank.de to the right address and can fetch the page over HTTPS without a warning.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
In reality, an attacker rarely tampers with the DNS server itself. More often they inject their answers on a public Wi-Fi, change a home router's settings or lure people with a similar-looking address like `www.biberbank-login.de` (**phishing**). HTTPS doesn't help against a similar-sounding name — the attacker can get a valid certificate for it. So: read the address carefully!
:::

:::tip Key point
With **DNS spoofing**, the DNS server returns an attacker's address for a name. With **HTTP** you notice nothing. With **HTTPS**, the attacker's certificate doesn't match the name you entered, and the browser **warns** — because no CA issues certificates for other people's domains, and the attacker doesn't have the real server's private key.
:::
