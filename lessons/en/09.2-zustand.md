# Stateless or Stateful

A connection always has **two directions**: the Lehrer-PC sends a request to a web server on the internet — and the web server sends the web page back. A firewall following the whitelist principle therefore has to let through not only the request but also the **reply**.

There are two kinds of packet filters for this:

| | **Stateless** | **Stateful** |
|---|---|---|
| how it works | checks every packet on its own, without memory | remembers allowed connections in a **state table** |
| replies | need their own rule for the return direction | are let through automatically because they belong to a known connection |
| used in | simple devices, very fast filters | practically every firewall today |

In the next two sections you'll experience why stateless filters have trouble with replies — and how a stateful firewall solves this.
