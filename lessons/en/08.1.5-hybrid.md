# Hybrid Encryption

Let's sum up:

| | symmetric (e.g. AES) | asymmetric (e.g. RSA) |
|---|---|---|
| keys | one shared secret key | key pair: public + private |
| speed | very fast | slow |
| key exchange | problem: how does the key get to the recipient? | no problem: the public key may be sent openly |

So each method has a strength the other lacks. The solution: combine both. This is called **hybrid encryption**.

1. At the start of a connection, both sides use an **asymmetric** method to agree on a shared secret key, the **session key**. That takes a moment but happens only **once**.
2. After that, all data is encrypted **symmetrically** with the session key — fast.
3. At the end of the connection the session key is thrown away. The next connection gets a new one.

This is how **HTTPS**, encrypted e-mail connections, **Wi-Fi** with WPA3, **SSH** and **VPN** work.

## A shared secret by mixing paint

An elegant way to agree on a session key is the **Diffie-Hellman key exchange** (1976). You can picture it with paint. The trick: mixing paint is easy, but splitting a mixed colour back into its components is practically impossible.

1. Anna and Ben **publicly** agree on a common base colour, e.g. **yellow**. Anyone may know it.
2. Each secretly picks a **secret colour**: Anna **red**, Ben **blue**.
3. Each mixes their secret colour into the base colour and sends the result **openly** to the other: Anna sends **yellow + red** (orange), Ben sends **yellow + blue** (green).
4. Now each mixes their own secret colour into the other's mixture:
    - Anna: green + red = **yellow + blue + red**
    - Ben: orange + blue = **yellow + red + blue**
5. Both now have **the same** colour (brown) — the shared key.

An eavesdropper has seen yellow, orange and green. But to get brown, they would need red or blue — and Anna and Ben never sent those.

In reality, of course, you don't calculate with paint but with very large numbers. In the tracer you'll soon see the exchange again as **Server Key Exchange** and **Client Key Exchange** — the "**DHE**" in **ECDHE** stands for *Diffie-Hellman Ephemeral*, i.e. Diffie-Hellman with throwaway keys.

:::warning
Diffie-Hellman alone doesn't stop an attacker from sitting in the middle and negotiating a separate key with Anna **and** with Ben. So Anna also has to be sure she's really talking to Ben. That requires **signatures** and **certificates** — the next topic.
:::

:::tip Key point
**Hybrid encryption** combines both worlds: with an **asymmetric** method (e.g. Diffie-Hellman) both sides agree on a secret **session key**; the data itself is then encrypted **symmetrically** (e.g. with AES). This is how HTTPS, Wi-Fi encryption, SSH and VPN work.
:::
