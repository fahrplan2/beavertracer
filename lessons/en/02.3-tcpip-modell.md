# The TCP/IP reference model

The ISO/OSI model is very detailed, but it was created purely in theory. In practice — and on the internet — the leaner **TCP/IP model** with only four layers won out instead. It combines several OSI layers into one:

| TCP/IP layer | corresponds to OSI layer(s) | Example protocols |
|---|---|---|
| Application | 5, 6, 7 (Session, Presentation, Application) | HTTP, DNS, SMTP |
| Transport | 4 (Transport) | TCP, UDP |
| Internet | 3 (Network) | IP, ICMP |
| Network access | 1, 2 (Physical, Data Link) | Ethernet, Wi-Fi |

ARP sits on the border between network access and internet (OSI 2/3, see the borderline cases on the last page).

In practice the split into session/presentation/application is rarely clear-cut — most application protocols like HTTP do all of that themselves. The TCP/IP model takes this into account by combining these three layers into a single one.

:::note
When you read about "layer 2", "layer 3" or "layer 4" in the next chapters, it always means the numbering of the ISO/OSI model — that stays the common reference in this course, even though BeaverTracer and everyday practice often think more in TCP/IP categories.
:::
