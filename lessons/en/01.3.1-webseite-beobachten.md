# Loading and observing a web page

You don't build anything yourself for this part: on the workspace there's a prepared simulation with a **Client-PC** and a **Webserver**.

## Loading the page

1. Switch to :fa-play: **Run** mode.
2. On the **Client-PC**, open the :fa-globe: **Browser** app and enter the web server's address: `http://192.168.0.20/`.
3. Switch to :fa-magnifying-glass: **Trace** mode and use **+** to open a trace for the **Client-PC**, port `eth0` — just like with the ping.

:::note
That's a surprising number of packets for a single page request — far more than with the ping. Fetching a web page is a multi-step process, not a single action.
:::

## Reading the packet list

You don't need to know yet what each protocol does exactly. Everything you need for the following questions is in the **Protocol** and **Info** columns.

:::quiz mc
Which protocol is at the very top of the list?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Count: how many **TCP** packets come before the first **HTTP** packet?
= 3
= three
:::

:::quiz mc
What does the web server reply to the browser's request? Look at the Info column of the second HTTP packet.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Check answers
:::

## Naming the protocols involved

From your observations you can now read off which protocol was responsible for what.

:::tip Tip
Read through the **Info** columns once more: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` and `200 OK` already give almost everything away.
:::

:::quiz match
ARP -> Asks everyone in the network: "Who has the IP address 192.168.0.20?"
TCP -> Sets up a connection with three short packets before any data flows
HTTP -> Requests the web page (GET) and delivers it back (200 OK)
:::

:::evaluate
Check matches
:::

:::tip Key point
Loading a web page happens in stages: first **find** the server in the network (ARP), then **set up** a connection (TCP), then **request and deliver** the page (HTTP) — and finally **close** the connection again (the TCP packets with `[FIN]` at the end of the list).
:::

:::note
This time you typed the server's IP address directly, so **DNS** (the "translation" of names like `www.example.com` into an IP address) wasn't used yet. We'll catch up on that in chapter 6.
:::

Did you notice that the protocols in the packet structure carry coloured markers with numbers? What they're about is explained in chapter 2. There we look at how to sort all these protocols systematically — with the OSI and the TCP/IP reference model. And with that, chapter 1 is done.
