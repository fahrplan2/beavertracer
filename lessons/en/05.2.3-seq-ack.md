# Sequence and acknowledgement numbers

:::sim
url=/sims/lesson-5.1.btsim
:::

How does TCP know whether everything has arrived — and in which order? Each side **numbers the bytes** it sends:

- The **sequence number** (`SEQ`) is the number of the first byte in this packet.
- The **acknowledgement number** (`ACK`) says: "I've received everything up to here — next I expect byte no. …"

Two rules on top: `SYN` and `FIN` count like one byte, even though they carry no data. And each side counts for itself — that's why there are two number ranges, red (client) and blue (server) in the diagram.

## Working it out

Here's your connection once more. The numbers on the lines show each computer's counter at that point:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Go through the red numbers:

1. The client starts at `SEQ=0`. Its `SYN` uses up one number — the server confirms with `ACK=1`.
2. The message starts at `SEQ=1` and is 13 bytes long (bytes 1 to 13). The server confirms with `ACK=14`: "Next I expect byte 14."
3. So the client's `FIN` has `SEQ=14` and is confirmed with `ACK=15`.

The server's blue numbers work exactly the same way.

:::tip Key point
The **sequence number** (`SEQ`) is the number of the first byte in the packet. The **acknowledgement number** (`ACK`) is the number of the next byte the receiver expects — everything before it has arrived. The rule is: **ACK = SEQ + length** of the received data; `SYN` and `FIN` count like one byte. Each side counts its own bytes.
:::

:::note
In real networks counting doesn't start at 0: each side picks a **random starting number** (*Initial Sequence Number*, ISN) between 0 and about 4.3 billion. When the highest number is reached, it continues at 0 again. The tracer subtracts the starting number and shows **relative** numbers — just like Wireshark. That's why you see `Seq=0` and `Seq=1`.

Every packet also contains `Win=` — the **window size**: this many bytes the receiver can currently take in. With it, the receiver slows down a sender that is too fast (*flow control*). In BeaverTracer the window always has the same size.
:::
