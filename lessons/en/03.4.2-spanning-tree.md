The same ring as before — this time you switch on the **Spanning Tree Protocol** (**STP**) first.

## Switching on STP

Do this on **all three** switches:

1. Switch to :fa-play: **Run** mode and click the switch.
2. Open the **STP** tab and choose **STP (802.1D)** as the mode.

Then wait about **15 seconds**. During this time the switches exchange small messages (so-called *BPDUs*) and agree on a common structure.

## What the switches negotiated

Open the **STP** tab on each switch and look at the table: every connected port has a **State**.

Now ping Ben from **Anna** (`ping 192.168.0.11`): this time the pings arrive, and nothing circles through the ring any more.

STP picked one switch as the root and built a **tree** from it: exactly one path leads to every switch. The one connection that would close a loop is **blocked** — the cable is still plugged in, but the switch doesn't send any normal frames over it.

## And if a cable fails?

1. Switch to :fa-pencil: **Edit** mode, choose the :fa-ban: **Delete** tool and click the cable between **Switch A** and **Switch B**.
2. Switch back to :fa-play: **Run** mode and again wait about 15 seconds.
3. Look at the **STP** tab of **Switch B** and then ping Ben from Anna once more.

:::quiz mc
What happened?
- [ ] Ben can no longer be reached
- [x] Switch B's previously blocked port now forwards — the pings take the detour via switch C
- [ ] Switch B is now the root
:::

Check answer
:::

:::tip Key point
The **Spanning Tree Protocol** (**STP**) prevents loops between switches: the switches elect a **root bridge** and **block** individual ports so that exactly one path leads to every switch. If a connection fails, STP releases a blocked port again — so the network stays reachable despite the failure.
:::

## Outlook: what else STP can do

What you've seen here is only the basic principle. In real networks there's a lot more to it:

- **Different variants:** besides classic STP there are further developed methods like **RSTP** (*Rapid* STP), which is ready again much faster after a failure, and **MSTP** (*Multiple* STP).
- **STP and VLANs:** if several VLANs run across the switches, you additionally have to define how the tree is built for the individual VLANs — there are separate methods and settings for that.
- **Electing the root bridge:** which switch becomes root follows its own precisely defined procedure. In this example we set things up in advance so that switch A always wins.

:::note
These topics go beyond this course — the only important thing is: anyone setting up STP in a real network needs considerably more knowledge than this section teaches.
:::
