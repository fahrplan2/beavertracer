# The sequence diagram

:::

The course of a connection is drawn as a **sequence diagram**: client and server each get a vertical line, time runs from top to bottom. Every arrow is one packet. It's drawn slanted because every packet is on the way for a little while.

This is your connection from the last page — compare it line by line with the trace:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Above every arrow are the **flags**, below it the numbers `SEQ` and `ACK`. **DATA** marks packets with payload. The red numbers belong to the client, the blue ones to the server — what they mean is explained on the next page.

## The flags

| Flag | stands for | Meaning |
|---|---|---|
| **SYN** | *synchronize* | set up a connection, define the starting number |
| **ACK** | *acknowledge* | confirms received data |
| **PSH** | *push* | pass the data to the program right away |
| **FIN** | *finish* | "I'm done" — tear down the connection |
| **RST** | *reset* | abort or refuse a connection (more on this in 5.3.2) |

## Three phases

**Setup:** the client sends `SYN`, the server answers with `SYN, ACK`, the client confirms with `ACK`. Because exactly three packets are needed, this is called the **three-way handshake**.

**Data:** every packet with data is confirmed by the receiver with an `ACK`. Here the server sends the echo back — the client confirms that too.

**Teardown:** each side ends its own sending direction separately: `FIN` from the client, `ACK` from the server — then `FIN` from the server, `ACK` from the client. That's four packets.

:::tip Key point
A TCP connection runs in three phases: **setup** with the **three-way handshake** (`SYN` → `SYN, ACK` → `ACK`), **data transfer** (every data packet is confirmed with `ACK`) and **teardown** (each side sends `FIN` and gets an `ACK`).
:::
