# Observing a Firewall

:::sim
url=/sims/lesson-9.1.1.btsim
:::

In this simulation someone has already entered three rules into the firewall. Click the **Firewall** and look at the **Rules** tab. The firewall's **Port A** is connected to the internet, **Port B** to the school router — so "A → B" means "from the internet into the school network".

:::quiz table
| Rule | Direction | Protocol | Dest. port | Action |
|---|---|---|---|---|
| 1 | A → B | {TCP} | {22} | {Drop} |
| 2 | A → B | TCP | {110} | {Reject} |
| 3 | A → B | {ICMP} | any | Drop |
:::

:::evaluate
Check table
:::

## Ping from outside

Switch to :fa-play: **Run** mode and ping the school server from the **Internet-PC**:

```
$ ping -c 2 198.51.100.10
```

Then open the firewall's **Log** tab.

:::quiz mc
What does `ping` report?
- [x] `Request timeout` — nothing comes back at all
- [ ] `Packet filtered`
- [ ] Two replies from the school server
:::

:::quiz short
Which word do the new lines in the firewall's log start with?
= DROP
:::

:::evaluate
Check answers
:::

## Port scan: dropped or rejected?

Now scan five specific ports. Port 3306 (a database) isn't running on the school server at all.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (dropped) -> filtered
25 (allowed, service running) -> open
110 (rejected) -> closed
3306 (allowed, no service) -> closed
:::

:::evaluate
Check matches
:::

:::quiz multi
What can an attacker conclude from the result?
- [x] With `filtered` they know: there's a firewall swallowing packets
- [x] With `closed` they can't tell whether a firewall rejects or simply no service is running
- [ ] With `filtered` they know which service runs behind the port
- [ ] With `closed` the service is still reachable
:::

:::evaluate
Check answers
:::

Finally, look at the **Hits** column in the rule list: there the firewall counts how many packets each rule has decided. The value next to the **Default policy** counts all packets that matched no rule.

:::tip Key point
**Dropped** packets vanish without a trace: `ping` reports a timeout, `nmap` reports `filtered`. **Rejected** packets are answered by the firewall with a refusal (a RST for TCP) — from outside that looks like a closed port. The firewall's **Log** shows which packets it stopped, the **Hits** column which rule applied.
:::
