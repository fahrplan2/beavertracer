HTTP, DNS, e-mail and DHCP are the protocols you meet all the time in everyday life. Besides them there are many more — here's a short overview of the most important ones. Some of them you can try out yourself in BeaverTracer: they're marked with :fa-flask:.

| Protocol | Port | Transport | what for |
|---|---|---|---|
| **SSH** | 22 | TCP | encrypted remote maintenance |
| **Telnet** :fa-flask: | 23 | TCP | unencrypted remote maintenance (outdated) |
| **FTP** / **SFTP** | 21 / 22 | TCP | transferring files |
| **NTP** :fa-flask: | 123 | UDP | synchronising the time |
| **IRC** :fa-flask: | 6667 | TCP | text chat |
| **SIP** / **RTP** :fa-flask: | 5060 / varying | UDP | internet telephony |
| **SNMP** | 161 | UDP | monitoring network devices |
| **SMB** | 445 | TCP | file shares in the network |
| **MQTT** | 1883 | TCP | messages in the Internet of Things |
| **QUIC** / **HTTP/3** | 443 | UDP | faster, encrypted web |

## SSH and Telnet

With **SSH** (*Secure Shell*) you control another computer via the command line as if you were sitting in front of it — administrators maintain servers and routers this way. Everything, including the password, is transmitted encrypted. Its predecessor **Telnet** does the same in plain text and is therefore considered insecure today; as a tool for testing text protocols it's still useful, though, as you saw in section 6.1.2.

## FTP and SFTP

The **File Transfer Protocol** (**FTP**) is one of the oldest internet protocols and is used for uploading and downloading files. It transmits passwords and data unencrypted and is therefore used less and less. It's usually replaced by **SFTP**, which transfers files over an SSH connection.

## NTP

The **Network Time Protocol** (**NTP**) synchronises the clocks of computers with a time server — accurate to milliseconds. That's more important than it sounds: certificates, log files and login procedures only work if all devices have the same time. In BeaverTracer there are the apps **NTP Server** and **Clock** and the command `ntpdate` for this.

## IRC

**Internet Relay Chat** (**IRC**) is a chat protocol from 1988: you connect to a server, join channels like `#schule` and write text messages to everyone in the channel. Like HTTP and SMTP, IRC is a pure text protocol — in the tracer you can read every message. Today's messengers work on the same basic principle, but encrypted. In BeaverTracer: apps **IRC Server** and **IRC**.

## SIP and RTP

With **internet telephony** (*Voice over IP*), two protocols work together: **SIP** (*Session Initiation Protocol*) sets the call up and tears it down again — it makes the other person's phone ring. The speech itself then runs in many small **RTP** packets over UDP, because in a phone call every millisecond counts (see section 5.5.2). In BeaverTracer: apps **SIP Server** and **Softphone**.

## SNMP

With the **Simple Network Management Protocol** (**SNMP**), monitoring programs query routers, switches and printers: how busy is a port? Has a device failed? Is the toner empty? That's how administrators keep an eye on even large networks.

## SMB

The **Server Message Block** protocol (**SMB**) is behind the network drives and shared folders you know from Windows networks — such as the shared drive at school. Network printers are also often addressed via SMB.

## MQTT

**MQTT** is a very lean protocol for the **Internet of Things**: sensors, smart thermostats or machines in a factory send their readings to a central intermediary (*broker*), and every program interested in them gets them from there. It's designed for devices with little computing power and unreliable connections.

## QUIC and HTTP/3

**QUIC** is a newer transport protocol developed by Google that many large websites use today. It's built on **UDP** and brings reliability and encryption along itself — so a connection is up faster than with TCP and TLS. **HTTP/3** is the version of HTTP that runs over QUIC.
