# Connecting two networks

:::sim
url=/sims/lesson-4.3.1.btsim
:::

The router has two ports:

| Port | IP address | Network |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Company A |
| `eth1` | `172.16.0.1/24` | Company B |

So that the PCs use the router, a **gateway** is entered on each of them: `192.168.0.1` on Anna and Ben, `172.16.0.1` on Clara and David. You find it in the :fa-gear: **IP Settings** in the **Gateway** field.

:::tip Key point
The **gateway** (more precisely: *default gateway*) is the IP address of the router **in your own network**. A PC sends all packets whose destination is in a foreign network to the gateway.
:::

## What the router does with the packet

The router receives Anna's frame, unpacks the IP packet and looks at the **destination IP address**. From it, it recognises: Clara is in the network on `eth1`. So it wraps the packet in a **new** frame — with its own MAC address as the source and Clara's MAC address as the destination — and sends it out there.

| What happens at the router to … | |
|---|---|
| the MAC addresses (layer 2)? | they're set **anew** — they're only valid in the respective network |
| the IP addresses (layer 3)? | they **stay the same** — from Anna all the way to Clara |
| the Time to Live? | it gets **1 smaller** |

:::tip Key point
A **router** works on **layer 3**: it forwards packets into other networks based on the **destination IP address**. The IP addresses stay the same along the whole way, the MAC addresses are set anew in every network. Every router decreases the **Time to Live (TTL)** by 1 — if it reaches 0, the packet is discarded. That way a packet can't run in circles forever.
:::

:::note
Remember the broadcast storm from chapter 3.4? Ethernet frames have no TTL — IP packets do.
:::

## Who does Anna know? The ARP cache

Remember chapter 1.2.3? There, ARP only showed up before the *first* ping, because the PC remembered the answer. This list is called the **ARP cache** (also *ARP table*). The question is called an **ARP request**, the answer an **ARP reply** (or *ARP response*).

Switch to :fa-play: **Run** mode, open the :fa-terminal: **Terminal** on **Anna** and display her ARP cache:

```
$ arp
```

:::quiz mc
What's in Anna's ARP cache?
- [x] Only the router's IP address (`192.168.0.1`) with its MAC address
- [ ] Clara's IP address with Clara's MAC address
- [ ] The addresses of the router and of Clara
:::

:::evaluate
Check answer
:::

Anna never needs Clara's MAC address: she sends everything meant for company B to the router. Only the router knows Clara's MAC address — it asked for it itself via ARP on its side.

:::tip Key point
In its **ARP cache** a device remembers which MAC address belongs to which IP address — so it doesn't have to send an ARP request before every packet. It's displayed with the command `arp`. A PC only knows MAC addresses from its **own** network: for all destinations in foreign networks it uses the router's MAC address.
:::

:::note
In real networks, entries in the ARP cache are deleted again after a while and asked for anew when needed — for example in case a device has a different network card by now. In BeaverTracer they're kept as long as the simulation runs.
:::
