# All together: what happens when loading a web page?

:::goal
**Learning goal:** You can explain step by step which protocols on which layer are involved when a freshly switched-on laptop loads a web page.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Now everything you've learned in this course comes together. A **DHCP-Server**, a **DNS-Server**, a **Webserver** and a **Laptop** that has just been switched on are connected to the switch — the laptop doesn't have an IP address yet and is set to DHCP.

## The experiment

1. Switch to :fa-play: **Run** mode and wait a few seconds.
2. Click the **Laptop**, open the :fa-globe: **Browser** and load `http://www.beaver-schule.de/`.
3. In :fa-magnifying-glass: **Trace** mode, open a trace for the **Laptop**. Here's the whole story — from the very first packet.

Put the steps in the right order, as they appear in the trace:

:::quiz match
Step 1 -> DHCP: the laptop gets its IP address, gateway and DNS server
Step 2 -> ARP: the laptop asks for the DNS server's MAC address
Step 3 -> DNS: the laptop asks for the IP address of www.beaver-schule.de
Step 4 -> ARP: the laptop asks for the web server's MAC address
Step 5 -> TCP: three-way handshake with the web server
Step 6 -> HTTP: GET / and the answer 200 OK
:::

:::evaluate
Check order
:::

## The big picture

| Step | Protocol | Layer (OSI) | Transport / port | what for |
|---|---|---|---|---|
| 1 | **DHCP** | 7 | UDP 67/68 | get your own address, gateway and DNS server |
| 2 | **ARP** | 2/3 | — | find the MAC address for the DNS server's IP address |
| 3 | **DNS** | 7 | UDP 53 | translate the name into an IP address |
| 4 | **ARP** | 2/3 | — | find the web server's MAC address |
| 5 | **TCP** | 4 | port 80 | set up a reliable connection |
| 6 | **HTTP** | 7 | TCP 80 | request and receive the page |

And underneath everything there's **IP** (layer 3), which addresses each of these packets, and **Ethernet** (layer 2), which brings it to the next device. If the web server were in another network, the **router** would come in too: then the laptop would ask for the MAC address of its **gateway**, not for that of the web server.

:::quiz mc
Why can the laptop only make the DNS request after DHCP?
- [ ] Because DNS only works over TCP
- [x] Because only through DHCP does it get its own IP address and learn which DNS server is responsible
- [ ] Because the DNS server only starts after the DHCP server
:::

:::quiz mc
How many TCP connections does the browser set up to the web server — and why?
- [ ] One, for everything together
- [x] Two — one for the page and one for the stylesheet
- [ ] None at all, HTTP doesn't need TCP
:::

Check answers

:::tip Key point
Behind a single click, all layers work together: **DHCP** provides the basic settings, **ARP** finds the MAC addresses in the local network, **DNS** translates the name, **TCP** sets up a reliable connection and **HTTP** fetches the page — all wrapped in **IP** packets and **Ethernet** frames.
:::

With that you've completed the chapter on the application layer — and can now explain loading a web page from the first to the last packet.
