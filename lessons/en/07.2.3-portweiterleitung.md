# From outside to inside: port forwarding

:::sim
url=/sims/lesson-7.2.3.btsim
:::

There's now a **Heim-Webserver** (home web server, `192.168.178.10`) of its own in the home network. Clara wants to load the page while she's out — her laptop **Clara** is on the internet on the right.

## The problem

1. Switch to :fa-play: **Run** mode and load `http://203.0.113.2/` in the :fa-globe: **Browser** on **Clara** — the home network's public address.
2. The browser waits and waits. After a few seconds, click **Stop**.
3. In :fa-magnifying-glass: **Trace** mode, open a trace for the **Heimrouter**, port `wan0`.

:::quiz mc
What happens to Clara's connection setup (`[SYN]` to port 80)?
- [x] It arrives at the home router — but the router doesn't forward it and doesn't answer
- [ ] It reaches the home web server, which answers with RST
- [ ] It doesn't even reach the home router
:::

:::evaluate
Check answer
:::

For a packet coming from outside there's no entry in the NAT table: nobody in the home network started this connection. The home router doesn't know which device to send it to — and discards it.

## Setting up the port forward

With a **port forward** you define: everything that arrives at a particular WAN port goes to a particular device in the home network.

1. Click the **Heimrouter** and open the **Port FW** tab.
2. Create a rule: protocol `TCP`, WAN port `80`, LAN IP `192.168.178.10`, LAN port `80`, and click **+ Add**.
3. Load `http://203.0.113.2/` on **Clara** once more.

:::task
title: Home web server reachable from outside?
Checks whether Clara can set up a connection from the internet to port 80 of the home network's public address. The simulation has to be running in Run mode for this.
check: tcpOpen(12, "203.0.113.2", 80)
:::

:::warning
A port forward opens a hole to the inside: anyone on the internet can reach the device behind it — including attackers who automatically search for open ports. So only forward what's really necessary and keep the device up to date. More on this in chapter 9 (firewall).
:::

:::tip Key point
From outside, nobody can start a connection to a device behind NAT — the router doesn't know where to send it. A **port forward** defines: packets at a particular **WAN port** go to a particular **LAN IP** (and a LAN port). That's how a server in the home network becomes reachable from the internet.
:::
