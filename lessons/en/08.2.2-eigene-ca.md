# Building Your Own CA

:::sim
url=/sims/lesson-8.2.2.btsim
:::

There's no certificate for `www.beaver-schule.de` yet. Instead of applying for one at a commercial CA, the school builds its **own CA**: the **Schul-CA** (school CA). Many companies and schools do this for their internal servers.

In reality the school CA would run on its own, particularly well-protected computer. Here you play all roles on the web server itself.

## Step 1: Create the school CA

1. Switch to :fa-play: **Run** mode and open the :fa-shield-halved: **Certificate Manager** on the web server **www.beaver-schule.de**.
2. In the **Generate** tab:
    - **Common Name:** `Schul-CA`
    - **Type:** Self-signed
    - Tick **This is a CA certificate**
    - **Save as:** `schul-ca.cert.json`
3. Click **Generate Certificate**.

This creates a new **key pair**. The certificate contains the public key; the private key stays in the file on the web server.

## Step 2: Issue the server certificate

Again in the **Generate** tab:

- **Common Name:** `www.beaver-schule.de` — exactly the name you type in the browser
- **Type:** Signed by CA, **Signing CA:** Schul-CA
- **Save as:** e.g. `www.beaver-schule.de.cert.json`

In the **My Certs** tab you now see both certificates. Click the new server certificate:

:::quiz short
Who is the **issuer** of the server certificate (without `CN=`)?
= Schul-CA
:::

:::quiz mc
What is its **chain**?
- [x] `www.beaver-schule.de ← Schul-CA`
- [ ] `Schul-CA ← www.beaver-schule.de`
- [ ] `www.beaver-schule.de` (self-signed)
:::

## Step 3: Teach the client about the school CA

The Client-PC doesn't know the school CA yet — it isn't pre-installed in its browser. You have to give it the CA's certificate, **without the private key**:

1. On the web server, select the **Schul-CA** under **My Certs** and click **Copy** (not *Copy + Key*!).
2. On the **Client-PC**, open the :fa-shield-halved: **Certificate Manager**, tab **Trusted CAs**.
3. Click **Paste: Schul-CA**.

:::warning
The **CA's private key** is the most valuable secret of the whole setup: whoever has it can issue certificates for **any** name, and all clients will trust them. It must never leave the CA computer.
:::

You haven't switched the web server itself over yet — it still only speaks HTTP. How to turn on HTTPS is covered in section 8.3.3.

:::tip Key point
An **own CA** consists of a **self-signed CA certificate** with a private key. You use it to issue **server certificates** whose common name matches the server name. For clients to trust these certificates, they get the **CA certificate without the private key** in their list of **trusted CAs**.
:::
