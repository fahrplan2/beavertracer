# Order and Basic Approach

## The exception first, then the rule

Since the **first matching rule** wins, order matters. Look at this rule list (all rules apply to the direction A → B, default policy: allow all):

| No. | Protocol | Dest. port | Action |
|---|---|---|---|
| 1 | TCP | any | Drop |
| 2 | TCP | 80 | Allow |

:::quiz mc
A packet from the internet to TCP port 80 arrives. What happens?
- [ ] It is allowed, because rule 2 allows exactly port 80
- [x] It is dropped, because rule 1 already matches — rule 2 is never reached
- [ ] The firewall asks the administrator
:::

:::evaluate
Check answer
:::

As a general rule: **specific rules at the top, general ones at the bottom.** A rule that covers a lot "shadows" all rules below it. The **Hits** column reveals such dead rules: they stay at 0.

## Blacklist or whitelist?

In section 9.1.2 you **forbade** individual ports and allowed everything else. That's called a **blacklist**. The opposite is the **whitelist**: you **allow** only what's needed and forbid everything else — with a final rule "drop everything" or the default policy **Drop all**.

| | Blacklist | Whitelist |
|---|---|---|
| basic approach | everything allowed, exceptions forbidden | everything forbidden, exceptions allowed |
| default policy | Allow | Drop |
| new service on the server | is reachable from outside immediately | stays blocked until someone opens it |

:::quiz mc
Tomorrow a teacher installs a database on the school server that listens on port 3306. What happens with the firewall from section 9.1.2 (blacklist)?
- [x] The database can be reached from the internet immediately
- [ ] The database is blocked automatically
- [ ] The firewall reports the new service
:::

:::evaluate
Check answer
:::

That's why good firewalls follow the **whitelist principle** ("default deny"): everything that isn't explicitly allowed is forbidden. A whitelist for the school server would look like this:

:::quiz table
| No. | Direction | Protocol | Dest. port | Action |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {Allow} |
| 2 | A → B | TCP | {25} | Allow |
| 3 | A → B | any | any | {Drop} |
:::

:::evaluate
Check table
:::

:::quiz mc
What happens if you move rule 3 to the very top?
- [ ] Nothing, order doesn't matter
- [x] Nothing gets in from the internet anymore, not even web and mail
- [ ] Only web and mail get in
:::

:::evaluate
Check answer
:::

:::tip Key point
Since the **first matching rule** wins, **specific rules go at the top** and general ones at the bottom. A **whitelist** (everything forbidden except …, *default deny*) is safer than a **blacklist** (everything allowed except …): forgotten or new services then stay blocked automatically.
:::
