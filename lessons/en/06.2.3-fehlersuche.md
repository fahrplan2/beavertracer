# Troubleshooting: the name doesn't work

:::sim
url=/sims/lesson-6.2.3.btsim
:::

A teacher reports: "`www.beaver-schule.de` doesn't load for me. But `http://192.168.0.20` works!" This is how it's *supposed* to be set up:

| What | Target |
|---|---|
| DNS server on the Client-PC | `192.168.0.53` (DNS-Resolver) |
| Entry in the Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Find the faults and fix them.

<details>
<summary>Tip 1: What does nslookup say?</summary>

Enter `nslookup www.beaver-schule.de` on the Client-PC. Which server did `nslookup` ask — and what came back? (The answer takes a few seconds.)
</details>

<details>
<summary>Tip 2: And now?</summary>

If you get an answer, compare the address with the plan. Where is this name entered?
</details>

:::task
title: Name lookup repaired?
Checks whether the Client-PC resolves www.beaver-schule.de to the right address. The simulation has to be running in Run mode for this.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## What was going on?

:::quiz multi
Which statements are true?
- [x] `192.168.0.35` was entered as the DNS server on the Client-PC — nobody answers there
- [x] In the Schul-DNS, `www.beaver-schule.de` pointed to `192.168.0.21` instead of `192.168.0.20`
- [ ] The web server was switched off
- [ ] The root server didn't know the domain `.de`
:::

:::evaluate
Check answer
:::

:::tip Key point
If a connection works with the **IP address** but not with the **name**, the problem is with **DNS**. First check the **DNS server entered** (does it answer at all?), then the **entry** itself (is the address right?). `nslookup` shows both: which server was asked and what it answered.
:::
