# Who gets which packet?

:::sim
url=/sims/lesson-3.1.2.btsim
:::

Now Anna, Ben and Clara are connected to the switch (ports 1, 2 and 3). When Anna sends a packet to Ben: does only Ben get it — or Clara too?

Think briefly about what you expect. Then try it out.

## The experiment

1. Switch to :fa-play: **Run** mode, open the :fa-terminal: **Terminal** on **Anna** and ping Ben:
   ```
   $ ping 192.168.0.11
   ```
2. Switch to :fa-magnifying-glass: **Trace** mode and use **+** to open a trace for **Clara**, port `eth0`.
3. Use **+** to open a second trace for **Ben**, port `eth0`. At the top you can switch back and forth between the two traces.

:::quiz short
How many packets arrived at **Clara**?
= 1
= one
:::

:::quiz mc
Which packet was it?
- [x] The ARP request "Who has 192.168.0.11?" to everyone (broadcast)
- [ ] A ping (Echo Request) from Anna
- [ ] Ben's ARP reply
:::

:::quiz mc
And what arrived at **Ben**?
- [ ] Only the ARP request
- [ ] Only the pings
- [x] The ARP request and all pings
:::

:::evaluate
Check answers
:::

## What's behind it

The ARP request has **Broadcast** as its destination — it's addressed to *everyone*. That's why the switch passed it on to every port, Clara's too. The pings, on the other hand, were addressed only to Ben. The switch sent them exclusively to Ben's port — Clara didn't notice any of it.

:::tip Key point
A **broadcast** is addressed to all devices in the local network — the switch distributes it to all ports. A **unicast** is addressed to exactly one device — the switch sends it only to the port that device is connected to.
:::

## A look inside the switch

But how does the switch know which port Ben is connected to? Switch back to :fa-play: **Run** mode and click the **Switch**. In the **SAT** tab you see its address table with two columns: **MAC** and **Port**.

:::quiz mc
Which devices are in the address table?
- [ ] Anna, Ben and Clara
- [x] Only Anna and Ben
- [ ] Only Ben
:::

:::quiz short
According to the table, which port is Ben connected to? Tip: you find Ben's MAC address in the tracer in his ARP reply `192.168.0.11 is at …`.
= 2
= port 2
:::

:::quiz mc
Why is Clara missing from the table?
- [ ] Her cable is broken
- [x] She hasn't sent a single packet yet
- [ ] The switch stores two entries at most
:::

:::evaluate
Check answers
:::

The switch **learns** as it goes: for every frame that arrives, it looks at the **source** MAC address and remembers which port that device is connected to. When Anna's ARP request came in, it noted "Anna → port 1", with Ben's reply "Ben → port 2". Clara hasn't sent anything — so it doesn't know her yet.

:::tip Key point
In its **address table** (**SAT**, *Source Address Table*) a switch remembers under which MAC address which device can be reached on which port — it learns this from the source addresses. If it knows a frame's destination, it sends the frame only to that port. If it doesn't (or it's a broadcast), it sends it to all ports.
:::
