# Troubleshooting the school network

:::sim
url=/sims/lesson-4.4.3.btsim
:::

A colleague set up the PCs in the school network — since then almost nothing works between the areas. This is what the network is *supposed* to look like:

| Device | IP address | Prefix length | Gateway |
|---|---|---|---|
| PC Verwaltung | `192.168.10.2` | `/26` | `192.168.10.1` |
| PC Lehrerzimmer | `192.168.10.66` | `/26` | `192.168.10.65` |
| PC Computerraum | `192.168.10.130` | `/26` | `192.168.10.129` |

Find the faults and fix them.

<details>
<summary>Tip 1: Where do I start?</summary>

Look at the :fa-gear: **IP Settings** of every PC and compare them with the network plan. Not every fault is obvious at first glance.
</details>

<details>
<summary>Tip 2: What exactly is wrong?</summary>

Work out for every PC: which subnet is its address really in? Is it perhaps the network or the broadcast address? And is the netmask right?
</details>

:::task
title: School network repaired?
Checks the addresses of the three PCs and whether they can reach each other via the router. The simulation has to be running in Run mode for this.
check: ip(9, "192.168.10.2/32")
check: ip(11, "192.168.10.66/32")
check: ip(13, "192.168.10.130/32")
check: pingOk(9, 11)
check: pingOk(9, 13)
check: pingOk(11, 13)
:::

## What was going on?

:::quiz match
PC Verwaltung -> The address .70 is in the staff room's subnet — the gateway .1 can't be reached from there
PC Lehrerzimmer -> The netmask was /24 instead of /26
PC Computerraum -> The address .191 is the subnet's broadcast address
:::

:::evaluate
Check matches
:::

:::tip Key point
Typical subnetting faults: an **address outside your own subnet** (then the gateway can't be reached either), a **wrong netmask** and the **network or broadcast address as a device address**. Careful: the IP Settings accept such wrong values without any warning — you have to do the maths yourself.
:::
