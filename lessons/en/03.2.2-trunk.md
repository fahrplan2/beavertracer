# VLANs across two switches: the trunk

:::sim
url=/sims/lesson-3.2.2.btsim
:::

The school has two floors with one switch each, connected by a cable on **port 8**:

| Switch | Port 1 (VLAN 10, administration) | Port 2 (VLAN 20, computer room) |
|---|---|---|
| **Switch EG** (ground floor) | Sekretariat `192.168.0.10` | Anna `192.168.0.20` |
| **Switch OG** (upper floor) | Schulleitung `192.168.0.11` | Ben `192.168.0.21` |

The VLANs on the PC ports are already set up.

## The problem

Switch to :fa-play: **Run** mode and ping Ben from **Anna** (`ping 192.168.0.21`). Both are in VLAN 20 — and still there's no reply.

In a switch's **VLAN** tab, look at the row **port 8**: it's still set to `untagged` with PVID `1`. So only VLAN 1 runs over this cable — neither VLAN 10 nor VLAN 20.

But frames from *both* VLANs have to run over the cable between the switches. To do that, the switch sticks a small label on every frame with the VLAN ID on it: the **VLAN tag**. That way the switch at the other end knows which VLAN the frame belongs to.

## Setting up the trunk

Do this on **both** switches:

1. Click the switch and open the **VLAN** tab.
2. In the row **port 8**, set the **Mode** to `tagged` and enter `10,20` under **Allowed VLANs**.
3. Click **Apply**.

Then ping Ben from **Anna** once more — and, for comparison, the Schulleitung (`ping 192.168.0.11`).

:::quiz mc
What happens now?
- [x] Anna reaches Ben, but not the Schulleitung
- [ ] Anna reaches Ben and the Schulleitung
- [ ] Anna still can't reach anyone
:::

:::evaluate
Check answer
:::

## The VLAN tag in the tracer

Switch to :fa-magnifying-glass: **Trace** mode and use **+** to open a trace for **Switch EG**, port **8** — that's the cable between the switches. Click one of Anna's pings (`Echo (ping) request`).

A new line has appeared in the protocol tree, directly below Ethernet: **802.1Q Virtual LAN**. That's the VLAN tag.

:::quiz short
Which VLAN ID is in the tag of Anna's ping?
= 20
:::

For comparison, open a trace for **Ben** (`eth0`) and click the same ping there.

:::quiz mc
What do you notice at Ben?
- [ ] The same tag with ID 20 is there
- [x] The 802.1Q line is missing — the switch removed the tag again before Ben's port
- [ ] The ping doesn't reach Ben at all
:::

:::evaluate
Check answers
:::

:::tip Key point
A **trunk** is a connection over which frames from several VLANs run — typically between two switches. For this, every frame gets a **VLAN tag** with the VLAN ID (standard **IEEE 802.1Q**). Such ports are called **tagged**. A normal device is connected to an **untagged** port; the switch removes the tag before sending the frame there.
:::
