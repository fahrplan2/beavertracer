# Reading and writing IPv6 addresses

## The hexadecimal system

Nobody can read 128 zeros and ones — and as decimal numbers in 16 groups it wouldn't be much better. That's why IPv6 addresses are written in the **hexadecimal system** (*hex* for short). It has **16 digits**: 0 to 9 and then a to f for the values 10 to 15.

The big advantage: one hex digit stands for exactly **4 bits**.

| decimal | hex | binary | | decimal | hex | binary |
|---|---|---|---|---|---|---|
| 0 | 0 | 0000 | | 8 | 8 | 1000 |
| 1 | 1 | 0001 | | 9 | 9 | 1001 |
| 2 | 2 | 0010 | | 10 | a | 1010 |
| 3 | 3 | 0011 | | 11 | b | 1011 |
| 4 | 4 | 0100 | | 12 | c | 1100 |
| 5 | 5 | 0101 | | 13 | d | 1101 |
| 6 | 6 | 0110 | | 14 | e | 1110 |
| 7 | 7 | 0111 | | 15 | f | 1111 |

So one byte (8 bits) is exactly two hex digits: `11111111` = `ff` = 255. You actually know this already: MAC addresses like `aa:28:39:e2:41:82` are written in hex as well.

## Structure of an IPv6 address

An IPv6 address consists of **eight blocks** of **16 bits** each — i.e. four hex digits each — separated by colons:

```
2001:0db8:0000:0000:0000:0000:0000:0001
```

As with IPv4 there's a network part and a host part. In IPv6 the network part is called the **prefix**, the host part the **interface ID**. Almost always the prefix is **64 bits** long (`/64`) — the first four blocks:

<pre class="bits-block">
[[n|2001:0db8:0001:0000]]:[[h|a828:39ff:fee2:4182]]
[[n|prefix (64 bits)]]     [[h|interface ID (64 bits)]]
</pre>

## The short form

Because IPv6 addresses are so long, you may shorten them. There are two rules for this:

1. **Leading zeros in a block may be dropped:** `0db8` → `db8`, `0001` → `1`, `0000` → `0`.
2. **One contiguous run of zero blocks** may be replaced by `::` — but only **once** per address. If there are several runs, you shorten the longest one.

Example:

```
2001:0db8:0000:0000:0000:0000:0000:0001   full
2001:db8:0:0:0:0:0:1                      rule 1
2001:db8::1                               rule 2
```

Why `::` only once? With `2001::1::5` nobody could tell how many zero blocks are missing where. With only one `::` it's unambiguous: exactly as many blocks are missing as needed to make eight in total again.

:::tip Key point
An **IPv6 address** has **128 bits**, written as **8 blocks** of **4 hex digits** each. The first 64 bits are usually the **prefix** (network part), the last 64 bits the **interface ID** (host part). Shortening: drop leading zeros and replace **one** run of zero blocks with `::`.
:::
