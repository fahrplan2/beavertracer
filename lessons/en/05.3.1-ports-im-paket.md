## The experiment

1. Switch to :fa-play: **Run** mode, click the **Client-PC** and open the :fa-globe: **Browser**. Load `http://192.168.0.20/`.

## Two kinds of ports

**Destination port — the service:** a server program waits for connections on a fixed port — it is said to **listen** there. For well-known services the numbers are fixed worldwide, the **well-known ports** (0 to 1023). That's why a browser knows without asking: web servers listen on port 80.

**Source port — the sender:** the operating system picks the port on the client side by itself for every new connection, from a high range (in BeaverTracer from 49152). From it, the client recognises which of its connections a reply belongs to.

So a connection is uniquely defined by four details: **IP address and port on both sides**. The pair of IP address and port is called a **socket**, e.g. `192.168.0.20:80`.

## A look at the server

Switch back to :fa-play: **Run** mode, open the :fa-terminal: **Terminal** on the **Server** and enter:

```
$ ss
```

`ss` shows all sockets of the computer. Lines with `LISTEN` are programs listening on a port. Lines with `ESTABLISHED` are existing connections — with the own socket (*Local Address:Port*) and the socket of the other side (*Peer Address:Port*).

## The most important well-known ports

| Port | Protocol | Service |
|---|---|---|
| 22 | SSH | secure remote maintenance (encrypted command line) |
| 25 | SMTP | sending e-mails |
| 53 | DNS | translating names into IP addresses (mostly over UDP) |
| 80 | HTTP | web pages |
| 110 | POP3 | collecting e-mails |
| 143 | IMAP | managing e-mails on the server |
| 443 | HTTPS | encrypted web pages |

:::tip Key point
**Ports** (0 to 65535) tell the connections on a computer apart. Server services **listen** on fixed **well-known ports** (e.g. HTTP 80, HTTPS 443), clients get a free high **source port** for every connection. A connection is uniquely defined by the **IP address and port of both sides**.
:::

:::
