# Entering static routes

:::sim
url=/sims/lesson-4.5.2.btsim
:::

This time there are **two** routers between company A and company B. They're connected via a small network of their own, the **transit network** `10.0.0.0/30`:

| Router | Interface | IP address | Network |
|---|---|---|---|
| Router A | `eth0` | `192.168.0.1/24` | Company A (Anna) |
| Router A | `eth1` | `10.0.0.1/30` | Transit network |
| Router B | `eth0` | `10.0.0.2/30` | Transit network |
| Router B | `eth1` | `172.16.0.1/24` | Company B (Clara) |

:::note
A `/30` network has exactly two usable addresses — perfect for connecting two routers (see section 4.2.3).
:::

## The problem

Switch to :fa-play: **Run** mode and ping Clara from **Anna** (`ping 172.16.0.10`). There's no reply.

Look at the **Routing table IPv4** of **Router A**.

:::quiz mc
Why doesn't Anna's ping arrive at Clara?
- [ ] Anna has no gateway entered
- [x] Router A doesn't know the network `172.16.0.0/24` — it isn't directly connected to it, and there's no route there
- [ ] The transit network is too small
:::

:::evaluate
Check answer
:::

## Entering the route

Router A has to learn: packets for `172.16.0.0/24` go to router B (`10.0.0.2`), and through `eth1`.

1. On **Router A**, open the **Routing table IPv4** tab and click **+ add**.
2. Enter in the new row: **Destination** `172.16.0.0`, **Netmask** `255.255.255.0`, **Next Hop** `10.0.0.2`, **Iface** `eth1`.
3. Save the row with the tick :fa-check:. The **Source** column now shows **Static**.

Ping Clara once more — now the reply comes.

:::note
By the way, router B already knows the way back to company A: its routing table already contains a static route for `192.168.0.0/24` via `10.0.0.1`. Why this way back is just as important you'll see on the next page.
:::

## Following the path: traceroute

With `traceroute` you can display which routers a packet passes through. Enter on **Anna**:

```
$ traceroute 172.16.0.10
```

:::quiz short
How many routers does the packet from Anna to Clara pass through?
= 2
= two
:::

:::quiz mc
Which address does `traceroute` show for router B?
- [x] `10.0.0.2` — its address in the transit network, through which the packet comes in
- [ ] `172.16.0.1` — its address in company B
- [ ] `192.168.0.1`
:::

:::evaluate
Check answers
:::

`traceroute` uses a trick with the **Time to Live** from section 4.3.1: first it sends a packet with TTL 1. The first router subtracts 1, gets 0, discards the packet and reports that back to the sender — now Anna knows the first router. Then TTL 2 for the second router, and so on, until the destination answers.

:::tip Key point
A **static route** is entered by the administrator by hand: destination network, netmask, next hop and interface. With **traceroute** you can follow a packet's path router by router.
:::
