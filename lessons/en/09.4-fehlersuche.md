# Troubleshooting: Nothing Works Since the New Rules

:::sim
url=/sims/lesson-9.4.btsim
:::

Mr Biber, the Beaver school's administrator, switched the firewall to the whitelist principle yesterday. Since then everyone has been complaining: the **school website** can no longer be reached from outside, and **no mail from the internet** arrives anymore. At least SSH is now blocked from outside, as intended.

Find the mistakes in the **Firewall**'s rules and fix them.

<details>
<summary>Tip 1: Does the packet even reach the right rule?</summary>

Test from the **Internet-PC** with `nmap -p 22,25,80 198.51.100.10`, then look at the **Hits** column in the firewall. A rule that stays at 0 although packets should arrive for it is hidden by another rule — or never matches.
</details>

<details>
<summary>Tip 2: Look closely</summary>

Compare every number in the rules with the ports from chapter 5: which port belongs to HTTP, which to SMTP? And remember the order: the first matching rule wins.
</details>

:::task
title: Web and mail reachable again?
Checks whether web and mail of the school server can be reached from the internet and SSH stays blocked.
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## What was going on?

:::quiz multi
Which mistakes were in the rules?
- [x] The web rule allowed port 8080 instead of 80
- [x] The mail rule was below the "drop everything" rule and was never reached
- [ ] The firewall was set to stateful
- [ ] Port 25 is the wrong port for mail
:::

:::evaluate
Check answers
:::

:::tip Key point
Typical mistakes in firewall rules: a **typo** in the port, the wrong **direction** and a wrong **order** in which a general rule hides a specific one. A **port scan** from outside, the firewall's **log** and the rules' **hit counters** help with troubleshooting.
:::
