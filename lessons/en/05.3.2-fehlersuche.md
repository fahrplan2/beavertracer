# Troubleshooting: the service doesn't answer

:::sim
url=/sims/lesson-5.3.2.btsim
:::

After an update, the school reports: "The echo service refuses every connection, and the web page doesn't load any more either." According to the plan, the **web server** is supposed to listen on port `80` and the **echo service** (TCP Echo-Server) on port `5000`. Find the faults and fix them.

<details>
<summary>Tip 1: What does the server answer?</summary>

Try to connect to `192.168.0.20`, port `5000` with the **Simple TCP Client** and open a trace for the Client-PC. What does the server answer to your `[SYN]`?
</details>

<details>
<summary>Tip 2: Which ports are open?</summary>

On the Client-PC, enter `nmap -p 80,5000 192.168.0.20` in the terminal. `nmap` tries the ports one after the other and shows which are open. With `ss` on the server you see on which ports a program really listens there.
</details>

<details>
<summary>Tip 3: Where is this set?</summary>

On the **Server**, open the apps **TCP Echo-Server** and **HTTP-Server**. Is the service running? And on which port?
</details>

:::task
title: Services reachable?
Checks whether the Client-PC reaches the echo service on port 5000 and the web server on port 80. The simulation has to be running in Run mode for this.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## What was going on?

:::quiz multi
Which statements are true?
- [x] The server answered the `[SYN]` to port 5000 with `[RST, ACK]`
- [x] The echo service was listening on port 5050 instead of port 5000
- [x] The web server wasn't started at all
- [ ] The cable between the Client-PC and the Server was broken
:::

:::evaluate
Check answer
:::

:::tip Key point
If a `SYN` is answered with **`RST`**, **no program** is listening on that port: the computer can be reached, but the service can't. Typical causes: the service **isn't started** or listens on a **different port**. A look at the server with `ss` shows which ports are really open.
:::
