# The ISO/OSI reference model

The ISO/OSI model divides the communication between two devices into seven layers. Every layer has a clearly defined job and only uses the services of the layer directly below it:

<table class="osi-table">
<thead>
<tr><th>Layer</th><th>Name</th><th>Job</th><th>Example protocols</th></tr>
</thead>
<tbody>
<tr class="osi-l7"><td>7</td><td>Application</td><td>Interface to the application</td><td>HTTP, DNS, SMTP</td></tr>
<tr class="osi-l6"><td>6</td><td>Presentation</td><td>Data format, encryption</td><td>JPEG, ASCII, MIME</td></tr>
<tr class="osi-l5"><td>5</td><td>Session</td><td>Session management</td><td>RPC, NetBIOS</td></tr>
<tr class="osi-l4"><td>4</td><td>Transport</td><td>End-to-end transmission</td><td>TCP, UDP</td></tr>
<tr class="osi-l3"><td>3</td><td>Network</td><td>Choosing routes between networks</td><td>IP, ICMP</td></tr>
<tr class="osi-l2"><td>2</td><td>Data Link</td><td>Transmission in the local network</td><td>Ethernet, ARP</td></tr>
<tr class="osi-l1"><td>1</td><td>Physical</td><td>Signals on the physical medium</td><td>Copper, fibre, Wi-Fi</td></tr>
</tbody>
</table>

From the experiment on the last page you already know four of these layers: Ethernet (2), IPv4 (3), TCP (4) and HTTP (7). These are exactly the numbers and colours the tracer shows you in the protocol tree.

:::tip Mnemonic
From layer 7 down: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing — **A**pplication, **P**resentation, **S**ession, **T**ransport, **N**etwork, **D**ata Link, **P**hysical.
:::

:::note Borderline cases
Not every protocol fits exactly into one layer. For these protocols the tracer therefore shows several layers:

- **ARP** — layer 2/3: it has no IP header, but it links IP addresses (layer 3) with hardware addresses (layer 2).
- **TLS** — layer 4/5: it sits directly on TCP and manages a secured session.
- **HTTPS** (HTTP inside TLS) — layers 5–7: the classic application layer of the TCP/IP model, which you'll get to know on the next page.
:::

:::note
Layer 1 describes the actual signal transmission on the cable or over the air. BeaverTracer doesn't simulate this level — cables always count as connected without errors, there are neither signal problems nor collisions. So in the tracer, things practically start at layer 2.
:::
