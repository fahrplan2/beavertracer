# The Reply Problem

:::sim
url=/sims/lesson-9.2.btsim
:::

The firewall now follows the whitelist principle: default policy **Drop all**. A single rule allows the school network to browse: **B → A, TCP, dest. port 80, Allow**. The mode is set to **Stateless**.

## The experiment

1. Switch to :fa-play: **Run** mode and load `http://203.0.113.80/` in the :fa-globe: **Browser** on the **Lehrer-PC**.
2. Look at the **Log** and the **Hits** in the **Firewall**.

:::quiz mc
What happens in the browser?
- [ ] The page of www.beispiel.de appears
- [x] The page doesn't load, the browser waits and eventually reports an error
:::

:::quiz mc
Which packets are listed as dropped (`DROP`) in the firewall's log?
- [ ] The Lehrer-PC's requests to port 80
- [x] The replies from `203.0.113.80` with **source port 80** to the Lehrer-PC
- [ ] None at all
:::

:::quiz short
In which direction (A→B or B→A) do the dropped packets travel?
= A→B
= A → B
= AtoB
:::

:::evaluate
Check answers
:::

The Lehrer-PC's request may go out — but already the web server's `SYN, ACK` doesn't get back, because there's no matching rule for the direction A → B, so **Drop all** applies.

## The naive solution

You could enter a second rule: **A → B, TCP, source port 80, Allow** — "everything coming from port 80 may come in". Then browsing actually works.

:::quiz mc
Why is this rule dangerous?
- [ ] Because web servers never use port 80 as source port
- [x] An attacker can simply send their packets with source port 80 — then the firewall lets them through to **any** port in the school network
- [ ] Because web pages then load more slowly
:::

:::evaluate
Check answer
:::

The sender chooses the source port itself — a firewall must not rely on it. But a stateless firewall doesn't know whether a packet is the **reply to a request** or a **new connection attempt** from outside. That's exactly what stateful mode changes.

:::tip Key point
A **stateless** packet filter checks every packet on its own. Replies then need their own rules for the return direction — and such rules (e.g. "source port 80 may come in") can be exploited by attackers, because the sender can choose the source port freely.
:::
