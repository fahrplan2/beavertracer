# Running a ping and following it in the tracer

:::sim
url=/sims/lesson-1.2.3.btsim
:::

The two PCs now have the addresses `192.168.0.10` and `192.168.0.11`. Time for the first test: with **ping**, a PC sends a small request to another one and waits for the reply.

## Running a ping

Switch to :fa-play: **Run** mode. On **Computer 1**, open the :fa-terminal: **Terminal** and type:

```
$ ping 192.168.0.11
```

If the other PC answers, you see one line with a response time for every packet sent — your first successful ping!

:::tip Key point
**Ping** checks whether another device can be reached: it sends a request and measures how long the reply takes.
:::

## Following it in the tracer

Now switch to :fa-magnifying-glass: **Trace** mode. Nothing is shown here yet — at the top left next to **Traces:**, click **+**, choose **Computer 1** and then its port `eth0`.

Now you see a list of all packets that went through this port — including the pings from before. Click one of the packets: below it you see its exact structure, layer by layer.

:::tip Key point
Data in a network isn't sent in one piece, but in small units called **packets**. Every packet carries the sender, the receiver and part of the data.
:::

:::tip
A ping always consists of a request (Echo Request) and a reply (Echo Reply) — can you find both directions in the **Info** column?
:::

## Who's asking before the first ping?

At the very top of the list, even before the first ping, there are two packets with the protocol **ARP**. Read their **Info** column — it says something like:

```
Who has 192.168.0.11? Tell 192.168.0.10
192.168.0.11 is at aa:fd:9f:a5:d2:89
```

Computer 1 knew the other PC's IP address, but not yet its **hardware address** (the *MAC address* — every network card has its own). Without it, it can't send anything. So first it calls out into the network: *"Who has 192.168.0.11? Tell 192.168.0.10!"* The PC being looked for answers with its hardware address. That is exactly the job of **ARP**.

After that, Computer 1 remembers the answer — that's why ARP only shows up before the first ping and not before every one.

:::tip Key point
**ARP** finds the matching hardware address (**MAC address**) for a known IP address: the PC asks everyone in the network, only the device being looked for answers.
:::

Who does Computer 1 send the first ARP packet to? Look at the **Destination** column.
- [ ] Only to the other PC
- [x] To all devices in the network (broadcast)
- [ ] To a server on the internet
:::

:::quiz mc
What does Computer 1 learn from the ARP reply?
