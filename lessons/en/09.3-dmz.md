# The DMZ

:::sim
url=/sims/lesson-9.3.btsim
:::

So far the **school server** was in the same network as the **Lehrer-PC**. That's dangerous: the school server can be reached from the internet. If an attacker finds a hole in the web server and takes over the machine, they're standing **right in the school network** — and the firewall can't do anything anymore, because the traffic from the school server to the Lehrer-PC doesn't flow through it.

The solution: servers that must be reachable from the internet go into a **network of their own** between the internet and the internal network. This network is called the **DMZ** (*demilitarised zone*, after the neutral strip between two borders).

## The setup

On the canvas you see the classic model with **two firewalls** (*Firewall außen* = outer firewall, *Firewall innen* = inner firewall):

```
Internet ──[ Firewall außen ]── Schulrouter ──── DMZ: Schulserver (198.51.100.10)
                                    │
                             [ Firewall innen ]
                                    │
                    LAN: Lehrer-PC (192.0.2.20), Schüler-PC (192.0.2.21)
```

- The **outer firewall** protects everything from the internet. Port A is connected to the internet, port B to the school router.
- The **inner firewall** protects the LAN — also from the DMZ. Port A is connected to the school router, port B to the LAN.

Both firewalls currently let everything through.

## Task: securing the DMZ

Set **both** firewalls to **Stateful** and **Drop all** and enter suitable rules:

- **Outer firewall:** from inside to outside (B → A) everything is allowed; from outside (A → B) only TCP 80 and 25 to the school server `198.51.100.10`.
- **Inner firewall:** from the LAN (B → A) everything is allowed; the direction towards the LAN (A → B) needs no rule — replies come back via the state table.

:::note
Many firewalls have three or more ports ("zones") and model a DMZ in a single device. The principle is the same: traffic between internet, DMZ and LAN always has to pass rules. The model with two firewalls has one advantage: an attacker has to overcome **two** hurdles — often devices from different vendors are even used, so that the same security hole doesn't open both.
:::

:::tip Key point
All servers that must be reachable from the internet go into a **DMZ**. It lies between two firewalls (or in a zone of its own on one firewall): the internet may only reach certain services in the DMZ, the LAN may go into the DMZ and the internet — but there's **no way into the LAN** from the DMZ or the internet. If a server in the DMZ is taken over, the LAN stays protected.
:::
