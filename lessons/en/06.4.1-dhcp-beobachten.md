# Getting an address automatically

:::sim
url=/sims/lesson-6.4.btsim
:::

A **DHCP-Server** and two laptops are connected to the switch. The laptops still have fixed addresses.

## The experiment

1. Switch to :fa-play: **Run** mode, click **Laptop 1** and open the :fa-gear: **IP Settings**.
2. Set the **Mode** from **Static** to **DHCP** and click **Apply**.
3. Wait a few seconds: the fields fill in by themselves.
4. In :fa-magnifying-glass: **Trace** mode, open a trace for **Laptop 1**.

:::quiz table
| Setting | received from the DHCP server |
|---|---|
| IP address | {192.168.0.100} |
| Gateway | {192.168.0.1} |
| DNS server | {192.168.0.53} |
:::

## What's behind it: DORA

A device without an address knows neither where the DHCP server is nor does it have a source address of its own. So it calls out into the network via **broadcast**. The procedure has four steps — named after their initial letters **DORA**:

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | "Is there a DHCP server here?"
DHCP-Server -> Laptop 1: DHCP Offer | "You can have 192.168.0.100."
Laptop 1 -> DHCP-Server: DHCP Request | "I'll take 192.168.0.100."
DHCP-Server -> Laptop 1: DHCP ACK | "Confirmed — valid for 3600 seconds."
:::

The address is only **borrowed** (*lease*): after the **lease time** runs out, the device has to renew it, otherwise the server may hand it out again. Which addresses are currently on loan you can see in the **DHCP Server** app in the **Leases** tab.

:::tip Try it out
Set **Laptop 2** to DHCP as well. Which address does it get? Then look at the DHCP server's **Leases**.
:::

:::tip Key point
**DHCP** hands out IP address, netmask, gateway and DNS server automatically. The procedure is called **DORA**: **D**iscover (client searches via broadcast), **O**ffer (server offers), **R**equest (client accepts), **A**CK (server confirms). The address is borrowed for the **lease time**. DHCP uses **UDP**, port 67 (server) and 68 (client).
:::

:::quiz match
Discover -> The client searches for a DHCP server via broadcast
Offer -> The server offers an address
Request -> The client requests the offered address
ACK -> The server confirms the assignment
:::
