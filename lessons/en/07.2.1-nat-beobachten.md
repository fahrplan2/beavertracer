## The experiment

1. Switch to :fa-play: **Run** mode, click the **PC** and load `http://www.beispiel.de/` in the :fa-globe: **Browser**.
2. In :fa-magnifying-glass: **Trace** mode, open a trace for the **PC** and a second one for the web server **www.beispiel.de**.
3. Compare the packet `GET / HTTP/1.1` in both traces: who is entered as the sender (**source**)?

## What's behind it

In every packet that goes to the internet, the home router replaces the private source address with its own **public WAN address** — and usually the source port too. To the web server it looks as if the request came from the home router. When the reply comes back, the home router swaps the address back again and passes the packet on to the PC.

That way the whole home network can get onto the internet with a single public address — and devices on the internet never see the private addresses.

## The way into the internet

Enter on the **PC** in the :fa-terminal: **Terminal**:

```
$ traceroute 192.0.2.80
```

:::quiz short
How many routers are there between the PC and the web server? (Count all lines before the last one.)
= 4
= four
:::

:::quiz mc
Which address does `traceroute` show for the first router?
- [x] `192.168.178.1` — the home router's LAN address
- [ ] `203.0.113.2` — its WAN address
- [ ] `203.0.113.1` — the provider's first router
:::

:::tip Key point
**NAT** (*Network Address Translation*) replaces a device's **private** source address with the router's **public WAN address** on the way into the internet — and the other way round for replies. That way all devices in the home network share **one** public IPv4 address. This saves addresses and hides the private addresses from the internet.
:::
