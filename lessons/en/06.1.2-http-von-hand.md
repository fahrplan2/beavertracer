# HTTP by hand

:::sim
url=/sims/lesson-6.1.btsim
:::

If HTTP is pure text — can you also talk to a web server yourself, without any browser? Yes: with `telnet` you set up a TCP connection to any port and type the text yourself.

## The experiment

1. Switch to :fa-play: **Run** mode and open the :fa-terminal: **Terminal** on the **Client-PC**.
2. Connect to port 80 of the server:
   ```
   $ telnet 192.168.0.20 80
   ```
3. Type the request line by line — and finish it with an **empty line** (just press **Enter** once more):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

The server answers with a status line, headers and the contact page — as text, just as the browser receives it.

:::quiz mc

- [ ] By a special command `END`
- [x] By the empty line
- [ ] After a certain time
:::

:::

## Provoking errors

A more convenient tool is `curl`: it makes the request for you. With `-v` (*verbose*) it shows everything that goes back and forth — lines with `>` were sent by `curl`, lines with `<` came from the server.

Try it out:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
Which status code do you get for `/gibtsnicht.html`?
= 404
:::

:::quiz short
And which one for the request with the method `POST`?
= 405
:::

:::evaluate
Check answers
:::

:::note
The web server in BeaverTracer can only deliver files — that's why it only allows `GET` and `HEAD`. Real web servers accept forms with `POST`, for example, and pass the data on to a program.
:::

:::tip Key point
Many application layer protocols are **text-based** — HTTP, but also SMTP, POP3 and IMAP. That's why you can speak them by hand with `telnet` and read them in the tracer. That's handy for troubleshooting — but also a security problem: anyone who records the traffic can read everything. How encryption (HTTPS) helps you'll learn in chapter 8.
:::
