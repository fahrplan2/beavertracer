# Packet Filter: Rules

The simplest and most important kind of firewall is the **packet filter**. It looks at every packet passing through and decides, based on a **rule list**, whether it may pass. For that it only reads the headers of layers 3 and 4 — it doesn't look at the content (e.g. the web page).

## What a rule consists of

| Field | Meaning | Example |
|---|---|---|
| **Direction** | Which side does the packet come from? | A → B (from the internet into the school network) |
| **Protocol** | TCP, UDP, ICMP or any | TCP |
| **Source IP** | sender address or network | any |
| **Source port** | sender port | any |
| **Destination IP** | recipient address or network | `198.51.100.10` |
| **Destination port** | recipient port, i.e. the service | `80` |
| **Action** | What happens to matching packets? | Allow |

An empty field means "any". Networks are written in CIDR notation like `198.51.100.0/24`, port ranges with a hyphen like `1024-65535`.

## Order matters

The firewall checks the rules **from top to bottom**. The **first rule that matches** decides — all following rules are no longer looked at for this packet. If no rule matches, the **default policy** applies.

## Three possible actions

| Action | What the firewall does | What the sender notices |
|---|---|---|
| **Allow** | the packet is forwarded | — |
| **Drop** | the packet is silently thrown away | nothing at all — it waits until a timeout expires |
| **Reject** | the packet is thrown away and the sender gets a refusal: a **RST** for TCP, otherwise ICMP "unreachable" | an error message right away |

Which is better? **Drop** tells an attacker less and costs them time, because they have to wait on every attempt. **Reject** is friendlier to your own users: a program gets an error immediately instead of hanging for a long time. In practice, packets from outside are therefore usually dropped and packets from your own network rejected.

:::quiz match
Allow -> The packet is forwarded
Drop -> The packet vanishes, the sender waits in vain for an answer
Reject -> The packet isn't forwarded, but the sender gets a refusal right away
Default policy -> Applies if no rule matches
:::

:::tip Key point
A **packet filter** checks every packet against a **rule list** based on direction, protocol, addresses and ports. The **first matching rule** decides the action: **allow**, **drop** (silently) or **reject** (with a refusal). If no rule matches, the **default policy** applies.
:::
