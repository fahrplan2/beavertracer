# Troubleshooting: it worked yesterday

:::sim
url=/sims/lesson-7.2.4.btsim
:::

Yesterday the home web server was reachable from outside — the port forward `TCP 80 → 192.168.178.10:80` is set up. After a power cut early this morning, Clara can't get to the page any more. Find the fault and fix it permanently.

<details>
<summary>Tip 1: Where does the rule point to?</summary>

Compare the LAN IP in the home router's **Port FW** tab with the address the **Heim-Webserver** really has right now (:fa-gear: **IP Settings**).
</details>

<details>
<summary>Tip 2: Why does it have a different address?</summary>

Is the home web server set to **DHCP**? Then after every restart it gets any free address from the home router's range (in the **DHCP** tab). How do you make sure it always has the same address?
</details>

:::task
title: Home web server reachable again?
Checks whether the home web server has its fixed address and Clara reaches it via the port forward. The simulation has to be running in Run mode for this.
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## What was going on?

:::quiz multi
Which statements are true?
- [x] The home web server got its address via DHCP and had a different one after the restart
- [x] So the port forward pointed to an address where no server was running any more
- [x] A fixed address outside the DHCP range solves the problem permanently
- [ ] The provider had blocked the WAN address
:::

:::evaluate
Check answer
:::

:::tip Key point
Devices a **port forward** points to (servers, printers, cameras) need a **fixed address**: either entered statically and **outside the DHCP range**, or as a fixed assignment in the router's DHCP server. Otherwise they may get a different address after a restart — and the rule leads nowhere.
:::
