# The TCP/IP reference model

The ISO/OSI model is very detailed, but it emerged as a purely theoretical construct. In practice — and also on the Internet — the leaner **TCP/IP model** with only four layers has become the standard instead. It combines several OSI layers into one:

| TCP/IP layer | corresponds to OSI layer(s) | example protocols |
|---|---|---|
| Application | 5, 6, 7 (session, presentation, application) | HTTP, DNS, SMTP |
| Transport | 4 (transport) | TCP, UDP |
| Internet | 3 (network) | IP, ICMP |
| Network access | 1, 2 (physical, data link) | Ethernet, ARP, Wi-Fi |

In practice, the split into session/presentation/application is rarely clear-cut — most application protocols like HTTP handle all of that themselves. The TCP/IP model accounts for this by combining these three layers into a single one.

:::note
When you read about "layer 2", "layer 3", or "layer 4" in the following chapters, this always refers to the numbering of the ISO/OSI model — that remains the shared reference throughout this course, even though BeaverTracer and real-world practice often think more in terms of TCP/IP categories.
:::
