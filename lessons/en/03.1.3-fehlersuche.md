# Troubleshooting the switch network

:::sim
url=/sims/lesson-3.1.3.btsim
:::

Since **David** joined the network, there have been problems: nobody can reach Clara, and something is wrong with Ben. As a network pro, it's your job to sort this out.

## The network plan

This is what the network is *supposed* to look like:

| Device | IP address | Switch port |
|---|---|---|
| Anna | `192.168.0.10/24` | 1 |
| Ben | `192.168.0.11/24` | 2 |
| Clara | `192.168.0.12/24` | 3 |
| David | `192.168.0.13/24` | 4 |

Compare the plan with the simulation: what's different? Fix every fault you find.

<details>
<summary>Tip 1: Where do I start?</summary>

First look at the cables: is every PC connected to the right port? Then check each PC's IP settings.
</details>

<details>
<summary>Tip 2: But Ben does answer pings …?</summary>

Ping Ben from Anna (`ping 192.168.0.11`) and open a trace for Anna. Look closely at the ARP replies: how many are there — and with which MAC addresses?
</details>

## What was going on?

:::quiz mc
How can you tell in the tracer that two devices have the same IP address?
- [ ] The ping always fails
- [x] One ARP request gets two replies with different MAC addresses
- [ ] The switch shows an error message
:::

:::evaluate
Check answer
:::

:::tip Key point
When **troubleshooting**, you compare the **target state** (network plan) with the **actual state** (cables, settings, tracer). Careful: a successful ping doesn't automatically mean everything is right — with a duplicate IP address, maybe the wrong device is simply answering.
:::
