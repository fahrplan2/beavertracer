## Kā izskatās pieprasījums

Noklikšķini trasējumā uz paketes `GET / HTTP/1.1` un atver **Hypertext Transfer Protocol**. HTTP pieprasījums ir tīrs teksts:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

Servera atbilde ir veidota tieši tāpat — ar statusa rindu, galvenēm, tukšu rindu un pēc tās pašu failu:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP pieprasījums
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP pieprasījums
Server -> Client-PC: 200 OK | style.css
:::

## Metodes un statusa kodi

**Metode** norāda, ko klients vēlas:

| Metode | Nozīme |
|---|---|
| **GET** | pieprasīt failu |
| **POST** | nosūtīt datus serverim, piem., aizpildītu veidlapu |
| **HEAD** | pieprasīt tikai galvenes, bez faila |

**Statusa kods** norāda, kā viss noritēja. Pirmais cipars norāda atbildes veidu:

| Kods | Teksts | Nozīme |
|---|---|---|
| **200** | OK | viss kārtībā |
| **301** | Moved Permanently | lapa ir pastāvīgi pārvietota |
| **404** | Not Found | šāda faila nav |
| **405** | Method Not Allowed | šī metode šeit nav atļauta |
| **500** | Internal Server Error | kļūda serverī |

`2xx` nozīmē sekmīgu izpildi, `3xx` pāradresāciju, `4xx` klienta kļūdu (nepareizs pieprasījums), `5xx` servera kļūdu.

:::tip Iegaumējamais secinājums
**HTTP** darbojas pēc **pieprasījuma–atbildes principa**: klients sūta **pieprasījumu** (metode, piemēram, `GET`, ceļš, galvenes), serveris atbild ar **statusa kodu** (piem., `200 OK`, `404 Not Found`), galvenēm un failu. Katram tīmekļa lapas failam ir atsevišķs pieprasījums.
:::
