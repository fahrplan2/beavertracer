# UDP novērošana

:::sim
url=/sims/lesson-5.5.btsim
:::

Uz **Server** šoreiz darbojas **UDP Atbalss-Serveris** ar portu `5000`. Arī šeit kabelis ir sagatavots: **otrā datagramma** no Client-PC uz serveri pazūd.

## Eksperiments

1. Pārslēdzies uz :fa-play: **Palaist** režīmu un atver :fa-terminal: **Termināls** uz **Client-PC**.
2. Ar `nc` sāc UDP „savienojumu“ ar serveri (`-u` nozīmē UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Ievadi pēc kārtas `eins`, `zwei` un `drei` un katru reizi nospied **Enter**. Katra rinda, kas atnāk atpakaļ, ir servera atbalss.
4. Pagaidi dažas sekundes un tad :fa-magnifying-glass: **Izsekošana** režīmā atver izsekošanu priekš **Client-PC**.

:::quiz mc
Kuras atbalsis atnāk atpakaļ?
- [ ] Visas trīs, `zwei` nedaudz vēlāk
- [x] Tikai `eins` un `drei` — `zwei` trūkst, un tā netiek arī nosūtīta atkārtoti
- [ ] Neviena
:::

:::quiz multi
Kuru paketes, ko pazīsti no TCP, UDP gadījumā pilnībā trūkst?
- [x] Savienojuma izveide (`SYN`)
- [x] Apstiprinājumi (`ACK`)
- [x] Savienojuma pārtraukšana (`FIN`)
- [ ] Paketes ar portu numuriem
:::

:::evaluate
Pārbaudīt atbildes
:::

Noklikšķini uz vienas no UDP paketēm un atver **User Datagram Protocol**. Salīdzinājumā ar TCP galveni UDP galvene ir sīka: **Source Port**, **Destination Port**, **Length** (garums) un **Checksum** (kontrolsumma) — kopā tikai 8 baiti. TCP galvene ir vismaz 20 baitu gara, ar secības un apstiprinājuma numuru, karodziņiem un loga izmēru.

:::quiz mc
Kuru uzdevumu no 5.1. sadaļas UDP tomēr veic?
- [x] Multipleksēšanu — izmantojot portus
- [ ] Savienojuma izveidi
- [ ] Drošu pārraidi
:::

:::evaluate
Pārbaudīt atbildi
:::

:::tip Iegaumējamais secinājums
**UDP** ir **bezsavienojuma**: nav izveides, nav apstiprinājuma, nav atkārtotas pārraides, nav secības. Tas piedāvā tikai **portus** (multipleksēšana) un **kontrolsummu**. Toties tas ir ātrs un viegls — UDP galvene ir tikai 8 baitus gara. Ja datagramma pazūd, programmai pašai jārisina šī problēma — vai arī tai tas ir vienalga.
:::
