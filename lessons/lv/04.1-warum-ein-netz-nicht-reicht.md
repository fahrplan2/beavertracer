# Kāpēc ar vienu tīklu nepietiek

:::sim
url=/sims/lesson-4.1.btsim
:::

Uz darbvirsmas redzami divi nelieli uzņēmumu tīkli: **Firma A** ar Annu (`192.168.0.10`) un Benu (`192.168.0.11`) un **Firma B** ar Klāru (`172.16.0.10`) un Dāvidu (`172.16.0.11`). Abi komutatori pat ir savienoti tieši ar kabeli.

## Ping savā tīklā

1. Pārslēdzies uz :fa-play: **Palaist** režīmu (Izpildes režīms), atver :fa-terminal: **Termināls** uz **Anna** un pingo Benu:
   ```
   $ ping 192.168.0.11
   ```
2. Pārslēdzies uz :fa-magnifying-glass: **Izsekošana** režīmu, atver izsekošanu priekš **Anna** un noklikšķini uz `Echo (ping) request`.
3. Protokolu kokā izvērs rindu **Internet Protocol Version 4**. Tā ir paketes IP daļa — tieši par to ir šī nodaļa.

:::quiz match
Source Address -> Sūtītāja IP adrese
Destination Address -> Saņēmēja IP adrese
Time to Live -> Cik maršrutētājiem pakete vēl drīkst iziet cauri
Protocol -> Kāds protokols atrodas paketē (šeit ICMP, tātad ping)
:::

:::evaluate
Pārbaudīt savienojumus
:::

## Ping uz citu tīklu

Pārslēdzies atpakaļ uz :fa-play: **Palaist** režīmu (Izpildes režīms) un pingo no **Anna** uz Klāru (`ping 172.16.0.10`). Pēc tam vēlreiz apskati Annas izsekošanu.

:::quiz mc
Kas notiek?
- [ ] Ping izdodas — komutatori taču ir savienoti
- [x] Neviens ping nenonāk galā, un Annas izsekošanā nav redzama neviena pakete uz Klāru — pat ne ARP pieprasījums
- [ ] Anna nosūta ARP pieprasījumu, bet Klāra neatbild
:::

:::quiz mc
Kāpēc Anna vispār neko nenosūta?
- [ ] Kabelis starp komutatoriem ir bojāts
- [ ] Klāra ir izslēgta
- [x] Anna pēc Klāras IP adreses atpazīst, ka Klāra atrodas citā tīklā — un nezina ceļu uz turieni
:::

Pārbaudīt atbildes
:::

## Kas slēpjas aiz tā

IP adrese darbojas līdzīgi kā pasta adrese: viena daļa norāda, kurā **tīklā** atrodas ierīce (kā iela), otra daļa — kura **ierīce** šajā tīklā ir domāta (kā mājas numurs). Anna atrodas tīklā `192.168.0…`, Klāra — tīklā `172.16.0…`, tātad divās dažādās „ielās“.

Ierīcēm *savā* tīklā dators sūta paketes tieši (ar ARP un komutatora palīdzību, kā jau zini). Lai nonāktu *citā* tīklā, vajadzīga ierīce, kas savieno tīklus un pārsūta paketes tālāk: **maršrutētājs**. Šeit tā vēl nav — tāpēc arī kabelis starp komutatoriem nepalīdz.

:::tip Iegaumējamais secinājums
**Internet Protocol** (**IP**) 3. slānī nodrošina, ka paketes nonāk galā arī starp dažādiem tīkliem. **IP adrese** sastāv no **tīkla daļas** (kurā tīklā?) un **resursdatora daļas** (kura ierīce?). Ierīces vienā tīklā sasniedz viena otru tieši — citiem tīkliem nepieciešams **maršrutētājs**.
:::

Tādējādi rodas divi jautājumi, kam veltīti nākamie apakšnodaļas: no kā dators zina, *kur tieši* adresē beidzas tīkla daļa? Un kā darbojas maršrutētājs?
