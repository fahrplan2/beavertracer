# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) ir pavisam parasts HTTP — tikai tas darbojas nevis tieši pa TCP, bet caur starpā ieliktu šifrētu slāni: **TLS** (*Transport Layer Security*). TLS priekštecis saucās **SSL**; tāpēc joprojām bieži runā par „SSL sertifikātiem”.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP no tā neko nemana: tas sūta savus pieprasījumus kā ierasts, TLS tos šifrē, TCP tos pārvadā. OSI modelī TLS atrodas starp transporta slāni un lietojumu slāni, tātad 4./5. slānī — tas balstās uz TCP un pārvalda aizsargātu sesiju.

| | HTTP | HTTPS |
|---|---|---|
| Ports | 80 | **443** |
| Adrese | `http://…` | `https://…` |
| Saturs izsekotājā lasāms? | jā | nē |
| Pārlūks rāda | „nav drošs” | slēdzene |

TLS savienojuma izveides laikā paveic visu, ko tu apguvi šajā nodaļā:

- Serveris identificē sevi ar savu **sertifikātu** (**autentiskums**).
- Abas puses ar **Diffie-Hellman** vienojas par **sesijas atslēgu** — serveris savu daļu **paraksta**.
- Pēc tam visi dati tiek šifrēti ar **AES** (**konfidencialitāte**) un aizsargāti pret izmaiņām (**integritāte**).

Princips nav attiecināms tikai uz tīmekli: arī e-pasts (8.4. apakšnodaļa) un daudzi citi protokoli darbojas caur TLS tieši tādā pašā veidā.

Turpmākajās apakšnodaļās tu novēro HTTPS izsekotājā, pats to iestati un pēti, kad pārlūks brīdina — un kāpēc.
