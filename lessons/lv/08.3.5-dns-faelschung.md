# Uzbrukums: DNS viltošana

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna vēlas **Client-PC** atvērt savu internetbanku **Biberbank**. Viņa nezina: kāds ir ieguvis piekļuvi **DNS-Server** un izmainījis vienu ierakstu.

Uz darbvirsmas redzams īstais tīmekļa serveris **www.biberbank.de** un **Angreifer** dators. Tajā darbojas bankas tīmekļa vietnes kopija.

## 1. daļa: bez šifrēšanas

Pārslēdzies uz :fa-play: **Palaist** režīmu un **Client-PC** :fa-globe: **Pārlūks** atver `http://www.biberbank.de/`.

:::quiz mc
Ko tu redzi?
- [x] Biberbank pieteikšanās lapu bez jebkāda brīdinājuma
- [ ] Brīdinājumu, ka lapa ir viltota
- [ ] Kļūdas paziņojumu
:::

:::evaluate
Pārbaudīt atbildi
:::

Viss izskatās normāli. Bet ar kuru serveri pārlūks patiesībā sazinās? Atver **Client-PC** :fa-terminal: **Termināls**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Kādu IP adresi DNS serveris atgriež vārdam `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Kam pieder šī adrese? (Rediģēšanas režīmā noklikšķini uz ierīcēm vai apskati to :fa-gear: **IP iestatījumi**.)
- [ ] Biberbank īstajam tīmekļa serverim
- [x] Uzbrucējam
- [ ] DNS serverim
:::

:::evaluate
Pārbaudīt atbildes
:::

Ja Anna tagad būtu ievadījusi konta numuru un PIN, tie būtu nonākuši tieši pie uzbrucēja. Izmantojot **HTTP**, viņai **nav nekādu iespēju** pamanīt krāpšanu: adreses joslā redzams pareizais nosaukums, un lapa izskatās īsta.

## 2. daļa: ar HTTPS

Tagad atver `https://www.biberbank.de/`.

:::quiz mc
Kas notiek?
- [ ] Viltotā lapa parādās ar atslēdziņas simbolu
- [x] Pārlūks brīdina: sertifikāts ir izsniegts citam vārdam
- [ ] Parādās Biberbank īstā lapa
:::

:::quiz short
Kādam vārdam ir izsniegts uzbrucēja sertifikāts (bez `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Pārbaudīt atbildes
:::

Uzbrucējam ir pat **īsts** sertifikāts no uzticama sertifikātu izsniedzēja (CA) — taču savam domēnam `www.biber-gewinnspiel.de`. Sertifikātu domēnam `www.biberbank.de` viņš no neviena CA nesaņems, jo šis domēns viņam nepieder. Bez Biberbank **privātās atslēgas** viņš nevar izmantot arī bankas īsto sertifikātu: rokasspiedienā ar to būtu jāparaksta Server Key Exchange.

:::quiz multi
No kā HTTPS šeit pasargā — un no kā nepasargā?
- [x] HTTPS atklāj, ka serveris nav īstais
- [ ] HTTPS novērš DNS servera viltošanu
- [x] HTTPS palīdz tikai tad, ja lietotājs brīdinājumu uztver nopietni
- [ ] Ar HTTPS viltotā lapa vispār nav sasniedzama
:::

:::evaluate
Pārbaudīt atbildes
:::

## 3. daļa: DNS servera labošana

Atver **DNS-Server** un izlabo ierakstu vārdam `www.biberbank.de`. Pareizo adresi atradīsi tīmekļa servera **www.biberbank.de** :fa-gear: **IP iestatījumi**. Neaizmirsti noklikšķināt uz **Saglabāt**.

:::note
**Client-PC** uz laiku iegaumē DNS atbildes, lai nebūtu katru reizi jājautā no jauna (**DNS kešatmiņa**). Cik ilgi, norādīts kolonnā **TTL** (*Time to Live*) sekundēs. Ja `nslookup` uzreiz pēc labojuma joprojām atgriež veco adresi, nogaidi TTL un mēģini vēlreiz.
:::

:::task
title: Vai Biberbank atkal ir īsta?
Pārbauda, vai Client-PC www.biberbank.de atrisina uz pareizo adresi un vai lapu var atvērt ar HTTPS bez brīdinājuma.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Patiesībā uzbrucējs reti viltojumu veic pašā DNS serverī. Biežāk viņš savas atbildes pasniedz publiskā WLAN tīklā, maina mājas maršrutētāja iestatījumus vai ar līdzīgi izskatošos adresi, piemēram, `www.biberbank-login.de`, vilina upurus (**pikšķerēšana**). Pret līdzīgi skanošu vārdu HTTPS nepalīdz — uzbrucējs tam var iegūt derīgu sertifikātu. Tāpēc: lasi adresi uzmanīgi!
:::

:::tip Iegaumējamais secinājums
Ja notiek **DNS viltošana**, DNS serveris vārdam atgriež uzbrucēja adresi. Izmantojot **HTTP**, to nemana. Izmantojot **HTTPS**, uzbrucēja sertifikāts neatbilst atvērtajam vārdam, un pārlūks **brīdina** — jo sertifikātu svešiem domēniem neviens CA neizsniedz, un īstā servera privātās atslēgas uzbrucējam nav.
:::
