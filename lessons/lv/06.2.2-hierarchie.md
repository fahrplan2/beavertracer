# Kā ir organizēta DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Neviens atsevišķs serveris nevar zināt visus pasaules vārdus. Tāpēc DNS ir veidota **hierarhiski** — tāpat kā paši vārdi. Tos lasa no labās uz kreiso pusi:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Serveri, kas ir atbildīgs par domēnu un patiešām zina atbildi, sauc par **autoritatīvo**. Ceļu līdz tam datora vietā veic **resolveris** — šeit tas ir dators **DNS-Resolver**.

## Eksperiments

1. Pārslēdzies uz :fa-play: **Palaist** režīmu un datorā **Client-PC** :fa-terminal: **Termināls** ievadi:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. :fa-magnifying-glass: **Izsekošana** režīmā atver izsekošanu priekš **DNS-Resolver**.

Resolveris tavā vietā ir veicis veselu virkni pieprasījumu. Sasaisti, kurš kādu atbildi ir sniedzis:

:::quiz match
Root-Server (192.168.0.101) -> Norāde: par .de ir atbildīgs ns.nic.de
de-Server (192.168.0.102) -> Norāde: par beaver-schule.de ir atbildīgs ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Atbilde: www.beaver-schule.de adrese ir 192.168.0.20
:::

:::quiz mc
Kuru resolveris jautā vispirms?
- [x] Root serveri
- [ ] Schul-DNS
- [ ] Client-PC
:::

:::evaluate
Pārbaudīt atbildes
:::

:::note
Starplaikā resolveris jautā arī to serveru adreses, uz kuriem tas tika novirzīts (`A ns.nic.de`). Īstie DNS serveri šīs adreses parasti nosūta uzreiz līdzi. Turklāt resolveri kādu laiku atceras katru atbildi (**kešatmiņa**) — uz nākamo pieprasījumu pēc tā paša vārda tie atbild uzreiz paši. Cik ilgi, ir norādīts ierakstā kā **TTL** (*Time to Live*) sekundēs.
:::

## Svarīgākie ierakstu veidi

| Veids | Nozīme | Piemērs |
|---|---|---|
| **A** | vārds → IPv4 adrese | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | vārds → IPv6 adrese | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | vārds → cits vārds (aizstājvārds) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | domēna atbildīgais pasta serveris | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | domēna atbildīgais DNS serveris | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Iegaumējamais secinājums
DNS ir **hierarhiska**: **root serveri** norāda uz **augstākā līmeņa domēnu** (piem., `.de`) serveriem, tie — uz atsevišķu **domēnu** serveriem. Atbildīgais **autoritatīvais** serveris zina atbildi. **Resolveris** šo ceļu veic datora vietā un atceras atbildes (**kešatmiņa**). Svarīgi ierakstu veidi: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Ieraksta izveide

Skola vēlas, lai tās tīmekļa vietne būtu pieejama arī adresē `intranet.beaver-schule.de`.

1. :fa-play: **Palaist** režīmā noklikšķini uz **Schul-DNS** un atver lietotni **DNS-Server**.
2. Atver cilni **A**. Noklikšķini uz **+** un jaunajā rindā ievadi vārdu `intranet.beaver-schule.de` un adresi `192.168.0.20`.
3. Pārbaudi datorā Client-PC ar `nslookup intranet.beaver-schule.de`.

:::task
title: Jaunais vārds ierakstīts?
Pārbauda, vai Client-PC vārdu intranet.beaver-schule.de atrisina uz tīmekļa servera adresi. Lai tas darbotos, simulācijai jādarbojas Izpildes režīmā.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
