# Tīmekļa vietnes atvēršana un novērošana

Šajā daļā tu pats neko neveido: uz darbvirsmas jau ir sagatavota simulācija ar **Client-PC** un **Webserver**.

## Lapas atvēršana

1. Pārslēdzies uz :fa-play: **Palaist** režīmu.
2. Uz **Client-PC** atver lietotni :fa-globe: **Pārlūks** un atver tīmekļa servera adresi: `http://192.168.0.20/`.
3. Pārslēdzies uz :fa-magnifying-glass: **Izsekošana** režīmu un ar **+** atver izsekojumu priekš **Client-PC**, pieslēgvieta `eth0` — tieši tāpat kā ar ping.

:::note
Vienas lapas atvēršanai tas ir pārsteidzoši daudz paketes — ievērojami vairāk nekā ar ping. Tīmekļa lapas lejupielāde ir daudzpakāpju process, nevis viena darbība.
:::

## Paketu saraksta lasīšana

Tev vēl nav jāzina, ko precīzi dara katrs protokols. Viss, kas vajadzīgs tālākajiem jautājumiem, ir kolonnās **Protokols** un **Info**.

:::quiz mc
Kurš protokols ir saraksta pašā augšā?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Saskaiti: cik **TCP** paketes ir pirms pirmās **HTTP** paketes?
= 3
= trīs
:::

:::quiz mc
Ko tīmekļa serveris atbild uz pārlūka pieprasījumu? Paskaties otrās HTTP paketes Info kolonnā.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Pārbaudīt atbildes
:::

## Iesaistīto protokolu nosaukšana

No taviem novērojumiem tagad var nolasīt, kurš protokols par ko bija atbildīgs.

:::tip Padoms
Vēlreiz izlasi **Info** kolonnas: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` un `200 OK` jau gandrīz visu pasaka.
:::

:::quiz match
ARP -> Jautā visiem tīklā: „Kam ir IP adrese 192.168.0.20?”
TCP -> Ar trim īsām paketēm izveido savienojumu, pirms tiek sūtīti dati
HTTP -> Pieprasa tīmekļa lapu (GET) un atsūta to atpakaļ (200 OK)
:::

:::evaluate
Pārbaudīt sakārtojumu
:::

:::tip Iegaumējamais secinājums
Tīmekļa lapas atvēršana noris pa posmiem: vispirms tīklā **atrast** serveri (ARP), tad **izveidot** savienojumu (TCP), tad **pieprasīt un saņemt** lapu (HTTP) — un beigās savienojumu atkal **pārtraukt** (TCP paketes ar `[FIN]` saraksta beigās).
:::

:::note
Šoreiz tu servera IP adresi ievadīji tieši, tāpēc **DNS** (vārdu, piemēram, `www.beispiel.de`, „tulkošana” par IP adresi) vēl netika izmantots. To mēs apskatīsim 6. nodaļā.
:::

Vai pamanīji, ka protokoliem paketes uzbūvē ir krāsaini apzīmējumi ar cipariem? Kas tas ir, noskaidrosim 2. nodaļā. Tur aplūkosim, kā sistemātiski klasificēt daudzos protokolus — ar OSI un TCP/IP atsauces modeli. Ar to 1. nodaļa ir pabeigta.
