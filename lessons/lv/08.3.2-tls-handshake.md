Pirms tiek nosūtīts pirmais šifrētais pieprasījums, klientam un serverim ir jāvienojas: par metodi, par sesijas atslēgu — un klientam ir jāpārbauda, ar ko viņš sazinās. Šī savienojuma izveide tiek saukta par **TLS rokasspiedienu** (TLS handshake).

## Norise diagrammā

Bez TCP apstiprinājumiem (`ACK`) rokasspiediens izskatās šādi:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Kas šajā laikā notiek — un kurš pamatelements no 8.1. sadaļas ir aiz tā:

1. **Client Hello / Server Hello:** klients un serveris sasveicinās, apmainās ar nejaušiem skaitļiem un vienojas par metodēm (BeaverTracer: atslēgu apmaiņa ar **ECDHE**, paraksts ar **ECDSA**, šifrēšana ar **AES**).
2. **Certificate:** serveris nosūta savu **sertifikātu**. Klients pārbauda CA parakstu, derīguma termiņu un vārdus. Ja pārbaude neizdodas, viņš šeit pārtrauc savienojumu — un pārlūks parāda brīdinājumu.
3. **Server Key Exchange:** serveris nosūta savu **Diffie-Hellman daļu** — un **paraksta** to ar savu privāto atslēgu. Klients pārbauda parakstu ar publisko atslēgu no sertifikāta. Tā viņš zina: šī daļa patiešām nāk no sertifikāta īpašnieka, nevis no Man-in-the-Middle uzbrucēja.
4. **Client Key Exchange:** klients nosūta savu Diffie-Hellman daļu. Tagad abi var aprēķināt vienu un to pašu **sesijas atslēgu** — tā nekad netika pārsūtīta.
5. **Change Cipher Spec:** „No šī brīža es šifrēju.”
6. **Encrypted Handshake Message (Finished):** abas puses nosūta — jau šifrētu — kontrolsummu par visiem līdzšinējiem rokasspiediena ziņojumiem. Ja uzbrucējs ceļā ko ir mainījis, kontrolsummas nesakritīs un savienojums tiks pārtraukts.
7. **Application Data:** no šī brīža plūst HTTP dati — simetriski šifrēti ar AES.

:::quiz match
Certificate -> Serveris apliecina savu identitāti ar sertifikātu
Server Key Exchange -> Servera parakstīta Diffie-Hellman daļa
Client Key Exchange -> Klienta Diffie-Hellman daļa
Change Cipher Spec -> No šī brīža tiek šifrēts
Application Data -> Šifrēti HTTP dati
:::

:::note
Izsekošanā tu redzi **divus** TLS savienojumus pēc kārtas: pārlūks vispirms lejupielādē lapu un pēc tam izveido jaunu savienojumu stila failam `style.css`. Katram savienojumam ir savs rokasspiediens un sava sesijas atslēga. Īstie pārlūki savienojumus notur atvērtus un tā ietaupa daļu šī darba. Jaunākā versija **TLS 1.3** turklāt iztiek ar mazāk ziņojumiem nekā šeit parādītā TLS 1.2.
:::

:::tip Iegaumējamais secinājums
Veicot **TLS rokasspiedienu**, serveris apliecina savu identitāti ar **sertifikātu**, abas puses ar **Diffie-Hellman** vienojas par **sesijas atslēgu** (serveris savu daļu **paraksta**), un ar **Finished** abas puses pārbauda, ka neviens nav mainījis rokasspiedienu. Pēc tam dati tiek pārsūtīti kā **Application Data**, simetriski šifrēti.
:::
