# IPv6 tīklā

:::sim
url=/sims/lesson-4.6.3.btsim
:::

Pie slēdža ir pieslēgti Anna, Ben un maršrutētājs. Annai un Benam IPv6 ir iestatīts uz **SLAAC (automatisks)** — IPv6 adresi viņiem neviens nav ierakstījis. Maršrutētājs zina prefiksu `2001:db8:1::/64`.

## No kurienes nāk adrese?

1. Pārslēdzies uz :fa-play: **Palaist** režīmu un pagaidi dažas sekundes.
2. Atver **Anna** :fa-terminal: **Termināls** un ievadi `ip a`.

Blakus IPv4 adresei tu redzi divas rindas ar `inet6`: vienu adresi ar `scope link` un vienu ar `scope global`.

:::quiz mc
Kura no abām IPv6 adresēm ir lokālās saites (link-local) adrese?
- [x] Tā, kas sākas ar `fe80::` (`scope link`)
- [ ] Tā, kas sākas ar `2001:db8:1:` (`scope global`)
:::

:::quiz mc
No kurienes nāk globālās adreses prefikss `2001:db8:1:0`?
- [ ] Anna to ir izdomājusi pati
- [x] No maršrutētāja — tas paziņo prefiksu tīklā
- [ ] No slēdža
:::

:::evaluate
Pārbaudīt atbildes
:::

Salīdzini **Interface ID** (pēdējos četrus blokus) ar Annas **MAC adresi** — tu to atradīsi pašā apakšā sadaļā :fa-gear: **IP iestatījumi**. No MAC adreses `aa:28:39:e2:41:82` rodas, piemēram, Interface ID `a828:39ff:fee2:4182`: vidū tiek ievietots `ff:fe`, un pirmais bits sākumā tiek apgriezts (tāpēc no `aa` kļūst `a8`).

Šo paņēmienu sauc par **SLAAC** (*Stateless Address Autoconfiguration*): maršrutētājs paziņo prefiksu, bet Interface ID katra ierīce izveido pati.

:::note
Tā kā MAC adrese ierīci identificē viennozīmīgi, pēc Interface ID to varētu atpazīt jebkur internetā. Tāpēc īstas ierīces parasti papildus izmanto nejaušus Interface ID, kas regulāri mainās (*Privacy Extensions*) — zināma privātuma aizsardzība.
:::

## Kaimiņu atrašana — bez ARP

1. Ievadi uz **Ben** `ip a` un iegaumē viņa **globālo** IPv6 adresi.
2. Ping to no **Anna**, piemēram, `ping 2001:db8:1:0:…` (ar Bena pilno adresi).
3. Pārslēdzies uz :fa-magnifying-glass: **Izsekošana** režīmu un atver trasējumu priekš **Anna**.

Apskati paketes tieši pirms pirmā `Echo (ping) request`.

:::quiz multi
Kuri apgalvojumi ir pareizi?
- [x] Annas ARP pieprasījuma vietā sūta **Neighbor Solicitation** („Kam pieder šī adrese?”)
- [x] Ben atbild ar **Neighbor Advertisement** un norāda savu MAC adresi
- [x] Pieprasījums tiek sūtīts uz multicast adresi (`ff02::1:ff…`), nevis visiem ar apraidi
- [ ] Anna sūta ARP pieprasījumu kā IPv4 gadījumā
- [x] Maršrutētājs regulāri sūta **Router Advertisements** uz `ff02::1` — tajos ir norādīts prefikss
:::

:::evaluate
Pārbaudīt atbildes
:::

:::tip Iegaumējamais secinājums
IPv6 gadījumā **NDP** (*Neighbor Discovery Protocol*, ICMPv6 daļa) pārņem ARP uzdevumus: ar **Neighbor Solicitation** un **Neighbor Advertisement** ierīces atrod savu kaimiņu MAC adreses. Ar **Router Advertisements** maršrutētājs paziņo prefiksu — no tā ierīces ar **SLAAC** palīdzību paši izveido savu adresi.
:::
