# Viss kopā: kas notiek, atverot tīmekļa lapu?

:::goal
**Mācību mērķis:** Tu vari soli pa solim izskaidrot, kuri protokoli un kuros slāņos ir iesaistīti, kad tikko ieslēgts portatīvais dators atver tīmekļa lapu.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Tagad viss, ko esi apguvis šajā kursā, savienojas kopā. Pie slēdža ir pieslēgti **DHCP serveris**, **DNS-Server**, **Webserver** un **Laptop**, kas tikko tika ieslēgts — tam vēl nav IP adreses, un tas ir iestatīts uz DHCP.

## Eksperiments

1. Pārslēdzies uz :fa-play: **Palaist** režīmu un pagaidi dažas sekundes.
2. Noklikšķini uz **Laptop**, atver :fa-globe: **Pārlūks** un atver `http://www.beaver-schule.de/`.
3. Režīmā :fa-magnifying-glass: **Izsekošana** atver izsekošanu (trace) ierīcei **Laptop**. Šeit ir visa stāsta gaita — no pašas pirmās paketes.

Sakārto soļus pareizajā secībā, kādā tie ir redzami izsekošanā:

:::quiz match
1. solis -> DHCP: portatīvais dators saņem IP adresi, vārteju un DNS serveri
2. solis -> ARP: portatīvais dators jautā pēc DNS servera MAC adreses
3. solis -> DNS: portatīvais dators jautā pēc www.beaver-schule.de IP adreses
4. solis -> ARP: portatīvais dators jautā pēc tīmekļa servera MAC adreses
5. solis -> TCP: trīspusējā rokasspiešana ar tīmekļa serveri
6. solis -> HTTP: GET / un atbilde 200 OK
:::

:::evaluate
Pārbaudīt secību
:::

Un zem visa tā atrodas **IP** (3. slānis), kas adresē katru no šīm paketēm, un **Ethernet** (2. slānis), kas to nogādā līdz nākamajai ierīcei. Ja tīmekļa serveris atrastos citā tīklā, klāt nāktu arī **maršrutētājs**: tad portatīvais dators jautātu pēc sava **vārtejas** MAC adreses, nevis pēc tīmekļa servera MAC adreses.

:::quiz mc
Kāpēc portatīvais dators DNS pieprasījumu var veikt tikai pēc DHCP?
- [ ] Jo DNS darbojas tikai caur TCP
- [x] Jo tikai ar DHCP palīdzību tas saņem savu IP adresi un uzzina, kurš DNS serveris ir atbildīgs
- [ ] Jo DNS serveris startē tikai pēc DHCP servera
:::

:::quiz mc
Cik TCP savienojumu pārlūks izveido ar tīmekļa serveri — un kāpēc?
- [ ] Vienu — visam kopā
- [x] Divus — vienu lapai un vienu stila lapai (stylesheet)
- [ ] Nevienu, HTTP nav vajadzīgs TCP
:::

:::tip Iegaumējamais secinājums
Aiz viena klikšķa kopā strādā visi slāņi: **DHCP** nodrošina pamatiestatījumus, **ARP** atrod MAC adreses lokālajā tīklā, **DNS** pārvērš nosaukumu, **TCP** izveido uzticamu savienojumu un **HTTP** lejupielādē lapu — viss iepakots **IP** paketēs un **Ethernet** kadros.
:::

Tagad tu vari izskaidrot tīmekļa lapas atvēršanu no pirmās līdz pēdējai paketei. Nodaļas noslēgumā vēl sekos īss ieskats citos protokolos. Nākamajās nodaļās aplūkosim mājas tīklu ar NAT, drošību un šifrēšanu — un līdz ar to jautājumu, kā novērst, ka kāds var nolasīt visas šīs paketes.
