# Kas jādara transporta slānim?

:::sim
url=/sims/lesson-5.1.btsim
:::

Uz **Server** vienlaikus darbojas divi pakalpojumi: **tīmekļa serveris** un neliels **atbalss pakalpojums**, kas katru saņemto ziņojumu uzreiz sūta atpakaļ. Ar diviem eksperimentiem tu uzzināsi, ko IP viens pats nespēj nodrošināt.

## 1. eksperiments: divas programmas vienlaikus

1. Pārslēdzies uz :fa-play: **Palaist** režīmu un noklikšķini uz **Client-PC**.
2. Atver :fa-globe: **Pārlūks** un atver `http://192.168.0.20/`.
3. Loga augšdaļā noklikšķini uz **Zurück** un atver **Vienkāršs TCP klients**. Laukā **Host** ievadi `192.168.0.20`, laukā **Port** ievadi `5000` un noklikšķini uz **Savienoties**.
4. Pārslēdzies uz :fa-magnifying-glass: **Izsekošana** režīmu un ar **+** atver trasējumu priekš **Client-PC**, pieslēgvieta `eth0`.

Noklikšķini uz pārlūka paketes (piemēram, `GET /`) un uz TCP klienta paketes un katrā gadījumā izvērs **Internet Protocol Version 4**.

:::quiz mc
Kādas IP adreses ir pārlūka un TCP klienta paketēm?
- [x] Abām vienādas: no `192.168.0.10` uz `192.168.0.20`
- [ ] Pārlūks izmanto citu mērķa IP adresi nekā TCP klients
- [ ] TCP klienta paketēm nav IP adreses
:::

:::quiz mc
Vai tātad ar mērķa IP adresi pietiek, lai serveris zinātu, vai pakete pieder tīmekļa serverim vai atbalss pakalpojumam?
- [ ] Jā
- [x] Nē — abām paketēm ir viena un tā pati mērķa IP adrese
:::

Kaut kam citam ir jānodala abi savienojumi. Apskati paketes ar `[SYN]` kolonnu **Info** — tā katrreiz ir savienojuma pirmā pakete:

:::quiz short
Kāds skaitlis **pārlūkam** ir aiz bultiņas `→`?
= 80
:::

:::quiz short
Un **TCP klientam**?
= 5000
:::

:::evaluate
Pārbaudīt atbildes
:::

Vairāk par šiem skaitļiem — **portiem** — uzzināsi 5.3. nodaļā. Pagaidām pietiek ar zināšanu: tikai transporta slānis nodrošina, ka vairākas programmas var vienlaikus sazināties, izmantojot *vienu* IP adresi, un katra pakete nonāk pie pareizās programmas. To sauc par **multipleksēšanu**.

## 2. eksperiments: kad pakete pazūd

1. Pārslēdzies uz :fa-play: **Palaist** režīmu un noklikšķini uz **kabeļa** starp Client-PC un Server.
2. Logā **Verbindung** iestati **Konfigurierten Paketverlust** uz `25%`.
3. Atver uz **Client-PC** :fa-terminal: **Termināls** un nosūti sešus ping:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Tas aizņem apmēram pusminūti — pagaidi, līdz parādās statistika.

:::quiz mc
Kas notiek?
- [ ] Uz visiem sešiem ping tiek atbildēts
- [x] Daži ping paliek bez atbildes — un neviens tos vairs nesūta atkārtoti
- [ ] Pazudušie ping tiek automātiski atkārtoti, līdz tie nonāk galā
:::

:::evaluate
Pārbaudīt atbildi
:::

Ar ping tā nav problēma — tā jēga taču ir parādīt, vai kaut kas pazūd. Taču tīmekļa lapai, e-pastam vai lejupielādei trūkstošs gabals būtu liktenīgs: fails būtu bojāts.

## Četri transporta slāņa uzdevumi

| Uzdevums | Ko tas nozīmē |
|---|---|
| **Multipleksēšana** | Vairākas programmas un savienojumi dala vienu IP adresi; katra pakete nonāk pie pareizās programmas. |
| **Savienojuma izveide** | Pirms dati sāk plūst, abas puses vienojas, ka sazināsies savā starpā. |
| **Uzticama pārraide** | Saņēmējs apstiprina, kas ir saņemts. Trūkstošais tiek nosūtīts vēlreiz, secība tiek atjaunota. |
| **Savienojuma pārtraukšana** | Beigās abas puses savienojumu pabeidz sakārtoti. |

:::tip Iegaumējamais secinājums
**Transporta slānis** (4. slānis) nodrošina, ka dati nonāk pie pareizās **programmas** (**multipleksēšana**). Protokols **TCP** papildus nodrošina, ka tie nonāk **pilnībā** un **pareizā secībā** — izmantojot savienojuma izveidi, apstiprinājumus, atkārtotu pārraidi un savienojuma pārtraukšanu.
:::

:::quiz match
Datorā vienlaikus darbojas pārlūks, pasta programma un ziņojumapmaiņas programma. -> Multipleksēšana
Pirms dati sāk plūst, abas puses pārliecinās, ka otra puse ir gatava. -> Savienojuma izveide
Faila daļa nenonāk galā un tiek nosūtīta vēlreiz. -> Uzticama pārraide
Pēc lejupielādes abas puses atkal atbrīvo savienojumu. -> Savienojuma pārtraukšana
:::
