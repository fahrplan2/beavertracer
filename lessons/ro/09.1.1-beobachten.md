# Observarea unui firewall

:::sim
url=/sims/lesson-9.1.1.btsim

În această simulare, cineva a introdus deja trei reguli în firewall. Fă clic pe **Firewall** și uită-te la fila **Regeln**. **Port A** al firewall-ului este conectat la internet, **Port B** la routerul școlii — „A → B" înseamnă deci „din internet în rețeaua școlii".

:::quiz table
| Regel | Richtung | Protokoll | Ziel-Port | Aktion |
|---|---|---|---|---|
| 1 | A → B | {TCP} | {22} | {Verwerfen} |
| 2 | A → B | TCP | {110} | {Zurückweisen} |
| 3 | A → B | {ICMP} | beliebig | Verwerfen |
:::

:::evaluate
Verifică tabelul
:::

## Ping din exterior

Treci în modul :fa-play: **Rulare** și dă ping de la **Internet-PC** către serverul școlii:

```
$ ping -c 2 198.51.100.10
```

Apoi deschide în firewall fila **Protokoll**.

:::quiz mc
Ce raportează `ping`?
- [x] `Anfrage abgelaufen` — nu se întoarce nimic
- [ ] `Paket gefiltert`
- [ ] Două răspunsuri de la serverul școlii
:::

:::quiz short
Cu ce cuvânt încep rândurile noi din jurnalul firewall-ului?
= DROP
:::

Verifică răspunsurile
:::

## Scanarea porturilor: abandonate sau respinse?

Scanează acum țintit cinci porturi. Portul 3306 (o bază de date) nu este deloc în funcțiune pe serverul școlii.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (abandonat) -> filtered
25 (permis, serviciul rulează) -> open
110 (respins) -> closed
3306 (permis, fără serviciu) -> closed
:::

:::evaluate
Verifică asocierea
:::

:::quiz multi
Ce poate deduce un atacator din rezultat?
- [x] La `filtered` află: acolo este un firewall care înghite pachetele
- [x] La `closed` nu poate distinge dacă un firewall respinge pachetele sau pur și simplu nu rulează niciun serviciu
- [ ] La `filtered` află ce serviciu rulează în spatele portului
- [ ] La `closed` serviciul este totuși accesibil
:::

:::evaluate
Verifică răspunsurile
:::

La final, uită-te la coloana **Treffer** din lista de reguli: acolo firewall-ul numără câte pachete a decis deja fiecare regulă. Valoarea de lângă **Standardrichtlinie** numără toate pachetele pentru care nu s-a potrivit nicio regulă.

:::tip De reținut
Pachetele **abandonate** dispar fără urmă: `ping` raportează un timeout, `nmap` raportează `filtered`. Pachetele **respinse** primesc din partea firewall-ului un răspuns de refuz (la TCP un RST) — din exterior arată ca un port închis. **Jurnalul** firewall-ului arată ce pachete a oprit, coloana **Treffer** arată ce regulă s-a aplicat.
:::
