# Ordinea regulilor și atitudinea de bază

## Mai întâi excepția, apoi regula

Deoarece **prima regulă potrivită** câștigă, ordinea contează. Uită-te la această listă de reguli (toate regulile se aplică pe direcția A → B, politica implicită: Permite tot):

| Nr. | Protocol | Port destinație | Acțiune |
|---|---|---|---|
| 1 | TCP | oricare | Respinge |
| 2 | TCP | 80 | Permite |

:::quiz mc
Un pachet din internet ajunge la portul TCP 80. Ce se întâmplă?
- [ ] Este permis, deoarece regula 2 permite exact portul 80
- [x] Este respins, deoarece se potrivește deja regula 1 — regula 2 nu este niciodată atinsă
- [ ] Firewall-ul îl întreabă pe administrator
:::

:::evaluate
Verifică răspunsul
:::

În general se aplică: **regulile speciale sus, cele generale jos.** O regulă care acoperă mult „umbrește" toate regulile de sub ea. Coloana **Potriviri** dezvăluie astfel de reguli moarte: ele rămân la 0.

## Blacklist sau whitelist?

În secțiunea 9.1.2 ai **interzis** anumite porturi și ai permis tot restul. Aceasta se numește **blacklist** („listă neagră"). Opusul este **whitelist**-ul: **permiți** doar ce este necesar și interzici tot restul — cu o regulă finală „respinge tot" sau cu politica implicită **Respinge tot**.

| | Blacklist | Whitelist |
|---|---|---|
| Atitudinea de bază | totul permis, excepțiile interzise | totul interzis, excepțiile permise |
| Politica implicită | Permite | Respinge |
| serviciu nou pe server | este imediat accesibil din exterior | rămâne blocat până când cineva îl deblochează |

:::quiz mc
Mâine un profesor instalează pe serverul școlii o bază de date care ascultă pe portul 3306. Ce se întâmplă cu firewall-ul din secțiunea 9.1.2 (blacklist)?
- [x] Baza de date este imediat accesibilă din internet
- [ ] Baza de date este blocată automat
- [ ] Firewall-ul semnalează noul serviciu
:::

:::evaluate
Verifică răspunsul
:::

De aceea firewall-urile bune funcționează după **principiul whitelist** („Default Deny"): tot ce nu este permis în mod explicit este interzis. Un whitelist pentru serverul școlii ar arăta astfel:

:::quiz table
| Nr. | Direcție | Protocol | Port destinație | Acțiune |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {Permite} |
| 2 | A → B | TCP | {25} | Permite |
| 3 | A → B | oricare | oricare | {Respinge} |
:::

:::evaluate
Verifică tabelul
:::

Ce se întâmplă dacă mutăm regula 3 complet în partea de sus?
- [ ] Nimic, ordinea nu contează
- [x] Din internet nu mai trece nimic, nici web, nici mail
- [ ] Mai trec doar web și mail
:::

:::evaluate
Verifică răspunsul
:::

:::tip De reținut
Deoarece **prima regulă potrivită** câștigă, **regulile speciale** trebuie puse **sus**, iar cele generale jos. Mai sigur decât un **blacklist** (totul permis, cu excepția …) este un **whitelist** (totul interzis, cu excepția …, *Default Deny*): serviciile uitate sau noi rămân astfel automat blocate.
:::
