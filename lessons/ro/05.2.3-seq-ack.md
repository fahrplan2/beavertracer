# Numere de secvență și de confirmare

:::sim
url=/sims/lesson-5.1.btsim
:::

De unde știe TCP dacă totul a ajuns — și în ce ordine? Fiecare parte **numerotează octeții** pe care îi trimite:

- **Numărul de secvență** (`SEQ`) este numărul primului octet din acest pachet.
- **Numărul de confirmare** (`ACK`) spune: „Am primit tot până aici — următorul pe care îl aștept este octetul nr. …"

La acestea se adaugă două reguli: `SYN` și `FIN` se numără ca un octet, deși nu transportă date. Și fiecare parte numără pentru sine — de aceea există două serii de numere, în diagramă roșu (client) și albastru (server).

## Verificarea prin calcul

Iată din nou conexiunea ta. Numerele de pe linii arată contorul calculatorului în punctul respectiv:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Parcurge șirul roșu de numere:

1. Clientul începe de la `SEQ=0`. `SYN`-ul său consumă un număr — serverul confirmă cu `ACK=1`.
2. Mesajul începe la `SEQ=1` și are 13 octeți (octeții de la 1 la 13). Serverul confirmă cu `ACK=14`: „Următorul pe care îl aștept este octetul 14."
3. `FIN`-ul clientului are, prin urmare, `SEQ=14` și este confirmat cu `ACK=15`.

Șirul albastru al serverului funcționează exact la fel.

:::tip De reținut
**Numărul de secvență** (`SEQ`) este numărul primului octet din pachet. **Numărul de confirmare** (`ACK`) este numărul următorului octet pe care îl așteaptă destinatarul — tot ce se află înainte a ajuns. Se aplică regula: **ACK = SEQ + lungimea** datelor primite; `SYN` și `FIN` se numără ca un octet. Fiecare parte își numără propriii octeți.
:::

:::tip Încearcă singur
Stabilește din nou conexiunea în **Client TCP simplu** și trimite două mesaje unul după altul. Spune dinainte ce valori `Seq` și `Ack` vor apărea în coloana **Info** — și verifică în trace.
:::

## Exersează

:::quiz short
Clientul trimite un pachet cu `Seq=1` și `Len=13`. Ce număr de confirmare trimite serverul înapoi?
= 14
:::

:::quiz short
După aceea, clientul trimite următorul mesaj. Cu ce număr de secvență începe acesta?
= 14
:::

:::quiz short
Sosește un pachet cu `Seq=40` și `Len=25`. Ce număr de confirmare trimite destinatarul?
= 65
:::

:::note
În rețelele reale, numărătoarea nu începe de la 0: fiecare parte alege un **număr de start aleatoriu** (*Initial Sequence Number*, ISN) între 0 și aproximativ 4,3 miliarde. Când se atinge cel mai mare număr, numărătoarea reîncepe de la 0. Tracerul scade numărul de start și afișează numere **relative** — exact ca Wireshark. De aceea vezi `Seq=0` și `Seq=1`.

În plus, fiecare pachet conține `Win=` — **dimensiunea ferestrei**: atâția octeți poate primi destinatarul în acel moment. Astfel el frânează un expeditor prea rapid (*controlul fluxului*). În BeaverTracer, fereastra are mereu aceeași dimensiune.
:::
