# Observarea UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

Pe **Server** rulează de data aceasta un **Server UDP Echo** pe portul `5000`. Și aici cablul este pregătit: **al doilea datagram** de la Client-PC către Server se pierde.

## Experimentul

1. Treci în modul :fa-play: **Rulare** și deschide :fa-terminal: **Terminal** pe **Client-PC**.
2. Pornește cu `nc` o „conexiune" UDP către server (`-u` înseamnă UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Tastează pe rând `eins`, `zwei` și `drei` și apasă de fiecare dată **Enter**. Fiecare linie care se întoarce este un ecou al serverului.
4. Așteaptă câteva secunde, apoi, în modul :fa-magnifying-glass: **Urmărire**, deschide o urmărire (trace) pentru **Client-PC**.

:::quiz mc
Care ecouri se întorc?
- [ ] Toate trei, `zwei` ceva mai târziu
- [x] Doar `eins` și `drei` — `zwei` lipsește și nici nu este retrimis
- [ ] Niciunul
:::

:::evaluate
Verifică răspunsurile
:::

Fă clic pe unul dintre pachetele UDP și deschide **User Datagram Protocol**. În comparație cu antetul TCP, antetul UDP este minuscul: **Source Port**, **Destination Port**, **Length** (lungime) și **Checksum** (sumă de control) — împreună doar 8 octeți. Un antet TCP are cel puțin 20 de octeți, cu număr de secvență și număr de confirmare, flaguri și dimensiunea ferestrei.

Ce sarcină din secțiunea 5.1 îndeplinește totuși UDP?
- [x] Multiplexarea — prin porturi
- [ ] Stabilirea conexiunii
- [ ] Transmiterea fiabilă
:::

:::evaluate
Verifică răspunsul

:::tip De reținut
**UDP** este **fără conexiune**: fără stabilire a conexiunii, fără confirmare, fără retransmisie, fără ordine. Oferă doar **porturi** (multiplexare) și o **sumă de control**. În schimb este rapid și ușor — antetul UDP are doar 8 octeți. Dacă un datagram se pierde, programul trebuie să se descurce singur — sau nu-i pasă.
:::
