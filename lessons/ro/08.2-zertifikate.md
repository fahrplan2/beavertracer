# Certificate: cui aparține această cheie?

Cu criptarea asimetrică și cu semnăturile, totul pare rezolvat: serverul web al băncii tale îți trimite cheia sa publică și gata. Dar de unde știi că această cheie publică **aparține cu adevărat băncii**?

Un atacator care îți redirecționează conexiunea ți-ar putea trimite pur și simplu **propria cheie** publică și ar putea pretinde că este banca. Browserul tău ar cripta atunci cuminte pentru atacator — iar acesta citește tot. Un astfel de atacator aflat la mijloc se numește **Man-in-the-Middle**.

## Certificatul: un act de identitate pentru chei

În viața reală îți arăți **cartea de identitate** ca să dovedești cine ești. Actul este crezut pentru că a fost emis de o **instituție de încredere** — primăria — și pentru că este greu de falsificat.

În rețea, această sarcină o preia un **certificat**. Acesta conține, printre altele:

| Câmp | Semnificație | la cartea de identitate |
|---|---|---|
| **Subiect** (*Subject*, adesea `CN=…`) | Pentru cine este certificatul? La serverele web: numele, de ex. `CN=www.biberbank.de` | numele titularului |
| **Cheie publică** | Cheia titularului | fotografie |
| **Emitent** (*Issuer*) | Cine a emis certificatul? | autoritatea emitentă |
| **Valabilitate** | de la … până la … | valabil până la |
| **Semnătura** emitentului | Dovedește că emitentul a emis într-adevăr certificatul în această formă | sigiliu, hologramă |

`CN` provine de la *Common Name*.

Instituția care emite certificate se numește **autoritate de certificare** (*Certificate Authority*, pe scurt **CA**). Înainte de a semna un certificat pentru `www.biberbank.de`, ea verifică dacă solicitantul deține cu adevărat acest domeniu.

## În cine are încredere browserul?

Pentru fiecare certificat, browserul tău verifică:

1. Este **semnătura** CA autentică? (Pentru aceasta are nevoie de cheia publică a CA.)
2. Este certificatul încă **valabil**?
3. Se potrivește **numele** din certificat cu adresa accesată?

Dar de unde cunoaște browserul CA-ul? În fiecare sistem de operare și browser este **preinstalată** o listă de aproximativ 150 de **CA-uri rădăcină** (*Root-CA*). Certificatele lor sunt **autosemnate** — se confirmă singure; li se acordă încredere pentru că sunt livrate împreună cu software-ul.

Adesea, un CA rădăcină nu semnează direct, ci printr-un **CA intermediar**. Astfel se formează un **lanț de încredere**:

```
Root-CA (vorinstalliert, vertraut)
  └─ signiert → Zwischen-CA
                  └─ signiert → www.biberbank.de
```

Browserul urmează lanțul de jos în sus, până ajunge la un CA rădăcină în care are încredere. Dacă nu reușește — sau dacă valabilitatea ori numele nu se potrivesc —, afișează un **avertisment**.

:::quiz match
Subiect (CN) -> Pentru ce nume este valabil certificatul
Emitent -> Ce CA a semnat certificatul
Cheie publică -> Este necesară pentru verificarea semnăturilor serverului
CA rădăcină -> Este preinstalat în browser și formează începutul lanțului de încredere
:::

:::tip De reținut
Un **certificat** confirmă că o **cheie publică** aparține unui anumit **nume**. El este semnat de o **autoritate de certificare (CA)**. Browserul are încredere într-un certificat dacă ajunge, printr-un **lanț de încredere**, la un **CA rădăcină** preinstalat, certificatul este **valabil** și **numele** se potrivește cu adresa.
:::
