# Accesarea și observarea unei pagini web

Pentru această parte nu construiești nimic singur: pe spațiul de lucru se află o simulare pregătită, cu un **Client-PC** și un **Webserver**.

## Accesarea paginii

1. Treci în modul :fa-play: **Rulare**.
2. Pe **Client-PC** deschide aplicația :fa-globe: **Browser** și accesează adresa serverului web: `http://192.168.0.20/`.
3. Treci în modul :fa-magnifying-glass: **Urmărire** și deschide cu **+** un trace pentru **Client-PC**, portul `eth0` — exact ca la ping.

:::note
Pentru o singură accesare de pagină sunt surprinzător de multe pachete — mult mai multe decât la ping. Preluarea unei pagini web este un proces în mai mulți pași, nu o singură acțiune.
:::

## Citirea listei de pachete

Încă nu trebuie să știi ce face exact fiecare protocol. Tot ce ai nevoie pentru întrebările următoare se află în coloanele **Protocol** și **Info**.

:::quiz mc
Care protocol se află chiar în vârful listei?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Numără: câte pachete **TCP** se află înaintea primului pachet **HTTP**?
= 3
= trei
:::

:::quiz mc
Ce răspunde serverul web la cererea browserului? Uită-te în coloana Info a celui de-al doilea pachet HTTP.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Verifică răspunsurile
:::

## Denumirea protocoalelor implicate

Din observațiile tale poți deduce acum ce protocol a fost responsabil pentru ce.

:::tip Sfat
Citește încă o dată coloanele **Info**: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` și `200 OK` îți dezvăluie aproape tot.
:::

:::quiz match
ARP -> Întreabă pe toată lumea din rețea: „Cine are adresa IP 192.168.0.20?”
TCP -> Stabilește o conexiune cu trei pachete scurte, înainte să circule datele
HTTP -> Solicită pagina web (GET) și o returnează (200 OK)
:::

:::evaluate
Verifică asocierea
:::

:::tip De reținut
Accesarea unei pagini web decurge în etape: mai întâi **găsești** serverul în rețea (ARP), apoi **stabilești** o conexiune (TCP), apoi **soliciți și livrezi** pagina (HTTP) — iar la final **închizi** din nou conexiunea (pachetele TCP cu `[FIN]` de la sfârșitul listei).
:::

:::note
De data aceasta ai introdus direct adresa IP a serverului, de aceea **DNS** („traducerea” numelor precum `www.beispiel.de` într-o adresă IP) nu a intrat încă în joc. Vom recupera acest lucru în capitolul 6.
:::

Ai observat că protocoalele din structura pachetului au marcaje colorate cu numere? Ce înseamnă acestea, lămurim în capitolul 2. Acolo vedem cum se încadrează sistematic multele protocoale — cu modelele de referință OSI și TCP/IP. Astfel, capitolul 1 este încheiat.
