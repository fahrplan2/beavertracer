# Depanare: de când cu regulile noi nu mai funcționează nimic

:::sim
url=/sims/lesson-9.4.btsim
:::

Domnul Biber, administratorul școlii Beaver, a trecut ieri firewall-ul pe principiul listei albe (whitelist). De atunci se plânge toată lumea: **site-ul școlii** nu mai este accesibil din exterior și **nu mai ajunge niciun e-mail din internet**. Măcar SSH este acum blocat din exterior, așa cum s-a dorit.

Găsește erorile din regulile **firewall-ului** și remediază-le.

<details>
<summary>Indiciul 1: Ajunge pachetul măcar la regula corectă?</summary>

Testează de pe **Internet-PC** cu `nmap -p 22,25,80 198.51.100.10`, apoi uită-te în firewall la coloana **Treffer**. O regulă care rămâne la 0, deși ar trebui să primească pachete, este acoperită de o altă regulă — sau nu se potrivește niciodată.
</details>

<details>
<summary>Indiciul 2: Uită-te cu atenție</summary>

Compară fiecare număr din reguli cu porturile din capitolul 5: ce port aparține HTTP și care SMTP? Și gândește-te la ordine: prima regulă care se potrivește câștigă.
</details>

:::task
title: Web și e-mail din nou accesibile?
Verifică dacă web-ul și e-mailul serverului școlii sunt accesibile din internet și dacă SSH rămâne blocat.
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## Ce s-a întâmplat?

:::quiz multi
Ce erori se aflau în reguli?
- [x] Regula pentru web permitea portul 8080 în loc de 80
- [x] Regula pentru e-mail se afla sub regula „respinge tot” și nu era niciodată atinsă
- [ ] Firewall-ul era setat pe Stateful
- [ ] Portul 25 este portul greșit pentru e-mail
:::

:::evaluate
Verifică răspunsurile
:::

:::tip De reținut
Erori tipice în regulile de firewall: **cifre inversate** în port, **direcția** greșită și **ordinea** greșită, în care o regulă generală acoperă una specială. La depanare ajută un **scan de porturi** din exterior, **jurnalul** firewall-ului și **contoarele de potriviri** ale regulilor.
:::
