# Atac: falsificarea DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna vrea să deschidă pe **Client-PC** serviciul de online banking al băncii **Biberbank**. Ceea ce ea nu știe: cineva a obținut acces la **DNS-Server** și a modificat o înregistrare.

Pe spațiul de lucru vezi serverul web real **www.biberbank.de** și calculatorul unui **atacator**. Pe acesta rulează o copie a site-ului băncii.

## Partea 1: Fără criptare

Treci în modul :fa-play: **Rulare** și deschide pe **Client-PC**, în :fa-globe: **Browser**, adresa `http://www.biberbank.de/`.

:::quiz mc
Ce vezi?
- [x] Pagina de autentificare a Biberbank, fără niciun avertisment
- [ ] Un avertisment că pagina este falsă
- [ ] Un mesaj de eroare
:::

:::evaluate
Verifică răspunsul
:::

Totul pare normal. Dar cu ce server vorbește de fapt browserul? Deschide pe Client-PC :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Ce adresă IP returnează serverul DNS pentru `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Cui aparține această adresă? (În modul Editare, fă clic pe dispozitive sau uită-te la :fa-gear: **Setări IP**.)
- [ ] Serverului web real al Biberbank
- [x] Atacatorului
- [ ] Serverului DNS
:::

:::evaluate
Verifică răspunsurile
:::

Dacă Anna ar fi introdus acum numărul de cont și PIN-ul, ar fi ajuns direct la atacator. Cu **HTTP** nu are **nicio șansă** să observe frauda: bara de adrese arată numele corect, iar pagina pare autentică.

## Partea 2: Cu HTTPS

Acum deschide `https://www.biberbank.de/`.

:::quiz mc
Ce se întâmplă?
- [ ] Pagina falsă apare cu lacăt
- [x] Browserul avertizează: certificatul a fost emis pentru un alt nume
- [ ] Apare pagina reală a Biberbank
:::

:::quiz short
Pentru ce nume este emis certificatul atacatorului (fără `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Verifică răspunsurile
:::

Atacatorul are chiar un certificat **real** de la o CA de încredere — dar pentru propriul domeniu `www.biber-gewinnspiel.de`. Un certificat pentru `www.biberbank.de` nu îl primește de la nicio CA, deoarece acest domeniu nu îi aparține. Iar fără **cheia privată** a Biberbank nu poate folosi nici certificatul real al acesteia: în handshake ar trebui să semneze cu ea Server Key Exchange.

:::quiz multi
De ce protejează HTTPS aici — și de ce nu?
- [x] HTTPS dezvăluie că serverul nu este cel real
- [ ] HTTPS împiedică falsificarea serverului DNS
- [x] HTTPS ajută doar dacă utilizatorul ia în serios avertismentul
- [ ] Cu HTTPS pagina falsă nu poate fi accesată deloc
:::

:::evaluate
Verifică răspunsurile
:::

## Partea 3: Repararea serverului DNS

Deschide **DNS-Server** și corectează înregistrarea pentru `www.biberbank.de`. Adresa corectă o găsești în :fa-gear: **Setări IP** ale serverului web **www.biberbank.de**. Nu uita să dai clic pe **Salvează**.

:::note
Client-PC reține o vreme răspunsurile DNS, ca să nu fie nevoit să întrebe din nou la fiecare accesare (**cache DNS**). Cât timp, se vede în coloana **TTL** (*Time to Live*), în secunde. Dacă `nslookup` returnează imediat după corectare încă vechea adresă, așteaptă să treacă TTL-ul și încearcă din nou.
:::

:::task
title: Este Biberbank din nou autentică?
Verifică dacă Client-PC rezolvă www.biberbank.de la adresa corectă și dacă poate prelua pagina prin HTTPS fără avertisment.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
În realitate, un atacator rareori falsifică chiar serverul DNS. Mai des își strecoară răspunsurile într-o rețea WLAN publică, modifică setările unui router de acasă sau momește cu o adresă cu aspect asemănător, precum `www.biberbank-login.de` (**phishing**). Împotriva unui nume cu sonoritate asemănătoare nu ajută nici HTTPS — atacatorul primește pentru el un certificat valid. De aceea: citește adresa cu atenție!
:::

:::tip De reținut
La o **falsificare DNS**, serverul DNS returnează pentru un nume adresa unui atacator. Cu **HTTP** nu observi nimic. Cu **HTTPS**, certificatul atacatorului nu se potrivește cu numele accesat, iar browserul **avertizează** — pentru că nicio CA nu emite certificate pentru domenii străine, iar atacatorul nu deține cheia privată a serverului real.
:::
