# Ce trebuie să facă stratul transport?

:::sim
url=/sims/lesson-5.1.btsim
:::

Pe **Server** rulează simultan două servicii: un **server web** și un mic **serviciu Echo**, care trimite imediat înapoi fiecare mesaj primit. Cu două experimente afli ce nu poate face IP singur.

## Experimentul 1: Două programe simultan

1. Treci în modul :fa-play: **Rulare** și dă clic pe **Client-PC**.
2. Deschide :fa-globe: **Browser** și accesează `http://192.168.0.20/`.
3. Dă clic sus în fereastră pe **Înapoi** și deschide **Client TCP simplu**. Introdu la **Host** `192.168.0.20` și la **Port** `5000` și dă clic pe **Conectare**.
4. Treci în modul :fa-magnifying-glass: **Urmărire** și deschide cu **+** un trace pentru **Client-PC**, portul `eth0`.

Dă clic pe un pachet al browserului (de ex. `GET /`) și pe unul al clientului TCP și extinde de fiecare dată **Internet Protocol Version 4**.

:::quiz mc
Ce adrese IP au pachetele browserului și ale clientului TCP?
- [x] Aceleași la amândouă: de la `192.168.0.10` către `192.168.0.20`
- [ ] Browserul folosește o altă adresă IP de destinație decât clientul TCP
- [ ] Pachetele clientului TCP nu au adresă IP
:::

:::quiz mc
Este deci adresa IP de destinație suficientă pentru ca serverul să știe dacă un pachet aparține serverului web sau serviciului Echo?
- [ ] Da
- [x] Nu — ambele pachete au aceeași adresă IP de destinație
:::

Altceva trebuie să deosebească cele două conexiuni. Uită-te în coloana **Info** a pachetelor cu `[SYN]` — acesta este de fiecare dată primul pachet al unei conexiuni:

:::quiz short
Ce număr apare la **browser** după săgeata `→`?
= 80
:::

:::quiz short
Și la **clientul TCP**?
= 5000
:::

:::evaluate
Verifică răspunsurile
:::

Despre aceste numere — **porturile** — vei afla mai multe în secțiunea 5.3. Deocamdată este suficient să știi: abia stratul transport face posibil ca mai multe programe să comunice simultan printr-o *singură* adresă IP și ca fiecare pachet să ajungă la programul potrivit. Aceasta se numește **multiplexare**.

## Experimentul 2: Când se pierde un pachet

1. Treci în modul :fa-play: **Rulare** și dă clic pe **cablul** dintre Client-PC și Server.
2. În fereastra **Conexiune** setează **Pierderea de pachete configurată** la `25%`.
3. Deschide pe **Client-PC** :fa-terminal: **Terminal** și trimite șase ping-uri:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Durează aproximativ o jumătate de minut — așteaptă până apare statistica.

:::quiz mc
Ce se întâmplă?
- [ ] Toate cele șase ping-uri primesc răspuns
- [x] Unele ping-uri rămân fără răspuns — și nimeni nu le mai trimite încă o dată
- [ ] Ping-urile pierdute sunt repetate automat până ajung
:::

:::evaluate
Verifică răspunsul
:::

La un ping nu este o problemă — tocmai asta trebuie să arate, dacă se pierde ceva. La o pagină web, un e-mail sau o descărcare, însă, o bucată lipsă ar fi fatală: fișierul ar fi defect.

## Cele patru sarcini ale stratului transport

| Sarcină | Ce înseamnă |
|---|---|
| **Multiplexare** | Mai multe programe și conexiuni folosesc împreună o adresă IP; fiecare pachet ajunge la programul potrivit. |
| **Stabilirea conexiunii** | Înainte să circule date, ambele părți stabilesc că vor comunica între ele. |
| **Transmitere fiabilă** | Destinatarul confirmă ce a primit. Ce lipsește este retrimis, iar ordinea este refăcută. |
| **Încheierea conexiunii** | La final, ambele părți închid conexiunea în mod ordonat. |

:::tip De reținut
**Stratul transport** (stratul 4) asigură că datele ajung la **programul** potrivit (**multiplexare**). Protocolul **TCP** asigură în plus că ele ajung **complete** și în **ordinea corectă** — prin stabilirea conexiunii, confirmări, retransmisie și încheierea conexiunii.
:::

:::quiz match
Pe un PC rulează simultan browser, program de e-mail și messenger. -> Multiplexare
Înainte să circule date, ambele părți constată că cealaltă este pregătită. -> Stabilirea conexiunii
O parte dintr-un fișier nu ajunge și este trimisă încă o dată. -> Transmitere fiabilă
După descărcare, ambele părți eliberează din nou conexiunea. -> Încheierea conexiunii
:::
