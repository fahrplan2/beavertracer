# Depanare: ieri încă funcționa

:::sim
url=/sims/lesson-7.2.4.btsim
:::

Ieri serverul web de acasă era accesibil din exterior — redirecționarea de porturi `TCP 80 → 192.168.178.10:80` este configurată. După o pană de curent de azi dimineață, Clara nu mai ajunge la pagină. Găsește eroarea și remediaz-o definitiv.

<details>
<summary>Indiciul 1: Încotro arată regula?</summary>

Compară adresa IP din LAN din **Port FW** a routerului de acasă cu adresa pe care o are de fapt acum **Heim-Webserver** (:fa-gear: **Setări IP**).
</details>

<details>
<summary>Indiciul 2: De ce are o altă adresă?</summary>

Este Heim-Webserver setat pe **DHCP**? Atunci primește după fiecare repornire o adresă liberă oarecare din intervalul routerului de acasă (în fila **DHCP**). Cum te asiguri că are mereu aceeași adresă?
</details>

:::task
title: Heim-Webserver este din nou accesibil?
Verifică dacă Heim-Webserver are adresa lui fixă și dacă Clara îl poate accesa prin redirecționarea de porturi. Pentru aceasta, simularea trebuie să ruleze în modul Rulare.
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## Ce s-a întâmplat?

:::quiz multi
Care afirmații sunt adevărate?
- [x] Heim-Webserver și-a primit adresa prin DHCP și, după repornire, a avut o altă adresă
- [x] Redirecționarea de porturi arăta de aceea spre o adresă la care nu mai rula niciun server
- [x] O adresă fixă în afara intervalului DHCP rezolvă problema definitiv
- [ ] Furnizorul blocase adresa WAN
:::

:::evaluate
Verifică răspunsul
:::

:::tip De reținut
Dispozitivele spre care arată o **redirecționare de porturi** (servere, imprimante, camere) au nevoie de o **adresă fixă**: fie introdusă static și **în afara intervalului DHCP**, fie ca asociere fixă în Server DHCP al routerului. Altfel, după o repornire pot primi o altă adresă — iar regula duce în gol.
:::
