# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) este HTTP obișnuit — doar că nu rulează direct peste TCP, ci printr-un strat criptat intermediar: **TLS** (*Transport Layer Security*). Predecesorul TLS se numea **SSL**; de aceea se vorbește adesea și acum despre „certificate SSL".

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP nu observă nimic din toate acestea: își trimite cererile ca de obicei, TLS le criptează, TCP le transportă. În modelul OSI, TLS se află între stratul transport și stratul aplicație, adică în stratul 4/5 — se bazează pe TCP și gestionează o sesiune securizată.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresă | `http://…` | `https://…` |
| Conținut lizibil în Tracer? | da | nu |
| Browserul afișează | „nesigur" | lacăt |

La stabilirea conexiunii, TLS se ocupă de tot ce ai învățat în acest capitol:

- Serverul se autentifică prin **certificatul** său (**autenticitate**).
- Ambele părți stabilesc de comun acord, prin **Diffie-Hellman**, o **cheie de sesiune** — serverul își **semnează** partea.
- După aceea, toate datele sunt criptate cu **AES** (**confidențialitate**) și protejate împotriva modificării (**integritate**).

Principiul nu se limitează la web: și e-mailul (secțiunea 8.4) și multe alte protocoale rulează în același mod prin TLS.

În secțiunile următoare observi HTTPS în Tracer, îl configurezi tu însuți și investighezi când avertizează browserul — și de ce.
