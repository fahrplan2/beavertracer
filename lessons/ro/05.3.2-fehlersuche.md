# Depanare: serviciul nu răspunde

:::sim
url=/sims/lesson-5.3.2.btsim
:::

După o actualizare, școala raportează: „Serviciul Echo refuză orice conexiune, iar pagina web nu se mai încarcă nici ea.” Conform planului, **serverul web** trebuie să asculte pe portul `80`, iar **serviciul Echo** (Server TCP Echo) pe portul `5000`. Găsește erorile și remediază-le.

<details>
<summary>Indiciul 1: Ce răspunde serverul?</summary>

Încearcă să te conectezi cu **Client TCP simplu** la `192.168.0.20`, portul `5000`, și deschide o urmărire pentru PC-ul client. Cu ce răspunde serverul la `[SYN]`-ul tău?
</details>

<details>
<summary>Indiciul 2: Care porturi sunt deschise?</summary>

Pe PC-ul client, introdu în terminal `nmap -p 80,5000 192.168.0.20`. `nmap` încearcă porturile pe rând și arată care sunt deschise. Cu `ss` pe server vezi pe ce porturi ascultă de fapt un program.
</details>

<details>
<summary>Indiciul 3: Unde se setează asta?</summary>

Deschide pe **server** aplicațiile **Server TCP Echo** și **Server HTTP**. Rulează serviciul? Și pe ce port?
</details>

:::task
title: Serviciile sunt accesibile?
Verifică dacă PC-ul client ajunge la serviciul Echo de pe portul 5000 și la serverul web de pe portul 80. Pentru aceasta, simularea trebuie să ruleze în modul Rulare.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Ce s-a întâmplat?

:::quiz multi
Care afirmații sunt corecte?
- [x] La `[SYN]`-ul către portul 5000, serverul a răspuns cu `[RST, ACK]`
- [x] Serviciul Echo asculta pe portul 5050 în loc de portul 5000
- [x] Serverul web nu era deloc pornit
- [ ] Cablul dintre PC-ul client și server era defect
:::

:::evaluate
Verifică răspunsul
:::

:::tip De reținut
Dacă la un `SYN` se întoarce un **`RST`**, pe acel port **nu ascultă niciun program**: calculatorul este accesibil, dar serviciul nu. Cauze tipice: serviciul **nu este pornit** sau ascultă pe un **alt port**. O privire cu `ss` pe server arată care porturi sunt de fapt deschise.
:::
