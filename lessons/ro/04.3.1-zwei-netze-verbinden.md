# Conectarea a două rețele

:::sim
url=/sims/lesson-4.3.1.btsim
:::

Routerul are două porturi:

| Port | Adresă IP | Rețea |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Pentru ca PC-urile să folosească routerul, fiecare dintre ele are configurat un **gateway**: `192.168.0.1` la Anna și Ben, `172.16.0.1` la Clara și David. Îl găsești în :fa-gear: **Setări IP**, în câmpul **Gateway**.

:::tip De reținut
**Gateway-ul** (mai exact: *gateway implicit*) este adresa IP a routerului **din propria rețea**. Către gateway, un PC trimite toate pachetele a căror destinație se află într-o altă rețea.
:::

2. Treci în modul :fa-magnifying-glass: **Urmărire** și deschide un trace pentru **Anna**.

## Ce face routerul cu pachetul

Routerul primește frame-ul de la Anna, despachetează pachetul IP și se uită la **adresa IP de destinație**. Din ea își dă seama: Clara se află în rețeaua de la `eth1`. Așadar, împachetează pachetul într-un frame **nou** — cu propria adresă MAC ca expeditor și cu adresa MAC a Clarei ca destinație — și îl trimite acolo.

| Ce se întâmplă la router cu … | |
|---|---|
| adresele MAC (stratul 2)? | sunt setate **din nou** — sunt valabile doar în rețeaua respectivă |
| adresele IP (stratul 3)? | **rămân aceleași** — de la Anna până la Clara |
| Time to Live? | scade cu **1** |

:::tip De reținut
Un **router** lucrează la **stratul 3**: transmite pachetele în alte rețele pe baza **adresei IP de destinație**. Adresele IP rămân aceleași pe tot parcursul, adresele MAC sunt setate din nou în fiecare rețea. Fiecare router scade **Time to Live (TTL)** cu 1 — dacă ajunge la 0, pachetul este eliminat. Astfel, un pachet nu poate circula la nesfârșit în cerc.
:::

:::note
Îți amintești de furtuna de broadcast din capitolul 3.4? Frame-urile Ethernet nu au TTL — pachetele IP au.
:::

## Pe cine cunoaște Anna? Cache-ul ARP

Îți amintești de capitolul 1.2.3? Acolo, ARP apărea doar înainte de *primul* ping, pentru că PC-ul își reținuse răspunsul. Această listă de reținere se numește **cache ARP** (sau *tabelă ARP*). Cererea se numește **ARP Request**, iar răspunsul **ARP Reply** (sau *ARP Response*).

Treci în modul :fa-play: **Rulare**, deschide pe **Anna** :fa-terminal: **Terminal** și afișează-i cache-ul ARP:

```
$ arp
```

:::quiz mc
Ce se află în cache-ul ARP al Annei?
- [x] Doar adresa IP a routerului (`192.168.0.1`) cu adresa lui MAC
- [ ] Adresa IP a Clarei cu adresa MAC a Clarei
- [ ] Adresele routerului și ale Clarei
:::

:::evaluate
Verifică răspunsul
:::

Anna nu are niciodată nevoie de adresa MAC a Clarei: tot ce este destinat firmei B trimite către router. Adresa MAC a Clarei o cunoaște doar routerul — el a aflat-o singur prin ARP, de partea lui.

:::tip De reținut
În **cache-ul ARP**, un dispozitiv reține ce adresă MAC corespunde cărei adrese IP — astfel nu trebuie să trimită un ARP Request înainte de fiecare pachet. Cache-ul poate fi afișat cu comanda `arp`. Un PC cunoaște doar adrese MAC din **propria** rețea: pentru toate destinațiile din alte rețele folosește adresa MAC a routerului.
:::

:::note
În rețelele reale, intrările din cache-ul ARP sunt șterse după un timp și cerute din nou la nevoie — de exemplu, dacă între timp un dispozitiv are altă placă de rețea. În BeaverTracer ele se păstrează cât timp rulează simularea.
:::
