# Depanare: numele nu funcționează

:::sim
url=/sims/lesson-6.2.3.btsim
:::

O profesoară raportează: „`www.beaver-schule.de` nu se încarcă la mine. Cu `http://192.168.0.20` însă funcționează!” Așa *ar trebui* să fie configurat:

| Ce | Valoare corectă |
|---|---|
| Server DNS pe Client-PC | `192.168.0.53` (DNS-Resolver) |
| Intrare în Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Găsește erorile și remediază-le.

<details>
<summary>Indiciul 1: Ce spune nslookup?</summary>

Introdu pe Client-PC comanda `nslookup www.beaver-schule.de`. Ce server a interogat `nslookup` — și ce a primit înapoi? (Răspunsul durează câteva secunde.)
</details>

<details>
<summary>Indiciul 2: Și acum?</summary>

Dacă primești un răspuns, compară adresa cu schema. Unde este înregistrat acest nume?
</details>

:::task
title: Rezolvarea numelui este reparată?
Verifică dacă Client-PC rezolvă www.beaver-schule.de la adresa corectă. Pentru aceasta, simularea trebuie să ruleze în modul Rulare.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Ce nu a mers?

:::quiz multi
Care afirmații sunt adevărate?
- [x] Pe Client-PC era configurat `192.168.0.35` ca server DNS — acolo nu răspunde nimeni
- [x] În Schul-DNS, `www.beaver-schule.de` indica spre `192.168.0.21` în loc de `192.168.0.20`
- [ ] Serverul web era oprit
- [ ] Serverul root nu cunoștea domeniul `.de`
:::

:::evaluate
Verifică răspunsul
:::

:::tip De reținut
Dacă o conexiune funcționează cu **adresa IP**, dar nu cu **numele**, problema este la **DNS**. Verifică mai întâi **serverul DNS configurat** (răspunde măcar?), apoi **intrarea** în sine (este corectă adresa?). `nslookup` arată ambele lucruri: ce server a fost interogat și ce a răspuns acesta.
:::
