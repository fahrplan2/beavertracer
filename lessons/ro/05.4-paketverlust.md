# Când se pierd pachetele

:::goal
**Obiectiv de învățare:** Poți observa în Tracer și explica cum observă TCP datele pierdute, cum le retrimite și cum restabilește ordinea.
:::

:::sim
url=/sims/lesson-5.4.btsim
:::

În această simulare cablul este pregătit special: **al doilea pachet cu date** de la Client-PC către Server se pierde. (Găsești setarea dacă în modul Rulare dai clic pe cablu: **Pierderea de pachete direcționată**.)

## Experimentul

1. Treci în modul :fa-play: **Rulare**, deschide pe **Client-PC** aplicația **Client TCP simplu** și conectează-l la `192.168.0.20`, portul `5000`.
2. Trimite pe rând trei mesaje: `Hallo`, apoi `Welt`, apoi `!`.
3. Observă fereastra de chat: ecoul pentru `Hallo` vine imediat. Dar celelalte două?
4. Așteaptă câteva secunde. Apoi, în modul :fa-magnifying-glass: **Urmărire**, deschide un trace pentru **Server** (destinatarul), interfața `eth0`.

:::quiz mc
Ce se întâmplă cu ecourile pentru `Welt` și `!`?
- [ ] Ecoul pentru `!` vine imediat, `Welt` lipsește pentru totdeauna
- [x] Ambele vin abia după câteva secunde — împreună și în ordinea corectă
- [ ] Niciunul dintre ele nu ajunge vreodată
:::

## Ce arată Tracer-ul

La server lipsește pachetul cu `Welt` — doar s-a pierdut. În schimb, găsești în coloana **Info** trei indicii în paranteze drepte:

| Indiciu | Ce s-a întâmplat |
|---|---|
| `[TCP Previous segment not captured]` | Pachetul cu `!` ajunge, dar înaintea lui lipsesc octeți — un **gol**. |
| `[TCP Dup ACK …]` | Serverul confirmă încă o dată același număr ca înainte (*duplicate ACK*): „Încă aștept octetul 8.” |
| `[TCP Retransmission]` | Clientul trimite `Welt` **încă o dată**. |

:::quiz short
Ce număr de secvență (`Seq`) are pachetul marcat cu `[TCP Retransmission]`?
= 8
:::

:::quiz short
Ce număr de confirmare (`Ack`) trimite serverul imediat după retransmisie?
= 17
:::

:::quiz mc
De ce confirmă serverul după retransmisie direct până la octetul 17 — și nu doar până la sfârșitul lui `Welt`?
- [x] Primise deja `!` și îl ținuse la păstrare — cu `Welt` golul s-a închis, acum există tot până la octetul 16
- [ ] Clientul a trimis `Welt` și `!` încă o dată împreună
- [ ] Numerele de confirmare sunt întotdeauna rotunjite
:::

:::evaluate
Verifică răspunsurile
:::

În diagrama de secvență arată așa — săgeata întreruptă cu ✕ este pachetul pierdut:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hallo" len=7
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=7
Client-PC -> Server: ACK
Client-PC -x Server: PSH, ACK "Welt" len=6
Client-PC -> Server: PSH, ACK "!" len=3
Server -> Client-PC: ACK
Client-PC -> Server: PSH, ACK "Welt" len=6 seq=8
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=9
Client-PC -> Server: ACK
:::

## Ce se află în spate

Clientul păstrează fiecare pachet trimis până când acesta este confirmat și pornește pentru el un **timer**. Dacă confirmarea întârzie prea mult, clientul trimite datele din nou — o **retransmisie** (*Retransmission*).

Serverul confirmă întotdeauna doar până la **primul gol**. Datele care sosesc după aceasta (aici `!`) le ține la păstrare până când golul este umplut. Abia apoi le predă pe toate programului în ordinea corectă — de aceea ecourile pentru `Welt` și `!` au venit împreună.

:::tip De reținut
TCP recunoaște pierderile după **confirmările lipsă**: destinatarul confirmă întotdeauna doar până la primul gol. Dacă confirmarea nu apare, expeditorul trimite datele **din nou** după expirarea unui timer (*Retransmission*). Ce sosește după un gol este ținut la păstrare de destinatar — astfel datele ajung la program **complete și în ordinea corectă**.
:::

:::tip Aprofundare: Fast Retransmit
După `Hallo`, trimite patru sau mai multe mesaje rapid, unul după altul. După pachetul pierdut, clientul primește trei *Dup ACK* la rând — și retrimite imediat, fără să aștepte expirarea timerului. Acest procedeu se numește **Fast Retransmit**.
:::

:::note
Implementările TCP reale își adaptează în plus și viteza de trimitere: dacă se pierd pachete, rețeaua este probabil suprasolicitată, iar expeditorul încetinește (*controlul congestiei*). Aceasta depășește cadrul acestui curs.
:::
