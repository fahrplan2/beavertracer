# De ce nu ajunge o singură rețea

:::sim
url=/sims/lesson-4.1.btsim
:::

Pe spațiul de lucru vezi două rețele mici de firmă: **Firma A** cu Anna (`192.168.0.10`) și Ben (`192.168.0.11`), **Firma B** cu Clara (`172.16.0.10`) și David (`172.16.0.11`). Cele două switch-uri sunt chiar conectate direct printr-un cablu.

## Un ping în propria rețea

1. Treci în modul :fa-play: **Rulare**, deschide pe **Anna** :fa-terminal: **Terminal** și dă ping către Ben:
   ```
   $ ping 192.168.0.11
   ```
2. Treci în modul :fa-magnifying-glass: **Urmărire**, deschide o urmărire pentru **Anna** și fă clic pe un `Echo (ping) request`.
3. Extinde în arborele de protocoale linia **Internet Protocol Version 4**. Aceasta este partea IP a pachetului — partea despre care este vorba în acest capitol.

:::quiz match
Source Address -> Adresa IP a expeditorului
Destination Address -> Adresa IP a destinatarului
Time to Live -> Prin câte routere mai poate trece pachetul
Protocol -> Ce protocol se află în pachet (aici ICMP, deci ping-ul)
:::

:::evaluate
Verifică asocierea
:::

## Un ping în cealaltă rețea

Treci înapoi în modul :fa-play: **Rulare** și dă ping de pe **Anna** către Clara (`ping 172.16.0.10`). Apoi uită-te încă o dată la urmărirea lui Anna.

:::quiz mc
Ce se întâmplă?
- [ ] Ping-ul reușește — doar switch-urile sunt conectate
- [x] Niciun ping nu ajunge, iar în urmărirea lui Anna nu apare niciun singur pachet către Clara — nici măcar o cerere ARP
- [ ] Anna trimite o cerere ARP, dar Clara nu răspunde
:::

:::quiz mc
De ce nu trimite Anna absolut nimic?
- [ ] Cablul dintre switch-uri este defect
- [ ] Clara este oprită
- [x] Anna observă după adresa IP a Clarei că Clara se află într-o altă rețea — și nu cunoaște niciun drum spre ea
:::

:::evaluate
Verifică răspunsurile

## Ce se află în spate

O adresă IP funcționează asemănător unei adrese poștale: o parte spune în ce **rețea** se află un dispozitiv (ca strada), cealaltă parte spune care **dispozitiv** din acea rețea este vizat (ca numărul casei). Anna se află în rețeaua `192.168.0…`, Clara în rețeaua `172.16.0…` — două „străzi” diferite.

Către dispozitivele din *propria* rețea, un PC trimite pachetele direct (prin ARP și switch, așa cum știi deja). Pentru o rețea *străină* are nevoie de un dispozitiv care conectează rețelele între ele și transmite pachetele mai departe: un **router**. Aici încă nu există unul — de aceea nici cablul dintre switch-uri nu ajută.

:::tip De reținut
**Internet Protocol** (**IP**) de pe stratul 3 asigură că pachetele ajung și între rețele diferite. O **adresă IP** este alcătuită dintr-o **parte de rețea** (în ce rețea?) și o **parte de gazdă** (care dispozitiv?). Dispozitivele din aceeași rețea se pot contacta direct — pentru alte rețele este nevoie de un **router**.
:::

Astfel apar două întrebări, despre care vorbim în secțiunile următoare: de unde știe un PC *unde anume* în adresă se termină partea de rețea? Și cum funcționează un router?
