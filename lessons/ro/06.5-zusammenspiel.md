# Totul la un loc: ce se întâmplă când accesezi o pagină web?

:::goal
**Obiectiv de învățare:** Poți explica pas cu pas ce protocoale de pe ce strat sunt implicate atunci când un laptop proaspăt pornit accesează o pagină web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Acum se leagă tot ce ai învățat în acest curs. La switch sunt conectate un **DHCP-Server**, un **DNS-Server**, un **Webserver** și un **Laptop** care tocmai a fost pornit — nu are încă o adresă IP și este setat pe DHCP.

## Experimentul

1. Treci în modul :fa-play: **Rulare** și așteaptă câteva secunde.
2. Dă clic pe **Laptop**, deschide :fa-globe: **Browser** și accesează `http://www.beaver-schule.de/`.
3. În modul :fa-magnifying-glass: **Urmărire**, deschide un trace pentru **Laptop**. Aici este toată povestea — de la primul pachet.

Aranjează pașii în ordinea corectă, așa cum apar în trace:

:::quiz match
1. Schritt -> DHCP: Der Laptop holt sich IP-Adresse, Gateway und DNS-Server
2. Schritt -> ARP: Der Laptop fragt nach der MAC-Adresse des DNS-Servers
3. Schritt -> DNS: Der Laptop fragt nach der IP-Adresse von www.beaver-schule.de
4. Schritt -> ARP: Der Laptop fragt nach der MAC-Adresse des Webservers
5. Schritt -> TCP: Drei-Wege-Handshake mit dem Webserver
6. Schritt -> HTTP: GET / und die Antwort 200 OK
:::

:::evaluate
Verifică ordinea
:::

Iar sub toate acestea se află **IP** (stratul 3), care adresează fiecare dintre aceste pachete, și **Ethernet** (stratul 2), care îl duce la următorul dispozitiv. Dacă serverul web ar fi într-o altă rețea, ar interveni și **routerul**: atunci laptopul ar cere adresa MAC a **gateway-ului** său, nu pe cea a serverului web.

:::quiz mc
De ce poate laptopul să trimită cererea DNS abia după DHCP?
- [ ] Pentru că DNS funcționează doar prin TCP
- [x] Pentru că abia prin DHCP primește o adresă IP proprie și află ce server DNS este responsabil
- [ ] Pentru că serverul DNS pornește abia după serverul DHCP
:::

:::quiz mc
Câte conexiuni TCP stabilește browserul către serverul web — și de ce?
- [ ] Una, pentru toate la un loc
- [x] Două — una pentru pagină și una pentru foaia de stil
- [ ] Niciuna, HTTP nu are nevoie de TCP
:::

Verifică răspunsurile

:::tip De reținut
În spatele unui singur clic lucrează împreună toate straturile: **DHCP** furnizează setările de bază, **ARP** găsește adresele MAC în rețeaua locală, **DNS** traduce numele, **TCP** stabilește o conexiune fiabilă, iar **HTTP** preia pagina — totul împachetat în pachete **IP** și cadre **Ethernet**.
:::
