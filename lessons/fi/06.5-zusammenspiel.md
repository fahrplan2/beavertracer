# Kaikki yhdessä: mitä tapahtuu, kun avaat verkkosivun?

:::goal
**Oppimistavoite:** Osaat selittää vaihe vaiheelta, mitkä protokollat ovat mukana millä kerroksella, kun juuri käynnistetty kannettava avaa verkkosivun.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Nyt kaikki, minkä olet oppinut tällä kurssilla, tulee yhteen. Kytkimeen on liitetty **DHCP-Server**, **DNS-Server**, **Webserver** ja **Laptop**, joka on juuri kytketty päälle. Sillä ei ole vielä IP-osoitetta, ja se on asetettu käyttämään DHCP:tä.

## Koe

1. Siirry :fa-play: **Suorita**-tilaan ja odota muutama sekunti.
2. Napsauta **Laptop**-laitetta, avaa :fa-globe: **Selain** ja avaa osoite `http://www.beaver-schule.de/`.
3. Avaa :fa-magnifying-glass: **Jäljitys**-tilassa **Laptop**-laitteelle jäljitys (trace). Tässä on koko tarina, aivan ensimmäisestä paketista alkaen.

Aseta vaiheet oikeaan järjestykseen sellaisena kuin ne näkyvät jäljityksessä:

:::quiz match
1. vaihe -> DHCP: Laptop hakee IP-osoitteen, yhdyskäytävän ja DNS-palvelimen
2. vaihe -> ARP: Laptop kysyy DNS-palvelimen MAC-osoitetta
3. vaihe -> DNS: Laptop kysyy osoitteen www.beaver-schule.de IP-osoitetta
4. vaihe -> ARP: Laptop kysyy web-palvelimen MAC-osoitetta
5. vaihe -> TCP: Kolmivaiheinen kättely web-palvelimen kanssa
6. vaihe -> HTTP: GET / ja vastaus 200 OK
:::

Kaiken alla ovat vielä **IP** (kerros 3), joka osoitteistaa jokaisen näistä paketeista, ja **Ethernet** (kerros 2), joka vie paketin seuraavalle laitteelle. Jos web-palvelin olisi toisessa verkossa, mukaan tulisi vielä **reititin**: silloin Laptop kysyisi oman **yhdyskäytävänsä** MAC-osoitetta, ei web-palvelimen.

:::quiz mc
Miksi Laptop voi lähettää DNS-kyselyn vasta DHCP:n jälkeen?
- [ ] Koska DNS toimii vain TCP:n yli
- [x] Koska se saa oman IP-osoitteensa ja tiedon vastuussa olevasta DNS-palvelimesta vasta DHCP:n kautta
- [ ] Koska DNS-palvelin käynnistyy vasta DHCP-palvelimen jälkeen
:::

:::quiz mc
Kuinka monta TCP-yhteyttä selain muodostaa web-palvelimeen — ja miksi?
- [ ] Yhden kaikelle yhteensä
- [x] Kaksi — yhden sivua varten ja yhden tyylitiedostoa varten
- [ ] Ei yhtään, HTTP ei tarvitse TCP:tä

:::tip Muista
Yhden ainoan napsautuksen takana kaikki kerrokset tekevät yhteistyötä: **DHCP** antaa perusasetukset, **ARP** selvittää MAC-osoitteet paikallisessa verkossa, **DNS** muuntaa nimen, **TCP** muodostaa luotettavan yhteyden ja **HTTP** hakee sivun — kaikki pakattuna **IP**-paketteihin ja **Ethernet**-kehyksiin.
:::

Nyt osaat selittää verkkosivun avaamisen ensimmäisestä viimeiseen pakettiin. Luvun lopuksi seuraa vielä lyhyt katsaus muihin protokolliin. Seuraavissa luvuissa käsitellään kotiverkkoa ja NAT:ia sekä tietoturvaa ja salausta — eli sitä, miten estetään kaikkia lukemasta kaikkia näitä paketteja.
