# Vianmääritys: paluureitti

:::sim
url=/sims/lesson-4.5.3.btsim
:::

Sama rakenne kuin äsken: Firma A — Router A — Zwischennetz — Router B — Firma B. Ylläpitäjä on lisännyt **Router A** -laitteeseen reitin Firma B:n verkkoon (`172.16.0.0/24` osoitteen `10.0.0.2` kautta). Silti Anna ilmoittaa: Clara ei vastaa.

Etsi virhe ja korjaa se.

<details>
<summary>Vihje 1: Saapuuko Annan ping perille lainkaan?</summary>

Pingaa Claraa Annalta ja avaa jäljitys **Clara**-laitteelle. Saapuuko ping hänelle — ja vastaako hän?
</details>

<details>
<summary>Vihje 2: Kuinka pitkälle traceroute pääsee?</summary>

Anna Annalla komento `traceroute 172.16.0.10`. Mihin reitittimeen asti vastauksia tulee takaisin — ja minkä reitittimen pitäisi välittää Claran vastaukset Annalle?
</details>

<details>
<summary>Vihje 3: Kuka tuntee minkäkin verkon?</summary>

Katso **Router B** -laitteen reititystaulu. Tietääkö se, minne verkon `192.168.0.0/24` paketit kuuluu lähettää?
</details>

:::task
title: Yhteys korjattu?
Tarkista, tunteeko Router B reitin Firma A:n verkkoon ja tavoittaako Anna Claran. Simulaation täytyy olla käynnissä Suoritustilassa.
check: hasRoute(5, "192.168.0.0/24")
check: pingOk(9, 11)
:::

## Mitä tapahtui?

:::quiz multi
Mitä havaitsit vianmäärityksessä?
- [x] Annan ping saapui Claralle, ja Clara vastasi
- [x] Vastaus jäi jumiin Router B:hen, koska se ei tuntenut Firma A:n verkkoa
- [ ] Router A hylkäsi Annan pingin
- [x] `traceroute` näytti Router A:n jälkeen enää vain `*`, vaikka menosuunta toimi
:::

:::evaluate
Tarkista vastaus
:::

:::tip Muista
Jokainen yhteys tarvitsee **menoreitin ja paluureitin**: jokaisen reitittimen reitin varrella täytyy tuntea *molemmat* verkot — kohdeverkko ja lähettäjän verkko. Puuttuva **paluureitti** on yksi yleisimmistä reitityksen virheistä. Varo: `traceroute` näyttää vain sen, mistä alkaen vastauksia ei enää tule takaisin — virhe voi olla myös paluureitillä.
:::
