# Vianmääritys: palvelu ei vastaa

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Päivityksen jälkeen koulu ilmoittaa: ”Kaiupalvelu hylkää kaikki yhteydet, eikä verkkosivukaan enää lataudu.” Suunnitelman mukaan **Webserver** kuuntelee porttia `80` ja **Echo-Dienst** (TCP-kaiupalvelin) porttia `5000`. Etsi virheet ja korjaa ne.

<details>
<summary>Vihje 1: Mitä palvelin vastaa?</summary>

Yritä muodostaa yhteys **Yksinkertaisella TCP-asiakkaalla** osoitteeseen `192.168.0.20`, porttiin `5000`, ja avaa jäljitys asiakaskoneelle. Mitä palvelin vastaa `[SYN]`-pakettiisi?
</details>

<details>
<summary>Vihje 2: Mitkä portit ovat auki?</summary>

Kirjoita asiakaskoneen päätteessä `nmap -p 80,5000 192.168.0.20`. `nmap` kokeilee portteja yksi kerrallaan ja näyttää, mitkä ovat auki. Komennolla `ss` näet palvelimella, mitä portteja siellä todella jokin ohjelma kuuntelee.
</details>

<details>
<summary>Vihje 3: Mistä tämä asetetaan?</summary>

Avaa **palvelimella** sovellukset **TCP-kaiupalvelin** ja **HTTP-palvelin**. Onko palvelu käynnissä? Ja mitä porttia se kuuntelee?
</details>

:::task
title: Ovatko palvelut tavoitettavissa?
Tarkistaa, tavoittaako asiakaskone kaiupalvelun portissa 5000 ja verkkopalvelimen portissa 80. Simulaation on tätä varten oltava käynnissä Suoritustilassa.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Mitä tapahtui?

:::quiz multi
Mitkä väitteet pitävät paikkansa?
- [x] Palvelin vastasi porttiin 5000 lähetettyyn `[SYN]`-pakettiin `[RST, ACK]`-paketilla
- [x] Kaiupalvelu kuunteli porttia 5050 portin 5000 sijaan
- [x] Verkkopalvelinta ei ollut käynnistetty lainkaan
- [ ] Asiakaskoneen ja palvelimen välinen kaapeli oli rikki
:::

:::evaluate
Tarkista vastaus
:::

:::tip Muista
Jos `SYN`-pakettiin vastataan **`RST`**-paketilla, kyseistä porttia ei kuuntele **mikään ohjelma**: tietokone on tavoitettavissa, mutta palvelu ei. Tyypillisiä syitä ovat, että palvelu **ei ole käynnissä** tai se kuuntelee **toista porttia**. Komennolla `ss` palvelimella näet, mitkä portit ovat todella auki.
:::
