# Mitä kuljetuskerroksen täytyy tehdä?

:::sim
url=/sims/lesson-5.1.btsim
:::

**Palvelimella** toimii samaan aikaan kaksi palvelua: **web-palvelin** ja pieni **kaiutuspalvelu**, joka lähettää jokaisen saamansa viestin heti takaisin. Kahden kokeen avulla selvität, mihin pelkkä IP ei pysty.

## Koe 1: Kaksi ohjelmaa yhtä aikaa

1. Siirry :fa-play: **Suorita**-tilaan (Suoritustila) ja napsauta **Client-PC**:tä.
2. Avaa :fa-globe: **Selain** ja avaa osoite `http://192.168.0.20/`.
3. Napsauta ikkunan yläreunassa **Takaisin** ja avaa **Yksinkertainen TCP-asiakas**. Kirjoita kohtaan **Host** `192.168.0.20` ja kohtaan **Port** `5000` ja napsauta **Yhdistä**.
4. Siirry :fa-magnifying-glass: **Jäljitys**-tilaan ja avaa **+**-painikkeella jäljitys **Client-PC**:lle, liitäntä `eth0`.

Napsauta selaimen pakettia (esim. `GET /`) ja TCP-asiakkaan pakettia ja avaa kummastakin kohta **Internet Protocol Version 4**.

:::quiz mc
Mitkä IP-osoitteet selaimen ja TCP-asiakkaan paketeissa ovat?
- [x] Molemmissa samat: osoitteesta `192.168.0.10` osoitteeseen `192.168.0.20`
- [ ] Selain käyttää eri kohde-IP-osoitetta kuin TCP-asiakas
- [ ] TCP-asiakkaan paketeissa ei ole IP-osoitetta
:::

:::quiz mc
Riittääkö kohde-IP-osoite siis siihen, että palvelin tietää, kuuluuko paketti web-palvelimelle vai kaiutuspalvelulle?
- [ ] Kyllä
- [x] Ei — molemmilla paketeilla on sama kohde-IP-osoite
:::

Jonkin muun täytyy erottaa nämä kaksi yhteyttä toisistaan. Katso `[SYN]`-pakettien **Info**-saraketta — se on kunkin yhteyden ensimmäinen paketti:

:::quiz short
Mikä luku on **selaimella** nuolen `→` jäljessä?
= 80
:::

:::quiz short
Entä **TCP-asiakkaalla**?
= 5000
:::

:::evaluate
Tarkista vastaukset
:::

Näistä luvuista — **porteista** — opit lisää osiossa 5.3. Toistaiseksi riittää tietää: vasta kuljetuskerros mahdollistaa sen, että useat ohjelmat voivat kommunikoida samaan aikaan *yhden* IP-osoitteen kautta ja että jokainen paketti päätyy oikealle ohjelmalle. Tätä kutsutaan **multipleksaukseksi**.

## Koe 2: Kun paketti katoaa

1. Siirry :fa-play: **Suorita**-tilaan (Suoritustila) ja napsauta Client-PC:n ja palvelimen välistä **kaapelia**.
2. Aseta ikkunassa **Yhteys** **Määritetty pakettihävikki** arvoon `25%`.
3. Avaa **Client-PC**:llä :fa-terminal: **Pääte** ja lähetä kuusi pingiä:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Tämä kestää noin puoli minuuttia — odota, kunnes tilasto ilmestyy.

:::quiz mc
Mitä tapahtuu?
- [ ] Kaikkiin kuuteen pingiin vastataan
- [x] Osa pingeistä jää ilman vastausta — eikä kukaan lähetä niitä uudelleen
- [ ] Kadonneet pingit toistetaan automaattisesti, kunnes ne perille
:::

:::evaluate
Tarkista vastaus
:::

Pingin kohdalla tämä ei ole ongelma — sen tarkoitushan on juuri näyttää, katoaako jotain. Verkkosivun, sähköpostin tai latauksen kohdalla puuttuva pala olisi kuitenkin tuhoisa: tiedosto olisi rikki.

## Kuljetuskerroksen neljä tehtävää

| Tehtävä | Mitä se tarkoittaa |
|---|---|
| **Multipleksaus** | Useat ohjelmat ja yhteydet jakavat yhden IP-osoitteen; jokainen paketti päätyy oikealle ohjelmalle. |
| **Yhteyden muodostus** | Ennen kuin dataa siirtyy, molemmat osapuolet sopivat keskustelevansa keskenään. |
| **Luotettava siirto** | Vastaanottaja kuittaa, mikä on saapunut perille. Puuttuva lähetetään uudelleen ja järjestys palautetaan. |
| **Yhteyden purku** | Lopuksi molemmat osapuolet päättävät yhteyden hallitusti. |

:::tip Muista
**Kuljetuskerros** (kerros 4) huolehtii siitä, että data saapuu oikealle **ohjelmalle** (**multipleksaus**). Lisäksi **TCP**-protokolla huolehtii siitä, että data saapuu **kokonaisena** ja **oikeassa järjestyksessä** — yhteyden muodostuksen, kuittausten, uudelleenlähetyksen ja yhteyden purun avulla.
:::

:::quiz match
Tietokoneella toimivat samaan aikaan selain, sähköpostiohjelma ja pikaviestin. -> Multipleksaus
Ennen kuin dataa siirtyy, molemmat osapuolet varmistavat, että toinen on valmis. -> Yhteyden muodostus
Osa tiedostosta ei saavu perille ja se lähetetään uudelleen. -> Luotettava siirto
Latauksen jälkeen molemmat osapuolet vapauttavat yhteyden. -> Yhteyden purku
:::
