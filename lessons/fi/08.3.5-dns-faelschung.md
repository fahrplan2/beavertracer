# Hyökkäys: DNS-väärennös

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna haluaa avata **Client-PC**:llä verkkopankkinsa **Biberbank**issa. Hän ei tiedä, että joku on päässyt käsiksi **DNS-palvelimeen** ja muuttanut yhtä merkintää.

Työtilassa näet oikean verkkopalvelimen **www.biberbank.de** ja **hyökkääjän** tietokoneen. Sillä pyörii pankin verkkosivun kopio.

## Osa 1: Ilman salausta

Siirry :fa-play: **Suorita**-tilaan ja avaa **Client-PC**:llä :fa-globe: **Selain**ssa osoite `http://www.biberbank.de/`.

:::quiz mc
Mitä näet?
- [x] Biberbankin kirjautumissivun ilman minkäänlaista varoitusta
- [ ] Varoituksen, että sivu on väärennetty
- [ ] Virheilmoituksen
:::

:::evaluate
Tarkista vastaus
:::

Kaikki näyttää normaalilta. Mutta minkä palvelimen kanssa selain oikeasti keskustelee? Avaa Client-PC:llä :fa-terminal: **Pääte**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Minkä IP-osoitteen DNS-palvelin palauttaa nimelle `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Kenelle tämä osoite kuuluu? (Klikkaa laitteita Muokkaustilassa tai katso niiden :fa-gear: **IP-asetukset**.)
- [ ] Biberbankin oikealle verkkopalvelimelle
- [x] Hyökkääjälle
- [ ] DNS-palvelimelle
:::

:::evaluate
Tarkista vastaukset
:::

Jos Anna olisi nyt syöttänyt tilinumeronsa ja PIN-koodinsa, ne olisivat menneet suoraan hyökkääjälle. **HTTP**:n kanssa hänellä **ei ole mitään mahdollisuutta** huomata huijausta: osoiterivillä on oikea nimi ja sivu näyttää aidolta.

## Osa 2: HTTPS:n kanssa

Avaa nyt `https://www.biberbank.de/`.

:::quiz mc
Mitä tapahtuu?
- [ ] Väärennetty sivu tulee näkyviin lukon kanssa
- [x] Selain varoittaa: varmenne on myönnetty toiselle nimelle
- [ ] Biberbankin oikea sivu tulee näkyviin
:::

:::quiz short
Millä nimellä hyökkääjän varmenne on myönnetty (ilman `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Tarkista vastaukset
:::

Hyökkääjällä on jopa **aito** luotettavan varmentajan (CA) myöntämä varmenne — mutta se on myönnetty hänen omalle verkkotunnukselleen `www.biber-gewinnspiel.de`. Varmennetta nimelle `www.biberbank.de` hän ei saa miltään CA:lta, koska tämä verkkotunnus ei kuulu hänelle. Ilman Biberbankin **yksityistä avainta** hän ei myöskään voi käyttää pankin aitoa varmennetta: kättelyssä hänen pitäisi allekirjoittaa sillä Server Key Exchange.

:::quiz multi
Miltä HTTPS suojaa tässä — ja miltä ei?
- [x] HTTPS paljastaa, että palvelin ei ole oikea
- [ ] HTTPS estää DNS-palvelimen väärentämisen
- [x] HTTPS auttaa vain, jos käyttäjä ottaa varoituksen vakavasti
- [ ] HTTPS:n kanssa väärennettyä sivua ei voi lainkaan avata
:::

:::evaluate
Tarkista vastaukset
:::

## Osa 3: DNS-palvelimen korjaaminen

Avaa **DNS-palvelin** ja korjaa merkintä nimelle `www.biberbank.de`. Oikean osoitteen löydät verkkopalvelimen **www.biberbank.de** :fa-gear: **IP-asetuksista**. Älä unohda klikata **Tallenna**.

:::note
Client-PC muistaa DNS-vastaukset hetken, jotta sen ei tarvitse kysyä uudelleen joka kerta (**DNS-välimuisti**). Sarake **TTL** (*Time to Live*) kertoo sekunteina, kuinka kauan. Jos `nslookup` palauttaa korjauksesi jälkeen vielä vanhan osoitteen, odota TTL:n verran ja yritä uudelleen.
:::

:::task
title: Onko Biberbank taas aito?
Tarkistaa, että Client-PC selvittää nimen www.biberbank.de oikeaan osoitteeseen ja pystyy noutamaan sivun HTTPS:llä ilman varoitusta.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Todellisuudessa hyökkääjä väärentää harvoin itse DNS-palvelinta. Useammin hän lipsauttaa vastauksensa mukaan julkisessa WLAN-verkossa, muuttaa kotireitittimen asetuksia tai houkuttelee samannäköisellä osoitteella, kuten `www.biberbank-login.de` (**tietojenkalastelu**, *phishing*). Samannäköistä nimeä vastaan HTTPS ei auta — hyökkääjä saa sille kelvollisen varmenteen. Siksi: lue osoite tarkasti!
:::

:::tip Muista
**DNS-väärennöksessä** DNS-palvelin palauttaa nimelle hyökkääjän osoitteen. **HTTP**:n kanssa tätä ei huomaa. **HTTPS**:n kanssa hyökkääjän varmenne ei vastaa avattua nimeä, ja selain **varoittaa** — sillä yksikään CA ei myönnä varmennetta vieraille verkkotunnuksille, eikä hyökkääjällä ole oikean palvelimen yksityistä avainta.
:::
