# Kun paketteja katoaa

:::goal
**Oppimistavoite:** Osaat tarkkailla Tracerilla ja selittää, miten TCP huomaa kadonneen datan, lähettää sen uudelleen ja palauttaa oikean järjestyksen.
:::

Tässä simulaatiossa kaapeli on valmisteltu: **toinen dataa sisältävä paketti** Client-PC:ltä palvelimelle katoaa. (Löydät asetuksen, kun napsautat kaapelia Suoritustilassa: **Kohdennettu pakettihävikki**.)

## Kokeilu

1. Siirry :fa-play: **Suorita**-tilaan, avaa **Client-PC**:llä **Yksinkertainen TCP-asiakas** ja yhdistä se osoitteeseen `192.168.0.20`, porttiin `5000`.
2. Lähetä peräkkäin kolme viestiä: `Hallo`, sitten `Welt` ja sitten `!`.
3. Seuraa keskusteluikkunaa: `Hallo`-viestin kaiku tulee heti. Entä kaksi muuta?
4. Odota muutama sekunti. Avaa sitten :fa-magnifying-glass: **Jäljitys**-tilassa jäljitys **palvelimelle** (vastaanottaja), liitäntä `eth0`.

:::quiz mc
Mitä viestien `Welt` ja `!` kaiuille tapahtuu?
- [ ] Viestin `!` kaiku tulee heti, `Welt` puuttuu ikuisesti
- [x] Molemmat tulevat vasta muutaman sekunnin kuluttua — yhdessä ja oikeassa järjestyksessä
- [ ] Kumpikaan ei saavu koskaan perille
:::

## Mitä Tracer näyttää

Palvelimella `Welt`-viestin sisältävä paketti puuttuu — onhan se kadonnut. Sen sijaan löydät **Info**-sarakkeesta kolme hakasulkeissa olevaa huomautusta:

| Huomautus | Mitä tapahtui |
|---|---|
| `[TCP Previous segment not captured]` | Paketti, jossa on `!`, saapuu, mutta sitä ennen puuttuu tavuja — **aukko**. |
| `[TCP Dup ACK …]` | Palvelin kuittaa uudelleen saman numeron kuin aiemmin (*duplicate ACK*): "Odotan edelleen tavua 8." |
| `[TCP Retransmission]` | Asiakas lähettää `Welt`-viestin **vielä kerran**. |

:::quiz short
Mikä järjestysnumero (`Seq`) paketilla on, joka on merkitty `[TCP Retransmission]`?
= 8
:::

:::quiz short
Minkä kuittausnumeron (`Ack`) palvelin lähettää heti uudelleenlähetyksen jälkeen?
= 17
:::

:::quiz mc
Miksi palvelin kuittaa uudelleenlähetyksen jälkeen heti tavuun 17 asti — eikä vain `Welt`-viestin loppuun?
- [x] Se oli jo vastaanottanut `!`-viestin ja pidätellyt sitä — `Welt`-viestin myötä aukko on umpeutunut, nyt kaikki tavuun 16 asti on perillä
- [ ] Asiakas lähetti `Welt`- ja `!`-viestit vielä kerran yhdessä
- [ ] Kuittausnumerot pyöristetään aina
:::

:::evaluate
Tarkista vastaukset
:::

Sekvenssikaaviossa tämä näyttää tältä — katkoviivanuoli, jossa on ✕, on kadonnut paketti:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hallo" len=7
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=7
Client-PC -> Server: ACK
Client-PC -x Server: PSH, ACK "Welt" len=6
Client-PC -> Server: PSH, ACK "!" len=3
Server -> Client-PC: ACK
Client-PC -> Server: PSH, ACK "Welt" len=6 seq=8
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=9
Client-PC -> Server: ACK
:::

## Mitä taustalla on

Asiakas säilyttää jokaisen lähettämänsä paketin, kunnes se on kuitattu, ja käynnistää sitä varten **ajastimen**. Jos kuittaus viipyy liian kauan, asiakas lähettää datan uudelleen — **uudelleenlähetys** (*Retransmission*).

Palvelin kuittaa aina vain **ensimmäiseen aukkoon** asti. Datan, joka saapuu sen jälkeen (tässä `!`), se pidättää, kunnes aukko on täytetty. Vasta sitten se välittää kaiken ohjelmalle oikeassa järjestyksessä — siksi `Welt`- ja `!`-viestien kaiut tulivat yhdessä.

:::tip Muista
TCP havaitsee katoamiset **puuttuvista kuittauksista**: vastaanottaja kuittaa aina vain ensimmäiseen aukkoon asti. Jos kuittaus jää tulematta, lähettäjä lähettää datan ajastimen umpeuduttua **uudelleen** (*Retransmission*). Sen, mikä saapuu aukon jälkeen, vastaanottaja pidättää — näin data saavuttaa ohjelman **kokonaisena ja oikeassa järjestyksessä**.
:::

:::tip Syventävä: Fast Retransmit
Lähetä `Hallo`-viestin jälkeen nopeasti peräkkäin neljä tai useampia viestejä. Kadonneen paketin jälkeen asiakas saa kolme *Dup ACK* -kuittausta peräkkäin — ja lähettää heti uudelleen odottamatta ajastintaan. Tätä menetelmää kutsutaan nimellä **Fast Retransmit**.
:::

:::note
Todelliset TCP-toteutukset mukauttavat lisäksi lähetysnopeuttaan: jos paketteja katoaa, verkko on todennäköisesti ylikuormittunut ja lähettäjä hidastaa (*ruuhkanhallinta*). Se menee tämän kurssin ulkopuolelle.
:::
