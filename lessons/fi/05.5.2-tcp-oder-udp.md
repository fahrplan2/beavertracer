# TCP vai UDP?

| | TCP | UDP |
|---|---|---|
| Yhteys | muodostus kolmivaiheisella kättelyllä, hallittu purku | ei lainkaan — jokainen datagrammi on itsenäinen |
| Kuittaukset | kyllä (`ACK`) | ei |
| Kadonneet tiedot | lähetetään uudelleen | pysyvät kadoksissa |
| Järjestys | palautetaan | ei taattu |
| Otsake | vähintään 20 tavua | 8 tavua |
| Nopeus | hieman hitaampi, enemmän paketteja | nopea, vähän lisäkuormaa |

Milloin vähemmän on enemmän?

- **Reaaliaika:** Videopuheluissa, internetpuheluissa tai verkkopeleissä jokainen millisekunti on tärkeä. Kadonnut pätkä ääntä, joka toimitetaan sekunnin myöhemmin, ei hyödytä ketään — mieluummin lyhyt rasahdus kuin viive.
- **Lyhyet kyselyt:** **DNS**-kysely ("Mikä IP-osoite on `www.beispiel.de`?") mahtuu yhteen datagrammiin, ja vastaus myös. Yhteyden muodostus kolminkertaistaisi työmäärän. Jos vastausta ei tule, ohjelma kysyy yksinkertaisesti uudelleen.

Kaikkialla, missä jokaisen tavun on päästävä perille — verkkosivut, sähköpostit, lataukset —, TCP on sen sijaan oikea valinta.

:::tip Muista
**TCP** on luotettava mutta raskaampi — kaikelle, minkä on päästävä perille **kokonaisena** (web, sähköposti, tiedostot). **UDP** on nopea ja kevyt mutta ilman takeita — **reaaliaikaisuuteen** (puhelut, video, pelit) ja **lyhyisiin kyselyihin** kuten DNS.
:::

Nyt tunnet kuljetuskerroksen työkalut. Seuraavassa luvussa tutustut protokolliin, jotka rakentuvat niiden päälle: HTTP, DNS, sähköposti ja DHCP.
