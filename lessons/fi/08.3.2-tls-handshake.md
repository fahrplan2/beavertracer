Ennen kuin ensimmäinen salattu pyyntö lähetetään, asiakkaan ja palvelimen täytyy sopia keskenään: käytettävästä menetelmästä ja istuntoavaimesta — ja asiakkaan täytyy tarkistaa, kenen kanssa se puhuu. Tätä yhteyden muodostusta kutsutaan **TLS-kätttelyksi**.

## Kulku kaaviona

Ilman TCP-kuittauksia (`ACK`) kättely näyttää tältä:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Mitä tässä tapahtuu — ja mikä luvun 8.1 rakennuspalikka on kunkin vaiheen takana:

1. **Client Hello / Server Hello:** Asiakas ja palvelin tervehtivät toisiaan, vaihtavat satunnaislukuja ja sopivat käytettävistä menetelmistä (BeaverTracerissa: avaimenvaihto **ECDHE**:lla, allekirjoitus **ECDSA**:lla, salaus **AES**:llä).
2. **Certificate:** Palvelin lähettää **varmenteensa**. Asiakas tarkistaa CA:n allekirjoituksen, voimassaolon ja nimen. Jos tarkistus epäonnistuu, asiakas keskeyttää tässä — ja selain näyttää varoituksen.
3. **Server Key Exchange:** Palvelin lähettää **Diffie-Hellman-osuutensa** — ja **allekirjoittaa** sen yksityisellä avaimellaan. Asiakas tarkistaa allekirjoituksen varmenteen julkisella avaimella. Näin se tietää: tämä osuus tulee todella varmenteen haltijalta, ei välimieshyökkääjältä (Man-in-the-Middle).
4. **Client Key Exchange:** Asiakas lähettää oman Diffie-Hellman-osuutensa. Nyt molemmat voivat laskea saman **istuntoavaimen** — ilman että sitä on koskaan lähetetty.
5. **Change Cipher Spec:** ”Tästä lähtien salaan.”
6. **Encrypted Handshake Message (Finished):** Molemmat osapuolet lähettävät — jo salattuna — tarkistussumman kaikista tähänastisista kättelyviesteistä. Jos hyökkääjä on muuttanut jotain matkalla, tarkistussummat eivät täsmää ja yhteys katkaistaan.
7. **Application Data:** Tästä eteenpäin HTTP-data kulkee — symmetrisesti AES:llä salattuna.

:::quiz match
Certificate -> Palvelin todistaa henkilöllisyytensä varmenteellaan
Server Key Exchange -> Palvelimen allekirjoitettu Diffie-Hellman-osuus
Client Key Exchange -> Asiakkaan Diffie-Hellman-osuus
Change Cipher Spec -> Tästä lähtien salataan
Application Data -> Salattu HTTP-data
:::

:::note
Jäljityksessä näet **kaksi** TLS-yhteyttä peräkkäin: selain hakee ensin sivun ja muodostaa sitten uuden yhteyden tyylitiedostolle `style.css`. Jokaisella yhteydellä on oma kättelynsä ja oma istuntoavaimensa. Oikeat selaimet pitävät yhteyksiä auki ja säästävät näin osan tästä vaivasta. Uudempi versio **TLS 1.3** pärjää lisäksi vähemmillä viesteillä kuin tässä näytetty TLS 1.2.
:::

:::tip Muista
**TLS-kättelyssä** palvelin todistaa henkilöllisyytensä **varmenteellaan**, molemmat osapuolet sopivat **Diffie-Hellmanilla** **istuntoavaimesta** (palvelin **allekirjoittaa** osuutensa), ja **Finished**-viesteillä molemmat tarkistavat, ettei kukaan ole muuttanut kättelyä. Sen jälkeen data siirretään symmetrisesti salattuna **Application Data** -viesteinä.
:::
