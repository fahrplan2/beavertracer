## Miltä pyyntö näyttää

Napsauta jäljityksessä pakettia `GET / HTTP/1.1` ja avaa **Hypertext Transfer Protocol**. HTTP-pyyntö on pelkkää tekstiä:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

Palvelimen vastaus on rakennettu samalla tavalla: siinä on tilarivi, otsakkeita, tyhjä rivi ja sen jälkeen varsinainen tiedosto:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP-pyyntö
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP-pyyntö
Server -> Client-PC: 200 OK | style.css
:::

## Metodit ja tilakoodit

**Metodi** kertoo, mitä asiakas haluaa:

| Metodi | Merkitys |
|---|---|
| **GET** | noutaa tiedoston |
| **POST** | lähettää tietoja palvelimelle, esim. täytetyn lomakkeen |
| **HEAD** | noutaa vain otsakkeet ilman tiedostoa |

**Tilakoodi** kertoo, miten pyynnön käsittely sujui. Ensimmäinen numero paljastaa vastauksen tyypin:

| Koodi | Teksti | Merkitys |
|---|---|---|
| **200** | OK | kaikki kunnossa |
| **301** | Moved Permanently | sivu on siirtynyt pysyvästi |
| **404** | Not Found | tiedostoa ei ole olemassa |
| **405** | Method Not Allowed | tämä metodi ei ole sallittu täällä |
| **500** | Internal Server Error | virhe palvelimella |

`2xx` tarkoittaa onnistumista, `3xx` uudelleenohjausta, `4xx` asiakkaan virhettä (virheellinen pyyntö) ja `5xx` palvelimen virhettä.

:::tip Muista
**HTTP** toimii **pyyntö-vastaus-periaatteella**: asiakas lähettää **pyynnön** (metodi kuten `GET`, polku, otsakkeet), ja palvelin vastaa **tilakoodilla** (esim. `200 OK`, `404 Not Found`), otsakkeilla ja tiedostolla. Jokaista verkkosivun tiedostoa varten on oma pyyntönsä.
:::
