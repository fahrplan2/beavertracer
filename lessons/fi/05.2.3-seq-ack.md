# Järjestys- ja kuittausnumerot

:::sim
url=/sims/lesson-5.1.btsim
:::

Mistä TCP tietää, onko kaikki perillä — ja missä järjestyksessä? Kumpikin osapuoli **numeroi lähettämänsä tavut**:

- **Järjestysnumero** (`SEQ`) on tämän paketin ensimmäisen tavun numero.
- **Kuittausnumero** (`ACK`) kertoo: "Olen saanut kaiken tähän asti — seuraavaksi odotan tavua nro …"

Lisäksi kaksi sääntöä: `SYN` ja `FIN` lasketaan yhdeksi tavuksi, vaikka ne eivät kuljeta dataa. Ja kumpikin osapuoli laskee omiaan — siksi numerosarjoja on kaksi: kaaviossa punainen (asiakas) ja sininen (palvelin).

## Laske itse

Tässä on yhteytesi vielä kerran. Viivojen vieressä olevat luvut näyttävät koneen laskurin arvon kyseisessä kohdassa:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Käy läpi punainen lukusarja:

1. Asiakas aloittaa luvusta `SEQ=0`. Sen `SYN` kuluttaa yhden numeron — palvelin kuittaa arvolla `ACK=1`.
2. Viesti alkaa kohdasta `SEQ=1` ja on 13 tavua pitkä (tavut 1–13). Palvelin kuittaa arvolla `ACK=14`: "Seuraavaksi odotan tavua 14."
3. Asiakkaan `FIN` saa siksi arvon `SEQ=14`, ja se kuitataan arvolla `ACK=15`.

Palvelimen sininen sarja toimii täsmälleen samoin.

:::tip Muista
**Järjestysnumero** (`SEQ`) on paketin ensimmäisen tavun numero. **Kuittausnumero** (`ACK`) on sen seuraavan tavun numero, jota vastaanottaja odottaa — kaikki sitä ennen on saapunut perille. Sääntö on: **ACK = SEQ + vastaanotetun datan pituus**; `SYN` ja `FIN` lasketaan yhdeksi tavuksi. Kumpikin osapuoli laskee omat tavunsa.
:::

:::tip Kokeile itse
Muodosta yhteys uudelleen **Yksinkertaisella TCP-asiakkaalla** ja lähetä kaksi viestiä peräkkäin. Sano etukäteen, mitkä `Seq`- ja `Ack`-arvot näkyvät **Info**-sarakkeessa — ja tarkista se jäljityksestä.
:::

:::note
Oikeissa verkoissa laskenta ei ala nollasta: kumpikin osapuoli valitsee **satunnaisen alkunumeron** (*Initial Sequence Number*, ISN) väliltä 0 – noin 4,3 miljardia. Kun suurin numero on saavutettu, laskenta jatkuu taas nollasta. Tracer vähentää alkunumeron ja näyttää **suhteelliset** numerot — aivan kuten Wireshark. Siksi näet arvot `Seq=0` ja `Seq=1`.

Lisäksi jokaisessa paketissa on `Win=` — **ikkunan koko**: näin monta tavua vastaanottaja pystyy juuri nyt ottamaan vastaan. Sillä se hidastaa liian nopeaa lähettäjää (*vuonohjaus*). BeaverTracerissa ikkuna on aina saman kokoinen.
:::
