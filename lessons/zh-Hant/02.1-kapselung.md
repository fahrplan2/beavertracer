## 逐層展開

點擊 **Ethernet**、**Internet Protocol Version 4**、**Transmission Control Protocol** 和 **Hypertext Transfer Protocol** 前面的小三角形。每一層都帶有自己的資訊：

| 樹中的層 | 你可以在其中找到什麼 | 用途 |
|---|---|---|
| Ethernet | `Source` 和 `Destination`：MAC 位址，例如 `aa:57:28:…` | 區域網路中的哪一張網路卡 |
| IPv4 | `Source Address` `192.168.0.10`，`Destination Address` `192.168.0.20` | 哪一台電腦——即使跨越網路邊界也適用 |
| TCP | `Source Port` `49152`，`Destination Port` `80` | 電腦上的哪個程式 |
| HTTP | `GET / HTTP/1.1`，`Host: 192.168.0.20` | 瀏覽器真正要傳達的訊息 |

另外請看這兩行：在 Ethernet 中有 `Type: IPv4`，在 IPv4 中有 `Protocol: TCP`。也就是說，每一層都會透露*它裡面裝的是什麼*——接收端就是這樣知道該如何繼續拆封。

## 信封裡的信封

你剛才看到的內容，在發送端是這樣產生的：

1. 瀏覽器寫下真正的訊息：`GET / HTTP/1.1`（**HTTP**）。
2. **TCP** 把它包起來，並在前面加上連接埠——這樣它才會送達正確的程式。
3. **IP** 把整個內容再包起來，並在前面加上 IP 位址——這樣它才會送達正確的電腦。
4. **Ethernet** 把所有內容放進一個帶有 MAC 位址的訊框中——這樣它才會在區域網路中送達正確的網路卡。

在接收端則完全相反：每一層取下屬於自己的部分，再把其餘部分往上層傳遞。這就像一封被裝進好幾層信封的信——最裡面是訊息，每個信封外面則寫著下一個要拆開它的人的收件地址。

:::tip 重點整理
每一層都會把自己的控制資訊——也就是**標頭（Header）**——加在上一層資料的前面。這種包裝與拆封的過程稱為**封裝**。
:::

依所在的層不同，這個「小包裹」有不同的名稱：

| 層 | 範例中的協定 | 資料單位的名稱 |
|---|---|---|
| 第 2 層 | Ethernet | **訊框（Frame）** |
| 第 3 層 | IPv4 | **封包** |
| 第 4 層 | TCP | **區段（Segment）** |

:::note
在日常用語中——本課程也一樣——人們常常直接說「封包」，不論是在哪一層。當需要精確表達時，就使用表格中的名稱。
:::

:::quiz fill
在發送端，每一層都會把上一層的資料包起來，並在前面加上一個{標頭}。這個原則稱為{封裝}。在第 2 層，資料單位稱為{訊框|Frame}，在第 4 層使用 TCP 時稱為{區段|Segment}。
