# TLS 握手

:::sim
url=/sims/lesson-8.2.1.btsim
:::

在傳送第一個加密請求之前，用戶端與伺服器必須先達成共識：約定一種加密方法、約定一把工作階段金鑰——而且用戶端還必須確認自己正在和誰通訊。這個連線建立過程稱為 **TLS 握手**（TLS-Handshake）。

## 觀察

在 **Client-PC** 上開啟 `https://www.beaver-schule.de/`（如果還沒有開啟過），為 **Client-PC** 開啟一個追蹤，並用 `tls` 過濾。

## 圖示流程

若不計 TCP 的確認（`ACK`），握手過程如下：

:::seq
mode: text
Client -> Server: Client Hello | 隨機數、可用的方法
Server -> Client: Server Hello | 選定的方法、隨機數
Server -> Client: Certificate | 伺服器的憑證
Server -> Client: Server Key Exchange | DH 部分，已簽章
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | 用戶端的 DH 部分
Client -> Server: Change Cipher Spec | 從現在起加密
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | 從現在起加密
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET /（已加密）
Server -> Client: Application Data | 網頁（已加密）
:::

過程中發生了什麼——以及背後運用了 8.1 節中的哪個基本要素：

1. **Client Hello / Server Hello：** 用戶端與伺服器互相問候、交換隨機數，並約定所用的方法（在 BeaverTracer 中：金鑰交換使用 **ECDHE**，簽章使用 **ECDSA**，加密使用 **AES**）。
2. **Certificate：** 伺服器傳送它的**憑證**。用戶端會檢查 CA 的簽章、有效期限和名稱。如果檢查失敗，用戶端會在此中止——瀏覽器則會顯示警告。
3. **Server Key Exchange：** 伺服器傳送它的 **Diffie-Hellman 部分**，並用自己的私密金鑰對其**簽章**。用戶端用憑證中的公開金鑰檢查簽章。這樣用戶端就知道：這個部分確實來自憑證持有者，而不是來自中間人（Man-in-the-Middle）。
4. **Client Key Exchange：** 用戶端傳送它的 Diffie-Hellman 部分。現在雙方可以計算出同一把**工作階段金鑰**——而這把金鑰從未被傳輸過。
5. **Change Cipher Spec：**「從現在起我開始加密。」
6. **Encrypted Handshake Message (Finished)：** 雙方各自傳送一個針對之前所有握手訊息的檢查碼——此時已經是加密的。如果攻擊者在途中更動了任何內容，檢查碼就會不吻合，連線隨即中止。
7. **Application Data：** 從這裡開始傳輸 HTTP 資料——以 AES 進行對稱式加密。

:::quiz match
Certificate -> 伺服器以它的憑證證明自己的身分
Server Key Exchange -> 伺服器已簽章的 Diffie-Hellman 部分
Client Key Exchange -> 用戶端的 Diffie-Hellman 部分
Change Cipher Spec -> 從現在起開始加密
Application Data -> 已加密的 HTTP 資料
:::

:::note
在追蹤中，你會看到**兩個**先後出現的 TLS 連線：瀏覽器先擷取網頁，然後為樣式表 `style.css` 建立一個新的連線。每個連線都有自己的握手和自己的工作階段金鑰。真正的瀏覽器會讓連線保持開啟，因此可以省下一部分這樣的開銷。此外，較新的版本 **TLS 1.3** 所需的訊息比這裡展示的 TLS 1.2 更少。
:::

:::tip 重點整理
在 **TLS 握手**中，伺服器以它的**憑證**證明自己的身分，雙方透過 **Diffie-Hellman** 協商出一把**工作階段金鑰**（伺服器會對自己的部分**簽章**），並且雙方以 **Finished** 確認沒有人更動過握手內容。之後，資料會以 **Application Data** 的形式經對稱式加密傳輸。
:::
