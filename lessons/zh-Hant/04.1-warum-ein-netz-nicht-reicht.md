# 為什麼一個網路不夠用

:::sim
url=/sims/lesson-4.1.btsim

在工作區中,你會看到兩個小型公司網路:**Firma A** 有 Anna(`192.168.0.10`)和 Ben(`192.168.0.11`),**Firma B** 有 Clara(`172.16.0.10`)和 David(`172.16.0.11`)。這兩台交換器甚至直接用一條網路線相連。

## 在自己的網路內 ping

1. 切換到 :fa-play: **執行**模式,在 **Anna** 上開啟 :fa-terminal: **終端機**,並 ping Ben:
   ```
   $ ping 192.168.0.11
   ```
2. 切換到 :fa-magnifying-glass: **追蹤**模式,為 **Anna** 開啟一個追蹤,然後點選一個 `Echo (ping) request`。
3. 在協定樹中展開 **Internet Protocol Version 4** 這一行。這就是封包中的 IP 部分——也是本章要探討的部分。

:::quiz match
Source Address -> 發送端的 IP 位址
Destination Address -> 接收端的 IP 位址
Time to Live -> 封包還可以經過多少台路由器
Protocol -> 封包中包含的是哪種協定(這裡是 ICMP,也就是 ping)
:::

檢查配對

## 對另一個網路 ping

切換回 :fa-play: **執行**模式,從 **Anna** 對 Clara 進行 ping(`ping 172.16.0.10`)。然後再看一次 Anna 的追蹤。

:::quiz mc
會發生什麼事?
- [ ] ping 成功——畢竟交換器是相連的
- [x] 沒有任何 ping 送達,而且 Anna 的追蹤中完全沒有出現任何傳往 Clara 的封包——連 ARP 請求都沒有
- [ ] Anna 傳送了 ARP 請求,但 Clara 沒有回應
:::

:::quiz mc
為什麼 Anna 完全沒有送出任何東西?
- [ ] 交換器之間的網路線壞了
- [ ] Clara 已關機
- [x] Anna 從 Clara 的 IP 位址看出 Clara 位於另一個網路——而且不知道通往那裡的路
:::

:::evaluate
檢查答案
:::

## 背後的原理

IP 位址的運作方式很像郵寄地址:一部分說明裝置位於哪個**網路**(就像街道),另一部分則說明指的是該網路中的哪一個**裝置**(就像門牌號碼)。Anna 位於網路 `192.168.0…`,Clara 位於網路 `172.16.0…`——是兩條不同的「街道」。

對於*自己*網路內的裝置,電腦會直接傳送封包(透過 ARP 和交換器,就像你已經知道的那樣)。若要送往*其他*網路,則需要一台能把各個網路連接起來並轉送封包的裝置:**路由器**。這裡還沒有路由器——所以交換器之間的那條網路線也幫不上忙。

:::tip 重點整理
第 3 層的**網際網路協定**(**IP**)負責確保封包即使在不同網路之間也能送達。**IP 位址**由**網路部分**(在哪個網路?)和**主機部分**(哪個裝置?)組成。位於同一個網路中的裝置可以直接互相通訊——要連到其他網路則需要**路由器**。
:::

這就引出兩個問題,也是接下來幾節要探討的內容:電腦如何知道位址中的網路部分*究竟*在哪裡結束?還有,路由器是如何運作的?
