# 設定 HTTPS

:::sim
url=/sims/lesson-8.3.3.btsim
:::

這裡接續第 8.2.2 節結束的地方：網頁伺服器 **www.beaver-schule.de** 上有 **Schul-CA** 以及由它簽發的伺服器憑證，而且 **Client-PC** 信任 Schul-CA。只是這台網頁伺服器還不支援 HTTPS。

## 之前

切換到 :fa-play: **執行**模式，在 **Client-PC** 的 :fa-globe: **瀏覽器**中開啟 `https://www.beaver-schule.de/`。

:::quiz mc
會發生什麼事？
- [x] 無法建立連線 — 連接埠 443 上沒有任何服務在監聽
- [ ] 瀏覽器警告憑證不安全
- [ ] 頁面顯示出來，但沒有鎖頭
:::

檢查答案

## 啟用 HTTPS

1. 在網頁伺服器上開啟 **HTTP 伺服器**，然後按一下 **Stoppen** — 只要伺服器還在運作，就無法變更設定。
2. 切換到 **HTTPS** 索引標籤：
    - 勾選 **HTTPS aktivieren**，**HTTPS-Port** 設為 `443`
    - 在 **Zertifikat** 中選擇伺服器憑證 `www.beaver-schule.de` — 不要選 Schul-CA！
    - 按一下 **Verwenden**
3. 按一下**開始**。

在 Client-PC 上再次透過 `https://` 開啟該頁面。按一下鎖頭，檢查簽發者與有效期限。

:::task
title: HTTPS 設定好了嗎？
檢查 Client-PC 是否能在沒有憑證警告的情況下擷取 https://www.beaver-schule.de/。模擬必須在執行模式下運作才能進行檢查。
check: httpsOk(2, "https://www.beaver-schule.de/")
:::

:::quiz mc
為什麼在 HTTP 伺服器中不能選擇 **Schul-CA** 的憑證？
- [ ] 因為 CA 憑證無法加密
- [x] 因為它是簽發給名稱 `Schul-CA` 的，而不是 `www.beaver-schule.de` — 瀏覽器會發出警告
- [ ] 因為 Schul-CA 沒有私密金鑰
:::

:::quiz mc
如果某個裝置**不**信任 Schul-CA，例如訪客的手機，它會看到什麼？
- [ ] 一切正常，頁面顯示並帶有鎖頭
- [x] 憑證警告，因為它無法沿著信任鏈追溯到已知的 CA
- [ ] 什麼都看不到，因為連線被拒絕
:::

檢查答案

:::note
公開網站需要由預先安裝在所有瀏覽器中的 CA 所簽發的憑證。自 2015 年起出現了 **Let's Encrypt**，這是一個免費且自動簽發這類憑證的 CA — 這也是如今幾乎所有網站都使用 HTTPS 的主要原因之一。
:::

:::tip 重點整理
要使用 **HTTPS**，網頁伺服器需要一張**帶有私密金鑰的伺服器憑證**，其名稱必須與網址相符，並且必須在**連接埠 443** 上監聽。只有當用戶端認識簽發的 **CA** 時，才會信任該網站。
:::
