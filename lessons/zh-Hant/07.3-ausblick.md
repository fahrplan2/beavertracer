# 展望：IPv6 與電信級 NAT

:::sim
empty
:::

NAT 是針對 IPv4 位址不足所想出的絕妙權宜之計——但終究只是權宜之計。以下兩項發展你應該要知道。

## IPv6：不再需要 NAT

**IPv6** 擁有極為充裕的位址（第 4.6 章）。因此，ISP 給家用路由器的不只是一個位址，而是一整個**前綴**——通常是 `/56` 或 `/48`，也就是數十億個位址。這稱為**前綴委派**（DHCPv6-PD）。家用路由器再從中透過 SLAAC 為每台裝置分配各自的**全球唯一**位址。

這樣就不再需要 NAT：每台裝置都可以被直接定址。這很方便，但路由器上需要一道良好的**防火牆**——因為 NAT 的「副作用」（外部無人能主動發起連線）不復存在。第 9 章會討論這個主題。

## 電信級 NAT：在 ISP 端做 NAT

許多 ISP 自己的 IPv4 位址也不夠用。這時，連家用路由器都拿不到公用位址，只會得到一個來自特殊範圍（`100.64.0.0/10`）的位址，而 ISP 會替許多客戶集中**再做一次 NAT**。這稱為**電信級 NAT**（Carrier-Grade-NAT，CGNAT）；在這種情況下，IPv4 往往只剩這一條路，而 IPv6 則有真正的公用位址（*DS-Lite*）。

結果是：在自己路由器上設定的**連接埠轉送**對 IPv4 就沒用了——來自外部的封包在 ISP 那裡就被擋下來了。想在家裡架設伺服器的人，就需要 IPv6 或其他的網路連線方案。
