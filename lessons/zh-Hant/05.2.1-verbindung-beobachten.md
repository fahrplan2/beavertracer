# 從頭到尾的一次連線

:::sim
url=/sims/lesson-5.1.btsim
:::

在 **Server** 上，回顯服務執行於連接埠 `5000`：它會立刻把每則訊息原樣傳回。透過 **簡單 TCP 用戶端**，你可以一步一步控制一次連線——每個按鈕就是一個階段。

## 實驗

1. 切換到 :fa-play: **執行**模式，點選 **Client-PC**，然後開啟 **簡單 TCP 用戶端**。
2. 在 **Host** 欄位輸入 `192.168.0.20`，在 **Port** 欄位輸入 `5000`。
3. 點選 **連線**。
4. 在訊息欄位輸入 `Hello World`，然後點選 **傳送**。不久後，你會在聊天視窗中看到伺服器的回顯。
5. 點選 **中斷連線**。
6. 切換到 :fa-magnifying-glass: **追蹤**模式，並用 **+** 為 **Client-PC** 的 `eth0` 介面開啟一個 Trace。

:::note
一開始的兩個 ARP 封包你在第 1 章已經認識了。在 TCP 封包的 **Info** 欄中，最前面是 `49152 → 5000`（從哪個連接埠到哪個連接埠），接著是方括號中的**旗標（Flags）**，之後是 `Seq=`、`Ack=` 和 `Len=` 這類數字。這些數字從第 5.2.3 頁開始才會講解——在這裡你只需留意旗標和 `Len`。
:::

## 階段 1：連線

:::quiz short
在你點選 **連線** 之後、你的訊息送出之前，一共交換了多少個 TCP 封包？
= 3
= 三
:::

:::quiz mc
誰發送第一個帶有 `[SYN]` 的封包？
- [x] Client-PC
- [ ] Server
:::

:::quiz mc
伺服器用哪些旗標回應？
- [ ] `[SYN]`
- [x] `[SYN, ACK]`
- [ ] `[ACK]`
- [ ] `[FIN, ACK]`
:::

## 階段 2：傳送

`Len` 表示一個封包攜帶了多少位元組的資料。

:::quiz short
帶有你訊息的封包攜帶了多少位元組（`Len`）？
= 13
:::

:::note
`Hello World` 只有 11 個字元。不過 TCP 用戶端會再附加一個行尾符號（2 位元組，`\r\n`）——許多網際網路協定（例如 SMTP 或 HTTP）都是這樣預期的。
:::

:::quiz mc
伺服器在你的訊息之後，於回顯之前，會立刻傳回什麼？
- [x] 一個帶有 `[ACK]` 且 `Len=0` 的封包——不含資料的確認
- [ ] 什麼都不傳
- [ ] 一個新的 `[SYN]`
:::

## 階段 3：中斷連線

:::

## 四項任務在哪裡？

請配對，你可以在 Trace 中的哪裡找到 5.1 節的各項任務：

:::quiz match
連線建立 -> 三個封包 [SYN]、[SYN, ACK] 和 [ACK]
可靠傳輸 -> 帶有 [ACK] 且 Len=0、用來確認收到的封包
連線拆除 -> 帶有 FIN 的封包及其確認
多工 -> 方括號前的連接埠號碼 49152 → 5000
:::
