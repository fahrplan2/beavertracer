## 從外部執行 ping

切換到 :fa-play: **執行**模式，從 **Internet-PC** 對 Schulserver 執行 ping：

```
$ ping -c 2 198.51.100.10
```

接著在防火牆中開啟 **Protokoll** 索引標籤。

## 連接埠掃描：被丟棄還是被拒絕？

現在針對性地掃描五個連接埠。連接埠 3306（資料庫）在 Schulserver 上完全沒有運作。

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22（被丟棄） -> filtered
25（允許，服務運作中） -> open
110（被拒絕） -> closed
3306（允許，沒有服務） -> closed
:::

:::evaluate
檢查配對
:::

:::quiz multi
攻擊者可以從結果中推斷出什麼？
- [x] 看到 `filtered` 時，他知道：那裡有一道防火牆，會把封包吞掉
- [x] 看到 `closed` 時，他無法分辨是防火牆拒絕了連線，還是根本沒有服務在運作
- [ ] 看到 `filtered` 時，他知道該連接埠後面運作的是哪種服務
- [ ] 看到 `closed` 時，該服務仍然可以連線
:::

:::evaluate
檢查答案
:::

最後，請查看規則清單中的 **Treffer** 欄：防火牆會在這裡統計每條規則已經處理了多少個封包。**Standardrichtlinie** 旁邊的數值，則是統計所有沒有符合任何規則的封包數量。

:::tip 重點整理
**被丟棄**的封包會無聲無息地消失：`ping` 回報逾時，`nmap` 回報 `filtered`。**被拒絕**的封包，防火牆會以拒絕訊息回應（TCP 為 RST）——從外部看起來就像是關閉的連接埠。防火牆的 **Protokoll** 會顯示它攔截了哪些封包，**Treffer** 欄則顯示是哪條規則生效。
:::
