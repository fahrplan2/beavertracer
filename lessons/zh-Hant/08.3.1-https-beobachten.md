# HTTP 與 HTTPS 的比較

:::sim
url=/sims/lesson-8.2.1.btsim
:::

網頁伺服器 **www.beaver-schule.de** 同時以 HTTP 和 HTTPS 提供學校的成績入口網站。竊聽者能看到什麼?

## 實驗

1. 切換到 :fa-play: **執行**模式,在 **Client-PC** 的 :fa-globe: **瀏覽器**中先開啟 `http://www.beaver-schule.de/`,再開啟 `https://www.beaver-schule.de/`。
2. 在 :fa-magnifying-glass: **追蹤**模式下,為 **Client-PC** 開啟一個追蹤。
3. 先找到封包 `HTTP/1.1 200 OK` 並點擊它。在下方的詳細資料中,你可以找到網頁的內容。

:::quiz mc
竊聽者在使用 **HTTP** 時能看到什麼?
- [x] 完整的網頁,包括 Anna 的成績
- [ ] 只有伺服器的位址
- [ ] 什麼都看不到,因為 HTTP 是透過 TCP 運作的
:::

:::quiz short
Anna 的數學成績是多少?
= 2
:::

:::evaluate
檢查答案
:::

現在進入 HTTPS 的部分。找到用戶端用來開始第二條連線的 `[SYN]` 封包。

:::quiz short
HTTPS 連線的目的連接埠是多少(**Info** 欄,`… → ???`)?
= 443
:::

現在在追蹤上方的篩選欄位中輸入 `tls` — 這樣你就只會看到 TLS 封包。

:::quiz mc
在包含網頁內容的封包中,**Info** 欄顯示的是什麼?
- [ ] `HTTP/1.1 200 OK`
- [x] `Application Data`
- [ ] `Encrypted HTML`
:::

:::quiz multi
竊聽者在使用 **HTTPS** 時仍然能看到什麼?
- [x] 用戶端與伺服器的 IP 位址
- [x] 使用的是連接埠 443,因此很可能是 HTTPS
- [x] 大約傳輸了多少資料
- [ ] 開啟了哪個頁面以及頁面上的內容
:::

:::evaluate
檢查答案
:::

:::note
點擊一個 **Application Data** 封包:其中的酬載資料只是一串看似隨機的位元組。追蹤工具無法將它解密 — 它和攻擊者一樣,都不知道工作階段金鑰。
:::

:::tip 重點整理
使用 **HTTP** 時,任何竊聽者都能讀取完整的網頁。使用 **HTTPS** 時,他只能看到**誰與誰**在通訊(IP 位址、連接埠 443)以及**多少資料** — 內容則以加密形式存放在 **Application Data** 封包中。
:::
