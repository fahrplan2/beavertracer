# 查看並觀察網頁

這部分你不需要自己建置任何東西：工作區上已經備有一個模擬，裡面有一台 **Client-PC** 和一台 **Webserver**。

## 開啟網頁

1. 切換到 :fa-play: **執行**模式。
2. 在 **Client-PC** 上開啟 :fa-globe: **瀏覽器** 應用程式，並輸入 Webserver 的位址：`http://192.168.0.20/`。
3. 切換到 :fa-magnifying-glass: **追蹤**模式，點選 **+** 為 **Client-PC** 的 `eth0` 連接埠開啟一個追蹤 — 和 ping 時完全一樣。

:::note
只是開啟一次網頁，封包數量卻多得令人意外 — 比 ping 多出許多。擷取一個網頁是一個多階段的過程，而不是單一動作。
:::

## 閱讀封包清單

你現在還不需要知道各個協定究竟做了什麼。回答下面的問題所需要的一切，都在 **Protokoll** 和 **Info** 欄位中。

:::quiz mc
清單最上方是哪一個協定？
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
請數一數：在第一個 **HTTP** 封包之前有多少個 **TCP** 封包？
= 3
= 三
:::

:::quiz mc
Webserver 如何回應瀏覽器的請求？請查看第二個 HTTP 封包的 Info 欄位。
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
檢查答案
:::

## 指出相關的協定

根據你的觀察，現在可以看出哪個協定負責哪件事。

:::tip 提示
再把 **Info** 欄位讀一遍：`Who has …?`、`[SYN]`、`[SYN, ACK]`、`[ACK]`、`GET /` 和 `200 OK` 幾乎已經透露了一切。
:::

:::quiz match
ARP -> 詢問網路中的所有人：「誰擁有 IP 位址 192.168.0.20？」
TCP -> 在資料開始傳送之前，先用三個簡短的封包建立連線
HTTP -> 請求網頁 (GET) 並將網頁回傳 (200 OK)
:::

:::evaluate
檢查配對
:::

:::tip 重點整理
開啟網頁是分階段進行的：先在網路中**找到**伺服器 (ARP)，接著**建立**連線 (TCP)，然後**請求並傳回**網頁 (HTTP) — 最後再把連線**拆除** (清單末尾帶有 `[FIN]` 的 TCP 封包)。
:::

:::note
這次你是直接輸入伺服器的 IP 位址，所以還沒有用到 **DNS** (將 `www.beispiel.de` 這類名稱「翻譯」成 IP 位址的服務)。我們會在第 6 章補上這一部分。
:::

你有沒有注意到，封包結構中的各個協定帶有附數字的彩色標記？這代表什麼，我們會在第 2 章說明。在那裡我們會看看如何有系統地將眾多協定分類 — 使用 OSI 和 TCP/IP 參考模型。到這裡，第 1 章就完成了。
