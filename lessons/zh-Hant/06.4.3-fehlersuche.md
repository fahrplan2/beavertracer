# 疑難排解：筆電連不上網路

:::sim
url=/sims/lesson-6.4.3.btsim
:::

假期結束後，老師們回報：「我們的筆電連不上網路了！」兩台筆電都設定為 **DHCP**。依照規劃，DHCP 伺服器應該分配 `192.168.0.100` 到 `192.168.0.120` 的位址，閘道為 `192.168.0.1`，DNS 伺服器為 `192.168.0.53`。

找出錯誤並加以修正。

<details>
<summary>提示 1：筆電取得了哪個位址？</summary>

查看筆電的 :fa-gear: **IP 設定**。以 `169.254` 開頭的位址是裝置**自己**指定的——因為沒有任何 DHCP 伺服器回應。
</details>

<details>
<summary>提示 2：DHCP 伺服器有回應嗎？</summary>

為一台筆電開啟追蹤。你只看到 `DHCP Discover`，還是也有回應？接著查看 **DHCP 伺服器** 應用程式：它有在執行嗎？它分配的是哪個範圍？
</details>

<details>
<summary>提示 3：重新取得新位址</summary>

如果你在伺服器上changed了設定，請在筆電的 IP 設定中先將模式暫時切換為**靜態**，再切換回 **DHCP**，然後按下**套用**——這樣它就會重新發出請求。
</details>

:::task
title: 筆電重新連上網路了嗎？
檢查兩台筆電是否都取得了規劃範圍內的位址，並且能連到 DHCP 伺服器。模擬必須在執行模式下運作才能檢查。
check: ip(3, "192.168.0.96/27")
check: ip(4, "192.168.0.96/27")
check: pingOk(3, 2)
check: pingOk(4, 2)
:::

## 發生了什麼事？

:::quiz multi
下列哪些敘述是正確的？
- [x] DHCP 伺服器沒有啟動——筆電自己指定了 `169.254` 位址
- [x] 位址範圍設在錯誤的網路中（`192.168.1.…` 而不是 `192.168.0.…`）
- [ ] 筆電被設定為固定位址
- [ ] 交換器上缺少閘道
:::

:::evaluate
檢查答案
:::

:::tip 重點整理
如果裝置的位址屬於 **`169.254.0.0/16`**，表示它**沒有收到任何 DHCP 伺服器的回應**，而自己指定了位址（**APIPA**）。使用這種位址時，它只能連到其他同樣情況的裝置。此時請檢查：DHCP 伺服器有在執行嗎？它可以連得到嗎？它分配的位址是否來自**正確的網路**？
:::
