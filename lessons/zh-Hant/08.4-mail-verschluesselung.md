# 加密傳輸電子郵件

:::sim
url=/sims/lesson-8.4.btsim
:::

在 6.3.2 節中你已經看到,使用 SMTP 和 POP3 時,發送端、接收端、內容甚至密碼都是以可讀的形式在線路上傳輸。和 HTTP 一樣,也可以用 TLS 來保護這些資料。電子郵件有兩種做法:

| | **隱式 TLS** | **STARTTLS** |
|---|---|---|
| 流程 | 連線從一開始就是加密的。 | 連線一開始是未加密的;用戶端傳送指令 `STARTTLS`,之後才開始加密。 |
| 連接埠 | 專用連接埠:**SMTPS 465**、**POP3S 995**、**IMAPS 993** | 一般連接埠,例如 SMTP 25 或 587 |

SMTPS、POP3S 和 IMAPS 中的「S」和 HTTPS 一樣,代表 *Secure*(安全)。

## 改用加密連接埠

在 Anna 的電子郵件程式中開啟**設定**:

- **內送:** 連接埠 `995`,並勾選 **TLS**
- **外寄(SMTP):** 連接埠 `465`,加密方式選 **隱式 TLS**

保存設定後,再寄一封郵件並再次擷取。查看追蹤記錄(篩選條件 `tls`)。

## 傳輸加密無法保護什麼

TLS 只加密兩台電腦之間的**路徑**:從 Anna 到郵件伺服器,以及——如果兩台郵件伺服器都支援的話——從郵件伺服器到郵件伺服器。但是郵件本身**存放在郵件伺服器上**時是明文。任何能存取郵件伺服器的人,都可以讀取上面所有的郵件。

如果只希望接收端能讀取郵件,就必須進行**端對端**加密:發送端用接收端的公開金鑰加密,只有接收端才能再將它解密。電子郵件有 **S/MIME** 和 **OpenPGP** 這兩種方法;Signal 或 WhatsApp 等通訊軟體則會自動完成這件事。

:::tip 重點整理
電子郵件使用 **TLS** 加密傳輸——可以是在專用連接埠上的**隱式 TLS**(**SMTPS 465**、**POP3S 995**、**IMAPS 993**),也可以是在一般連接埠上透過 **STARTTLS**。這屬於**傳輸加密**:它保護的是路徑,而不是伺服器上的郵件。要做到這一點,需要**端對端加密**。
:::
