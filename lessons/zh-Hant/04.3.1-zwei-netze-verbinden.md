# 連接兩個網路

:::sim
url=/sims/lesson-4.3.1.btsim
:::

路由器有兩個介面：

| 介面 | IP 位址 | 網路 |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

為了讓這些 PC 使用路由器，每一台 PC 都設定了**預設閘道**：Anna 和 Ben 的是 `192.168.0.1`，Clara 和 David 的是 `172.16.0.1`。你可以在 :fa-gear: **IP 設定**的 **Gateway** 欄位中找到它。

:::tip 重點整理
**閘道**（更精確地說：*預設閘道*）是路由器**在自己網路中**的 IP 位址。PC 會把所有目的地位於其他網路的封包傳送給閘道。
:::

## 路由器如何處理封包

路由器接收 Anna 傳來的訊框，拆開 IP 封包，並查看**目的 IP 位址**。由此它判斷：Clara 位於 `eth1` 所連接的網路。於是它把封包封裝進一個**新的**訊框——以自己的 MAC 位址作為來源，以 Clara 的 MAC 位址作為目的——然後從該介面傳送出去。

| 路由器對……做了什麼？ | |
|---|---|
| MAC 位址（第 2 層）？ | 會**重新**設定——它們只在各自的網路中有效 |
| IP 位址（第 3 層）？ | **保持不變**——從 Anna 到 Clara 都一樣 |
| Time to Live？ | **減少 1** |

:::tip 重點整理
**路由器**運作在**第 3 層**：它根據**目的 IP 位址**把封包轉送到其他網路。IP 位址在整條路徑上保持不變，MAC 位址則在每個網路中重新設定。每經過一台路由器，**Time to Live（TTL）**就減 1——減到 0 時，封包會被丟棄。這樣封包就不會無止盡地繞圈。
:::

:::note
你還記得第 3.4 章的廣播風暴嗎？Ethernet 訊框沒有 TTL——IP 封包才有。
:::

## Anna 認識誰？ARP 快取

你還記得第 1.2.3 章嗎？當時 ARP 只出現在*第一次* ping 之前，因為 PC 記住了回應。這份記憶清單稱為 **ARP 快取**（也叫 *ARP 表*）。請求稱為 **ARP-Request**，回應稱為 **ARP-Reply**（或 *ARP-Response*）。

切換到 :fa-play: **執行**模式，在 **Anna** 上開啟 :fa-terminal: **終端機**，並顯示她的 ARP 快取：

```
$ arp
```

:::quiz mc
Anna 的 ARP 快取中有什麼？
- [x] 只有路由器的 IP 位址（`192.168.0.1`）及其 MAC 位址
- [ ] Clara 的 IP 位址及 Clara 的 MAC 位址
- [ ] 路由器和 Clara 的位址
:::

:::evaluate
檢查答案
:::

Anna 從來不需要 Clara 的 MAC 位址：凡是要送往 Firma B 的東西，她都傳給路由器。只有路由器知道 Clara 的 MAC 位址——它在自己這一側自行透過 ARP 查詢到了。

:::tip 重點整理
裝置會在 **ARP 快取**中記住哪個 MAC 位址對應哪個 IP 位址——這樣就不必在每個封包之前都傳送 ARP-Request。可以用指令 `arp` 來顯示。PC 只認識**自己**網路中的 MAC 位址：對於其他網路中的所有目的地，它都使用路由器的 MAC 位址。
:::

:::note
在真實的網路中，ARP 快取中的項目會在一段時間後被刪除，並在需要時重新查詢——例如某個裝置在這段期間換了網路卡。在 BeaverTracer 中，只要模擬還在運行，這些項目就會一直保留。
:::
