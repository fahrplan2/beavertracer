# TCP 還是 UDP?

| | TCP | UDP |
|---|---|---|
| 連線 | 以三向交握建立連線,有序地結束連線 | 無——每個資料報都各自獨立 |
| 確認 | 有(`ACK`) | 無 |
| 遺失的資料 | 會重新傳送 | 就此遺失 |
| 順序 | 會被還原 | 不保證 |
| 標頭 | 至少 20 位元組 | 8 位元組 |
| 速度 | 稍慢,封包較多 | 快,負擔小 |

什麼時候少即是多?

- **即時性:** 在視訊通話、網路電話或線上遊戲中,每一毫秒都很重要。一段遺失的聲音若在一秒後才補送過來,對任何人都已經沒有用處——寧可出現一點短暫的雜音,也不要延遲。
- **簡短的請求:** 一個 **DNS** 查詢(「`www.beispiel.de` 的 IP 位址是什麼?」)只需要一個資料報,回應也是一個資料報。如果還要先做連線建立,負擔就會變成三倍。如果沒有收到回應,程式只要再問一次即可。

反之,凡是每個位元組都必須送達的場合——網頁、電子郵件、下載——TCP 才是正確的選擇。

:::tip 重點整理
**TCP** 可靠,但負擔較大——適用於所有必須**完整**送達的內容(網頁、電子郵件、檔案)。**UDP** 快速而精簡,但沒有任何保證——適用於**即時**應用(電話、視訊、遊戲)以及像 DNS 這樣的**簡短請求**。
:::
