# 誰會收到哪個封包？

:::sim
url=/sims/lesson-3.1.2.btsim
:::

現在 Anna、Ben 和 Clara 都連接在交換器上（連接埠 1、2 和 3）。當 Anna 傳送一個封包給 Ben 時：只有 Ben 會收到，還是 Clara 也會收到？

先想一想你的猜測，然後再實際試試看。

## 實驗

1. 切換到 :fa-play: **執行**模式，在 **Anna** 上開啟 :fa-terminal: **終端機**，然後 ping Ben：
   ```
   $ ping 192.168.0.11
   ```
2. 切換到 :fa-magnifying-glass: **追蹤**模式，用 **+** 為 **Clara** 的連接埠 `eth0` 開啟一個 Trace。
3. 用 **+** 為 **Ben** 的連接埠 `eth0` 開啟第二個 Trace。你可以在上方於這兩個 Trace 之間來回切換。

:::quiz short

= 一
= 一個
:::

:::quiz mc

- [ ] 來自 Anna 的 ping（Echo Request）

:::

## 背後的原理

ARP 請求的目的地是**廣播**，也就是發送給*所有*裝置。因此交換器把它轉發到每一個連接埠，Clara 也收到了。相較之下，ping 只以 Ben 為目的地。交換器只把它們傳送到 Ben 的連接埠，Clara 完全沒有察覺。

:::tip 重點整理
**廣播**是發送給本地網路中所有裝置的，交換器會把它分送到所有連接埠。**單播**則只發送給唯一一個裝置，交換器只會把它傳送到該裝置所連接的連接埠。
:::

## 看看交換器內部

但是交換器怎麼知道 Ben 連接在哪個連接埠呢？切換回 :fa-play: **執行**模式，然後點擊**交換器**。在 **SAT** 索引標籤中，你可以看到它的位址表，有兩欄：**MAC** 和 **Port**。

:::quiz mc
位址表中有哪些裝置？
- [ ] Anna、Ben 和 Clara
- [x] 只有 Anna 和 Ben
- [ ] 只有 Ben
:::

:::quiz short

= 2
= 連接埠 2
= 連接埠2
= port 2
:::

:::quiz mc
為什麼位址表中沒有 Clara？
- [ ] 她的網路線壞了
- [x] 她還沒有傳送過任何一個封包
- [ ] 交換器最多只能儲存兩筆記錄
:::

:::evaluate
檢查答案
:::

交換器會**邊運作邊學習**：對於每一個到達的訊框，它會查看**發送端** MAC 位址，並記住該裝置連接在哪個連接埠。當 Anna 的 ARP 請求到達時，它記下了「Anna → 連接埠 1」，Ben 回應時則記下「Ben → 連接埠 2」。Clara 沒有傳送任何東西，所以它還不認識她。

:::tip 重點整理
交換器會在它的**位址表**（**SAT**，*Source Address Table*）中記住：哪個 MAC 位址的裝置可以透過哪個連接埠到達。它是從發送端位址學到這些資訊的。如果它知道某個訊框的目的地，就只把訊框傳送到那個連接埠；如果不知道（或是廣播），就傳送到所有連接埠。
:::
