# 順序與基本原則

## 先例外，再一般規則

因為**第一條符合的規則**會生效，所以順序很重要。請看這份規則清單（所有規則都適用於 A → B 方向，預設原則：全部允許）：

| 編號 | 協定 | 目的連接埠 | 動作 |
|---|---|---|---|
| 1 | TCP | 任意 | 丟棄 |
| 2 | TCP | 80 | 允許 |

:::quiz mc
一個來自網際網路、目的為 TCP 連接埠 80 的封包抵達了。會發生什麼事？
- [ ] 會被允許，因為規則 2 正好允許連接埠 80
- [x] 會被丟棄，因為規則 1 就已經符合——規則 2 永遠不會被執行到
- [ ] 防火牆會向管理員詢問
:::

:::evaluate
檢查答案
:::

一般而言：**特殊規則放上面，一般規則放下面。**涵蓋範圍很廣的規則會「遮蔽」它下面的所有規則。**命中**欄可以顯示出這類失效的規則：它們的數值會一直維持在 0。

## 黑名單還是白名單？

在 9.1.2 節中，你禁止了個別的連接埠，並允許其他所有內容。這稱為**黑名單**（「黑色清單」）。相反的是**白名單**：只**允許**必要的內容，並禁止其他所有內容——方法是在最後加上一條「全部丟棄」的規則，或使用預設原則**全部丟棄**。

| | 黑名單 | 白名單 |
|---|---|---|
| 基本原則 | 全部允許，例外禁止 | 全部禁止，例外允許 |
| 預設原則 | 允許 | 丟棄 |
| 伺服器上的新服務 | 立即可從外部連線 | 保持封鎖，直到有人開放它 |

:::quiz mc
一位老師明天在學校伺服器上安裝了一個監聽連接埠 3306 的資料庫。9.1.2 節的防火牆（黑名單）會發生什麼事？
- [x] 資料庫立即可從網際網路連線
- [ ] 資料庫會被自動封鎖
- [ ] 防火牆會通報新的服務
:::

:::evaluate
檢查答案
:::

因此好的防火牆會依照**白名單原則**（「Default Deny」）運作：所有沒有明確允許的內容都是禁止的。學校伺服器的白名單看起來會像這樣：

:::quiz table
| 編號 | 方向 | 協定 | 目的連接埠 | 動作 |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {允許} |
| 2 | A → B | TCP | {25} | 允許 |
| 3 | A → B | 任意 | 任意 | {丟棄} |
:::

:::

:::quiz mc
如果把規則 3 移到最上面，會發生什麼事？
- [ ] 什麼都不會發生，順序無關緊要
- [x] 來自網際網路的內容完全無法通過，網頁和郵件也不例外
- [ ] 只有網頁和郵件可以通過

:::tip 重點整理
因為**第一條符合的規則**會生效，所以**特殊規則應放在上面**，一般規則放在下面。比**黑名單**（除了……以外全部允許）更安全的是**白名單**（除了……以外全部禁止，*Default Deny*）：被遺忘的或新增的服務就會自動保持封鎖。
:::
