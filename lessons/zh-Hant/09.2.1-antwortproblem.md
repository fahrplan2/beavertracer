# 回應問題

:::sim
url=/sims/lesson-9.2.btsim
:::

防火牆現在依照白名單原則運作：預設政策為 **Alle verwerfen**。只有一條規則允許學校網路上網瀏覽：**B → A, TCP, Ziel-Port 80, Zulassen**。模式設為 **Stateless**。

## 實驗

1. 切換到 :fa-play: **執行**模式，在 **Lehrer-PC** 上的 :fa-globe: **瀏覽器**開啟 `http://203.0.113.80/`。
2. 在 **Firewall** 中查看 **Protokoll** 和 **Treffer**。

:::quiz mc
瀏覽器會發生什麼事？
- [ ] 出現 www.beispiel.de 的頁面
- [x] 頁面無法載入，瀏覽器一直等待，最後顯示錯誤
:::

:::quiz mc
哪些封包在防火牆的 Protokoll 中顯示為被丟棄（`DROP`）？
- [ ] Lehrer-PC 發往 80 埠的請求
- [x] 來自 `203.0.113.80`、**來源埠 80**、發往 Lehrer-PC 的回應
- [ ] 完全沒有
:::

:::quiz short
被丟棄的封包是朝哪個方向傳送的（A→B 還是 B→A）？
= A→B
= A → B
= AtoB
:::

:::evaluate
檢查答案
:::

Lehrer-PC 的請求可以送出去，但網頁伺服器回傳的 `SYN, ACK` 就已經回不來了，因為 A → B 方向沒有符合的規則，所以適用 **Alle verwerfen**。

## 天真的解決辦法

可以再加入第二條規則：**A → B, TCP, Quell-Port 80, Zulassen**，也就是「所有來自 80 埠的封包都可以進來」。這樣上網瀏覽確實就能正常運作了。

:::quiz mc
為什麼這條規則很危險？
- [ ] 因為網頁伺服器從不使用 80 埠作為來源埠
- [x] 攻擊者可以直接用來源埠 80 傳送他的封包，這樣防火牆就會讓這些封包通往學校網路中的**任何**連接埠
- [ ] 因為這樣網頁載入會變慢
:::

:::evaluate
檢查答案
:::

來源埠是由發送端自己決定的，防火牆不能依賴它。但無狀態防火牆無法得知一個封包是**對某個請求的回應**，還是來自外部的**新連線嘗試**。有狀態模式改變的正是這一點。

:::tip 重點整理
**無狀態**封包過濾器會逐一檢查每個封包。回應封包因此需要針對反方向另設規則，而這類規則（例如「來源埠 80 可以進入」）會被攻擊者利用，因為發送端可以自由選擇來源埠。
:::
