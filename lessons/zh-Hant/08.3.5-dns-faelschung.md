# 攻擊：DNS 偽造

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna 想在 **Client-PC** 上開啟她在 **Biberbank** 的網路銀行。她不知道的是：有人入侵了 **DNS-Server**，並修改了其中一筆記錄。

在工作區中，你可以看到真正的網頁伺服器 **www.biberbank.de**，以及一台**攻擊者**的電腦。攻擊者的電腦上運行著一份銀行網站的複製品。

## 第 1 部分：未加密

切換到 :fa-play: **執行**模式，在 **Client-PC** 的 :fa-globe: **瀏覽器**中開啟 `http://www.biberbank.de/`。

:::quiz mc
你看到了什麼？
- [x] Biberbank 的登入頁面，沒有任何警告
- [ ] 一則警告，說明此網站是偽造的
- [ ] 一則錯誤訊息
:::

:::evaluate
檢查答案
:::

一切看起來都很正常。但瀏覽器實際上是在和哪一台伺服器通訊？在 Client-PC 上開啟 :fa-terminal: **終端機**：

```
$ nslookup www.biberbank.de
```

:::quiz short
DNS-Server 為 `www.biberbank.de` 回傳哪個 IP 位址？
= 192.168.0.66
:::

:::quiz mc
這個位址屬於誰？（在編輯模式下點選裝置，或查看它們的 :fa-gear: **IP 設定**。）
- [ ] Biberbank 真正的網頁伺服器
- [x] 攻擊者
- [ ] DNS-Server
:::

:::evaluate
檢查答案
:::

如果 Anna 現在輸入了帳號和 PIN 碼，這些資料就會直接落入攻擊者手中。使用 **HTTP** 時，她**完全沒有機會**發現這場詐騙：網址列顯示的是正確的名稱，頁面看起來也很真實。

## 第 2 部分：使用 HTTPS

現在開啟 `https://www.biberbank.de/`。

:::quiz mc
會發生什麼事？
- [ ] 偽造的頁面出現，並顯示鎖頭圖示
- [x] 瀏覽器發出警告：該憑證是為另一個名稱簽發的
- [ ] Biberbank 真正的頁面出現
:::

:::quiz short
攻擊者的憑證是為哪個名稱簽發的（不含 `CN=`）？
= www.biber-gewinnspiel.de
:::

:::evaluate
檢查答案
:::

攻擊者甚至擁有一張由受信任 CA 簽發的**真**憑證，只不過是為他自己的網域 `www.biber-gewinnspiel.de` 簽發的。他無法從任何 CA 取得 `www.biberbank.de` 的憑證，因為這個網域不屬於他。而且沒有 Biberbank 的**私密金鑰**，他也無法使用 Biberbank 真正的憑證：在交握過程中，他必須用該金鑰對 Server Key Exchange 進行簽章。

:::quiz multi
在這個情境中，HTTPS 能防範什麼，又不能防範什麼？
- [x] HTTPS 會揭露該伺服器不是真正的伺服器
- [ ] HTTPS 可以防止 DNS-Server 被偽造
- [x] HTTPS 只有在使用者認真看待警告時才有幫助
- [ ] 使用 HTTPS 時，根本無法連到偽造的頁面
:::

:::evaluate
檢查答案
:::

## 第 3 部分：修復 DNS-Server

開啟 **DNS-Server**，並修正 `www.biberbank.de` 的記錄。正確的位址可以在網頁伺服器 **www.biberbank.de** 的 :fa-gear: **IP 設定**中找到。別忘了點選**保存**。

:::note
Client-PC 會暫時記住 DNS 的回應，這樣就不必每次存取時都重新查詢（**DNS 快取**）。記住多久，可以在 **TTL**（*Time to Live*）欄中查看，單位為秒。如果你修正之後，`nslookup` 仍然回傳舊的位址，請等待 TTL 時間過去後再試一次。
:::

:::task
title: Biberbank 恢復真實了嗎？
檢查 Client-PC 是否將 www.biberbank.de 解析為正確的位址，並且能透過 HTTPS 在沒有警告的情況下擷取該頁面。
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
在現實中，攻擊者很少直接偽造 DNS-Server 本身。更常見的做法是在公共 WLAN 中偷偷塞入他的回應、修改家用路由器的設定，或是用看起來很相似的位址（例如 `www.biberbank-login.de`）來誘騙使用者（**網路釣魚**）。面對這種名稱相似的網址，HTTPS 也無濟於事，因為攻擊者可以為它取得有效的憑證。所以：要仔細閱讀網址！
:::

:::tip 重點整理
發生 **DNS 偽造**時，DNS-Server 會為某個名稱回傳攻擊者的位址。使用 **HTTP** 時，使用者完全察覺不到。使用 **HTTPS** 時，攻擊者的憑證與所要存取的名稱不符，瀏覽器會**發出警告**，因為沒有任何 CA 會為他人的網域簽發憑證，而攻擊者也沒有真正伺服器的私密金鑰。
:::
