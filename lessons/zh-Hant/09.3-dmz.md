# DMZ

:::sim
url=/sims/lesson-9.3.btsim
:::

到目前為止，**Schulserver** 和 **Lehrer-PC** 位於同一個網路中。這很危險：Schulserver 可以從網際網路存取。如果攻擊者在網頁伺服器中發現漏洞並控制了這台電腦，他就位於**學校網路的中心**——而防火牆也無能為力，因為從 Schulserver 到 Lehrer-PC 的流量根本不會經過防火牆。

解決方法：必須能從網際網路存取的伺服器，要放在網際網路與內部網路之間的**獨立網路**中。這個網路稱為 **DMZ**（*非軍事區*，名稱來自兩條邊界之間的中立地帶）。

## 架構

在工作區中，你會看到採用**兩道防火牆**的經典模型：

```
Internet ──[ Firewall außen ]── Schulrouter ──── DMZ: Schulserver (198.51.100.10)
                                    │
                             [ Firewall innen ]
                                    │
                    LAN: Lehrer-PC (192.0.2.20), Schüler-PC (192.0.2.21)
```

- **Firewall außen** 保護所有設備不受網際網路威脅。連接埠 A 連接網際網路，連接埠 B 連接 Schulrouter。
- **Firewall innen** 保護 LAN——也包括防範來自 DMZ 的威脅。連接埠 A 連接 Schulrouter，連接埠 B 連接 LAN。

目前兩道防火牆都還允許所有流量通過。

:::quiz multi

- [x] 網際網路 → DMZ：Schulserver 的網頁（80）和郵件（25）
- [x] LAN → DMZ：例如收取郵件（110）
- [x] LAN → 網際網路：瀏覽網頁

## 任務：保護 DMZ

將**兩道**防火牆都設為 **Stateful** 和 **Alle verwerfen**，並填入適當的規則：

- **Firewall außen：** 從內部到外部（B → A）允許所有流量；從外部（A → B）只允許前往 Schulserver `198.51.100.10` 的 TCP 80 和 25。
- **Firewall innen：** 從 LAN（B → A）允許所有流量；往 LAN 的方向（A → B）不需要規則——回應封包會透過狀態表回傳。

:::note
許多防火牆有三個或更多介面（「區域」），在單一設備中實現 DMZ。原理是相同的：網際網路、DMZ 和 LAN 之間的流量必須一律經過規則檢查。採用兩道防火牆的模型有一個優點：攻擊者必須突破**兩道**關卡——通常甚至會使用不同廠商的設備，以避免同一個安全漏洞同時打開兩道防火牆。
:::

:::tip 重點整理
所有必須能從網際網路存取的伺服器都要放進 **DMZ**。DMZ 位於兩道防火牆之間（或位於一道防火牆的獨立區域中）：網際網路只能存取 DMZ 中特定的服務，LAN 可以存取 DMZ 和網際網路——但從 DMZ 和網際網路**都沒有通往 LAN 的路徑**。即使 DMZ 中的伺服器被控制，LAN 仍然受到保護。
:::
