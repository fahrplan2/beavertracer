# 自動取得位址

:::sim
url=/sims/lesson-6.4.btsim
:::

交換器上連接了一台 **DHCP 伺服器**和兩台筆記型電腦。筆記型電腦目前仍使用固定位址。

## 實驗

1. 切換到 :fa-play: **執行**模式，點選 **Laptop 1**，然後開啟 :fa-gear: **IP 設定**。
2. 將**模式**從**靜態**改為 **DHCP**，然後點選**套用**。
3. 等待幾秒鐘：各欄位會自動填入。
4. 在 :fa-magnifying-glass: **追蹤**模式中，為 **Laptop 1** 開啟一個追蹤。

:::quiz table
| 設定 | 從 DHCP 伺服器取得 |
|---|---|
| IP 位址 | {192.168.0.100} |
| 閘道 | {192.168.0.1} |
| DNS 伺服器 | {192.168.0.53} |
:::

:::quiz short
你在追蹤中找到幾個 DHCP 封包？
= 4
= 四
:::

:::quiz mc
Laptop 1 將它的第一個封包（`DHCP Discover`）傳送到哪個目的 IP 位址？
- [ ] 傳送到 DHCP 伺服器 `192.168.0.2`
- [x] 傳送到 `255.255.255.255` — 傳給所有裝置（廣播）
- [ ] 傳送到閘道 `192.168.0.1`

- [ ] `192.168.0.100` — 它的新位址

## 背後的原理：DORA

沒有位址的裝置既不知道 DHCP 伺服器在哪裡，也沒有自己的發送端位址。因此它會以**廣播**的方式向網路呼叫。整個流程有四個步驟，並依其英文單字的首字母稱為 **DORA**：

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | „這裡有 DHCP 伺服器嗎？“
DHCP-Server -> Laptop 1: DHCP Offer | „你可以使用 192.168.0.100。“
Laptop 1 -> DHCP-Server: DHCP Request | „我要使用 192.168.0.100。“
DHCP-Server -> Laptop 1: DHCP ACK | „已確認 — 有效期限 3600 秒。“
:::

這個位址只是**租用**的（*Lease*）：**租約時間**到期後，裝置必須續租，否則伺服器可以將該位址重新分配出去。目前有哪些位址被租出，你可以在 **DHCP 伺服器**的**Leases** 索引標籤中看到。

:::tip 試試看
也把 **Laptop 2** 設為 DHCP。它會得到哪個位址？然後查看 DHCP 伺服器的 **Leases**。
:::

:::tip 重點整理
**DHCP** 會自動分配 IP 位址、子網路遮罩、閘道和 DNS 伺服器。其流程稱為 **DORA**：**D**iscover（用戶端以廣播搜尋）、**O**ffer（伺服器提供）、**R**equest（用戶端接受）、**A**CK（伺服器確認）。位址在**租約時間**內是租用的。DHCP 使用 **UDP**，連接埠為 67（伺服器）和 68（用戶端）。
:::

:::quiz match
Discover -> 用戶端以廣播搜尋 DHCP 伺服器
Offer -> 伺服器提供一個位址
Request -> 用戶端請求所提供的位址
ACK -> 伺服器確認分配
:::
