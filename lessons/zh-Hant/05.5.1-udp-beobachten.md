# 觀察 UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

這次在 **Server** 上的連接埠 `5000` 執行了一個 **UDP 回應伺服器**。這裡的網路線同樣被動了手腳：從 Client-PC 傳往 Server 的**第二個資料包**會遺失。

## 實驗

1. 切換到 :fa-play: **執行**模式，在 **Client-PC** 上開啟 :fa-terminal: **終端機**。
2. 用 `nc` 向伺服器建立一個 UDP「連線」（`-u` 代表 UDP）：
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. 依序輸入 `eins`、`zwei` 和 `drei`，每次都按下 **Enter**。每一行傳回來的內容，都是伺服器的回應。
4. 等待幾秒鐘，然後在 :fa-magnifying-glass: **追蹤**模式下，為 **Client-PC** 開啟一個追蹤。

:::quiz mc
哪些回應會傳回來？
- [ ] 三個都會，`zwei` 稍晚一點
- [x] 只有 `eins` 和 `drei` — `zwei` 不見了，而且不會被補送
- [ ] 一個也沒有
:::

:::quiz multi
你在 TCP 中認識的哪些封包，在 UDP 中完全不會出現？
- [x] 連線建立（`SYN`）
- [x] 確認（`ACK`）
- [x] 連線終止（`FIN`）
- [ ] 帶有連接埠號碼的封包
:::

:::evaluate
檢查答案
:::

點擊其中一個 UDP 封包，並展開 **User Datagram Protocol**。與 TCP 標頭相比，UDP 標頭非常小：**Source Port**、**Destination Port**、**Length**（長度）和 **Checksum**（檢查碼）——加起來只有 8 位元組。TCP 標頭至少有 20 位元組，包含序號、確認號碼、旗標和視窗大小。

:::quiz mc
UDP 仍然負責 5.1 節中的哪項任務？
- [x] 多工 — 透過連接埠
- [ ] 連線建立
- [ ] 可靠傳輸
:::

:::evaluate
檢查答案
:::

:::tip 重點整理
**UDP** 是**無連線**的：沒有建立、沒有確認、沒有重傳、沒有順序。它只提供**連接埠**（多工）和**檢查碼**。相對地，它快速又精簡——UDP 標頭只有 8 位元組。如果資料包遺失，就必須由程式自己處理——或者程式根本不在意。
:::
