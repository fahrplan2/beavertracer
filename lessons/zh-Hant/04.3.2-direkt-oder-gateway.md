# 直接傳送還是透過閘道？

:::sim
url=/sims/lesson-4.3.2.btsim
:::

PC 在傳送封包之前，會先判斷：目標是否位於**自己的網路**內？為此，它會借助自己的子網路遮罩，將自己位址的網路部分與目標位址的網路部分進行比較。

## 流程

1. **目標 IP 是否位於自己的網路內？**
   - **是：** PC 將封包**直接**傳送給目標。它需要目標的 MAC 位址。
   - **否：** PC 將封包傳送給**閘道**。它需要路由器的 MAC 位址。如果沒有設定閘道，它就完全無法傳送這個封包。
2. **它是否已經知道所需的 MAC 位址**（是否存在於它的 ARP 快取中）？如果不知道，它會透過 **ARP** 來詢問。
3. 它將訊框傳送到這個 MAC 位址。在這兩種情況下，封包中的**目標 IP 位址**都是真正的目標。

| | 直接傳送（自己的網路） | 透過閘道（其他網路） |
|---|---|---|
| ARP 詢問 … | 目標的 MAC | 路由器的 MAC |
| 訊框中的目標 MAC | 目標 | 路由器 |
| 封包中的目標 IP | 目標 | 目標 |

## 疑難排解：無法連到 Firma B

從昨天開始，Anna 就無法連到 Firma B 的 PC 了。網路*應該*這樣設定：

| 裝置 | IP 位址 | 閘道 |
|---|---|---|
| Anna | `192.168.0.10/24` | `192.168.0.1` |
| Ben | `192.168.0.11/24` | `192.168.0.1` |
| Clara | `172.16.0.10/24` | `172.16.0.1` |
| David | `172.16.0.11/24` | `172.16.0.1` |

找出錯誤並加以修正。

<details>
<summary>提示 1：Anna 的 ping 到底有沒有送達？</summary>

從 Anna 對 Clara 執行 ping，並為 **Clara** 開啟追蹤。ping 有送達嗎？Clara 有回應嗎？
</details>

<details>
<summary>提示 2：David 在做什麼？</summary>

</details>

:::tip 重點整理
PC 不僅在傳送時需要正確的閘道，在**回應**時也需要：沒有閘道的話，ping 雖然能送達，但回應卻找不到回去的路。如果設定了**錯誤的閘道位址**，PC 就會透過 ARP 徒勞地詢問一個根本不存在的路由器。
:::
