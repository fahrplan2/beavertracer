和 HTTP 一樣，SMTP 也是**文字協定**。來看看有哪些內容是以明文在線路上傳輸的。

## 實驗

1. 在 :fa-play: **執行**模式下，像上一頁那樣，從 **Anna** 寄一封郵件給 `ben@biber-mail.de`。
2. 在 :fa-magnifying-glass: **追蹤**模式下，為 **Anna** 開啟一個追蹤。在 **Info** 欄中可以看到 SMTP 對話：以 `C:` 開頭的行由用戶端傳送，以 `S:` 開頭的行由伺服器傳送。

:::quiz short
`MAIL FROM:` 後面是哪個位址？
= anna@beaver-schule.de
= <anna@beaver-schule.de>
:::

:::quiz short
那 `RCPT TO:` 後面是哪個位址？
= ben@biber-mail.de
= <ben@biber-mail.de>
:::

:::quiz mc
伺服器接受一個指令時，會傳送哪個數字代碼？
- [x] `250`
- [ ] `200`
- [ ] `404`
:::

檢查答案

## 那密碼呢？

在 `MAIL FROM` 之前，Anna 的程式會用 `AUTH PLAIN` 和一串像 `AGFubmEAZ2VoZWlt` 的字元進行登入。這看起來像是加密過的，但其實不是：它只是 **Base64**，一種任何人都能立刻還原的編碼——裡面包含 `anna` 和她的密碼 `geheim`。

現在請在 **Ben** 那裡收信（**擷取**），並為 **Ben** 開啟一個追蹤。透過 IMAP 收信時，內容更加一目了然：

:::quiz short
Ben 的電子郵件程式以明文傳送哪個密碼給伺服器？（請看包含 `LOGIN` 的那一行。）
= biber123
:::

:::evaluate
檢查答案
:::

:::warning
沒有加密的話，任何擷取資料流量的人都能讀取**內容、發送端、接收端和密碼**。因此現在都會使用加密的版本（例如搭配 STARTTLS 的 SMTP、使用連接埠 993 的 IMAPS）。其運作方式你會在第 8 章學到。
:::

:::tip 重點整理
**SMTP**、**POP3** 和 **IMAP** 都是文字協定：像 `MAIL FROM`、`RCPT TO`、`DATA`（SMTP）或 `LOGIN`（IMAP）這樣的指令以及回應都是可讀的。沒有加密時，**密碼**也會以明文（或僅經 Base64 編碼）在線路上傳輸。
:::
