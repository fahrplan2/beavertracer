# 執行 Ping 並在追蹤器中查看

:::sim
url=/sims/lesson-1.2.3.btsim
:::

兩台 PC 現在的位址分別是 `192.168.0.10` 和 `192.168.0.11`。該進行第一次測試了：使用 **Ping**，一台 PC 會向另一台 PC 傳送一個小小的請求，並等待回應。

## 執行 Ping

切換到 :fa-play: **執行**模式。在 **Computer 1** 上開啟 :fa-terminal: **終端機**，然後輸入：

```
$ ping 192.168.0.11
```

如果另一台 PC 有回應，你會看到每個已傳送的封包各有一行，並附有回應時間——這就是你第一次成功的 Ping！

:::tip 重點整理
**Ping** 用來檢查另一台裝置是否可以連線到：它會傳送一個請求，並測量回應需要多長時間。
:::

## 在追蹤器中查看

現在切換到 :fa-magnifying-glass: **追蹤**模式。這裡目前什麼都看不到——請點擊左上角 **Traces:** 旁邊的 **+**，選擇 **Computer 1**，再選擇它的連接埠 `eth0`。

現在你會看到一份清單，列出所有經過這個連接埠的封包——也包括剛才的 Ping。點擊其中一個封包：在下方你會看到它的詳細結構，一層一層地呈現。

:::tip 重點整理
資料在網路中不是一次整批傳送，而是分成一個個小單位，也就是**封包**。每個封包都帶有發送端、接收端以及一部分資料。
:::

:::tip
一次 Ping 一定包含一個請求（Echo Request）和一個回應（Echo Reply）——你能在 **Info** 欄中找到這兩個方向嗎？
:::

## 第一次 Ping 之前是誰在詢問？

在清單的最上方，第一次 Ping 之前，有兩個使用 **ARP** 協定的封包。請閱讀它們的 **Info** 欄——內容大致如下：

```
Who has 192.168.0.11? Tell 192.168.0.10
192.168.0.11 is at aa:fd:9f:a5:d2:89
```

Computer 1 雖然知道另一台 PC 的 IP 位址，但還不知道它的**硬體位址**（即 *MAC 位址*——每張網路卡都有自己專屬的位址）。沒有這個位址，它就無法傳送任何東西。所以它先向網路中喊話：*「誰擁有 192.168.0.11？告訴 192.168.0.10！」* 被找的那台 PC 就會用自己的硬體位址回應。這正是 **ARP** 的任務。

之後 Computer 1 會記住這個回應——所以 ARP 只會出現在第一次 Ping 之前，而不是每次 Ping 之前都出現。

:::tip 重點整理
**ARP** 會為已知的 IP 位址找出對應的硬體位址（**MAC 位址**）：PC 會詢問網路中的所有裝置，只有被找的那台裝置會回應。
:::

:::
