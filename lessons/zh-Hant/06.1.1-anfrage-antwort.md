由此可見,一個網頁通常由許多檔案組成:文字、樣式表、圖片。瀏覽器會為每一個檔案各自傳送一個請求。

## 請求長什麼樣子

在追蹤中點選封包 `GET / HTTP/1.1`,並展開 **Hypertext Transfer Protocol**。HTTP 請求是純文字:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

伺服器的回應結構也是一樣的——包含一行狀態列、數個 Header、一個空行,最後才是檔案本身:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP-Anfrage
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP-Anfrage
Server -> Client-PC: 200 OK | style.css
:::

## 方法與狀態碼

**方法**說明用戶端想要做什麼:

| 方法 | 意義 |
|---|---|
| **GET** | 擷取一個檔案 |
| **POST** | 將資料傳送給伺服器,例如填寫完成的表單 |
| **HEAD** | 只擷取 Header,不含檔案 |

**狀態碼**說明處理結果如何。第一位數字表示回應的類型:

| 代碼 | 文字 | 意義 |
|---|---|---|
| **200** | OK | 一切正常 |
| **301** | Moved Permanently | 頁面已永久搬移 |
| **404** | Not Found | 該檔案不存在 |
| **405** | Method Not Allowed | 此處不允許使用這個方法 |
| **500** | Internal Server Error | 伺服器發生錯誤 |

`2xx` 表示成功,`3xx` 表示重新導向,`4xx` 表示用戶端的錯誤(錯誤的請求),`5xx` 表示伺服器的錯誤。

:::tip 重點整理
**HTTP** 依照**請求—回應原則**運作:用戶端傳送一個**請求**(方法如 `GET`、路徑、Header),伺服器則以**狀態碼**(例如 `200 OK`、`404 Not Found`)、Header 和檔案作為回應。網頁中的每個檔案都有各自的請求。
:::

:::quiz match
200 -> 一切正常
301 -> 頁面已永久搬移
404 -> 所請求的檔案不存在
500 -> 伺服器發生了錯誤
:::
