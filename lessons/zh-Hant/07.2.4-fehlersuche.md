# 疑難排解：昨天還好好的

:::sim
url=/sims/lesson-7.2.4.btsim
:::

昨天從外部還可以連到家用網路的網頁伺服器——連接埠轉送規則 `TCP 80 → 192.168.178.10:80` 已經設定好了。今天清晨停電之後，Clara 就打不開這個網頁了。找出錯誤，並徹底解決它。

<details>
<summary>提示 1：這條規則指向哪裡？</summary>

請比較家用路由器的**連接埠轉發**中的 LAN IP，與 **Heim-Webserver** 目前實際使用的位址（:fa-gear: **IP 設定**）。
</details>

<details>
<summary>提示 2：為什麼它的位址不一樣了？</summary>

Heim-Webserver 是否設定為 **DHCP**？那麼每次重新啟動後，它都會從家用路由器的範圍（在**DHCP** 索引標籤中）取得任意一個空閒的位址。你要怎麼做，才能讓它永遠使用同一個位址？
</details>

:::task
title: Heim-Webserver 又能連線了嗎？
檢查 Heim-Webserver 是否擁有固定位址，以及 Clara 是否能透過連接埠轉送連到它。為此，模擬必須在執行模式下運作。
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## 發生了什麼事？

:::quiz multi
下列哪些說法是正確的？
- [x] Heim-Webserver 是透過 DHCP 取得位址，重新啟動後得到了不同的位址
- [x] 因此連接埠轉送指向了一個已經沒有任何伺服器運作的位址
- [x] 在 DHCP 範圍之外設定固定位址，可以徹底解決這個問題
- [ ] 網際網路服務供應商封鎖了 WAN 位址
:::

:::evaluate
檢查答案
:::

:::tip 重點整理
連接埠轉送所指向的裝置（伺服器、印表機、攝影機）需要**固定位址**：可以是手動靜態設定且位於 **DHCP 範圍之外**，或是在路由器的 DHCP 伺服器中設定固定分配。否則它們在重新啟動後可能會取得不同的位址——規則就會落空。
:::
