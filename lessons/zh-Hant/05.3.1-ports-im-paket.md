## 實驗

1. 切換到 :fa-play: **執行**模式，點選 **Client-PC** 並開啟 :fa-globe: **瀏覽器**。開啟 `http://192.168.0.20/`。

3. 切換到 :fa-magnifying-glass: **追蹤**模式，為 **Client-PC** 開啟一個 Trace，並點選含有 `[SYN]` 的封包。展開 **Transmission Control Protocol**。

## 兩種連接埠

**目的連接埠——服務：** 伺服器程式會在固定的連接埠等待連線——這稱為在該處**監聽**（lauschen）。對於常見的服務，其編號在全球範圍內都是固定的，稱為 **Well-known Ports**（0 到 1023）。因此瀏覽器不需要詢問就知道：網頁伺服器在連接埠 80 監聽。

**來源連接埠——發送端：** 用戶端的連接埠是由作業系統為每個新連線自行從較高的範圍中選出的（在 BeaverTracer 中從 49152 開始）。用戶端藉由它辨識回應屬於自己的哪一個連線。

因此，一個連線由四項資訊唯一決定：**兩端的 IP 位址和連接埠**。IP 位址與連接埠的組合稱為 **Socket**，例如 `192.168.0.20:80`。

## 看一下伺服器

切換回 :fa-play: **執行**模式，在 **Server** 上開啟 :fa-terminal: **終端機**並輸入：

```
$ ss
```

`ss` 會顯示這台電腦的所有 Socket。含有 `LISTEN` 的行是在某個連接埠監聽的程式。含有 `ESTABLISHED` 的行是現有的連線——包含自己的 Socket（*Local Address:Port*）和對方的 Socket（*Peer Address:Port*）。

:::note
瀏覽器的連線已經結束了——網頁載入完成後，連線已用 `FIN` 關閉。`ss` 仍會短暫地將它顯示為 `TIME-WAIT`：伺服器會等待一段時間，看這個連線是否還有延遲的封包送達。相對地，TCP 用戶端的連線仍然開啟，因為你還沒有點選**中斷連線**。
:::

## 最重要的 Well-known Ports

| 連接埠 | 協定 | 服務 |
|---|---|---|
| 22 | SSH | 安全的遠端維護（加密的命令列） |
| 25 | SMTP | 傳送電子郵件 |
| 53 | DNS | 將名稱轉換為 IP 位址（通常透過 UDP） |
| 80 | HTTP | 網頁 |
| 110 | POP3 | 收取電子郵件 |
| 143 | IMAP | 在伺服器上管理電子郵件 |
| 443 | HTTPS | 加密的網頁 |

:::tip 重點整理
**連接埠**（0 到 65535）用來區分一台電腦上的各個連線。伺服器服務在固定的 **Well-known Ports** 上**監聽**（例如 HTTP 80、HTTPS 443），用戶端則為每個連線取得一個空閒的高編號**來源連接埠**。一個連線由**雙方的 IP 位址和連接埠**唯一決定。
:::
