# HTTPS

:::osi 5
:::

**HTTPS**（*HTTP Secure*）就是一般的 HTTP——只不過它不是直接在 TCP 上運行，而是中間多了一層加密層：**TLS**（*Transport Layer Security*）。TLS 的前身叫做 **SSL**，所以人們常常還是說「SSL 憑證」。

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP 對此毫無察覺：它照常傳送請求，由 TLS 加密，再由 TCP 傳輸。在 OSI 模型中，TLS 位於傳輸層與應用層之間，也就是第 4/5 層——它建立在 TCP 之上，並管理一個受保護的工作階段。

| | HTTP | HTTPS |
|---|---|---|
| 連接埠 | 80 | **443** |
| 位址 | `http://…` | `https://…` |
| 在 Tracer 中內容可讀取？ | 是 | 否 |
| 瀏覽器顯示 | 「不安全」 | 鎖頭 |

TLS 在連線建立時，會完成你在本章學到的所有事情：

- 伺服器以自己的**憑證**表明身分（**真實性**）。
- 雙方用 **Diffie-Hellman** 協商出一個**工作階段金鑰**——伺服器會對自己的部分進行**簽章**。
- 之後所有資料都以 **AES** 加密（**機密性**），並受到保護以防遭竄改（**完整性**）。

這個原理不僅限於網頁：電子郵件（第 8.4 節）和許多其他協定也以相同的方式透過 TLS 運行。
