# ISO/OSI 參考模型

ISO/OSI 模型將兩台裝置之間的通訊分成七層。每一層都有明確劃分的任務，並且只使用緊鄰其下一層所提供的服務：

<thead>
<tr><th>層</th><th>名稱</th><th>任務</th><th>範例協定</th></tr>
</thead>
<tbody>
<tr class="osi-l7"><td>7</td><td>應用層</td><td>應用程式的介面</td><td>HTTP, DNS, SMTP</td></tr>
<tr class="osi-l6"><td>6</td><td>表示層</td><td>資料格式、加密</td><td>JPEG, ASCII, MIME</td></tr>
<tr class="osi-l5"><td>5</td><td>會話層</td><td>會話管理</td><td>RPC, NetBIOS</td></tr>
<tr class="osi-l4"><td>4</td><td>傳輸層</td><td>端對端傳輸</td><td>TCP, UDP</td></tr>

從上一頁的實驗中，你已經認識了其中四層：Ethernet（第 2 層）、IPv4（第 3 層）、TCP（第 4 層）和 HTTP（第 7 層）。追蹤器在協定樹中顯示給你的，正是這些編號和顏色。

:::tip 記憶口訣
從第 7 層往下：**應**用層、**表**示層、**會**話層、**傳**輸層、**網**路層、**資**料連結層、**實**體層——取每層名稱的第一個字，就是「應表會傳網資實」。
:::

:::note 邊界情況
並非每個協定都能恰好歸入某一層。因此，追蹤器對這些協定會顯示多個層：

- **ARP** — 第 2/3 層：它沒有 IP 標頭，但會把 IP 位址（第 3 層）與硬體位址（第 2 層）對應起來。
- **TLS** — 第 4/5 層：它直接建立在 TCP 之上，並管理一個受保護的會話。
- **HTTPS**（TLS 內的 HTTP）— 第 5–7 層：即 TCP/IP 模型中典型的應用層，你會在下一頁認識它。
:::

:::note
第 1 層描述的是在電纜上或透過無線電進行的實際訊號傳輸。BeaverTracer 不會模擬這一層——電纜一律視為無錯誤地連接，既沒有訊號問題，也沒有碰撞。因此在追蹤器中，觀察實際上是從第 2 層開始的。
:::
