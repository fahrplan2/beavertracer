# 讀寫 IPv6 位址

## 十六進位系統

128 個 0 和 1 沒有人讀得懂，就算改寫成 16 組十進位數字，也好不到哪裡去。因此 IPv6 位址是用**十六進位系統**（簡稱 *Hex*）來書寫的。它有 **16 個數字**：0 到 9，再加上 a 到 f，分別代表 10 到 15 這幾個值。

最大的優點是：一個十六進位數字剛好代表 **4 位元**。

| 十進位 | 十六進位 | 二進位 | | 十進位 | 十六進位 | 二進位 |
|---|---|---|---|---|---|---|
| 0 | 0 | 0000 | | 8 | 8 | 1000 |
| 1 | 1 | 0001 | | 9 | 9 | 1001 |
| 2 | 2 | 0010 | | 10 | a | 1010 |
| 3 | 3 | 0011 | | 11 | b | 1011 |
| 4 | 4 | 0100 | | 12 | c | 1100 |
| 5 | 5 | 0101 | | 13 | d | 1101 |
| 6 | 6 | 0110 | | 14 | e | 1110 |
| 7 | 7 | 0111 | | 15 | f | 1111 |

也就是說，一個位元組（8 位元）剛好是兩個十六進位數字：`11111111` = `ff` = 255。其實你已經看過了：像 `aa:28:39:e2:41:82` 這樣的 MAC 位址同樣是用十六進位書寫的。

## IPv6 位址的結構

一個 IPv6 位址由**八個區塊**組成，每個區塊 **16 位元**，也就是四個十六進位數字，區塊之間以冒號分隔：

```
2001:0db8:0000:0000:0000:0000:0000:0001
```

和 IPv4 一樣，IPv6 也有網路部分和主機部分。在 IPv6 中，網路部分稱為**前綴**，主機部分稱為**介面 ID**。前綴幾乎總是 **64 位元**長（`/64`），也就是前四個區塊：

[[n|2001:0db8:0001:0000]]:[[h|a828:39ff:fee2:4182]]
[[n|前綴 (64 位元)]]      [[h|介面 ID (64 位元)]]
</pre>

## 簡寫方式

由於 IPv6 位址很長，所以可以縮短書寫。有兩條規則：

1. **區塊中開頭的 0 可以省略：** `0db8` → `db8`，`0001` → `1`，`0000` → `0`。
2. **連續的全 0 區塊**可以用 `::` 取代，但每個位址**只能使用一次**。如果有好幾段連續的全 0 區塊，就縮短最長的那一段。

範例：

```
2001:0db8:0000:0000:0000:0000:0000:0001   vollständig
2001:db8:0:0:0:0:0:1                      Regel 1
2001:db8::1                               Regel 2
```

為什麼 `::` 只能用一次？以 `2001::1::5` 為例，沒有人能判斷各處分別省略了多少個全 0 區塊。只用一個 `::` 就不會有歧義：省略的區塊數剛好讓總數補回八個。

:::tip 重點整理
一個 **IPv6 位址**有 **128 位元**，以 **8 個區塊**書寫，每個區塊 **4 個十六進位數字**。前 64 位元通常是**前綴**（網路部分），後 64 位元是**介面 ID**（主機部分）。縮短方式：省略開頭的 0，並用 `::` 取代**一段**連續的全 0 區塊。
:::
