# 傳輸層必須做到什麼？

:::sim
url=/sims/lesson-5.1.btsim
:::

**Server** 上同時執行兩個服務：一個**網頁伺服器**和一個小型**回顯服務**，它會立刻把收到的每則訊息傳回去。透過兩個實驗，你會發現單靠 IP 做不到哪些事。

## 實驗 1：兩個程式同時執行

1. 切換到 :fa-play: **執行**模式，點選 **Client-PC**。
2. 開啟 :fa-globe: **瀏覽器**，並連到 `http://192.168.0.20/`。
3. 點選視窗上方的**返回**，然後開啟**簡單 TCP 用戶端**。在 **Host** 填入 `192.168.0.20`，在 **Port** 填入 `5000`，然後點選**連線**。
4. 切換到 :fa-magnifying-glass: **追蹤**模式，並用 **+** 為 **Client-PC** 的連接埠 `eth0` 開啟一個追蹤。

點選一個來自瀏覽器的封包（例如 `GET /`）和一個來自 TCP 用戶端的封包，並分別展開 **Internet Protocol Version 4**。

:::quiz mc
瀏覽器和 TCP 用戶端的封包帶有哪些 IP 位址？
- [x] 兩者相同：從 `192.168.0.10` 到 `192.168.0.20`
- [ ] 瀏覽器使用的目的 IP 位址與 TCP 用戶端不同
- [ ] TCP 用戶端的封包沒有 IP 位址
:::

:::quiz mc
那麼，光憑目的 IP 位址，伺服器就能知道某個封包屬於網頁伺服器還是回顯服務嗎？
- [ ] 可以
- [x] 不行 — 兩個封包的目的 IP 位址相同
:::

一定有其他東西能區分這兩條連線。請查看帶有 `[SYN]` 的封包的 **Info** 欄 — 那分別是每條連線的第一個封包：

:::quiz short
**瀏覽器**的箭頭 `→` 後面是哪個數字？
= 80
:::

:::quiz short
那 **TCP 用戶端**呢？
= 5000
:::

:::evaluate
檢查答案
:::

關於這些數字 — 也就是**連接埠**（Port） — 你會在 5.3 節學到更多。目前只需知道：要靠傳輸層，多個程式才能同時透過*同一個* IP 位址通訊，而且每個封包都會送到正確的程式。這稱為**多工**。

## 實驗 2：當封包遺失時

1. 切換到 :fa-play: **執行**模式，點選 Client-PC 與 Server 之間的**網路線**。
2. 在**連線**視窗中，將**已設定的封包遺失**設為 `25%`。
3. 在 **Client-PC** 上開啟 :fa-terminal: **終端機**，傳送六個 ping：
   ```
   $ ping -c 6 192.168.0.20
   ```
   這大約需要半分鐘 — 請等到統計資料出現。

:::quiz mc
會發生什麼事？
- [ ] 六個 ping 全部都有回應
- [x] 有些 ping 沒有得到回應 — 而且沒有人會再重傳
- [ ] 遺失的 ping 會自動重複傳送，直到送達為止
:::

:::evaluate
檢查答案
:::

對 ping 來說這不成問題 — 它本來就是要顯示是否有東西遺失。但對於網頁、電子郵件或下載來說，缺少一部分就會造成嚴重後果：檔案會損壞。

## 傳輸層的四項任務

| 任務 | 意義 |
|---|---|
| **多工** | 多個程式和連線共用一個 IP 位址；每個封包都會送到正確的程式。 |
| **連線建立** | 在資料開始傳送之前，雙方先約定彼此要進行通訊。 |
| **可靠傳輸** | 接收端確認哪些資料已到達。缺少的部分會重新傳送，並恢復正確的順序。 |
| **連線終止** | 最後，雙方有秩序地結束連線。 |

:::tip 重點整理
**傳輸層**（第 4 層）確保資料送達正確的**程式**（**多工**）。**TCP** 協定則進一步確保資料**完整**且依**正確順序**送達 — 透過連線建立、確認、重傳和連線終止。
:::
