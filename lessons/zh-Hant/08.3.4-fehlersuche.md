# 疑難排解：憑證警告

學校網路中還有三台網頁伺服器：**Mensa**、**Bibliothek** 和 **Sport-AG**。這三台都使用 HTTPS——但 **Client-PC** 的瀏覽器在每一台上都會顯示警告。Client-PC 信任 **Schul-CA**。

## 調查

切換到 :fa-play: **執行**模式，在 **Client-PC** 上依序開啟：

- `https://mensa.beaver-schule.de/`
- `https://bibliothek.beaver-schule.de/`
- `https://sport.beaver-schule.de/`

分別閱讀警告內容以及憑證的資訊（主體、簽發者、有效期限）。

:::quiz match

sport.beaver-schule.de -> 憑證是為另一個名稱簽發的
:::

## 修復 Mensa

Mensa 是最快修復的：它的憑證曾經由 Schul-CA 簽發——只是已經過期。為了簡化，Schul-CA 在這裡直接放在 Mensa 伺服器上。

<details>
<summary>提示 1：簽發新憑證</summary>

在 **mensa.beaver-schule.de** 上開啟 :fa-shield-halved: **Zertifikatverwaltung**。在 **Signieren** 索引標籤中，你可以讓 Schul-CA 對現有的憑證**重新簽署**——這樣它會獲得新的有效期限。請以新的檔名保存，例如 `mensa-neu.cert.json`。
</details>

<details>
<summary>提示 2：使用新憑證</summary>

在 Mensa 的 **HTTP 伺服器**中：**Stoppen**，在 **HTTPS** 索引標籤中選擇新的憑證（可由檔名辨識），**Verwenden**，**開始**。
</details>

## 那另外兩台呢？

:::quiz mc
要如何正確解決 **Bibliothek** 的問題？
- [ ] 每位學生都點選「仍要繼續」
- [x] Bibliothek 取得由 Schul-CA 簽發、對應 `bibliothek.beaver-schule.de` 的憑證
- [ ] 在所有裝置上把 Bibliothek 的自簽憑證登錄為受信任的 CA
:::

:::quiz mc
那 **Sport-AG** 呢？
- [ ] 把 Sport-AG 重新命名為 `www.beaver-schule.de`
- [x] Sport-AG 取得專屬於 `sport.beaver-schule.de` 的憑證
- [ ] 把伺服器的時鐘調回去
:::

:::evaluate
檢查答案
:::

:::warning
遇到憑證警告時，**「仍要繼續」**幾乎從來都不是好主意。因為如果攻擊者把他自己的憑證塞給你，看起來也會一模一樣。`curl -k` 也是同樣的道理：它會關閉憑證檢查——測試時很方便，但在實際運作環境中很危險。
:::

:::tip 重點整理
當憑證**已過期**、瀏覽器**不認識**簽發的 **CA**（例如**自簽**憑證），或憑證中的**名稱**與所開啟的位址不相符時，瀏覽器就會發出警告。解決方法永遠是取得由受信任 CA 簽發的、相符且有效的憑證——而不是把警告關掉不理。
:::
