# 混合式加密

我們來整理一下:

| | 對稱式(例如 AES) | 非對稱式(例如 RSA) |
|---|---|---|
| 金鑰 | 一把共用的秘密金鑰 | 金鑰對:公開金鑰 + 私密金鑰 |
| 速度 | 非常快 | 慢 |
| 金鑰交換 | 問題:金鑰要如何送到接收端? | 沒有問題:公開金鑰可以公開傳送 |

也就是說,每種方法都有另一種方法所欠缺的優點。解決辦法:把兩者結合起來,這稱為**混合式加密**。

1. 連線一開始,雙方借助**非對稱式**方法,約定出一把共用的秘密金鑰,也就是**會話金鑰**。這需要花一點時間,但只會進行**一次**。
2. 之後所有資料都用會話金鑰進行**對稱式**加密 — 速度很快。
3. 連線結束時,會話金鑰就會被丟棄。下一次連線會取得新的金鑰。

**HTTPS**、加密的電子郵件連線、使用 WPA3 的 **WLAN**、**SSH** 以及 **VPN** 都是這樣運作的。

## 透過混色得到共同的秘密

約定會話金鑰有一種很優雅的方法,就是**迪菲-赫爾曼金鑰交換**(Diffie-Hellman,1976 年)。我們可以用顏色來想像它。訣竅在於:把顏色混合很容易,但要把混合後的顏色再分解回原本的成分,實際上卻幾乎不可能。

1. Anna 和 Ben **公開地**約定一個共同的基本色,例如**黃色**。任何人都可以知道。
2. 每個人偷偷選一個**秘密顏色**:Anna 選**紅色**,Ben 選**藍色**。
3. 每個人把自己的秘密顏色混入基本色,並把結果**公開地**傳給對方:Anna 傳送**黃 + 紅**(橘色),Ben 傳送**黃 + 藍**(綠色)。
4. 現在每個人再把自己的秘密顏色混入對方傳來的混合色:
    - Anna:綠 + 紅 = **黃 + 藍 + 紅**
    - Ben:橘 + 藍 = **黃 + 紅 + 藍**
5. 兩人現在得到了**相同的**顏色(棕色) — 也就是共同的金鑰。

竊聽者看到的是黃色、橘色和綠色。但他要得到棕色,就需要紅色或藍色 — 而這兩種顏色 Anna 和 Ben 從來沒有傳送過。

實際上當然不是用顏色來計算,而是用非常大的數字。在 Tracer 中,你馬上就會再次看到這個交換過程,即 **Server Key Exchange** 和 **Client Key Exchange** — **ECDHE** 中的「**DHE**」代表 *Diffie-Hellman Ephemeral*,也就是使用一次性金鑰的 Diffie-Hellman。

:::warning
單靠 Diffie-Hellman 無法防止攻擊者坐在中間,分別與 Anna **和** Ben 各自協商出一把金鑰。因此 Anna 還必須確定自己真的是在和 Ben 通訊。這需要**簽章**和**憑證** — 這是下一個主題。
:::

:::tip 重點整理
**混合式加密**結合了兩種方法的優點:先用**非對稱式**方法(例如 Diffie-Hellman)讓雙方約定一把秘密的**會話金鑰**;資料本身再以**對稱式**方法(例如 AES)加密。HTTPS、WLAN 加密、SSH 和 VPN 都是這樣運作的。
:::
