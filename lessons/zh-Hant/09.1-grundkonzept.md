# 封包過濾器：規則

最簡單也最重要的一種防火牆是**封包過濾器**（Paketfilter）。它會檢查每一個經過的封包，並依據一份**規則清單**決定該封包是否可以通過。為此它只讀取第 3 層和第 4 層的標頭——封包的內容（例如網頁）它不會查看。

## 規則由哪些部分組成

| 欄位 | 意義 | 範例 |
|---|---|---|
| **方向** | 封包來自哪一側？ | A → B（從網際網路進入學校網路） |
| **協定** | TCP、UDP、ICMP 或任意 | TCP |
| **來源 IP** | 發送端位址或網路 | 任意 |
| **來源連接埠** | 發送端連接埠 | 任意 |
| **目的 IP** | 接收端位址或網路 | `198.51.100.10` |
| **目的連接埠** | 接收端連接埠，也就是服務 | `80` |
| **動作** | 符合規則的封包會怎麼處理？ | 允許 |

空白的欄位表示「任意」。網路以 CIDR 表示法書寫，例如 `198.51.100.0/24`；連接埠範圍則用連字號表示，例如 `1024-65535`。

## 順序決定結果

防火牆會**由上而下**檢查規則。**第一條符合的規則**會決定結果——對於這個封包，後面的規則就不會再被查看。如果沒有任何規則符合，就適用**預設政策**（*Default Policy*）。

## 三種可能的動作

| 動作 | 防火牆的處理方式 | 發送端會察覺到什麼 |
|---|---|---|
| **允許**（*Allow*） | 封包被轉送 | — |
| **丟棄**（*Drop*） | 封包被默默丟掉，不作任何回應 | 什麼都沒有——它會一直等到逾時 |
| **拒絕**（*Reject*） | 封包被丟掉，發送端會收到拒絕通知：TCP 為 **RST**，其他情況為 ICMP「無法到達」 | 立刻收到錯誤訊息 |

哪一種比較好？**丟棄**會讓攻擊者得到的資訊較少，也會耗費他的時間，因為他對每次嘗試都必須等待。**拒絕**對自己的使用者比較友善：程式會立刻收到錯誤訊息，而不是長時間卡住。因此在實務上，通常會丟棄來自外部的封包，並拒絕來自自己網路的封包。

:::quiz match
允許 -> 封包被轉送
丟棄 -> 封包消失，發送端白白等待回應
拒絕 -> 封包不會被轉送，但發送端會立刻收到拒絕通知
預設政策 -> 在沒有任何規則符合時適用
:::

:::tip 重點整理
**封包過濾器**會依據方向、協定、位址和連接埠，將每個封包與一份**規則清單**比對。**第一條符合的規則**決定動作：**允許**、**丟棄**（無聲）或**拒絕**（並發出拒絕通知）。如果沒有任何規則符合，就適用**預設政策**。
:::
