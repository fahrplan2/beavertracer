# 全部整合：開啟網頁時會發生什麼事？

:::goal
**學習目標：** 你可以逐步說明，當一台剛開機的筆記型電腦開啟網頁時，有哪些協定在哪一層參與其中。
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

現在，你在這門課程中學到的一切都要整合起來了。交換器上連接著一台 **DHCP-Server**、一台 **DNS-Server**、一台 **Webserver** 和一台剛開機的 **Laptop**——它還沒有 IP 位址，並且設定為 DHCP。

## 實驗

1. 切換到 :fa-play: **執行**模式，等待幾秒鐘。
2. 點選 **Laptop**，開啟 :fa-globe: **瀏覽器**，並輸入 `http://www.beaver-schule.de/`。
3. 在 :fa-magnifying-glass: **追蹤**模式中，為 **Laptop** 開啟一個追蹤。這裡記錄了整個過程——從第一個封包開始。

請依照追蹤中出現的順序排列這些步驟：

:::quiz match
1. Schritt -> DHCP: Der Laptop holt sich IP-Adresse, Gateway und DNS-Server
2. Schritt -> ARP: Der Laptop fragt nach der MAC-Adresse des DNS-Servers
3. Schritt -> DNS: Der Laptop fragt nach der IP-Adresse von www.beaver-schule.de
4. Schritt -> ARP: Der Laptop fragt nach der MAC-Adresse des Webservers
5. Schritt -> TCP: Drei-Wege-Handshake mit dem Webserver
6. Schritt -> HTTP: GET / und die Antwort 200 OK
:::

:::evaluate
檢查順序
:::

而在這一切之下，還有 **IP**（第 3 層），它為每一個封包定址；以及 **Ethernet**（第 2 層），它把封包送到下一個裝置。如果網頁伺服器位於另一個網路，就還需要**路由器**：這時筆記型電腦會詢問its **閘道**的 MAC 位址，而不是網頁伺服器的 MAC 位址。

:::quiz mc
為什麼筆記型電腦要等到 DHCP 之後才能發出 DNS 查詢？
- [ ] 因為 DNS 只能透過 TCP 運作
- [x] 因為它要透過 DHCP 才能取得自己的 IP 位址，並得知由哪台 DNS 伺服器負責
- [ ] 因為 DNS 伺服器要在 DHCP 伺服器之後才啟動
:::

:::quiz mc
瀏覽器會與網頁伺服器建立幾個 TCP 連線——為什麼？
- [ ] 一個，所有內容共用
- [x] 兩個——一個用於網頁，一個用於樣式表
- [ ] 完全不需要，HTTP 不需要 TCP
:::

:::evaluate
檢查答案
:::

:::tip 重點整理
一次點擊的背後，所有層都在協同運作：**DHCP** 提供基本設定，**ARP** 在區域網路中找出 MAC 位址，**DNS** 轉換名稱，**TCP** 建立可靠的連線，**HTTP** 取得網頁——這一切都封裝在 **IP** 封包和 **Ethernet** 訊框中。
:::

這樣你就能從第一個封包到最後一個封包，完整說明開啟網頁的過程。本章最後還會簡短展望其他協定。接下來的章節將介紹使用 NAT 的家用網路、安全性與加密——以及如何防止有人讀取這些封包的問題。
