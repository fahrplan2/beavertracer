# 疑難排解：新規則上線後，什麼都不通了

:::sim
url=/sims/lesson-9.4.btsim
:::

Beaver 學校的管理員 Biber 先生昨天把防火牆改成了白名單原則。從那時起大家都在抱怨：**學校網站**從外部無法再存取，而且**來自網際網路的郵件**也完全收不到了。至少 SSH 現在如願從外部被封鎖了。

找出**防火牆**規則中的錯誤並修正它們。

<details>
<summary>提示 1：封包到底有沒有比對到正確的規則？</summary>

從 **Internet-PC** 用 `nmap -p 22,25,80 198.51.100.10` 進行測試，然後在防火牆中查看 **Treffer** 欄。如果某條規則的數值一直是 0，但明明應該有封包符合它，那麼這條規則不是被另一條規則遮蔽了，就是永遠不會符合。
</details>

<details>
<summary>提示 2：仔細檢查</summary>

把規則中的每個數字和第 5 章的連接埠對照一下：哪個連接埠屬於 HTTP，哪個屬於 SMTP？另外也要留意順序：第一條符合的規則優先生效。
</details>

:::task
title: 網站和郵件又可以存取了嗎？
檢查學校伺服器的網站和郵件是否可以從網際網路存取，同時 SSH 仍然保持封鎖。
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## 發生了什麼事？

:::quiz multi
規則中藏有哪些錯誤？
- [x] 網站規則允許的是連接埠 8080，而不是 80
- [x] 郵件規則排在「全部丟棄」規則的下面，因此永遠不會被比對到
- [ ] 防火牆被設定成有狀態模式
- [ ] 連接埠 25 對郵件來說是錯誤的連接埠
:::

檢查答案
:::

:::tip 重點整理
防火牆規則中常見的錯誤有：連接埠的**數字顛倒**、**方向**錯誤，以及**順序**錯誤，也就是一般性的規則遮蔽了特定的規則。疑難排解時，可以利用來自外部的**連接埠掃描**、防火牆的**日誌**，以及規則的**命中計數器**。
:::
