# 總結與展望

## 各個基本要素總覽

| 基本要素 | 保護目標 | 範例 |
|---|---|---|
| **對稱式加密** | 機密性 | AES 加密 HTTPS 連線的資料 |
| **非對稱式加密** | 機密性、金鑰交換 | Diffie-Hellman、RSA |
| **雜湊值** | 完整性 | 下載檔案的 SHA-256 檢查碼 |
| **數位簽章** | 真實性、完整性 | 伺服器對自己的 Diffie-Hellman 部分進行簽章 |
| **憑證** | 真實性 | 證明：這把金鑰屬於 `www.biberbank.de` |

## 同樣的原理出現在許多地方

你在 HTTPS 中學到的內容，也存在於許多其他技術中：

- **無線區域網路（WPA2/WPA3）：** 在 3.3.2 章中，範圍內的每個裝置都能讀取通訊內容。使用 WPA2 或 WPA3 時，每個無線訊框都會以 AES 加密；此外，WPA3 協商金鑰的方式也使得竊聽者即使知道 WLAN 密碼，也無法解密舊的側錄資料。
- **SSH：** 即第 6.6 章的加密遠端維護。用戶端不使用憑證，而是在第一次連線時記住伺服器金鑰的**指紋**，並在之後指紋改變時發出警告。
- **VPN：** 穿越網際網路的加密通道，例如連到學校或公司的網路。這是第 10 章的主題。
- **即時通訊軟體：** Signal、WhatsApp 等軟體採用**端對端**加密：就連服務的營運者也無法讀取訊息。

:::note
大型**量子電腦**有朝一日可能破解大數的質因數分解，進而破解 RSA 和 Diffie-Hellman。因此，現在就已經在導入新的**抗量子**方法。使用長金鑰的對稱式方法（如 AES）則仍被視為安全。
:::

- [ ] RSA，因為它最安全
- [x] 對稱式方法（如 AES）和協商出來的工作階段金鑰

- [ ] 點擊「仍要繼續」——反正連線還是加密的
