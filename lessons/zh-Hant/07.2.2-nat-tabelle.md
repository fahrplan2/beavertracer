# NAT 表

:::sim
url=/sims/lesson-7.1.btsim
:::

當 PC 和平板同時載入同一個網頁時，兩個請求都會從 `203.0.113.2` 到達網頁伺服器。家用路由器要如何知道某個回應是給誰的？它會做記錄——記在 **NAT 表**中。

## 實驗

1. 切換到 :fa-play: **執行**模式，在 **PC** 和 **Tablet** 上分別開啟 `http://www.beispiel.de/`。
2. 點選 **Heimrouter**，然後開啟 **NAT** 索引標籤。

每一列都是一筆**對應**：通訊協定、家用網路中該裝置的 LAN IP 與 LAN 連接埠——以及路由器為此在其公用位址上使用的 **WAN 連接埠**。

:::quiz short
表格上方顯示的是哪個 WAN IP？
= 203.0.113.2
:::

:::quiz mc
PC 和平板都以 LAN 連接埠 `49152` 建立了連線。它們會得到哪個 WAN 連接埠？
- [ ] 兩者都是同一個，`49152`
- [x] 各自不同——否則路由器不會知道回應屬於誰
- [ ] 完全沒有，NAT 只會改變 IP 位址
:::

:::quiz mc
網頁伺服器的一個回應以特定的**目的連接埠**抵達 `203.0.113.2`。家用路由器會如何處理它？
- [x] 它會在 NAT 表中查找該連接埠，並將封包傳送到對應的 LAN IP 和 LAN 連接埠
- [ ] 它會將封包傳送給家用網路中的所有裝置
- [ ] 它會丟棄該封包
:::

:::evaluate
檢查答案
:::

這裡第 5 章的**連接埠**又派上用場了：由於 NAT 也會改寫連接埠，數百個連線就可以共用同一個位址。嚴格來說，這因此稱為 **PAT**（*Port Address Translation*，連接埠位址轉換）或*帶連接埠轉換的 NAT*——不過在日常用語中，大家還是直接說 NAT。

這樣的轉換例如可能如下所示：

| | 來自 PC 的封包（在家用網路中） | 同一個封包在網際網路上 |
|---|---|---|
| 發送端 | `192.168.178.20 : 49152` | `203.0.113.2 : 10001` |
| 接收端 | `192.0.2.80 : 80` | `192.0.2.80 : 80` |

:::tip 重點整理
在 **NAT 表**中，路由器會為每個連線記住哪個裝置（**LAN IP 與 LAN 連接埠**）對應到哪個 **WAN 連接埠**。來自網際網路的回應，則透過目的連接埠再對應回正確的裝置。由於連接埠也會被改寫，更精確的說法是 **PAT**。
:::
