# 廣播風暴

:::sim
url=/sims/lesson-3.4.1.btsim
:::

三台交換器（A、B、C）以環狀方式連接。**Anna**（`192.168.0.10`）連接在交換器 A 上，**Ben**（`192.168.0.11`）連接在交換器 B 上。

## 實驗

1. 切換到 :fa-play: **執行**模式，在 **Anna** 上開啟 :fa-terminal: **終端機**，並 ping Ben：
   ```
   $ ping 192.168.0.11
   ```
2. 關閉 Anna 的視窗，並在工作區觀察一會兒：封包會在環狀架構中不停地循環。
3. 切換到 :fa-magnifying-glass: **追蹤**模式，並用 **+** 為 **Ben** 的連接埠 `eth0` 開啟一個追蹤。在右上角可以看到目前已記錄了多少封包。
4. 在**執行**和**追蹤**之間來回切換幾次，並留意這個數字。

:::quiz mc
你在 Ben 的封包列表中看到什麼？
- [ ] Anna 的 ping 和 Ben 的回覆，一如往常
- [x] 同一個 ARP 請求「Who has 192.168.0.11?」一再重複出現——而且封包數量不斷增加
- [ ] 什麼都沒有，環狀架構會阻擋一切
:::

:::quiz mc
那麼 Anna 的終端機顯示什麼？
- [ ] 所有 ping 都成功送達
- [x] 沒有任何 ping 送達
:::

:::evaluate
檢查答案
:::

## 背後的原因

Anna 的 ARP 請求是一個廣播。交換器 A 會把它從所有連接埠送出——也就是送到交換器 B *和*交換器 C。這兩台交換器又會把它從自己所有的連接埠再轉送出去，因此也會送到另一台交換器，並回到 A。A 又再次轉送……廣播就這樣在環狀架構中無止盡地循環，而且每出現一個新的請求，就會多出更多副本。

由於相同的訊框不斷從不同方向抵達交換器，它們的位址表也會被攪亂：一下子 Anna 在這個連接埠，一下子又在那個連接埠。因此連 ping 也無法再送達。

:::tip 重點整理
如果交換器之間存在**迴圈**，廣播就會在網路中無止盡地循環並不斷倍增——這就是**廣播風暴**。它會讓整個網路癱瘓。與 IP 封包不同，乙太網路訊框沒有「到期日」，因此不會在某個時候被終止。
:::
