# 網路中的 IPv6

:::sim
url=/sims/lesson-4.6.3.btsim
:::

Anna、Ben 和一台路由器連接在交換器上。Anna 和 Ben 的 IPv6 設定為 **SLAAC (automatisch)**——沒有人為他們填入 IPv6 位址。路由器知道前綴 `2001:db8:1::/64`。

## 位址從哪裡來？

1. 切換到 :fa-play: **執行**模式，並等待幾秒鐘。
2. 在 **Anna** 上開啟 :fa-terminal: **終端機**，輸入 `ip a`。

除了 IPv4 位址之外，你還會看到兩行 `inet6`：一個位址帶有 `scope link`，另一個帶有 `scope global`。

:::quiz mc
這兩個 IPv6 位址中，哪一個是連結本地位址（Link-Local）？
- [x] 開頭為 `fe80::` 的那個（`scope link`）
- [ ] 開頭為 `2001:db8:1:` 的那個（`scope global`）
:::

:::quiz mc
全域位址的前綴 `2001:db8:1:0` 是從哪裡來的？
- [ ] Anna 自己想出來的
- [x] 來自路由器——它在網路中宣告這個前綴
- [ ] 來自交換器
:::

:::evaluate
檢查答案
:::

請將**介面 ID**（Interface-ID，最後四個區塊）與 Anna 的 **MAC 位址**做比較——你可以在 :fa-gear: **IP 設定**的最下方找到它。例如，MAC 位址 `aa:28:39:e2:41:82` 會變成介面 ID `a828:39ff:fee2:4182`：在中間插入 `ff:fe`，並將開頭的一個位元翻轉（因此 `aa` 變成 `a8`）。

這個方法稱為 **SLAAC**（*Stateless Address Autoconfiguration*，無狀態位址自動設定）：路由器宣告前綴，介面 ID 則由每台裝置自行產生。

:::note
由於 MAC 位址能唯一識別一台裝置，因此可以透過介面 ID 在網際網路上的任何地方重新辨識出該裝置。所以真實的裝置通常還會額外使用定期變更的隨機介面 ID（*Privacy Extensions*，隱私擴充）——這是一種資料保護的做法。
:::

## 尋找鄰居——不使用 ARP

1. 在 **Ben** 上輸入 `ip a`，並記下他的**全域** IPv6 位址。
2. 從 **Anna** 對它執行 ping，例如 `ping 2001:db8:1:0:…`（使用 Ben 的完整位址）。
3. 切換到 :fa-magnifying-glass: **追蹤**模式，並為 **Anna** 開啟一個追蹤。

請查看第一個 `Echo (ping) request` 之前緊接著的封包。

:::quiz multi
以下哪些敘述是正確的？
- [x] Anna 不是傳送 ARP 請求，而是傳送 **Neighbor Solicitation**（「誰擁有這個位址？」）
- [x] Ben 以 **Neighbor Advertisement** 回應，並告知他的 MAC 位址
- [x] 這個請求是傳送到多點傳播位址（`ff02::1:ff…`），而不是以廣播傳送給所有裝置
- [ ] Anna 像在 IPv4 中一樣傳送 ARP 請求
- [x] 路由器會定期將 **Router Advertisement** 傳送到 `ff02::1`——其中包含前綴
:::

:::evaluate
檢查答案
:::

:::tip 重點整理
在 IPv6 中，由 **NDP**（*Neighbor Discovery Protocol*，鄰居探索協定，屬於 ICMPv6 的一部分）接手 ARP 的工作：裝置透過 **Neighbor Solicitation** 與 **Neighbor Advertisement** 找出鄰居的 MAC 位址。路由器則透過 **Router Advertisement** 宣告前綴——裝置再藉由 **SLAAC** 以此自行產生位址。
:::
