# 序列圖

:::sim
url=/sims/lesson-5.1.btsim
:::

連線的過程會畫成**序列圖**：用戶端和伺服器各有一條垂直線，時間由上往下流動。每個箭頭代表一個封包。箭頭畫成斜的，是因為每個封包都需要一點時間在途中傳送。

下面是你在上一頁建立的連線——請逐行與追蹤結果對照：

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

每個箭頭上方是**旗標**（Flags），下方是 `SEQ` 和 `ACK` 的數字。**DATA** 標示帶有資料內容的封包。紅色數字屬於用戶端，藍色數字屬於伺服器——它們的意義會在下一頁說明。

## 旗標

| 旗標 | 全名 | 意義 |
|---|---|---|
| **SYN** | *synchronize* | 建立連線，決定起始編號 |
| **ACK** | *acknowledge* | 確認已收到資料 |
| **PSH** | *push* | 立即將資料交給程式 |
| **FIN** | *finish* | 「我已經完成了」——結束連線 |
| **RST** | *reset* | 中止或拒絕連線（詳見 5.3.2） |

## 三個階段

**建立：** 用戶端傳送 `SYN`，伺服器以 `SYN, ACK` 回應，用戶端再以 `ACK` 確認。因為剛好需要三個封包，所以稱為**三向交握**。

**資料：** 每個帶有資料的封包，接收端都會以 `ACK` 確認。這裡伺服器會把回顯傳回來——用戶端同樣會確認。

**結束：** 雙方各自單獨結束自己的傳送方向：先由用戶端傳送 `FIN`，伺服器回 `ACK`——接著由伺服器傳送 `FIN`，用戶端回 `ACK`。這共有四個封包。

:::tip 重點整理
TCP 連線分為三個階段：以**三向交握**（`SYN` → `SYN, ACK` → `ACK`）進行的**建立**、**資料傳輸**（每個資料封包都以 `ACK` 確認），以及**結束**（雙方各自傳送 `FIN` 並收到一個 `ACK`）。
:::

## 換你試試

這次用戶端只傳送 `Hi`（加上行尾字元共 4 位元組）。請填入缺少的旗標——同一欄位內的順序不拘。

:::quiz seq
hide: counters
Client-PC -> Server: ? SYN
Server -> Client-PC: ? SYN, ACK
Client-PC -> Server: ? ACK
Client-PC -> Server: PSH, ACK "Hi" len=4
Server -> Client-PC: ? ACK
Client-PC -> Server: ? FIN, ACK
Server -> Client-PC: ? ACK
Server -> Client-PC: ? FIN, ACK
Client-PC -> Server: ? ACK
:::
