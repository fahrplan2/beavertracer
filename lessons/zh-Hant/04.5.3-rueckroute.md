# 疑難排解：回程路由

:::sim
url=/sims/lesson-4.5.3.btsim
:::

和剛才相同的架構：Firma A — Router A — Zwischennetz — Router B — Firma B。管理員已在 **Router A** 上設定了通往 Firma B 的路由（`172.16.0.0/24` 經由 `10.0.0.2`）。儘管如此，Anna 還是回報：Clara 沒有回應。

找出錯誤並加以修復。

<details>
<summary>提示 1：Anna 的 ping 到底有沒有送達？</summary>

從 Anna 對 Clara 執行 ping，並為 **Clara** 開啟追蹤。ping 有送達她那裡嗎？她有回應嗎？
</details>

<details>
<summary>提示 2：traceroute 走到哪裡？</summary>

在 Anna 上輸入 `traceroute 172.16.0.10`。回應一直到哪個路由器都還有回來？又是哪個路由器必須把 Clara 的回應轉送給 Anna？
</details>

<details>
<summary>提示 3：誰知道哪個網路？</summary>

查看 **Router B** 的路由表。它知道目的地為 `192.168.0.0/24` 的封包該往哪裡送嗎？
</details>

:::task
title: 連線修復了嗎？
檢查 Router B 是否知道通往 Firma A 的路徑，以及 Anna 是否能連到 Clara。為此，模擬必須在執行模式下運作。
check: hasRoute(5, "192.168.0.0/24")
check: pingOk(9, 11)
:::

## 發生了什麼事？

:::quiz multi
你在疑難排解時觀察到了什麼？
- [x] Anna 的 ping 送達了 Clara，而且 Clara 有回應
- [x] 回應卡在 Router B，因為它不認識 Firma A
- [ ] Router A 丟棄了 Anna 的 ping
- [x] 過了 Router A 之後，`traceroute` 只顯示 `*`，儘管去程是正常的
:::

:::evaluate
檢查答案
:::

:::tip 重點整理
每一條連線都需要**去程和回程**：路徑上的每個路由器都必須認識*兩個*網路——目的網路和發送端所在的網路。缺少**回程路由**是最常見的路由錯誤之一。請注意：`traceroute` 只會顯示從哪裡開始不再有回應傳回——錯誤也可能出在回程上。
:::
