Na **serveru** tentokrát běží **UDP Echo-Server** na portu `5000`. I tady je kabel připravený: **druhý datagram** od klientského PC k serveru se ztratí.

## Experiment

1. Přepni se do režimu :fa-play: **Spustit** a na **Client-PC** otevři :fa-terminal: **Terminál**.
2. Pomocí `nc` naváž UDP „spojení“ se serverem (`-u` znamená UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Postupně napiš `eins`, `zwei` a `drei` a pokaždé stiskni **Enter**. Každý řádek, který se vrátí, je echo ze serveru.
4. Počkej několik sekund a pak v režimu :fa-magnifying-glass: **Trasování** otevři trace pro **Client-PC**.

:::quiz mc
Která echa se vrátí?
- [ ] Všechna tři, `zwei` o něco později
- [x] Jen `eins` a `drei` — `zwei` chybí a ani se znovu neodešle
- [ ] Žádné
:::

:::quiz multi
Které pakety, které znáš z TCP, u UDP úplně chybí?
- [x] Navázání spojení (`SYN`)
- [x] Potvrzení (`ACK`)
- [x] Ukončení spojení (`FIN`)
- [ ] Pakety s čísly portů
:::

:::evaluate
Zkontrolovat odpovědi
:::

Klikni na jeden z UDP paketů a rozbal **User Datagram Protocol**. Ve srovnání s hlavičkou TCP je hlavička UDP drobná: **Source Port**, **Destination Port**, **Length** (délka) a **Checksum** (kontrolní součet) — dohromady jen 8 bajtů. Hlavička TCP má nejméně 20 bajtů, se sekvenčním a potvrzovacím číslem, příznaky a velikostí okna.

:::quiz mc
Který úkol z části 5.1 UDP přesto zajišťuje?
- [x] Multiplexování — prostřednictvím portů
- [ ] Navázání spojení
- [ ] Spolehlivý přenos
:::

:::evaluate
Zkontrolovat odpověď
:::

:::tip Zapamatuj si
**UDP** je **nespojované**: žádné navázání spojení, žádné potvrzování, žádné opakované odeslání, žádné pořadí. Nabízí jen **porty** (multiplexování) a **kontrolní součet**. Zato je rychlé a nenáročné — hlavička UDP má jen 8 bajtů. Pokud se datagram ztratí, musí se o to program postarat sám — nebo je mu to jedno.
:::
