# Útok: falšování DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna chce na **Client-PC** otevřít své online bankovnictví u **Biberbank**. Neví však, že se někdo dostal k **DNS-Server** a změnil jeden záznam.

Na pracovní ploše vidíš skutečný webový server **www.biberbank.de** a počítač **útočníka**. Běží na něm kopie webových stránek banky.

## Část 1: Bez šifrování

Přepni do :fa-play: **Spustit** režimu spuštění a na **Client-PC** zadej v :fa-globe: **Prohlížeč** adresu `http://www.biberbank.de/`.

:::quiz mc
Co vidíš?
- [x] Přihlašovací stránku Biberbank bez jakéhokoli varování
- [ ] Varování, že stránka je podvržená
- [ ] Chybovou zprávu
:::

:::evaluate
Zkontrolovat odpověď
:::

Všechno vypadá normálně. Ale s jakým serverem prohlížeč skutečně komunikuje? Otevři na Client-PC :fa-terminal: **Terminál**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Jakou IP adresu vrátí DNS server pro `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Komu patří tato adresa? (V režimu úprav klikni na zařízení nebo si zobraz jejich :fa-gear: **Nastavení IP**.)
- [ ] Skutečnému webovému serveru Biberbank
- [x] Útočníkovi
- [ ] DNS serveru
:::

:::evaluate
Zkontrolovat odpovědi
:::

Kdyby Anna teď zadala číslo účtu a PIN, skončily by přímo u útočníka. U **HTTP** nemá **žádnou šanci** podvod poznat: v adresním řádku je správné jméno a stránka vypadá pravě.

## Část 2: S HTTPS

Nyní zadej `https://www.biberbank.de/`.

:::quiz mc
Co se stane?
- [ ] Zobrazí se podvržená stránka se zámkem
- [x] Prohlížeč varuje: certifikát byl vystaven pro jiné jméno
- [ ] Zobrazí se skutečná stránka Biberbank
:::

:::quiz short
Pro jaké jméno je vystaven certifikát útočníka (bez `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Zkontrolovat odpovědi
:::

Útočník má dokonce **skutečný** certifikát důvěryhodné CA, ale pro svou vlastní doménu `www.biber-gewinnspiel.de`. Certifikát pro `www.biberbank.de` od žádné CA nezíská, protože tato doména mu nepatří. A bez **soukromého klíče** Biberbank nemůže použít ani její skutečný certifikát: při handshaku by s ním musel podepsat Server Key Exchange.

:::quiz multi
Před čím HTTPS v tomto případě chrání — a před čím ne?
- [x] HTTPS odhalí, že server není ten pravý
- [ ] HTTPS zabrání tomu, aby byl DNS server podvržen
- [x] HTTPS pomůže jen tehdy, když uživatel bere varování vážně
- [ ] S HTTPS není podvržená stránka vůbec dostupná
:::

:::evaluate
Zkontrolovat odpovědi
:::

## Část 3: Oprava DNS serveru

Otevři **DNS-Server** a oprav záznam pro `www.biberbank.de`. Správnou adresu najdeš v :fa-gear: **Nastavení IP** webového serveru **www.biberbank.de**. Nezapomeň kliknout na **Uložit**.

:::note
Client-PC si DNS odpovědi na nějakou dobu pamatuje, aby se nemusel při každém přístupu ptát znovu (**DNS cache**). Jak dlouho, udává sloupec **TTL** (*Time to Live*) v sekundách. Pokud `nslookup` hned po tvé opravě stále vrací starou adresu, počkej, až TTL vyprší, a zkus to znovu.
:::

:::task
title: Je Biberbank zase pravá?
Zkontrolujte, zda Client-PC přeloží www.biberbank.de na správnou adresu a zda lze stránku načíst přes HTTPS bez varování.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Ve skutečnosti útočník jen zřídka falšuje samotný DNS server. Častěji podsouvá své odpovědi ve veřejné síti Wi-Fi, mění nastavení domácího routeru nebo láká na podobně vypadající adresu, např. `www.biberbank-login.de` (**phishing**). Proti podobně znějícímu jménu nepomůže ani HTTPS — útočník pro ně získá platný certifikát. Proto: čti adresu pozorně!
:::

:::tip Zapamatuj si
Při **falšování DNS** vrátí DNS server pro určité jméno adresu útočníka. U **HTTP** si toho nevšimneš. U **HTTPS** certifikát útočníka neodpovídá zadanému jménu a prohlížeč **varuje** — certifikát pro cizí domény žádná CA nevystaví a soukromý klíč skutečného serveru útočník nemá.
:::
