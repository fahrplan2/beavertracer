# Sekvenční a potvrzovací čísla

:::sim
url=/sims/lesson-5.1.btsim
:::

Jak TCP pozná, jestli všechno dorazilo — a v jakém pořadí? Každá strana **čísluje bajty**, které odesílá:

- **Sekvenční číslo** (`SEQ`) je číslo prvního bajtu, který je v tomto paketu.
- **Potvrzovací číslo** (`ACK`) říká: „Až sem jsem dostal všechno — příště očekávám bajt č. …“

K tomu dvě pravidla: `SYN` a `FIN` se počítají jako jeden bajt, i když nenesou žádná data. A každá strana počítá zvlášť — proto existují dvě číselné řady, v diagramu červená (klient) a modrá (server).

## Přepočítej si to

Tady je ještě jednou tvé spojení. Čísla u čar ukazují vždy čítač daného počítače v tomto místě:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Projdi si červenou řadu čísel:

1. Klient začíná na `SEQ=0`. Jeho `SYN` spotřebuje jedno číslo — server potvrdí s `ACK=1`.
2. Zpráva začíná na `SEQ=1` a je dlouhá 13 bajtů (bajty 1 až 13). Server potvrdí s `ACK=14`: „Příště očekávám bajt 14.“
3. `FIN` klienta má proto `SEQ=14` a je potvrzen s `ACK=15`.

Modrá řada serveru funguje úplně stejně.

:::tip Zapamatuj si
**Sekvenční číslo** (`SEQ`) je číslo prvního bajtu v paketu. **Potvrzovací číslo** (`ACK`) je číslo dalšího bajtu, který příjemce očekává — vše před ním dorazilo. Platí: **ACK = SEQ + délka** přijatých dat; `SYN` a `FIN` se počítají jako jeden bajt. Každá strana počítá své vlastní bajty.
:::

:::tip Vyzkoušej si to
Znovu navaž spojení v **Jednoduchý TCP klient** a pošli dvě zprávy za sebou. Předem řekni, jaké hodnoty `Seq` a `Ack` budou ve sloupci **Info** — a ověř to v trasování.
:::

:::note
V reálných sítích se počítání nezačíná od 0: každá strana zvolí **náhodné počáteční číslo** (*Initial Sequence Number*, ISN) mezi 0 a zhruba 4,3 miliardy. Když je dosaženo nejvyššího čísla, pokračuje se opět od 0. Tracer počáteční číslo odečítá a zobrazuje **relativní** čísla — stejně jako Wireshark. Proto vidíš `Seq=0` a `Seq=1`.

Kromě toho je v každém paketu `Win=` — **velikost okna**: tolik bajtů může příjemce právě přijmout. Tím brzdí příliš rychlého odesílatele (*řízení toku*). V BeaverTraceru je okno vždy stejně velké.
:::
