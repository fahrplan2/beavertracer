# Vše dohromady: co se stane při otevření webové stránky?

:::goal
**Cíl výuky:** Dokážeš krok za krokem vysvětlit, které protokoly na které vrstvě se účastní, když čerstvě zapnutý laptop otevře webovou stránku.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Teď se spojí všechno, co ses v tomto kurzu naučil(a). K switchi je připojený **DHCP Server**, **DNS-Server**, **Webserver** a **Laptop**, který byl právě zapnutý — zatím nemá žádnou IP adresu a je nastavený na DHCP.

## Experiment

1. Přepni do režimu :fa-play: **Spustit** a počkej několik sekund.
2. Klikni na **Laptop**, otevři :fa-globe: **Prohlížeč** a zadej `http://www.beaver-schule.de/`.
3. V režimu :fa-magnifying-glass: **Trasování** otevři trace pro **Laptop**. Tady je celý příběh — od úplně prvního paketu.

Seřaď kroky do správného pořadí, tak jak jsou v trace:

:::quiz match
1. Schritt -> DHCP: Laptop získá IP adresu, bránu a DNS server
2. Schritt -> ARP: Laptop se ptá na MAC adresu DNS serveru
3. Schritt -> DNS: Laptop se ptá na IP adresu www.beaver-schule.de
4. Schritt -> ARP: Laptop se ptá na MAC adresu webového serveru
5. Schritt -> TCP: třícestný handshake s webovým serverem
6. Schritt -> HTTP: GET / a odpověď 200 OK
:::

:::evaluate
Zkontrolovat pořadí
:::

A pod tím vším leží **IP** (vrstva 3), které adresuje každý z těchto paketů, a **Ethernet** (vrstva 2), který ho doručí k dalšímu zařízení. Kdyby byl webový server v jiné síti, přibyl by ještě **router**: Laptop by se pak ptal na MAC adresu své **brány**, ne na MAC adresu webového serveru.

:::quiz mc
Proč může laptop odeslat DNS dotaz až po DHCP?
- [ ] Protože DNS funguje jen přes TCP
- [x] Protože vlastní IP adresu a informaci o tom, který DNS server je příslušný, získá teprve pomocí DHCP
- [ ] Protože DNS server se spustí až po DHCP serveru
:::

:::quiz mc
Kolik TCP spojení naváže prohlížeč s webovým serverem — a proč?
- [ ] Jedno, pro všechno dohromady
- [x] Dvě — jedno pro stránku a jedno pro stylesheet
- [ ] Žádné, HTTP TCP nepotřebuje
:::

:::tip Zapamatuj si
Za jediným kliknutím spolupracují všechny vrstvy: **DHCP** dodá základní nastavení, **ARP** najde MAC adresy v místní síti, **DNS** přeloží jméno, **TCP** naváže spolehlivé spojení a **HTTP** stáhne stránku — vše zabalené do **IP** paketů a **Ethernet** rámců.
:::

Tím jsi schopen/schopna vysvětlit otevření webové stránky od prvního do posledního paketu. Na závěr kapitoly následuje ještě krátký výhled na další protokoly. V dalších kapitolách půjde o domácí síť s NAT, o bezpečnost a šifrování — a tedy o otázku, jak zabránit tomu, aby někdo všechny tyto pakety odposlouchával.
