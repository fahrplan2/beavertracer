# Shrnutí a výhled

## Přehled stavebních prvků

| Stavební prvek | Cíl ochrany | Příklad |
|---|---|---|
| **Symetrické šifrování** | důvěrnost | AES šifruje data spojení HTTPS |
| **Asymetrické šifrování** | důvěrnost, výměna klíčů | Diffie-Hellman, RSA |
| **Hashe** | integrita | kontrolní součet SHA-256 staženého souboru |
| **Digitální podpis** | autenticita, integrita | server podepisuje svůj podíl Diffie-Hellmanovy výměny |
| **Certifikát** | autenticita | potvrzuje: Tento klíč patří k `www.biberbank.de` |

## Stejný princip na mnoha místech

Co ses naučil/a na HTTPS, najdeš i v mnoha dalších technologiích:

- **WLAN (WPA2/WPA3):** V kapitole 3.3.2 mohlo každé zařízení v dosahu odposlouchávat. U WPA2 nebo WPA3 je každý rámec šifrovaný pomocí AES; WPA3 navíc vyjednává klíč tak, že odposlouchávající nedokáže staré záznamy dešifrovat, ani když zná heslo k WLAN.
- **SSH:** Šifrovaná vzdálená správa z kapitoly 6.6. Místo certifikátů si klient při prvním připojení zapamatuje **otisk** klíče serveru a varuje, pokud se později změní.
- **VPN:** Šifrovaný tunel přes internet, např. do školní nebo firemní sítě. Tomu se věnuje kapitola 10.
- **Messengery:** Signal, WhatsApp a další šifrují **end-to-end**: ani provozovatel služby nemůže zprávy číst.

:::note
Velké **kvantové počítače** by jednoho dne mohly prolomit rozklad velkých čísel na prvočinitele — a tím i RSA a Diffie-Hellmana. Proto se už dnes zavádějí nové, **kvantově bezpečné** metody. Symetrické metody jako AES s dlouhými klíči se nadále považují za bezpečné.
:::

## Otestuj se

:::quiz mc
U HTTPS se vlastní data šifrují pomocí …
- [ ] RSA, protože je nejbezpečnější
- [x] symetrické metody, jako je AES, a vyjednaného klíče relace
- [ ] soukromého klíče serveru
:::

:::quiz mc
Otevřeš `https://www.biberbank.de/` a prohlížeč zobrazí hlášení „Certifikát byl vydán pro `www.gewinn-biber.de`“. Co uděláš?
- [ ] Klikneš na „Přesto pokračovat“ — spojení je přece i tak šifrované
- [x] Přerušíš spojení — prohlížeč možná vůbec nekomunikuje s bankou
- [ ] Otevřeš stránku přes `http://`, pak žádné varování nepřijde
:::

:::quiz multi
Která tvrzení jsou pravdivá?
- [x] Hash se zcela změní, i když se data změní jen minimálně
- [x] Podpis se vytváří soukromým klíčem a ověřuje veřejným
- [x] Kořenové CA jsou předinstalované v prohlížeči nebo v operačním systému
- [ ] U HTTPS odposlouchávající nevidí ani IP adresu serveru
- [ ] SMTPS šifruje e-mail i na poštovním serveru
:::
