# Co musí zajistit transportní vrstva?

:::sim
url=/sims/lesson-5.1.btsim
:::

Na **Serveru** běží současně dvě služby: **webový server** a malá **echo služba**, která každou zprávu, kterou dostane, okamžitě pošle zpět. Dvěma experimenty zjistíš, co samotný protokol IP zajistit nedokáže.

## Experiment 1: Dva programy současně

1. Přepni do režimu :fa-play: **Spustit** (režim spuštění) a klikni na **Client-PC**.
2. Otevři :fa-globe: **Prohlížeč** a načti `http://192.168.0.20/`.
3. Klikni nahoře v okně na **Zpět** a otevři **Jednoduchý TCP klient**. Do pole **Host** zadej `192.168.0.20`, do pole **Port** zadej `5000` a klikni na **Připojit**.
4. Přepni do režimu :fa-magnifying-glass: **Trasování** a pomocí **+** otevři trasování pro **Client-PC**, rozhraní `eth0`.

Klikni na paket prohlížeče (např. `GET /`) a na paket TCP klienta a u každého rozbal **Internet Protocol Version 4**.

:::quiz mc
Jaké IP adresy mají pakety prohlížeče a TCP klienta?
- [x] U obou stejné: od `192.168.0.10` na `192.168.0.20`
- [ ] Prohlížeč používá jinou cílovou IP adresu než TCP klient
- [ ] Pakety TCP klienta nemají žádnou IP adresu
:::

:::quiz mc
Stačí tedy cílová IP adresa k tomu, aby server poznal, zda paket patří webovému serveru, nebo echo službě?
- [ ] Ano
- [x] Ne — oba pakety mají stejnou cílovou IP adresu
:::

Něco jiného musí obě spojení rozlišit. Podívej se do sloupce **Info** u paketů s `[SYN]` — to je vždy první paket spojení:

:::quiz short
Jaké číslo je u **prohlížeče** za šipkou `→`?
= 80
:::

:::quiz short
A u **TCP klienta**?
= 5000
:::

:::evaluate
Zkontrolovat odpovědi
:::

Více se o těchto číslech — **portech** — dozvíš v oddílu 5.3. Zatím stačí vědět: teprve transportní vrstva zajistí, že může více programů komunikovat současně přes *jednu* IP adresu a každý paket skončí u správného programu. Tomu se říká **multiplexování**.

## Experiment 2: Když se paket ztratí

1. Přepni do režimu :fa-play: **Spustit** (režim spuštění) a klikni na **kabel** mezi Client-PC a Serverem.
2. V okně **Verbindung** nastav **Konfigurierten Paketverlust** na `25%`.
3. Na **Client-PC** otevři :fa-terminal: **Terminál** a pošli šest pingů:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Trvá to asi půl minuty — počkej, až se zobrazí statistika.

:::quiz mc
Co se stane?
- [ ] Na všech šest pingů přijde odpověď
- [x] Některé pingy zůstanou bez odpovědi — a nikdo je neodešle znovu
- [ ] Ztracené pingy se automaticky opakují, dokud nedorazí
:::

:::evaluate
Zkontrolovat odpověď
:::

U pingu to není problém — má přece právě ukázat, zda se něco ztrácí. U webové stránky, e-mailu nebo stahování by ale chybějící kousek byl fatální: soubor by byl poškozený.

## Čtyři úkoly transportní vrstvy

| Úkol | Co to znamená |
|---|---|
| **Multiplexování** | Více programů a spojení sdílí jednu IP adresu; každý paket skončí u správného programu. |
| **Navázání spojení** | Než začnou proudit data, obě strany se dohodnou, že spolu budou komunikovat. |
| **Spolehlivý přenos** | Příjemce potvrzuje, co dorazilo. Chybějící data se pošlou znovu, pořadí se obnoví. |
| **Ukončení spojení** | Na konci obě strany spojení řádně ukončí. |

:::tip Zapamatuj si
**Transportní vrstva** (vrstva 4) zajišťuje, že data dorazí ke správnému **programu** (**multiplexování**). Protokol **TCP** navíc zajišťuje, že dorazí **kompletní** a ve **správném pořadí** — s navázáním spojení, potvrzováním, opakovaným odesláním a ukončením spojení.
:::

:::quiz match
Na PC běží současně prohlížeč, poštovní program a messenger. -> Multiplexování
Než začnou proudit data, obě strany zjistí, že ta druhá je připravená. -> Navázání spojení
Část souboru nedorazí a pošle se znovu. -> Spolehlivý přenos
Po stažení obě strany spojení opět uvolní. -> Ukončení spojení
:::

:::
