# Sekvenční diagram

:::sim
url=/sims/lesson-5.1.btsim
:::

Průběh spojení se zakresluje jako **sekvenční diagram**: klient a server dostanou každý svislou čáru života, čas plyne shora dolů. Každá šipka je jeden paket. Je nakreslená šikmo, protože každý paket je chvíli na cestě.

Takto vypadá tvé spojení z minulé stránky — porovnej ho řádek po řádku s trasováním:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Nad každou šipkou jsou **příznaky (flags)**, pod ní čísla `SEQ` a `ACK`. **DATA** označuje pakety s užitečnými daty. Červená čísla patří klientovi, modrá serveru — co znamenají, vysvětlí další stránka.

## Příznaky

| Příznak | zkratka pro | Význam |
|---|---|---|
| **SYN** | *synchronize* | navázat spojení, určit počáteční číslo |
| **ACK** | *acknowledge* | potvrzuje přijatá data |
| **PSH** | *push* | okamžitě předat data programu |
| **FIN** | *finish* | „Jsem hotový“ — ukončit spojení |
| **RST** | *reset* | přerušit nebo odmítnout spojení (více v 5.3.2) |

## Tři fáze

**Navázání spojení:** Klient pošle `SYN`, server odpoví `SYN, ACK`, klient potvrdí `ACK`. Protože jsou potřeba přesně tři pakety, říká se tomu **třícestný handshake**.

**Data:** Každý paket s daty příjemce potvrdí paketem `ACK`. Tady server posílá zpět echo — i to klient potvrdí.

**Ukončení spojení:** Každá strana ukončí svůj směr odesílání zvlášť: `FIN` od klienta, `ACK` od serveru — pak `FIN` od serveru, `ACK` od klienta. To jsou čtyři pakety.

:::tip Zapamatuj si
TCP spojení probíhá ve třech fázích: **navázání spojení** pomocí **třícestného handshaku** (`SYN` → `SYN, ACK` → `ACK`), **přenos dat** (každý datový paket se potvrzuje pomocí `ACK`) a **ukončení spojení** (každá strana pošle `FIN` a dostane `ACK`).
:::
