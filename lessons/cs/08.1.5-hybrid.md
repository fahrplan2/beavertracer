# Hybridní šifrování

Shrňme si to:

| | symetrické (např. AES) | asymetrické (např. RSA) |
|---|---|---|
| Klíč | jeden společný tajný klíč | pár klíčů: veřejný + soukromý |
| Rychlost | velmi rychlé | pomalé |
| Výměna klíčů | problém: Jak se klíč dostane k příjemci? | není problém: veřejný klíč se smí posílat otevřeně |

Každý z obou způsobů má tedy silnou stránku, která tomu druhému chybí. Řešení: obojí se zkombinuje. Tomu se říká **hybridní šifrování**.

1. Na začátku spojení se obě strany pomocí **asymetrického** způsobu dohodnou na společném tajném klíči, tzv. **klíči relace**. Chvíli to trvá, ale děje se to jen **jednou**.
2. Potom se všechna data šifrují **symetricky** pomocí klíče relace — rychle.
3. Na konci spojení se klíč relace zahodí. Další spojení dostane nový.

Takto pracují **HTTPS**, šifrovaná e-mailová spojení, **Wi-Fi** s WPA3, **SSH** a **VPN**.

## Společné tajemství pomocí míchání barev

Elegantní způsob, jak se dohodnout na klíči relace, je **výměna klíčů Diffie-Hellman** (1976). Dá se to představit pomocí barev. Trik: barvy se míchají snadno, ale rozložit smíchanou barvu zpět na původní složky je prakticky nemožné.

1. Anna a Ben se **veřejně** dohodnou na společné základní barvě, např. **žluté**. Smí ji znát každý.
2. Každý si tajně zvolí **tajnou barvu**: Anna **červenou**, Ben **modrou**.
3. Každý přimíchá svou tajnou barvu do základní barvy a výsledek **otevřeně** pošle druhému: Anna pošle **žlutá + červená** (oranžová), Ben pošle **žlutá + modrá** (zelená).
4. Každý teď přimíchá svou vlastní tajnou barvu do směsi toho druhého:
    - Anna: zelená + červená = **žlutá + modrá + červená**
    - Ben: oranžová + modrá = **žlutá + červená + modrá**
5. Oba mají nyní **stejnou** barvu (hnědou) — společný klíč.

Odposlouchávající viděl žlutou, oranžovou a zelenou. Aby se dostal k hnědé, potřeboval by ale červenou nebo modrou — a ty Anna a Ben nikdy neposlali.

Ve skutečnosti se samozřejmě nepočítá s barvami, ale s velmi velkými čísly. V Traceru tuto výměnu brzy uvidíš znovu jako **Server Key Exchange** a **Client Key Exchange** — „**DHE**“ v **ECDHE** znamená *Diffie-Hellman Ephemeral*, tedy Diffie-Hellman s jednorázovými klíči.

:::warning
Samotný Diffie-Hellman nechrání před tím, aby se útočník postavil doprostřed a vyjednal zvláštní klíč s Annou **i** s Benem. Anna si proto musí být jistá, že opravdu mluví s Benem. K tomu jsou potřeba **podpisy** a **certifikáty** — to je další téma.
:::

:::tip Zapamatuj si
**Hybridní šifrování** kombinuje oba světy: pomocí **asymetrického** způsobu (např. Diffie-Hellman) se obě strany dohodnou na tajném **klíči relace**; samotná data se pak šifrují **symetricky** (např. pomocí AES). Takto pracují HTTPS, šifrování Wi-Fi, SSH a VPN.
:::
