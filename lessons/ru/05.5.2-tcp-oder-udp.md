# TCP или UDP?

| | TCP | UDP |
|---|---|---|
| Соединение | установление с помощью трёхстороннего рукопожатия, упорядоченное завершение | нет — каждая датаграмма самостоятельна |
| Подтверждения | да (`ACK`) | нет |
| Потерянные данные | отправляются повторно | остаются потерянными |
| Порядок | восстанавливается | не гарантируется |
| Заголовок | не менее 20 байт | 8 байт |
| Скорость | немного медленнее, больше пакетов | быстро, мало накладных расходов |

Когда меньше — значит лучше?

- **Реальное время:** при видеосвязи, интернет-телефонии или в онлайн-играх важна каждая миллисекунда. Потерянный фрагмент звука, который доставят секунду спустя, уже никому не нужен — лучше короткий треск, чем задержка.
- **Короткие запросы:** **DNS**-запрос («Какой IP-адрес у `www.beispiel.de`?») умещается в одну датаграмму, ответ тоже. Установление соединения увеличило бы затраты втрое. Если ответа нет, программа просто спрашивает ещё раз.

Везде, где должен дойти каждый байт — веб-страницы, электронные письма, загрузки, — правильный выбор, напротив, TCP.

:::tip Запомни
**TCP** надёжен, но требует больше затрат — для всего, что должно дойти **полностью** (веб, электронная почта, файлы). **UDP** быстр и лёгок, но без гарантий — для **реального времени** (телефония, видео, игры) и **коротких запросов**, таких как DNS.
:::

Теперь ты знаешь инструменты транспортного уровня. В следующей главе ты рассмотришь протоколы, которые работают поверх него: HTTP, DNS, электронную почту и DHCP.
