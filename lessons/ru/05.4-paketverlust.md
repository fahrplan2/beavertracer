# Когда пакеты теряются

:::goal
**Цель обучения:** Ты можешь с помощью трассировки наблюдать и объяснять, как TCP замечает потерянные данные, отправляет их повторно и восстанавливает порядок.
:::

:::sim
url=/sims/lesson-5.4.btsim
:::

В этой симуляции кабель специально подготовлен: **второй пакет с данными** от Client-PC к серверу теряется. (Эту настройку ты найдёшь, если в режиме выполнения щёлкнешь по кабелю: **Целевая потеря пакетов**.)

## Эксперимент

1. Переключись в режим :fa-play: **Запустить**, открой на **Client-PC** **Простой TCP-клиент** и подключи его к `192.168.0.20`, порт `5000`.
2. Отправь друг за другом три сообщения: `Hallo`, затем `Welt`, затем `!`.
3. Понаблюдай за окном чата: эхо для `Hallo` приходит сразу. А два других?
4. Подожди несколько секунд. Затем в режиме :fa-magnifying-glass: **Трассировка** открой трассу для **сервера** (получатель), интерфейс `eth0`.

:::quiz mc
Что происходит с эхо-ответами для `Welt` и `!`?
- [ ] Эхо для `!` приходит сразу, а `Welt` пропадает навсегда
- [x] Оба приходят только через несколько секунд — вместе и в правильном порядке
- [ ] Ни один из них не приходит никогда
:::

## Что показывает трассировка

На сервере пакета с `Welt` нет — он ведь потерялся. Зато в столбце **Info** ты найдёшь три пометки в квадратных скобках:

| Пометка | Что произошло |
|---|---|
| `[TCP Previous segment not captured]` | Пакет с `!` приходит, но перед ним не хватает байтов — **пропуск**. |
| `[TCP Dup ACK …]` | Сервер ещё раз подтверждает тот же номер, что и раньше (*duplicate ACK*): «Я всё ещё жду байт 8». |
| `[TCP Retransmission]` | Клиент отправляет `Welt` **ещё раз**. |

:::quiz short
Какой порядковый номер (`Seq`) у пакета, помеченного `[TCP Retransmission]`?
= 8
:::

:::quiz short
Какой номер подтверждения (`Ack`) сервер отправляет сразу после повторной передачи?
= 17
:::

:::quiz mc
Почему после повторной передачи сервер сразу подтверждает данные до байта 17, а не только до конца `Welt`?
- [x] Он уже получил `!` и придержал его — с приходом `Welt` пропуск закрыт, и теперь всё до байта 16 на месте
- [ ] Клиент ещё раз отправил `Welt` и `!` вместе
- [ ] Номера подтверждения всегда округляются
:::

:::evaluate
Проверить ответы
:::

На диаграмме последовательности это выглядит так — пунктирная стрелка с ✕ обозначает потерянный пакет:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hallo" len=7
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=7
Client-PC -> Server: ACK
Client-PC -x Server: PSH, ACK "Welt" len=6
Client-PC -> Server: PSH, ACK "!" len=3
Server -> Client-PC: ACK
Client-PC -> Server: PSH, ACK "Welt" len=6 seq=8
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=9
Client-PC -> Server: ACK
:::

## Что за этим стоит

Клиент хранит каждый отправленный пакет, пока тот не подтверждён, и запускает для него **таймер**. Если подтверждение не приходит слишком долго, он отправляет данные снова — это **повторная передача** (*Retransmission*).

Сервер всегда подтверждает данные только до **первого пропуска**. Данные, пришедшие после него (здесь `!`), он придерживает, пока пропуск не будет заполнен. Только тогда он передаёт всё программе в правильном порядке — поэтому эхо для `Welt` и `!` пришли вместе.

:::tip Запомни
TCP распознаёт потери по **отсутствию подтверждений**: получатель всегда подтверждает данные только до первого пропуска. Если подтверждение не приходит, отправитель по истечении таймера отправляет данные **повторно** (*Retransmission*). Всё, что пришло после пропуска, получатель придерживает — так данные попадают в программу **полностью и в правильном порядке**.
:::

:::tip Углублённо: Fast Retransmit
Отправь после `Hallo` четыре или больше сообщений быстро одно за другим. После потерянного пакета клиент получит подряд три *Dup ACK* — и сразу отправит данные заново, не дожидаясь своего таймера. Этот механизм называется **Fast Retransmit**.
:::

:::note
Настоящие реализации TCP, кроме того, подстраивают скорость отправки: если пакеты теряются, сеть, вероятно, перегружена, и отправитель замедляется (*управление перегрузкой*). Это выходит за рамки данного курса.
:::
