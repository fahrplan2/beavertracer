# Цифровые подписи

Шифрование обеспечивает **конфиденциальность**, а по хеш-значениям можно обнаружить изменения. Но как доказать, **от кого** пришло сообщение? На бумаге для этого ставят подпись. В сети для этого есть **цифровая подпись**.

## Пара ключей, использованная наоборот

При шифровании отправитель использует **открытый** ключ получателя. При подписи всё наоборот: отправитель использует **свой собственный закрытый** ключ. Поскольку этот ключ есть только у него, только он и может создать такую подпись. А вот проверить её может любой — с помощью **открытого** ключа отправителя.

**Подписание** (Anna подписывает договор):

1. Anna вычисляет **хеш-значение** договора.
2. Она обрабатывает хеш-значение своим **закрытым ключом**. Результат — **подпись**.
3. Она отправляет договор вместе с подписью Ben.

**Проверка** (Ben проверяет подпись):

1. Ben сам вычисляет хеш-значение полученного договора.
2. Он проверяет подпись с помощью **открытого ключа** Anna: соответствует ли она этому хеш-значению?
3. Если она соответствует, Ben знает сразу две вещи:
    - Договор действительно пришёл от Anna — закрытый ключ есть только у неё (**аутентичность**).
    - Договор не был изменён по пути — иначе у него было бы другое хеш-значение (**целостность**).

:::note
Почему Anna подписывает только хеш-значение, а не весь договор? Асимметричные алгоритмы работают медленно. Хеш-значение всегда короткое — независимо от того, состоит ли договор из одной страницы или из тысячи.
:::

:::tip Запомни
**Цифровую подпись** отправитель создаёт из **хеш-значения** сообщения и своего **закрытого ключа**. Любой может проверить её с помощью **открытого ключа** отправителя. Действительная подпись доказывает, **от кого** пришло сообщение (**аутентичность**) и что оно **не было изменено** (**целостность**).
:::
