# Что должен обеспечивать транспортный уровень?

:::sim
url=/sims/lesson-5.1.btsim
:::

На **Server** одновременно работают две службы: **веб-сервер** и небольшая **echo-служба**, которая сразу отправляет обратно каждое полученное сообщение. С помощью двух экспериментов ты выяснишь, чего одному IP не хватает.

## Эксперимент 1: две программы одновременно

1. Перейди в режим выполнения :fa-play: **Запустить** и щёлкни по **Client-PC**.
2. Открой :fa-globe: **Браузер** и перейди по адресу `http://192.168.0.20/`.
3. Нажми вверху окна **Назад** и открой **Простой TCP-клиент**. В поле **Host** введи `192.168.0.20`, в поле **Port** — `5000` и нажми **Подключиться**.
4. Перейди в режим :fa-magnifying-glass: **Трассировка** и с помощью **+** открой трассировку для **Client-PC**, порт `eth0`.

Щёлкни по пакету браузера (например, `GET /`) и по пакету TCP-клиента и в каждом раскрой **Internet Protocol Version 4**.

:::quiz mc
Какие IP-адреса указаны в пакетах браузера и TCP-клиента?
- [x] У обоих одинаковые: от `192.168.0.10` к `192.168.0.20`
- [ ] Браузер использует другой IP-адрес назначения, чем TCP-клиент
- [ ] У пакетов TCP-клиента нет IP-адреса
:::

:::quiz mc
Достаточно ли IP-адреса назначения, чтобы сервер знал, к веб-серверу или к echo-службе относится пакет?
- [ ] Да
- [x] Нет — у обоих пакетов один и тот же IP-адрес назначения
:::

Что-то другое должно различать эти два соединения. Посмотри на столбец **Info** у пакетов с `[SYN]` — это первый пакет каждого соединения:

:::quiz short
Какое число стоит после стрелки `→` у **браузера**?
= 80
:::

:::quiz short
А у **TCP-клиента**?
= 5000
:::

:::evaluate
Проверить ответы
:::

Подробнее об этих числах — **портах** — ты узнаешь в разделе 5.3. Пока достаточно знать: только транспортный уровень позволяет нескольким программам одновременно обмениваться данными через *один* IP-адрес, и каждый пакет попадает к нужной программе. Это называется **мультиплексированием**.

## Эксперимент 2: когда пакет теряется

1. Перейди в режим выполнения :fa-play: **Запустить** и щёлкни по **кабелю** между Client-PC и Server.
2. В окне **Соединение** установи **Настроенную потерю пакетов** равной `25%`.
3. Открой на **Client-PC** :fa-terminal: **Терминал** и отправь шесть пингов:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Это займёт около получаса минуты — дождись, пока появится статистика.

:::quiz mc
Что происходит?
- [ ] На все шесть пингов приходит ответ
- [x] На некоторые пинги нет ответа — и никто не отправляет их повторно
- [ ] Потерянные пинги автоматически повторяются, пока не дойдут
:::

:::evaluate
Проверить ответ
:::

Для пинга это не проблема — он как раз и должен показать, теряется ли что-то. Но для веб-страницы, электронного письма или загрузки отсутствующий фрагмент был бы фатальным: файл оказался бы повреждён.

## Четыре задачи транспортного уровня

| Задача | Что это означает |
|---|---|
| **Мультиплексирование** | Несколько программ и соединений делят один IP-адрес; каждый пакет попадает к нужной программе. |
| **Установление соединения** | Прежде чем пойдут данные, обе стороны договариваются, что будут обмениваться ими друг с другом. |
| **Надёжная передача** | Получатель подтверждает, что дошло. Недостающее отправляется повторно, порядок восстанавливается. |
| **Разрыв соединения** | В конце обе стороны упорядоченно завершают соединение. |

:::tip Запомни
**Транспортный уровень** (уровень 4) обеспечивает доставку данных нужной **программе** (**мультиплексирование**). Протокол **TCP** дополнительно гарантирует, что они дойдут **полностью** и в **правильном порядке** — с установлением соединения, подтверждениями, повторной передачей и разрывом соединения.
:::
