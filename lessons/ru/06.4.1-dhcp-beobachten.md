К коммутатору подключены **DHCP сервер** и два ноутбука. Пока у ноутбуков статические адреса.

## Эксперимент

1. Перейди в режим выполнения :fa-play: **Запустить**, щёлкни по **Laptop 1** и открой :fa-gear: **Параметры IP**.
2. Переключи **Режим** со **Статический** на **DHCP** и нажми **Применить**.
3. Подожди несколько секунд: поля заполнятся сами.
4. В режиме :fa-magnifying-glass: **Трассировка** открой трассу для **Laptop 1**.

## Что за этим стоит: DORA

Устройство без адреса не знает, где находится DHCP-сервер, и у него нет собственного адреса отправителя. Поэтому оно обращается ко всем в сети с помощью **широковещательной рассылки**. Процесс состоит из четырёх шагов — по их начальным буквам он называется **DORA**:

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | „Есть ли здесь DHCP-сервер?“
DHCP-Server -> Laptop 1: DHCP Offer | „Ты можешь получить 192.168.0.100.“
Laptop 1 -> DHCP-Server: DHCP Request | „Я беру 192.168.0.100.“
DHCP-Server -> Laptop 1: DHCP ACK | „Подтверждаю — действует 3600 секунд.“
:::

Адрес выдаётся только **во временное пользование** (*Lease*, аренда): по истечении **времени аренды** устройство должно продлить её, иначе сервер может выдать этот адрес снова. Какие адреса выданы в данный момент, ты увидишь в **DHCP сервер** на вкладке **Leases**.

:::tip Попробуй сам
Переведи **Laptop 2** тоже на DHCP. Какой адрес он получит? Затем загляни в **Leases** DHCP-сервера.
:::

:::tip Запомни
**DHCP** автоматически раздаёт IP-адрес, маску сети, шлюз и DNS-сервер. Процесс называется **DORA**: **D**iscover (клиент ищет сервер широковещательно), **O**ffer (сервер предлагает адрес), **R**equest (клиент принимает предложение), **A**CK (сервер подтверждает). Адрес выдаётся на **время аренды**. DHCP использует **UDP**, порты 67 (сервер) и 68 (клиент).
:::

:::quiz match
Discover -> Клиент ищет DHCP-сервер с помощью широковещательной рассылки
Offer -> Сервер предлагает адрес
Request -> Клиент запрашивает предложенный адрес
ACK -> Сервер подтверждает выдачу
:::
