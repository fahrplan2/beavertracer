# Соединяем две сети

:::sim

У маршрутизатора два интерфейса:

| Интерфейс | IP-адрес | Сеть |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Чтобы компьютеры использовали маршрутизатор, на каждом из них указан **шлюз**: у Anna и Ben — `192.168.0.1`, у Clara и David — `172.16.0.1`. Ты найдёшь его в :fa-gear: **Параметры IP** в поле **Gateway**.

:::tip Запомни
**Шлюз** (точнее: *шлюз по умолчанию*) — это IP-адрес маршрутизатора **в собственной сети**. Компьютер отправляет шлюзу все пакеты, адрес назначения которых находится в другой сети.
:::

## Эксперимент

1. Перейди в :fa-play: режим выполнения (**Запустить**) и пингуй Clara с компьютера **Anna** (`ping 172.16.0.10`). На этот раз всё получится — обрати внимание в выводе на значение `ttl=`.

## Что маршрутизатор делает с пакетом

Маршрутизатор принимает кадр от Anna, извлекает IP-пакет и смотрит на **IP-адрес назначения**. По нему он определяет: Clara находится в сети на интерфейсе `eth1`. Поэтому он упаковывает пакет в **новый** кадр — со своим собственным MAC-адресом в качестве отправителя и MAC-адресом Clara в качестве получателя — и отправляет его туда.

| Что происходит на маршрутизаторе с … | |
|---|---|
| MAC-адресами (уровень 2)? | устанавливаются **заново** — они действуют только в своей сети |
| IP-адресами (уровень 3)? | **остаются прежними** — от Anna до Clara |
| Time to Live? | **уменьшается на 1** |

:::tip Запомни
**Маршрутизатор** работает на **уровне 3**: он пересылает пакеты в другие сети на основе **IP-адреса назначения**. IP-адреса остаются прежними на всём пути, а MAC-адреса в каждой сети устанавливаются заново. Каждый маршрутизатор уменьшает **Time to Live (TTL)** на 1 — когда значение достигает 0, пакет отбрасывается. Так пакет не может бесконечно ходить по кругу.
:::

:::note
Помнишь широковещательный шторм из главы 3.4? У кадров Ethernet нет TTL — а у IP-пакетов есть.
:::

## Кого знает Anna? ARP-кэш

Помнишь главу 1.2.3? Там ARP появлялся только перед *первым* пингом, потому что компьютер запомнил ответ. Этот список запомненного называется **ARP-кэш** (также *ARP-таблица*). Запрос называют **ARP-запросом** (*ARP Request*), а ответ — **ARP-ответом** (*ARP Reply*, или *ARP Response*).

Перейди в :fa-play: режим выполнения (**Запустить**), открой на **Anna** :fa-terminal: **Терминал** и выведи её ARP-кэш:

```
$ arp
```

:::quiz mc
Что находится в ARP-кэше Anna?
- [x] Только IP-адрес маршрутизатора (`192.168.0.1`) с его MAC-адресом
- [ ] IP-адрес Clara с MAC-адресом Clara
- [ ] Адреса маршрутизатора и Clara
:::

:::evaluate
Проверить ответ
:::

Anna никогда не нужен MAC-адрес Clara: всё, что предназначено для Firma B, она отправляет маршрутизатору. MAC-адрес Clara знает только маршрутизатор — он сам запросил его по ARP со своей стороны.

:::tip Запомни
В **ARP-кэше** устройство запоминает, какой MAC-адрес соответствует какому IP-адресу — так ему не нужно отправлять ARP-запрос перед каждым пакетом. Показать его можно командой `arp`. Компьютер знает только MAC-адреса из **своей** сети: для всех получателей в других сетях он использует MAC-адрес маршрутизатора.
:::

:::note
В реальных сетях записи в ARP-кэше через некоторое время удаляются и при необходимости запрашиваются заново — например, если у устройства тем временем появилась другая сетевая карта. В BeaverTracer они сохраняются, пока работает симуляция.
:::
