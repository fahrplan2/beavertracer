# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) — это самый обычный HTTP, только работает он не напрямую поверх TCP, а через промежуточный зашифрованный уровень: **TLS** (*Transport Layer Security*). Предшественник TLS назывался **SSL**, поэтому до сих пор часто говорят «SSL-сертификаты».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP об этом ничего не знает: он отправляет свои запросы как обычно, TLS шифрует их, а TCP передаёт. В модели OSI TLS находится между транспортным и прикладным уровнями, то есть на уровне 4/5 — он опирается на TCP и управляет защищённым сеансом.

| | HTTP | HTTPS |
|---|---|---|
| Порт | 80 | **443** |
| Адрес | `http://…` | `https://…` |
| Содержимое читается в трассировщике? | да | нет |
| Браузер показывает | «не защищено» | замок |

При установлении соединения TLS выполняет всё, что ты изучил в этой главе:

- Сервер подтверждает свою личность с помощью **сертификата** (**аутентичность**).
- Обе стороны согласуют **сеансовый ключ** с помощью **Диффи — Хеллмана** — сервер **подписывает** свою часть.
- После этого все данные шифруются с помощью **AES** (**конфиденциальность**) и защищаются от изменения (**целостность**).

Этот принцип не ограничивается вебом: электронная почта (раздел 8.4) и многие другие протоколы работают через TLS точно так же.

В следующих разделах ты понаблюдаешь за HTTPS в трассировщике, сам настроишь его и выяснишь, когда браузер выдаёт предупреждение — и почему.
