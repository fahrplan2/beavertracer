# Сертификаты: кому принадлежит этот ключ?

Кажется, что с асимметричным шифрованием и подписями всё решено: веб-сервер твоего банка присылает тебе свой открытый ключ, и можно начинать. Но откуда ты знаешь, что этот открытый ключ **действительно принадлежит банку**?

Злоумышленник, который перенаправляет твоё соединение, мог бы просто прислать тебе **свой собственный** открытый ключ и заявить, что он и есть банк. Тогда твой браузер послушно зашифрует данные для злоумышленника, и тот прочитает всё. Такой злоумышленник «посередине» называется **Man-in-the-Middle** (человек посередине).

## Сертификат: удостоверение личности для ключей

В реальной жизни ты показываешь **паспорт**, чтобы доказать, кто ты. Паспорту верят, потому что его выдал **надёжный орган**, например городская администрация, и потому что его трудно подделать.

В сети эту задачу выполняет **сертификат**. Среди прочего он содержит:

| Поле | Значение | в паспорте |
|---|---|---|
| **Субъект** (*Subject*, часто `CN=…`) | Для кого выдан сертификат? У веб-серверов это имя, например `CN=www.biberbank.de` | имя владельца |
| **Открытый ключ** | Ключ владельца | фотография |
| **Издатель** (*Issuer*) | Кто выдал сертификат? | орган, выдавший документ |
| **Срок действия** | с … по … | действителен до |
| **Подпись** издателя | Доказывает, что издатель действительно выдал сертификат именно в таком виде | печать, голограмма |

`CN` означает *Common Name* (общее имя).

Организация, которая выдаёт сертификаты, называется **центром сертификации** (*Certificate Authority*, сокращённо **CA**). Прежде чем подписать сертификат для `www.biberbank.de`, она проверяет, что заявитель действительно владеет этим доменом.

## Кому доверяет браузер?

Для каждого сертификата твой браузер проверяет:

1. Подлинна ли **подпись** CA? (Для этого ему нужен открытый ключ CA.)
2. Действителен ли сертификат ещё, то есть не истёк ли его **срок действия**?
3. Совпадает ли **имя** в сертификате с запрошенным адресом?

Но откуда браузер знает CA? В каждой операционной системе и в каждом браузере **предустановлен** список примерно из 150 **корневых CA** (*Root-CA*). Их сертификаты **самоподписанные**: они подтверждают сами себя. Им доверяют, потому что они поставляются вместе с программным обеспечением.

Часто корневой CA подписывает сертификаты не напрямую, а через **промежуточный CA**. Так возникает **цепочка доверия**:

```
Root-CA (vorinstalliert, vertraut)
  └─ signiert → Zwischen-CA
                  └─ signiert → www.biberbank.de
```

Браузер идёт по цепочке снизу вверх, пока не дойдёт до корневого CA, которому доверяет. Если это не получается, а также если срок действия или имя не подходят, он показывает **предупреждение**.

:::quiz match
Субъект (CN) -> Для какого имени действителен сертификат
Издатель -> Какой CA подписал сертификат
Открытый ключ -> Нужен для проверки подписей сервера
Корневой CA -> Предустановлен в браузере и является началом цепочки доверия
:::

:::tip Запомни
**Сертификат** подтверждает, что **открытый ключ** принадлежит определённому **имени**. Его подписывает **центр сертификации (CA)**. Браузер доверяет сертификату, если по **цепочке доверия** доходит до предустановленного **корневого CA**, сертификат **действителен** и **имя** совпадает с адресом.
:::
