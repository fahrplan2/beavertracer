## Эксперимент

1. Перейди в режим :fa-play: **Запустить**, нажми на **Client-PC** и открой :fa-globe: **Браузер**. Открой `http://192.168.0.20/`.
2. Нажми вверху окна **Назад**, открой **Простой TCP-клиент** и подключи его к `192.168.0.20`, порт `5000`. Оставь соединение открытым.
3. Перейди в режим :fa-magnifying-glass: **Трассировка**, открой трассировку для **Client-PC** и нажми на пакет с `[SYN]`. Разверни **Transmission Control Protocol**.

В самом верху заголовка TCP указаны два порта: **Source Port** (порт источника) и **Destination Port** (порт назначения).

:::quiz table
| Соединение | Порт источника | Порт назначения |
|---|---|---|
| Браузер → веб-сервер | {49152} | {80} |
| TCP-клиент → эхо-сервис | {49153} | {5000} |
:::

## Два вида портов

**Порт назначения — сервис:** серверная программа ждёт соединений на фиксированном порту — говорят, что она **прослушивает** его. Для известных сервисов номера закреплены по всему миру — это **Well-known Ports** (общеизвестные порты, от 0 до 1023). Поэтому браузер без лишних вопросов знает: веб-серверы прослушивают порт 80.

**Порт источника — отправитель:** порт на стороне клиента операционная система сама выбирает для каждого нового соединения из верхнего диапазона (в BeaverTracer начиная с 49152). По нему клиент определяет, к какому из его соединений относится ответ.

Таким образом, соединение однозначно определяется четырьмя значениями: **IP-адрес и порт с обеих сторон**. Пара из IP-адреса и порта называется **сокетом**, например `192.168.0.20:80`.

## Взгляд на сервер

Вернись в режим :fa-play: **Запустить**, открой на **Server** :fa-terminal: **Терминал** и введи:

```
$ ss
```

`ss` показывает все сокеты компьютера. Строки с `LISTEN` — это программы, прослушивающие порт. Строки с `ESTABLISHED` — установленные соединения — с собственным сокетом (*Local Address:Port*) и сокетом противоположной стороны (*Peer Address:Port*).

- [x] 5000
- [ ] 49152
- [ ] 443
:::

Соединение браузера уже разорвано — после загрузки страницы оно было завершено с помощью `FIN`. `ss` ещё некоторое время показывает его как `TIME-WAIT`: сервер какое-то время ждёт, не придут ли ещё запоздавшие пакеты этого соединения. Соединение TCP-клиента, напротив, всё ещё открыто, потому что ты ещё не нажал **Отключиться**.

## Важнейшие Well-known Ports

| Порт | Протокол | Сервис |
|---|---|---|
| 22 | SSH | безопасное удалённое администрирование (зашифрованная командная строка) |
| 25 | SMTP | отправка электронной почты |
| 53 | DNS | преобразование имён в IP-адреса (в основном по UDP) |
| 80 | HTTP | веб-страницы |
| 110 | POP3 | получение электронной почты |
| 143 | IMAP | управление письмами на сервере |
| 443 | HTTPS | зашифрованные веб-страницы |

:::tip Запомни
**Порты** (от 0 до 65535) разделяют соединения на одном компьютере. Серверные сервисы **прослушивают** фиксированные **Well-known Ports** (например, HTTP 80, HTTPS 443), а клиенты получают для каждого соединения свободный высокий **порт источника**. Соединение однозначно определяется **IP-адресом и портом обеих сторон**.
:::
