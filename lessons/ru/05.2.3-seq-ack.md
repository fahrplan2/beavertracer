# Порядковые номера и номера подтверждения

:::sim
url=/sims/lesson-5.1.btsim
:::

Откуда TCP знает, что всё дошло — и в каком порядке? Каждая сторона **нумерует байты**, которые отправляет:

- **Порядковый номер** (`SEQ`) — это номер первого байта, который находится в этом пакете.
- **Номер подтверждения** (`ACK`) говорит: «Всё до этого места я получил — следующим жду байт № …»

К этому два правила: `SYN` и `FIN` считаются как один байт, хотя данных не несут. И каждая сторона считает отдельно — поэтому есть две нумерации: на диаграмме красная (клиент) и синяя (сервер).

## Проверяем расчётом

Вот снова твоё соединение. Числа на линиях показывают счётчик компьютера в этой точке:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Пройдись по красному ряду чисел:

1. Клиент начинает с `SEQ=0`. Его `SYN` занимает один номер — сервер подтверждает с `ACK=1`.
2. Сообщение начинается с `SEQ=1` и имеет длину 13 байт (байты с 1 по 13). Сервер подтверждает с `ACK=14`: «Следующим жду байт 14».
3. Поэтому `FIN` клиента имеет `SEQ=14` и подтверждается с `ACK=15`.

Синий ряд сервера работает точно так же.

:::tip Запомни
**Порядковый номер** (`SEQ`) — это номер первого байта в пакете. **Номер подтверждения** (`ACK`) — это номер следующего байта, который ожидает получатель; всё, что было до него, дошло. Действует правило: **ACK = SEQ + длина** полученных данных; `SYN` и `FIN` считаются как один байт. Каждая сторона считает свои собственные байты.
:::

Ещё раз установи соединение в **Простой TCP-клиент** и отправь два сообщения подряд. Заранее скажи, какие `Seq` и `Ack` будут в столбце **Info** — и проверь это в трассировке.

:::note
В реальных сетях отсчёт начинается не с 0: каждая сторона выбирает **случайный начальный номер** (*Initial Sequence Number*, ISN) от 0 до примерно 4,3 миллиарда. Когда достигнут наибольший номер, счёт снова продолжается с 0. Трассировщик вычитает начальный номер и показывает **относительные** номера — точно так же, как Wireshark. Поэтому ты видишь `Seq=0` и `Seq=1`.

Кроме того, в каждом пакете есть `Win=` — **размер окна**: столько байт получатель может принять в данный момент. Так он притормаживает слишком быстрого отправителя (*управление потоком*). В BeaverTracer окно всегда одного и того же размера.
:::
