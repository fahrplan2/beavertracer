# Создание собственного УЦ

:::sim
url=/sims/lesson-8.2.2.btsim
:::

Для `www.beaver-schule.de` пока нет сертификата. Вместо того чтобы заказывать его в коммерческом УЦ, школа создаёт **собственный УЦ** (удостоверяющий центр): **Schul-CA**. Так поступают многие компании и школы для своих внутренних серверов.

В реальности Schul-CA работал бы на отдельном, особенно хорошо защищённом компьютере. Здесь ты играешь все роли на самом веб-сервере.

## Шаг 1: создаём Schul-CA

1. Перейди в режим :fa-play: **Запустить** и открой на веб-сервере **www.beaver-schule.de** :fa-shield-halved: **Zertifikatverwaltung**.
2. На вкладке **Generieren**:
    - **Common Name:** `Schul-CA`
    - **Typ:** Selbstsigniert
    - Поставь галочку **Dies ist ein CA-Zertifikat**
    - **Speichern unter:** `schul-ca.cert.json`
3. Нажми **Zertifikat generieren**.

При этом создаётся новая **пара ключей**. Сертификат содержит открытый ключ; закрытый ключ остаётся в файле на веб-сервере.

## Шаг 2: выпускаем сертификат сервера

Снова на вкладке **Generieren**:

- **Common Name:** `www.beaver-schule.de` — именно то имя, которое вводят в браузере
- **Typ:** Von CA signiert, **Signierende CA:** Schul-CA
- **Speichern unter:** например, `www.beaver-schule.de.cert.json`

На вкладке **Meine Zertifikate** теперь видны оба сертификата. Нажми на новый сертификат сервера:

:::quiz short
Кто является **издателем** (Aussteller) сертификата сервера (без `CN=`)?
= Schul-CA
:::

:::quiz mc
Как выглядит его **цепочка** (Kette)?
- [x] `www.beaver-schule.de ← Schul-CA`
- [ ] `Schul-CA ← www.beaver-schule.de`
- [ ] `www.beaver-schule.de` (самоподписанный)
:::

## Шаг 3: учим клиента доверять Schul-CA

Клиентский ПК пока не знает Schul-CA — в его браузере она не установлена заранее. Тебе нужно передать ему её сертификат, причём **без закрытого ключа**:

1. На веб-сервере на вкладке **Meine Zertifikate** выбери **Schul-CA** и нажми **Kopieren** (а не *Kopieren + Schlüssel*!).
2. На **клиентском ПК** открой :fa-shield-halved: **Zertifikatverwaltung**, вкладка **Vertrauenswürdige CAs**.
3. Нажми **Einfügen: Schul-CA**.

:::warning
**Закрытый ключ УЦ** — самый ценный секрет всей инфраструктуры: тот, у кого он есть, может выпускать сертификаты для **любых** имён, и все клиенты будут им доверять. Он ни в коем случае не должен покидать компьютер УЦ.
:::

:::task
title: Schul-CA настроен?
Проверьте, есть ли на веб-сервере сертификат для www.beaver-schule.de, выпущенный Schul-CA, и доверяет ли клиентский ПК Schul-CA.
check: hasCert(4, "www.beaver-schule.de", "Schul-CA")
check: trusts(2, "Schul-CA")
:::

Почему для клиента ты копируешь только сертификат **без** закрытого ключа?

- [x] Для проверки подписей достаточно открытого ключа; имея закрытый ключ, любой на клиенте мог бы сам выпускать сертификаты
- [ ] Потому что иначе клиент не сможет установить соединение

Сам веб-сервер ты пока не перенастраивал — он по-прежнему работает только по HTTP. Как включить HTTPS, ты узнаешь в разделе 8.3.3.

:::tip Запомни
**Собственный УЦ** состоит из **самоподписанного сертификата УЦ** с закрытым ключом. С его помощью выпускают **сертификаты серверов**, у которых Common Name совпадает с именем сервера. Чтобы клиенты доверяли этим сертификатам, их список **доверенных УЦ** пополняют **сертификатом УЦ без закрытого ключа**.
:::
