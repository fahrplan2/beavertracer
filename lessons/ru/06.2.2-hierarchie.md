# Как организована DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Ни один сервер не может знать все имена в мире. Поэтому DNS устроена **иерархически** — так же, как и сами имена. Их читают справа налево:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Сервер, который отвечает за домен и действительно знает ответ, называется **авторитетным**. Путь до него вместо компьютера проходит **резолвер** — здесь это компьютер **DNS-Resolver**.

## Эксперимент

1. Перейди в режим :fa-play: **Запустить** и введи на **Client-PC** в :fa-terminal: **Терминал**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Открой в режиме :fa-magnifying-glass: **Трассировка** трассу для **DNS-Resolver**.

Резолвер отправил за тебя целую серию запросов. Сопоставь, кто какой ответ дал:

:::quiz match
Root-Server (192.168.0.101) -> Перенаправление: за .de отвечает ns.nic.de
de-Server (192.168.0.102) -> Перенаправление: за beaver-schule.de отвечает ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Ответ: у www.beaver-schule.de адрес 192.168.0.20
:::

:::quiz mc
Кого резолвер спрашивает первым?
- [x] Корневой сервер
- [ ] Schul-DNS
- [ ] Client-PC
:::

:::evaluate
Проверить ответы
:::

:::note
Между делом резолвер также запрашивает адреса серверов, на которые его перенаправили (`A ns.nic.de`). Настоящие DNS-серверы обычно сразу присылают эти адреса вместе с ответом. Кроме того, резолверы некоторое время запоминают каждый ответ (**кеш**) — на следующий запрос того же имени они отвечают сами и сразу. Как долго, указано в записи как **TTL** (*Time to Live*) в секундах.
:::

## Важнейшие типы записей

| Тип | Значение | Пример |
|---|---|---|
| **A** | имя → адрес IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | имя → адрес IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | имя → другое имя (псевдоним) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | почтовый сервер, отвечающий за домен | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | DNS-сервер, отвечающий за домен | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Запомни
DNS **иерархична**: **корневые серверы** указывают на серверы **доменов верхнего уровня** (например, `.de`), а те — на серверы отдельных **доменов**. Ответственный **авторитетный** сервер знает ответ. **Резолвер** проходит этот путь за компьютер и запоминает ответы (**кеш**). Важные типы записей: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Создание записи

Школа хочет, чтобы её сайт был доступен дополнительно по адресу `intranet.beaver-schule.de`.

1. В режиме :fa-play: **Запустить** щёлкни по **Schul-DNS** и открой приложение **DNS-Server**.
2. Открой вкладку **A**. Нажми **+** и впиши в новую строку имя `intranet.beaver-schule.de` и адрес `192.168.0.20`.
3. Проверь на Client-PC командой `nslookup intranet.beaver-schule.de`.

:::task
title: Новое имя внесено?
Проверяется, разрешает ли Client-PC имя intranet.beaver-schule.de в адрес веб-сервера. Для этого симуляция должна работать в режиме выполнения.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
