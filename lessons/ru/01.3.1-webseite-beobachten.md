# Открываем веб-страницу и наблюдаем

В этой части ты ничего не собираешь сам: на рабочей области уже лежит подготовленная симуляция с **Client-PC** и **Webserver**.

## Открываем страницу

1. Перейди в режим :fa-play: **Запустить**.
2. На **Client-PC** открой приложение :fa-globe: **Браузер** и введи адрес веб-сервера: `http://192.168.0.20/`.
3. Перейди в режим :fa-magnifying-glass: **Трассировка** и с помощью **+** открой трассировку для **Client-PC**, порт `eth0` — точно так же, как при пинге.

:::note
Для одного-единственного обращения к странице это удивительно много пакетов — гораздо больше, чем при пинге. Получение веб-страницы — многоступенчатый процесс, а не одно действие.
:::

## Читаем список пакетов

Тебе пока не нужно знать, что именно делает каждый протокол. Всё, что понадобится для следующих вопросов, есть в столбцах **Протокол** и **Info**.

:::quiz mc
Какой протокол стоит в самом верху списка?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Посчитай: сколько **TCP**-пакетов стоит перед первым **HTTP**-пакетом?
= 3
= три
:::

:::quiz mc
Что отвечает веб-сервер на запрос браузера? Посмотри в столбец Info второго HTTP-пакета.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Проверить ответы
:::

## Называем задействованные протоколы

По твоим наблюдениям теперь можно определить, какой протокол за что отвечал.

:::tip Подсказка
Перечитай столбцы **Info** ещё раз: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` и `200 OK` уже почти всё объясняют.
:::

:::quiz match
ARP -> Спрашивает всех в сети: «У кого IP-адрес 192.168.0.20?»
TCP -> Устанавливает соединение тремя короткими пакетами, прежде чем начнётся передача данных
HTTP -> Запрашивает веб-страницу (GET) и возвращает её (200 OK)
:::

:::evaluate
Проверить соответствие
:::

:::tip Запомни
Открытие веб-страницы проходит в несколько этапов: сначала **найти** сервер в сети (ARP), затем **установить** соединение (TCP), затем **запросить и получить** страницу (HTTP) — и в конце снова **разорвать** соединение (TCP-пакеты с `[FIN]` в конце списка).
:::

:::note
В этот раз ты ввёл IP-адрес сервера напрямую, поэтому **DNS** («перевод» имён вроде `www.beispiel.de` в IP-адрес) пока не использовался. Мы вернёмся к этому в главе 6.
:::

Ты заметил, что у протоколов в структуре пакета есть цветные метки с цифрами? Что это значит, мы выясним в главе 2. Там мы посмотрим, как систематически классифицировать множество протоколов — с помощью эталонных моделей OSI и TCP/IP. На этом глава 1 завершена.
