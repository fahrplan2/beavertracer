# Гибридное шифрование

Подведём итог:

| | симметричное (например, AES) | асимметричное (например, RSA) |
|---|---|---|
| Ключ | один общий секретный ключ | пара ключей: открытый + закрытый |
| Скорость | очень высокая | низкая |
| Обмен ключами | проблема: как ключ попадёт к получателю? | не проблема: открытый ключ можно пересылать открыто |

У каждого метода есть сильная сторона, которой нет у другого. Решение: объединить оба. Это называется **гибридным шифрованием**.

1. В начале соединения обе стороны с помощью **асимметричного** метода договариваются об общем секретном ключе — **сеансовом ключе**. Это занимает некоторое время, но происходит только **один раз**.
2. После этого все данные шифруются **симметрично** с помощью сеансового ключа — быстро.
3. В конце соединения сеансовый ключ выбрасывается. Следующее соединение получает новый.

Так работают **HTTPS**, защищённые соединения электронной почты, **Wi-Fi** с WPA3, **SSH** и **VPN**.

## Общий секрет с помощью смешивания цветов

Элегантный способ договориться о сеансовом ключе — **обмен ключами Диффи — Хеллмана** (1976). Его можно представить с помощью цветов. Суть в том, что смешать цвета легко, а разложить смесь обратно на составляющие практически невозможно.

1. Анна и Бен **открыто** договариваются об общем основном цвете, например **жёлтом**. Его может знать любой.
2. Каждый тайно выбирает **секретный цвет**: Анна — **красный**, Бен — **синий**.
3. Каждый смешивает свой секретный цвет с основным и отправляет результат другому **открыто**: Анна отправляет **жёлтый + красный** (оранжевый), Бен отправляет **жёлтый + синий** (зелёный).
4. Теперь каждый подмешивает свой собственный секретный цвет в смесь другого:
    - Анна: зелёный + красный = **жёлтый + синий + красный**
    - Бен: оранжевый + синий = **жёлтый + красный + синий**
5. Теперь у обоих **один и тот же** цвет (коричневый) — общий ключ.

Подслушивающий видел жёлтый, оранжевый и зелёный. Но чтобы получить коричневый, ему нужен красный или синий, а их Анна и Бен никогда не пересылали.

В реальности, конечно, вычисления выполняются не с цветами, а с очень большими числами. В трассировке ты скоро снова встретишь этот обмен в виде **Server Key Exchange** и **Client Key Exchange** — «**DHE**» в **ECDHE** означает *Diffie-Hellman Ephemeral*, то есть Диффи — Хеллман с одноразовыми ключами.

:::warning
Один лишь обмен Диффи — Хеллмана не защищает от атакующего, который встаёт посередине и договаривается о собственном ключе отдельно с Анной **и** отдельно с Беном. Поэтому Анна должна быть уверена, что она действительно общается с Беном. Для этого нужны **подписи** и **сертификаты** — это тема следующего урока.
:::

:::tip Запомни
**Гибридное шифрование** объединяет оба подхода: с помощью **асимметричного** метода (например, Диффи — Хеллмана) обе стороны договариваются о секретном **сеансовом ключе**, а сами данные затем шифруются **симметрично** (например, с помощью AES). Так работают HTTPS, шифрование Wi-Fi, SSH и VPN.
:::
