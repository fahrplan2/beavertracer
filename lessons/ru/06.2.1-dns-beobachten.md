## Эксперимент

1. Перейди в режим выполнения :fa-play: **Запустить**, щёлкни на **Client-PC** и открой :fa-globe: **Браузер**.
2. На этот раз открой `http://www.beaver-schule.de/` — с именем вместо IP-адреса.
3. Перейди в режим :fa-magnifying-glass: **Трассировка** и открой трассировку для **Client-PC**.

Только после того как Client-PC узнаёт IP-адрес, он устанавливает TCP-соединение с веб-сервером — точно так же, как в главе 5.

:::seq
mode: text
Client-PC -> DNS-Resolver: DNS-Anfrage | A www.beaver-schule.de?
DNS-Resolver -> Client-PC: DNS-Antwort | A 192.168.0.20
:::

## Откуда ПК знает DNS-сервер?

Открой на **Client-PC** :fa-gear: **Параметры IP**: в поле **DNS-Server** указан `192.168.0.53` — компьютер **DNS-Resolver**. Именно ему ПК отправляет каждый запрос имени.

Ты можешь обратиться к DNS-серверу и напрямую, без браузера. Открой :fa-terminal: **Терминал** и введи:

```
$ nslookup www.beaver-schule.de
```

`nslookup` сначала показывает, какой сервер он опросил, а затем ответ. Для сравнения запроси имя, которого не существует, например `nslookup gibtsnicht.beaver-schule.de`.

:::quiz mc
Что отвечает DNS-сервер на неизвестное имя?
- [ ] Случайный IP-адрес
- [x] `NXDOMAIN` — такого имени нет
- [ ] Вообще ничего
:::

:::evaluate
Проверить ответ
:::

:::tip Запомни
**DNS** преобразует имена (например, `www.beaver-schule.de`) в IP-адреса. Прежде чем ПК сможет установить соединение по имени, он обращается к **DNS-серверу**, указанному в его параметрах IP, — обычно по **UDP, порт 53**. С помощью `nslookup` ты можешь отправлять DNS-запросы вручную.
:::
