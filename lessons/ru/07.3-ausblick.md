# Перспективы: IPv6 и Carrier-Grade NAT

:::sim
empty
:::

NAT — гениальное временное решение проблемы нехватки адресов IPv4, но всё же только временное. Тебе стоит знать о двух направлениях развития.

## IPv6: NAT больше не нужен

В **IPv6** адресов в избытке (глава 4.6). Поэтому провайдер выдаёт домашнему маршрутизатору не просто один адрес, а целый **префикс** — часто `/56` или `/48`, то есть миллиарды адресов. Это называется **делегирование префикса** (DHCPv6-PD). Из этого префикса домашний маршрутизатор с помощью SLAAC выдаёт каждому устройству собственный **глобально уникальный** адрес.

Тогда NAT больше не нужен: каждое устройство адресуется напрямую. Это удобно, но требует хорошего **межсетевого экрана** в маршрутизаторе — ведь «побочный эффект» NAT, из-за которого никто снаружи не может инициировать соединение, исчезает. Этому посвящена глава 9.

## Carrier-Grade NAT: NAT у провайдера

Многим провайдерам самим не хватает адресов IPv4. Тогда даже домашний маршрутизатор не получает публичный адрес, а только адрес из специального диапазона (`100.64.0.0/10`), а провайдер выполняет **ещё один NAT** сразу для многих клиентов. Это называется **Carrier-Grade NAT** (CGNAT); часто для IPv4 тогда остаётся только такой вариант, а для IPv6 при этом выдаются настоящие публичные адреса (*DS-Lite*).

Следствие: **проброс портов** на собственном маршрутизаторе для IPv4 больше не помогает — пакеты снаружи застревают уже у провайдера. Тому, кто хочет запустить дома сервер, тогда нужен IPv6 или другое подключение.
