# Диаграмма последовательности

:::sim
url=/sims/lesson-5.1.btsim
:::

Ход соединения изображают в виде **диаграммы последовательности**: у клиента и сервера есть по одной вертикальной линии (линии жизни), а время идёт сверху вниз. Каждая стрелка — это пакет. Она нарисована наклонно, потому что каждый пакет какое-то время находится в пути.

Вот как выглядит твоё соединение с прошлой страницы — сравни его строка за строкой с трассировкой:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Над каждой стрелкой указаны **флаги**, под ней — номера `SEQ` и `ACK`. **DATA** отмечает пакеты с полезными данными. Красные числа относятся к клиенту, синие — к серверу; что они означают, объясняется на следующей странице.

## Флаги

| Флаг | расшифровка | Значение |
|---|---|---|
| **SYN** | *synchronize* | установить соединение, задать начальный номер |
| **ACK** | *acknowledge* | подтверждает полученные данные |
| **PSH** | *push* | немедленно передать данные приложению |
| **FIN** | *finish* | «Я закончил» — завершить соединение |
| **RST** | *reset* | прервать или отклонить соединение (подробнее в 5.3.2) |

## Три фазы

**Установление:** клиент отправляет `SYN`, сервер отвечает `SYN, ACK`, клиент подтверждает `ACK`. Поскольку нужно ровно три пакета, это называется **трёхстороннее рукопожатие**.

**Данные:** каждый пакет с данными получатель подтверждает пакетом `ACK`. Здесь сервер отправляет эхо обратно — и клиент тоже его подтверждает.

**Завершение:** каждая сторона закрывает своё направление передачи отдельно: `FIN` от клиента, `ACK` от сервера — затем `FIN` от сервера, `ACK` от клиента. Это четыре пакета.

:::tip Запомни
TCP-соединение проходит три фазы: **установление** с помощью **трёхстороннего рукопожатия** (`SYN` → `SYN, ACK` → `ACK`), **передача данных** (каждый пакет с данными подтверждается пакетом `ACK`) и **завершение** (каждая сторона отправляет `FIN` и получает `ACK`).
:::

## Теперь ты

На этот раз клиент отправляет только `Hi` (вместе с символом конца строки это 4 байта). Впиши недостающие флаги — порядок внутри одного поля не важен.

:::quiz seq
hide: counters
Client-PC -> Server: ? SYN
Server -> Client-PC: ? SYN, ACK
Client-PC -> Server: ? ACK
Client-PC -> Server: PSH, ACK "Hi" len=4
Server -> Client-PC: ? ACK
Client-PC -> Server: ? FIN, ACK
Server -> Client-PC: ? ACK
Server -> Client-PC: ? FIN, ACK
Client-PC -> Server: ? ACK
:::
