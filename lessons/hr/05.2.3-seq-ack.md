# Redni brojevi i brojevi potvrde

:::sim
url=/sims/lesson-5.1.btsim
:::

Kako TCP zna je li sve stiglo — i kojim redoslijedom? Svaka strana **numerira bajtove** koje šalje:

- **Redni broj** (`SEQ`) je broj prvog bajta koji se nalazi u ovom paketu.
- **Broj potvrde** (`ACK`) kaže: „Sve do ovdje sam primio — sljedeće očekujem bajt br. …“

Uz to dva pravila: `SYN` i `FIN` računaju se kao jedan bajt, iako ne nose podatke. I svaka strana broji za sebe — zato postoje dva niza brojeva, na dijagramu crveni (klijent) i plavi (poslužitelj).

## Provjera računom

Evo ponovno tvoje veze. Brojevi na linijama prikazuju brojač računala na tom mjestu:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Prođi kroz crveni niz brojeva:

1. Klijent počinje od `SEQ=0`. Njegov `SYN` troši jedan broj — poslužitelj potvrđuje s `ACK=1`.
2. Poruka počinje od `SEQ=1` i dugačka je 13 bajtova (bajtovi od 1 do 13). Poslužitelj potvrđuje s `ACK=14`: „Sljedeće očekujem bajt 14.“
3. `FIN` klijenta zato ima `SEQ=14` i potvrđuje se s `ACK=15`.

Plavi niz poslužitelja funkcionira na isti način.

:::tip Zapamti
**Redni broj** (`SEQ`) je broj prvog bajta u paketu. **Broj potvrde** (`ACK`) je broj sljedećeg bajta koji primatelj očekuje — sve prije njega je stiglo. Vrijedi: **ACK = SEQ + duljina** primljenih podataka; `SYN` i `FIN` računaju se kao jedan bajt. Svaka strana broji svoje vlastite bajtove.
:::

:::tip Isprobaj
Ponovno uspostavi vezu u **Jednostavni TCP klijent** i pošalji dvije poruke jednu za drugom. Prije toga reci koji će `Seq` i `Ack` biti u stupcu **Info** — i provjeri to u tragu.
:::

:::note
U stvarnim mrežama brojanje ne počinje od 0: svaka strana odabire **nasumičan početni broj** (*Initial Sequence Number*, ISN) između 0 i otprilike 4,3 milijarde. Kad se dosegne najveći broj, nastavlja se ponovno od 0. Tracer oduzima početni broj i prikazuje **relativne** brojeve — baš kao Wireshark. Zato vidiš `Seq=0` i `Seq=1`.

Osim toga, u svakom paketu stoji `Win=` — **veličina prozora**: toliko bajtova primatelj trenutačno može primiti. Time usporava prebrzog pošiljatelja (*kontrola toka*). U BeaverTraceru je prozor uvijek iste veličine.
:::
