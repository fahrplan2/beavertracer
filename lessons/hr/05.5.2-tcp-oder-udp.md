# TCP ili UDP?

| | TCP | UDP |
|---|---|---|
| Veza | uspostava trostrukim rukovanjem (three-way handshake), uredno prekidanje | nema — svaki datagram stoji sam za sebe |
| Potvrde | da (`ACK`) | ne |
| Izgubljeni podaci | šalju se ponovno | ostaju izgubljeni |
| Redoslijed | ponovno se uspostavlja | nije zajamčen |
| Zaglavlje | najmanje 20 bajtova | 8 bajtova |
| Brzina | nešto sporije, više paketa | brzo, malo dodatnog opterećenja |

Kada je manje više?

- **Stvarno vrijeme:** Kod videopoziva, internetske telefonije ili online igara svaka milisekunda ima težinu. Izgubljeni komadić zvuka koji stigne sekundu kasnije nikomu više ne koristi — bolje kratko pucketanje nego kašnjenje.
- **Kratki upiti:** **DNS** upit („Koju IP adresu ima `www.beispiel.de`?“) stane u jedan jedini datagram, a i odgovor također. Uspostava veze utrostručila bi trud. Ako odgovor ne stigne, program jednostavno pita ponovno.

Posvuda gdje svaki bajt mora stići — web-stranice, e-pošta, preuzimanja —, TCP je, naprotiv, pravi izbor.

:::tip Zapamti
**TCP** je pouzdan, ali zahtjevniji — za sve što mora stići **u cijelosti** (web, e-pošta, datoteke). **UDP** je brz i štedljiv, ali bez jamstava — za **stvarno vrijeme** (telefonija, video, igre) i **kratke upite** poput DNS-a.
:::

Time poznaješ alate transportnog sloja. U sljedećem poglavlju upoznat ćeš protokole koji se nadograđuju na njega: HTTP, DNS, e-poštu i DHCP.
