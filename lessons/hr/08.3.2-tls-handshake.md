# TLS handshake

:::sim

Prije nego što se pošalje prvi šifrirani zahtjev, klijent i poslužitelj moraju se dogovoriti: o postupku, o ključu sesije — a klijent mora provjeriti s kim razgovara. Ta uspostava veze zove se **TLS handshake**.

## Tijek na dijagramu

Bez TCP potvrda (`ACK`) handshake izgleda ovako:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Što se pritom događa — i koji se gradivni element iz odjeljka 8.1 krije iza toga:

1. **Client Hello / Server Hello:** Klijent i poslužitelj pozdravljaju se, razmjenjuju slučajne brojeve i dogovaraju postupke (u BeaverTraceru: razmjena ključeva pomoću **ECDHE**, potpis pomoću **ECDSA**, šifriranje pomoću **AES**).
2. **Certificate:** Poslužitelj šalje svoj **certifikat**. Klijent provjerava potpis CA-a, valjanost i ime. Ako to ne uspije, ovdje prekida vezu — a preglednik prikazuje upozorenje.
3. **Server Key Exchange:** Poslužitelj šalje svoj **Diffie-Hellman udio** — i **potpisuje** ga svojim privatnim ključem. Klijent provjerava potpis javnim ključem iz certifikata. Tako zna: ovaj udio doista dolazi od vlasnika certifikata, a ne od napadača koji se umetnuo u komunikaciju (man-in-the-middle).
4. **Client Key Exchange:** Klijent šalje svoj Diffie-Hellman udio. Sada oboje mogu izračunati isti **ključ sesije** — a da on nikada nije prenesen.
5. **Change Cipher Spec:** „Od sada šifriram.“
6. **Encrypted Handshake Message (Finished):** Obje strane šalju — već šifriranu — kontrolni zbroj svih dosadašnjih poruka handshakea. Ako je napadač nešto promijenio na putu, kontrolni se zbrojevi ne podudaraju i veza se prekida.
7. **Application Data:** Odavde teku HTTP podaci — simetrično šifrirani pomoću AES-a.

:::quiz match
Certificate -> Poslužitelj se predstavlja svojim certifikatom
Server Key Exchange -> Potpisani Diffie-Hellman udio poslužitelja
Client Key Exchange -> Diffie-Hellman udio klijenta
Change Cipher Spec -> Od sada se šifrira
Application Data -> Šifrirani HTTP podaci
:::

:::note
U tragu vidiš **dvije** TLS veze jednu za drugom: preglednik prvo dohvaća stranicu, a zatim uspostavlja novu vezu za stilsku datoteku `style.css`. Svaka veza dobiva vlastiti handshake i vlastiti ključ sesije. Pravi preglednici drže veze otvorenima i tako uštede dio tog napora. Novija verzija **TLS 1.3** osim toga treba manje poruka od ovdje prikazanog TLS-a 1.2.
:::

:::tip Zapamti
U **TLS handshakeu** poslužitelj se predstavlja svojim **certifikatom**, obje strane dogovaraju **ključ sesije** pomoću **Diffie-Hellmana** (poslužitelj **potpisuje** svoj udio), a porukom **Finished** obje provjeravaju da nitko nije promijenio handshake. Nakon toga se podaci prenose kao **Application Data**, simetrično šifrirani.
:::
