# Promatranje UDP-a

Na **Serveru** ovaj put radi **UDP Echo Server** na portu `5000`. I ovdje je kabel pripremljen: **drugi datagram** od Client-PC-ja prema Serveru se gubi.

## Pokus

1. Prijeđi u način izvođenja :fa-play: **Pokreni** i na **Client-PC-ju** otvori :fa-terminal: **Terminal**.
2. Pomoću `nc` pokreni UDP „vezu“ prema serveru (`-u` označava UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Upiši redom `eins`, `zwei` i `drei` i svaki put pritisni **Enter**. Svaki redak koji se vrati odjek je (echo) servera.
4. Pričekaj nekoliko sekundi, a zatim u načinu :fa-magnifying-glass: **Praćenje** otvori trag za **Client-PC**.

:::quiz mc
Koji se odjeci vraćaju?
- [ ] Sva tri, `zwei` malo kasnije
- [x] Samo `eins` i `drei` — `zwei` nedostaje i ne šalje se ponovno
- [ ] Nijedan
:::

:::quiz multi
Koji paketi koje poznaješ iz TCP-a potpuno nedostaju kod UDP-a?
- [x] Uspostava veze (`SYN`)
- [x] Potvrde (`ACK`)
- [x] Prekid veze (`FIN`)
- [ ] Paketi s brojevima portova
:::

:::evaluate
Provjeri odgovore
:::

Klikni na jedan od UDP paketa i otvori **User Datagram Protocol**. U usporedbi s TCP zaglavljem UDP zaglavlje je sićušno: **Source Port**, **Destination Port**, **Length** (duljina) i **Checksum** (kontrolni zbroj) — zajedno samo 8 bajtova. TCP zaglavlje ima najmanje 20 bajtova, s rednim brojem i brojem potvrde, zastavicama i veličinom prozora.

:::tip Zapamti
**UDP** je **bez uspostave veze**: nema uspostave, nema potvrde, nema ponovnog slanja, nema redoslijeda. Nudi samo **portove** (multipleksiranje) i **kontrolni zbroj**. Zato je brz i jednostavan — UDP zaglavlje ima samo 8 bajtova. Ako se datagram izgubi, program se mora sam pobrinuti za to — ili mu je svejedno.
:::
