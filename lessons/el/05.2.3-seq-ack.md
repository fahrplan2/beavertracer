# Αριθμοί ακολουθίας και επιβεβαίωσης

:::sim
url=/sims/lesson-5.1.btsim
:::

Πώς ξέρει το TCP αν έφτασαν όλα — και με ποια σειρά; Κάθε πλευρά **αριθμεί τα bytes** που στέλνει:

- Ο **αριθμός ακολουθίας** (`SEQ`) είναι ο αριθμός του πρώτου byte που περιέχεται σε αυτό το πακέτο.
- Ο **αριθμός επιβεβαίωσης** (`ACK`) λέει: «Μέχρι εδώ τα έχω λάβει όλα — στη συνέχεια περιμένω το byte αρ. …»

Επιπλέον ισχύουν δύο κανόνες: Τα `SYN` και `FIN` μετράνε σαν ένα byte, παρόλο που δεν μεταφέρουν δεδομένα. Και κάθε πλευρά μετράει ξεχωριστά — γι' αυτό υπάρχουν δύο σειρές αρίθμησης, στο διάγραμμα η κόκκινη (πελάτης) και η μπλε (διακομιστής).

## Κάνε τους υπολογισμούς

Εδώ βλέπεις ξανά τη σύνδεσή σου. Οι αριθμοί πάνω στις γραμμές δείχνουν κάθε φορά τον μετρητή του αντίστοιχου υπολογιστή σε εκείνο το σημείο:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Ακολούθησε την κόκκινη σειρά αριθμών:

1. Ο πελάτης ξεκινά με `SEQ=0`. Το `SYN` του καταναλώνει έναν αριθμό — ο διακομιστής επιβεβαιώνει με `ACK=1`.
2. Το μήνυμα ξεκινά με `SEQ=1` και έχει μήκος 13 bytes (bytes 1 έως 13). Ο διακομιστής επιβεβαιώνει με `ACK=14`: «Στη συνέχεια περιμένω το byte 14.»
3. Γι' αυτό το `FIN` του πελάτη έχει `SEQ=14` και επιβεβαιώνεται με `ACK=15`.

Η μπλε σειρά του διακομιστή λειτουργεί ακριβώς με τον ίδιο τρόπο.

:::tip Βασικό σημείο
Ο **αριθμός ακολουθίας** (`SEQ`) είναι ο αριθμός του πρώτου byte στο πακέτο. Ο **αριθμός επιβεβαίωσης** (`ACK`) είναι ο αριθμός του επόμενου byte που περιμένει ο παραλήπτης — όλα όσα προηγούνται έχουν φτάσει. Ισχύει: **ACK = SEQ + μήκος** των δεδομένων που λήφθηκαν· τα `SYN` και `FIN` μετράνε σαν ένα byte. Κάθε πλευρά μετράει τα δικά της bytes.
:::

:::tip Δοκίμασέ το
Δημιούργησε ξανά τη σύνδεση στο **Απλό TCP Client** και στείλε δύο μηνύματα το ένα μετά το άλλο. Πρόβλεψε από πριν ποια `Seq` και `Ack` θα εμφανιστούν στη στήλη **Info** — και έλεγξέ το στο ίχνος.
:::

## Εξάσκηση

:::quiz short
Ο πελάτης στέλνει ένα πακέτο με `Seq=1` και `Len=13`. Ποιον αριθμό επιβεβαίωσης στέλνει πίσω ο διακομιστής;
= 14
:::

:::quiz short
Στη συνέχεια ο πελάτης στέλνει το επόμενο μήνυμά του. Με ποιον αριθμό ακολουθίας ξεκινά αυτό;
= 14
:::

:::quiz short
Φτάνει ένα πακέτο με `Seq=40` και `Len=25`. Ποιον αριθμό επιβεβαίωσης στέλνει ο παραλήπτης;
= 65
:::

:::evaluate
Έλεγχος απαντήσεων
:::

Συμπλήρωσε τους αριθμούς που λείπουν. Ο πελάτης στέλνει `Hallo` και στη συνέχεια `Tschau` (το καθένα με χαρακτήρα τέλους γραμμής):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
Έλεγχος διαγράμματος
:::

:::note
Στα πραγματικά δίκτυα η αρίθμηση δεν ξεκινά από το 0: Κάθε πλευρά επιλέγει έναν **τυχαίο αρχικό αριθμό** (*Initial Sequence Number*, ISN) μεταξύ 0 και περίπου 4,3 δισεκατομμυρίων. Όταν φτάσει στον μεγαλύτερο αριθμό, η αρίθμηση συνεχίζει ξανά από το 0. Το εργαλείο ιχνηλάτησης αφαιρεί τον αρχικό αριθμό και δείχνει **σχετικούς** αριθμούς — ακριβώς όπως το Wireshark. Γι' αυτό βλέπεις `Seq=0` και `Seq=1`.

Επιπλέον, σε κάθε πακέτο υπάρχει το `Win=` — το **μέγεθος παραθύρου**: τόσα bytes μπορεί να δεχτεί ο παραλήπτης αυτή τη στιγμή. Με αυτό φρενάρει έναν αποστολέα που στέλνει πολύ γρήγορα (*έλεγχος ροής*). Στο BeaverTracer το παράθυρο έχει πάντα το ίδιο μέγεθος.
:::
