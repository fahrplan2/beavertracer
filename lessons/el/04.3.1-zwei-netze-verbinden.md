# Σύνδεση δύο δικτύων

:::sim
url=/sims/lesson-4.3.1.btsim
:::

Ο δρομολογητής έχει δύο διεπαφές:

| Διεπαφή | Διεύθυνση IP | Δίκτυο |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Για να χρησιμοποιούν οι υπολογιστές τον δρομολογητή, σε καθέναν από αυτούς έχει καταχωριστεί μια **πύλη** (gateway): στην Anna και στον Ben η `192.168.0.1`, στην Clara και στον David η `172.16.0.1`. Θα τη βρεις στις :fa-gear: **Ρυθμίσεις IP**, στο πεδίο **Gateway**.

:::tip Βασικό σημείο
Η **πύλη** (ακριβέστερα: *προεπιλεγμένη πύλη*, default gateway) είναι η διεύθυνση IP του δρομολογητή **στο δικό σου δίκτυο**. Ένας υπολογιστής στέλνει στην πύλη όλα τα πακέτα που έχουν προορισμό σε ξένο δίκτυο.
:::

## Το πείραμα

1. Πήγαινε στη λειτουργία :fa-play: **Εκτέλεση** και κάνε ping από την **Anna** στην Clara (`ping 172.16.0.10`). Αυτή τη φορά λειτουργεί — πρόσεξε στην έξοδο την τιμή `ttl=`.
2. Πήγαινε στη λειτουργία :fa-magnifying-glass: **Ίχνος** και άνοιξε ένα ίχνος (trace) για την **Anna**.

Δες το πρώτο πακέτο (το αίτημα ARP):

:::quiz multi
Ποιες προτάσεις για το πρώτο πακέτο είναι σωστές;
- [x] Η Anna γνωρίζει ήδη τη διεύθυνση IP της Clara πριν στείλει το πακέτο
- [ ] Η Anna ρωτά για τη διεύθυνση MAC της Clara
- [x] Η Anna ρωτά όλες τις συσκευές του δικτύου για τη διεύθυνση MAC του δρομολογητή
- [ ] Η Anna ρωτά το switch για τη διεύθυνση IP της Clara
:::

Κάνε τώρα κλικ στο πρώτο `Echo (ping) request` και ανάπτυξε τα **Ethernet II** και **Internet Protocol Version 4**. Σύγκρινε τις διευθύνσεις MAC με την απάντηση ARP που προηγείται.

:::quiz multi
Ποιες προτάσεις για το ping είναι σωστές;
- [x] Ως διεύθυνση IP προορισμού αναγράφεται η Clara (`172.16.0.10`)
- [ ] Ως διεύθυνση IP προορισμού αναγράφεται ο δρομολογητής (`192.168.0.1`)
- [x] Ως διεύθυνση MAC προορισμού αναγράφεται η διεύθυνση MAC του δρομολογητή
- [ ] Η Anna στέλνει το ping απευθείας στη διεύθυνση MAC της Clara

## Τι κάνει ο δρομολογητής με το πακέτο

Ο δρομολογητής παραλαμβάνει το πλαίσιο (frame) της Anna, βγάζει από μέσα το πακέτο IP και κοιτάζει τη **διεύθυνση IP προορισμού**. Από αυτήν καταλαβαίνει: η Clara βρίσκεται στο δίκτυο της `eth1`. Έτσι, πακετάρει το πακέτο σε ένα **νέο** πλαίσιο — με τη δική του διεύθυνση MAC ως αποστολέα και τη διεύθυνση MAC της Clara ως προορισμό — και το στέλνει έξω από εκείνη τη διεπαφή.

| Τι συμβαίνει στον δρομολογητή με … | |
|---|---|
| τις διευθύνσεις MAC (επίπεδο 2); | ορίζονται **εκ νέου** — ισχύουν μόνο στο εκάστοτε δίκτυο |
| τις διευθύνσεις IP (επίπεδο 3); | **παραμένουν ίδιες** — από την Anna μέχρι την Clara |
| το Time to Live; | **μειώνεται κατά 1** |

:::tip Βασικό σημείο
Ένας **δρομολογητής** λειτουργεί στο **επίπεδο 3**: προωθεί πακέτα σε άλλα δίκτυα με βάση τη **διεύθυνση IP προορισμού**. Οι διευθύνσεις IP παραμένουν ίδιες σε όλη τη διαδρομή, ενώ οι διευθύνσεις MAC ορίζονται εκ νέου σε κάθε δίκτυο. Κάθε δρομολογητής μειώνει το **Time to Live (TTL)** κατά 1 — αν φτάσει στο 0, το πακέτο απορρίπτεται. Έτσι ένα πακέτο δεν μπορεί να κάνει κύκλους επ' άπειρον.
:::

:::note
Θυμάσαι την καταιγίδα γενικής εκπομπής (broadcast storm) από το κεφάλαιο 3.4; Τα πλαίσια Ethernet δεν έχουν TTL — τα πακέτα IP όμως έχουν.
:::

## Ποιους γνωρίζει η Anna; Η ARP cache

Θυμάσαι το κεφάλαιο 1.2.3; Εκεί το ARP εμφανίστηκε μόνο πριν από το *πρώτο* ping, επειδή ο υπολογιστής είχε απομνημονεύσει την απάντηση. Αυτή η λίστα ονομάζεται **ARP cache** (κρυφή μνήμη ARP, επίσης *πίνακας ARP*). Το αίτημα ονομάζεται **ARP request** και η απάντηση **ARP reply** (ή *ARP response*).

Πήγαινε στη λειτουργία :fa-play: **Εκτέλεση**, άνοιξε στην **Anna** το :fa-terminal: **Terminal** και εμφάνισε την ARP cache της:

```
$ arp
```

:::quiz mc
Τι περιέχει η ARP cache της Anna;
- [x] Μόνο τη διεύθυνση IP του δρομολογητή (`192.168.0.1`) με τη διεύθυνση MAC του
- [ ] Τη διεύθυνση IP της Clara με τη διεύθυνση MAC της Clara
- [ ] Τις διευθύνσεις του δρομολογητή και της Clara
:::

:::evaluate
Έλεγχος απάντησης
:::

Η Anna δεν χρειάζεται ποτέ τη διεύθυνση MAC της Clara: ό,τι προορίζεται για τη Firma B το στέλνει στον δρομολογητή. Τη διεύθυνση MAC της Clara τη γνωρίζει μόνο ο δρομολογητής — τη ζήτησε ο ίδιος μέσω ARP στη δική του πλευρά.

:::tip Βασικό σημείο
Στην **ARP cache** μια συσκευή απομνημονεύει ποια διεύθυνση MAC αντιστοιχεί σε ποια διεύθυνση IP — έτσι δεν χρειάζεται να στέλνει ARP request πριν από κάθε πακέτο. Μπορείς να την εμφανίσεις με την εντολή `arp`. Ένας υπολογιστής γνωρίζει μόνο διευθύνσεις MAC από το **δικό του** δίκτυο: για όλους τους προορισμούς σε ξένα δίκτυα χρησιμοποιεί τη διεύθυνση MAC του δρομολογητή.
:::

:::note
Σε πραγματικά δίκτυα, οι καταχωρίσεις στην ARP cache διαγράφονται μετά από κάποιο χρονικό διάστημα και ζητούνται ξανά όταν χρειαστεί — για παράδειγμα, σε περίπτωση που μια συσκευή έχει στο μεταξύ άλλη κάρτα δικτύου. Στο BeaverTracer διατηρούνται όσο εκτελείται η προσομοίωση.
:::
