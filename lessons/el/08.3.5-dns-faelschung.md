# Επίθεση: πλαστογράφηση DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Η Anna θέλει να ανοίξει στον **Client-PC** το e-banking της στην **Biberbank**. Αυτό που δεν ξέρει: κάποιος απέκτησε πρόσβαση στον **DNS-Server** και άλλαξε μια εγγραφή.

Στον χώρο εργασίας βλέπεις τον πραγματικό web server **www.biberbank.de** και τον υπολογιστή ενός επιτιθέμενου (**Angreifer**). Σε αυτόν τρέχει ένα αντίγραφο της ιστοσελίδας της τράπεζας.

## Μέρος 1: Χωρίς κρυπτογράφηση

Πέρασε στη λειτουργία :fa-play: **Εκτέλεση** και άνοιξε στον **Client-PC** στον :fa-globe: **Περιηγητής** τη διεύθυνση `http://www.biberbank.de/`.

:::quiz mc
Τι βλέπεις;
- [x] Τη σελίδα σύνδεσης της Biberbank, χωρίς καμία προειδοποίηση
- [ ] Μια προειδοποίηση ότι η σελίδα είναι πλαστή
- [ ] Ένα μήνυμα σφάλματος
:::

:::evaluate
Έλεγχος απάντησης
:::

Όλα φαίνονται φυσιολογικά. Αλλά με ποιον server μιλάει πραγματικά ο περιηγητής; Άνοιξε στον Client-PC το :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Ποια διεύθυνση IP επιστρέφει ο DNS-Server για το `www.biberbank.de`;
= 192.168.0.66
:::

:::quiz mc
Σε ποιον ανήκει αυτή η διεύθυνση; (Κάνε κλικ στις συσκευές στη λειτουργία επεξεργασίας ή δες τις :fa-gear: **Ρυθμίσεις IP** τους.)
- [ ] Στον πραγματικό web server της Biberbank
- [x] Στον επιτιθέμενο
- [ ] Στον DNS-Server
:::

:::evaluate
Έλεγχος απαντήσεων
:::

Αν η Anna είχε πληκτρολογήσει τώρα τον αριθμό λογαριασμού και το PIN της, αυτά θα είχαν καταλήξει κατευθείαν στον επιτιθέμενο. Με **HTTP** δεν έχει **καμία πιθανότητα** να αντιληφθεί την απάτη: η γραμμή διευθύνσεων δείχνει το σωστό όνομα και η σελίδα φαίνεται γνήσια.

## Μέρος 2: Με HTTPS

Άνοιξε τώρα τη διεύθυνση `https://www.biberbank.de/`.

:::quiz mc
Τι συμβαίνει;
- [ ] Η πλαστή σελίδα εμφανίζεται με λουκέτο
- [x] Ο περιηγητής προειδοποιεί: το πιστοποιητικό εκδόθηκε για άλλο όνομα
- [ ] Εμφανίζεται η πραγματική σελίδα της Biberbank
:::

:::quiz short
Για ποιο όνομα έχει εκδοθεί το πιστοποιητικό του επιτιθέμενου (χωρίς `CN=`);
= www.biber-gewinnspiel.de
:::

:::evaluate
Έλεγχος απαντήσεων
:::

Ο επιτιθέμενος έχει μάλιστα ένα **γνήσιο** πιστοποιητικό από μια αξιόπιστη CA — όμως για τον δικό του τομέα `www.biber-gewinnspiel.de`. Πιστοποιητικό για το `www.biberbank.de` δεν θα του δώσει καμία CA, γιατί αυτός ο τομέας δεν του ανήκει. Και χωρίς το **ιδιωτικό κλειδί** της Biberbank δεν μπορεί να χρησιμοποιήσει ούτε το πραγματικό της πιστοποιητικό: στο handshake θα έπρεπε να υπογράψει με αυτό το Server Key Exchange.

:::quiz multi
Από τι προστατεύει εδώ το HTTPS — και από τι όχι;
- [x] Το HTTPS αποκαλύπτει ότι ο server δεν είναι ο γνήσιος
- [ ] Το HTTPS εμποδίζει την πλαστογράφηση του DNS-Server
- [x] Το HTTPS βοηθά μόνο αν ο χρήστης πάρει στα σοβαρά την προειδοποίηση
- [ ] Με HTTPS η πλαστή σελίδα δεν είναι καθόλου προσβάσιμη
:::

:::evaluate
Έλεγχος απαντήσεων
:::

## Μέρος 3: Επιδιόρθωση του DNS-Server

Άνοιξε τον **DNS-Server** και διόρθωσε την εγγραφή για το `www.biberbank.de`. Τη σωστή διεύθυνση θα τη βρεις στις :fa-gear: **Ρυθμίσεις IP** του web server **www.biberbank.de**. Μην ξεχάσεις να κάνεις κλικ στο **Αποθήκευση**.

:::note
Ο Client-PC θυμάται τις απαντήσεις DNS για λίγο, ώστε να μη χρειάζεται να ρωτάει ξανά σε κάθε αίτημα (**DNS cache**). Για πόσο, αναγράφεται στη στήλη **TTL** (*Time to Live*) σε δευτερόλεπτα. Αν το `nslookup` επιστρέφει ακόμη την παλιά διεύθυνση αμέσως μετά τη διόρθωσή σου, περίμενε να λήξει το TTL και δοκίμασε ξανά.
:::

:::task
title: Είναι η Biberbank ξανά γνήσια;
Ελέγχει αν ο Client-PC επιλύει το www.biberbank.de στη σωστή διεύθυνση και μπορεί να ανοίξει τη σελίδα μέσω HTTPS χωρίς προειδοποίηση.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Στην πραγματικότητα, ένας επιτιθέμενος σπάνια πλαστογραφεί τον ίδιο τον DNS server. Συχνότερα «φυτεύει» τις δικές του απαντήσεις σε ένα δημόσιο WLAN, αλλάζει τις ρυθμίσεις ενός οικιακού δρομολογητή ή δελεάζει με μια διεύθυνση που μοιάζει, όπως `www.biberbank-login.de` (**phishing**). Απέναντι σε ένα όνομα που μοιάζει, ούτε το HTTPS βοηθά — ο επιτιθέμενος παίρνει γι' αυτό έγκυρο πιστοποιητικό. Γι' αυτό: διάβαζε τη διεύθυνση προσεκτικά!
:::

:::tip Βασικό σημείο
Σε μια **πλαστογράφηση DNS** ο DNS server επιστρέφει για ένα όνομα τη διεύθυνση ενός επιτιθέμενου. Με **HTTP** δεν το αντιλαμβάνεσαι καθόλου. Με **HTTPS** το πιστοποιητικό του επιτιθέμενου δεν ταιριάζει με το όνομα που ζητήθηκε, και ο περιηγητής **προειδοποιεί** — γιατί καμία CA δεν εκδίδει πιστοποιητικό για ξένους τομείς, και ο επιτιθέμενος δεν έχει το ιδιωτικό κλειδί του γνήσιου server.
:::
