# Όλα μαζί: τι συμβαίνει όταν ανοίγεις μια ιστοσελίδα;

:::goal
**Μαθησιακός στόχος:** Μπορείς να εξηγήσεις βήμα προς βήμα ποια πρωτόκολλα και σε ποιο επίπεδο συμμετέχουν, όταν ένας laptop που μόλις άνοιξε φορτώνει μια ιστοσελίδα.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Τώρα όλα όσα έμαθες σε αυτό το μάθημα έρχονται μαζί. Στο switch είναι συνδεδεμένοι ένας **DHCP-Server**, ένας **DNS-Server**, ένας **Webserver** και ένας **Laptop** που μόλις άνοιξε. Ο laptop δεν έχει ακόμη διεύθυνση IP και είναι ρυθμισμένος σε DHCP.

## Το πείραμα

1. Πήγαινε στη :fa-play: **Λειτουργία εκτέλεσης** και περίμενε μερικά δευτερόλεπτα.
2. Κάνε κλικ στον **Laptop**, άνοιξε τον :fa-globe: **Περιηγητής** και φόρτωσε τη διεύθυνση `http://www.beaver-schule.de/`.
3. Στη λειτουργία :fa-magnifying-glass: **Ίχνος**, άνοιξε ένα trace για τον **Laptop**. Εκεί βρίσκεται ολόκληρη η ιστορία, από το πρώτο κιόλας πακέτο.

Βάλε τα βήματα στη σωστή σειρά, όπως εμφανίζονται στο trace:

:::quiz match
Βήμα 1 -> DHCP: Ο laptop παίρνει διεύθυνση IP, gateway και DNS server
Βήμα 2 -> ARP: Ο laptop ρωτά για τη διεύθυνση MAC του DNS server
Βήμα 3 -> DNS: Ο laptop ρωτά για τη διεύθυνση IP του www.beaver-schule.de
Βήμα 4 -> ARP: Ο laptop ρωτά για τη διεύθυνση MAC του web server
Βήμα 5 -> TCP: Τριμερής χειραψία με τον web server
Βήμα 6 -> HTTP: GET / και η απάντηση 200 OK
:::

Κάτω από όλα αυτά βρίσκονται το **IP** (επίπεδο 3), που δίνει διεύθυνση σε καθένα από αυτά τα πακέτα, και το **Ethernet** (επίπεδο 2), που το μεταφέρει στην επόμενη συσκευή. Αν ο web server βρισκόταν σε άλλο δίκτυο, θα έμπαινε στο παιχνίδι και ο **δρομολογητής**. Τότε ο laptop θα ρωτούσε για τη διεύθυνση MAC του **gateway** του και όχι για εκείνη του web server.

:::quiz mc
Γιατί ο laptop μπορεί να στείλει το αίτημα DNS μόνο μετά το DHCP;
- [ ] Επειδή το DNS λειτουργεί μόνο μέσω TCP
- [x] Επειδή μόνο μέσω του DHCP αποκτά δική του διεύθυνση IP και μαθαίνει ποιος DNS server είναι αρμόδιος
- [ ] Επειδή ο DNS server ξεκινά μόνο μετά τον DHCP server
:::

:::quiz mc
Πόσες συνδέσεις TCP εγκαθιστά ο περιηγητής με τον web server και γιατί;
- [ ] Μία, για όλα μαζί
- [x] Δύο: μία για τη σελίδα και μία για το stylesheet
- [ ] Καμία, το HTTP δεν χρειάζεται TCP
:::

:::tip Βασικό σημείο
Πίσω από ένα μόνο κλικ συνεργάζονται όλα τα επίπεδα: το **DHCP** παρέχει τις βασικές ρυθμίσεις, το **ARP** βρίσκει τις διευθύνσεις MAC στο τοπικό δίκτυο, το **DNS** μεταφράζει το όνομα, το **TCP** εγκαθιστά μια αξιόπιστη σύνδεση και το **HTTP** φέρνει τη σελίδα. Όλα αυτά είναι πακεταρισμένα σε πακέτα **IP** και πλαίσια **Ethernet**.
:::

Έτσι μπορείς πλέον να εξηγήσεις τη φόρτωση μιας ιστοσελίδας από το πρώτο έως το τελευταίο πακέτο. Για να ολοκληρωθεί το κεφάλαιο, ακολουθεί μια σύντομη ματιά σε άλλα πρωτόκολλα. Τα επόμενα κεφάλαια ασχολούνται με το οικιακό δίκτυο με NAT, με την ασφάλεια και την κρυπτογράφηση. Εκεί θα δούμε πώς εμποδίζουμε κάποιον να διαβάζει όλα αυτά τα πακέτα.
