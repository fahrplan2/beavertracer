# Σύνοψη και προοπτικές

## Τα δομικά στοιχεία με μια ματιά

| Δομικό στοιχείο | Στόχος προστασίας | Παράδειγμα |
|---|---|---|
| **Συμμετρική κρυπτογράφηση** | Εμπιστευτικότητα | Το AES κρυπτογραφεί τα δεδομένα μιας σύνδεσης HTTPS |
| **Ασύμμετρη κρυπτογράφηση** | Εμπιστευτικότητα, ανταλλαγή κλειδιών | Diffie-Hellman, RSA |
| **Τιμές κατακερματισμού (hash)** | Ακεραιότητα | Άθροισμα ελέγχου SHA-256 ενός αρχείου λήψης |
| **Ψηφιακή υπογραφή** | Αυθεντικότητα, ακεραιότητα | Ο server υπογράφει το δικό του μέρος του Diffie-Hellman |
| **Πιστοποιητικό** | Αυθεντικότητα | βεβαιώνει: Αυτό το κλειδί ανήκει στο `www.biberbank.de` |

## Η ίδια αρχή σε πολλά σημεία

Ό,τι έμαθες για το HTTPS βρίσκεται και σε πολλές άλλες τεχνολογίες:

- **WLAN (WPA2/WPA3):** Στο κεφάλαιο 3.3.2 κάθε συσκευή εντός εμβέλειας μπορούσε να διαβάσει την κίνηση. Με το WPA2 ή το WPA3 κάθε ασύρματο πλαίσιο κρυπτογραφείται με AES· επιπλέον, το WPA3 διαπραγματεύεται το κλειδί με τέτοιο τρόπο, ώστε ένας υποκλοπέας να μην μπορεί να αποκρυπτογραφήσει παλιές καταγραφές, ακόμη κι αν γνωρίζει τον κωδικό του WLAN.
- **SSH:** Η κρυπτογραφημένη απομακρυσμένη διαχείριση από το κεφάλαιο 6.6. Αντί για πιστοποιητικά, ο client απομνημονεύει κατά την πρώτη σύνδεση το **αποτύπωμα** (fingerprint) του κλειδιού του server και σε προειδοποιεί αν αυτό αλλάξει αργότερα.
- **VPN:** Ένα κρυπτογραφημένο τούνελ μέσα από το διαδίκτυο, π.χ. προς το δίκτυο του σχολείου ή της εταιρείας. Αυτό είναι το θέμα του κεφαλαίου 10.
- **Εφαρμογές ανταλλαγής μηνυμάτων:** Το Signal, το WhatsApp και άλλες εφαρμογές κρυπτογραφούν **από άκρο σε άκρο** (end-to-end): Ούτε καν ο πάροχος της υπηρεσίας δεν μπορεί να διαβάσει τα μηνύματα.

:::note
Μεγάλοι **κβαντικοί υπολογιστές** θα μπορούσαν κάποια μέρα να καταφέρουν την ανάλυση μεγάλων αριθμών σε πρώτους παράγοντες — και κατ' επέκταση να σπάσουν το RSA και το Diffie-Hellman. Γι' αυτό ήδη από σήμερα εισάγονται νέες μέθοδοι, **ανθεκτικές στους κβαντικούς υπολογιστές**. Οι συμμετρικές μέθοδοι, όπως το AES με μεγάλα κλειδιά, εξακολουθούν να θεωρούνται ασφαλείς.
:::

## Έλεγξε τον εαυτό σου

:::quiz mc
Στο HTTPS τα πραγματικά δεδομένα κρυπτογραφούνται με …
- [ ] το RSA, επειδή είναι το πιο ασφαλές
- [x] μια συμμετρική μέθοδο όπως το AES και ένα κλειδί συνεδρίας που έχει συμφωνηθεί μέσω διαπραγμάτευσης
- [ ] το ιδιωτικό κλειδί του server
:::

:::quiz mc
Ανοίγεις τη διεύθυνση `https://www.biberbank.de/` και το πρόγραμμα περιήγησης εμφανίζει το μήνυμα «Το πιστοποιητικό εκδόθηκε για το `www.gewinn-biber.de`». Τι κάνεις;
- [ ] Κάνω κλικ στο «Συνέχεια παρ' όλα αυτά» — η σύνδεση είναι έτσι κι αλλιώς κρυπτογραφημένη
- [x] Ακυρώνω — ίσως το πρόγραμμα περιήγησης δεν επικοινωνεί καν με την τράπεζα
- [ ] Ανοίγω τη σελίδα μέσω `http://`, οπότε δεν εμφανίζεται προειδοποίηση
:::

:::quiz multi
Ποιες προτάσεις είναι σωστές;
- [x] Μια τιμή κατακερματισμού αλλάζει εντελώς, ακόμη κι αν τα δεδομένα αλλάξουν ελάχιστα
- [x] Μια υπογραφή δημιουργείται με το ιδιωτικό κλειδί και επαληθεύεται με το δημόσιο
- [x] Οι Root CA είναι προεγκατεστημένες στο πρόγραμμα περιήγησης ή στο λειτουργικό σύστημα
- [ ] Στο HTTPS ένας υποκλοπέας δεν μπορεί να δει ούτε καν τη διεύθυνση IP του server
- [ ] Το SMTPS κρυπτογραφεί το email και πάνω στον διακομιστή αλληλογραφίας
:::

:::quiz fill
Το HTTPS είναι HTTP πάνω από {TLS} και χρησιμοποιεί από προεπιλογή τη θύρα {443}. Ο server ταυτοποιείται με ένα {πιστοποιητικό}, το οποίο έχει υπογράψει μια {CA|Αρχή Πιστοποίησης}.
:::
