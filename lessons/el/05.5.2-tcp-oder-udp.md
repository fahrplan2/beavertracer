# TCP ή UDP;

| | TCP | UDP |
|---|---|---|
| Σύνδεση | εγκατάσταση με τριμερή χειραψία, ομαλός τερματισμός | καμία — κάθε datagram είναι ανεξάρτητο |
| Επιβεβαιώσεις | ναι (`ACK`) | όχι |
| Χαμένα δεδομένα | αποστέλλονται ξανά | παραμένουν χαμένα |
| Σειρά | αποκαθίσταται | δεν είναι εγγυημένη |
| Κεφαλίδα | τουλάχιστον 20 byte | 8 byte |
| Ταχύτητα | κάπως πιο αργό, περισσότερα πακέτα | γρήγορο, μικρή επιβάρυνση |

Πότε το λιγότερο είναι περισσότερο;

- **Πραγματικός χρόνος:** Στις βιντεοκλήσεις, στην τηλεφωνία μέσω διαδικτύου ή στα online παιχνίδια μετράει κάθε χιλιοστό του δευτερολέπτου. Ένα χαμένο κομμάτι ήχου που φτάνει ένα δευτερόλεπτο αργότερα δεν χρησιμεύει πια σε κανέναν — καλύτερα ένα σύντομο τρίξιμο παρά μια καθυστέρηση.
- **Σύντομα αιτήματα:** Ένα αίτημα **DNS** («Ποια διεύθυνση IP έχει το `www.beispiel.de`;») χωράει σε ένα μόνο datagram, όπως και η απάντηση. Μια εγκατάσταση σύνδεσης θα τριπλασίαζε την επιβάρυνση. Αν δεν έρθει απάντηση, το πρόγραμμα απλώς ρωτάει ξανά.

Αντίθετα, όπου πρέπει να φτάσει κάθε byte — ιστοσελίδες, e-mail, λήψεις αρχείων — η σωστή επιλογή είναι το TCP.

:::quiz multi
Για ποιες εφαρμογές είναι το **UDP** η καλύτερη επιλογή;

- [x] Βιντεοκλήσεις
- [ ] Αποστολή ενός e-mail

- [x] Δεδομένα θέσης σε ένα online παιχνίδι

- [x] Η ερώτηση και η απάντηση χωράνε η καθεμία σε ένα datagram — μια εγκατάσταση σύνδεσης θα ήταν μεγαλύτερη επιβάρυνση από το ίδιο το αίτημα
- [ ] Επειδή το UDP είναι κρυπτογραφημένο

:::tip Βασικό σημείο
Το **TCP** είναι αξιόπιστο, αλλά πιο απαιτητικό — για οτιδήποτε πρέπει να φτάσει **ολόκληρο** (web, e-mail, αρχεία). Το **UDP** είναι γρήγορο και λιτό, αλλά χωρίς εγγυήσεις — για **πραγματικό χρόνο** (τηλεφωνία, βίντεο, παιχνίδια) και για **σύντομα αιτήματα** όπως το DNS.
:::

Τώρα γνωρίζεις τα εργαλεία του επιπέδου μεταφοράς. Στο επόμενο κεφάλαιο θα εξετάσεις τα πρωτόκολλα που βασίζονται σε αυτό: HTTP, DNS, e-mail και DHCP.
