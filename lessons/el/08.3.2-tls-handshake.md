# Η χειραψία TLS

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Πριν σταλεί το πρώτο κρυπτογραφημένο αίτημα, ο πελάτης και ο διακομιστής πρέπει να συμφωνήσουν σε μια μέθοδο και σε ένα κλειδί συνεδρίας. Επιπλέον, ο πελάτης πρέπει να ελέγξει με ποιον μιλάει. Αυτή η εγκατάσταση σύνδεσης ονομάζεται **χειραψία TLS** (TLS handshake).

## Παρατήρηση

Άνοιξε στον **Client-PC** τη διεύθυνση `https://www.beaver-schule.de/` (αν δεν το έχεις κάνει ήδη). Μετά άνοιξε ένα ίχνος (trace) για τον **Client-PC** και φίλτραρε με `tls`.

## Η διαδικασία στο διάγραμμα

Χωρίς τις επιβεβαιώσεις TCP (`ACK`), η χειραψία μοιάζει έτσι:

:::seq
mode: text
Client -> Server: Client Hello | τυχαίος αριθμός, υποστηριζόμενες μέθοδοι
Server -> Client: Server Hello | επιλεγμένη μέθοδος, τυχαίος αριθμός
Server -> Client: Certificate | πιστοποιητικό του διακομιστή
Server -> Client: Server Key Exchange | μερίδιο DH, υπογεγραμμένο
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | μερίδιο DH του πελάτη
Client -> Server: Change Cipher Spec | από εδώ και πέρα κρυπτογραφημένα
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | από εδώ και πέρα κρυπτογραφημένα
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (κρυπτογραφημένο)
Server -> Client: Application Data | ιστοσελίδα (κρυπτογραφημένη)
:::

Τι συμβαίνει σε κάθε βήμα και ποιο δομικό στοιχείο από την ενότητα 8.1 βρίσκεται από πίσω:

1. **Client Hello / Server Hello:** Ο πελάτης και ο διακομιστής χαιρετιούνται, ανταλλάσσουν τυχαίους αριθμούς και συμφωνούν στις μεθόδους (στο BeaverTracer: ανταλλαγή κλειδιών με **ECDHE**, υπογραφή με **ECDSA**, κρυπτογράφηση με **AES**).
2. **Certificate:** Ο διακομιστής στέλνει το **πιστοποιητικό** του. Ο πελάτης ελέγχει την υπογραφή της CA, την εγκυρότητα και το όνομα. Αν ο έλεγχος αποτύχει, ο πελάτης διακόπτει εδώ και ο περιηγητής εμφανίζει μια προειδοποίηση.
3. **Server Key Exchange:** Ο διακομιστής στέλνει το **μερίδιο Diffie-Hellman** του και το **υπογράφει** με το ιδιωτικό του κλειδί. Ο πελάτης ελέγχει την υπογραφή με το δημόσιο κλειδί από το πιστοποιητικό. Έτσι ξέρει ότι αυτό το μερίδιο προέρχεται πράγματι από τον κάτοχο του πιστοποιητικού και όχι από κάποιον man-in-the-middle.
4. **Client Key Exchange:** Ο πελάτης στέλνει το δικό του μερίδιο Diffie-Hellman. Τώρα και οι δύο μπορούν να υπολογίσουν το ίδιο **κλειδί συνεδρίας**, χωρίς αυτό να έχει μεταδοθεί ποτέ.
5. **Change Cipher Spec:** «Από εδώ και πέρα κρυπτογραφώ.»
6. **Encrypted Handshake Message (Finished):** Και οι δύο πλευρές στέλνουν, ήδη κρυπτογραφημένο, ένα άθροισμα ελέγχου όλων των μέχρι τώρα μηνυμάτων της χειραψίας. Αν ένας επιτιθέμενος έχει αλλάξει κάτι στη διαδρομή, τα αθροίσματα ελέγχου δεν ταιριάζουν και η σύνδεση διακόπτεται.
7. **Application Data:** Από εδώ και πέρα μεταφέρονται τα δεδομένα HTTP, συμμετρικά κρυπτογραφημένα με AES.

:::quiz match
Certificate -> Ο διακομιστής ταυτοποιείται με το πιστοποιητικό του
Server Key Exchange -> Υπογεγραμμένο μερίδιο Diffie-Hellman του διακομιστή
Client Key Exchange -> Μερίδιο Diffie-Hellman του πελάτη
Change Cipher Spec -> Από εδώ και πέρα όλα κρυπτογραφούνται
Application Data -> Κρυπτογραφημένα δεδομένα HTTP
:::

:::note
Στο ίχνος βλέπεις **δύο** συνδέσεις TLS τη μία μετά την άλλη. Ο περιηγητής φέρνει πρώτα τη σελίδα και μετά εγκαθιστά νέα σύνδεση για το φύλλο στυλ `style.css`. Κάθε σύνδεση έχει τη δική της χειραψία και το δικό της κλειδί συνεδρίας. Οι πραγματικοί περιηγητές κρατούν τις συνδέσεις ανοιχτές και έτσι γλιτώνουν μέρος αυτής της επιβάρυνσης. Επιπλέον, η νεότερη έκδοση **TLS 1.3** χρειάζεται λιγότερα μηνύματα από το TLS 1.2 που βλέπεις εδώ.
:::

:::tip Βασικό σημείο
Στη **χειραψία TLS** ο διακομιστής ταυτοποιείται με το **πιστοποιητικό** του. Οι δύο πλευρές συμφωνούν μέσω **Diffie-Hellman** ένα **κλειδί συνεδρίας** (ο διακομιστής **υπογράφει** το μερίδιό του). Με το **Finished** ελέγχουν και οι δύο ότι κανείς δεν έχει αλλοιώσει τη χειραψία. Στη συνέχεια τα δεδομένα μεταδίδονται ως **Application Data**, συμμετρικά κρυπτογραφημένα.
:::
