# Τι πρέπει να κάνει το επίπεδο μεταφοράς;

:::sim
url=/sims/lesson-5.1.btsim
:::

Στον **Server** τρέχουν ταυτόχρονα δύο υπηρεσίες: ένας **διακομιστής ιστού** και μια μικρή **υπηρεσία echo**, που στέλνει αμέσως πίσω κάθε μήνυμα που λαμβάνει. Με δύο πειράματα θα ανακαλύψεις τι δεν μπορεί να κάνει το IP από μόνο του.

## Πείραμα 1: Δύο προγράμματα ταυτόχρονα

1. Πέρασε στη λειτουργία :fa-play: **Εκτέλεση** και κάνε κλικ στον **Client-PC**.
2. Άνοιξε τον :fa-globe: **Περιηγητής** και φόρτωσε τη διεύθυνση `http://192.168.0.20/`.
3. Κάνε κλικ στο **Πίσω** στο πάνω μέρος του παραθύρου και άνοιξε το **Απλό TCP Client**. Συμπλήρωσε `192.168.0.20` στο **Host** και `5000` στο **Port** και κάνε κλικ στο **Connect**.
4. Πέρασε στη λειτουργία :fa-magnifying-glass: **Ίχνος** και άνοιξε με το **+** ένα ίχνος για τον **Client-PC**, διεπαφή `eth0`.

Κάνε κλικ σε ένα πακέτο του περιηγητή (π.χ. `GET /`) και σε ένα του TCP client και ανάπτυξε κάθε φορά το **Internet Protocol Version 4**.

:::quiz mc
Ποιες διευθύνσεις IP έχουν τα πακέτα του περιηγητή και του TCP client;
- [x] Τις ίδιες και τα δύο: από `192.168.0.10` προς `192.168.0.20`
- [ ] Ο περιηγητής χρησιμοποιεί διαφορετική διεύθυνση IP προορισμού από τον TCP client
- [ ] Τα πακέτα του TCP client δεν έχουν διεύθυνση IP
:::

:::quiz mc
Αρκεί λοιπόν η διεύθυνση IP προορισμού για να ξέρει ο server αν ένα πακέτο ανήκει στον διακομιστή ιστού ή στην υπηρεσία echo;
- [ ] Ναι
- [x] Όχι — και τα δύο πακέτα έχουν την ίδια διεύθυνση IP προορισμού
:::

Κάτι άλλο πρέπει να ξεχωρίζει τις δύο συνδέσεις. Κοίτα τη στήλη **Info** των πακέτων με `[SYN]` — αυτό είναι κάθε φορά το πρώτο πακέτο μιας σύνδεσης:

:::quiz short
Ποιος αριθμός βρίσκεται μετά το βέλος `→` στον **περιηγητή**;
= 80
:::

:::quiz short
Και στον **TCP client**;
= 5000
:::

:::evaluate
Έλεγχος απαντήσεων
:::

Για αυτούς τους αριθμούς — τις **θύρες** — θα μάθεις περισσότερα στην ενότητα 5.3. Προς το παρόν αρκεί να ξέρεις: μόνο το επίπεδο μεταφοράς φροντίζει ώστε πολλά προγράμματα να μπορούν να επικοινωνούν ταυτόχρονα μέσω *μίας* διεύθυνσης IP και κάθε πακέτο να καταλήγει στο σωστό πρόγραμμα. Αυτό ονομάζεται **πολυπλεξία**.

## Πείραμα 2: Όταν χάνεται ένα πακέτο

1. Πέρασε στη λειτουργία :fa-play: **Εκτέλεση** και κάνε κλικ στο **καλώδιο** ανάμεσα στον Client-PC και τον Server.
2. Στο παράθυρο **Σύνδεση** ρύθμισε τη **Ρυθμισμένη απώλεια πακέτων** στο `25%`.
3. Άνοιξε στον **Client-PC** το :fa-terminal: **Terminal** και στείλε έξι pings:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Αυτό διαρκεί περίπου μισό λεπτό — περίμενε μέχρι να εμφανιστούν τα στατιστικά.

:::quiz mc
Τι συμβαίνει;
- [ ] Και τα έξι pings απαντώνται
- [x] Κάποια pings μένουν αναπάντητα — και κανείς δεν τα ξαναστέλνει
- [ ] Τα χαμένα pings επαναλαμβάνονται αυτόματα μέχρι να φτάσουν
:::

:::evaluate
Έλεγχος απάντησης
:::

Σε ένα ping αυτό δεν είναι πρόβλημα — άλλωστε σκοπός του είναι ακριβώς να δείξει αν χάνεται κάτι. Σε μια ιστοσελίδα, ένα e-mail ή μια λήψη αρχείου όμως, ένα κομμάτι που λείπει θα ήταν καταστροφικό: το αρχείο θα ήταν χαλασμένο.

## Οι τέσσερις εργασίες του επιπέδου μεταφοράς

| Εργασία | Τι σημαίνει |
|---|---|
| **Πολυπλεξία** | Πολλά προγράμματα και συνδέσεις μοιράζονται μία διεύθυνση IP· κάθε πακέτο καταλήγει στο σωστό πρόγραμμα. |
| **Εγκατάσταση σύνδεσης** | Πριν αρχίσουν να ρέουν δεδομένα, οι δύο πλευρές συμφωνούν ότι θα επικοινωνήσουν μεταξύ τους. |
| **Αξιόπιστη μετάδοση** | Ο παραλήπτης επιβεβαιώνει τι έχει φτάσει. Ό,τι λείπει αποστέλλεται ξανά και η σειρά αποκαθίσταται. |
| **Τερματισμός σύνδεσης** | Στο τέλος, οι δύο πλευρές κλείνουν τη σύνδεση με οργανωμένο τρόπο. |

:::tip Βασικό σημείο
Το **επίπεδο μεταφοράς** (επίπεδο 4) φροντίζει ώστε τα δεδομένα να φτάνουν στο σωστό **πρόγραμμα** (**πολυπλεξία**). Το πρωτόκολλο **TCP** φροντίζει επιπλέον ώστε να φτάνουν **πλήρη** και με τη **σωστή σειρά** — με εγκατάσταση σύνδεσης, επιβεβαιώσεις, επαναμετάδοση και τερματισμό σύνδεσης.
:::

:::quiz match
Σε έναν υπολογιστή τρέχουν ταυτόχρονα περιηγητής, πρόγραμμα αλληλογραφίας και messenger. -> Πολυπλεξία
Πριν αρχίσουν να ρέουν δεδομένα, οι δύο πλευρές διαπιστώνουν ότι η άλλη είναι έτοιμη. -> Εγκατάσταση σύνδεσης
Ένα μέρος ενός αρχείου δεν φτάνει και αποστέλλεται ξανά. -> Αξιόπιστη μετάδοση
Μετά τη λήψη, οι δύο πλευρές απελευθερώνουν ξανά τη σύνδεση. -> Τερματισμός σύνδεσης
:::
