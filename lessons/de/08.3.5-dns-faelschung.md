# Angriff: DNS-Fälschung

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna möchte auf dem **Client-PC** ihr Online-Banking bei der **Biberbank** öffnen. Was sie nicht weiß: Jemand hat sich Zugang zum **DNS-Server** verschafft und einen Eintrag verändert.

Auf der Arbeitsfläche siehst du den echten Webserver **www.biberbank.de** und den Rechner eines **Angreifers**. Auf ihm läuft eine Kopie der Bank-Webseite.

## Teil 1: Ohne Verschlüsselung

Wechsle in den :fa-play: **Ausführen**-Modus und rufe auf dem **Client-PC** im :fa-globe: **Browser** `http://www.biberbank.de/` auf.

:::quiz mc
Was siehst du?
- [x] Die Anmeldeseite der Biberbank, ohne jede Warnung
- [ ] Eine Warnung, dass die Seite gefälscht ist
- [ ] Eine Fehlermeldung
:::

:::evaluate
Antwort prüfen
:::

Sieht alles normal aus. Aber mit welchem Server spricht der Browser wirklich? Öffne auf dem Client-PC das :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Welche IP-Adresse liefert der DNS-Server für `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Wem gehört diese Adresse? (Klicke im Bearbeiten-Modus auf die Geräte oder sieh dir ihre :fa-gear: **IP-Einstellungen** an.)
- [ ] Dem echten Webserver der Biberbank
- [x] Dem Angreifer
- [ ] Dem DNS-Server
:::

:::evaluate
Antworten prüfen
:::

Hätte Anna jetzt Kontonummer und PIN eingegeben, wären sie direkt beim Angreifer gelandet. Bei **HTTP** hat sie **keine Chance**, den Betrug zu bemerken: Die Adresszeile zeigt den richtigen Namen, die Seite sieht echt aus.

## Teil 2: Mit HTTPS

Rufe jetzt `https://www.biberbank.de/` auf.

:::quiz mc
Was passiert?
- [ ] Die gefälschte Seite erscheint mit Schloss
- [x] Der Browser warnt: Das Zertifikat wurde für einen anderen Namen ausgestellt
- [ ] Die echte Seite der Biberbank erscheint
:::

:::quiz short
Für welchen Namen ist das Zertifikat des Angreifers ausgestellt (ohne `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Antworten prüfen
:::

Der Angreifer hat sogar ein **echtes** Zertifikat einer vertrauenswürdigen CA — allerdings für seine eigene Domain `www.biber-gewinnspiel.de`. Ein Zertifikat für `www.biberbank.de` bekommt er von keiner CA, denn diese Domain gehört ihm nicht. Und ohne den **privaten Schlüssel** der Biberbank kann er auch ihr echtes Zertifikat nicht benutzen: Im Handshake müsste er den Server Key Exchange damit signieren.

:::quiz multi
Wovor schützt HTTPS hier — und wovor nicht?
- [x] HTTPS deckt auf, dass der Server nicht der echte ist
- [ ] HTTPS verhindert, dass der DNS-Server gefälscht wird
- [x] HTTPS hilft nur, wenn der Benutzer die Warnung ernst nimmt
- [ ] Mit HTTPS ist die gefälschte Seite gar nicht erreichbar
:::

:::evaluate
Antworten prüfen
:::

## Teil 3: Den DNS-Server reparieren

Öffne den **DNS-Server** und korrigiere den Eintrag für `www.biberbank.de`. Die richtige Adresse findest du in den :fa-gear: **IP-Einstellungen** des Webservers **www.biberbank.de**. Vergiss nicht, auf **Speichern** zu klicken.

:::note
Der Client-PC merkt sich DNS-Antworten eine Weile, damit er nicht bei jedem Aufruf neu fragen muss (**DNS-Cache**). Wie lange, steht in der Spalte **TTL** (*Time to Live*) in Sekunden. Liefert `nslookup` direkt nach deiner Korrektur noch die alte Adresse, warte die TTL ab und versuche es noch einmal.
:::

:::task
title: Biberbank wieder echt?
Prüft, ob der Client-PC www.biberbank.de zur richtigen Adresse auflöst und die Seite über HTTPS ohne Warnung abrufen kann.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
In echt fälscht ein Angreifer selten den DNS-Server selbst. Häufiger schiebt er seine Antworten in einem öffentlichen WLAN unter, verändert die Einstellungen eines Heimrouters oder lockt mit einer ähnlich aussehenden Adresse wie `www.biberbank-login.de` (**Phishing**). Gegen einen ähnlich klingenden Namen hilft auch HTTPS nicht — der Angreifer bekommt dafür ein gültiges Zertifikat. Deshalb: Adresse genau lesen!
:::

:::tip Merksatz
Bei einer **DNS-Fälschung** liefert der DNS-Server für einen Namen die Adresse eines Angreifers. Bei **HTTP** merkt man davon nichts. Bei **HTTPS** passt das Zertifikat des Angreifers nicht zum aufgerufenen Namen, und der Browser **warnt** — denn ein Zertifikat für fremde Domains stellt keine CA aus, und den privaten Schlüssel des echten Servers hat der Angreifer nicht.
:::
