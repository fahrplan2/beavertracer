# UDP beobachten

:::sim
url=/sims/lesson-5.5.btsim
:::

Auf dem **Server** läuft diesmal ein **UDP-Echo-Server** an Port `5000`. Auch hier ist das Kabel präpariert: Das **zweite Datagramm** vom Client-PC zum Server geht verloren.

## Das Experiment

1. Wechsle in den :fa-play: **Ausführen**-Modus und öffne auf dem **Client-PC** das :fa-terminal: **Terminal**.
2. Starte mit `nc` eine UDP-„Verbindung“ zum Server (`-u` steht für UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Tippe nacheinander `eins`, `zwei` und `drei` und drücke jeweils **Enter**. Jede Zeile, die zurückkommt, ist ein Echo des Servers.
4. Warte ein paar Sekunden und öffne dann im :fa-magnifying-glass: **Verfolgung**-Modus einen Trace für den **Client-PC**.

:::quiz mc
Welche Echos kommen zurück?
- [ ] Alle drei, `zwei` etwas später
- [x] Nur `eins` und `drei` — `zwei` fehlt und wird auch nicht nachgeschickt
- [ ] Gar keines
:::

:::quiz multi
Welche Pakete, die du von TCP kennst, fehlen bei UDP völlig?
- [x] Verbindungsaufbau (`SYN`)
- [x] Bestätigungen (`ACK`)
- [x] Verbindungsabbau (`FIN`)
- [ ] Pakete mit Portnummern
:::

:::evaluate
Antworten prüfen
:::

Klicke auf eines der UDP-Pakete und klappe **User Datagram Protocol** auf. Im Vergleich zum TCP-Kopf ist der UDP-Kopf winzig: **Source Port**, **Destination Port**, **Length** (Länge) und **Checksum** (Prüfsumme) — zusammen nur 8 Byte. Ein TCP-Kopf hat mindestens 20 Byte, mit Sequenz- und Bestätigungsnummer, Flags und Fenstergröße.

:::quiz mc
Welche Aufgabe aus Abschnitt 5.1 erledigt UDP trotzdem?
- [x] Multiplexen — über die Ports
- [ ] Verbindungsaufbau
- [ ] Zuverlässige Übertragung
:::

:::evaluate
Antwort prüfen
:::

:::tip Merksatz
**UDP** ist **verbindungslos**: kein Aufbau, keine Bestätigung, keine Neuübertragung, keine Reihenfolge. Es bietet nur **Ports** (Multiplexen) und eine **Prüfsumme**. Dafür ist es schnell und schlank — der UDP-Kopf hat nur 8 Byte. Geht ein Datagramm verloren, muss sich das Programm selbst darum kümmern — oder es ist ihm egal.
:::
