# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) ist ganz normales HTTP — nur dass es nicht direkt über TCP läuft, sondern durch eine verschlüsselte Schicht dazwischen: **TLS** (*Transport Layer Security*). Der Vorgänger von TLS hieß **SSL**; deshalb spricht man oft noch von „SSL-Zertifikaten“.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP merkt davon nichts: Es schickt seine Anfragen wie gewohnt, TLS verschlüsselt sie, TCP transportiert sie. Im OSI-Modell sitzt TLS zwischen Transport- und Anwendungsschicht, also in Schicht 4/5 — es baut auf TCP auf und verwaltet eine gesicherte Sitzung.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresse | `http://…` | `https://…` |
| Inhalt im Tracer lesbar? | ja | nein |
| Browser zeigt | „nicht sicher“ | Schloss |

TLS erledigt beim Verbindungsaufbau alles, was du in diesem Kapitel gelernt hast:

- Der Server weist sich mit seinem **Zertifikat** aus (**Authentizität**).
- Beide Seiten handeln mit **Diffie-Hellman** einen **Sitzungsschlüssel** aus — der Server **signiert** seinen Anteil.
- Danach werden alle Daten mit **AES** verschlüsselt (**Vertraulichkeit**) und gegen Veränderung gesichert (**Integrität**).

Das Prinzip ist nicht auf das Web beschränkt: Auch E-Mail (Abschnitt 8.4) und viele andere Protokolle laufen auf dieselbe Weise durch TLS.
