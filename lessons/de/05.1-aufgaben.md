# Was muss die Transportschicht leisten?

:::sim
url=/sims/lesson-5.1.btsim
:::

Auf dem **Server** laufen zwei Dienste gleichzeitig: ein **Webserver** und ein kleiner **Echo-Dienst**, der jede Nachricht, die er bekommt, sofort zurückschickt. Mit zwei Experimenten findest du heraus, was IP allein nicht leisten kann.

## Experiment 1: Zwei Programme gleichzeitig

1. Wechsle in den :fa-play: **Ausführen**-Modus und klicke auf den **Client-PC**.
2. Öffne den :fa-globe: **Browser** und rufe `http://192.168.0.20/` auf.
3. Klicke oben im Fenster auf **Zurück** und öffne den **Einfachen TCP-Client**. Trage bei **Host** `192.168.0.20` und bei **Port** `5000` ein und klicke auf **Verbinden**.
4. Wechsle in den :fa-magnifying-glass: **Verfolgung**-Modus und öffne mit **+** einen Trace für den **Client-PC**, Anschluss `eth0`.

Klicke auf ein Paket des Browsers (z.B. `GET /`) und auf eines des TCP-Clients und klappe jeweils **Internet Protocol Version 4** auf.

:::quiz mc
Welche IP-Adressen tragen die Pakete von Browser und TCP-Client?
- [x] Bei beiden dieselben: von `192.168.0.10` an `192.168.0.20`
- [ ] Der Browser verwendet eine andere Ziel-IP-Adresse als der TCP-Client
- [ ] Die Pakete des TCP-Clients haben keine IP-Adresse
:::

:::quiz mc
Reicht die Ziel-IP-Adresse also aus, damit der Server weiß, ob ein Paket zum Webserver oder zum Echo-Dienst gehört?
- [ ] Ja
- [x] Nein — beide Pakete haben dieselbe Ziel-IP-Adresse
:::

Irgendetwas anderes muss die beiden Verbindungen auseinanderhalten. Schau in die **Info**-Spalte der Pakete mit `[SYN]` — das ist jeweils das erste Paket einer Verbindung:

:::quiz short
Welche Zahl steht beim **Browser** hinter dem Pfeil `→`?
= 80
:::

:::quiz short
Und beim **TCP-Client**?
= 5000
:::

:::evaluate
Antworten prüfen
:::

Über diese Zahlen — die **Ports** — erfährst du in Abschnitt 5.3 mehr. Fürs Erste genügt: Erst die Transportschicht sorgt dafür, dass mehrere Programme gleichzeitig über *eine* IP-Adresse kommunizieren können und jedes Paket beim richtigen Programm landet. Das nennt man **Multiplexen**.

## Experiment 2: Wenn ein Paket verloren geht

1. Wechsle in den :fa-play: **Ausführen**-Modus und klicke auf das **Kabel** zwischen Client-PC und Server.
2. Stelle im Fenster **Verbindung** den **Konfigurierten Paketverlust** auf `25%`.
3. Öffne auf dem **Client-PC** das :fa-terminal: **Terminal** und schicke sechs Pings:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Das dauert etwa eine halbe Minute — warte, bis die Statistik erscheint.

:::quiz mc
Was passiert?
- [ ] Alle sechs Pings werden beantwortet
- [x] Einige Pings bleiben unbeantwortet — und niemand schickt sie noch einmal
- [ ] Verlorene Pings werden automatisch wiederholt, bis sie ankommen
:::

:::evaluate
Antwort prüfen
:::

Bei einem Ping ist das kein Problem — er soll ja gerade zeigen, ob etwas verloren geht. Bei einer Webseite, einer E-Mail oder einem Download wäre ein fehlendes Stück aber fatal: Die Datei wäre kaputt.

## Die vier Aufgaben der Transportschicht

| Aufgabe | Was das bedeutet |
|---|---|
| **Multiplexen** | Mehrere Programme und Verbindungen teilen sich eine IP-Adresse; jedes Paket landet beim richtigen Programm. |
| **Verbindungsaufbau** | Bevor Daten fließen, vereinbaren beide Seiten, dass sie miteinander sprechen. |
| **Zuverlässige Übertragung** | Der Empfänger bestätigt, was angekommen ist. Fehlendes wird erneut gesendet, die Reihenfolge wiederhergestellt. |
| **Verbindungsabbau** | Am Ende beenden beide Seiten die Verbindung geordnet. |

:::tip Merksatz
Die **Transportschicht** (Schicht 4) sorgt dafür, dass Daten beim richtigen **Programm** ankommen (**Multiplexen**). Das Protokoll **TCP** sorgt zusätzlich dafür, dass sie **vollständig** und in der **richtigen Reihenfolge** ankommen — mit Verbindungsaufbau, Bestätigungen, Neuübertragung und Verbindungsabbau.
:::

:::quiz match
Auf einem PC laufen Browser, Mail-Programm und Messenger gleichzeitig. -> Multiplexen
Bevor Daten fließen, stellen beide Seiten fest, dass die andere bereit ist. -> Verbindungsaufbau
Ein Teil einer Datei kommt nicht an und wird noch einmal geschickt. -> Zuverlässige Übertragung
Nach dem Download geben beide Seiten die Verbindung wieder frei. -> Verbindungsabbau
:::
