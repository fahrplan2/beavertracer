# TCP oder UDP?

| | TCP | UDP |
|---|---|---|
| Verbindung | Aufbau mit Drei-Wege-Handshake, geordneter Abbau | keine — jedes Datagramm steht für sich |
| Bestätigungen | ja (`ACK`) | nein |
| Verlorene Daten | werden erneut gesendet | bleiben verloren |
| Reihenfolge | wird wiederhergestellt | nicht garantiert |
| Kopf | mindestens 20 Byte | 8 Byte |
| Tempo | etwas langsamer, mehr Pakete | schnell, wenig Aufwand |

Wann ist weniger mehr?

- **Echtzeit:** Bei Videotelefonie, Internet-Telefonie oder Online-Spielen zählt jede Millisekunde. Ein verlorenes Stück Ton, das eine Sekunde später nachgeliefert wird, nützt niemandem mehr — lieber ein kurzes Knacksen als eine Verzögerung.
- **Kurze Anfragen:** Eine **DNS**-Anfrage („Welche IP-Adresse hat `www.beispiel.de`?“) passt in ein einziges Datagramm, die Antwort auch. Ein Verbindungsaufbau würde den Aufwand verdreifachen. Kommt keine Antwort, fragt das Programm einfach noch einmal.

Überall dort, wo jedes Byte ankommen muss — Webseiten, E-Mails, Downloads —, ist dagegen TCP die richtige Wahl.

:::tip Merksatz
**TCP** ist zuverlässig, aber aufwendiger — für alles, was **vollständig** ankommen muss (Web, E-Mail, Dateien). **UDP** ist schnell und schlank, aber ohne Garantien — für **Echtzeit** (Telefonie, Video, Spiele) und **kurze Anfragen** wie DNS.
:::
