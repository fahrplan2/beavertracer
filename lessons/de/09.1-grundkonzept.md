# Paketfilter: Regeln

Die einfachste und wichtigste Art von Firewall ist der **Paketfilter**. Er schaut sich jedes Paket an, das ihn passiert, und entscheidet anhand einer **Regelliste**, ob es durchdarf. Dafür liest er nur die Köpfe der Schichten 3 und 4 — den Inhalt (z.B. die Webseite) betrachtet er nicht.

## Woraus eine Regel besteht

| Feld | Bedeutung | Beispiel |
|---|---|---|
| **Richtung** | Von welcher Seite kommt das Paket? | A → B (aus dem Internet ins Schulnetz) |
| **Protokoll** | TCP, UDP, ICMP oder beliebig | TCP |
| **Quell-IP** | Absenderadresse oder -netz | beliebig |
| **Quell-Port** | Absenderport | beliebig |
| **Ziel-IP** | Empfängeradresse oder -netz | `198.51.100.10` |
| **Ziel-Port** | Empfängerport, also der Dienst | `80` |
| **Aktion** | Was passiert mit passenden Paketen? | Zulassen |

Ein leeres Feld bedeutet „beliebig“. Netze schreibt man in CIDR-Schreibweise wie `198.51.100.0/24`, Portbereiche mit Bindestrich wie `1024-65535`.

## Die Reihenfolge entscheidet

Die Firewall prüft die Regeln **von oben nach unten**. Die **erste Regel, die passt**, entscheidet — alle folgenden werden für dieses Paket nicht mehr angesehen. Passt keine Regel, gilt die **Standardrichtlinie** (*Default Policy*).

## Drei mögliche Aktionen

| Aktion | Was die Firewall tut | Was der Absender merkt |
|---|---|---|
| **Zulassen** (*Allow*) | Paket wird weitergeleitet | — |
| **Verwerfen** (*Drop*) | Paket wird kommentarlos weggeworfen | gar nichts — er wartet, bis ein Timeout abläuft |
| **Zurückweisen** (*Reject*) | Paket wird weggeworfen, der Absender bekommt eine Absage: bei TCP ein **RST**, sonst ICMP „nicht erreichbar“ | sofort eine Fehlermeldung |

Was ist besser? **Verwerfen** verrät einem Angreifer weniger und kostet ihn Zeit, weil er auf jeden Versuch warten muss. **Zurückweisen** ist freundlicher zu den eigenen Nutzern: Ein Programm bekommt sofort eine Fehlermeldung, statt lange zu hängen. In der Praxis verwirft man daher meist Pakete von außen und weist Pakete aus dem eigenen Netz zurück.

:::quiz match
Zulassen -> Das Paket wird weitergeleitet
Verwerfen -> Das Paket verschwindet, der Absender wartet vergeblich auf Antwort
Zurückweisen -> Das Paket wird nicht weitergeleitet, aber der Absender bekommt sofort eine Absage
Standardrichtlinie -> Gilt, wenn keine Regel passt
:::

:::tip Merksatz
Ein **Paketfilter** prüft jedes Paket anhand von Richtung, Protokoll, Adressen und Ports gegen eine **Regelliste**. Die **erste passende Regel** entscheidet über die Aktion: **Zulassen**, **Verwerfen** (still) oder **Zurückweisen** (mit Absage). Passt keine Regel, gilt die **Standardrichtlinie**.
:::
