# HTTP von Hand

:::sim
url=/sims/lesson-6.1.btsim
:::

Wenn HTTP reiner Text ist — kann man dann auch selbst mit einem Webserver sprechen, ganz ohne Browser? Ja: Mit `telnet` baust du eine TCP-Verbindung zu einem beliebigen Port auf und tippst den Text selbst.

## Das Experiment

1. Wechsle in den :fa-play: **Ausführen**-Modus und öffne auf dem **Client-PC** das :fa-terminal: **Terminal**.
2. Verbinde dich mit Port 80 des Servers:
   ```
   $ telnet 192.168.0.20 80
   ```
3. Tippe die Anfrage Zeile für Zeile — und schließe sie mit einer **leeren Zeile** ab (einfach noch einmal **Enter**):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

Der Server antwortet mit Statuszeile, Headern und der Kontaktseite — als Text, so wie der Browser sie auch bekommt.

:::quiz mc
Woran erkennt der Server, dass deine Anfrage zu Ende ist?
- [ ] An einem besonderen Befehl `END`
- [x] An der leeren Zeile
- [ ] Nach einer bestimmten Zeit
:::

:::quiz short
Welcher Wert steht in der Antwort beim Header `Content-Type`? (nur der erste Teil vor dem `;`)
= text/html
:::

## Fehler provozieren

Ein bequemeres Werkzeug ist `curl`: Es stellt die Anfrage für dich. Mit `-v` (*verbose*, ausführlich) zeigt es dabei alles, was hin- und hergeht — Zeilen mit `>` hat `curl` gesendet, Zeilen mit `<` kamen vom Server.

Probiere aus:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
Welchen Statuscode bekommst du für `/gibtsnicht.html`?
= 404
:::

:::quiz short
Und welchen für die Anfrage mit der Methode `POST`?
= 405
:::

:::evaluate
Antworten prüfen
:::

:::note
Der Webserver in BeaverTracer kann nur Dateien ausliefern — deshalb erlaubt er nur `GET` und `HEAD`. Echte Webserver nehmen mit `POST` zum Beispiel Formulare entgegen und reichen die Daten an ein Programm weiter.
:::

:::tip Merksatz
Viele Protokolle der Anwendungsschicht sind **textbasiert** — HTTP, aber auch SMTP, POP3 und IMAP. Man kann sie deshalb mit `telnet` von Hand sprechen und im Tracer mitlesen. Das ist praktisch zur Fehlersuche — aber auch ein Sicherheitsproblem: Jeder, der mitschneidet, kann alles lesen. Wie Verschlüsselung (HTTPS) hilft, lernst du in Kapitel 8.
:::
