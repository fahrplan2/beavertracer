# Wie DNS organisiert ist

:::sim
url=/sims/lesson-6.2.btsim
:::

Kein einzelner Server kann alle Namen der Welt kennen. DNS ist deshalb **hierarchisch** aufgebaut — wie die Namen selbst. Man liest sie von rechts nach links:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Der Server, der für eine Domain zuständig ist und die Antwort wirklich kennt, heißt **autoritativ**. Den Weg dorthin übernimmt für den PC ein **Resolver** — hier der Rechner **DNS-Resolver**.

## Das Experiment

1. Wechsle in den :fa-play: **Ausführen**-Modus und gib auf dem **Client-PC** im :fa-terminal: **Terminal** ein:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. Öffne im :fa-magnifying-glass: **Verfolgung**-Modus einen Trace für den **DNS-Resolver**.

Der Resolver hat für dich eine ganze Reihe von Anfragen gestellt. Ordne zu, wer welche Antwort gegeben hat:

:::quiz match
Root-Server (192.168.0.101) -> Verweis: Für .de ist ns.nic.de zuständig
de-Server (192.168.0.102) -> Verweis: Für beaver-schule.de ist ns.beaver-schule.de zuständig
Schul-DNS (192.168.0.103) -> Antwort: www.beaver-schule.de hat die Adresse 192.168.0.20
:::

:::quiz mc
Wen fragt der Resolver als Erstes?
- [x] Den Root-Server
- [ ] Den Schul-DNS
- [ ] Den Client-PC
:::

:::evaluate
Antworten prüfen
:::

:::note
Zwischendurch fragt der Resolver auch nach den Adressen der Server, auf die er verwiesen wurde (`A ns.nic.de`). Echte DNS-Server schicken diese Adressen meist gleich mit. Außerdem merken sich Resolver jede Antwort eine Weile (**Cache**) — die nächste Anfrage nach demselben Namen beantworten sie sofort selbst. Wie lange, steht im Eintrag als **TTL** (*Time to Live*) in Sekunden.
:::

## Die wichtigsten Eintragstypen

| Typ | Bedeutung | Beispiel |
|---|---|---|
| **A** | Name → IPv4-Adresse | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | Name → IPv6-Adresse | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | Name → anderer Name (Alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | zuständiger Mailserver einer Domain | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | zuständiger DNS-Server einer Domain | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Merksatz
DNS ist **hierarchisch**: **Root-Server** verweisen auf die Server der **Top-Level-Domains** (z.B. `.de`), diese auf die Server der einzelnen **Domains**. Der zuständige **autoritative** Server kennt die Antwort. Ein **Resolver** geht diesen Weg für den PC und merkt sich die Antworten (**Cache**). Wichtige Eintragstypen: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Einen Eintrag anlegen

Die Schule möchte, dass ihre Webseite zusätzlich unter `intranet.beaver-schule.de` erreichbar ist.

1. Klicke im :fa-play: **Ausführen**-Modus auf den **Schul-DNS** und öffne die App **DNS-Server**.
2. Öffne den Reiter **A**. Klicke auf **+** und trage in die neue Zeile den Namen `intranet.beaver-schule.de` und die Adresse `192.168.0.20` ein.
3. Teste auf dem Client-PC mit `nslookup intranet.beaver-schule.de`.

:::task

Prüft, ob der Client-PC den Namen intranet.beaver-schule.de zur Adresse des Webservers auflöst. Die Simulation muss dafür im Ausführen-Modus laufen.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
