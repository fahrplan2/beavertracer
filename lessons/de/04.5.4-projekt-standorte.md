# Projekt: Eine Firma mit vier Standorten

:::sim
url=/sims/lesson-4.5.4.btsim
:::

Eine Firma hat ihren Hauptsitz in **Hanau** und Filialen in **Kassel**, **Gießen** und **Darmstadt**. Jeder Standort hat ein eigenes Netz und einen eigenen Router. Alle Router sind über Standleitungen mit einem **zentralen Netz** verbunden, in dem auch der Hauptserver der Firma steht.

## Der Adressplan

Der Administrator hat die Adressen nach folgendem Schema vergeben — sie sind in der Simulation schon eingetragen:

| Netz | Adressbereich |
|---|---|
| Zentrales Netz | `10.19.0.0/24` |
| Hanau | `10.19.1.0/24` |
| Kassel | `10.19.2.0/24` |
| Gießen | `10.19.3.0/24` |
| Darmstadt | `10.19.4.0/24` |

| Gerät | im zentralen Netz | im Standortnetz |
|---|---|---|
| Server | `10.19.0.10` | — |
| Router Hanau | `10.19.0.1` | `10.19.1.1` |
| Router Kassel | `10.19.0.2` | `10.19.2.1` |
| Router Gießen | `10.19.0.3` | `10.19.3.1` |
| Router Darmstadt | `10.19.0.4` | `10.19.4.1` |
| PC am Standort | — | jeweils `.2` (z.B. PC Kassel `10.19.2.2`) |

Bei allen Routern zeigt `eth0` ins zentrale Netz und `eth1` ins Standortnetz.

## Dein Auftrag

Damit alle Rechner der Firma sich gegenseitig und den Server erreichen, fehlen noch zwei Dinge:

1. **Gateways:** Trage bei allen vier PCs und beim Server ein Gateway ein. Die PCs nutzen den Router ihres Standorts; der Server nutzt den **Router Hanau**.
2. **Routing-Tabellen:** Ergänze bei allen vier Routern die Routen, die noch fehlen. Jeder Router muss die Netze der **drei anderen** Standorte kennen.

Teste zwischendurch mit `ping` und `traceroute`.

<details>
<summary>Tipp: Wie sieht eine Route hier aus?</summary>

Ein Beispiel für **Router Kassel**: Pakete für Gießen (`10.19.3.0/24`) gehen an den Router Gießen in seinem zentralen Netz — also **Nächster Hop** `10.19.0.3`, **Iface** `eth0`. Nach diesem Muster braucht jeder Router drei Routen.
</details>
