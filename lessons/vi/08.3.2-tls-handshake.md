## Quá trình trong sơ đồ

Nếu bỏ qua các xác nhận TCP (`ACK`), handshake trông như sau:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Điều gì xảy ra ở đây — và khối kiến thức nào của phần 8.1 nằm phía sau:

1. **Client Hello / Server Hello:** Máy khách và máy chủ chào nhau, trao đổi các số ngẫu nhiên và thống nhất các phương pháp (trong BeaverTracer: trao đổi khóa bằng **ECDHE**, chữ ký bằng **ECDSA**, mã hóa bằng **AES**).
2. **Certificate:** Máy chủ gửi **chứng chỉ** của nó. Máy khách kiểm tra chữ ký của CA, thời hạn hiệu lực và tên. Nếu việc này thất bại, máy khách dừng lại ngay tại đây — và trình duyệt hiển thị cảnh báo.
3. **Server Key Exchange:** Máy chủ gửi **phần Diffie-Hellman** của nó — và **ký** phần đó bằng khóa riêng của mình. Máy khách kiểm tra chữ ký bằng khóa công khai lấy từ chứng chỉ. Nhờ vậy nó biết: phần này thực sự đến từ chủ sở hữu chứng chỉ, không phải từ kẻ tấn công man-in-the-middle.
4. **Client Key Exchange:** Máy khách gửi phần Diffie-Hellman của nó. Bây giờ cả hai bên có thể tính ra cùng một **khóa phiên** — mà khóa đó chưa từng được truyền đi.
5. **Change Cipher Spec:** "Từ giờ tôi mã hóa."
6. **Encrypted Handshake Message (Finished):** Cả hai bên gửi — đã được mã hóa — một giá trị kiểm tra (checksum) trên tất cả các thông điệp handshake trước đó. Nếu kẻ tấn công đã thay đổi điều gì đó trên đường đi, các giá trị kiểm tra sẽ không khớp và kết nối bị hủy.
7. **Application Data:** Từ đây dữ liệu HTTP được truyền đi — được mã hóa đối xứng bằng AES.

:::quiz match
Certificate -> Máy chủ xác thực bản thân bằng chứng chỉ của nó
Server Key Exchange -> Phần Diffie-Hellman của máy chủ đã được ký
Client Key Exchange -> Phần Diffie-Hellman của máy khách
Change Cipher Spec -> Từ giờ dữ liệu được mã hóa
Application Data -> Dữ liệu HTTP đã mã hóa
:::

:::note
Trong trace, bạn chỉ thấy **một** handshake, mặc dù trình duyệt tải hai tệp — trang và stylesheet `style.css`. Trình duyệt giữ kết nối mở (**Keep-Alive**) và gửi yêu cầu thứ hai qua chính kết nối đã được mã hóa đó. Nếu không có Keep-Alive, mỗi tệp sẽ cần một kết nối riêng với handshake riêng và khóa phiên riêng. Phiên bản mới hơn **TLS 1.3** còn cần ít thông điệp hơn so với TLS 1.2 được trình bày ở đây.
:::

:::tip Ghi nhớ
Trong **TLS handshake**, máy chủ xác thực bản thân bằng **chứng chỉ**, hai bên thỏa thuận một **khóa phiên** bằng **Diffie-Hellman** (máy chủ **ký** phần của nó), và bằng **Finished** cả hai kiểm tra rằng không ai đã thay đổi handshake. Sau đó dữ liệu được truyền đi dưới dạng **Application Data** được mã hóa đối xứng.
:::
