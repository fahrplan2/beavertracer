# Sơ đồ trình tự

:::sim
url=/sims/lesson-5.1.btsim
:::

Diễn biến của một kết nối được vẽ thành **sơ đồ trình tự**: client và server mỗi bên có một đường thẳng đứng, thời gian chạy từ trên xuống dưới. Mỗi mũi tên là một gói tin. Mũi tên được vẽ nghiêng vì mỗi gói tin cần một khoảng thời gian nhất định để đi trên đường truyền.

Đây là kết nối của bạn ở trang trước — hãy so sánh từng dòng với bản trace:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Phía trên mỗi mũi tên là các **cờ (flag)**, phía dưới là các số `SEQ` và `ACK`. **DATA** đánh dấu các gói tin có dữ liệu thực. Các số màu đỏ thuộc về client, các số màu xanh thuộc về server — ý nghĩa của chúng sẽ được giải thích ở trang tiếp theo.

## Các cờ

| Cờ | viết tắt của | Ý nghĩa |
|---|---|---|
| **SYN** | *synchronize* | Thiết lập kết nối, xác định số bắt đầu |
| **ACK** | *acknowledge* | Xác nhận dữ liệu đã nhận |
| **PSH** | *push* | Chuyển dữ liệu ngay cho chương trình |
| **FIN** | *finish* | „Tôi đã xong“ — đóng kết nối |
| **RST** | *reset* | Hủy hoặc từ chối kết nối (xem thêm ở 5.3.2) |

## Ba giai đoạn

**Thiết lập:** Client gửi `SYN`, server trả lời bằng `SYN, ACK`, client xác nhận bằng `ACK`. Vì cần đúng ba gói tin nên quá trình này được gọi là **bắt tay ba bước (Three-way Handshake)**.

**Dữ liệu:** Mỗi gói tin có dữ liệu được bên nhận xác nhận bằng một `ACK`. Ở đây server gửi lại echo — client cũng xác nhận gói tin đó.

**Đóng kết nối:** Mỗi bên kết thúc chiều gửi của mình một cách riêng biệt: `FIN` từ client, `ACK` từ server — sau đó `FIN` từ server, `ACK` từ client. Tổng cộng là bốn gói tin.

:::tip Ghi nhớ
Một kết nối TCP diễn ra qua ba giai đoạn: **thiết lập** bằng **bắt tay ba bước** (`SYN` → `SYN, ACK` → `ACK`), **truyền dữ liệu** (mỗi gói tin dữ liệu được xác nhận bằng `ACK`) và **đóng kết nối** (mỗi bên gửi `FIN` và nhận lại một `ACK`).
:::

## Đến lượt bạn

Lần này client chỉ gửi `Hi` (cùng ký tự xuống dòng là 4 byte). Hãy điền các cờ còn thiếu — thứ tự trong cùng một ô không quan trọng.

Client-PC -> Server: ? FIN, ACK
Server -> Client-PC: ? ACK
Server -> Client-PC: ? FIN, ACK
Client-PC -> Server: ? ACK
:::
