## Một yêu cầu trông như thế nào

Trong trace, nhấp vào gói tin `GET / HTTP/1.1` và mở rộng **Hypertext Transfer Protocol**. Một yêu cầu HTTP chỉ là văn bản thuần:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

Phản hồi của máy chủ cũng có cấu trúc tương tự — gồm một dòng trạng thái, các header, một dòng trống và sau đó là chính tệp được yêu cầu:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | Yêu cầu HTTP
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | Yêu cầu HTTP
Server -> Client-PC: 200 OK | style.css
:::

## Phương thức và mã trạng thái

**Phương thức** cho biết client muốn gì:

| Phương thức | Ý nghĩa |
|---|---|
| **GET** | lấy một tệp |
| **POST** | gửi dữ liệu đến máy chủ, ví dụ một biểu mẫu đã điền |
| **HEAD** | chỉ lấy các header, không lấy tệp |

**Mã trạng thái** cho biết mọi việc diễn ra thế nào. Chữ số đầu tiên cho biết loại phản hồi:

| Mã | Văn bản | Ý nghĩa |
|---|---|---|
| **200** | OK | mọi thứ đều ổn |
| **301** | Moved Permanently | trang đã được chuyển vĩnh viễn |
| **404** | Not Found | không có tệp này |
| **405** | Method Not Allowed | phương thức này không được phép ở đây |
| **500** | Internal Server Error | lỗi trên máy chủ |

`2xx` nghĩa là thành công, `3xx` chuyển hướng, `4xx` lỗi do client (yêu cầu sai), `5xx` lỗi do máy chủ.

:::tip Ghi nhớ
**HTTP** hoạt động theo **nguyên tắc yêu cầu – phản hồi**: client gửi một **yêu cầu** (phương thức như `GET`, đường dẫn, header), máy chủ trả lời bằng một **mã trạng thái** (ví dụ `200 OK`, `404 Not Found`), các header và tệp. Mỗi tệp của một trang web đều có một yêu cầu riêng.
:::
