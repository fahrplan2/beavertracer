# HTTP يدويًا

:::sim
url=/sims/lesson-6.1.btsim
:::

إذا كان HTTP نصًا عاديًا فقط — فهل يمكنك أن تتحدث بنفسك مع خادم ويب دون أي متصفح؟ نعم: باستخدام `telnet` تنشئ اتصال TCP بأي منفذ تريده وتكتب النص بنفسك.

## التجربة

1. انتقل إلى وضع التشغيل :fa-play: **تشغيل** وافتح :fa-terminal: **المحطة الطرفية** على **Client-PC**.
2. اتصل بالمنفذ 80 على الخادم:
   ```
   $ telnet 192.168.0.20 80
   ```
3. اكتب الطلب سطرًا بعد سطر — وأنهِه بـ **سطر فارغ** (اضغط **Enter** مرة أخرى فقط):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

يرد الخادم بسطر الحالة والترويسات وصفحة الاتصال — كنص، تمامًا كما يستقبلها المتصفح.

:::quiz mc
بماذا يعرف الخادم أن طلبك قد انتهى؟
- [ ] بأمر خاص `END`
- [x] بالسطر الفارغ
- [ ] بعد مرور وقت معين
:::

:::quiz short
ما القيمة الموجودة في الترويسة `Content-Type` في الرد؟ (الجزء الأول فقط قبل `;`)
= text/html
:::

:::evaluate
التحقق من الإجابات
:::

## افتعال الأخطاء

أداة أكثر راحة هي `curl`: فهي ترسل الطلب نيابةً عنك. ومع الخيار `-v` (*verbose*، أي مفصّل) تعرض كل ما يُرسَل ويُستقبَل — الأسطر التي تبدأ بـ `>` أرسلها `curl`، والأسطر التي تبدأ بـ `<` جاءت من الخادم.

جرّب ما يلي:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
ما رمز الحالة الذي تحصل عليه للمسار `/gibtsnicht.html`؟
= 404
:::

:::quiz short
وما رمز الحالة للطلب الذي يستخدم الطريقة `POST`؟
= 405
:::

:::evaluate
التحقق من الإجابات
:::

:::note
خادم الويب في BeaverTracer يستطيع تقديم الملفات فقط — لذلك يسمح بالطريقتين `GET` و`HEAD` فقط. أما خوادم الويب الحقيقية فتستقبل بالطريقة `POST` مثلًا النماذج، وتمرّر البيانات إلى برنامج ما.
:::

:::tip تذكّر
كثير من بروتوكولات طبقة التطبيقات **نصية** — مثل HTTP، وكذلك SMTP وPOP3 وIMAP. لذلك يمكنك التحدث بها يدويًا باستخدام `telnet` وقراءتها في المتتبّع. هذا مفيد في استكشاف الأخطاء وإصلاحها — لكنه أيضًا مشكلة أمنية: كل من يلتقط حركة البيانات يستطيع قراءة كل شيء. ستتعلم في الفصل 8 كيف يساعد التشفير (HTTPS) في ذلك.
:::
