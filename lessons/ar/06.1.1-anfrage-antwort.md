## كيف يبدو الطلب

انقر في التتبع على الحزمة `GET / HTTP/1.1` ووسّع **Hypertext Transfer Protocol**. طلب HTTP هو نص عادي:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

استجابة الخادم مبنية بالطريقة نفسها — من سطر حالة ورؤوس (Header) وسطر فارغ ثم الملف نفسه:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | طلب HTTP
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | طلب HTTP
Server -> Client-PC: 200 OK | style.css
:::

## الطرائق ورموز الحالة

تحدّد **الطريقة** (Method) ما يريده العميل:

| الطريقة | المعنى |
|---|---|
| **GET** | استرجاع ملف |
| **POST** | إرسال بيانات إلى الخادم، مثل نموذج تمت تعبئته |
| **HEAD** | استرجاع الرؤوس فقط دون الملف |

يبيّن **رمز الحالة** كيف سارت الأمور. ويدلّ الرقم الأول على نوع الاستجابة:

| الرمز | النص | المعنى |
|---|---|---|
| **200** | OK | كل شيء على ما يرام |
| **301** | Moved Permanently | انتقلت الصفحة بشكل دائم |
| **404** | Not Found | الملف غير موجود |
| **405** | Method Not Allowed | هذه الطريقة غير مسموح بها هنا |
| **500** | Internal Server Error | خطأ على الخادم |

يعني `2xx` النجاح، و`3xx` إعادة التوجيه، و`4xx` خطأ من جانب العميل (طلب خاطئ)، و`5xx` خطأ من جانب الخادم.

:::tip تذكّر
يعمل **HTTP** وفق **مبدأ الطلب والاستجابة**: يرسل العميل **طلبًا** (طريقة مثل `GET`، ومسارًا، ورؤوسًا)، ويردّ الخادم برمز **حالة** (مثل `200 OK` أو `404 Not Found`) ورؤوس والملف. ولكل ملف من ملفات صفحة الويب طلب مستقل.
:::
