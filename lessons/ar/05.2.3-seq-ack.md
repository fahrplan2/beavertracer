# أرقام التسلسل وأرقام التأكيد

:::sim
url=/sims/lesson-5.1.btsim
:::

كيف يعرف TCP أن كل شيء قد وصل — وبأي ترتيب؟ كل طرف **يرقّم البايتات** التي يرسلها:

- **رقم التسلسل** (`SEQ`) هو رقم أول بايت موجود في هذه الحزمة.
- **رقم التأكيد** (`ACK`) يقول: «استلمت كل شيء حتى هنا — والبايت التالي الذي أتوقعه هو رقم …»

وهناك قاعدتان إضافيتان: يُحتسب كل من `SYN` و`FIN` كبايت واحد، رغم أنهما لا يحملان بيانات. ويعدّ كل طرف بشكل مستقل — لذلك هناك نطاقان للأرقام، باللون الأحمر (العميل) والأزرق (الخادم) في المخطط.

## التحقق بالحساب

هذا هو اتصالك مرة أخرى. تُظهر الأرقام على الخطوط عدّاد الجهاز عند تلك النقطة:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

تابع سلسلة الأرقام الحمراء:

1. يبدأ العميل من `SEQ=0`. وتستهلك رسالة `SYN` الخاصة به رقمًا واحدًا — فيؤكد الخادم بـ `ACK=1`.
2. تبدأ الرسالة عند `SEQ=1` وطولها 13 بايت (البايتات من 1 إلى 13). ويؤكد الخادم بـ `ACK=14`: «البايت التالي الذي أتوقعه هو رقم 14.»
3. لذلك تحمل رسالة `FIN` الخاصة بالعميل `SEQ=14` ويتم تأكيدها بـ `ACK=15`.

وتعمل سلسلة الأرقام الزرقاء الخاصة بالخادم بالطريقة نفسها تمامًا.

:::tip تذكّر
**رقم التسلسل** (`SEQ`) هو رقم أول بايت في الحزمة. أما **رقم التأكيد** (`ACK`) فهو رقم البايت التالي الذي يتوقعه المستقبِل — وكل ما قبله قد وصل. والقاعدة: **ACK = SEQ + طول** البيانات المستلمة؛ ويُحتسب كل من `SYN` و`FIN` كبايت واحد. كل طرف يعدّ بايتاته الخاصة.
:::

:::tip جرّب بنفسك
أنشئ الاتصال مرة أخرى في **عميل TCP البسيط** وأرسل رسالتين إحداهما بعد الأخرى. توقّع مسبقًا أي قيمتَي `Seq` و`Ack` ستظهران في عمود **Info** — ثم تحقق من ذلك في التتبع.
:::

## تدرّب

:::quiz short
يرسل العميل حزمة بـ `Seq=1` و`Len=13`. ما رقم التأكيد الذي يرسله الخادم في الرد؟
= 14
:::

:::quiz short
بعد ذلك يرسل العميل رسالته التالية. بأي رقم تسلسل تبدأ؟
= 14
:::

:::quiz short
وصلت حزمة بـ `Seq=40` و`Len=25`. ما رقم التأكيد الذي يرسله المستقبِل؟
= 65
:::

Server -> Client-PC: ACK ack=?

Server -> Client-PC: ACK ack=?

التحقق من المخطط

:::note
في الشبكات الحقيقية لا يبدأ العدّ من 0: إذ يختار كل طرف **رقمًا ابتدائيًا عشوائيًا** (*Initial Sequence Number*، أي ISN) بين 0 وحوالي 4.3 مليار. وعند الوصول إلى أعلى رقم يستمر العدّ من 0 مجددًا. يطرح المتتبّع الرقم الابتدائي ويعرض أرقامًا **نسبية** — تمامًا مثل Wireshark. لهذا ترى `Seq=0` و`Seq=1`.

كما تحتوي كل حزمة على `Win=` — أي **حجم النافذة**: وهو عدد البايتات التي يستطيع المستقبِل استيعابها حاليًا. وبهذا يبطّئ المستقبِل مرسِلًا سريعًا أكثر من اللازم (*التحكم في التدفق*). في BeaverTracer يكون حجم النافذة ثابتًا دائمًا.
:::
