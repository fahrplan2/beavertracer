# مخطط التراسل

:::sim
url=/sims/lesson-5.1.btsim
:::

يُرسم مسار الاتصال على شكل **مخطط التراسل**: يحصل العميل والخادم كلٌّ على خط عمودي، ويسير الزمن من الأعلى إلى الأسفل. كل سهم يمثّل حزمة. يُرسم السهم مائلاً لأن كل حزمة تستغرق وقتاً قصيراً في الطريق.

هكذا يبدو اتصالك من الصفحة السابقة — قارنه سطراً بسطر مع التتبع:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

فوق كل سهم توجد **الأعلام (Flags)**، وتحته الرقمان `SEQ` و`ACK`. تشير **DATA** إلى الحزم التي تحمل بيانات مفيدة. الأرقام الحمراء تخص العميل، والزرقاء تخص الخادم — ستوضح الصفحة التالية معناها.

## الأعلام

| العلم | اختصار لـ | المعنى |
|---|---|---|
| **SYN** | *synchronize* | إنشاء الاتصال وتحديد رقم البداية |
| **ACK** | *acknowledge* | يؤكد استلام البيانات |
| **PSH** | *push* | تمرير البيانات فوراً إلى البرنامج |
| **FIN** | *finish* | «لقد انتهيت» — إنهاء الاتصال |
| **RST** | *reset* | إلغاء الاتصال أو رفضه (المزيد عن ذلك في 5.3.2) |

## ثلاث مراحل

**الإنشاء:** يرسل العميل `SYN`، فيردّ الخادم بـ `SYN, ACK`، ثم يؤكد العميل بـ `ACK`. ولأن ثلاث حزم بالضبط لازمة، يُسمّى ذلك **المصافحة الثلاثية**.

**البيانات:** يؤكد المستقبِل كل حزمة تحمل بيانات بحزمة `ACK`. هنا يرسل الخادم الصدى عائداً — ويؤكد العميل ذلك أيضاً.

**الإنهاء:** ينهي كل طرف اتجاه إرساله على حدة: `FIN` من العميل، و`ACK` من الخادم — ثم `FIN` من الخادم، و`ACK` من العميل. أي أربع حزم.

:::tip تذكّر
يمر اتصال TCP بثلاث مراحل: **الإنشاء** عبر **المصافحة الثلاثية** (`SYN` ← `SYN, ACK` ← `ACK`)، و**نقل البيانات** (تُؤكَّد كل حزمة بيانات بـ `ACK`)، و**الإنهاء** (يرسل كل طرف `FIN` ويتلقى `ACK`).
:::
