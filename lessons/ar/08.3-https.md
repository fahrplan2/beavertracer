# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) هو بروتوكول HTTP العادي تمامًا — إلا أنه لا يعمل مباشرةً فوق TCP، بل عبر طبقة مشفّرة في المنتصف: **TLS** (*Transport Layer Security*). كان اسم سلف TLS هو **SSL**؛ ولذلك ما زال الناس يتحدثون غالبًا عن «شهادات SSL».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

لا يلاحظ HTTP شيئًا من ذلك: فهو يرسل طلباته كالمعتاد، ويقوم TLS بتشفيرها، وينقلها TCP. في نموذج OSI يقع TLS بين طبقة النقل وطبقة التطبيقات، أي في الطبقة 4/5 — فهو يعتمد على TCP ويدير جلسة مؤمَّنة.

| | HTTP | HTTPS |
|---|---|---|
| المنفذ | 80 | **443** |
| العنوان | `http://…` | `https://…` |
| هل المحتوى مقروء في المتتبع؟ | نعم | لا |
| ما يعرضه المتصفح | «غير آمن» | قفل |

يقوم TLS عند إنشاء الاتصال بكل ما تعلمته في هذا الفصل:

- يُثبت الخادم هويته بواسطة **شهادته الرقمية** (**الأصالة**).
- يتفق الطرفان باستخدام **Diffie-Hellman** على **مفتاح الجلسة** — ويقوم الخادم بـ**توقيع** حصته.
- بعد ذلك تُشفَّر جميع البيانات باستخدام **AES** (**السرّية**) وتُحمى من التغيير (**السلامة**).

هذا المبدأ لا يقتصر على الويب: فالبريد الإلكتروني (القسم 8.4) والعديد من البروتوكولات الأخرى تعمل أيضًا عبر TLS بالطريقة نفسها.

في الأقسام التالية ستلاحظ HTTPS في المتتبع، وتقوم بإعداده بنفسك، وتبحث متى يحذّرك المتصفح — ولماذا.
