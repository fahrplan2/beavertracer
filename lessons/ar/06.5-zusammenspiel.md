# كل شيء معًا: ماذا يحدث عند فتح صفحة ويب؟

:::goal
**هدف التعلّم:** تستطيع أن تشرح خطوة بخطوة أي البروتوكولات تشارك وعلى أي طبقة، عندما يفتح لابتوب جرى تشغيله للتو صفحة ويب.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

الآن يجتمع كل ما تعلمته في هذه الدورة. بالـ Switch يتصل **خادم DHCP** و**خادم DNS** و**خادم ويب** (**Webserver**) و**لابتوب** (**Laptop**) جرى تشغيله للتو — ليس لديه عنوان IP بعد، وهو مضبوط على DHCP.

## التجربة

1. انتقل إلى وضع :fa-play: **تشغيل** وانتظر بضع ثوانٍ.
2. انقر على **Laptop**، وافتح :fa-globe: **المتصفح** وافتح العنوان `http://www.beaver-schule.de/`.
3. في وضع :fa-magnifying-glass: **التتبع** افتح تتبعًا (Trace) للجهاز **Laptop**. هنا تجد القصة كاملة — منذ الحزمة الأولى.

رتّب الخطوات بالترتيب الصحيح كما تظهر في التتبع:

:::quiz match
1. Schritt -> DHCP: يحصل اللابتوب على عنوان IP والبوابة وخادم DNS
2. Schritt -> ARP: يسأل اللابتوب عن عنوان MAC الخاص بخادم DNS
3. Schritt -> DNS: يسأل اللابتوب عن عنوان IP للموقع www.beaver-schule.de
4. Schritt -> ARP: يسأل اللابتوب عن عنوان MAC الخاص بخادم الويب
5. Schritt -> TCP: مصافحة ثلاثية الاتجاه مع خادم الويب
6. Schritt -> HTTP: GET / والاستجابة 200 OK
:::

:::evaluate
التحقق من الترتيب
:::

وتحت كل ذلك يوجد **IP** (الطبقة 3) الذي يعنون كل واحدة من هذه الحزم، و**Ethernet** (الطبقة 2) الذي يوصلها إلى الجهاز التالي. لو كان خادم الويب في شبكة أخرى، لدخل **الراوتر** في المشهد أيضًا: عندها يسأل اللابتوب عن عنوان MAC الخاص بـ**البوابة** (Gateway) وليس عن عنوان MAC الخاص بخادم الويب.

:::quiz mc
لماذا لا يستطيع اللابتوب إرسال طلب DNS إلا بعد DHCP؟
- [ ] لأن DNS لا يعمل إلا عبر TCP
- [x] لأنه لا يحصل على عنوان IP خاص به ولا يعرف أي خادم DNS هو المسؤول إلا من خلال DHCP
- [ ] لأن خادم DNS لا يبدأ العمل إلا بعد خادم DHCP
:::

:::quiz mc
كم اتصال TCP يُنشئه المتصفح مع خادم الويب — ولماذا؟
- [ ] اتصال واحد لكل شيء معًا
- [x] اتصالان — واحد للصفحة وآخر لملف الأنماط (Stylesheet)
- [ ] لا اتصال إطلاقًا، فـ HTTP لا يحتاج إلى TCP
:::

:::evaluate
التحقق من الإجابات
:::

:::tip تذكّر
خلف نقرة واحدة تعمل كل الطبقات معًا: **DHCP** يوفّر الإعدادات الأساسية، و**ARP** يجد عناوين MAC في الشبكة المحلية، و**DNS** يترجم الاسم، و**TCP** يُنشئ اتصالًا موثوقًا، و**HTTP** يجلب الصفحة — وكل ذلك مغلّف في حزم **IP** وإطارات **Ethernet**.
:::

بهذا تستطيع أن تشرح عملية فتح صفحة ويب من الحزمة الأولى حتى الأخيرة. في ختام هذا الفصل يأتي استعراض موجز لبروتوكولات أخرى. وتتناول الفصول القادمة الشبكة المنزلية مع NAT، والأمان والتشفير — وبالتالي سؤال كيف نمنع أي شخص من قراءة كل هذه الحزم.
