# 방화벽 관찰하기

:::sim
url=/sims/lesson-9.1.1.btsim

이 시뮬레이션에서는 누군가 이미 방화벽에 규칙 세 개를 등록해 두었다. **Firewall**을 클릭하고 **Regeln** 탭을 살펴보자. 방화벽의 **Port A**는 인터넷에, **Port B**는 학교 라우터에 연결되어 있다. 따라서 "A → B"는 "인터넷에서 학교 네트워크로"를 뜻한다.

:::quiz table
| 규칙 | 방향 | 프로토콜 | 대상 포트 | 동작 |
|---|---|---|---|---|
| 1 | A → B | {TCP} | {22} | {폐기} |
| 2 | A → B | TCP | {110} | {거부} |
| 3 | A → B | {ICMP} | 임의 | 폐기 |
:::

:::evaluate
표 확인
:::

## 외부에서 보내는 ping

:fa-play: **실행** 모드로 전환하고 **Internet-PC**에서 학교 서버로 ping을 보내 보자.

```
$ ping -c 2 198.51.100.10
```

그런 다음 방화벽의 **Protokoll** 탭을 열어 보자.

## 포트 스캔: 폐기인가, 거부인가?

이제 포트 다섯 개를 골라서 스캔해 보자. 포트 3306(데이터베이스)은 학교 서버에서 전혀 운영되고 있지 않다.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (폐기) -> filtered
25 (허용, 서비스 실행 중) -> open
110 (거부) -> closed
3306 (허용, 서비스 없음) -> closed
:::

:::evaluate
짝짓기 확인
:::

:::quiz multi
공격자는 이 결과에서 무엇을 유추할 수 있는가?
- [x] `filtered`이면 패킷을 삼켜 버리는 방화벽이 있다는 것을 안다
- [x] `closed`이면 방화벽이 거부한 것인지 단순히 서비스가 실행되고 있지 않은 것인지 구분할 수 없다
- [ ] `filtered`이면 그 포트 뒤에서 어떤 서비스가 실행되는지 안다
- [ ] `closed`이더라도 서비스에는 접근할 수 있다
:::

:::evaluate
답 확인
:::

마지막으로 규칙 목록의 **Treffer** 열을 살펴보자. 방화벽은 여기에 각 규칙이 지금까지 몇 개의 패킷을 처리했는지 센다. **Standardrichtlinie** 옆의 값은 어떤 규칙에도 해당하지 않았던 모든 패킷의 수를 센 것이다.

:::tip 핵심 정리
**폐기된** 패킷은 흔적 없이 사라진다. `ping`은 타임아웃을 알리고 `nmap`은 `filtered`라고 알린다. **거부된** 패킷에는 방화벽이 거절 응답을 보낸다(TCP에서는 RST). 외부에서 보면 닫힌 포트처럼 보인다. 방화벽의 **Protokoll**은 어떤 패킷을 차단했는지, **Treffer** 열은 어떤 규칙이 적용되었는지 보여 준다.
:::
