첫 번째 암호화된 요청을 보내기 전에 클라이언트와 서버는 먼저 합의해야 한다. 어떤 방식을 쓸지, 어떤 세션 키를 쓸지 정해야 하고, 클라이언트는 누구와 통신하고 있는지도 확인해야 한다. 이러한 연결 설정을 **TLS 핸드셰이크**라고 한다.

## 다이어그램으로 보는 진행 과정

TCP 확인 응답(`ACK`)을 제외하면 핸드셰이크는 다음과 같다.

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

각 단계에서 일어나는 일과, 8.1절의 어떤 구성 요소가 그 뒤에 있는지 살펴보자.

1. **Client Hello / Server Hello:** 클라이언트와 서버가 서로 인사하고, 난수를 교환하며, 사용할 방식에 합의한다(BeaverTracer에서는 키 교환에 **ECDHE**, 서명에 **ECDSA**, 암호화에 **AES**를 사용한다).
2. **Certificate:** 서버가 자신의 **인증서**를 보낸다. 클라이언트는 CA의 서명, 유효 기간, 이름을 확인한다. 이 검증이 실패하면 여기서 중단하고, 브라우저는 경고를 표시한다.
3. **Server Key Exchange:** 서버가 자신의 **Diffie-Hellman 값**을 보내고, 이를 자신의 개인 키로 **서명**한다. 클라이언트는 인증서에 들어 있는 공개 키로 이 서명을 검증한다. 이렇게 해서 이 값이 Man-in-the-Middle이 아니라 인증서의 소유자에게서 온 것임을 알 수 있다.
4. **Client Key Exchange:** 클라이언트가 자신의 Diffie-Hellman 값을 보낸다. 이제 양쪽 모두 동일한 **세션 키**를 계산할 수 있으며, 이 키는 한 번도 전송되지 않았다.
5. **Change Cipher Spec:** "지금부터 암호화해서 보낼게요."
6. **Encrypted Handshake Message (Finished):** 양쪽이 이미 암호화된 상태로, 지금까지의 모든 핸드셰이크 메시지에 대한 체크섬을 보낸다. 공격자가 중간에 무언가를 변경했다면 체크섬이 일치하지 않아 연결이 중단된다.
7. **Application Data:** 이 시점부터 HTTP 데이터가 오가며, AES로 대칭 암호화된다.

:::quiz match
Certificate -> 서버가 자신의 인증서로 신원을 증명한다
Server Key Exchange -> 서버의 서명된 Diffie-Hellman 값
Client Key Exchange -> 클라이언트의 Diffie-Hellman 값
Change Cipher Spec -> 지금부터 암호화된다
Application Data -> 암호화된 HTTP 데이터
:::

:::note
트레이스에서는 TLS 연결이 차례로 **두 개** 보인다. 브라우저가 먼저 페이지를 가져오고, 이어서 스타일시트 `style.css`를 위한 새 연결을 설정한다. 각 연결은 자체 핸드셰이크와 자체 세션 키를 가진다. 실제 브라우저는 연결을 열어 둔 채 재사용하여 이런 부담을 일부 줄인다. 또한 최신 버전인 **TLS 1.3**은 여기에서 보여 주는 TLS 1.2보다 적은 메시지로 처리한다.
:::

:::tip 핵심 정리
**TLS 핸드셰이크**에서 서버는 **인증서**로 신원을 증명하고, 양쪽은 **Diffie-Hellman**으로 **세션 키**를 협상하며(서버는 자신의 값에 **서명**한다), **Finished**로 아무도 핸드셰이크를 변경하지 않았음을 서로 확인한다. 그 후 데이터는 **Application Data**로서 대칭 암호화되어 전송된다.
:::
