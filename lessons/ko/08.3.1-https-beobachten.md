# HTTP와 HTTPS 비교

:::sim
url=/sims/lesson-8.2.1.btsim
:::

웹 서버 **www.beaver-schule.de**는 학교의 성적 포털을 HTTP와 HTTPS 두 방식으로 모두 제공한다. 도청자는 무엇을 볼 수 있을까?

## 실험

1. :fa-play: **실행** 모드로 전환하고, **Client-PC**의 :fa-globe: **브라우저**에서 먼저 `http://www.beaver-schule.de/`를, 그다음 `https://www.beaver-schule.de/`를 열어 봐.
2. :fa-magnifying-glass: **추적** 모드에서 **Client-PC**의 트레이스를 열어 봐.
3. 먼저 `HTTP/1.1 200 OK` 패킷을 찾아 클릭해 봐. 아래 상세 정보에서 페이지의 내용을 확인할 수 있어.

:::quiz mc
**HTTP**를 사용할 때 도청자는 무엇을 볼 수 있을까?
- [x] 웹 페이지 전체, Anna의 성적도 포함해서
- [ ] 서버의 주소만
- [ ] 아무것도 볼 수 없다. HTTP는 TCP 위에서 동작하기 때문이다
:::

:::quiz short
Anna의 수학 성적은 몇 점일까?
= 2
:::

:::evaluate
답 확인
:::

이제 HTTPS 부분이다. 클라이언트가 두 번째 연결을 시작하는 `[SYN]` 패킷을 찾아 봐.

:::quiz short
HTTPS 연결의 목적지 포트는 무엇일까? (**Info** 열, `… → ???`)
= 443
:::

이제 트레이스 위쪽의 필터 입력란에 `tls`를 입력해 봐. 그러면 TLS 패킷만 보인다.

:::quiz mc
웹 페이지를 담고 있는 패킷의 **Info** 열에는 무엇이 표시될까?
- [ ] `HTTP/1.1 200 OK`
- [x] `Application Data`
- [ ] `Encrypted HTML`
:::

:::quiz multi
**HTTPS**를 사용해도 도청자가 여전히 볼 수 있는 것은 무엇일까?
- [x] 클라이언트와 서버의 IP 주소
- [x] 포트 443이 사용된다는 것, 즉 아마도 HTTPS라는 것
- [x] 대략 얼마나 많은 데이터가 전송되는지
- [ ] 어떤 페이지를 열었는지, 그리고 그 페이지에 무엇이 쓰여 있는지
:::

:::evaluate
답 확인
:::

:::note
**Application Data** 패킷을 클릭해 봐. 페이로드는 겉보기에 무작위인 바이트의 나열일 뿐이야. 트레이서는 이를 복호화할 수 없다. 세션 키를 알지 못하는 것은 공격자와 마찬가지이기 때문이다.
:::

:::tip 핵심 정리
**HTTP**에서는 어떤 도청자든 웹 페이지 전체를 읽을 수 있다. **HTTPS**에서는 **누가 누구와** 통신하는지(IP 주소, 포트 443)와 **얼마나 많이** 통신하는지만 보인다. 내용은 **Application Data** 패킷 안에 암호화되어 들어 있다.
:::
