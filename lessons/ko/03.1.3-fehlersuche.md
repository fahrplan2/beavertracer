# 스위치 네트워크 문제 해결

:::sim
url=/sims/lesson-3.1.3.btsim
:::

**David**가 네트워크에 새로 들어온 뒤로 문제가 생겼어: Clara에게는 아무도 접속할 수 없고, Ben도 뭔가 이상해. 네트워크 전문가로서 이 문제를 해결해야 해.

## 네트워크 구성도

네트워크는 원래 이렇게 *되어 있어야* 해:

| 장치 | IP 주소 | 스위치 포트 |
|---|---|---|
| Anna | `192.168.0.10/24` | 1 |
| Ben | `192.168.0.11/24` | 2 |
| Clara | `192.168.0.12/24` | 3 |
| David | `192.168.0.13/24` | 4 |

구성도와 시뮬레이션을 비교해 봐: 무엇이 다를까? 찾아낸 오류를 모두 고쳐 봐.

<details>
<summary>힌트 1: 어디서부터 시작할까?</summary>

먼저 케이블을 살펴봐: 모든 PC가 올바른 포트에 연결되어 있을까? 그다음 각 PC의 IP 설정을 확인해 봐.
</details>

<details>
<summary>힌트 2: Ben은 ping에 응답하는데 …?</summary>

Anna에서 Ben에게 ping을 보내고(`ping 192.168.0.11`) Anna에 대한 추적을 열어 봐. ARP 응답을 자세히 살펴봐: 응답이 몇 개이고, 어떤 MAC 주소를 가지고 있을까?
</details>

:::task
title: 네트워크 수리 완료?
모든 장치가 네트워크 구성도에 나온 주소를 가지고 있고 서로 통신할 수 있는지 확인해. 이를 위해 시뮬레이션이 실행 모드로 동작 중이어야 해.
check: ip(3, "192.168.0.10/32")
check: ip(5, "192.168.0.11/32")
check: ip(7, "192.168.0.12/32")
check: ip(11, "192.168.0.13/32")
check: pingOk(3, 7)
check: pingOk(3, 11)
check: pingOk(5, 7)
:::

## 무슨 일이 있었을까?

:::quiz mc
트레이서에서 두 장치가 같은 IP 주소를 가지고 있다는 것을 어떻게 알 수 있을까?
- [ ] ping이 항상 실패한다
- [x] 하나의 ARP 요청에 서로 다른 MAC 주소를 가진 응답이 두 개 온다
- [ ] 스위치가 오류 메시지를 표시한다
:::

:::evaluate
답 확인
:::

:::tip 핵심 정리
**문제 해결**을 할 때는 **목표 상태**(네트워크 구성도)와 **실제 상태**(케이블, 설정, 트레이서)를 비교해. 주의: ping이 성공했다고 해서 반드시 모든 것이 올바른 것은 아니야. IP 주소가 중복된 경우에는 엉뚱한 장치가 대신 응답하고 있을 수도 있어.
:::
