# 전송 계층은 무엇을 해야 할까?

:::sim
url=/sims/lesson-5.1.btsim
:::

**Server**에서는 두 가지 서비스가 동시에 실행된다. **웹 서버**와, 받은 메시지를 즉시 되돌려 보내는 작은 **에코 서비스**이다. 두 가지 실험을 통해 IP만으로는 무엇을 할 수 없는지 알아보자.

## 실험 1: 두 프로그램을 동시에

1. :fa-play: **실행** 모드로 전환하고 **Client-PC**를 클릭한다.
2. :fa-globe: **브라우저**를 열고 `http://192.168.0.20/`에 접속한다.
3. 창 위쪽의 **뒤로**를 클릭하고 **단순 TCP 클라이언트**를 연다. **Host**에 `192.168.0.20`을, **Port**에 `5000`을 입력하고 **연결**을 클릭한다.
4. :fa-magnifying-glass: **추적** 모드로 전환하고 **+**로 **Client-PC**의 `eth0` 포트에 대한 트레이스를 연다.

브라우저의 패킷(예: `GET /`)과 TCP 클라이언트의 패킷을 각각 클릭하고, 둘 다 **Internet Protocol Version 4**를 펼쳐 보자.

:::quiz mc
브라우저와 TCP 클라이언트의 패킷에는 어떤 IP 주소가 들어 있을까?
- [x] 둘 다 같다: `192.168.0.10`에서 `192.168.0.20`으로
- [ ] 브라우저는 TCP 클라이언트와 다른 목적지 IP 주소를 사용한다
- [ ] TCP 클라이언트의 패킷에는 IP 주소가 없다
:::

:::quiz mc
그렇다면 서버가 어떤 패킷이 웹 서버로 가는 것인지 에코 서비스로 가는 것인지 알려면 목적지 IP 주소만으로 충분할까?
- [ ] 그렇다
- [x] 아니다 — 두 패킷의 목적지 IP 주소가 같다
:::

두 연결을 구분해 주는 무언가가 따로 있어야 한다. `[SYN]`이 있는 패킷의 **Info** 열을 살펴보자. 이 패킷이 각 연결의 첫 번째 패킷이다.

:::quiz short
**브라우저**의 경우 화살표 `→` 뒤에 어떤 숫자가 있을까?
= 80
:::

:::quiz short
**TCP 클라이언트**의 경우는?
= 5000
:::

:::evaluate
답 확인
:::

이 숫자, 즉 **포트**에 대해서는 5.3절에서 더 자세히 배운다. 지금은 이것만 알면 된다. 전송 계층이 있어야 여러 프로그램이 *하나의* IP 주소로 동시에 통신할 수 있고, 각 패킷이 올바른 프로그램에 전달된다. 이를 **다중화**라고 한다.

## 실험 2: 패킷이 손실되면

1. :fa-play: **실행** 모드로 전환하고 Client-PC와 Server 사이의 **케이블**을 클릭한다.
2. **Verbindung** 창에서 **Konfigurierter Paketverlust**를 `25%`로 설정한다.
3. **Client-PC**에서 :fa-terminal: **터미널**을 열고 ping을 여섯 번 보낸다.
   ```
   $ ping -c 6 192.168.0.20
   ```
   약 30초가 걸린다. 통계가 나타날 때까지 기다리자.

:::quiz mc
어떻게 될까?
- [ ] 여섯 개의 ping에 모두 응답이 온다
- [x] 일부 ping은 응답이 없고, 아무도 다시 보내 주지 않는다
- [ ] 손실된 ping은 도착할 때까지 자동으로 반복된다
:::

:::evaluate
답 확인
:::

ping에서는 문제가 되지 않는다. ping은 바로 무언가 손실되는지 보여 주기 위한 것이기 때문이다. 하지만 웹 페이지, 이메일, 다운로드에서 일부가 빠지면 치명적이다. 파일이 손상되기 때문이다.

## 전송 계층의 네 가지 역할

| 역할 | 의미 |
|---|---|
| **다중화** | 여러 프로그램과 연결이 하나의 IP 주소를 공유하며, 각 패킷은 올바른 프로그램에 전달된다. |
| **연결 설정** | 데이터가 오가기 전에 양쪽이 서로 통신하기로 합의한다. |
| **신뢰성 있는 전송** | 수신자가 도착한 것을 확인해 준다. 빠진 것은 다시 전송하고, 순서를 복원한다. |
| **연결 종료** | 마지막에 양쪽이 연결을 질서 있게 끝낸다. |

:::tip 핵심 정리
**전송 계층**(4계층)은 데이터가 올바른 **프로그램**에 도착하도록 한다(**다중화**). 여기에 더해 **TCP** 프로토콜은 데이터가 **빠짐없이** 그리고 **올바른 순서**로 도착하도록 보장한다. 연결 설정, 확인 응답, 재전송, 연결 종료를 통해서이다.
:::

:::quiz match
한 PC에서 브라우저, 메일 프로그램, 메신저가 동시에 실행된다. -> 다중화
데이터가 오가기 전에 양쪽이 상대방이 준비되었는지 확인한다. -> 연결 설정
파일의 일부가 도착하지 않아 다시 전송된다. -> 신뢰성 있는 전송
다운로드가 끝나면 양쪽이 연결을 다시 해제한다. -> 연결 종료
:::
