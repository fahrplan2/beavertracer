# 하나의 네트워크로는 부족한 이유

:::sim
url=/sims/lesson-4.1.btsim
:::

작업 영역에는 작은 회사 네트워크 두 개가 보인다. **Firma A**에는 Anna(`192.168.0.10`)와 Ben(`192.168.0.11`)이 있고, **Firma B**에는 Clara(`172.16.0.10`)와 David(`172.16.0.11`)가 있다. 두 스위치는 심지어 케이블로 직접 연결되어 있다.

## 같은 네트워크 안에서의 핑

1. :fa-play: **실행** 모드로 전환하고, **Anna**에서 :fa-terminal: **터미널**을 열어 Ben에게 핑을 보낸다:
   ```
   $ ping 192.168.0.11
   ```
2. :fa-magnifying-glass: **추적** 모드로 전환하고, **Anna**의 트레이스를 연 다음 `Echo (ping) request`를 클릭한다.
3. 프로토콜 트리에서 **Internet Protocol Version 4** 줄을 펼친다. 이것이 패킷의 IP 부분이며, 이번 장에서 다루는 부분이다.

:::quiz match
Source Address -> 송신자의 IP 주소
Destination Address -> 수신자의 IP 주소
Time to Live -> 패킷이 앞으로 몇 개의 라우터를 더 통과할 수 있는지
Protocol -> 패킷 안에 어떤 프로토콜이 들어 있는지 (여기서는 ICMP, 즉 핑)
:::

:::evaluate
짝짓기 확인
:::

## 다른 네트워크로의 핑

다시 :fa-play: **실행** 모드로 전환하고 **Anna**에서 Clara에게 핑을 보낸다(`ping 172.16.0.10`). 그런 다음 Anna의 트레이스를 한 번 더 살펴본다.

:::quiz mc
무슨 일이 일어날까?
- [ ] 핑이 성공한다 — 스위치가 연결되어 있으니까
- [x] 핑이 도착하지 않고, Anna의 트레이스에는 Clara로 가는 패킷이 단 하나도 나타나지 않는다 — ARP 요청조차 없다
- [ ] Anna가 ARP 요청을 보내지만 Clara가 응답하지 않는다
:::

:::quiz mc
Anna는 왜 아무것도 보내지 않을까?
- [ ] 스위치 사이의 케이블이 고장 났다
- [ ] Clara의 전원이 꺼져 있다
- [x] Anna는 Clara의 IP 주소를 보고 Clara가 다른 네트워크에 있다는 것을 알아차리지만, 그곳으로 가는 경로를 알지 못한다
:::

:::evaluate
답 확인
:::

## 그 뒤에 있는 원리

IP 주소는 우편 주소와 비슷하게 동작한다. 한 부분은 장치가 어느 **네트워크**에 있는지(도로명에 해당)를 나타내고, 다른 부분은 그 네트워크 안에서 어느 **장치**를 가리키는지(번지수에 해당)를 나타낸다. Anna는 `192.168.0…` 네트워크에, Clara는 `172.16.0…` 네트워크에 있다. 서로 다른 두 개의 "도로"인 셈이다.

PC는 *같은* 네트워크에 있는 장치에는 패킷을 직접 보낸다(이미 알고 있듯이 ARP와 스위치를 통해). *다른* 네트워크로 보내려면 네트워크들을 서로 연결하고 패킷을 전달해 주는 장치, 즉 **라우터**가 필요하다. 여기에는 아직 라우터가 없다. 그래서 스위치 사이의 케이블도 도움이 되지 않는다.

:::tip 핵심 정리
3계층의 **인터넷 프로토콜**(**IP**)은 서로 다른 네트워크 사이에서도 패킷이 도착하도록 해 준다. **IP 주소**는 **네트워크 부분**(어느 네트워크인가?)과 **호스트 부분**(어느 장치인가?)으로 이루어진다. 같은 네트워크에 있는 장치끼리는 서로 직접 통신할 수 있지만, 다른 네트워크와 통신하려면 **라우터**가 필요하다.
:::

이로써 다음 절들에서 다룰 두 가지 질문이 생긴다. PC는 주소의 *정확히 어디*에서 네트워크 부분이 끝나는지 어떻게 알까? 그리고 라우터는 어떻게 동작할까?
