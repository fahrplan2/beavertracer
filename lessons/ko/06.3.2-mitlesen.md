# 트레이서에서 이메일 들여다보기

:::sim
url=/sims/lesson-6.3.btsim
:::

HTTP와 마찬가지로 SMTP도 **텍스트 프로토콜**이다. 이때 어떤 내용이 평문 그대로 회선을 오가는지 살펴보자.

## 실험

1. :fa-play: **실행** 모드에서 지난 페이지에서 했던 것처럼 **Anna**가 `ben@biber-mail.de`에게 메일을 보내 보자.
2. :fa-magnifying-glass: **추적** 모드에서 **Anna**의 트레이스를 열어 보자. **Info** 열에 SMTP 대화가 표시된다. `C:`로 시작하는 줄은 클라이언트가, `S:`로 시작하는 줄은 서버가 보낸 것이다.

:::quiz short
`MAIL FROM:` 뒤에는 어떤 주소가 있는가?
= anna@beaver-schule.de
= <anna@beaver-schule.de>
:::

:::quiz short
그렇다면 `RCPT TO:` 뒤에는 어떤 주소가 있는가?
= ben@biber-mail.de
= <ben@biber-mail.de>
:::

## 그럼 비밀번호는?

`MAIL FROM` 앞에서 Anna의 프로그램은 `AUTH PLAIN`과 `AGFubmEAZ2VoZWlt` 같은 문자열로 로그인한다. 암호화된 것처럼 보이지만 그렇지 않다. 이것은 단지 **Base64**일 뿐이고, 누구나 바로 원래대로 되돌릴 수 있는 인코딩 방식이다. 그 안에는 `anna`와 그녀의 비밀번호 `geheim`이 들어 있다.

이제 **Ben**에서 메일을 받아 오고(**가져오기**) **Ben**의 트레이스를 열어 보자. IMAP으로 메일을 가져올 때는 더욱 분명하게 보인다.

:::quiz short
Ben의 이메일 프로그램은 어떤 비밀번호를 평문으로 서버에 보내는가? (`LOGIN`이 있는 줄을 살펴보자.)
= biber123
:::

:::evaluate
답 확인
:::

:::warning
암호화하지 않으면 데이터 트래픽을 캡처하는 누구나 **내용, 송신자, 수신자, 비밀번호**를 읽을 수 있다. 그래서 오늘날에는 암호화된 방식(예: STARTTLS를 사용하는 SMTP, 포트 993의 IMAPS)을 사용한다. 이것이 어떻게 작동하는지는 8장에서 배운다.
:::

:::tip 핵심 정리
**SMTP**, **POP3**, **IMAP**은 텍스트 프로토콜이다. `MAIL FROM`, `RCPT TO`, `DATA`(SMTP)나 `LOGIN`(IMAP) 같은 명령과 그에 대한 응답을 읽을 수 있다. 암호화하지 않으면 **비밀번호**도 평문으로(또는 Base64로 인코딩만 된 채) 회선을 오간다.
:::
