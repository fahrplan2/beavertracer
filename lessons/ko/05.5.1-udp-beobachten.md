# UDP 관찰하기

:::sim
url=/sims/lesson-5.5.btsim

이번에는 **Server**에서 **UDP Echo-Server**가 포트 `5000`으로 실행된다. 여기서도 케이블에 조작이 되어 있다. Client-PC에서 서버로 가는 **두 번째 데이터그램**이 손실된다.

## 실험

1. :fa-play: **실행** 모드로 전환하고 **Client-PC**에서 :fa-terminal: **터미널**을 연다.
2. `nc`로 서버에 UDP "연결"을 시작한다(`-u`는 UDP를 뜻한다):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. `eins`, `zwei`, `drei`를 차례로 입력하고 매번 **Enter**를 누른다. 돌아오는 각 줄은 서버가 보낸 에코다.
4. 몇 초 기다린 뒤 :fa-magnifying-glass: **추적** 모드에서 **Client-PC**의 트레이스를 연다.

:::quiz mc

:::evaluate
답 확인
:::

UDP 패킷 중 하나를 클릭하고 **User Datagram Protocol**을 펼쳐 보자. TCP 헤더와 비교하면 UDP 헤더는 아주 작다. **Source Port**, **Destination Port**, **Length**(길이), **Checksum**(체크섬)이 전부이며, 합쳐서 8바이트뿐이다. TCP 헤더는 순서 번호와 확인 응답 번호, 플래그, 윈도우 크기가 있어서 최소 20바이트이다.

:::tip 핵심 정리
**UDP**는 **비연결형**이다. 연결 설정도, 확인 응답도, 재전송도, 순서 보장도 없다. 제공하는 것은 **포트**(다중화)와 **체크섬**뿐이다. 대신 빠르고 가볍다. UDP 헤더는 8바이트밖에 되지 않는다. 데이터그램이 손실되면 프로그램이 직접 처리해야 하고, 아니면 신경 쓰지 않을 수도 있다.
:::
