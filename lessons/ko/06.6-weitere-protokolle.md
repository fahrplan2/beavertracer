HTTP, DNS, 이메일, DHCP는 일상에서 끊임없이 마주치는 프로토콜이다. 이 밖에도 많은 프로토콜이 있는데, 여기서는 가장 중요한 것들을 간단히 살펴본다. 그중 일부는 BeaverTracer에서 직접 해 볼 수 있다. 이런 프로토콜에는 :fa-flask: 표시가 있다.

| 프로토콜 | 포트 | 전송 | 용도 |
|---|---|---|---|
| **SSH** | 22 | TCP | 암호화된 원격 관리 |
| **Telnet** :fa-flask: | 23 | TCP | 암호화되지 않은 원격 관리(구식) |
| **FTP** / **SFTP** | 21 / 22 | TCP | 파일 전송 |
| **NTP** :fa-flask: | 123 | UDP | 시각 동기화 |
| **IRC** :fa-flask: | 6667 | TCP | 텍스트 채팅 |
| **SIP** / **RTP** :fa-flask: | 5060 / 가변 | UDP | 인터넷 전화 |
| **SNMP** | 161 | UDP | 네트워크 장치 모니터링 |
| **SMB** | 445 | TCP | 네트워크 파일 공유 |
| **MQTT** | 1883 | TCP | 사물 인터넷의 메시지 |
| **QUIC** / **HTTP/3** | 443 | UDP | 더 빠르고 암호화된 웹 |

## SSH와 Telnet

**SSH**(*Secure Shell*)를 사용하면 다른 컴퓨터 앞에 앉아 있는 것처럼 명령줄로 그 컴퓨터를 제어할 수 있다. 관리자는 이런 방식으로 서버와 라우터를 관리한다. 비밀번호를 포함한 모든 내용이 암호화되어 전송된다. 이전 세대인 **Telnet**은 같은 일을 평문으로 처리하기 때문에 오늘날에는 안전하지 않다고 여겨진다. 하지만 6.1.2절에서 보았듯이 텍스트 기반 프로토콜을 테스트하는 도구로는 여전히 유용하다.

## FTP와 SFTP

**File Transfer Protocol**(**FTP**)은 가장 오래된 인터넷 프로토콜 중 하나로, 파일을 업로드하고 다운로드하는 데 쓰인다. 비밀번호와 데이터를 암호화하지 않고 전송하기 때문에 점점 덜 사용된다. 대개 SSH 연결을 통해 파일을 전송하는 **SFTP**가 FTP를 대체한다.

## NTP

**Network Time Protocol**(**NTP**)은 컴퓨터의 시계를 시간 서버와 맞춘다. 밀리초 단위까지 정확하다. 이것은 들리는 것보다 더 중요하다. 인증서, 로그 파일, 로그인 절차는 모든 장치의 시간이 같아야만 제대로 동작하기 때문이다. BeaverTracer에는 이를 위한 앱 **NTP-Server**와 **Uhrzeit**, 그리고 `ntpdate` 명령이 있다.

## IRC

**Internet Relay Chat**(**IRC**)은 1988년에 나온 채팅 프로토콜이다. 서버에 연결해 `#schule` 같은 채널에 들어가고, 채널에 있는 모든 사람에게 텍스트 메시지를 보낸다. HTTP, SMTP와 마찬가지로 IRC도 순수한 텍스트 프로토콜이어서 트레이서에서 모든 메시지를 읽을 수 있다. 오늘날의 메신저도 같은 기본 원리로 동작하지만 암호화되어 있다. BeaverTracer에서는 앱 **IRC-Server**와 **IRC**를 사용한다.

## SIP와 RTP

**인터넷 전화**(*Voice over IP*)에서는 두 프로토콜이 함께 동작한다. **SIP**(*Session Initiation Protocol*)는 통화를 설정하고 종료한다. 상대방의 전화기가 울리게 하는 것이 SIP이다. 음성 자체는 UDP를 통해 수많은 작은 **RTP** 패킷에 실려 전달되는데, 통화에서는 1밀리초가 아쉽기 때문이다(5.5.2절 참고). BeaverTracer에서는 앱 **SIP-Server**와 **Softphone**을 사용한다.

## SNMP

**Simple Network Management Protocol**(**SNMP**)을 통해 모니터링 프로그램은 라우터, 스위치, 프린터에 질의한다. 포트가 얼마나 사용되고 있는지, 장치가 고장 났는지, 토너가 떨어졌는지 같은 것들이다. 이렇게 관리자는 대규모 네트워크도 한눈에 파악한다.

## SMB

**Server Message Block** 프로토콜(**SMB**)은 Windows 네트워크에서 알고 있는 네트워크 드라이브와 공유 폴더의 바탕이 된다. 예를 들어 학교의 공유 드라이브가 그렇다. 네트워크 프린터도 흔히 SMB를 통해 접근한다.

## MQTT

**MQTT**는 **사물 인터넷**을 위한 매우 가벼운 프로토콜이다. 센서, 스마트 온도 조절기, 공장의 기계 등이 측정값을 중앙 중개자(*브로커*)에게 보내면, 그 값에 관심 있는 모든 프로그램이 브로커로부터 값을 받아 간다. 연산 능력이 낮은 장치와 불안정한 연결 환경에 맞게 설계되었다.

## QUIC와 HTTP/3

**QUIC**는 Google이 개발한 비교적 새로운 전송 프로토콜로, 오늘날 많은 대형 웹사이트가 사용한다. **UDP** 위에 구축되며 신뢰성과 암호화 기능을 자체적으로 갖추고 있어서, TCP와 TLS를 쓸 때보다 연결이 더 빨리 만들어진다. **HTTP/3**는 QUIC 위에서 동작하는 HTTP 버전이다.

:::quiz match
SSH -> 다른 컴퓨터를 명령줄로 암호화하여 제어하기

SIP -> 인터넷으로 전화 통화 설정하기
SNMP -> 라우터, 스위치, 프린터 모니터링하기
