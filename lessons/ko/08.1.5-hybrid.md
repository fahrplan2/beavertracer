# 하이브리드 암호화

정리해 보자.

| | 대칭 (예: AES) | 비대칭 (예: RSA) |
|---|---|---|
| 키 | 하나의 공유 비밀 키 | 키 쌍: 공개 키 + 개인 키 |
| 속도 | 매우 빠름 | 느림 |
| 키 교환 | 문제: 키를 어떻게 수신자에게 전달할까? | 문제 없음: 공개 키는 그대로 공개해서 보내도 됨 |

이처럼 각 방식은 다른 방식에 없는 강점을 하나씩 가지고 있다. 해결책은 둘을 결합하는 것이다. 이를 **하이브리드 암호화**라고 한다.

1. 연결을 시작할 때 양쪽은 **비대칭** 방식을 이용해 공통 비밀 키인 **세션 키**에 합의한다. 시간이 잠깐 걸리지만 **한 번만** 일어난다.
2. 그 후 모든 데이터는 세션 키로 **대칭** 방식으로 암호화된다 — 빠르다.
3. 연결이 끝나면 세션 키는 버려진다. 다음 연결은 새로운 키를 받는다.

**HTTPS**, 암호화된 이메일 연결, WPA3를 사용하는 **WLAN**, **SSH**, **VPN**이 이렇게 동작한다.

## 색 섞기로 만드는 공유 비밀

세션 키에 합의하는 우아한 방법 중 하나가 **디피-헬만 키 교환**(1976)이다. 이것을 색에 비유해서 생각해 볼 수 있다. 핵심 요령은 이렇다. 색을 섞는 것은 쉽지만, 섞인 색을 다시 원래 성분으로 분리하는 것은 사실상 불가능하다.

1. Anna와 Ben은 공통 기본 색, 예를 들어 **노랑**에 **공개적으로** 합의한다. 누구든 이 색을 알아도 된다.
2. 각자 **비밀 색**을 몰래 고른다: Anna는 **빨강**, Ben은 **파랑**.
3. 각자 자신의 비밀 색을 기본 색에 섞고, 그 결과를 상대에게 **공개적으로** 보낸다: Anna는 **노랑 + 빨강**(주황)을 보내고, Ben은 **노랑 + 파랑**(초록)을 보낸다.
4. 이제 각자 자신의 비밀 색을 상대가 보낸 혼합색에 섞는다:
    - Anna: 초록 + 빨강 = **노랑 + 파랑 + 빨강**
    - Ben: 주황 + 파랑 = **노랑 + 빨강 + 파랑**
5. 둘은 이제 **같은** 색(갈색)을 갖게 된다 — 바로 공유 키이다.

도청자는 노랑, 주황, 초록을 보았다. 하지만 갈색을 만들려면 빨강이나 파랑이 필요한데, 이 색들은 Anna와 Ben이 한 번도 보낸 적이 없다.

실제로는 물론 색이 아니라 매우 큰 수로 계산한다. Tracer에서 이 교환을 곧 **Server Key Exchange**와 **Client Key Exchange**로 다시 보게 될 것이다 — **ECDHE**의 "**DHE**"는 *Diffie-Hellman Ephemeral*, 즉 일회용 키를 사용하는 디피-헬만을 뜻한다.

:::warning
디피-헬만만으로는 공격자가 중간에 끼어들어 Anna와 Ben 각각과 별도의 키를 협상하는 것을 막지 못한다. 따라서 Anna는 자신이 정말 Ben과 통신하고 있다는 것도 확신할 수 있어야 한다. 이를 위해 **서명**과 **인증서**가 필요하다 — 다음 주제이다.
:::

:::tip 핵심 정리
**하이브리드 암호화**는 두 방식의 장점을 결합한다. **비대칭** 방식(예: 디피-헬만)으로 양쪽이 비밀 **세션 키**에 합의하고, 데이터 자체는 **대칭** 방식(예: AES)으로 암호화한다. HTTPS, WLAN 암호화, SSH, VPN이 이렇게 동작한다.
:::
