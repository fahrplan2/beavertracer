# NAT 테이블

:::sim
url=/sims/lesson-7.1.btsim
:::

PC와 태블릿이 동시에 같은 웹 페이지를 불러오면, 두 요청 모두 `203.0.113.2`에서 웹 서버로 도착한다. 가정용 라우터는 응답이 누구를 위한 것인지 어떻게 알까? 라우터는 **NAT 테이블**에 기록을 남겨 둔다.

## 실험

1. :fa-play: **실행** 모드로 전환하고, **PC**와 **Tablet**에서 각각 `http://www.beispiel.de/`를 불러와 봐라.
2. **Heimrouter**를 클릭하고 **NAT** 탭을 열어 봐라.

각 행은 하나의 **매핑**이다. 프로토콜, 홈 네트워크에 있는 기기의 LAN IP와 LAN 포트, 그리고 라우터가 이를 위해 자신의 공인 주소에서 사용하는 **WAN 포트**가 적혀 있다.

:::quiz short
테이블 위에 표시된 WAN IP는 무엇인가?
= 203.0.113.2
:::

:::quiz mc
PC와 태블릿이 둘 다 LAN 포트 `49152`로 연결을 설정했다. 이들은 어떤 WAN 포트를 받을까?
- [ ] 둘 다 같은 `49152`
- [x] 각각 서로 다른 포트 — 그렇지 않으면 라우터가 응답이 누구의 것인지 알 수 없다
- [ ] 아무것도 받지 않는다. NAT는 IP 주소만 바꾼다
:::

:::quiz mc
웹 서버의 응답이 특정 **목적지 포트**와 함께 `203.0.113.2`에 도착한다. 가정용 라우터는 이 패킷을 어떻게 처리할까?
- [x] NAT 테이블에서 해당 포트를 찾아, 그에 해당하는 LAN IP와 LAN 포트로 패킷을 보낸다
- [ ] 홈 네트워크의 모든 기기로 패킷을 보낸다
- [ ] 패킷을 폐기한다
:::

:::evaluate
답안 확인
:::

여기서 5장의 **포트**가 다시 등장한다. NAT가 포트까지 바꿔 쓰기 때문에 수백 개의 연결이 하나의 주소를 함께 사용할 수 있다. 그래서 엄밀히 말하면 이것은 **PAT**(*Port Address Translation*) 또는 *포트 변환을 사용하는 NAT*라고 부른다. 그래도 일상에서는 그냥 NAT라고 한다.

이러한 변환은 예를 들어 다음과 같이 이루어질 수 있다.

| | PC에서 나온 패킷(홈 네트워크 내부) | 인터넷에서의 같은 패킷 |
|---|---|---|
| 송신자 | `192.168.178.20 : 49152` | `203.0.113.2 : 10001` |
| 수신자 | `192.0.2.80 : 80` | `192.0.2.80 : 80` |

:::tip 핵심 정리
라우터는 **NAT 테이블**에 각 연결마다 어떤 기기(**LAN IP와 LAN 포트**)가 어떤 **WAN 포트** 뒤에 있는지 기억해 둔다. 인터넷에서 오는 응답은 목적지 포트를 통해 다시 올바른 기기에 연결한다. 포트도 함께 바꿔 쓰기 때문에, 더 정확하게는 **PAT**라고 부른다.
:::
