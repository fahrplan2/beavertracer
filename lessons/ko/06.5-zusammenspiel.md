# 모두 합쳐 보기: 웹 페이지를 열면 무슨 일이 일어날까?

:::goal
**학습 목표:** 방금 켠 노트북이 웹 페이지를 열 때 어떤 프로토콜이 어느 계층에서 관여하는지 단계별로 설명할 수 있다.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

이제 이 강의에서 배운 모든 내용이 하나로 모인다. 스위치에는 **DHCP-Server**, **DNS-Server**, **Webserver**, 그리고 방금 전원을 켠 **Laptop**이 연결되어 있다. 노트북은 아직 IP 주소가 없고 DHCP로 설정되어 있다.

## 실험

1. :fa-play: **실행** 모드로 전환하고 몇 초 기다려 봐.
2. **Laptop**을 클릭하고 :fa-globe: **브라우저**를 열어 `http://www.beaver-schule.de/`에 접속해 봐.
3. :fa-magnifying-glass: **추적** 모드에서 **Laptop**의 트레이스를 열어 봐. 첫 번째 패킷부터 전체 과정이 여기에 나와 있다.

트레이스에 나오는 순서대로 단계를 맞춰 봐:

:::quiz match
1. Schritt -> DHCP: 노트북이 IP 주소, 게이트웨이, DNS 서버를 받아 온다
2. Schritt -> ARP: 노트북이 DNS 서버의 MAC 주소를 묻는다
3. Schritt -> DNS: 노트북이 www.beaver-schule.de의 IP 주소를 묻는다
4. Schritt -> ARP: 노트북이 웹 서버의 MAC 주소를 묻는다
5. Schritt -> TCP: 웹 서버와 3-way 핸드셰이크
6. Schritt -> HTTP: GET / 요청과 200 OK 응답
:::

:::evaluate
순서 확인
:::

그리고 이 모든 것의 아래에는 이 패킷 하나하나에 주소를 붙이는 **IP**(3계층)와 패킷을 다음 장치까지 전달하는 **이더넷**(2계층)이 있다. 웹 서버가 다른 네트워크에 있다면 **라우터**도 관여한다. 그러면 노트북은 웹 서버가 아니라 **게이트웨이**의 MAC 주소를 묻게 된다.

- [ ] 하나, 모든 것을 합쳐서

:::tip 핵심 정리
클릭 한 번 뒤에서는 모든 계층이 함께 일한다. **DHCP**는 기본 설정을 제공하고, **ARP**는 로컬 네트워크에서 MAC 주소를 찾고, **DNS**는 이름을 변환하고, **TCP**는 신뢰할 수 있는 연결을 설정하고, **HTTP**는 페이지를 가져온다. 이 모든 것은 **IP** 패킷과 **이더넷** 프레임에 담겨 전달된다.
:::

이제 웹 페이지 접속 과정을 첫 번째 패킷부터 마지막 패킷까지 설명할 수 있다. 이 장의 마무리로 다른 프로토콜들을 간단히 살펴본다. 다음 장들에서는 NAT가 적용된 홈 네트워크, 보안과 암호화를 다루며, 누군가가 이 모든 패킷을 엿보지 못하게 하려면 어떻게 해야 하는지도 살펴본다.
