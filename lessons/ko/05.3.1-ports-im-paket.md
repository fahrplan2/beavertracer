## 실험

1. :fa-play: **실행** 모드로 전환하고, **Client-PC**를 클릭한 다음 :fa-globe: **브라우저**를 열어라. `http://192.168.0.20/`에 접속해 봐라.
2. 창 상단의 **뒤로**를 클릭하고, **단순 TCP 클라이언트**를 열어 `192.168.0.20`, 포트 `5000`으로 연결해라. 연결은 열어 둔 채로 두어라.
3. :fa-magnifying-glass: **추적** 모드로 전환하고, **Client-PC**의 트레이스를 연 다음 `[SYN]`이 있는 패킷을 클릭해라. **Transmission Control Protocol**을 펼쳐라.

TCP 헤더 맨 위에는 두 개의 포트가 있다. **Source Port**(출발지 포트)와 **Destination Port**(목적지 포트)다.

:::quiz table
| 연결 | 출발지 포트 | 목적지 포트 |
|---|---|---|
| 브라우저 → 웹 서버 | {49152} | {80} |
| TCP 클라이언트 → 에코 서비스 | {49153} | {5000} |
:::

## 두 종류의 포트

**목적지 포트 — 서비스:** 서버 프로그램은 정해진 포트에서 연결을 기다린다. 이를 그 포트에서 **리슨(listen)** 한다고 한다. 잘 알려진 서비스의 번호는 전 세계적으로 정해져 있는데, 이것이 **Well-known 포트**(0~1023)다. 그래서 브라우저는 따로 묻지 않아도 웹 서버가 80번 포트에서 리슨한다는 것을 안다.

**출발지 포트 — 송신자:** 클라이언트 쪽 포트는 운영체제가 새 연결마다 높은 번호 범위에서 스스로 고른다(BeaverTracer에서는 49152부터). 클라이언트는 이 포트를 보고 응답이 자신의 어느 연결에 속하는지 알아본다.

따라서 하나의 연결은 네 가지 정보로 유일하게 결정된다. 바로 **양쪽의 IP 주소와 포트**다. IP 주소와 포트의 쌍을 **소켓**이라고 하며, 예를 들면 `192.168.0.20:80`과 같다.

## 서버 들여다보기

다시 :fa-play: **실행** 모드로 돌아가 **Server**에서 :fa-terminal: **터미널**을 열고 다음을 입력해라.

```
$ ss
```

`ss`는 컴퓨터의 모든 소켓을 보여 준다. `LISTEN`이 있는 줄은 포트에서 리슨하는 프로그램이다. `ESTABLISHED`가 있는 줄은 현재 맺어진 연결이며, 자신의 소켓(*Local Address:Port*)과 상대편의 소켓(*Peer Address:Port*)이 함께 표시된다.

:::quiz multi
서버는 어떤 포트에서 리슨하는가?
- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc
`ss`는 어떤 연결을 `ESTABLISHED`로 보여 주는가?

- [ ] `192.168.0.20:80`과 `192.168.0.10:49152` — 브라우저의 연결

:::

:::note
브라우저의 연결은 이미 종료되었다. 페이지를 불러온 뒤 `FIN`으로 끝났다. `ss`는 이 연결을 잠시 동안 `TIME-WAIT`로 보여 준다. 서버가 이 연결의 늦게 도착하는 패킷이 더 있는지 한동안 기다리기 때문이다. 반면 TCP 클라이언트의 연결은 아직 **연결 해제**를 클릭하지 않았기 때문에 계속 열려 있다.
:::

## 가장 중요한 Well-known 포트

| 포트 | 프로토콜 | 서비스 |
|---|---|---|
| 22 | SSH | 보안 원격 관리(암호화된 명령줄) |
| 25 | SMTP | 이메일 보내기 |
| 53 | DNS | 이름을 IP 주소로 변환(대개 UDP 사용) |
| 80 | HTTP | 웹 페이지 |
| 110 | POP3 | 이메일 가져오기 |
| 143 | IMAP | 서버에서 이메일 관리 |
| 443 | HTTPS | 암호화된 웹 페이지 |

:::tip 핵심 정리
**포트**(0~65535)는 한 컴퓨터 안의 연결들을 구분해 준다. 서버 서비스는 정해진 **Well-known 포트**(예: HTTP 80, HTTPS 443)에서 **리슨**하고, 클라이언트는 연결마다 비어 있는 높은 번호의 **출발지 포트**를 받는다. 하나의 연결은 **양쪽의 IP 주소와 포트**로 유일하게 결정된다.
:::
