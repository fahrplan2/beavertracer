# 응답 문제

:::sim
url=/sims/lesson-9.2.btsim
:::

방화벽은 이제 화이트리스트 원칙으로 동작한다. 기본 정책은 **Alle verwerfen**이다. 단 하나의 규칙만이 학교 네트워크의 웹 서핑을 허용한다: **B → A, TCP, Ziel-Port 80, Zulassen**. 모드는 **Stateless**로 설정되어 있다.

## 실험

1. :fa-play: **실행** 모드로 전환하고 **Lehrer-PC**의 :fa-globe: **브라우저**에서 `http://203.0.113.80/`을 열어 봐라.
2. **Firewall**에서 **Protokoll**과 **Treffer**를 확인해 봐라.

:::quiz mc
브라우저에서 어떤 일이 일어날까?
- [ ] www.beispiel.de의 페이지가 나타난다
- [x] 페이지가 로드되지 않고, 브라우저가 기다리다가 결국 오류를 표시한다
:::

:::quiz mc
방화벽의 로그에서 폐기된(`DROP`) 패킷으로 나타나는 것은 무엇일까?
- [ ] Lehrer-PC가 포트 80으로 보낸 요청
- [x] `203.0.113.80`이 **출발지 포트 80**으로 Lehrer-PC에 보낸 응답
- [ ] 하나도 없다
:::

:::quiz short
폐기된 패킷은 어느 방향(A→B 또는 B→A)으로 이동할까?
= A→B
= A → B
= AtoB
:::

:::evaluate
답 확인
:::

Lehrer-PC의 요청은 밖으로 나갈 수 있다. 하지만 웹 서버의 `SYN, ACK`는 이미 돌아오지 못한다. A → B 방향에는 맞는 규칙이 없으므로 **Alle verwerfen**이 적용되기 때문이다.

## 단순한 해결책

두 번째 규칙을 추가할 수도 있다: **A → B, TCP, Quell-Port 80, Zulassen** — "포트 80에서 오는 것은 모두 들어와도 된다". 그러면 웹 서핑이 실제로 작동한다.

:::quiz mc
이 규칙은 왜 위험할까?
- [ ] 웹 서버는 포트 80을 출발지 포트로 절대 사용하지 않기 때문이다
- [x] 공격자가 자신의 패킷을 간단히 출발지 포트 80으로 보내면, 방화벽이 그 패킷을 학교 네트워크의 **모든** 포트로 통과시키기 때문이다
- [ ] 그러면 웹 페이지가 더 느리게 로드되기 때문이다
:::

:::evaluate
답 확인
:::

출발지 포트는 송신자가 직접 정하므로, 방화벽이 이를 신뢰해서는 안 된다. 그런데 상태 비저장 방화벽은 패킷이 **요청에 대한 응답**인지, 외부에서 시도하는 **새로운 연결**인지 알지 못한다. 상태 저장 모드가 바로 이 점을 바꿔 준다.

:::tip 핵심 정리
**상태 비저장** 패킷 필터는 각 패킷을 개별적으로 검사한다. 그러면 응답에는 반대 방향을 위한 별도의 규칙이 필요하다. 그런데 이런 규칙(예: "출발지 포트 80은 들어와도 된다")은 송신자가 출발지 포트를 자유롭게 고를 수 있기 때문에 공격자가 악용할 수 있다.
:::
