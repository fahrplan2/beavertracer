Beaver 학교는 자체 공인 주소(`198.51.100.…`)를 가지고 있다. 이 학교의 **Schulserver**는 NAT 없이 인터넷에서 직접 접근할 수 있다. 곧 IPv6에서는 어디서나 이렇게 될 것이다(7.3장). 인터넷과 **Schulrouter** 사이에는 **방화벽**이 있지만, 지금은 아직 모든 트래픽을 통과시킨다.

왼쪽에는 "인터넷"이 보인다. **Internet-PC**와 웹 서버 `www.beispiel.de`가 있다. 오른쪽에는 **Schulserver**와 **Lehrer-PC**가 있는 학교 네트워크가 있다.

## 공격자는 무엇을 볼까?

서버를 공격하려는 사람은 먼저 **열린 포트**, 즉 연결을 기다리는 서비스를 찾는다. 이를 위한 도구가 **포트 스캐너**이며, 가장 잘 알려진 것은 `nmap`이다.

:fa-play: **실행** 모드로 전환하고, **Internet-PC**에서 :fa-terminal: **터미널**을 열어 다음을 입력해 보자.

```
$ nmap 198.51.100.10
```

`nmap`은 가장 자주 쓰이는 20개 포트에 TCP 연결을 시도하고, 어떤 포트가 열려 있는지 알려 준다.

:::quiz multi
인터넷에서 Schulserver의 어떤 포트가 열려 있을까?
- [x] 22 (SSH, 원격 관리)
- [x] 25 (SMTP)
- [x] 80 (HTTP)
- [x] 110 (POP3)
- [x] 143 (IMAP)
- [ ] 443 (HTTPS)
:::

:::evaluate
답 확인
:::

웹 페이지(80)와 이메일 수신(25)은 인터넷에서 접근할 수 있어야 한다. 하지만 **원격 관리**(22)와 메일 가져오기(110, 143)는 학교 네트워크 안에서만 필요하다. 열린 포트는 모두 공격 표면이 될 수 있다. 서비스에 보안 취약점이 있거나 비밀번호가 약하면 공격자가 전 세계 어디에서든 이를 악용할 수 있고, 인터넷의 자동 스캐너는 바로 그것을 하루 종일 시도한다.

:::tip 핵심 정리
**방화벽**은 두 네트워크의 경계에서 데이터 트래픽을 제어하며, 명시적으로 허용된 것만 통과시킨다. 이렇게 하면 내부에서만 필요한 서비스는 인터넷에 보이지 않게 된다.
:::
