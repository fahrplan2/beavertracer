# 직접 보낼까, 게이트웨이를 거칠까?

:::sim
url=/sims/lesson-4.3.2.btsim
:::

PC는 패킷을 보내기 전에 먼저 판단한다. 목적지가 **같은 네트워크**에 있을까? 이를 위해 PC는 자신의 넷마스크를 이용해 자기 주소의 네트워크 부분과 목적지 주소의 네트워크 부분을 비교한다.

## 진행 순서

1. **목적지 IP가 같은 네트워크에 있는가?**
   - **예:** PC는 패킷을 목적지로 **직접** 보낸다. 이때 목적지의 MAC 주소가 필요하다.
   - **아니요:** PC는 패킷을 **게이트웨이**로 보낸다. 이때 라우터의 MAC 주소가 필요하다. 게이트웨이가 설정되어 있지 않으면 패킷을 아예 보낼 수 없다.
2. **필요한 MAC 주소를 이미 알고 있는가**(ARP 캐시에 있는가)? 모르면 **ARP**로 물어본다.
3. PC는 이 MAC 주소로 프레임을 보낸다. 두 경우 모두 패킷 안의 **목적지 IP 주소**가 실제 목적지이다.

| | 직접 (같은 네트워크) | 게이트웨이 경유 (다른 네트워크) |
|---|---|---|
| ARP로 묻는 대상 … | 목적지의 MAC | 라우터의 MAC |
| 프레임의 목적지 MAC | 목적지 | 라우터 |
| 패킷의 목적지 IP | 목적지 | 목적지 |

## 문제 해결: 회사 B에 연결되지 않는다

어제부터 Anna가 회사 B의 PC에 접속하지 못한다. 네트워크는 원래 다음과 같이 설정되어 있어야 한다.

| 장치 | IP 주소 | 게이트웨이 |
|---|---|---|
| Anna | `192.168.0.10/24` | `192.168.0.1` |
| Ben | `192.168.0.11/24` | `192.168.0.1` |
| Clara | `172.16.0.10/24` | `172.16.0.1` |
| David | `172.16.0.11/24` | `172.16.0.1` |

오류를 찾아서 고쳐 보자.

<details>
<summary>힌트 1: Anna의 핑이 도착하긴 할까?</summary>

Anna에서 Clara로 핑을 보내고 **Clara**의 트레이스를 열어 보자. 핑이 도착했을까? 그리고 Clara가 응답했을까?
</details>

<details>
<summary>힌트 2: David는 무엇을 하고 있을까?</summary>

Anna에서 David로 핑을 보내고 **David**의 트레이스를 열어 보자. David는 ARP로 어떤 IP 주소를 물어보고 있을까? 그리고 응답을 받을까?
</details>

:::tip 핵심 정리
PC에는 패킷을 보낼 때뿐만 아니라 **응답할 때**도 올바른 게이트웨이가 필요하다. 게이트웨이가 없으면 핑은 도착하더라도 응답이 돌아갈 길을 찾지 못한다. **잘못된 게이트웨이 주소**가 설정되어 있으면, PC는 존재하지 않는 라우터를 ARP로 계속 찾게 되지만 헛수고로 끝난다.
:::
