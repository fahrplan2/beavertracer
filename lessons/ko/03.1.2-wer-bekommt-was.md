# 누가 어떤 패킷을 받을까?

:::sim
url=/sims/lesson-3.1.2.btsim
:::

이제 Anna, Ben, Clara가 스위치에 연결되어 있다(포트 1, 2, 3). Anna가 Ben에게 패킷을 보내면, Ben만 받을까, 아니면 Clara도 받을까?

어떻게 될지 잠깐 생각해 봐. 그다음 직접 해 보자.

## 실험

1. :fa-play: **실행** 모드로 전환하고, **Anna**에서 :fa-terminal: **터미널**을 열어 Ben에게 ping을 보내 봐:
   ```
   $ ping 192.168.0.11
   ```
2. :fa-magnifying-glass: **추적** 모드로 전환하고 **+**를 눌러 **Clara**의 `eth0` 포트에 대한 트레이스를 열어 봐.
3. **+**를 눌러 **Ben**의 `eth0` 포트에 대한 두 번째 트레이스를 열어 봐. 위쪽에서 두 트레이스를 번갈아 전환할 수 있어.

= 1개
= 하나
:::

## 그 배경

ARP 요청의 목적지는 **브로드캐스트**이다. 즉 *모든* 장치를 향한다. 그래서 스위치는 이 요청을 모든 포트로, Clara에게도 전달했다. 반면 ping은 Ben만을 수신자로 하고 있었다. 스위치는 이를 Ben의 포트로만 보냈고, Clara는 이에 대해 아무것도 알지 못했다.

:::tip 핵심 정리
**브로드캐스트**는 로컬 네트워크의 모든 장치를 향한다. 스위치는 이를 모든 포트로 전달한다. **유니캐스트**는 정확히 한 장치만을 향한다. 스위치는 이를 그 장치가 연결된 포트로만 보낸다.
:::

## 스위치 들여다보기

그런데 스위치는 Ben이 어느 포트에 연결되어 있는지 어떻게 알까? :fa-play: **실행** 모드로 돌아가 **스위치**를 클릭해 봐. **SAT** 탭에서 **MAC**과 **Port** 두 열로 이루어진 주소 테이블을 볼 수 있어.

:::quiz mc
주소 테이블에는 어떤 장치가 있을까?
- [ ] Anna, Ben, Clara
- [x] Anna와 Ben만
- [ ] Ben만
:::

:::quiz short
테이블에 따르면 Ben은 어느 포트에 연결되어 있을까? 힌트: Ben의 MAC 주소는 트레이서에서 그의 ARP 응답 `192.168.0.11 is at …`에서 찾을 수 있어.
= 2
= 포트 2
= port 2
:::

:::quiz mc
테이블에 Clara가 없는 이유는 무엇일까?
- [ ] 케이블이 고장 났다
- [x] 아직 패킷을 단 하나도 보내지 않았다
- [ ] 스위치는 최대 두 개의 항목만 저장한다
:::

답 확인

스위치는 **학습**한다. 도착하는 모든 프레임에서 **송신자** MAC 주소를 보고, 그 장치가 어느 포트에 연결되어 있는지 기억해 둔다. Anna의 ARP 요청이 도착했을 때 "Anna → 포트 1"을, Ben의 응답에서 "Ben → 포트 2"를 기록했다. Clara는 아무것도 보내지 않았으므로 스위치는 아직 Clara를 알지 못한다.

:::tip 핵심 정리
스위치는 **주소 테이블**(**SAT**, *Source Address Table*)에 어떤 MAC 주소의 장치가 어느 포트에서 접근 가능한지를 기억한다. 이는 송신자 주소로부터 학습한다. 프레임의 목적지를 알면 그 포트로만 보낸다. 목적지를 모르거나 브로드캐스트이면 모든 포트로 보낸다.
:::
