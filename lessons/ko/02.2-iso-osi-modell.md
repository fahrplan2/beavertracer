# ISO/OSI 참조 모델

ISO/OSI 모델은 두 장치 사이의 통신을 7개의 계층으로 나눕니다. 각 계층은 명확하게 구분된 역할을 가지며, 바로 아래 계층의 서비스만 이용합니다:

<tr class="osi-l7"><td>7</td><td>응용</td><td>애플리케이션과의 인터페이스</td><td>HTTP, DNS, SMTP</td></tr>
<tr class="osi-l6"><td>6</td><td>표현</td><td>데이터 형식, 암호화</td><td>JPEG, ASCII, MIME</td></tr>

지난 페이지의 실험에서 이 계층 중 네 가지를 이미 만나 보았습니다. Ethernet(2), IPv4(3), TCP(4), HTTP(7)입니다. 트레이서는 프로토콜 트리에서 바로 이 번호와 색상을 보여 줍니다.

:::tip 암기 요령
7계층부터 아래로: **A**lle **D**eutschen **S**tudenten **T**rinken **V**erschiedene **S**orten **B**ier — **A**nwendung(응용), **D**arstellung(표현), **S**itzung(세션), **T**ransport(전송), **V**ermittlung(네트워크), **S**icherung(데이터 링크), **B**itübertragung(물리).

한국어로는 첫 글자를 따서 "응표세전네데물"로 외울 수도 있어.
:::

:::note 경계 사례
모든 프로토콜이 정확히 하나의 계층에 들어맞는 것은 아니야. 그래서 트레이서는 이런 프로토콜에 대해 여러 계층을 함께 표시해:

- **ARP** — 2/3계층: IP 헤더는 없지만 IP 주소(3계층)와 하드웨어 주소(2계층)를 연결해.
- **TLS** — 4/5계층: TCP 바로 위에 위치하며 보호된 세션을 관리해.
- **HTTPS** (TLS 안의 HTTP) — 5~7계층: 다음 페이지에서 배우게 될 TCP/IP 모델의 전형적인 응용 계층이야.
:::

:::note
1계층은 케이블이나 무선을 통한 실제 신호 전송을 설명해. BeaverTracer는 이 단계를 시뮬레이션하지 않아. 케이블은 항상 오류 없이 연결된 것으로 간주되며, 신호 문제나 충돌도 없어. 그래서 트레이서에서는 사실상 2계층부터 살펴보게 돼.
:::
