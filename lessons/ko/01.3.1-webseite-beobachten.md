# 웹 페이지 접속하고 관찰하기

이번 부분에서는 직접 만들 것이 없다. 작업 영역에 **Client-PC**와 **Webserver**가 있는 시뮬레이션이 미리 준비되어 있다.

## 페이지 접속하기

1. :fa-play: **실행** 모드로 전환한다.
2. **Client-PC**에서 :fa-globe: **브라우저** 앱을 열고 웹 서버의 주소 `http://192.168.0.20/`에 접속한다.
3. :fa-magnifying-glass: **추적** 모드로 전환하고 **+** 버튼으로 **Client-PC**의 `eth0` 포트에 대한 트레이스를 연다. Ping 때와 똑같이 하면 된다.

:::note
페이지를 한 번 불러오는 데 패킷이 놀라울 만큼 많다. Ping보다 훨씬 많다. 웹 페이지를 가져오는 일은 하나의 동작이 아니라 여러 단계로 이루어진 과정이다.
:::

## 패킷 목록 읽기

각 프로토콜이 정확히 무슨 일을 하는지는 아직 몰라도 된다. 다음 질문에 필요한 정보는 모두 **프로토콜**과 **정보** 열에 있다.

:::quiz mc
목록 맨 위에 있는 프로토콜은 무엇인가?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
세어 보자. 첫 번째 **HTTP** 패킷 앞에 **TCP** 패킷이 몇 개 있는가?
= 3
= 세 개
= 3개
:::

:::quiz mc
브라우저의 요청에 웹 서버는 무엇이라고 응답하는가? 두 번째 HTTP 패킷의 정보 열을 확인해 보자.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
답안 확인
:::

## 관련된 프로토콜 이름 붙이기

지금까지 관찰한 내용으로 어떤 프로토콜이 어떤 역할을 맡았는지 알아낼 수 있다.

:::tip 힌트
**정보** 열을 다시 한번 읽어 보자. `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /`, `200 OK`만 봐도 거의 모든 것을 알 수 있다.
:::

:::quiz match
ARP -> 네트워크의 모든 장치에 묻는다: "IP 주소 192.168.0.20을 가진 장치가 누구인가?"
TCP -> 데이터가 오가기 전에 짧은 패킷 세 개로 연결을 설정한다
HTTP -> 웹 페이지를 요청하고(GET) 그 페이지를 돌려준다(200 OK)
:::

:::evaluate
짝짓기 확인
:::

:::tip 핵심 정리
웹 페이지 접속은 여러 단계로 진행된다. 먼저 네트워크에서 서버를 **찾고**(ARP), 그다음 연결을 **설정하고**(TCP), 이어서 페이지를 **요청하고 전달받으며**(HTTP), 마지막으로 연결을 다시 **종료**한다(목록 끝에 있는 `[FIN]` TCP 패킷).
:::

:::note
이번에는 서버의 IP 주소를 직접 입력했기 때문에 **DNS**(`www.beispiel.de` 같은 이름을 IP 주소로 "번역"해 주는 것)는 아직 사용되지 않았다. 이 부분은 6장에서 다룬다.
:::

패킷 구조에서 프로토콜마다 숫자가 붙은 색깔 표시가 있다는 것을 눈치챘는가? 그 의미는 2장에서 설명한다. 거기서는 수많은 프로토콜을 체계적으로 분류하는 방법을 OSI 모델과 TCP/IP 참조 모델로 살펴본다. 이것으로 1장을 마친다.
