# 상태 기반 방화벽

:::sim
url=/sims/lesson-9.2.btsim
:::

**상태 기반**(*stateful*) 방화벽은 한 번 허용한 모든 연결을 **상태 테이블**에 기억해 둔다. 여기에는 프로토콜, 양쪽 주소, 양쪽 포트가 저장된다. 항목과 일치하는 패킷이 오면 — 방향과 관계없이 — 추가 검사 없이 통과시킨다. 반면 새로운 연결은 규칙을 통과해야 한다.

## 관찰하기

1. **방화벽**에서 **모드**를 **Stateful**로 설정해 봐.
2. **Lehrer-PC**의 :fa-globe: **브라우저**에서 다시 `http://203.0.113.80/`을 열어 봐.
3. 곧바로 방화벽의 **Zustände** 탭을 열어 봐.

:::quiz mc
지금 무슨 일이 일어날까?
- [x] 페이지가 로드되고, **Zustände**에 Lehrer-PC에서 `203.0.113.80:80`으로 가는 연결이 표시된다
- [ ] 응답에 대한 규칙이 여전히 없기 때문에 페이지가 로드되지 않는다
:::

:::quiz short
상태 테이블의 **목적지**에는 어떤 포트가 있을까?
= 80
:::

:::evaluate
답 확인
:::

**Zustände**의 항목은 연결을 통해 더 이상 아무것도 오가지 않으면 잠시 후 다시 사라진다(**Timeout** 열).

## 작업: 학교 방화벽

이제 실제 학교에서 필요한 방식으로 방화벽을 설정해 봐.

- **학교 네트워크에서** 인터넷으로 가는 모든 통신을 허용한다(방향 B → A, 모든 프로토콜).
- **인터넷에서**는 학교 서버의 웹(80)과 메일 수신(25)만 접근할 수 있다.
- 그 밖의 모든 것은 **폐기**하고, 모드는 **Stateful**로 한다.

:::task
title: 학교 방화벽을 설정했을까?
학교 네트워크에서 인터넷에 접속할 수 있는지, 외부에서 학교 서버의 웹과 메일만 접근할 수 있는지, 그리고 Lehrer-PC에 외부에서 접근할 수 없는지 확인한다.
check: tcpOpen(8, "203.0.113.80", 80)
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
check: pingFails(1, 8)
:::

:::quiz mc
Lehrer-PC가 `203.0.113.80`으로 ping을 보낸다. 응답이 돌아올까?
- [x] 응답이 돌아온다 — ping은 B → A 방향으로 허용되었고, 응답은 이 상태에 속한다
- [ ] 돌아오지 않는다 — 외부에서 들어오는 ICMP에 대한 규칙이 없다
:::

:::evaluate
답 확인
:::

:::tip 핵심 정리
**상태 기반 방화벽**은 허용된 모든 연결을 **상태 테이블**에 기록하고, 이 연결에 속한 모든 패킷을 **양방향**으로 통과시킨다. 따라서 **연결 설정**에 대한 규칙만 있으면 충분하다. 즉 "내부에서 외부로는 허용"과 "외부에서는 특정 서비스로만 허용"이다. 외부에서 시작해 학교 네트워크로 들어오는 연결은 계속 차단된다.
:::
