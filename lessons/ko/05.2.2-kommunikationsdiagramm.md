# 시퀀스 다이어그램

:::sim
url=/sims/lesson-5.1.btsim
:::

연결의 진행 과정은 **시퀀스 다이어그램**으로 그린다. 클라이언트와 서버에 각각 세로선(라이프라인)을 하나씩 주고, 시간은 위에서 아래로 흐른다. 화살표 하나가 패킷 하나다. 모든 패킷은 이동하는 데 약간의 시간이 걸리기 때문에 화살표는 비스듬하게 그려진다.

지난 페이지에서 만든 연결은 다음과 같이 보인다. 한 줄씩 트레이스와 비교해 봐:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

각 화살표 위에는 **플래그**가, 아래에는 `SEQ`와 `ACK` 번호가 표시된다. **DATA**는 페이로드(실제 데이터)가 있는 패킷을 나타낸다. 빨간색 숫자는 클라이언트의 것이고 파란색 숫자는 서버의 것이다. 이 숫자들이 무엇을 의미하는지는 다음 페이지에서 설명한다.

## 플래그

| 플래그 | 의미(원어) | 설명 |
|---|---|---|
| **SYN** | *synchronize* | 연결을 설정하고 시작 번호를 정함 |
| **ACK** | *acknowledge* | 수신한 데이터를 확인 응답함 |
| **PSH** | *push* | 데이터를 즉시 프로그램에 전달함 |
| **FIN** | *finish* | "나는 끝났다" — 연결을 종료함 |
| **RST** | *reset* | 연결을 중단하거나 거부함 (자세한 내용은 5.3.2) |

## 세 단계

**설정:** 클라이언트가 `SYN`을 보내고, 서버가 `SYN, ACK`로 응답하며, 클라이언트가 `ACK`로 확인한다. 정확히 세 개의 패킷이 필요하기 때문에 이를 **3-way 핸드셰이크**라고 한다.

**데이터:** 데이터가 담긴 모든 패킷은 수신자가 `ACK`로 확인 응답한다. 여기서는 서버가 에코를 돌려보내는데, 이것도 클라이언트가 확인 응답한다.

**종료:** 각 측이 자신의 전송 방향을 따로 종료한다. 클라이언트의 `FIN`, 서버의 `ACK`, 그다음 서버의 `FIN`, 클라이언트의 `ACK` 순서다. 모두 네 개의 패킷이다.

:::tip 핵심 정리
TCP 연결은 세 단계로 진행된다. **3-way 핸드셰이크**(`SYN` → `SYN, ACK` → `ACK`)로 하는 **설정**, **데이터 전송**(모든 데이터 패킷은 `ACK`로 확인 응답), 그리고 **종료**(각 측이 `FIN`을 보내고 `ACK`를 받음)이다.
:::
