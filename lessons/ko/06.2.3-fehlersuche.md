# 문제 해결: 이름이 작동하지 않는다

:::sim
url=/sims/lesson-6.2.3.btsim
:::

한 선생님이 이렇게 알려 왔다. "`www.beaver-schule.de`가 제 컴퓨터에서 로드되지 않아요. 그런데 `http://192.168.0.20`으로는 되네요!" 설정은 다음과 같이 되어 있어야 *한다*:

| 항목 | 목표 상태 |
|---|---|
| Client-PC의 DNS 서버 | `192.168.0.53` (DNS-Resolver) |
| Schul-DNS의 항목 | `www.beaver-schule.de` → `192.168.0.20` |

오류를 찾아서 해결해 보자.

<details>
<summary>힌트 1: nslookup은 뭐라고 말하는가?</summary>

Client-PC에서 `nslookup www.beaver-schule.de`를 입력해 보자. `nslookup`은 어느 서버에 물어봤고, 무엇이 돌아왔는가? (응답이 오기까지 몇 초 걸린다.)
</details>

<details>
<summary>힌트 2: 그럼 이제는?</summary>

응답을 받았다면 그 주소를 계획과 비교해 보자. 이 이름은 어디에 등록되어 있는가?
</details>

:::task
title: 이름 확인이 복구되었는가?
Client-PC가 www.beaver-schule.de를 올바른 주소로 확인하는지 검사한다. 이를 위해 시뮬레이션이 실행 모드로 동작 중이어야 한다.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## 무엇이 문제였을까?

:::quiz multi
어떤 설명이 맞는가?
- [x] Client-PC에 DNS 서버로 `192.168.0.35`가 등록되어 있었다 — 그곳에서는 아무도 응답하지 않는다
- [x] Schul-DNS에서 `www.beaver-schule.de`가 `192.168.0.20`이 아니라 `192.168.0.21`을 가리키고 있었다
- [ ] 웹 서버가 꺼져 있었다
- [ ] 루트 서버가 `.de` 도메인을 알지 못했다
:::

:::evaluate
답 확인
:::

:::tip 핵심 정리
**IP 주소**로는 연결이 되는데 **이름**으로는 되지 않는다면, 문제는 **DNS**에 있다. 먼저 **등록된 DNS 서버**를 확인하고(과연 응답하는가?), 그다음 **항목** 자체를 확인한다(주소가 맞는가?). `nslookup`은 이 두 가지를 모두 보여 준다. 어느 서버에 물어봤는지, 그리고 그 서버가 무엇이라고 답했는지를 알려 준다.
:::
