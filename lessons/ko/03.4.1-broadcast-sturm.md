# 브로드캐스트 스톰

:::sim
url=/sims/lesson-3.4.1.btsim
:::

스위치 세 대(A, B, C)가 링 구조로 연결되어 있다. 스위치 A에는 **Anna**(`192.168.0.10`)가, 스위치 B에는 **Ben**(`192.168.0.11`)이 연결되어 있다.

## 실험

1. :fa-play: **실행** 모드로 전환하고, **Anna**에서 :fa-terminal: **터미널**을 열어 Ben에게 ping을 보내 봐:
   ```
   $ ping 192.168.0.11
   ```
2. Anna의 창을 닫고 작업 영역을 잠시 관찰해 봐. 패킷이 링을 따라 끊임없이 돌고 있다.
3. :fa-magnifying-glass: **추적** 모드로 전환하고 **+** 를 눌러 **Ben**의 `eth0` 포트에 대한 트레이스를 열어 봐. 오른쪽 위에서 지금까지 기록된 패킷 수를 확인할 수 있다.
4. **실행** 모드와 **추적** 모드를 몇 번 오가면서 그 숫자를 계속 지켜봐.

:::quiz mc
Ben의 패킷 목록에서 무엇이 보이는가?
- [ ] 평소처럼 Anna의 ping과 Ben의 응답
- [x] "Who has 192.168.0.11?"라는 동일한 ARP 요청이 계속 반복되고, 패킷 수가 계속 늘어난다
- [ ] 아무것도 보이지 않는다. 링이 모든 것을 차단한다
:::

:::quiz mc
그렇다면 Anna의 터미널에는 어떤 결과가 나타나는가?
- [ ] 모든 ping이 도착한다
- [x] ping이 하나도 도착하지 않는다
:::

## 그 원리

Anna의 ARP 요청은 브로드캐스트이다. 스위치 A는 이를 모든 포트로 내보낸다. 즉 스위치 B *와* 스위치 C로 보낸다. 두 스위치는 이를 다시 자신의 모든 포트로 전달하므로, 서로 상대 스위치로도, 그리고 A로 되돌아가기도 한다. A는 이를 또다시 전달한다 … 브로드캐스트는 링을 따라 끝없이 돌고, 새 요청이 생길 때마다 복사본이 더 늘어난다.

같은 프레임이 여러 방향에서 계속 스위치에 도착하기 때문에 스위치의 주소 테이블도 뒤죽박죽이 된다. Anna가 어떤 때는 이 포트에, 어떤 때는 저 포트에 있는 것으로 기록된다. 그래서 ping조차 더 이상 도착하지 못한다.

:::tip 핵심 정리
스위치 사이에 **루프**가 있으면 브로드캐스트가 네트워크 안을 끝없이 돌면서 불어난다. 이것이 **브로드캐스트 스톰**이다. 브로드캐스트 스톰은 네트워크를 마비시킨다. IP 패킷과 달리 이더넷 프레임에는 언젠가 전달을 멈추게 해 줄 "유효 기간"이 없다.
:::
