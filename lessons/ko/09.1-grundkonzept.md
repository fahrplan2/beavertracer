# 패킷 필터: 규칙

가장 단순하면서도 가장 중요한 방화벽은 **패킷 필터**야. 패킷 필터는 자신을 통과하는 모든 패킷을 살펴보고, **규칙 목록**을 기준으로 그 패킷을 통과시킬지 결정해. 이때 3계층과 4계층의 헤더만 읽고, 내용(예: 웹 페이지)은 보지 않아.

## 규칙의 구성 요소

| 필드 | 의미 | 예시 |
|---|---|---|
| **방향** | 패킷은 어느 쪽에서 오는가? | A → B (인터넷에서 학교 네트워크로) |
| **프로토콜** | TCP, UDP, ICMP 또는 임의 | TCP |
| **출발지 IP** | 송신자 주소 또는 네트워크 | 임의 |
| **출발지 포트** | 송신자 포트 | 임의 |
| **목적지 IP** | 수신자 주소 또는 네트워크 | `198.51.100.10` |
| **목적지 포트** | 수신자 포트, 즉 서비스 | `80` |
| **동작** | 일치하는 패킷은 어떻게 되는가? | 허용 |

비어 있는 필드는 "임의"를 뜻해. 네트워크는 `198.51.100.0/24`처럼 CIDR 표기법으로 쓰고, 포트 범위는 `1024-65535`처럼 하이픈으로 써.

## 순서가 결과를 좌우한다

방화벽은 규칙을 **위에서 아래로** 검사해. **처음으로 일치하는 규칙**이 결정을 내리고, 그 뒤에 오는 규칙은 이 패킷에 대해 더 이상 보지 않아. 일치하는 규칙이 하나도 없으면 **기본 정책**(*Default Policy*)이 적용돼.

## 세 가지 동작

| 동작 | 방화벽이 하는 일 | 송신자가 알아차리는 것 |
|---|---|---|
| **허용** (*Allow*) | 패킷을 전달한다 | — |
| **폐기** (*Drop*) | 패킷을 아무 말 없이 버린다 | 아무것도 알 수 없음 — 타임아웃이 끝날 때까지 기다린다 |
| **거부** (*Reject*) | 패킷을 버리고, 송신자에게 거절 응답을 보낸다: TCP에서는 **RST**, 그 외에는 ICMP "도달할 수 없음" | 즉시 오류 메시지를 받는다 |

어느 쪽이 더 나을까? **폐기**는 공격자에게 알려주는 정보가 적고, 시도할 때마다 기다려야 하므로 공격자의 시간을 낭비하게 만들어. **거부**는 내부 사용자에게 더 친절해. 프로그램이 오랫동안 멈춰 있는 대신 즉시 오류 메시지를 받으니까. 그래서 실무에서는 보통 외부에서 오는 패킷은 폐기하고, 내부 네트워크에서 오는 패킷은 거부해.

:::quiz match
허용 -> 패킷이 전달된다
폐기 -> 패킷이 사라지고, 송신자는 응답을 헛되이 기다린다
거부 -> 패킷은 전달되지 않지만, 송신자는 즉시 거절 응답을 받는다
기본 정책 -> 일치하는 규칙이 없을 때 적용된다
:::

매칭 확인

:::tip 핵심 정리
**패킷 필터**는 모든 패킷을 방향, 프로토콜, 주소, 포트를 기준으로 **규칙 목록**과 대조해 검사해. **처음으로 일치하는 규칙**이 동작을 결정해: **허용**, **폐기**(조용히) 또는 **거부**(거절 응답과 함께). 일치하는 규칙이 없으면 **기본 정책**이 적용돼.
:::
