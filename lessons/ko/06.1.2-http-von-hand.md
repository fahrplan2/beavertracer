# HTTP 직접 입력하기

:::sim
url=/sims/lesson-6.1.btsim
:::

HTTP가 순수한 텍스트라면, 브라우저 없이 직접 웹 서버와 대화할 수도 있지 않을까? 가능하다. `telnet`을 사용하면 임의의 포트로 TCP 연결을 설정하고, 텍스트를 직접 입력할 수 있다.

## 실험

1. :fa-play: **실행** 모드로 전환하고 **Client-PC**에서 :fa-terminal: **터미널**을 연다.
2. 서버의 80번 포트에 연결한다:
   ```
   $ telnet 192.168.0.20 80
   ```
3. 요청을 한 줄씩 입력하고, **빈 줄**로 끝낸다(**Enter**를 한 번 더 누르면 된다):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

서버는 상태 줄, 헤더, 그리고 연락처 페이지로 응답한다. 브라우저가 받는 것과 똑같이 텍스트로 온다.

:::quiz mc
서버는 네 요청이 끝났다는 것을 어떻게 알까?
- [ ] 특별한 명령 `END`로
- [x] 빈 줄로
- [ ] 일정 시간이 지난 뒤에
:::

:::quiz short
응답의 `Content-Type` 헤더에는 어떤 값이 있는가? (`;` 앞의 첫 번째 부분만)
= text/html
:::

## 오류 일으켜 보기

`curl`은 더 편리한 도구로, 요청을 대신 만들어 준다. `-v`(*verbose*, 상세 출력)를 사용하면 오가는 모든 내용을 보여 준다. `>`로 시작하는 줄은 `curl`이 보낸 것이고, `<`로 시작하는 줄은 서버에서 온 것이다.

직접 해 보자:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
`/gibtsnicht.html`에 대해 어떤 상태 코드를 받는가?
= 404
:::

:::quiz short
그리고 `POST` 메서드로 보낸 요청에는 어떤 상태 코드를 받는가?
= 405
:::

:::note
BeaverTracer의 웹 서버는 파일만 제공할 수 있다. 그래서 `GET`과 `HEAD`만 허용한다. 실제 웹 서버는 예를 들어 `POST`로 폼을 받아 그 데이터를 프로그램에 전달한다.
:::

:::tip 핵심 정리
응용 계층의 많은 프로토콜은 **텍스트 기반**이다. HTTP뿐만 아니라 SMTP, POP3, IMAP도 마찬가지다. 그래서 `telnet`으로 직접 입력해 대화할 수 있고, 트레이서에서 내용을 함께 읽을 수도 있다. 문제 해결에는 실용적이지만 보안 문제이기도 하다. 트래픽을 가로채는 사람은 누구나 모든 내용을 읽을 수 있기 때문이다. 암호화(HTTPS)가 어떻게 도움이 되는지는 8장에서 배운다.
:::
