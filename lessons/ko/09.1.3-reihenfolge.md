# 순서와 기본 방침

## 예외 먼저, 그다음 일반 규칙

**처음으로 일치하는 규칙**이 적용되기 때문에 순서가 중요해. 다음 규칙 목록을 살펴봐 (모든 규칙은 A → B 방향에 적용되고, 기본 정책은 모두 허용이야):

| 번호 | 프로토콜 | 대상 포트 | 동작 |
|---|---|---|---|
| 1 | TCP | 임의 | 폐기 |
| 2 | TCP | 80 | 허용 |

:::quiz mc

- [x] 이미 규칙 1이 일치하므로 폐기된다 — 규칙 2에는 도달하지 않는다
- [ ] 방화벽이 관리자에게 문의한다
:::

일반적으로 **구체적인 규칙은 위에, 일반적인 규칙은 아래에** 둬야 해. 넓은 범위를 포괄하는 규칙은 그 아래의 모든 규칙을 "가려 버린다". **적중** 열을 보면 이런 죽은 규칙을 알 수 있어. 이런 규칙은 계속 0으로 남아 있어.

## 블랙리스트일까, 화이트리스트일까?

9.1.2절에서 너는 개별 포트를 **금지**하고 나머지는 모두 허용했어. 이것을 **블랙리스트**("검은 목록")라고 해. 그 반대가 **화이트리스트**야. 꼭 필요한 것만 **허용**하고 나머지는 모두 금지하는 방식이야. 마지막에 "모두 폐기" 규칙을 두거나 기본 정책을 **모두 폐기**로 설정해.

| | 블랙리스트 | 화이트리스트 |
|---|---|---|
| 기본 방침 | 모두 허용, 예외는 금지 | 모두 금지, 예외는 허용 |
| 기본 정책 | 허용 | 폐기 |
| 서버의 새 서비스 | 곧바로 외부에서 접근 가능 | 누군가 허용할 때까지 차단된 상태 유지 |

:::quiz mc
한 교사가 내일 학교 서버에 포트 3306에서 대기하는 데이터베이스를 설치한다. 9.1.2절의 방화벽(블랙리스트)에서는 어떻게 될까?
- [x] 데이터베이스가 곧바로 인터넷에서 접근 가능해진다
- [ ] 데이터베이스가 자동으로 차단된다
- [ ] 방화벽이 새 서비스를 알려 준다
:::

:::evaluate
답 확인
:::

그래서 좋은 방화벽은 **화이트리스트 원칙**("Default Deny")으로 동작해. 명시적으로 허용되지 않은 것은 모두 금지되는 거야. 학교 서버를 위한 화이트리스트는 다음과 같아:

:::quiz table
| 번호 | 방향 | 프로토콜 | 대상 포트 | 동작 |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {허용} |
| 2 | A → B | TCP | {25} | 허용 |
| 3 | A → B | 임의 | 임의 | {폐기} |
:::

:::evaluate
표 확인
:::

:::quiz mc
규칙 3을 맨 위로 옮기면 어떻게 될까?
- [ ] 아무 일도 없다, 순서는 상관없다
- [x] 인터넷에서 아무것도 통과하지 못한다, 웹과 메일도 마찬가지다
- [ ] 웹과 메일만 통과한다
:::

:::tip 핵심 정리
**처음으로 일치하는 규칙**이 적용되기 때문에 **구체적인 규칙은 위에**, 일반적인 규칙은 아래에 둬야 해. **블랙리스트**(…를 제외하고 모두 허용)보다 **화이트리스트**(…를 제외하고 모두 금지, *Default Deny*)가 더 안전해. 잊어버린 서비스나 새 서비스가 자동으로 차단된 상태로 남기 때문이야.
:::
