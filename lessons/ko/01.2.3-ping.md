# ping 실행하고 트레이서에서 따라가기

:::sim
url=/sims/lesson-1.2.3.btsim
:::

이제 두 PC의 주소는 `192.168.0.10`과 `192.168.0.11`이야. 첫 번째 테스트를 해 볼 시간이야. **ping**을 사용하면 한 PC가 다른 PC에 작은 요청을 보내고 응답을 기다려.

## ping 실행하기

:fa-play: **실행** 모드로 전환해. **Computer 1**에서 :fa-terminal: **터미널**을 열고 다음과 같이 입력해:

```
$ ping 192.168.0.11
```

상대 PC가 응답하면, 전송한 패킷마다 응답 시간이 적힌 한 줄이 표시돼. 첫 번째 ping 성공이야!

:::tip 핵심 정리
**ping**은 다른 장치에 도달할 수 있는지 확인해. 요청을 보내고 응답이 오기까지 걸리는 시간을 측정해.
:::

## 트레이서에서 따라가기

이제 :fa-magnifying-glass: **추적** 모드로 전환해. 여기에는 아직 아무것도 보이지 않아. 왼쪽 위 **Traces:** 옆의 **+**를 클릭하고 **Computer 1**을 선택한 다음 포트 `eth0`을 선택해.

이제 이 포트를 지나간 모든 패킷의 목록이 보여. 방금 보낸 ping도 포함돼 있어. 패킷 하나를 클릭해 봐. 그 아래에 패킷의 정확한 구조가 계층별로 표시돼.

:::tip 핵심 정리
네트워크에서 데이터는 한꺼번에 전송되지 않고 **패킷**이라는 작은 단위로 나뉘어 전송돼. 각 패킷에는 송신자, 수신자, 그리고 데이터의 일부가 들어 있어.
:::

:::tip
ping은 항상 요청(Echo Request)과 응답(Echo Reply)으로 이루어져 있어. **Info** 열에서 두 방향을 모두 찾을 수 있겠니?
:::

## 첫 번째 ping 전에 누가 묻고 있을까?

목록 맨 위, 첫 번째 ping보다도 앞에 프로토콜이 **ARP**인 패킷이 두 개 있어. **Info** 열을 읽어 봐. 대략 이런 내용이 적혀 있어:

```
Who has 192.168.0.11? Tell 192.168.0.10
192.168.0.11 is at aa:fd:9f:a5:d2:89
```

Computer 1은 상대 PC의 IP 주소는 알고 있었지만, 아직 **하드웨어 주소**(*MAC 주소* — 모든 네트워크 카드는 저마다 고유한 주소를 가져)는 몰랐어. 이 주소가 없으면 아무것도 보낼 수 없어. 그래서 먼저 네트워크에 이렇게 외쳐. *"192.168.0.11 가진 사람? 192.168.0.10에게 알려 줘!"* 찾던 PC가 자신의 하드웨어 주소로 응답해. 바로 이것이 **ARP**의 역할이야.

그 후 Computer 1은 받은 응답을 기억해 둬. 그래서 ARP는 매번이 아니라 첫 번째 ping 전에만 나타나.

:::tip 핵심 정리
**ARP**는 알고 있는 IP 주소에 맞는 하드웨어 주소(**MAC 주소**)를 찾아 줘. PC가 네트워크의 모든 장치에 묻고, 찾는 장치만 응답해.
:::
