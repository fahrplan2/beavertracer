# 문제 해결: 리턴 경로

:::sim
url=/sims/lesson-4.5.3.btsim
:::

방금 전과 같은 구성이야: Firma A — Router A — Zwischennetz — Router B — Firma B. 관리자가 **Router A**에 Firma B로 가는 경로(`172.16.0.0/24`, `10.0.0.2`를 경유)를 등록해 두었어. 그런데도 Anna는 Clara가 응답하지 않는다고 알려 와.

오류를 찾아서 해결해 보자.

<details>
<summary>힌트 1: Anna의 핑이 도착하긴 할까?</summary>

Anna에서 Clara로 핑을 보내고 **Clara**에 대한 추적을 열어 봐. 핑이 Clara에게 도착할까? 그리고 Clara는 응답할까?
</details>

<details>
<summary>힌트 2: traceroute는 어디까지 갈까?</summary>

Anna에서 `traceroute 172.16.0.10`을 입력해 봐. 어느 라우터까지 응답이 돌아오고, Clara의 응답을 Anna에게 전달해야 하는 라우터는 어느 쪽일까?
</details>

<details>
<summary>힌트 3: 누가 어떤 네트워크를 알고 있을까?</summary>

**Router B**의 라우팅 테이블을 살펴봐. `192.168.0.0/24`로 가는 패킷이 어디로 가야 하는지 알고 있을까?
</details>

:::task
title: 연결이 복구되었을까?
Router B가 Firma A로 가는 경로를 알고 있는지, 그리고 Anna가 Clara에게 도달하는지 확인해. 이를 위해 시뮬레이션이 실행 모드에서 동작 중이어야 해.
check: hasRoute(5, "192.168.0.0/24")
check: pingOk(9, 11)
:::

## 무슨 일이 있었을까?

:::quiz multi
문제 해결 중에 무엇을 관찰했니?
- [x] Anna의 핑이 Clara에게 도착했고, Clara가 응답했다
- [x] Router B가 Firma A를 알지 못해서 응답이 Router B에서 멈췄다
- [ ] Router A가 Anna의 핑을 폐기했다
- [x] 가는 경로는 정상 동작했는데도 `traceroute`는 Router A 이후로 `*`만 표시했다
:::

:::evaluate
답 확인
:::

:::tip 핵심 정리
모든 연결에는 **가는 경로와 돌아오는 경로**가 필요해: 경로상의 모든 라우터는 목적지 네트워크와 송신자의 네트워크, 이 *두* 네트워크를 모두 알고 있어야 해. **리턴 경로**가 없는 것은 가장 흔한 라우팅 오류 중 하나야. 주의: `traceroute`는 어느 지점부터 응답이 돌아오지 않는지만 보여 줘. 오류는 돌아오는 경로에 있을 수도 있어.
:::
