작업 영역에는 **Client-PC**, **DNS-Server**, 그리고 학교 웹 서버인 `www.beaver-schule.de`가 보인다. 이 웹 서버는 **HTTPS**로도 페이지를 제공한다.

## 브라우저의 자물쇠

1. :fa-play: **실행** 모드로 전환하고, **Client-PC**를 클릭한 다음 :fa-globe: **브라우저**를 연다.
2. `https://www.beaver-schule.de/`에 접속한다. 주소가 **https**로 시작하는지 확인한다.
3. 주소 왼쪽에 **자물쇠**가 나타난다. 자물쇠를 클릭한다.

:::quiz short
인증서는 어떤 이름으로 발급되었는가(주체, `CN=` 제외)?
= www.beaver-schule.de
:::

:::quiz short
인증서를 발급한 곳은 어디인가(발급자, `CN=` 제외)?
= Biber Root CA
:::

:::evaluate
답 확인
:::

## Client-PC는 왜 이 인증서를 신뢰할까?

**Client-PC**에서 :fa-shield-halved: **Zertifikatverwaltung**을 열고 **Vertrauenswürdige CAs** 탭으로 이동한다.

:::quiz mc
그곳에서 무엇을 찾을 수 있는가?
- [x] **Biber Root CA**의 인증서
- [ ] `www.beaver-schule.de`의 인증서
- [ ] 항목 없음
:::

:::quiz mc
Biber Root CA가 루트 CA라는 것을 어떻게 알 수 있는가?
- [x] **자체 서명**되어 있다: 주체와 발급자가 같다
- [ ] 이름이 "CA"로 끝난다
- [ ] 공개 키가 없다
:::

:::quiz mc
Client-PC의 **Privater Schlüssel** 항목에는 "Ja"와 "Nein" 중 무엇이 표시되는가?
- [ ] Ja — 클라이언트는 서명을 검증하기 위해 CA의 개인 키가 필요하다
- [x] Nein — 검증에는 공개 키만으로 충분하며, 개인 키는 CA만 가지고 있다
:::

:::evaluate
답 확인
:::

## 반대편: 웹 서버

이번에는 웹 서버 **www.beaver-schule.de**에서 :fa-shield-halved: **Zertifikatverwaltung**(**Meine Zertifikate** 탭)을 열고 서버의 인증서를 살펴본다.

:::quiz multi
웹 서버의 인증서에 대해 맞는 설명은 무엇인가?
- [x] **Privater Schlüssel** 항목에 "Ja"가 표시된다 — 서버는 연결 설정을 위해 개인 키가 필요하다
- [x] **체인**은 `www.beaver-schule.de ← Biber Root CA`이다
- [x] **지문**이 브라우저의 자물쇠 창에 표시된 것과 같다
- [ ] 자체 서명되어 있다
:::

:::evaluate
답 확인
:::

:::note
**지문**(Fingerabdruck)은 인증서에 대한 해시값이다. 이를 이용하면 모든 필드를 하나하나 확인하지 않고도 두 인증서를 빠르게 비교할 수 있다.
:::

:::tip 핵심 정리
**웹 서버**는 자신의 인증서를 **개인 키와 함께** 보유한다. **클라이언트**는 **루트 CA의 인증서**(개인 키 없음)만 알고 있으며, 이것만으로 서버 인증서의 서명을 검증할 수 있다. 브라우저에서 **자물쇠**를 클릭하면 주체, 발급자, 지문, 유효 기간을 볼 수 있다.
:::
