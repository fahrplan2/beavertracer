# 문제 해결: 새 규칙 이후로 아무것도 안 돼요

:::sim
url=/sims/lesson-9.4.btsim
:::

Beaver-Schule의 관리자인 Biber 선생님이 어제 방화벽을 화이트리스트 방식으로 바꿨다. 그 뒤로 모두가 불평하고 있다. **학교 웹사이트**는 외부에서 더 이상 접속되지 않고, 인터넷에서 오는 **메일도 전혀 도착하지 않는다**. 그래도 원하던 대로 SSH는 이제 외부에서 차단되었다.

**방화벽**의 규칙에서 오류를 찾아 고쳐 보자.

<details>
<summary>힌트 1: 패킷이 올바른 규칙에 도달하기는 할까?</summary>

**Internet-PC**에서 `nmap -p 22,25,80 198.51.100.10`으로 테스트한 다음, 방화벽의 **Treffer** 열을 확인해 보자. 해당 패킷이 도착해야 하는데도 0에 머물러 있는 규칙은 다른 규칙에 가려져 있거나, 애초에 조건이 맞지 않는 것이다.
</details>

<details>
<summary>힌트 2: 자세히 살펴보기</summary>

규칙에 적힌 모든 숫자를 5장에서 배운 포트와 비교해 보자. HTTP에는 어떤 포트가, SMTP에는 어떤 포트가 해당할까? 그리고 순서도 생각해 보자. 처음으로 일치하는 규칙이 적용된다.
</details>

:::task
title: 웹과 메일에 다시 접속할 수 있을까?
학교 서버의 웹과 메일에 인터넷에서 접속할 수 있고 SSH는 계속 차단되어 있는지 확인한다.
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## 무슨 일이 있었을까?

:::quiz multi
규칙에 어떤 오류가 있었을까?
- [x] 웹 규칙이 80번 대신 8080번 포트를 허용했다
- [x] 메일 규칙이 "모두 차단" 규칙 아래에 있어서 한 번도 적용되지 않았다
- [ ] 방화벽이 스테이트풀로 설정되어 있었다
- [ ] 메일에는 25번 포트가 잘못된 포트이다
:::

답 확인
:::

:::tip 핵심 정리
방화벽 규칙에서 흔한 오류는 포트 번호의 **자리 바꿈**, 잘못된 **방향**, 그리고 일반적인 규칙이 특정 규칙을 가리는 잘못된 **순서**이다. 문제를 해결할 때는 외부에서 하는 **포트 스캔**, 방화벽의 **로그**, 규칙의 **적중 횟수 카운터**가 도움이 된다.
:::
