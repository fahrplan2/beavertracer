# 문제 해결: 노트북이 네트워크에 연결되지 않아요

:::sim
url=/sims/lesson-6.4.3.btsim
:::

방학이 끝난 뒤 선생님들이 연락해 왔다: "우리 노트북이 더는 네트워크에 연결되지 않아요!" 두 노트북 모두 **DHCP**로 설정되어 있다. 계획에 따르면 DHCP 서버는 `192.168.0.100`부터 `192.168.0.120`까지의 주소를 배포해야 하고, 게이트웨이는 `192.168.0.1`, DNS 서버는 `192.168.0.53`이다.

오류를 찾아서 해결해 보자.

<details>
<summary>힌트 1: 노트북의 주소는 무엇일까?</summary>

노트북의 :fa-gear: **IP 설정**을 확인해 보자. `169.254`로 시작하는 주소는 장치가 **스스로** 정한 주소다. DHCP 서버가 응답하지 않았기 때문이다.
</details>

<details>
<summary>힌트 2: DHCP 서버가 응답할까?</summary>

노트북에 대한 추적을 열어 보자. `DHCP Discover`만 보이니, 아니면 응답도 보이니? 그런 다음 **DHCP 서버** 앱을 살펴보자. 서버가 실행 중일까? 그리고 어떤 범위를 배포하고 있을까?
</details>

<details>
<summary>힌트 3: 새 주소 받기</summary>

서버에서 무언가를 변경했다면, 노트북의 IP 설정에서 모드를 잠깐 **정적**으로 바꿨다가 다시 **DHCP**로 바꾸고 **적용**을 클릭하자. 그러면 노트북이 다시 요청한다.
</details>

:::task
title: 노트북이 다시 네트워크에 연결되었을까?
두 노트북이 계획된 범위의 주소를 가지고 있고 DHCP 서버에 도달할 수 있는지 확인해 보자. 이를 위해 시뮬레이션이 실행 모드로 동작 중이어야 한다.
check: ip(3, "192.168.0.96/27")
check: ip(4, "192.168.0.96/27")
check: pingOk(3, 2)
check: pingOk(4, 2)
:::

## 무슨 일이 있었을까?

:::quiz multi
어떤 설명이 맞을까?
- [x] DHCP 서버가 시작되지 않았다. 그래서 노트북이 스스로 `169.254` 주소를 정했다
- [x] 주소 범위가 잘못된 네트워크에 있었다 (`192.168.0.…` 대신 `192.168.1.…`)
- [ ] 노트북이 고정 주소로 설정되어 있었다
- [ ] 스위치에 게이트웨이가 없었다
:::

답 확인
:::

:::tip 핵심 정리
장치가 **`169.254.0.0/16`**의 주소를 가지고 있다면, **DHCP 서버로부터 응답을 받지 못해** 스스로 주소를 정한 것이다 (**APIPA**). 이 주소로는 같은 상황에 놓인 다른 장치와만 통신할 수 있다. 그럴 때는 이렇게 확인하자. DHCP 서버가 실행 중인가? 서버에 도달할 수 있는가? 그리고 **올바른 네트워크**의 주소를 배포하고 있는가?
:::
