라우터에는 연결 포트가 두 개 있다:

| 포트 | IP 주소 | 네트워크 |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

PC들이 라우터를 사용하도록 각 PC에는 **게이트웨이**가 설정되어 있다. Anna와 Ben은 `192.168.0.1`, Clara와 David는 `172.16.0.1`이다. 게이트웨이는 :fa-gear: **IP 설정**의 **Gateway** 필드에서 확인할 수 있다.

:::tip 핵심 정리
**게이트웨이**(정확히는 *기본 게이트웨이*)는 **자신의 네트워크 안에 있는** 라우터의 IP 주소이다. PC는 목적지가 다른 네트워크에 있는 모든 패킷을 게이트웨이로 보낸다.
:::

## 실험

1. :fa-play: **실행** 모드로 전환하고 **Anna**에서 Clara에게 ping을 보내 본다(`ping 172.16.0.10`). 이번에는 성공한다. 출력에서 `ttl=` 값을 눈여겨보자.
2. :fa-magnifying-glass: **추적** 모드로 전환하고 **Anna**의 트레이스를 연다.

첫 번째 패킷(ARP 요청)을 살펴보자:

## 라우터가 패킷으로 하는 일

라우터는 Anna가 보낸 프레임을 받아 IP 패킷을 꺼내고 **목적지 IP 주소**를 확인한다. 이를 통해 Clara가 `eth1` 쪽 네트워크에 있다는 것을 알아낸다. 그래서 패킷을 **새** 프레임에 담는데, 송신자로는 자신의 MAC 주소를, 목적지로는 Clara의 MAC 주소를 넣어 그쪽으로 내보낸다.

| 라우터에서 … 은(는) 어떻게 되는가 | |
|---|---|
| MAC 주소(계층 2)? | **새로** 설정된다 — 해당 네트워크 안에서만 유효하다 |
| IP 주소(계층 3)? | **그대로 유지된다** — Anna에서 Clara까지 |
| Time to Live? | **1 감소**한다 |

:::tip 핵심 정리
**라우터**는 **계층 3**에서 동작한다. **목적지 IP 주소**를 기준으로 패킷을 다른 네트워크로 전달한다. IP 주소는 전체 경로에서 그대로 유지되고, MAC 주소는 네트워크마다 새로 설정된다. 라우터는 지날 때마다 **Time to Live(TTL)** 를 1씩 줄이며, 0에 도달하면 패킷이 폐기된다. 덕분에 패킷이 끝없이 순환하지 않는다.
:::

:::note
3.4장의 브로드캐스트 폭풍을 기억하는가? 이더넷 프레임에는 TTL이 없지만, IP 패킷에는 있다.
:::

## Anna는 누구를 알고 있을까? ARP 캐시

1.2.3장을 기억하는가? 거기서는 ARP가 *첫 번째* ping 전에만 나타났는데, PC가 응답을 기억해 두었기 때문이다. 이 기억 목록을 **ARP 캐시**(*ARP 테이블*이라고도 함)라고 한다. 요청은 **ARP Request**, 응답은 **ARP Reply**(또는 *ARP Response*)라고 부른다.

:fa-play: **실행** 모드로 전환하고 **Anna**에서 :fa-terminal: **터미널**을 열어 Anna의 ARP 캐시를 표시해 보자:

```
$ arp
```

:::quiz mc
Anna의 ARP 캐시에는 무엇이 들어 있는가?
- [x] 라우터의 IP 주소(`192.168.0.1`)와 그 MAC 주소만
- [ ] Clara의 IP 주소와 Clara의 MAC 주소
- [ ] 라우터와 Clara의 주소
:::

:::evaluate
답 확인
:::

Anna는 Clara의 MAC 주소가 전혀 필요 없다. Firma B로 향하는 모든 것을 라우터로 보내기 때문이다. Clara의 MAC 주소는 라우터만 알고 있다. 라우터가 자기 쪽에서 직접 ARP로 물어봤기 때문이다.

:::tip 핵심 정리
**ARP 캐시**에는 장치가 어떤 MAC 주소가 어떤 IP 주소에 속하는지 기억해 둔다. 그래서 패킷을 보낼 때마다 ARP Request를 보낼 필요가 없다. `arp` 명령으로 확인할 수 있다. PC는 **자신의** 네트워크에 있는 MAC 주소만 알고 있다. 다른 네트워크에 있는 모든 목적지에는 라우터의 MAC 주소를 사용한다.
:::

:::note
실제 네트워크에서는 ARP 캐시의 항목이 일정 시간이 지나면 삭제되고 필요할 때 다시 요청한다. 예를 들어 그사이 장치의 네트워크 카드가 바뀐 경우를 대비해서이다. BeaverTracer에서는 시뮬레이션이 실행되는 동안 항목이 유지된다.
:::
