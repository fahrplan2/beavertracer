# 자체 CA 구축하기

:::sim
url=/sims/lesson-8.2.2.btsim
:::

`www.beaver-schule.de`에 대한 인증서는 아직 없다. 학교는 상용 CA에 인증서를 신청하는 대신 **자체 CA**인 **Schul-CA**를 구축한다. 많은 회사와 학교가 내부 서버를 위해 이렇게 한다.

실제로는 Schul-CA가 별도로 마련한, 특별히 잘 보호된 컴퓨터에서 동작한다. 여기서는 웹 서버 한 대에서 모든 역할을 네가 직접 맡는다.

## 1단계: Schul-CA 생성하기

1. :fa-play: **실행** 모드로 전환하고, 웹 서버 **www.beaver-schule.de**에서 :fa-shield-halved: **Zertifikatverwaltung**을 연다.
2. **Generieren** 탭에서 다음과 같이 설정한다.
    - **Common Name:** `Schul-CA`
    - **Typ:** Selbstsigniert
    - **Dies ist ein CA-Zertifikat**에 체크
    - **Speichern unter:** `schul-ca.cert.json`
3. **Zertifikat generieren**을 클릭한다.

이때 새로운 **키 쌍**이 만들어진다. 인증서에는 공개 키가 들어 있고, 개인 키는 웹 서버의 파일 안에 남는다.

## 2단계: 서버 인증서 발급하기

다시 **Generieren** 탭에서 다음과 같이 설정한다.

- **Common Name:** `www.beaver-schule.de` — 브라우저에 입력하는 이름과 정확히 같아야 한다
- **Typ:** Von CA signiert, **Signierende CA:** Schul-CA
- **Speichern unter:** 예: `www.beaver-schule.de.cert.json`

**Meine Zertifikate** 탭에서 이제 두 인증서를 볼 수 있다. 새 서버 인증서를 클릭해 보자.

:::quiz short
서버 인증서의 **발급자**(Aussteller)는 누구인가? (`CN=` 제외)
= Schul-CA
:::

:::quiz mc
이 인증서의 **체인**(Kette)은 어떻게 표시되는가?
- [x] `www.beaver-schule.de ← Schul-CA`
- [ ] `Schul-CA ← www.beaver-schule.de`
- [ ] `www.beaver-schule.de` (자체 서명)
:::

:::evaluate
답 확인
:::

## 3단계: 클라이언트에 Schul-CA 알려 주기

클라이언트 PC는 아직 Schul-CA를 모른다. 브라우저에 미리 설치되어 있지 않기 때문이다. 클라이언트에 Schul-CA의 인증서를 주어야 하는데, 이때 **개인 키는 제외**해야 한다.

1. 웹 서버의 **Meine Zertifikate**에서 **Schul-CA**를 선택하고 **Kopieren**을 클릭한다(*Kopieren + Schlüssel*이 아니다!).
2. **클라이언트 PC**에서 :fa-shield-halved: **Zertifikatverwaltung**을 열고 **Vertrauenswürdige CAs** 탭으로 이동한다.
3. **Einfügen: Schul-CA**를 클릭한다.

:::warning
**CA의 개인 키**는 시스템 전체에서 가장 가치 있는 비밀이다. 이 키를 가진 사람은 **임의의** 이름에 대한 인증서를 발급할 수 있고, 모든 클라이언트가 그 인증서를 신뢰하게 된다. 이 키는 CA 컴퓨터 밖으로 절대 나가서는 안 된다.
:::

:::task
title: Schul-CA를 설정했나요?
웹 서버에 Schul-CA가 발급한 www.beaver-schule.de용 인증서가 있는지, 그리고 클라이언트 PC가 Schul-CA를 신뢰하는지 확인한다.
check: hasCert(4, "www.beaver-schule.de", "Schul-CA")
check: trusts(2, "Schul-CA")
:::

:::quiz mc
클라이언트에는 왜 개인 키 **없이** 인증서만 복사할까?
- [ ] 키와 함께 복사하면 시간이 더 오래 걸리기 때문에
- [x] 서명을 검증하는 데는 공개 키만으로 충분하고, 개인 키가 있으면 클라이언트에서 누구나 직접 인증서를 발급할 수 있기 때문에
- [ ] 그렇지 않으면 클라이언트가 연결을 설정할 수 없기 때문에
:::

:::evaluate
답 확인
:::

웹 서버 자체는 아직 설정을 바꾸지 않았다. 여전히 HTTP만 사용한다. HTTPS를 켜는 방법은 8.3.3절에서 배운다.

:::tip 핵심 정리
**자체 CA**는 개인 키를 가진 **자체 서명 CA 인증서**로 이루어진다. 이 인증서로 Common Name이 서버 이름과 일치하는 **서버 인증서**를 발급한다. 클라이언트가 이 인증서들을 신뢰하려면, **개인 키가 없는 CA 인증서**를 **신뢰할 수 있는 CA** 목록에 넣어 주어야 한다.
:::
