# 전망: 동적 라우팅

프로젝트에서 너는 네 개의 지점을 위해 열두 개의 경로를 직접 입력했다. 큰 회사 네트워크에는 라우터가 수백 대 있고, 인터넷에는 수만 대가 있다. 게다가 어딘가에서는 끊임없이 회선이 끊기거나 새 회선이 추가된다. 이런 일을 직접 손으로 처리하는 것은 더 이상 불가능하다.

그래서 라우터는 대개 서로 경로를 자동으로 교환한다. 이를 위한 것이 **라우팅 프로토콜**이다. 이렇게 하는 방식을 **동적 라우팅**이라고 하며, 모든 것을 직접 입력하는 **정적 라우팅**과 대비된다.

가장 잘 알려진 라우팅 프로토콜:

| 프로토콜 | 아이디어 | 대표적인 사용처 |
|---|---|---|
| **RIP** (*Routing Information Protocol*) | 각 라우터는 이웃 라우터에게 자신이 어떤 네트워크에 라우터 몇 대(*홉*)를 거쳐 도달할 수 있는지 주기적으로 알려 준다. | 소규모 네트워크, 학습용 예제 |
| **OSPF** (*Open Shortest Path First*) | 각 라우터는 네트워크의 전체 구성을 알고 있으며, 이를 바탕으로 최단 경로를 스스로 계산한다. | 회사 네트워크 |
| **BGP** (*Border Gateway Protocol*) | 대형 네트워크 사업자(예: 인터넷 서비스 제공자)가 자신이 도달할 수 있는 네트워크를 서로 알려 준다. | 제공자 간의 인터넷 |

:::quiz match
RIP -> 라우터가 이웃에게 몇 홉 떨어진 곳에서 네트워크에 도달할 수 있는지 알려 준다
OSPF -> 각 라우터가 전체 네트워크 구성을 알고 최단 경로를 계산한다
BGP -> 대형 인터넷 서비스 제공자들의 네트워크를 연결한다
:::

:::tip 핵심 정리
**정적 라우팅**에서는 관리자가 모든 경로를 직접 입력한다. **동적 라우팅**에서는 라우터가 RIP, OSPF, BGP 같은 **라우팅 프로토콜**을 이용해 경로를 자동으로 교환하며, 연결이 끊기면 스스로 적응한다.
:::

:::note
BeaverTracer는 RIP, OSPF, BGP를 시뮬레이션할 수 있다. 라우터의 같은 이름의 탭에서 찾을 수 있다. 이 강의에서는 전망 소개까지만 다룬다.
:::
