# 네트워크에서의 IPv6

:::sim
url=/sims/lesson-4.6.3.btsim
:::

스위치에 Anna, Ben, 그리고 라우터가 연결되어 있다. Anna와 Ben은 IPv6가 **SLAAC (automatisch)**로 설정되어 있다 — 아무도 IPv6 주소를 직접 입력해 주지 않았다. 라우터는 프리픽스 `2001:db8:1::/64`를 알고 있다.

## 주소는 어디서 올까?

1. :fa-play: **실행** 모드로 전환하고 몇 초 기다린다.
2. **Anna**에서 :fa-terminal: **터미널**을 열고 `ip a`를 입력한다.

IPv4 주소 외에도 `inet6`가 있는 줄이 두 개 보인다. 하나는 `scope link`인 주소이고, 다른 하나는 `scope global`인 주소이다.

:::quiz mc
두 IPv6 주소 중 링크 로컬 주소는 어느 것일까?
- [x] 앞부분이 `fe80::`인 주소 (`scope link`)
- [ ] 앞부분이 `2001:db8:1:`인 주소 (`scope global`)
:::

:::quiz mc
글로벌 주소의 프리픽스 `2001:db8:1:0`은 어디서 온 것일까?
- [ ] Anna가 스스로 만들어 냈다
- [x] 라우터에서 왔다 — 라우터가 네트워크에 프리픽스를 알려 준다
- [ ] 스위치에서 왔다
:::

**인터페이스 ID**(마지막 네 블록)를 Anna의 **MAC 주소**와 비교해 보자. MAC 주소는 :fa-gear: **IP 설정** 맨 아래에서 찾을 수 있다. 예를 들어 MAC 주소 `aa:28:39:e2:41:82`는 인터페이스 ID `a828:39ff:fee2:4182`가 된다. 가운데에 `ff:fe`가 삽입되고, 맨 앞의 비트 하나가 반전된다(그래서 `aa`가 `a8`이 된다).

이 방식을 **SLAAC**(*Stateless Address Autoconfiguration*)라고 한다. 라우터는 프리픽스를 알려 주고, 인터페이스 ID는 각 장치가 스스로 만든다.

:::note
MAC 주소는 장치를 고유하게 식별하므로, 인터페이스 ID만으로 그 장치를 인터넷 어디에서나 알아볼 수 있게 된다. 그래서 실제 장치들은 대개 주기적으로 바뀌는 임의의 인터페이스 ID(*프라이버시 확장*)를 추가로 사용한다 — 개인정보 보호를 위한 장치이다.
:::

## 이웃 찾기 — ARP 없이

1. **Ben**에서 `ip a`를 입력하고 그의 **글로벌** IPv6 주소를 기억해 둔다.
2. **Anna**에서 그 주소로 핑을 보낸다. 예: `ping 2001:db8:1:0:…` (Ben의 전체 주소를 사용).
3. :fa-magnifying-glass: **추적** 모드로 전환하고 **Anna**의 트레이스를 연다.

첫 번째 `Echo (ping) request` 바로 앞의 패킷들을 살펴보자.

:::quiz multi
맞는 설명은 어느 것일까?
- [x] ARP 요청 대신 Anna는 **Neighbor Solicitation**("이 주소를 가진 장치는 누구인가?")을 보낸다
- [x] Ben은 **Neighbor Advertisement**로 응답하며 자신의 MAC 주소를 알려 준다
- [x] 요청은 브로드캐스트로 모두에게 가는 것이 아니라 멀티캐스트 주소(`ff02::1:ff…`)로 간다
- [ ] Anna는 IPv4처럼 ARP 요청을 보낸다
- [x] 라우터는 `ff02::1`로 주기적으로 **Router Advertisement**를 보낸다 — 여기에 프리픽스가 들어 있다
:::

:::tip 핵심 정리
IPv6에서는 **NDP**(*Neighbor Discovery Protocol*, ICMPv6의 일부)가 ARP의 역할을 넘겨받는다. 장치들은 **Neighbor Solicitation**과 **Neighbor Advertisement**로 이웃의 MAC 주소를 찾는다. 라우터는 **Router Advertisement**로 프리픽스를 알려 주고, 장치들은 이를 바탕으로 **SLAAC**를 통해 스스로 주소를 만든다.
:::
