# 정적 경로 등록하기

:::sim
url=/sims/lesson-4.5.2.btsim
:::

이번에는 회사 A와 회사 B 사이에 라우터가 **두 대** 있다. 두 라우터는 별도의 작은 네트워크인 **중간 네트워크** `10.0.0.0/30`으로 연결되어 있다:

| 라우터 | 인터페이스 | IP 주소 | 네트워크 |
|---|---|---|---|
| Router A | `eth0` | `192.168.0.1/24` | 회사 A (Anna) |
| Router A | `eth1` | `10.0.0.1/30` | 중간 네트워크 |
| Router B | `eth0` | `10.0.0.2/30` | 중간 네트워크 |
| Router B | `eth1` | `172.16.0.1/24` | 회사 B (Clara) |

:::note
`/30` 네트워크에는 사용할 수 있는 주소가 정확히 두 개 있다. 그래서 라우터 두 대를 연결하는 데 안성맞춤이다(4.2.3절 참고).
:::

## 문제 상황

:fa-play: **실행** 모드로 전환하고 **Anna**에서 Clara로 ping을 보내 보자(`ping 172.16.0.10`). Clara는 응답하지 않고, 대신 Router A(`192.168.0.1`)가 "목적지 네트워크에 도달할 수 없음"이라고 알려 준다.

**Router A**의 **라우팅 테이블 IPv4**를 살펴보자.

:::quiz mc
Anna의 ping이 Clara에게 도착하지 않는 이유는 무엇일까?
- [ ] Anna에 게이트웨이가 등록되어 있지 않다
- [x] Router A는 `172.16.0.0/24` 네트워크를 모른다. 이 네트워크는 Router A에 직접 연결되어 있지 않고, 그쪽으로 가는 경로도 없다
- [ ] 중간 네트워크가 너무 작다
:::

## 경로 등록하기

Router A는 `172.16.0.0/24`로 가는 패킷을 `eth1`을 통해 Router B(`10.0.0.2`)로 보내야 한다는 것을 알아야 한다.

1. **Router A**에서 **라우팅 테이블 IPv4** 탭을 열고 **+ 추가**를 클릭한다.
2. 새 행에 다음과 같이 입력한다: **대상** `172.16.0.0`, **넷마스크** `255.255.255.0`, **다음 홉** `10.0.0.2`, **Iface** `eth1`.
3. 체크 표시 :fa-check:를 눌러 행을 저장한다. **출처** 열에 이제 **정적**이라고 표시된다.

Clara에게 다시 ping을 보내 보자. 이제 응답이 온다.

:::note
참고로 Router B는 회사 A로 돌아가는 길을 이미 알고 있다. Router B의 라우팅 테이블에는 `10.0.0.1`을 경유하는 `192.168.0.0/24`용 정적 경로가 이미 들어 있다. 이 되돌아오는 경로가 왜 똑같이 중요한지는 다음 페이지에서 확인할 수 있다.
:::

## 경로 추적하기: traceroute

`traceroute`를 사용하면 패킷이 어떤 라우터들을 거쳐 가는지 볼 수 있다. **Anna**에서 다음과 같이 입력한다:

```
$ traceroute 172.16.0.10
```

:::quiz short
Anna에서 Clara로 가는 패킷은 몇 대의 라우터를 거칠까?
= 2
= 두 대
= 두 개
= 둘
:::

:::quiz mc
`traceroute`는 Router B의 주소로 어떤 것을 보여 줄까?
- [x] `10.0.0.2` — 패킷이 들어오는 중간 네트워크 쪽 Router B의 주소
- [ ] `172.16.0.1` — 회사 B 쪽 Router B의 주소
- [ ] `192.168.0.1`
:::

:::evaluate
답 확인
:::

`traceroute`는 4.3.1절에서 배운 **Time to Live**를 이용한 방법을 쓴다. 먼저 TTL이 1인 패킷을 보낸다. 첫 번째 라우터는 TTL에서 1을 빼서 0이 되면 패킷을 버리고, 이를 송신자에게 알려 준다. 이렇게 Anna는 첫 번째 라우터를 알게 된다. 그다음에는 두 번째 라우터를 위해 TTL 2를 보내고, 목적지가 응답할 때까지 이를 계속 반복한다.

:::tip 핵심 정리
**정적 경로**는 관리자가 직접 손으로 등록한다. 대상 네트워크, 넷마스크, 다음 홉, 인터페이스를 입력한다. **traceroute**를 사용하면 패킷이 지나는 경로를 라우터 하나하나 따라가며 확인할 수 있다.
:::
