# 무선은 누구나 엿듣는다

:::sim
url=/sims/lesson-3.3.2.btsim
:::

이제 WLAN `Schule`에 태블릿 두 대가 있다. **Anna**(`192.168.0.30`)와 **Ben**(`192.168.0.31`)이다.

3.1장을 떠올려 보자. Anna가 스위치를 통해 Ben에게 ping을 보냈을 때 Clara는 아무것도 알아채지 못했다. 스위치가 ping을 Ben의 포트로만 보냈기 때문이다. WLAN에서도 똑같을까? 어떻게 될지 잠깐 생각해 보자.

## 실험

1. :fa-play: **실행** 모드로 전환하고 **Anna**에서 학교 PC로 ping을 보낸다(`ping 192.168.0.10`).
2. :fa-magnifying-glass: **추적** 모드로 전환하고 **+** 로 **Ben**의 `wlan0` 포트에 대한 트레이스를 연다.

:::quiz mc
Ben에서 무엇이 보이는가?
- [ ] Anna의 ARP 요청만 보인다 — 스위치에서처럼
- [x] Anna와 학교 PC 사이의 모든 패킷이 보이고, ping도 보인다
- [ ] 아무것도 보이지 않는다. ping은 Ben과 상관없다
:::

## 그 이면의 원리

전파는 모든 방향으로 퍼져 나간다. 그래서 Anna가 보내는 것은 액세스 포인트뿐 아니라 근처에 있는 *모든* 장치에 도달한다. 무선은 **공유 매체**이다. Ben의 태블릿은 보통 자신에게 향하지 않은 것은 모두 무시한다. 하지만 캡처하려고 *마음먹은* 사람은 누구나 모든 것을 읽을 수 있다.

| | 스위치(유선) | WLAN(무선) |
|---|---|---|
| 유니캐스트를 받는 것은? | 수신자의 포트뿐 | 범위 안의 모든 장치 |
| 제3자가 엿볼 수 있는가? | 보통은 불가능 | 가능, 아무 어려움 없이 |

:::tip 핵심 정리
무선은 **공유 매체**이다. WLAN에서 전송되는 모든 것은 범위 안의 모든 장치가 수신할 수 있다. 그래서 WLAN은 반드시 **암호화**해야 한다(오늘날에는 **WPA2** 또는 **WPA3**). 그러면 낯선 사람이 데이터를 수신하더라도 읽을 수는 없다.
:::

:::note
BeaverTracer는 WLAN 암호화를 시뮬레이션하지 않는다. 그래서 여기서는 모든 것을 읽을 수 있다. 암호화가 어떻게 동작하는지는 8장에서 배운다.
:::

:::quiz mc
카페에서 비밀번호 없는 개방형 WLAN을 사용하는 것이 왜 위험한가?
- [ ] 그러면 WLAN이 더 느려지기 때문이다
- [x] 근처에 있는 누구나 암호화되지 않고 전송되는 내용을 엿볼 수 있기 때문이다
- [ ] 액세스 포인트가 SSID를 표시할 수 없기 때문이다
:::
