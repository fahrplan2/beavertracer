# 문제 해결: 어제까지는 됐는데

:::sim
url=/sims/lesson-7.2.4.btsim
:::

어제는 Heim-Webserver에 외부에서 접속할 수 있었다. 포트 포워딩 `TCP 80 → 192.168.178.10:80`이 설정되어 있기 때문이다. 오늘 아침 정전이 난 뒤로 Clara가 해당 페이지에 접속하지 못한다. 오류를 찾아서 영구적으로 해결해 보자.

<details>
<summary>힌트 1: 규칙은 어디를 가리키고 있을까?</summary>

가정용 라우터의 **Port FW**에 있는 LAN IP와 **Heim-Webserver**가 지금 실제로 가지고 있는 주소를 비교해 보자 (:fa-gear: **IP 설정**).
</details>

<details>
<summary>힌트 2: 왜 다른 주소를 갖게 되었을까?</summary>

Heim-Webserver가 **DHCP**로 설정되어 있는가? 그렇다면 재시작할 때마다 가정용 라우터의 범위(**DHCP** 탭) 안에서 비어 있는 아무 주소나 받게 된다. 항상 같은 주소를 갖게 하려면 어떻게 해야 할까?
</details>

:::task
title: Heim-Webserver에 다시 접속할 수 있을까?
Heim-Webserver가 고정 주소를 가지고 있고 Clara가 포트 포워딩을 통해 접속할 수 있는지 확인한다. 이를 위해 시뮬레이션이 실행 모드로 동작 중이어야 한다.
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## 무슨 일이 있었을까?

:::quiz multi
어떤 설명이 맞을까?
- [x] Heim-Webserver는 DHCP로 주소를 받았고, 재시작 후 다른 주소를 갖게 되었다
- [x] 그래서 포트 포워딩은 더 이상 서버가 동작하지 않는 주소를 가리켰다
- [x] DHCP 범위 밖의 고정 주소를 사용하면 문제가 영구적으로 해결된다
- [ ] 통신사가 WAN 주소를 차단했다
:::

:::evaluate
답 확인
:::

:::tip 핵심 정리
**포트 포워딩**이 가리키는 장치(서버, 프린터, 카메라)에는 **고정 주소**가 필요하다. **DHCP 범위 밖**의 주소를 정적으로 직접 입력하거나, 라우터의 DHCP 서버에서 고정 할당으로 지정하면 된다. 그렇지 않으면 재시작 후 다른 주소를 받을 수 있고, 그러면 규칙이 아무 곳도 가리키지 못하게 된다.
:::
