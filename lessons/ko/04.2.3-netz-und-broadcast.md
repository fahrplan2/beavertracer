# 네트워크 주소, 브로드캐스트 주소와 호스트

모든 네트워크에서 두 주소는 특별한 역할을 한다:

- **네트워크 주소**는 네트워크에서 **가장 낮은** 주소다. 호스트 부분의 모든 비트가 0이다. 이 주소는 예를 들어 라우팅 테이블에서 네트워크 전체를 가리킨다.
- **브로드캐스트 주소**는 네트워크에서 **가장 높은** 주소다. 호스트 부분의 모든 비트가 1이다. 이 주소로 보낸 데이터는 네트워크의 모든 장치로 전달된다.

이 두 주소는 장치에 **할당하지 않는다**. 그 사이의 모든 주소는 장치(**호스트**)에 사용할 수 있다.

## 간단한 예

`192.168.0.12/24` — 호스트 부분은 마지막 옥텟이다:

| | 주소 |
|---|---|
| 네트워크 주소 (호스트 부분 = 0) | `192.168.0.0` |
| 브로드캐스트 주소 (호스트 부분 = 255) | `192.168.0.255` |
| 호스트용 범위 | `192.168.0.1` – `192.168.0.254` |
| 호스트 수 | 254 |

## 경계가 옥텟 중간에 있을 때

프리픽스 길이가 8의 배수가 아니면 더 어려워진다. 이럴 때는 해당 옥텟을 2진법으로 변환한다. 예: `194.9.190.12/27`.

앞의 세 옥텟은 모두 [[n|네트워크 부분]](24비트)에 속한다. 마지막 옥텟에서는 **3비트**가 아직 네트워크 부분에 속하고(24 + 3 = 27), 나머지 **5비트**는 [[h|호스트 부분]]에 속한다:

| | 마지막 옥텟 (2진수) | 10진수 |
|---|---|---|
| IP 주소 | [[n|000]][[h|01100]] | 12 |
| 넷마스크 (`/27`) | [[n|111]][[h|00000]] | 224 |
| 네트워크 주소: 호스트 비트를 0으로 | [[n|000]][[h|00000]] | **0** |
| 브로드캐스트 주소: 호스트 비트를 1로 | [[n|000]][[h|11111]] | **31** |

결과:

- 네트워크 주소: `194.9.190.0`
- 브로드캐스트 주소: `194.9.190.31`
- 호스트용 범위: `194.9.190.1` – `194.9.190.30`
- 호스트 수: 2⁵ − 2 = **30**

:::tip 핵심 정리
**네트워크 주소:** 모든 호스트 비트가 0 (가장 낮은 주소). **브로드캐스트 주소:** 모든 호스트 비트가 1 (가장 높은 주소). 두 주소는 장치에 할당하지 않는다. 프리픽스 길이가 *n*인 네트워크에는 호스트에 사용할 수 있는 주소가 **2<sup>32 − n</sup> − 2**개 있다.
:::

:::tip 팁: 블록 크기
2진법으로 푸는 방법을 이해했다면 지름길이 있다. **256에서 마스크 옥텟을 뺀 값**이 해당 옥텟에서 네트워크의 크기다. `/27`(마스크 224)에서는 256 − 224 = **32**다. 그러면 네트워크는 0, 32, 64, 96 … 에서 시작한다. 주소 `.12`는 `.0`에서 시작하는 네트워크에, 주소 `.70`은 `.64`에서 시작하는 네트워크에 속한다.
:::

## 가장 중요한 네트워크 크기

| 프리픽스 | 넷마스크 | 호스트 수 |
|---|---|---|
| `/8` | `255.0.0.0` | 16 777 214 |
| `/16` | `255.255.0.0` | 65 534 |
| `/24` | `255.255.255.0` | 254 |
| `/25` | `255.255.255.128` | 126 |
| `/26` | `255.255.255.192` | 62 |
| `/27` | `255.255.255.224` | 30 |
| `/28` | `255.255.255.240` | 14 |
| `/29` | `255.255.255.248` | 6 |
| `/30` | `255.255.255.252` | 2 |

:::note
실무에서 흔히 쓰는 가장 작은 네트워크는 `/30`이다. 사용할 수 있는 주소가 정확히 두 개이며, 라우터 두 대 사이의 연결에 자주 쓰인다. `/32`는 단일 주소를 뜻한다. 네트워크로는 사용할 수 없지만 라우팅 테이블과 방화벽 규칙에는 나온다.
:::
