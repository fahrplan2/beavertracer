# IPv6 주소 읽고 쓰기

## 16진수 체계

0과 1이 128개 늘어선 것은 아무도 읽을 수 없고, 10진수로 16개 그룹에 나누어 써도 크게 나아지지 않는다. 그래서 IPv6 주소는 **16진수**(줄여서 *Hex*)로 쓴다. 16진수에는 **16개의 숫자**가 있다. 0부터 9까지, 그리고 10부터 15까지의 값을 나타내는 a부터 f까지이다.

큰 장점이 있다. 16진수 숫자 하나는 정확히 **4비트**를 나타낸다.

| 10진수 | 16진수 | 2진수 | | 10진수 | 16진수 | 2진수 |
|---|---|---|---|---|---|---|
| 0 | 0 | 0000 | | 8 | 8 | 1000 |
| 1 | 1 | 0001 | | 9 | 9 | 1001 |
| 2 | 2 | 0010 | | 10 | a | 1010 |
| 3 | 3 | 0011 | | 11 | b | 1011 |
| 4 | 4 | 0100 | | 12 | c | 1100 |
| 5 | 5 | 0101 | | 13 | d | 1101 |
| 6 | 6 | 0110 | | 14 | e | 1110 |
| 7 | 7 | 0111 | | 15 | f | 1111 |

따라서 1바이트(8비트)는 정확히 16진수 숫자 두 개이다. `11111111` = `ff` = 255. 사실 이건 이미 알고 있을 거야. `aa:28:39:e2:41:82` 같은 MAC 주소도 16진수로 쓰여 있다.

## IPv6 주소의 구조

IPv6 주소는 각각 **16비트**, 즉 16진수 숫자 네 개로 이루어진 **여덟 개의 블록**으로 구성되며, 블록은 콜론으로 구분한다.

```
2001:0db8:0000:0000:0000:0000:0000:0001
```

IPv4와 마찬가지로 네트워크 부분과 호스트 부분이 있다. IPv6에서는 네트워크 부분을 **프리픽스**, 호스트 부분을 **인터페이스 ID**라고 부른다. 프리픽스는 거의 항상 **64비트**(`/64`) 길이이며, 앞의 네 블록이 여기에 해당한다.

## 축약 표기

IPv6 주소는 매우 길기 때문에 줄여서 쓸 수 있다. 여기에는 두 가지 규칙이 있다.

1. **블록 앞쪽의 0은 생략할 수 있다:** `0db8` → `db8`, `0001` → `1`, `0000` → `0`.
2. **연속된 0 블록의 나열**은 `::`로 바꿀 수 있다. 단, 주소 하나당 **딱 한 번**만 쓸 수 있다. 연속된 0 블록 나열이 여러 개라면 가장 긴 것을 줄인다.

예:

```
2001:0db8:0000:0000:0000:0000:0000:0001   vollständig
2001:db8:0:0:0:0:0:1                      Regel 1
2001:db8::1                               Regel 2
```

`::`를 왜 한 번만 쓸 수 있을까? `2001::1::5`에서는 어느 위치에 0 블록이 몇 개 빠졌는지 아무도 알 수 없다. `::`가 하나뿐이면 의미가 분명하다. 전체 블록이 다시 여덟 개가 되도록 필요한 만큼의 블록이 빠진 것이다.

:::tip 핵심 정리
**IPv6 주소**는 **128비트**이며, 각각 16진수 숫자 **4개**로 된 **8개의 블록**으로 쓴다. 앞의 64비트는 대개 **프리픽스**(네트워크 부분), 뒤의 64비트는 **인터페이스 ID**(호스트 부분)이다. 축약하려면 앞쪽의 0을 생략하고, 연속된 0 블록 **한 곳**을 `::`로 바꾼다.
:::
