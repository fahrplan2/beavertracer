# 순서 번호와 확인 응답 번호

:::sim
url=/sims/lesson-5.1.btsim
:::

TCP는 모든 데이터가 도착했는지, 그리고 어떤 순서로 도착했는지 어떻게 알까? 각 쪽은 자신이 보내는 **바이트에 번호를 매긴다**:

- **순서 번호**(`SEQ`)는 이 패킷에 들어 있는 첫 번째 바이트의 번호다.
- **확인 응답 번호**(`ACK`)는 이렇게 말한다: "여기까지는 모두 받았다 — 다음으로 기다리는 것은 ○번 바이트다."

여기에 규칙이 두 가지 더 있다. `SYN`과 `FIN`은 데이터를 담고 있지 않더라도 1바이트로 센다. 그리고 각 쪽은 자기 바이트만 센다 — 그래서 다이어그램에는 번호 체계가 두 개, 빨간색(클라이언트)과 파란색(서버)으로 나타난다.

## 직접 계산해 보기

앞에서 만든 연결을 다시 살펴보자. 선 위의 숫자는 그 시점에 해당 컴퓨터의 카운터 값을 보여 준다:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

빨간색 숫자를 차례대로 따라가 보자:

1. 클라이언트는 `SEQ=0`에서 시작한다. `SYN`이 번호 하나를 소비하므로 서버는 `ACK=1`로 확인 응답한다.
2. 메시지는 `SEQ=1`에서 시작하고 길이는 13바이트(1번부터 13번 바이트)다. 서버는 `ACK=14`로 확인 응답한다: "다음으로 14번 바이트를 기다린다."
3. 따라서 클라이언트의 `FIN`은 `SEQ=14`이고, `ACK=15`로 확인 응답된다.

서버의 파란색 숫자도 똑같은 방식으로 동작한다.

:::tip 핵심 정리
**순서 번호**(`SEQ`)는 패킷에 들어 있는 첫 번째 바이트의 번호다. **확인 응답 번호**(`ACK`)는 수신자가 다음에 기다리는 바이트의 번호이며, 그 앞의 바이트는 모두 도착했다는 뜻이다. 공식은 **ACK = SEQ + 길이**(받은 데이터의 길이)이고, `SYN`과 `FIN`은 1바이트로 센다. 각 쪽은 자신의 바이트를 센다.
:::

:::tip 직접 해 보기
**단순 TCP 클라이언트**로 연결을 다시 만들고 메시지를 연달아 두 개 보내 보자. **Info** 열에 어떤 `Seq`와 `Ack`가 나타날지 미리 예측해 보고, 추적에서 확인해 보자.
:::

## 연습

:::quiz short
클라이언트가 `Seq=1`, `Len=13`인 패킷을 보낸다. 서버는 어떤 확인 응답 번호를 돌려보낼까?
= 14
:::

:::quiz short
그 후 클라이언트가 다음 메시지를 보낸다. 이 메시지는 어떤 순서 번호로 시작할까?
= 14
:::

:::quiz short
`Seq=40`, `Len=25`인 패킷이 도착한다. 수신자는 어떤 확인 응답 번호를 보낼까?
= 65
:::

:::evaluate
답 확인
:::

빠진 번호를 채워 넣자. 클라이언트는 `Hallo`를 보내고 이어서 `Tschau`를 보낸다(각각 줄 끝 문자 포함):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
다이어그램 확인
:::

:::note
실제 네트워크에서는 카운트가 0에서 시작하지 않는다. 각 쪽은 0부터 약 43억 사이의 **무작위 시작 번호**(*Initial Sequence Number*, ISN)를 고른다. 가장 큰 번호에 도달하면 다시 0부터 이어진다. 트레이서는 시작 번호를 빼고 **상대** 번호를 보여 준다 — Wireshark와 똑같이. 그래서 `Seq=0`과 `Seq=1`이 보이는 것이다.

또한 모든 패킷에는 `Win=`이 들어 있다. 이것은 **윈도우 크기**로, 수신자가 현재 받아들일 수 있는 바이트 수를 뜻한다. 수신자는 이것으로 너무 빠른 송신자의 속도를 늦춘다(*흐름 제어*). BeaverTracer에서는 윈도우 크기가 항상 같다.
:::
