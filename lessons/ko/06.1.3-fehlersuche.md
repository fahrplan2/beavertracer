# 문제 해결: 연락처 페이지가 없어요

:::sim
url=/sims/lesson-6.1.3.btsim
:::

행정실에서 이렇게 알려 왔다. "우리 웹사이트에서 **Kontakt** 링크를 누르면 오류 메시지만 나와요." 연락처 페이지는 `http://192.168.0.20/kontakt.html`에서 접속할 수 있어야 한다. 오류를 찾아서 해결해 보자.

<details>
<summary>힌트 1: 서버는 뭐라고 응답할까?</summary>

**브라우저**에서 연락처 페이지를 열거나 `curl -v`로 호출해 봐. 어떤 상태 코드가 돌아오니? 오류 페이지에는 서버가 파일을 어디에서 찾았는지도 나와 있어.
</details>

<details>
<summary>힌트 2: 파일은 어디에 있을까?</summary>

웹 서버는 자신의 **문서 루트**(*Document Root*)에 있는 파일만 제공해. 이 값은 **HTTP 서버** 앱에서 확인할 수 있어. **Server**의 **터미널**에서 `ls`로 그곳에 무엇이 있는지 살펴보고, `/home`에서도 연락처 페이지를 찾아 봐.
</details>

<details>
<summary>힌트 3: 파일 옮기기</summary>

`mv`로 파일을 옮길 수 있어: `mv <원본> <대상 폴더>`.
</details>

:::task
title: 연락처 페이지를 고쳤을까?
연락처 페이지가 웹 서버의 문서 루트에 있는지 확인한다.
check: fileExists(2, "/var/www/kontakt.html")
:::

## 무슨 일이 있었을까?

:::quiz multi
맞는 설명을 모두 고르세요.
- [x] 서버가 `404 Not Found`로 응답했다
- [x] 파일이 문서 루트 `/var/www`가 아니라 `/home`에 있었다
- [ ] 웹 서버가 아예 시작되지 않았다
- [ ] 브라우저가 잘못된 IP 주소를 사용했다
:::

:::evaluate
답 확인
:::

:::tip 핵심 정리
**404**는 웹 서버가 실행 중이고 접속도 가능하지만, 요청한 **파일**이 해당 경로에는 없다는 뜻이다. 서버는 자신의 **문서 루트**(*Document Root*, 여기서는 `/var/www`)에서만 파일을 찾는다. 비교해 보자. 서버가 아예 응답하지 않거나 `RST`로 응답한다면 문제는 더 깊은 곳, 즉 네트워크나 서비스 자체에 있다(5.3.2장).
:::
