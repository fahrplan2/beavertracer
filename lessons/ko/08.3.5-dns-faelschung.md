# 공격: DNS 위조

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna는 **Client-PC**에서 **Biberbank**의 온라인 뱅킹을 열려고 한다. 그녀가 모르는 사실이 있다. 누군가 **DNS-Server**에 접근해 항목 하나를 변경해 놓았다.

작업 영역에는 진짜 웹 서버 **www.biberbank.de**와 **Angreifer**의 컴퓨터가 보인다. 이 컴퓨터에서는 은행 웹 페이지의 복사본이 실행되고 있다.

:fa-play: **실행** 모드로 전환하고 **Client-PC**의 :fa-globe: **브라우저**에서 `http://www.biberbank.de/`를 열어 봐.

- [ ] 페이지가 위조되었다는 경고
- [ ] 오류 메시지
:::

:::evaluate

:::

모든 것이 정상으로 보인다. 하지만 브라우저는 실제로 어떤 서버와 통신하고 있을까? Client-PC에서 :fa-terminal: **터미널**을 열어 봐.

```
$ nslookup www.biberbank.de
```

## 파트 2: HTTPS 사용

이번에는 `https://www.biberbank.de/`를 열어 봐.

:::quiz mc
어떤 일이 일어나니?
- [ ] 자물쇠 표시와 함께 위조된 페이지가 나타난다
- [x] 브라우저가 경고한다: 인증서가 다른 이름으로 발급되었다
- [ ] Biberbank의 진짜 페이지가 나타난다
:::

:::quiz short
공격자의 인증서는 어떤 이름으로 발급되어 있니? (`CN=`은 제외)
= www.biber-gewinnspiel.de
:::

:::evaluate
답 확인
:::

공격자는 신뢰할 수 있는 CA에서 발급한 **진짜** 인증서도 가지고 있다. 다만 자신의 도메인 `www.biber-gewinnspiel.de`용이다. `www.biberbank.de`용 인증서는 어떤 CA도 발급해 주지 않는다. 이 도메인은 공격자의 것이 아니기 때문이다. 그리고 Biberbank의 **개인 키**가 없으면 은행의 진짜 인증서도 사용할 수 없다. 핸드셰이크에서 Server Key Exchange에 그 키로 서명해야 하기 때문이다.

:::quiz multi
여기서 HTTPS는 무엇으로부터 보호해 주고, 무엇으로부터는 보호해 주지 못할까?
- [x] HTTPS는 서버가 진짜가 아니라는 사실을 드러낸다
- [ ] HTTPS는 DNS 서버가 위조되는 것을 막는다
- [x] HTTPS는 사용자가 경고를 진지하게 받아들일 때만 도움이 된다
- [ ] HTTPS를 사용하면 위조된 페이지에는 아예 접속할 수 없다
:::

:::evaluate
답 확인
:::

## 파트 3: DNS 서버 복구하기

**DNS-Server**를 열고 `www.biberbank.de`의 항목을 수정해 봐. 올바른 주소는 웹 서버 **www.biberbank.de**의 :fa-gear: **IP 설정**에서 찾을 수 있다. **저장**을 클릭하는 것을 잊지 마.

:::note
Client-PC는 DNS 응답을 한동안 기억해 두어, 접속할 때마다 새로 묻지 않아도 되게 한다(**DNS 캐시**). 얼마나 오래 기억하는지는 **TTL**(*Time to Live*) 열에 초 단위로 적혀 있다. 수정 직후에도 `nslookup`이 여전히 이전 주소를 알려 주면 TTL이 지날 때까지 기다린 후 다시 시도해 봐.
:::

:::task
title: Biberbank가 다시 진짜가 되었을까?
Client-PC가 www.biberbank.de를 올바른 주소로 변환하고 HTTPS로 경고 없이 페이지를 가져올 수 있는지 확인한다.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
실제로 공격자가 DNS 서버 자체를 위조하는 경우는 드물다. 더 흔한 방법은 공용 WLAN에서 자신의 응답을 끼워 넣거나, 가정용 라우터의 설정을 변경하거나, `www.biberbank-login.de`처럼 비슷해 보이는 주소로 유인하는 것이다(**피싱**). 비슷하게 들리는 이름에는 HTTPS도 도움이 되지 않는다. 공격자가 그 이름으로는 유효한 인증서를 받을 수 있기 때문이다. 그러니 주소를 꼼꼼히 읽어야 한다!
:::

:::tip 핵심 정리
**DNS 위조**에서는 DNS 서버가 어떤 이름에 대해 공격자의 주소를 알려 준다. **HTTP**에서는 이를 전혀 알아챌 수 없다. **HTTPS**에서는 공격자의 인증서가 요청한 이름과 맞지 않아 브라우저가 **경고**한다. 어떤 CA도 남의 도메인에 대한 인증서를 발급하지 않고, 공격자에게는 진짜 서버의 개인 키도 없기 때문이다.
:::
