# HTTPS

:::osi 5
:::

**HTTPS**(*HTTP Secure*)는 평범한 HTTP와 같다. 다만 TCP 위에서 곧바로 동작하지 않고, 그 사이에 있는 암호화 계층인 **TLS**(*Transport Layer Security*)를 거친다는 점이 다르다. TLS의 前身은 **SSL**이었고, 그래서 지금도 흔히 "SSL 인증서"라고 부른다.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP는 이 과정을 전혀 알아채지 못한다. HTTP는 평소처럼 요청을 보내고, TLS가 그것을 암호화하며, TCP가 전송한다. OSI 모델에서 TLS는 전송 계층과 응용 계층 사이, 즉 4/5 계층에 위치한다. TLS는 TCP를 기반으로 동작하며 보안이 적용된 세션을 관리한다.

| | HTTP | HTTPS |
|---|---|---|
| 포트 | 80 | **443** |
| 주소 | `http://…` | `https://…` |
| 트레이서에서 내용을 읽을 수 있는가? | 예 | 아니요 |
| 브라우저 표시 | "안전하지 않음" | 자물쇠 |

TLS는 연결 설정 과정에서 이 장에서 배운 모든 것을 처리한다.

- 서버는 자신의 **인증서**로 신원을 증명한다(**인증성**).
- 양쪽은 **디피-헬만**으로 **세션 키**를 협상한다. 이때 서버는 자신의 몫에 **서명**한다.
- 그 후 모든 데이터는 **AES**로 암호화되고(**기밀성**) 변조로부터 보호된다(**무결성**).

이 원리는 웹에만 국한되지 않는다. 이메일(8.4절)과 그 밖의 많은 프로토콜도 같은 방식으로 TLS를 거쳐 동작한다.

이어지는 절에서는 트레이서에서 HTTPS를 관찰하고, 직접 설정해 보며, 브라우저가 언제 그리고 왜 경고를 표시하는지 알아본다.
