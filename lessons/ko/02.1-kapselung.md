## 계층별로 펼쳐 보기

**Ethernet**, **Internet Protocol Version 4**, **Transmission Control Protocol**, **Hypertext Transfer Protocol** 앞에 있는 작은 삼각형을 각각 클릭한다. 각 계층에는 저마다 고유한 정보가 들어 있다.

| 트리의 계층 | 그 안에서 볼 수 있는 것 | 용도 |
|---|---|---|
| Ethernet | `Source`와 `Destination`: `aa:57:28:…` 같은 MAC 주소 | 로컬 네트워크에서 어느 네트워크 카드인지 |
| IPv4 | `Source Address` `192.168.0.10`, `Destination Address` `192.168.0.20` | 어느 컴퓨터인지 — 네트워크 경계를 넘어서도 |
| TCP | `Source Port` `49152`, `Destination Port` `80` | 컴퓨터의 어느 프로그램인지 |
| HTTP | `GET / HTTP/1.1`, `Host: 192.168.0.20` | 브라우저가 보내는 실제 메시지 |

다음 두 줄도 살펴보자. Ethernet에는 `Type: IPv4`가, IPv4에는 `Protocol: TCP`가 적혀 있다. 즉 각 계층은 *자기 안에 무엇이 들어 있는지*를 알려 준다. 그래서 수신자는 계속 어떻게 풀어야 하는지 알 수 있다.

## 봉투 속의 봉투

방금 본 구조는 송신자에서 다음과 같이 만들어진다.

1. 브라우저가 실제 메시지 `GET / HTTP/1.1`을 작성한다(**HTTP**).
2. **TCP**가 이를 감싸고 앞에 포트를 붙인다. 올바른 프로그램에 도착하도록 하기 위해서다.
3. **IP**가 전체를 다시 감싸고 앞에 IP 주소를 붙인다. 올바른 컴퓨터에 도착하도록 하기 위해서다.
4. **Ethernet**이 모든 것을 MAC 주소가 담긴 프레임에 넣는다. 로컬 네트워크에서 올바른 네트워크 카드에 도착하도록 하기 위해서다.

수신자에서는 정확히 반대로 진행된다. 각 계층이 자기 몫의 헤더를 떼어 내고 나머지를 위 계층으로 넘긴다. 마치 편지를 여러 겹의 봉투에 넣는 것과 같다. 가장 안쪽에는 메시지가 있고, 각 봉투 겉면에는 그 봉투를 다음으로 열 사람의 주소가 적혀 있다.

:::tip 핵심 정리
각 계층은 자신의 제어 정보인 **헤더**를 바로 위 계층의 데이터 앞에 붙인다. 이렇게 싸고 푸는 과정을 **캡슐화**라고 한다.
:::

계층에 따라 이 "꾸러미"는 저마다 다른 이름을 가진다.

| 계층 | 예시의 프로토콜 | 데이터 단위의 이름 |
|---|---|---|
| 2계층 | Ethernet | **프레임** (Frame) |
| 3계층 | IPv4 | **패킷** |
| 4계층 | TCP | **세그먼트** (Segment) |

:::note
일상에서는, 그리고 이 강의에서도, 어느 계층이든 흔히 그냥 "패킷"이라고 부른다. 정확한 구분이 필요할 때는 표에 나온 이름을 사용한다.
:::

:::quiz fill
송신자에서 각 계층은 바로 위 계층의 데이터를 감싸고 그 앞에 {헤더}를 붙인다. 이 원리를 {캡슐화}라고 한다. 2계층에서 데이터 단위는 {프레임}이라고 하고, 4계층의 TCP에서는 {세그먼트}라고 한다.
