## 요청은 어떻게 생겼을까

트레이스에서 `GET / HTTP/1.1` 패킷을 클릭하고 **Hypertext Transfer Protocol**을 펼쳐 봐. HTTP 요청은 순수한 텍스트야:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

서버의 응답도 똑같은 구조로 되어 있어. 상태 줄, 헤더, 빈 줄, 그리고 그다음에 실제 파일이 온다:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP-Anfrage
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP-Anfrage
Server -> Client-PC: 200 OK | style.css
:::

## 메서드와 상태 코드

**메서드**는 클라이언트가 무엇을 원하는지 알려 줘:

| 메서드 | 의미 |
|---|---|
| **GET** | 파일을 가져온다 |
| **POST** | 서버로 데이터를 보낸다. 예: 작성한 양식 |
| **HEAD** | 파일 없이 헤더만 가져온다 |

**상태 코드**는 처리가 어떻게 되었는지 알려 줘. 첫 번째 숫자가 응답의 종류를 나타내:

| 코드 | 텍스트 | 의미 |
|---|---|---|
| **200** | OK | 모두 정상 |
| **301** | Moved Permanently | 페이지가 영구적으로 이동했다 |
| **404** | Not Found | 해당 파일이 없다 |
| **405** | Method Not Allowed | 여기서는 이 메서드가 허용되지 않는다 |
| **500** | Internal Server Error | 서버에서 오류가 발생했다 |

`2xx`는 성공, `3xx`는 리디렉션, `4xx`는 클라이언트의 오류(잘못된 요청), `5xx`는 서버의 오류를 뜻해.

:::tip 핵심 정리
**HTTP**는 **요청-응답 원칙**으로 동작해. 클라이언트가 **요청**(`GET` 같은 메서드, 경로, 헤더)을 보내면, 서버는 **상태 코드**(예: `200 OK`, `404 Not Found`), 헤더, 그리고 파일로 응답해. 웹 페이지의 파일마다 각각 별도의 요청이 있어.
:::

:::quiz match
200 -> 모두 정상
301 -> 페이지가 영구적으로 이동했다
404 -> 요청한 파일이 없다
500 -> 서버에서 오류가 발생했다
:::
