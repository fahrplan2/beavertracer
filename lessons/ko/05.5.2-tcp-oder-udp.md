# TCP와 UDP, 무엇을 쓸까?

| | TCP | UDP |
|---|---|---|
| 연결 | 3-way 핸드셰이크로 연결 설정, 순차적인 연결 종료 | 없음 — 각 데이터그램은 독립적임 |
| 확인 응답 | 있음 (`ACK`) | 없음 |
| 손실된 데이터 | 다시 전송됨 | 손실된 채로 남음 |
| 순서 | 복원됨 | 보장되지 않음 |
| 헤더 | 최소 20바이트 | 8바이트 |
| 속도 | 다소 느림, 패킷이 더 많음 | 빠름, 부담이 적음 |

언제 적은 것이 더 나을까?

- **실시간:** 화상 통화, 인터넷 전화, 온라인 게임에서는 1밀리초가 중요하다. 1초 뒤에 뒤늦게 도착한 음성 조각은 아무에게도 쓸모가 없다. 지연되는 것보다 잠깐 잡음이 나는 편이 낫다.
- **짧은 요청:** **DNS** 요청("`www.beispiel.de`의 IP 주소는 무엇인가?")은 데이터그램 하나에 들어가고, 응답도 마찬가지다. 연결 설정을 하면 작업량이 세 배로 늘어난다. 응답이 오지 않으면 프로그램은 그냥 한 번 더 요청한다.

반면 웹 페이지, 이메일, 다운로드처럼 모든 바이트가 도착해야 하는 곳에는 TCP가 올바른 선택이다.

:::tip 핵심 정리
**TCP**는 신뢰할 수 있지만 부담이 더 크다 — **완전하게** 도착해야 하는 모든 것(웹, 이메일, 파일)에 사용한다. **UDP**는 빠르고 가볍지만 보장이 없다 — **실시간**(전화, 영상, 게임)과 DNS 같은 **짧은 요청**에 사용한다.
:::
