# 观察 UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

这次 **Server** 上在端口 `5000` 运行着一个 **UDP 回显服务器**。这里的线缆同样被动过手脚：从 Client-PC 发往 Server 的**第二个数据报**会丢失。

## 实验

1. 切换到 :fa-play: **运行**模式，在 **Client-PC** 上打开 :fa-terminal: **终端**。
2. 用 `nc` 向服务器发起一个 UDP“连接”（`-u` 表示 UDP）：
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. 依次输入 `eins`、`zwei` 和 `drei`，每次都按 **Enter**。每返回一行，就是服务器的一次回显。
4. 等待几秒钟，然后在 :fa-magnifying-glass: **追踪**模式下为 **Client-PC** 打开一个追踪。

:::quiz mc
哪些回显会返回？
- [ ] 三个都会返回，`zwei` 稍晚一些
- [x] 只有 `eins` 和 `drei` — `zwei` 缺失，而且不会被重新发送
- [ ] 一个也没有
:::

:::quiz multi
你在 TCP 中见过的哪些数据包在 UDP 中完全没有？
- [x] 连接建立（`SYN`）
- [x] 确认（`ACK`）
- [x] 连接断开（`FIN`）
- [ ] 带有端口号的数据包
:::

:::evaluate
检查答案
:::

点击其中一个 UDP 数据包，展开 **User Datagram Protocol**。与 TCP 首部相比，UDP 首部非常小：**Source Port**、**Destination Port**、**Length**（长度）和 **Checksum**（校验和）——加起来只有 8 字节。TCP 首部至少有 20 字节，包含序列号和确认号、标志位以及窗口大小。

:::quiz mc
UDP 仍然完成了 5.1 节中的哪项任务？
- [x] 多路复用 — 通过端口
- [ ] 连接建立
- [ ] 可靠传输
:::

:::evaluate
检查答案
:::

:::tip 要点
**UDP** 是**无连接**的：没有建立、没有确认、没有重传、没有顺序保证。它只提供**端口**（多路复用）和**校验和**。作为回报，它快速而精简——UDP 首部只有 8 字节。数据报一旦丢失，就得由程序自己处理——或者程序根本不在乎。
:::
