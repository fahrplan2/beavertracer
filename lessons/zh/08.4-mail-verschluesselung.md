# 加密传输电子邮件

:::sim
url=/sims/lesson-8.4.btsim
:::

在 6.3.2 节中你已经看到，使用 SMTP 和 POP3 时，发送方、接收方、内容甚至密码都是以明文形式在线路上传输的。用 TLS 可以像保护 HTTP 一样保护这些数据。电子邮件有两种方式：

| | **隐式 TLS** | **STARTTLS** |
|---|---|---|
| 流程 | 连接从一开始就是加密的。 | 连接开始时未加密；客户端发送命令 `STARTTLS`，之后才进行加密。 |
| 端口 | 专用端口：**SMTPS 465**、**POP3S 995**、**IMAPS 993** | 常规端口，例如 SMTP 25 或 587 |

SMTPS、POP3S 和 IMAPS 中的“S”与 HTTPS 一样，代表 *Secure*（安全）。

## 切换到加密端口

在 Anna 的邮件程序中打开**设置**：

- **接收：** 端口 `995`，并勾选 **TLS**
- **发送（SMTP）：** 端口 `465`，加密方式选择**隐式 TLS**

保存，再发送一封邮件，然后再次获取。查看追踪（过滤器 `tls`）。

## 传输加密无法保护什么

TLS 只加密两台计算机之间的**传输路径**：从 Anna 到邮件服务器，以及——如果两个邮件服务器都支持——从邮件服务器到邮件服务器。但邮件在**邮件服务器上**本身是以明文存放的。能访问邮件服务器的人可以读取其上的所有邮件。

如果只希望接收方能读到邮件，就必须进行**端到端**加密：发送方用接收方的公钥加密，只有接收方才能再将其解密。电子邮件有 **S/MIME** 和 **OpenPGP** 这两种方法；Signal 或 WhatsApp 等即时通讯软件会自动完成这一过程。

:::tip 要点
电子邮件通过 **TLS** 加密传输——要么在专用端口上使用**隐式 TLS**（**SMTPS 465**、**POP3S 995**、**IMAPS 993**），要么在常规端口上使用 **STARTTLS**。这就是**传输加密**：它保护传输路径，但不保护服务器上的邮件。为此需要**端到端加密**。
:::
