# 攻击：DNS 伪造

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna 想在**Client-PC**上打开她在**Biberbank**的网上银行。她不知道的是：有人入侵了**DNS-Server**，并篡改了其中的一条记录。

在工作区中，你可以看到真正的 Web 服务器 **www.biberbank.de** 和一台**攻击者**的计算机。攻击者的计算机上运行着一份银行网页的副本。

## 第 1 部分：没有加密

切换到 :fa-play: **运行**模式，在**Client-PC**的 :fa-globe: **浏览器**中访问 `http://www.biberbank.de/`。

:::quiz mc
你看到了什么？
- [x] Biberbank 的登录页面，没有任何警告
- [ ] 提示该网页是伪造的警告
- [ ] 一条错误信息
:::

:::evaluate
检查答案
:::

一切看起来都很正常。但浏览器实际上是在和哪台服务器通信呢？在 Client-PC 上打开 :fa-terminal: **终端**：

```
$ nslookup www.biberbank.de
```

:::quiz short
DNS 服务器为 `www.biberbank.de` 返回了哪个 IP 地址？
= 192.168.0.66
:::

:::quiz mc
这个地址属于谁？（在编辑模式下点击这些设备，或查看它们的 :fa-gear: **IP设置**。）
- [ ] Biberbank 真正的 Web 服务器
- [x] 攻击者
- [ ] DNS 服务器
:::

:::evaluate
检查答案
:::

如果 Anna 此时输入了账号和 PIN，它们会直接落到攻击者手中。使用 **HTTP** 时，她**根本没有机会**发现这场骗局：地址栏显示的是正确的名称，网页看起来也很真实。

## 第 2 部分：使用 HTTPS

现在访问 `https://www.biberbank.de/`。

:::quiz mc
会发生什么？
- [ ] 伪造的网页出现，并带有锁形图标
- [x] 浏览器发出警告：该证书是为另一个名称签发的
- [ ] Biberbank 的真实网页出现
:::

:::quiz short
攻击者的证书是为哪个名称签发的（不含 `CN=`）？
= www.biber-gewinnspiel.de
:::

:::evaluate
检查答案
:::

攻击者甚至拥有一份来自受信任 CA 的**真实**证书——不过是为他自己的域名 `www.biber-gewinnspiel.de` 签发的。任何 CA 都不会为他签发 `www.biberbank.de` 的证书，因为这个域名不属于他。而没有 Biberbank 的**私钥**，他也无法使用银行的真实证书：在握手过程中，他必须用私钥对 Server Key Exchange 进行签名。

:::quiz multi
在这里，HTTPS 能防范什么——又不能防范什么？
- [x] HTTPS 能揭示出该服务器不是真正的服务器
- [ ] HTTPS 能防止 DNS 服务器被伪造
- [x] 只有当用户认真对待警告时，HTTPS 才有帮助
- [ ] 使用 HTTPS 时，根本无法访问伪造的网页
:::

:::evaluate
检查答案
:::

## 第 3 部分：修复 DNS 服务器

打开 **DNS-Server**，修正 `www.biberbank.de` 的记录。正确的地址可以在 Web 服务器 **www.biberbank.de** 的 :fa-gear: **IP设置**中找到。别忘了点击**保存**。

:::note
Client-PC 会将 DNS 应答缓存一段时间，这样就不必每次访问都重新查询（**DNS 缓存**）。缓存多长时间，由 **TTL**（*Time to Live*）一列以秒为单位给出。如果在你修正之后，`nslookup` 仍然返回旧地址，请等待 TTL 过期后再试一次。
:::

:::task
title: Biberbank 恢复正常了吗？
检查 Client-PC 是否将 www.biberbank.de 解析为正确的地址，并且能通过 HTTPS 无警告地获取该网页。
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
在现实中，攻击者很少直接伪造 DNS 服务器本身。更常见的做法是：在公共 WLAN 中塞入他的应答、修改家用路由器的设置，或者用一个外观相似的地址（如 `www.biberbank-login.de`）进行诱骗（**网络钓鱼**）。面对听起来相似的名称，HTTPS 也无能为力——攻击者可以为它获得有效的证书。因此：一定要仔细阅读地址！
:::

:::tip 要点
发生 **DNS 伪造**时，DNS 服务器会为某个名称返回攻击者的地址。使用 **HTTP** 时，人们对此毫无察觉。使用 **HTTPS** 时，攻击者的证书与所访问的名称不匹配，浏览器会**发出警告**——因为任何 CA 都不会为他人的域名签发证书，而攻击者也没有真实服务器的私钥。
:::
