还是刚才那个环形网络——不过这次你要先启用**生成树协议**（**STP**）。

## 启用 STP

在**所有三台**交换机上都这样操作：

1. 切换到 :fa-play: **运行**模式，然后点击该交换机。
2. 打开 **STP** 标签页，在模式中选择 **STP (802.1D)**。

然后等待大约 **15 秒**。在这段时间里，交换机会互相交换一些小消息（即 *BPDU*），并就一个共同的结构达成一致。

## 交换机协商的结果

在每台交换机上打开 **STP** 标签页，看一下表格：每个已连接的端口都有一个 **State**（状态）。

现在从 **Anna** 去 ping Ben（`ping 192.168.0.11`）：这次 ping 能够到达，而且不再有任何数据在环中循环。

STP 选了一台交换机作为根，并以它为起点构建出一棵**树**：到每台交换机都恰好只有一条路径。会形成环路的那一条连接被**阻塞**了——网线仍然插着，但交换机不会通过它发送正常的帧。

## 如果一根网线断了呢？

1. 切换到 :fa-pencil: **编辑**模式，选择 :fa-ban: **删除**工具，然后点击 **Switch A** 和 **Switch B** 之间的网线。
2. 切换回 :fa-play: **运行**模式，再等待大约 15 秒。
3. 查看 **Switch B** 的 **STP** 标签页，然后再从 Anna 去 ping 一次 Ben。

:::quiz mc

- [ ] 现在无法再访问 Ben 了
- [x] Switch B 之前被阻塞的端口现在开始转发——ping 数据包绕道经过 Switch C
- [ ] Switch B 现在成了 Root
:::

检查答案
:::

:::tip 要点
**生成树协议**（**STP**）用来防止交换机之间出现环路：交换机选出一个**根网桥**（Root Bridge），并**阻塞**个别端口，使得到每台交换机都恰好只有一条路径。如果某条连接中断，STP 会重新放行一个被阻塞的端口——这样即使出现故障，网络仍然可以访问。
:::

## 展望：STP 还能做什么

你在这里看到的只是基本原理。在真实网络中，背后还有更多内容：

- **不同的变种：**除了经典的 STP，还有改进后的协议，例如 **RSTP**（*Rapid* STP，快速生成树），它在故障后能更快恢复可用；以及 **MSTP**（*Multiple* STP，多生成树）。
- **STP 与 VLAN：**如果交换机上运行了多个 VLAN，还必须额外规定如何为各个 VLAN 构建树——为此有专门的方法和设置。
- **根网桥的选举：**哪台交换机成为根，遵循一套专门的、严格规定的流程。在这个例子中，我们事先做了设置，使 Switch A 总是胜出。

:::note
这些主题超出了本课程的范围——重要的只有一点：要在真实网络中配置 STP，需要的知识远多于本节所讲的内容。
:::
