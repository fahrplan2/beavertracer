## 实验

1. 切换到 :fa-play: **运行**模式。
2. 在 **Client-PC** 上打开 :fa-globe: **浏览器**，访问 `http://192.168.0.20/`。
3. 切换到 :fa-magnifying-glass: **追踪**模式，点击 **+** 为 **Client-PC** 的 `eth0` 接口打开一个跟踪。
4. 点击 Info 列中带有 `GET` 的数据包，并查看其下方的协议树。

:::note
最上面一行 **Frame** 只包含抓包记录的相关信息（大小、时间），本身并不是一个协议。在它下面，协议树自上而下依次是：**Ethernet**，其下是 **IPv4**，再下是 **TCP**，最底部是 **HTTP**。右边缘的彩色数字你在第 1 章已经见过了——它们的含义会在下一页讲解。

## 逐层展开

点击 **Ethernet**、**Internet Protocol Version 4**、**Transmission Control Protocol** 和 **Hypertext Transfer Protocol** 前面的小三角。每一层都带有各自的信息：

| 树中的层 | 你能在其中找到什么 | 作用 |
|---|---|---|
| Ethernet | `Source` 和 `Destination`：MAC 地址，如 `aa:57:28:…` | 指明本地网络中的哪块网卡 |
| IPv4 | `Source Address` `192.168.0.10`，`Destination Address` `192.168.0.20` | 指明哪台计算机——即使跨越网络边界也适用 |
| TCP | `Source Port` `49152`，`Destination Port` `80` | 指明计算机上的哪个程序 |
| HTTP | `GET / HTTP/1.1`，`Host: 192.168.0.20` | 浏览器真正要传达的消息 |

再看一下这两行：在 Ethernet 中是 `Type: IPv4`，在 IPv4 中是 `Protocol: TCP`。也就是说，每一层都会说明*自己里面装的是什么*——接收方就是这样知道该如何继续拆包的。

## 信封里的信封

你刚才看到的内容，在发送方是这样生成的：

1. 浏览器写出真正的消息：`GET / HTTP/1.1`（**HTTP**）。
2. **TCP** 把它封装起来，并在前面加上端口——这样它就能到达正确的程序。
3. **IP** 把整体再封装一层，并在前面加上 IP 地址——这样它就能到达正确的计算机。
4. **Ethernet** 把所有内容放进一个带有 MAC 地址的帧中——这样它就能在本地网络中到达正确的网卡。

在接收方，过程则完全相反：每一层取走属于自己的部分，并把剩下的部分向上层传递。这就像一封信被装进了好几层信封：消息在最里面，每个信封的外面写着下一个拆开它的人的地址。

:::tip 要点
每一层都会把自己的控制信息——**首部**（Header）——加在上一层数据的前面。这种一层层的打包与拆包称为**封装**。
:::

根据所在的层不同，这个“包裹”有各自的名称：

| 层 | 示例中的协议 | 数据单元的名称 |
|---|---|---|
| 第 2 层 | Ethernet | **帧**（Frame） |
| 第 3 层 | IPv4 | **数据包** |
| 第 4 层 | TCP | **段**（Segment） |

:::note
在日常交流中——在本课程中也是如此——人们常常不区分所在的层，统称为“数据包”。当需要精确表达时，请使用表格中的名称。
:::

:::quiz fill
在发送方，每一层都会把上一层的数据封装起来，并在前面加上{首部}。这一原理称为{封装}。在第 2 层，数据单元称为{帧}，在第 4 层的 TCP 中称为{段}。
:::
