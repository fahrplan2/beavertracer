# 序列号和确认号

:::sim
url=/sims/lesson-5.1.btsim
:::

TCP 怎么知道所有数据是否都已到达,以及到达的顺序?双方各自**给自己发送的字节编号**:

- **序列号**(`SEQ`)是这个数据包中第一个字节的编号。
- **确认号**(`ACK`)表示:“到这里为止的数据我都收到了——接下来我期待第 … 号字节。”

另外还有两条规则:`SYN` 和 `FIN` 虽然不携带数据,但各算作一个字节。并且每一方只为自己计数——因此有两套编号,在图中分别用红色(客户端)和蓝色(服务器)表示。

## 动手计算

这是你之前建立的那条连接。线上的数字显示的是该计算机在这一时刻的计数器:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

来看一下红色的数字序列:

1. 客户端从 `SEQ=0` 开始。它的 `SYN` 占用一个编号——服务器用 `ACK=1` 进行确认。
2. 消息从 `SEQ=1` 开始,长度为 13 字节(第 1 到第 13 字节)。服务器用 `ACK=14` 确认:“接下来我期待第 14 号字节。”
3. 因此客户端的 `FIN` 的 `SEQ=14`,并由 `ACK=15` 确认。

服务器的蓝色序列的工作方式完全相同。

:::tip 要点
**序列号**(`SEQ`)是数据包中第一个字节的编号。**确认号**(`ACK`)是接收方期待收到的下一个字节的编号——在它之前的所有数据都已到达。规则是:**ACK = SEQ + 所收到数据的长度**;`SYN` 和 `FIN` 各算作一个字节。每一方只计算自己的字节。
:::

:::tip 试一试
在**简单 TCP 客户端**中再建立一次连接,并连续发送两条消息。先预测 **Info** 列中会显示哪些 `Seq` 和 `Ack`——然后在追踪中核对。
:::

:::note
在真实网络中,计数并不是从 0 开始的:每一方都会在 0 到大约 43 亿之间选择一个**随机起始编号**(*Initial Sequence Number*,ISN)。达到最大编号后,会重新从 0 继续。追踪器会减去起始编号,显示**相对**编号——和 Wireshark 完全一样。所以你看到的是 `Seq=0` 和 `Seq=1`。

此外,每个数据包中还有 `Win=`——即**窗口大小**:表示接收方当前能够接收多少字节。接收方借此让发送过快的发送方放慢速度(*流量控制*)。在 BeaverTracer 中,窗口大小始终保持不变。
:::
