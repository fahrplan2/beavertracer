# 故障排查：回程路由

:::sim
url=/sims/lesson-4.5.3.btsim
:::

拓扑与刚才相同：Firma A — Router A — Zwischennetz — Router B — Firma B。管理员已经在 **Router A** 上添加了通往 Firma B 的路由（`172.16.0.0/24` 经由 `10.0.0.2`）。可是 Anna 仍然反馈：Clara 没有响应。

找出故障并修复它。

<details>
<summary>提示 1：Anna 的 ping 到底有没有到达？</summary>

从 Anna 去 ping Clara，并为 **Clara** 打开一个追踪。ping 有没有到达她那里？她有没有回应？
</details>

<details>
<summary>提示 2：traceroute 能走多远？</summary>

在 Anna 上输入 `traceroute 172.16.0.10`。回应一直到哪个路由器为止还能返回？而 Clara 发给 Anna 的回应应该由哪个路由器转发？
</details>

<details>
<summary>提示 3：谁认识哪个网络？</summary>

查看 **Router B** 的路由表。它知道发往 `192.168.0.0/24` 的数据包该往哪里走吗？
</details>

:::task
title: 连接修复了吗？
检查 Router B 是否知道通往 Firma A 的路径，以及 Anna 是否能访问 Clara。为此，仿真必须处于运行模式。
check: hasRoute(5, "192.168.0.0/24")
check: pingOk(9, 11)
:::

## 问题出在哪里？

:::quiz multi
你在故障排查中观察到了什么？
- [x] Anna 的 ping 到达了 Clara，并且 Clara 做出了回应
- [x] 回应卡在了 Router B，因为它不认识 Firma A
- [ ] Router A 丢弃了 Anna 的 ping
- [x] 经过 Router A 之后，`traceroute` 只显示 `*`，尽管去程是通的
:::

:::evaluate
检查答案
:::

:::tip 要点
每一次通信都需要**去程和回程**：路径上的每个路由器都必须知道*两个*网络——目的网络和发送方所在的网络。缺少**回程路由**是最常见的路由故障之一。注意：`traceroute` 只能显示从哪里开始不再有回应返回——故障也可能出在回程上。
:::
