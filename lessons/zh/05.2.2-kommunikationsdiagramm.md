# 通信时序图

:::sim
url=/sims/lesson-5.1.btsim
:::

一次连接的过程可以画成**时序图**：客户端和服务器各有一条竖线，时间从上往下流逝。每个箭头代表一个数据包。箭头画成斜线，是因为每个数据包在传输途中都需要一点时间。

下面是你在上一页建立的那次连接——请把它与追踪结果逐行对照：

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

每个箭头上方是**标志位**，下方是序号 `SEQ` 和 `ACK`。**DATA** 标记带有有效载荷的数据包。红色数字属于客户端，蓝色数字属于服务器——它们的含义将在下一页讲解。

## 标志位

| 标志位 | 全称 | 含义 |
|---|---|---|
| **SYN** | *synchronize* | 建立连接，确定起始序号 |
| **ACK** | *acknowledge* | 确认已收到的数据 |
| **PSH** | *push* | 立即把数据交给应用程序 |
| **FIN** | *finish* | “我已经发完了”——拆除连接 |
| **RST** | *reset* | 中止或拒绝连接（详见 5.3.2） |

## 三个阶段

**建立：**客户端发送 `SYN`，服务器用 `SYN, ACK` 回应，客户端再用 `ACK` 确认。因为恰好需要三个数据包，所以称为**三次握手**。

**数据：**接收方对每个带数据的数据包都用一个 `ACK` 来确认。这里服务器把回显内容发回——客户端同样会对其进行确认。

**拆除：**双方各自单独结束自己的发送方向：先是客户端发 `FIN`、服务器回 `ACK`，然后服务器发 `FIN`、客户端回 `ACK`。一共是四个数据包。

:::tip 要点
一次 TCP 连接分为三个阶段：通过**三次握手**（`SYN` → `SYN, ACK` → `ACK`）进行**建立**，**数据传输**（每个数据包都用 `ACK` 确认），以及**拆除**（双方各发送一个 `FIN` 并收到一个 `ACK`）。
:::
