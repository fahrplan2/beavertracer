# 在追踪器中查看电子邮件

:::sim
url=/sims/lesson-6.3.btsim
:::

和 HTTP 一样，SMTP 也是一种**文本协议**。来看看线路上究竟有哪些内容是以明文传输的。

## 实验

1. 在 :fa-play: **运行**模式下，像上一页那样，从 **Anna** 向 `ben@biber-mail.de` 发送一封邮件。
2. 在 :fa-magnifying-glass: **追踪**模式下，为 **Anna** 打开一个追踪。在 **Info** 列中可以看到 SMTP 对话：以 `C:` 开头的行由客户端发送，以 `S:` 开头的行由服务器发送。

:::quiz short
`MAIL FROM:` 后面是哪个地址？
= anna@beaver-schule.de
= <anna@beaver-schule.de>
:::

:::quiz short
那么 `RCPT TO:` 后面是哪个地址？
= ben@biber-mail.de
= <ben@biber-mail.de>
:::

:::quiz mc
服务器接受一条命令时，会发送哪个数字代码？
- [x] `250`
- [ ] `200`
- [ ] `404`
:::

:::evaluate
检查答案
:::

## 那密码呢？

在 `MAIL FROM` 之前，Anna 的程序会用 `AUTH PLAIN` 和一串类似 `AGFubmEAZ2VoZWlt` 的字符进行登录。这看起来像是加密过的，但其实不是：它只是 **Base64**，一种任何人都能立刻还原的编码——里面包含 `anna` 和她的密码 `geheim`。

现在到 **Ben** 那里收取邮件（**获取**），并为 **Ben** 打开一个追踪。通过 IMAP 收取邮件时，内容暴露得更加明显：

:::quiz short
Ben 的邮件程序以明文向服务器发送了哪个密码？（看一下带有 `LOGIN` 的那一行。）
= biber123
:::

:::evaluate
检查答案
:::

:::warning
如果没有加密，任何截获数据流量的人都可以读取**内容、发送方、接收方和密码**。因此如今人们使用加密的版本（例如带 STARTTLS 的 SMTP、使用 993 端口的 IMAPS）。它是如何工作的，你将在第 8 章学到。
:::

:::tip 要点
**SMTP**、**POP3** 和 **IMAP** 都是文本协议：`MAIL FROM`、`RCPT TO`、`DATA`（SMTP）或 `LOGIN`（IMAP）等命令以及相应的响应都是可读的。如果没有加密，**密码**也会以明文（或仅经过 Base64 编码）在线路上传输。
:::
