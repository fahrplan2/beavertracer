# DMZ

:::sim
url=/sims/lesson-9.3.btsim
:::

之前，**Schulserver** 和 **Lehrer-PC** 位于同一个网络中。这很危险：Schulserver 可以从互联网访问。如果攻击者在 Web 服务器中发现漏洞并控制了这台计算机，他就**身处校园网内部**——而防火墙对此无能为力，因为从 Schulserver 到 Lehrer-PC 的流量根本不经过防火墙。

解决办法：必须能从互联网访问的服务器，要放进互联网与内部网络之间的**独立网络**中。这个网络叫做 **DMZ**（*demilitarisierte Zone*，即非军事区，得名于两条边界之间的中立地带）。

## 结构

在工作区中你可以看到带有**两个防火墙**的经典模型：

```
Internet ──[ Firewall außen ]── Schulrouter ──── DMZ: Schulserver (198.51.100.10)
                                    │
                             [ Firewall innen ]
                                    │
                    LAN: Lehrer-PC (192.0.2.20), Schüler-PC (192.0.2.21)
```

- **Firewall außen** 保护一切免受来自互联网的威胁。端口 A 连接互联网，端口 B 连接 Schulrouter。
- **Firewall innen** 保护 LAN——也包括防范来自 DMZ 的威胁。端口 A 连接 Schulrouter，端口 B 连接 LAN。

目前两个防火墙还会放行所有流量。

## 任务：保护 DMZ

将**两个**防火墙都设为 **Stateful** 和 **Alle verwerfen**，并填入合适的规则：

- **Firewall außen：** 从内向外（B → A）允许所有流量；从外向内（A → B）只允许到 Schulserver `198.51.100.10` 的 TCP 80 和 25。
- **Firewall innen：** 来自 LAN（B → A）的流量全部允许；朝向 LAN 的方向（A → B）不需要规则——响应会通过状态表返回。

:::task
title: DMZ 已保护好了吗？
检查互联网、DMZ 和 LAN 之间被允许和被禁止的路径。
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
check: pingFails(1, 10)
check: tcpOpen(10, "198.51.100.10", 110)
check: tcpOpen(10, "203.0.113.80", 80)
check: pingFails(7, 10)
:::

:::note
许多防火墙拥有三个或更多接口（“区域”），在单台设备中实现 DMZ。原理是相同的：互联网、DMZ 和 LAN 之间的流量必须始终经过规则检查。采用两个防火墙的模型有一个优点：攻击者必须突破**两道**屏障——为此人们常常甚至使用不同厂商的设备，以免同一个安全漏洞同时打开两道防线。
:::

:::tip 要点
所有必须能从互联网访问的服务器都放进 **DMZ**。它位于两个防火墙之间（或位于一个防火墙的独立区域中）：互联网只能访问 DMZ 中的特定服务，LAN 可以访问 DMZ 和互联网——但从 DMZ 和互联网出发，**没有任何通往 LAN 的路径**。即使 DMZ 中的服务器被控制，LAN 依然受到保护。
:::
