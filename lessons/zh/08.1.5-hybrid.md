# 混合加密

我们来总结一下:

| | 对称加密(如 AES) | 非对称加密(如 RSA) |
|---|---|---|
| 密钥 | 一个共同的秘密密钥 | 密钥对:公钥 + 私钥 |
| 速度 | 非常快 | 慢 |
| 密钥交换 | 问题:密钥如何送到接收方手中? | 没有问题:公钥可以公开发送 |

可见,每种方法都有另一种所缺少的优点。解决办法是:把两者结合起来。这就叫作**混合加密**。

1. 连接开始时,双方借助**非对称**方法就一个共同的秘密密钥达成一致,这个密钥称为**会话密钥**。这需要一点时间,但只会进行**一次**。
2. 此后,所有数据都用会话密钥进行**对称**加密——速度很快。
3. 连接结束时,会话密钥被丢弃。下一次连接会得到一个新的密钥。

**HTTPS**、加密的电子邮件连接、使用 WPA3 的 **WLAN**、**SSH** 和 **VPN** 都是这样工作的。

## 通过混合颜色得到共同的秘密

就会话密钥达成一致的一种巧妙方式是 **Diffie-Hellman 密钥交换**(1976 年)。可以用颜色来理解它。诀窍在于:把颜色混合起来很容易,但要把一种混合色重新分解成原来的成分,实际上几乎不可能。

1. Anna 和 Ben **公开**约定一种共同的基础颜色,例如**黄色**。任何人都可以知道它。
2. 每个人各自悄悄选择一种**秘密颜色**:Anna 选**红色**,Ben 选**蓝色**。
3. 每个人把自己的秘密颜色混入基础颜色,然后把结果**公开**发给对方:Anna 发送**黄 + 红**(橙色),Ben 发送**黄 + 蓝**(绿色)。
4. 现在每个人把自己的秘密颜色再混入对方发来的混合色中:
    - Anna:绿 + 红 = **黄 + 蓝 + 红**
    - Ben:橙 + 蓝 = **黄 + 红 + 蓝**
5. 现在两人得到了**同一种**颜色(棕色)——这就是共同的密钥。

窃听者看到了黄色、橙色和绿色。但要得到棕色,他还需要红色或蓝色——而 Anna 和 Ben 从未发送过这两种颜色。

现实中当然不是用颜色来计算,而是用非常大的数字。在 Tracer 中,你很快就会以 **Server Key Exchange** 和 **Client Key Exchange** 的形式再次见到这一交换过程——**ECDHE** 中的“**DHE**”代表 *Diffie-Hellman Ephemeral*,即使用一次性密钥的 Diffie-Hellman。

:::warning
仅靠 Diffie-Hellman 并不能防止攻击者插入中间,分别与 Anna **和** Ben 各自协商出一个单独的密钥。因此 Anna 还必须确信自己真的是在和 Ben 通信。为此需要**签名**和**证书**——这是下一个主题。
:::

:::tip 要点
**混合加密**结合了两者的优点:先用**非对称**方法(如 Diffie-Hellman)使双方就一个秘密的**会话密钥**达成一致;数据本身则用**对称**方式(如 AES)加密。HTTPS、WLAN 加密、SSH 和 VPN 都是这样工作的。
:::
