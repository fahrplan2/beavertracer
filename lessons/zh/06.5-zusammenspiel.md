# 综合应用：访问网页时会发生什么？

:::goal
**学习目标：** 你可以一步一步解释，当一台刚开机的笔记本电脑访问网页时，哪些协议在哪一层参与其中。
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

现在，你在本课程中学到的所有内容都将汇集到一起。交换机上连接着一台 **DHCP-Server**、一台 **DNS-Server**、一台 **Webserver** 和一台刚刚开机的 **Laptop**——它还没有 IP 地址，并且设置为 DHCP。

## 实验

1. 切换到 :fa-play: **运行模式**，等待几秒钟。
2. 点击 **Laptop**，打开 :fa-globe: **浏览器**，访问 `http://www.beaver-schule.de/`。
3. 在 :fa-magnifying-glass: **追踪**模式下，为 **Laptop** 打开一个追踪。整个过程都记录在这里——从第一个数据包开始。

请按照追踪中显示的顺序排列这些步骤：

:::quiz match
1. Schritt -> DHCP：笔记本电脑获取 IP 地址、网关和 DNS 服务器
2. Schritt -> ARP：笔记本电脑询问 DNS 服务器的 MAC 地址
3. Schritt -> DNS：笔记本电脑询问 www.beaver-schule.de 的 IP 地址
4. Schritt -> ARP：笔记本电脑询问 Web 服务器的 MAC 地址
5. Schritt -> TCP：与 Web 服务器进行三次握手
6. Schritt -> HTTP：GET / 以及响应 200 OK
:::

:::evaluate
检查顺序
:::

而在这一切之下，是为每个数据包寻址的 **IP**（第 3 层），以及将数据包送到下一个设备的 **以太网**（第 2 层）。如果 Web 服务器位于另一个网络中，还会有**路由器**参与进来：这时笔记本电脑会询问其**网关**的 MAC 地址，而不是 Web 服务器的 MAC 地址。

:::quiz mc
为什么笔记本电脑只有在 DHCP 之后才能发出 DNS 请求？
- [ ] 因为 DNS 只能通过 TCP 工作
- [x] 因为只有通过 DHCP，它才能获得自己的 IP 地址，并得知由哪台 DNS 服务器负责
- [ ] 因为 DNS 服务器要在 DHCP 服务器之后才启动
:::

:::quiz mc
浏览器与 Web 服务器建立了多少个 TCP 连接——为什么？
- [ ] 一个，所有内容共用
- [x] 两个——一个用于网页，一个用于样式表
- [ ] 一个也没有，HTTP 不需要 TCP
:::

:::evaluate
检查答案
:::

:::tip 要点
一次点击的背后，所有层协同工作：**DHCP** 提供基本设置，**ARP** 在本地网络中查找 MAC 地址，**DNS** 解析域名，**TCP** 建立可靠连接，**HTTP** 获取网页——这一切都封装在 **IP** 数据包和**以太网**帧中。
:::

这样你就能从第一个到最后一个数据包，完整地解释一次网页访问了。本章结尾还有一个关于其他协议的简短展望。接下来的章节将讲解带有 NAT 的家庭网络、安全与加密——也就是如何防止别人读取所有这些数据包。
