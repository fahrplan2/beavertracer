# 一条从头到尾的连接

:::sim
url=/sims/lesson-5.1.btsim
:::

**Server** 上的回显服务运行在端口 `5000` 上：它会立即把收到的每条消息原样发回。通过**简单 TCP 客户端**，你可以一步一步地控制一条连接——每个按钮对应一个阶段。

## 实验

1. 切换到 :fa-play: **运行**模式，点击 **Client-PC**，打开**简单 TCP 客户端**。
2. 在 **Host** 中输入 `192.168.0.20`，在 **Port** 中输入 `5000`。
3. 点击**连接**。
4. 在消息输入框中输入 `Hello World`，然后点击**发送**。随后你会在聊天窗口中看到服务器的回显。
5. 点击**断开连接**。
6. 切换到 :fa-magnifying-glass: **追踪**模式，点击 **+** 为 **Client-PC** 的 `eth0` 接口打开一个追踪。

:::note
开头的两个 ARP 数据包你在第 1 章已经认识了。在 TCP 数据包的 **Info** 列中，首先是 `49152 → 5000`（从哪个端口到哪个端口），然后是方括号中的**标志位**，再后面是 `Seq=`、`Ack=` 和 `Len=` 之类的数字。这些数字从第 5.2.3 页开始讲解——这里你只需关注标志位和 `Len`。
:::

## 阶段 1：连接

:::quiz short
你点击**连接**之后，在你的消息发出之前，一共交换了多少个 TCP 数据包？
= 3
= 三
:::

:::quiz mc
谁发送了第一个带有 `[SYN]` 的数据包？
- [x] Client-PC
- [ ] Server
:::

:::quiz mc
服务器用哪些标志位来回应？
- [ ] `[SYN]`
- [x] `[SYN, ACK]`
- [ ] `[ACK]`
- [ ] `[FIN, ACK]`
:::

## 阶段 2：发送

`Len` 表示一个数据包携带了多少字节的有效载荷。

:::quiz short
带有你的消息的数据包携带了多少字节（`Len`）？
= 13
:::

:::note
`Hello World` 只有 11 个字符。但 TCP 客户端会附加一个行结束符（2 字节，`\r\n`）——许多互联网协议（如 SMTP 或 HTTP）都是这样要求的。
:::

:::quiz mc
服务器在你的消息之后、回显之前，立刻发回了什么？
- [x] 一个带有 `[ACK]` 和 `Len=0` 的数据包——不含数据的确认
- [ ] 什么都没有
- [ ] 一个新的 `[SYN]`
:::

= 四
:::

## 这四项任务体现在哪里？

请匹配：你可以在追踪中的哪里找到第 5.1 节中的各项任务：

:::quiz match
连接建立 -> 三个数据包 [SYN]、[SYN, ACK] 和 [ACK]
可靠传输 -> 带有 [ACK] 和 Len=0、用于确认接收的数据包
连接拆除 -> 带有 FIN 的数据包及其确认
多路复用 -> 方括号前的端口号 49152 → 5000
:::
