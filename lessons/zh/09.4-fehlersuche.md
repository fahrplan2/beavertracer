# 故障排查:新规则生效后一切都不通了

:::sim
url=/sims/lesson-9.4.btsim
:::

Beaver 学校的管理员 Biber 先生昨天把防火墙改成了白名单原则。从那以后大家都在抱怨:**学校网站**从外部无法访问,而且**互联网上的邮件**也收不到了。不过至少:SSH 现在从外部被屏蔽了,正如所愿。

找出**防火墙**规则中的错误并修复它们。

<details>
<summary>提示 1:数据包到底有没有匹配到正确的规则?</summary>

在 **Internet-PC** 上用 `nmap -p 22,25,80 198.51.100.10` 进行测试,然后在防火墙中查看 **Treffer** 列。如果一条规则的计数一直是 0,而本应有数据包匹配它,那么它要么被另一条规则遮蔽了,要么永远无法匹配。
</details>

<details>
<summary>提示 2:仔细看清楚</summary>

把规则中的每个数字与第 5 章中的端口进行比较:HTTP 使用哪个端口,SMTP 使用哪个端口?还要注意顺序:第一条匹配的规则生效。
</details>

:::task
title: Web 和邮件又可以访问了吗?
检查学校服务器的 Web 和邮件服务能否从互联网访问,并且 SSH 仍然被屏蔽。
check: tcpOpen(1, "198.51.100.10", 80)
check: tcpOpen(1, "198.51.100.10", 25)
check: tcpFails(1, "198.51.100.10", 22)
:::

## 问题出在哪里?

:::quiz multi
规则中存在哪些错误?
- [x] Web 规则允许的是 8080 端口,而不是 80 端口
- [x] 邮件规则位于“全部丢弃”规则之下,因此从未被匹配到
- [ ] 防火墙被设置为有状态(Stateful)
- [ ] 25 端口不是邮件使用的正确端口
:::

:::evaluate
检查答案
:::

:::tip 要点
防火墙规则中的典型错误有:端口号的**数字写反**、**方向**错误,以及**顺序**错误,即通用规则遮蔽了特殊规则。故障排查时,从外部进行的**端口扫描**、防火墙的**日志**以及规则的**命中计数器**都能提供帮助。
:::
