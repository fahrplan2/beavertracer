# IPv6 在网络中的应用

:::sim
url=/sims/lesson-4.6.3.btsim
:::

Anna、Ben 和一台路由器连接在交换机上。Anna 和 Ben 的 IPv6 设置为 **SLAAC (automatisch)**——没有人为他们填写 IPv6 地址。路由器知道前缀 `2001:db8:1::/64`。

## 地址从哪里来?

1. 切换到 :fa-play: **运行**模式,等待几秒钟。
2. 在 **Anna** 上打开 :fa-terminal: **终端**,输入 `ip a`。

除了 IPv4 地址,你还会看到两行 `inet6`:一个地址带有 `scope link`,另一个带有 `scope global`。

:::quiz mc
这两个 IPv6 地址中,哪一个是链路本地地址?
- [x] 以 `fe80::` 开头的(`scope link`)
- [ ] 以 `2001:db8:1:` 开头的(`scope global`)
:::

:::quiz mc
全局地址的前缀 `2001:db8:1:0` 从哪里来?
- [ ] Anna 自己想出来的
- [x] 来自路由器——它在网络中通告该前缀
- [ ] 来自交换机
:::

:::evaluate
检查答案
:::

把 **接口 ID**(最后四个块)与 Anna 的 **MAC 地址**比较一下——你可以在 :fa-gear: **IP设置**的最下方找到它。例如,MAC 地址 `aa:28:39:e2:41:82` 会变成接口 ID `a828:39ff:fee2:4182`:在中间插入 `ff:fe`,并把开头的一个比特取反(所以 `aa` 变成了 `a8`)。

这种方式称为 **SLAAC**(*Stateless Address Autoconfiguration*,无状态地址自动配置):路由器通告前缀,接口 ID 则由每台设备自己生成。

:::note
由于 MAC 地址能唯一标识一台设备,通过接口 ID 就可以在互联网上的任何地方识别出它。因此,真实的设备通常还会额外使用定期变化的随机接口 ID(*Privacy Extensions*,隐私扩展)——这是一种数据保护措施。
:::

## 查找邻居——无需 ARP

1. 在 **Ben** 上输入 `ip a`,记下他的**全局** IPv6 地址。
2. 从 **Anna** 向它发送 ping,例如 `ping 2001:db8:1:0:…`(使用 Ben 的完整地址)。
3. 切换到 :fa-magnifying-glass: **追踪**模式,为 **Anna** 打开一条追踪。

看看第一个 `Echo (ping) request` 之前紧挨着的那些数据包。

:::quiz multi
下列哪些说法是正确的?
- [x] Anna 发送的不是 ARP 请求,而是**邻居请求**(Neighbor Solicitation,“谁拥有这个地址?”)
- [x] Ben 用**邻居通告**(Neighbor Advertisement)回应,并告知自己的 MAC 地址
- [x] 该请求发往一个组播地址(`ff02::1:ff…`),而不是以广播方式发给所有设备
- [ ] Anna 像 IPv4 那样发送 ARP 请求
- [x] 路由器定期向 `ff02::1` 发送**路由器通告**(Router Advertisement)——其中包含前缀
:::

:::evaluate
检查答案
:::

:::tip 要点
在 IPv6 中,**NDP**(*Neighbor Discovery Protocol*,邻居发现协议,属于 ICMPv6 的一部分)承担了 ARP 的任务:设备通过**邻居请求**和**邻居通告**找到邻居的 MAC 地址。路由器通过**路由器通告**来通告前缀——设备据此通过 **SLAAC** 自行生成自己的地址。
:::
