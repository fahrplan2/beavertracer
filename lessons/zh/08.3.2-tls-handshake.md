# TLS 握手

:::sim
url=/sims/lesson-8.2.1.btsim
:::

在发送第一个加密请求之前,客户端和服务器必须先达成一致:约定一种加密方法、协商一个会话密钥——而且客户端还必须验证自己正在和谁通信。这个连接建立过程称为 **TLS 握手**。

## 观察

在**客户端 PC**(Client-PC)上访问 `https://www.beaver-schule.de/`(如果还没有访问过的话),为**客户端 PC**(Client-PC)打开一个追踪,并用 `tls` 进行过滤。

= Client Hello
:::

:::quiz short

= Certificate
:::

:::quiz short

## 图中的流程

不含 TCP 确认(`ACK`)时,握手过程如下:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

下面说明每一步发生了什么,以及它对应 8.1 节中的哪个基本构件:

1. **Client Hello / Server Hello:** 客户端和服务器相互问候,交换随机数,并约定所用的方法(在 BeaverTracer 中:密钥交换使用 **ECDHE**,签名使用 **ECDSA**,加密使用 **AES**)。
2. **Certificate:** 服务器发送它的**证书**。客户端检查 CA 的签名、有效期和名称。如果检查失败,客户端会在此中止——浏览器随即显示警告。
3. **Server Key Exchange:** 服务器发送它的 **Diffie-Hellman 份额**,并用自己的私钥对其**签名**。客户端用证书中的公钥验证该签名。这样客户端就知道:这个份额确实来自证书的持有者,而不是来自中间人。
4. **Client Key Exchange:** 客户端发送它的 Diffie-Hellman 份额。现在双方都可以计算出相同的**会话密钥**——而这个密钥从未被传输过。
5. **Change Cipher Spec:** “从现在起我开始加密。”
6. **Encrypted Handshake Message(Finished):** 双方都发送一个针对此前所有握手消息的校验值——此时已经是加密的。如果攻击者在途中篡改了什么,校验值就对不上,连接随即被中止。
7. **Application Data:** 从这里开始传输 HTTP 数据——使用 AES 进行对称加密。

:::quiz match
Certificate -> 服务器用它的证书证明自己的身份
Server Key Exchange -> 服务器经过签名的 Diffie-Hellman 份额
Client Key Exchange -> 客户端的 Diffie-Hellman 份额
Change Cipher Spec -> 从现在起开始加密
Application Data -> 加密的 HTTP 数据
:::

:::note
在追踪中你会看到**两个**先后建立的 TLS 连接:浏览器先获取页面,然后为样式表 `style.css` 建立一个新连接。每个连接都有自己的握手和自己的会话密钥。真实的浏览器会保持连接打开,从而省去其中一部分开销。此外,较新的版本 **TLS 1.3** 所需的消息比这里展示的 TLS 1.2 更少。
:::

:::tip 要点
在 **TLS 握手**中,服务器用它的**证书**证明自己的身份,双方通过 **Diffie-Hellman** 协商出一个**会话密钥**(服务器对自己的份额进行**签名**),并通过 **Finished** 确认没有人篡改过握手。之后,数据以 **Application Data** 的形式经对称加密后传输。
:::
