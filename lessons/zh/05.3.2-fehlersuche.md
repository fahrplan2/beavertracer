# 故障排查：服务没有响应

:::sim
url=/sims/lesson-5.3.2.btsim
:::

更新之后，学校反馈：“回显服务拒绝所有连接，网页也加载不出来了。”按照规划，**Webserver** 应该监听端口 `80`，**回显服务**（TCP 回显服务器）应该监听端口 `5000`。找出故障并修复它们。

<details>
<summary>提示 1：服务器是如何响应的？</summary>

用**简单 TCP 客户端**尝试连接 `192.168.0.20`，端口 `5000`，并为客户端 PC 打开一个追踪。服务器是如何响应你发出的 `[SYN]` 的？
</details>

<details>
<summary>提示 2：哪些端口是开放的？</summary>

在客户端 PC 的终端中输入 `nmap -p 80,5000 192.168.0.20`。`nmap` 会依次尝试这些端口，并显示哪些是开放的。在服务器上使用 `ss`，你可以看到那里究竟有哪些端口上有程序在监听。
</details>

<details>
<summary>提示 3：在哪里设置？</summary>

在 **Server** 上打开 **TCP 回显服务器**和 **HTTP 服务器**这两个应用。服务在运行吗？它使用的是哪个端口？
</details>

:::task
title: 服务可以访问吗？
检查客户端 PC 能否访问端口 5000 上的回显服务和端口 80 上的 Webserver。为此，模拟必须处于运行模式。
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## 问题出在哪里？

:::quiz multi
下列哪些说法是正确的？
- [x] 服务器用 `[RST, ACK]` 响应了发往端口 5000 的 `[SYN]`
- [x] 回显服务监听的是端口 5050，而不是端口 5000
- [x] Webserver 根本没有启动
- [ ] 客户端 PC 与服务器之间的网线损坏了
:::

:::evaluate
检查答案
:::

:::tip 要点
如果收到 `SYN` 后返回的是 **`RST`**，说明该端口上**没有程序**在监听：这台主机可以访问，但服务不可用。常见原因：服务**没有启动**，或者监听的是**另一个端口**。在服务器上用 `ss` 查看一下，就能知道哪些端口真正处于开放状态。
:::
