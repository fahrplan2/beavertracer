# 故障排查：联系页面不见了

:::sim
url=/sims/lesson-6.1.3.btsim
:::

秘书处反馈说：“我们网站上的 **Kontakt** 链接现在只会跳转到一条错误信息。”联系页面本应可以通过 `http://192.168.0.20/kontakt.html` 访问。请找出故障并修复它。

<details>
<summary>提示 1：服务器返回了什么？</summary>

在浏览器中或使用 `curl -v` 访问联系页面。返回的状态码是什么？错误页面还会告诉你服务器在哪里查找过这个文件。
</details>

<details>
<summary>提示 2：文件在哪里？</summary>

Web 服务器只会提供其**文档根目录**（*Document Root*）中的文件——这一设置可以在 **HTTP 服务器** 应用中看到。在 **Server** 上，通过终端用 `ls` 查看那里有哪些文件，并且也在 `/home` 中查找联系页面。
</details>

<details>
<summary>提示 3：移动文件</summary>

用 `mv` 可以移动文件：`mv <源文件> <目标文件夹>`。
</details>

:::task
title: 联系页面修好了吗？
检查联系页面是否位于 Web 服务器的文档根目录中。
check: fileExists(2, "/var/www/kontakt.html")
:::

## 到底出了什么问题？

:::quiz multi
下列哪些说法是正确的？
- [x] 服务器返回了 `404 Not Found`
- [x] 文件位于 `/home`，而不是文档根目录 `/var/www`
- [ ] Web 服务器根本没有启动
- [ ] 浏览器使用了错误的 IP 地址
:::

:::evaluate
检查答案
:::

:::tip 要点
**404** 表示：Web 服务器正在运行且可以访问，但在这个路径下**不存在**所请求的**文件**。服务器只会在它的**文档根目录**（*Document Root*，这里是 `/var/www`）中查找。对比一下：如果服务器完全没有响应，或者以 `RST` 响应，那么问题出在更底层——在网络上或服务本身（第 5.3.2 章）。
:::
