# 广播风暴

:::sim
url=/sims/lesson-3.4.1.btsim
:::

三台交换机（A、B、C）连接成环形。**Anna**（`192.168.0.10`）连接在交换机 A 上，**Ben**（`192.168.0.11`）连接在交换机 B 上。

## 实验

1. 切换到 :fa-play: **运行**模式，在 **Anna** 上打开 :fa-terminal: **终端**，ping Ben：
   ```
   $ ping 192.168.0.11
   ```
2. 关闭 Anna 的窗口，在工作区观察一会儿：数据包在环路中不停地循环。
3. 切换到 :fa-magnifying-glass: **追踪**模式，点击 **+** 为 **Ben** 的接口 `eth0` 打开一个追踪。在右上角可以看到已经记录了多少个数据包。
4. 在**运行**和**追踪**之间来回切换几次，并留意这个数字。

:::quiz mc
你在 Ben 的数据包列表中看到了什么？
- [ ] Anna 的 ping 请求和 Ben 的回复，一切如常
- [x] 同一个 ARP 请求“Who has 192.168.0.11?”一遍又一遍地出现——而且数据包的数量不断增长
- [ ] 什么也没有，环路阻塞了一切
:::

:::quiz mc
那么 Anna 的终端显示了什么？
- [ ] 所有 ping 都到达了
- [x] 没有任何 ping 到达
:::

:::evaluate
检查答案
:::

## 背后的原因

Anna 的 ARP 请求是一个广播。交换机 A 把它发送到所有端口——也就是发给交换机 B *和*交换机 C。两者又会把它转发到各自的所有端口，因此也会转发给另一台交换机并回到 A。A 又再次转发……广播在环路中无休止地循环，而且每出现一个新的请求，就会多出更多副本。

由于相同的帧不断从不同方向到达交换机，它们的地址表也会被搅乱：一会儿 Anna 在这个端口，一会儿又在那个端口。因此，就连 ping 也不再能到达。

:::tip 要点
如果交换机之间存在**环路**，广播就会在网络中无休止地循环并不断增殖——这就是**广播风暴**。它会使网络瘫痪。与 IP 数据包不同，以太网帧没有“有效期限”来使其最终停止传输。
:::
