# TCP 还是 UDP?

| | TCP | UDP |
|---|---|---|
| 连接 | 通过三次握手建立,有序断开 | 无连接 — 每个数据报都是独立的 |
| 确认 | 有(`ACK`) | 无 |
| 丢失的数据 | 会被重新发送 | 就此丢失 |
| 顺序 | 会被恢复 | 不保证 |
| 首部 | 至少 20 字节 | 8 字节 |
| 速度 | 稍慢,数据包更多 | 快,开销小 |

什么时候少即是多?

- **实时性:** 在视频通话、网络电话或在线游戏中,每一毫秒都很重要。一段丢失的声音如果一秒钟后才补发过来,对任何人都没有用了 — 宁可有一小段杂音,也不要延迟。
- **简短的请求:** 一个 **DNS** 请求(“`www.beispiel.de` 的 IP 地址是什么?”)只需一个数据报就能装下,应答也是如此。如果再进行连接建立,开销就会变成三倍。如果没有收到应答,程序只需再问一次。

而在每个字节都必须送达的场合 — 网页、电子邮件、下载 — TCP 则是正确的选择。

:::tip 要点
**TCP** 可靠,但开销较大 — 适用于所有必须**完整**送达的内容(网页、电子邮件、文件)。**UDP** 快速而轻量,但没有任何保证 — 适用于**实时**应用(电话、视频、游戏)以及 DNS 这类**简短的请求**。
:::
