# 运行 ping 并在追踪器中查看过程

:::sim
url=/sims/lesson-1.2.3.btsim
:::

两台 PC 现在的地址分别是 `192.168.0.10` 和 `192.168.0.11`。该做第一次测试了：用 **Ping**，一台 PC 向另一台发送一个小请求，并等待对方的响应。

## 运行 ping

切换到 :fa-play: **运行**模式。在 **Computer 1** 上打开 :fa-terminal: **终端**，输入：

```
$ ping 192.168.0.11
```

如果另一台 PC 做出响应，你会看到每发送一个数据包就有一行带有响应时间的输出——这就是你第一次成功的 ping！

:::tip 要点
**Ping** 用来检查另一台设备是否可达：它发送一个请求，并测量响应需要多长时间。
:::

## 在追踪器中查看

现在切换到 :fa-magnifying-glass: **追踪**模式。这里暂时什么都看不到——点击左上角 **Traces:** 旁边的 **+**，选择 **Computer 1**，再选择它的接口 `eth0`。

现在你会看到一个列表，列出了所有经过该接口的数据包——也包括刚才的 ping。点击其中一个数据包：下方会显示它的详细结构，一层一层地展示。

:::tip 要点
数据在网络中不是一次性整体发送的，而是分成许多小单元，即**数据包**。每个数据包都带有发送方、接收方和一部分数据。
:::

:::tip
一次 ping 总是由一个请求（Echo Request）和一个响应（Echo Reply）组成——你能在 **Info** 列中找到这两个方向的数据包吗？
:::

## 第一次 ping 之前是谁在询问？

在列表的最上方，也就是第一次 ping 之前，有两个协议为 **ARP** 的数据包。阅读它们的 **Info** 列——内容大致如下：

```
Who has 192.168.0.11? Tell 192.168.0.10
192.168.0.11 is at aa:fd:9f:a5:d2:89
```

Computer 1 虽然知道另一台 PC 的 IP 地址，但还不知道它的**硬件地址**（即 *MAC 地址*——每块网卡都有自己独一无二的地址）。没有硬件地址，它就无法发送任何数据。所以它先向网络里喊话：*“谁拥有 192.168.0.11？告诉 192.168.0.10！”* 被查找的那台 PC 会用自己的硬件地址作答。这正是 **ARP** 的任务。

之后 Computer 1 会记住这个答复——因此 ARP 只在第一次 ping 之前出现，而不是每次 ping 之前都出现。

:::tip 要点
**ARP** 可以根据已知的 IP 地址找到对应的硬件地址（**MAC 地址**）：PC 向网络中的所有设备询问，只有被查找的设备会作答。
:::
