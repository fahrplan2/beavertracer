# 证书：这把密钥属于谁？

有了非对称加密和签名，一切似乎都解决了：你的银行的 Web 服务器把它的公钥发给你，然后就可以开始通信了。但你怎么知道这把公钥**真的属于银行**呢？

如果攻击者把你的连接重定向，他完全可以把**他自己的**公钥发给你，并声称自己是银行。你的浏览器就会乖乖地用攻击者的密钥加密——而攻击者可以读取所有内容。这样处于通信中间的攻击者称为**中间人**（*Man-in-the-Middle*）。

## 证书：密钥的身份证

在现实生活中，你出示**身份证**来证明自己是谁。人们之所以相信身份证，是因为它由一个**值得信任的机构**——市政管理部门——签发，而且很难伪造。

在网络中，这个任务由**证书**来承担。它包含的内容有：

| 字段 | 含义 | 对应身份证上的 |
|---|---|---|
| **主体**（*Subject*，常写作 `CN=…`） | 证书是为谁签发的？对 Web 服务器而言：即名称，例如 `CN=www.biberbank.de` | 持证人姓名 |
| **公钥** | 持有者的密钥 | 照片 |
| **颁发者**（*Issuer*） | 谁签发了这份证书？ | 签发机关 |
| **有效期** | 从……到…… | 有效期至 |
| 颁发者的**签名** | 证明颁发者确实签发了这样的证书 | 印章、全息图 |

`CN` 是 *Common Name*（通用名称）的缩写。

签发证书的机构称为**证书颁发机构**（*Certificate Authority*，简称 **CA**）。在为 `www.biberbank.de` 签发证书之前，它会检查申请者是否真的拥有这个域名。

## 浏览器信任谁？

对于每一份证书，你的浏览器都会检查：

1. CA 的**签名**是否真实？（为此它需要 CA 的公钥。）
2. 证书是否仍然**有效**？
3. 证书中的**名称**是否与所访问的地址相符？

但浏览器是怎么认识这个 CA 的呢？每个操作系统和浏览器中都**预装**了一份大约 150 个**根 CA**（*Root-CA*）的列表。它们的证书是**自签名**的——也就是自己为自己担保；之所以信任它们，是因为它们随软件一起提供。

通常根 CA 并不直接签发，而是通过**中间 CA** 来签发。这样就形成了一条**信任链**：

```
Root-CA (vorinstalliert, vertraut)
  └─ signiert → Zwischen-CA
                  └─ signiert → www.biberbank.de
```

浏览器沿着这条链自下而上验证，直到到达一个它信任的根 CA。如果验证失败——或者有效期或名称不符——它就会显示**警告**。

:::tip 要点
**证书**用来确认某个**公钥**属于某个特定的**名称**。它由**证书颁发机构（CA）**签名。如果浏览器通过**信任链**到达了一个预装的**根 CA**，证书**有效**，并且**名称**与地址相符，浏览器就会信任该证书。
:::
