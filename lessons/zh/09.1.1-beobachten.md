## 来自外部的 Ping

切换到 :fa-play: **运行**模式，从 **Internet-PC** 向学校服务器发送 ping：

```
$ ping -c 2 198.51.100.10
```

然后在防火墙中打开**日志**标签页。

## 端口扫描：丢弃还是拒绝？

现在有针对性地扫描五个端口。端口 3306（一个数据库）在学校服务器上根本没有运行。

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22（丢弃） -> filtered
25（允许，服务运行中） -> open
110（拒绝） -> closed
3306（允许，无服务） -> closed
:::

:::evaluate
检查匹配
:::

:::quiz multi
攻击者可以从结果中得出什么结论？
- [x] 看到 `filtered` 时，他知道：那里有一个会悄悄吞掉数据包的防火墙
- [x] 看到 `closed` 时，他无法区分是防火墙拒绝了请求，还是根本没有服务在运行
- [ ] 看到 `filtered` 时，他知道该端口背后运行的是什么服务
- [ ] 看到 `closed` 时，该服务仍然可以访问
:::

:::evaluate
检查答案
:::

最后，查看规则列表中的**命中**列：防火墙在这里统计每条规则已经处理了多少个数据包。**默认策略**旁边的数值统计的是没有匹配任何规则的所有数据包。

:::tip 要点
**被丢弃**的数据包会无声无息地消失：`ping` 报告超时，`nmap` 报告 `filtered`。**被拒绝**的数据包，防火墙会回复一个拒绝响应（TCP 中是 RST）——从外部看起来就像端口是关闭的。防火墙的**日志**显示它拦截了哪些数据包，**命中**列显示是哪条规则起了作用。
:::
