# 访问并观察网页

这一部分你不需要自己搭建任何东西：工作区中已经有一个准备好的模拟，里面有一台 **Client-PC** 和一台 **Webserver**。

## 访问网页

1. 切换到 :fa-play: **运行**模式。
2. 在 **Client-PC** 上打开 :fa-globe: **浏览器** 应用，并访问 Web 服务器的地址：`http://192.168.0.20/`。
3. 切换到 :fa-magnifying-glass: **追踪**模式，点击 **+** 为 **Client-PC** 的 `eth0` 接口打开一个追踪——和 ping 时完全一样。

:::note
仅仅访问一次网页，数据包的数量就多得出人意料——比 ping 多得多。获取一个网页是一个分多个步骤的过程，而不是单一的操作。
:::

## 阅读数据包列表

你现在还不需要知道各个协议具体做什么。回答下面的问题所需的一切信息，都在 **协议** 和 **信息** 这两列中。

:::quiz mc

- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
数一数：第一个 **HTTP** 数据包之前有多少个 **TCP** 数据包？
= 3

:::

:::quiz mc
Web 服务器如何回应浏览器的请求？请查看第二个 HTTP 数据包的“信息”列。
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
检查答案
:::

## 说出涉及的协议

根据你的观察，现在可以看出每个协议分别负责什么。

:::tip 提示
再仔细读一遍 **信息** 列：`Who has …?`、`[SYN]`、`[SYN, ACK]`、`[ACK]`、`GET /` 和 `200 OK` 几乎已经说明了一切。
:::

:::quiz match
ARP -> 询问网络中的所有设备：“谁拥有 IP 地址 192.168.0.20？”
TCP -> 在数据传输之前，先用三个简短的数据包建立连接
HTTP -> 请求网页（GET）并将其返回（200 OK）
:::

:::evaluate
检查匹配
:::

:::tip 要点
访问网页分几个阶段进行：先在网络中**找到**服务器（ARP），然后**建立**连接（TCP），接着**请求并传送**网页（HTTP）——最后再把连接**断开**（列表末尾带有 `[FIN]` 的 TCP 数据包）。
:::

:::note
这次你直接输入了服务器的 IP 地址，所以 **DNS**（把 `www.beispiel.de` 这样的名称“翻译”成 IP 地址）还没有派上用场。我们会在第 6 章补上这一部分。
:::

你有没有注意到，数据包结构中的各个协议带有标着数字的彩色标记？这是怎么回事，我们将在第 2 章讲解。在那里我们会看看如何用 OSI 和 TCP/IP 参考模型，把众多协议系统地归类。至此，第 1 章就完成了。
