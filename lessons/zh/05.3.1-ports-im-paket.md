## 实验

1. 切换到 :fa-play: **运行**模式，点击 **Client-PC**，打开 :fa-globe: **浏览器**。访问 `http://192.168.0.20/`。
2. 点击窗口顶部的 **Zurück**，打开**简单 TCP 客户端**，并将其连接到 `192.168.0.20`，端口 `5000`。保持连接不要关闭。
3. 切换到 :fa-magnifying-glass: **追踪**模式，为 **Client-PC** 打开一个 Trace，并点击带有 `[SYN]` 的数据包。展开 **Transmission Control Protocol**。

在 TCP 头部的最上方有两个端口：**Source Port**（源端口）和 **Destination Port**（目的端口）。

:::quiz table
| 连接 | 源端口 | 目的端口 |
|---|---|---|
| 浏览器 → Webserver | {49152} | {80} |
| TCP-Client → Echo-Dienst | {49153} | {5000} |
:::

## 两种端口

**目的端口——服务：** 服务器程序在固定的端口上等待连接，我们说它在该端口上**监听**。对于常见的服务，其端口号是全球统一规定的，即**知名端口**（Well-known Ports，0 到 1023）。因此浏览器无需询问就知道：Web 服务器监听 80 端口。

**源端口——发送方：** 客户端一侧的端口由操作系统为每个新连接自行从较高的范围中选取（在 BeaverTracer 中从 49152 开始）。客户端通过它来判断一个响应属于自己的哪一个连接。

因此，一个连接由四项信息唯一确定：**双方的 IP 地址和端口**。IP 地址与端口的组合称为**套接字**（Socket），例如 `192.168.0.20:80`。

## 看一看服务器

切换回 :fa-play: **运行**模式，在 **Server** 上打开 :fa-terminal: **终端**，输入：

```
$ ss
```

`ss` 会显示这台计算机的所有套接字。带有 `LISTEN` 的行是在某个端口上监听的程序。带有 `ESTABLISHED` 的行是已建立的连接——包含本机的套接字（*Local Address:Port*）和对端的套接字（*Peer Address:Port*）。

:::quiz multi
服务器在哪些端口上监听？
- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc

- [x] `192.168.0.20:5000` 与 `192.168.0.10:49153`——TCP 客户端的已打开连接
- [ ] `192.168.0.20:80` 与 `192.168.0.10:49152`——浏览器的连接
- [ ] 两个都是
:::

检查答案
:::

:::note
浏览器的连接已经被断开了——页面加载完成后，它通过 `FIN` 结束。`ss` 仍会短暂地将其显示为 `TIME-WAIT`：服务器会等待一段时间，看是否还有属于该连接的迟到数据包到达。而 TCP 客户端的连接仍然是打开的，因为你还没有点击**断开连接**。
:::

## 最重要的知名端口

| 端口 | 协议 | 服务 |
|---|---|---|
| 22 | SSH | 安全远程维护（加密的命令行） |
| 25 | SMTP | 发送电子邮件 |
| 53 | DNS | 将域名解析为 IP 地址（通常通过 UDP） |
| 80 | HTTP | 网页 |
| 110 | POP3 | 收取电子邮件 |
| 143 | IMAP | 在服务器上管理电子邮件 |
| 443 | HTTPS | 加密网页 |

:::tip 要点
**端口**（0 到 65535）用于区分一台计算机上的各个连接。服务器服务在固定的**知名端口**上**监听**（例如 HTTP 80、HTTPS 443），客户端则为每个连接获得一个空闲的较高**源端口**。一个连接由**双方的 IP 地址和端口**唯一确定。
:::

:::quiz match

53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
