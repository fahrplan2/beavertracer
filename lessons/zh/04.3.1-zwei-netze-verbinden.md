# 连接两个网络

:::sim
url=/sims/lesson-4.3.1.btsim
:::

路由器有两个接口:

| 接口 | IP 地址 | 网络 |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

为了让各台 PC 使用路由器,每台 PC 上都设置了一个**网关**:Anna 和 Ben 的是 `192.168.0.1`,Clara 和 David 的是 `172.16.0.1`。你可以在 :fa-gear: **IP设置**的**网关**字段中找到它。

:::tip 要点
**网关**(更准确地说:*默认网关*)是路由器**在本网络中**的 IP 地址。PC 会把所有目的地在其他网络中的数据包发送给网关。
:::

## 路由器如何处理数据包

路由器接收 Anna 发来的帧,拆开 IP 数据包,查看**目的 IP 地址**。由此它判断出:Clara 位于 `eth1` 所连接的网络中。于是它把数据包封装进一个**新的**帧——以自己的 MAC 地址作为发送方、以 Clara 的 MAC 地址作为目的地址——并从那个接口发送出去。

| 路由器对……做了什么 | |
|---|---|
| MAC 地址(第 2 层)? | **重新**设置——它们只在各自的网络中有效 |
| IP 地址(第 3 层)? | **保持不变**——从 Anna 一直到 Clara |
| Time to Live? | **减少 1** |

:::tip 要点
**路由器**工作在**第 3 层**:它根据**目的 IP 地址**把数据包转发到其他网络。IP 地址在整条路径上保持不变,而 MAC 地址在每个网络中都会重新设置。每经过一个路由器,**Time to Live(TTL)**就减 1——减到 0 时,数据包被丢弃。这样数据包就不会无休止地兜圈子。
:::

:::note
还记得第 3.4 章中的广播风暴吗?以太网帧没有 TTL——IP 数据包有。
:::

## Anna 认识谁?ARP 缓存

还记得第 1.2.3 章吗?当时 ARP 只在*第一次* ping 之前出现,因为 PC 记住了应答。这张记忆表叫作 **ARP 缓存**(也称 *ARP 表*)。这个询问称为 **ARP 请求**,应答称为 **ARP 应答**(也叫 *ARP Response*)。

切换到 :fa-play: **运行**模式,在 **Anna** 上打开 :fa-terminal: **终端**,显示她的 ARP 缓存:

```
$ arp
```

:::quiz mc
Anna 的 ARP 缓存中有什么?
- [x] 只有路由器的 IP 地址(`192.168.0.1`)及其 MAC 地址
- [ ] Clara 的 IP 地址及 Clara 的 MAC 地址
- [ ] 路由器和 Clara 的地址
:::

:::evaluate
检查答案
:::

Anna 从不需要 Clara 的 MAC 地址:所有发往 Firma B 的数据,她都交给路由器。只有路由器知道 Clara 的 MAC 地址——它在自己这一侧通过 ARP 自行询问到了。

:::tip 要点
设备在 **ARP 缓存**中记录哪个 MAC 地址对应哪个 IP 地址——这样就不必在每个数据包之前都发送一次 ARP 请求。可以用命令 `arp` 查看。PC 只知道**本网络**中的 MAC 地址:对于其他网络中的所有目的地,它都使用路由器的 MAC 地址。
:::

:::note
在真实网络中,ARP 缓存中的条目会在一段时间后被删除,并在需要时重新询问——例如设备在此期间更换了网卡。在 BeaverTracer 中,只要仿真在运行,这些条目就会一直保留。
:::
