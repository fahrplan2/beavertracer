# 故障排查：名称无法解析

:::sim
url=/sims/lesson-6.2.3.btsim
:::

一位老师反映：“`www.beaver-schule.de` 在我这里打不开。但用 `http://192.168.0.20` 却可以！”网络应当按如下方式配置：

| 项目 | 应有配置 |
|---|---|
| Client-PC 上的 DNS 服务器 | `192.168.0.53`（DNS-Resolver） |
| Schul-DNS 中的记录 | `www.beaver-schule.de` → `192.168.0.20` |

找出错误并修复。

<details>
<summary>提示 1：nslookup 显示了什么？</summary>

在 Client-PC 上输入 `nslookup www.beaver-schule.de`。`nslookup` 询问了哪台服务器？返回了什么？（响应需要几秒钟。）
</details>

<details>
<summary>提示 2：接下来呢？</summary>

如果你收到了应答，请把该地址与拓扑图进行比较。这个名称是在哪里登记的？
</details>

:::task
title: 名称解析修复了吗？
检查 Client-PC 是否能把 www.beaver-schule.de 解析到正确的地址。为此，模拟必须处于运行模式。
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## 问题出在哪里？

:::quiz multi
下列哪些说法是正确的？
- [x] Client-PC 上设置的 DNS 服务器是 `192.168.0.35`——那里没有任何设备应答
- [x] 在 Schul-DNS 中，`www.beaver-schule.de` 指向的是 `192.168.0.21`，而不是 `192.168.0.20`
- [ ] Web 服务器被关闭了
- [ ] 根服务器不认识域名 `.de`
:::

:::evaluate
检查答案
:::

:::tip 要点
如果用 **IP 地址**可以连接，但用**名称**不行，问题就出在 **DNS** 上。先检查**所设置的 DNS 服务器**（它到底有没有应答？），再检查**记录**本身（地址对不对？）。`nslookup` 可以同时显示这两点：询问了哪台服务器，以及它给出了什么应答。
:::
