# 响应问题

:::sim
url=/sims/lesson-9.2.btsim
:::

防火墙现在按白名单原则工作：默认策略为 **Alle verwerfen**。只有一条规则允许校园网上网：**B → A, TCP, Ziel-Port 80, Zulassen**。模式设置为 **Stateless**。

## 实验

1. 切换到 :fa-play: **运行**模式，在 **Lehrer-PC** 上通过 :fa-globe: **浏览器** 访问 `http://203.0.113.80/`。
2. 在 **Firewall** 中查看 **Protokoll** 和 **Treffer**。

:::quiz mc
浏览器中会发生什么？
- [ ] 显示 www.beispiel.de 的页面
- [x] 页面无法加载，浏览器一直等待，最后报错
:::

:::quiz mc
防火墙日志中哪些数据包被标记为丢弃（`DROP`）？
- [ ] Lehrer-PC 发往 80 端口的请求
- [x] 来自 `203.0.113.80`、**源端口为 80**、发往 Lehrer-PC 的响应
- [ ] 一个都没有
:::

:::quiz short
被丢弃的数据包是沿哪个方向传输的（A→B 还是 B→A）？
= A→B
= A → B
= AtoB
:::

:::evaluate
检查答案
:::

Lehrer-PC 的请求可以发出去，但 Web 服务器返回的 `SYN, ACK` 却回不来，因为 A → B 方向没有匹配的规则，所以适用 **Alle verwerfen**。

## 简单粗暴的解决办法

可以再添加第二条规则：**A → B, TCP, Quell-Port 80, Zulassen**，即“所有来自 80 端口的数据包都允许进入”。这样上网确实就能正常工作了。

:::quiz mc
为什么这条规则很危险？
- [ ] 因为 Web 服务器从不使用 80 端口作为源端口
- [x] 攻击者可以直接用源端口 80 发送数据包，这样防火墙就会放行这些数据包到校园网内的**任意**端口
- [ ] 因为这样网页加载会变慢
:::

:::evaluate
检查答案
:::

源端口由发送方自己决定，防火墙不能依赖它。而无状态防火墙无法判断一个数据包是**对某个请求的响应**，还是从外部发起的**新连接尝试**。有状态模式改变的正是这一点。

:::tip 要点
**无状态**数据包过滤器会逐个检查每个数据包。响应数据包因此需要为返回方向单独设置规则，而这类规则（例如“源端口 80 允许进入”）很容易被攻击者利用，因为发送方可以任意选择源端口。
:::
