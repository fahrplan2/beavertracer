# 包过滤器：规则

最简单也最重要的一类防火墙是**包过滤器**。它会检查经过的每一个数据包，并根据一份**规则列表**决定该数据包能否通过。为此它只读取第 3 层和第 4 层的首部——数据包的内容（例如网页）它不会查看。

## 一条规则由什么组成

| 字段 | 含义 | 示例 |
|---|---|---|
| **方向** | 数据包来自哪一侧？ | A → B（从互联网进入学校网络） |
| **协议** | TCP、UDP、ICMP 或任意 | TCP |
| **源 IP** | 发送方地址或网络 | 任意 |
| **源端口** | 发送方端口 | 任意 |
| **目的 IP** | 接收方地址或网络 | `198.51.100.10` |
| **目的端口** | 接收方端口，即所提供的服务 | `80` |
| **动作** | 匹配的数据包会怎样处理？ | 允许 |

空字段表示“任意”。网络用 CIDR 表示法书写，例如 `198.51.100.0/24`；端口范围用连字符表示，例如 `1024-65535`。

## 顺序决定结果

防火墙**自上而下**检查规则。**第一条匹配的规则**起决定作用——对于这个数据包，后面的规则不会再被查看。如果没有任何规则匹配，则适用**默认策略**（*Default Policy*）。

## 三种可能的动作

| 动作 | 防火墙的处理 | 发送方的感受 |
|---|---|---|
| **允许**（*Allow*） | 数据包被转发 | — |
| **丢弃**（*Drop*） | 数据包被悄无声息地丢掉 | 毫无察觉——只能一直等到超时 |
| **拒绝**（*Reject*） | 数据包被丢掉，发送方会收到拒绝通知：TCP 返回 **RST**，其他情况返回 ICMP“不可达” | 立即收到错误信息 |

哪种更好？**丢弃**向攻击者透露的信息更少，还会消耗他的时间，因为每次尝试他都要等待。**拒绝**对自己的用户更友好：程序会立即得到错误信息，而不是长时间卡住。因此在实践中，通常对来自外部的数据包采取丢弃，对来自内部网络的数据包采取拒绝。

:::quiz match
允许 -> 数据包被转发
丢弃 -> 数据包消失，发送方白白等待回应
拒绝 -> 数据包不被转发，但发送方会立即收到拒绝通知
默认策略 -> 在没有任何规则匹配时生效
:::

:::tip 要点
**包过滤器**根据方向、协议、地址和端口，将每个数据包与一份**规则列表**进行比对。**第一条匹配的规则**决定采取的动作：**允许**、**丢弃**（静默）或**拒绝**（并发送拒绝通知）。如果没有任何规则匹配，则适用**默认策略**。
:::
