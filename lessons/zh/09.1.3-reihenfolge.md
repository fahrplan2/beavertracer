# 顺序与基本原则

## 先例外，后通则

因为**第一条匹配的规则**生效，所以顺序非常重要。请看下面这张规则列表（所有规则都适用于 A → B 方向，默认策略：全部允许）：

| 序号 | 协议 | 目标端口 | 动作 |
|---|---|---|---|
| 1 | TCP | 任意 | 丢弃 |
| 2 | TCP | 80 | 允许 |

:::quiz mc
一个来自互联网、发往 TCP 端口 80 的数据包到达了。会发生什么？
- [ ] 它会被允许通过，因为规则 2 恰好允许端口 80
- [x] 它会被丢弃，因为规则 1 已经匹配——规则 2 永远不会被执行到
- [ ] 防火墙会向管理员询问
:::

:::evaluate
检查答案
:::

一般来说：**具体的规则放在上面，笼统的规则放在下面。** 一条覆盖范围很大的规则会“遮蔽”它下面的所有规则。通过**命中**这一列可以发现这种失效规则：它们的计数始终为 0。

## 黑名单还是白名单？

在 9.1.2 小节中，你禁止了个别端口，而允许其他所有端口。这称为**黑名单**。与之相反的是**白名单**：只**允许**必要的内容，其余一律禁止——通过最后一条“全部丢弃”的规则，或者通过默认策略**全部丢弃**来实现。

| | 黑名单 | 白名单 |
|---|---|---|
| 基本原则 | 默认全部允许，例外被禁止 | 默认全部禁止，例外被允许 |
| 默认策略 | 允许 | 丢弃 |
| 服务器上的新服务 | 立即可从外部访问 | 保持封锁，直到有人放行 |

:::quiz mc
明天一位老师在学校服务器上安装了一个监听端口 3306 的数据库。对于 9.1.2 小节中的防火墙（黑名单），会发生什么？
- [x] 数据库立即可以从互联网访问
- [ ] 数据库会被自动封锁
- [ ] 防火墙会报告这个新服务
:::

:::evaluate
检查答案
:::

因此，好的防火墙遵循**白名单原则**（“Default Deny”，默认拒绝）：凡是没有明确允许的，一律禁止。学校服务器的白名单大致如下：

:::quiz table
| 序号 | 方向 | 协议 | 目标端口 | 动作 |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {允许} |
| 2 | A → B | TCP | {25} | 允许 |
| 3 | A → B | 任意 | 任意 | {丢弃} |
:::

:::evaluate
检查表格
:::

:::quiz mc
如果把规则 3 移到最上面，会发生什么？
- [ ] 什么也不会发生，顺序无所谓
- [x] 来自互联网的任何流量都无法通过，Web 和邮件也不行
- [ ] 只有 Web 和邮件可以通过
:::

:::evaluate
检查答案
:::

:::tip 要点
因为**第一条匹配的规则**生效，所以**具体的规则应放在上面**，笼统的规则放在下面。比**黑名单**（除……外全部允许）更安全的是**白名单**（除……外全部禁止，即 *Default Deny*）：这样被遗忘的或新增的服务会自动保持封锁。
:::
