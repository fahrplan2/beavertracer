# 传输层必须做到什么？

:::sim
url=/sims/lesson-5.1.btsim
:::

**Server** 上同时运行着两个服务：一个**Web 服务器**和一个小型**回显服务**，后者会立即把收到的每条消息原样发回。通过两个实验，你会发现仅靠 IP 做不到什么。

## 实验 1：两个程序同时运行

1. 切换到 :fa-play: **运行**模式，点击 **Client-PC**。
2. 打开 :fa-globe: **浏览器**，访问 `http://192.168.0.20/`。
3. 点击窗口顶部的**返回**，然后打开**简单 TCP 客户端**。在 **Host** 中填入 `192.168.0.20`，在 **Port** 中填入 `5000`，然后点击**连接**。
4. 切换到 :fa-magnifying-glass: **追踪**模式，点击 **+** 为 **Client-PC** 的 `eth0` 接口打开一个追踪。

分别点击一个浏览器的数据包（例如 `GET /`）和一个 TCP 客户端的数据包，并展开 **Internet Protocol Version 4**。

:::quiz mc
浏览器和 TCP 客户端的数据包带有哪些 IP 地址？
- [x] 两者相同：从 `192.168.0.10` 发往 `192.168.0.20`
- [ ] 浏览器使用的目的 IP 地址与 TCP 客户端不同
- [ ] TCP 客户端的数据包没有 IP 地址
:::

:::quiz mc
那么，仅凭目的 IP 地址，服务器就足以知道一个数据包属于 Web 服务器还是回显服务吗？
- [ ] 是
- [x] 否 — 两个数据包的目的 IP 地址相同
:::

一定还有别的东西把这两个连接区分开来。看一下带有 `[SYN]` 的数据包的 **Info** 列 — 它们分别是各自连接的第一个数据包：

:::quiz short
**浏览器**的箭头 `→` 后面是哪个数字？
= 80
:::

:::quiz short
**TCP 客户端**的呢？
= 5000
:::

:::evaluate
检查答案
:::

关于这些数字 — 即**端口** — 你将在 5.3 节了解更多。现在只需知道：只有传输层才能让多个程序通过*同一个* IP 地址同时通信，并让每个数据包都到达正确的程序。这称为**多路复用**。

## 实验 2：当数据包丢失时

1. 切换到 :fa-play: **运行**模式，点击 Client-PC 和 Server 之间的**线缆**。
2. 在**连接**窗口中，将**配置的丢包率**设为 `25%`。
3. 在 **Client-PC** 上打开 :fa-terminal: **终端**，发送六个 ping：
   ```
   $ ping -c 6 192.168.0.20
   ```
   这大约需要半分钟 — 请等到统计信息出现。

:::quiz mc
会发生什么？
- [ ] 六个 ping 全部得到响应
- [x] 部分 ping 没有得到响应 — 而且没有人再重新发送它们
- [ ] 丢失的 ping 会被自动重复发送，直到到达为止
:::

:::evaluate
检查答案
:::

对 ping 来说，这不是问题 — 它的作用本来就是显示是否有数据丢失。但对于网页、电子邮件或下载来说，缺失一块就是致命的：文件会损坏。

## 传输层的四项任务

| 任务 | 含义 |
|---|---|
| **多路复用** | 多个程序和连接共用一个 IP 地址；每个数据包都到达正确的程序。 |
| **连接建立** | 在数据传输之前，双方约定彼此进行通信。 |
| **可靠传输** | 接收方确认已收到的内容。缺失的部分会被重新发送，并恢复正确的顺序。 |
| **连接释放** | 最后，双方有序地结束连接。 |

:::tip 要点
**传输层**（第 4 层）确保数据到达正确的**程序**（**多路复用**）。此外，**TCP** 协议还确保数据**完整**且**按正确顺序**到达 — 通过连接建立、确认、重传和连接释放来实现。
:::

:::quiz match
一台 PC 上同时运行着浏览器、邮件程序和即时通讯程序。 -> 多路复用
在数据传输之前，双方确认对方已准备就绪。 -> 连接建立
文件的一部分没有到达，于是被再次发送。 -> 可靠传输
下载结束后，双方重新释放连接。 -> 连接释放
:::
