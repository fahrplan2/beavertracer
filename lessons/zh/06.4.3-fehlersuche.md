# 故障排查：笔记本电脑无法联网

:::sim
url=/sims/lesson-6.4.3.btsim
:::

假期结束后，老师们反馈说：“我们的笔记本电脑连不上网络了！”两台笔记本电脑都设置为 **DHCP**。根据规划，DHCP 服务器应分配从 `192.168.0.100` 到 `192.168.0.120` 的地址，网关为 `192.168.0.1`，DNS 服务器为 `192.168.0.53`。

找出故障并排除。

<details>
<summary>提示 1：笔记本电脑获得了什么地址？</summary>

查看笔记本电脑的 :fa-gear: **IP设置**。如果地址以 `169.254` 开头，说明这是设备**自己**给自己分配的地址——因为没有 DHCP 服务器作出应答。
</details>

<details>
<summary>提示 2：DHCP 服务器有应答吗？</summary>

为一台笔记本电脑打开追踪。你只看到 `DHCP Discover`，还是也看到了应答？然后查看 **DHCP 服务器** 应用：它在运行吗？它分配的是哪个地址范围？
</details>

<details>
<summary>提示 3：重新获取地址</summary>

如果你在服务器上做了修改，请在 IP设置中先把笔记本电脑的模式短暂切换为**静态**，再切换回 **DHCP**，然后点击**应用**——这样它就会重新发出请求。
</details>

:::task
title: 笔记本电脑重新联网了吗？
检查两台笔记本电脑是否都获得了规划范围内的地址，并且能够访问 DHCP 服务器。为此，仿真必须在运行模式下运行。
check: ip(3, "192.168.0.96/27")
check: ip(4, "192.168.0.96/27")
check: pingOk(3, 2)
check: pingOk(4, 2)
:::

## 问题出在哪里？

:::quiz multi
下列哪些说法是正确的？
- [x] DHCP 服务器没有启动——笔记本电脑给自己分配了一个 `169.254` 地址
- [x] 地址范围位于错误的网络中（是 `192.168.1.…` 而不是 `192.168.0.…`）
- [ ] 笔记本电脑被设置为固定地址
- [ ] 交换机上缺少网关
:::

:::evaluate
检查答案
:::

:::tip 要点
如果设备的地址属于 **`169.254.0.0/16`**，说明它**没有收到 DHCP 服务器的应答**，于是自己给自己分配了地址（**APIPA**）。凭这个地址，它只能与同样处境的其他设备通信。此时请检查：DHCP 服务器在运行吗？能访问到它吗？它分配的地址是否来自**正确的网络**？
:::
