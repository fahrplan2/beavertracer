# TLS handshake

:::sim
url=/sims/lesson-8.2.1.btsim
:::

Skôr než sa odošle prvá šifrovaná požiadavka, sa musia klient a server dohodnúť: na postupe, na kľúči relácie — a klient musí overiť, s kým vlastne komunikuje. Toto nadviazanie spojenia sa nazýva **TLS handshake**.

## Priebeh v diagrame

Bez potvrdení TCP (`ACK`) vyzerá handshake takto:

:::seq
mode: text
Client -> Server: Client Hello | Zufallszahl, mögliche Verfahren
Server -> Client: Server Hello | gewähltes Verfahren, Zufallszahl
Server -> Client: Certificate | Zertifikat des Servers
Server -> Client: Server Key Exchange | DH-Anteil, signiert
Server -> Client: Server Hello Done
Client -> Server: Client Key Exchange | DH-Anteil des Clients
Client -> Server: Change Cipher Spec | ab jetzt verschlüsselt
Client -> Server: Encrypted Handshake Message | Finished
Server -> Client: Change Cipher Spec | ab jetzt verschlüsselt
Server -> Client: Encrypted Handshake Message | Finished
Client -> Server: Application Data | GET / (verschlüsselt)
Server -> Client: Application Data | Webseite (verschlüsselt)
:::

Čo sa pritom deje — a ktorý stavebný prvok z kapitoly 8.1 za tým stojí:

1. **Client Hello / Server Hello:** Klient a server sa pozdravia, vymenia si náhodné čísla a dohodnú sa na postupoch (v BeaverTracer: výmena kľúčov pomocou **ECDHE**, podpis pomocou **ECDSA**, šifrovanie pomocou **AES**).
2. **Certificate:** Server pošle svoj **certifikát**. Klient skontroluje podpis CA, platnosť a mená. Ak sa to nepodarí, v tomto bode skončí — a prehliadač zobrazí varovanie.
3. **Server Key Exchange:** Server pošle svoj **podiel Diffie-Hellman** — a **podpíše** ho svojím súkromným kľúčom. Klient overí podpis pomocou verejného kľúča z certifikátu. Vďaka tomu vie: Tento podiel naozaj pochádza od držiteľa certifikátu, nie od útočníka typu Man-in-the-Middle.
4. **Client Key Exchange:** Klient pošle svoj podiel Diffie-Hellman. Teraz môžu obaja vypočítať rovnaký **kľúč relácie** — bez toho, aby sa kedy prenášal.
5. **Change Cipher Spec:** „Odteraz šifrujem.“
6. **Encrypted Handshake Message (Finished):** Obe strany pošlú — už šifrovane — kontrolný súčet zo všetkých doterajších správ handshaku. Ak útočník cestou niečo zmenil, kontrolné súčty sa nezhodujú a spojenie sa preruší.
7. **Application Data:** Odtiaľto tečú dáta HTTP — symetricky šifrované pomocou AES.

:::quiz match
Certificate -> Server sa preukáže svojím certifikátom
Server Key Exchange -> Podpísaný podiel Diffie-Hellman servera
Client Key Exchange -> Podiel Diffie-Hellman klienta
Change Cipher Spec -> Odteraz sa šifruje
Application Data -> Šifrované dáta HTTP
:::

:::note
V stope vidíš **dve** spojenia TLS za sebou: Prehliadač si najprv stiahne stránku a potom nadviaže nové spojenie pre štýl `style.css`. Každé spojenie dostane vlastný handshake a vlastný kľúč relácie. Skutočné prehliadače držia spojenia otvorené, a tak ušetria časť tejto réžie. Novšia verzia **TLS 1.3** si navyše vystačí s menším počtom správ než tu zobrazené TLS 1.2.
:::

:::tip Zapamätaj si
Pri **TLS handshaku** sa server preukáže svojím **certifikátom**, obe strany si pomocou **Diffie-Hellman** dohodnú **kľúč relácie** (server svoj podiel **podpíše**) a správou **Finished** obe overia, že nikto handshake nezmenil. Potom sa dáta prenášajú ako **Application Data** symetricky šifrované.
:::
