# Diagram komunikácie

:::sim
url=/sims/lesson-5.1.btsim
:::

Priebeh spojenia sa zakresľuje ako **diagram komunikácie**: klient a server dostanú každý jednu zvislú čiaru, čas plynie zhora nadol. Každá šípka je jeden paket. Je nakreslená šikmo, pretože každý paket je chvíľu na ceste.

Takto vyzerá tvoje spojenie z poslednej stránky — porovnaj ho riadok po riadku so stopou:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Nad každou šípkou sú **príznaky (flags)**, pod ňou čísla `SEQ` a `ACK`. **DATA** označuje pakety s užitočnými dátami. Červené čísla patria klientovi, modré serveru — čo znamenajú, vysvetlí nasledujúca stránka.

## Príznaky

| Príznak | skratka pre | Význam |
|---|---|---|
| **SYN** | *synchronize* | nadviazať spojenie, určiť počiatočné číslo |
| **ACK** | *acknowledge* | potvrdzuje prijaté dáta |
| **PSH** | *push* | okamžite odovzdať dáta programu |
| **FIN** | *finish* | „Som hotový“ — ukončiť spojenie |
| **RST** | *reset* | prerušiť alebo odmietnuť spojenie (viac v 5.3.2) |

## Tri fázy

**Nadviazanie:** Klient pošle `SYN`, server odpovie `SYN, ACK`, klient potvrdí `ACK`. Pretože sú potrebné presne tri pakety, volá sa to **trojcestný handshake**.

**Dáta:** Každý paket s dátami príjemca potvrdí paketom `ACK`. Tu server posiela späť echo — aj to klient potvrdí.

**Ukončenie:** Každá strana ukončí svoj smer odosielania samostatne: `FIN` od klienta, `ACK` od servera — potom `FIN` od servera, `ACK` od klienta. To sú štyri pakety.

:::tip Zapamätaj si
TCP spojenie prebieha v troch fázach: **nadviazanie** pomocou **trojcestného handshaku** (`SYN` → `SYN, ACK` → `ACK`), **prenos dát** (každý dátový paket sa potvrdzuje paketom `ACK`) a **ukončenie** (každá strana pošle `FIN` a dostane `ACK`).
:::
