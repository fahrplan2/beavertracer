# Čo musí zvládnuť transportná vrstva?

:::sim
url=/sims/lesson-5.1.btsim
:::

Na **serveri** súčasne bežia dve služby: **webový server** a malá **echo služba**, ktorá každú prijatú správu okamžite pošle späť. Dvoma experimentmi zistíš, čo samotný IP nedokáže.

## Experiment 1: Dva programy naraz

1. Prepni sa do režimu :fa-play: **Spustiť** a klikni na **Client-PC**.
2. Otvor :fa-globe: **Prehliadač** a zadaj `http://192.168.0.20/`.
3. Klikni hore v okne na **Zurück** a otvor **Jednoduchý TCP klient**. Do poľa **Host** zadaj `192.168.0.20`, do poľa **Port** zadaj `5000` a klikni na **Pripojiť**.
4. Prepni sa do režimu :fa-magnifying-glass: **Stopa** a pomocou **+** otvor trace pre **Client-PC**, rozhranie `eth0`.

Klikni na paket prehliadača (napr. `GET /`) a na paket TCP klienta a v oboch rozbaľ **Internet Protocol Version 4**.

:::quiz mc
Aké IP adresy majú pakety prehliadača a TCP klienta?
- [x] Pri oboch rovnaké: od `192.168.0.10` pre `192.168.0.20`
- [ ] Prehliadač používa inú cieľovú IP adresu ako TCP klient
- [ ] Pakety TCP klienta nemajú IP adresu
:::

:::quiz mc
Stačí teda cieľová IP adresa na to, aby server vedel, či paket patrí webovému serveru alebo echo službe?
- [ ] Áno
- [x] Nie — oba pakety majú rovnakú cieľovú IP adresu
:::

Tie dve spojenia musí od seba odlíšiť niečo iné. Pozri sa do stĺpca **Info** pri paketoch s `[SYN]` — to je vždy prvý paket spojenia:

:::quiz short
Aké číslo je pri **prehliadači** za šípkou `→`?
= 80
:::

:::quiz short
A pri **TCP klientovi**?
= 5000
:::

:::evaluate
Skontrolovať odpovede
:::

Viac sa o týchto číslach — **portoch** — dozvieš v časti 5.3. Zatiaľ stačí vedieť: až transportná vrstva zabezpečí, že viaceré programy môžu komunikovať súčasne cez *jednu* IP adresu a každý paket skončí pri správnom programe. Toto sa nazýva **multiplexovanie**.

## Experiment 2: Keď sa stratí paket

1. Prepni sa do režimu :fa-play: **Spustiť** a klikni na **kábel** medzi Client-PC a serverom.
2. V okne **Verbindung** nastav **Konfigurierten Paketverlust** na `25%`.
3. Na **Client-PC** otvor :fa-terminal: **Terminál** a pošli šesť pingov:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Trvá to asi pol minúty — počkaj, kým sa zobrazí štatistika.

:::quiz mc
Čo sa stane?
- [ ] Na všetkých šesť pingov príde odpoveď
- [x] Niektoré pingy zostanú bez odpovede — a nikto ich neodošle znova
- [ ] Stratené pingy sa automaticky opakujú, kým nedorazia
:::

:::evaluate
Skontrolovať odpoveď
:::

Pri pingu to nie je problém — jeho účelom je práve ukázať, či sa niečo stráca. Pri webovej stránke, e-maile alebo sťahovaní by však chýbajúci kúsok bol fatálny: súbor by bol poškodený.

## Štyri úlohy transportnej vrstvy

| Úloha | Čo to znamená |
|---|---|
| **Multiplexovanie** | Viaceré programy a spojenia zdieľajú jednu IP adresu; každý paket skončí pri správnom programe. |
| **Nadviazanie spojenia** | Skôr ako začnú prúdiť dáta, obe strany sa dohodnú, že spolu budú komunikovať. |
| **Spoľahlivý prenos** | Príjemca potvrdzuje, čo dorazilo. Chýbajúce dáta sa odošlú znova, poradie sa obnoví. |
| **Ukončenie spojenia** | Na konci obe strany spojenie usporiadane ukončia. |

:::tip Zapamätaj si
**Transportná vrstva** (vrstva 4) zabezpečuje, aby dáta dorazili k správnemu **programu** (**multiplexovanie**). Protokol **TCP** navyše zaisťuje, že dorazia **úplné** a v **správnom poradí** — s nadviazaním spojenia, potvrdeniami, opakovaným prenesením a ukončením spojenia.
:::

:::quiz match
Na jednom PC bežia súčasne prehliadač, poštový program a messenger. -> Multiplexovanie
Skôr ako začnú prúdiť dáta, obe strany zistia, že druhá strana je pripravená. -> Nadviazanie spojenia
Časť súboru nedorazí a odošle sa ešte raz. -> Spoľahlivý prenos
Po stiahnutí obe strany spojenie opäť uvoľnia. -> Ukončenie spojenia
:::

:::
