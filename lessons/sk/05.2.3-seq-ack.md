# Poradové a potvrdzovacie čísla

:::sim
url=/sims/lesson-5.1.btsim
:::

Ako TCP vie, či všetko dorazilo — a v akom poradí? Každá strana **čísluje bajty**, ktoré odosiela:

- **Poradové číslo** (`SEQ`) je číslo prvého bajtu, ktorý je v tomto pakete.
- **Potvrdzovacie číslo** (`ACK`) hovorí: „Dostal som všetko až po tento bajt — ako ďalší očakávam bajt č. …“

K tomu dve pravidlá: `SYN` a `FIN` sa počítajú ako jeden bajt, hoci nenesú žiadne dáta. A každá strana počíta samostatne — preto existujú dva číselné rady, v diagrame červený (klient) a modrý (server).

## Prepočítanie

Tu je ešte raz tvoje spojenie. Čísla pri čiarach ukazujú počítadlo príslušného počítača v danom bode:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Prejdi si červený rad čísel:

1. Klient začína s `SEQ=0`. Jeho `SYN` spotrebuje jedno číslo — server potvrdzuje s `ACK=1`.
2. Správa začína na `SEQ=1` a je dlhá 13 bajtov (bajty 1 až 13). Server potvrdzuje s `ACK=14`: „Ako ďalší očakávam bajt 14.“
3. `FIN` klienta má preto `SEQ=14` a potvrdzuje sa s `ACK=15`.

Modrý rad servera funguje úplne rovnako.

:::tip Zapamätaj si
**Poradové číslo** (`SEQ`) je číslo prvého bajtu v pakete. **Potvrdzovacie číslo** (`ACK`) je číslo ďalšieho bajtu, ktorý príjemca očakáva — všetko pred ním dorazilo. Platí: **ACK = SEQ + dĺžka** prijatých dát; `SYN` a `FIN` sa počítajú ako jeden bajt. Každá strana počíta svoje vlastné bajty.
:::

:::tip Vyskúšaj si to
Vytvor spojenie v **Jednoduchý TCP klient** ešte raz a pošli dve správy za sebou. Najprv povedz, aké `Seq` a `Ack` budú v stĺpci **Info** — a potom to skontroluj v stope.
:::

## Precvičovanie

:::quiz short
Klient pošle paket so `Seq=1` a `Len=13`. Aké potvrdzovacie číslo pošle server späť?
= 14
:::

:::quiz short

= 14
:::

:::note
V skutočných sieťach sa počítanie nezačína od 0: každá strana si zvolí **náhodné počiatočné číslo** (*Initial Sequence Number*, ISN) medzi 0 a približne 4,3 miliardy. Keď sa dosiahne najvyššie číslo, pokračuje sa opäť od 0. Tracer počiatočné číslo odpočíta a zobrazuje **relatívne** čísla — presne ako Wireshark. Preto vidíš `Seq=0` a `Seq=1`.

Okrem toho je v každom pakete `Win=` — **veľkosť okna**: toľko bajtov môže príjemca práve prijať. Tým brzdí príliš rýchleho odosielateľa (*riadenie toku*). V BeaverTracer je okno vždy rovnako veľké.
:::
