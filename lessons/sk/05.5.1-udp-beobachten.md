# Pozorovanie UDP

:::sim

Na **Serveri** tentoraz beží **UDP Echo-Server** na porte `5000`. Aj tu je kábel pripravený: **druhý datagram** od Client-PC k serveru sa stratí.

## Experiment

1. Prepni sa do :fa-play: režimu **Spustiť** a na **Client-PC** otvor :fa-terminal: **Terminál**.
2. Pomocou `nc` spusti UDP „spojenie“ so serverom (`-u` znamená UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Postupne napíš `eins`, `zwei` a `drei` a po každom stlač **Enter**. Každý riadok, ktorý sa vráti, je ozvena (echo) zo servera.
4. Počkaj niekoľko sekúnd a potom v režime :fa-magnifying-glass: **Stopa** otvor trace pre **Client-PC**.

:::quiz mc
Ktoré ozveny sa vrátia?
- [ ] Všetky tri, `zwei` o niečo neskôr
- [x] Iba `eins` a `drei` — `zwei` chýba a ani sa neposiela znova
- [ ] Žiadna
:::

:::quiz multi
Ktoré pakety, ktoré poznáš z TCP, pri UDP úplne chýbajú?
- [x] Nadviazanie spojenia (`SYN`)
- [x] Potvrdenia (`ACK`)
- [x] Ukončenie spojenia (`FIN`)
- [ ] Pakety s číslami portov
:::

:::evaluate
Skontrolovať odpovede
:::

Klikni na jeden z UDP paketov a rozbaľ **User Datagram Protocol**. V porovnaní s hlavičkou TCP je hlavička UDP drobná: **Source Port**, **Destination Port**, **Length** (dĺžka) a **Checksum** (kontrolný súčet) — dohromady len 8 bajtov. Hlavička TCP má aspoň 20 bajtov, s poradovým a potvrdzovacím číslom, príznakmi a veľkosťou okna.

:::quiz mc
Ktorú úlohu z časti 5.1 UDP napriek tomu plní?
- [x] Multiplexovanie — pomocou portov
- [ ] Nadviazanie spojenia
- [ ] Spoľahlivý prenos
:::

:::evaluate
Skontrolovať odpoveď
:::

:::tip Zapamätaj si
**UDP** je **nespojované**: bez nadviazania spojenia, bez potvrdzovania, bez opakovaného prenesenia, bez zachovania poradia. Ponúka iba **porty** (multiplexovanie) a **kontrolný súčet**. Za to je rýchle a štíhle — hlavička UDP má iba 8 bajtov. Ak sa datagram stratí, musí sa o to postarať samotný program — alebo mu je to jedno.
:::
