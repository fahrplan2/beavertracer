# Numery sekwencyjne i numery potwierdzenia

:::sim
url=/sims/lesson-5.1.btsim
:::

Skąd TCP wie, czy wszystko dotarło — i w jakiej kolejności? Każda strona **numeruje bajty**, które wysyła:

- **Numer sekwencyjny** (`SEQ`) to numer pierwszego bajtu zawartego w tym pakiecie.
- **Numer potwierdzenia** (`ACK`) mówi: „Do tego miejsca otrzymałem wszystko — jako następny oczekuję bajtu nr …"

Do tego dwie zasady: `SYN` i `FIN` liczą się jak jeden bajt, chociaż nie niosą danych. Poza tym każda strona liczy osobno — dlatego na diagramie są dwie osobne numeracje: czerwona (klient) i niebieska (serwer).

## Sprawdź obliczenia

Oto jeszcze raz Twoje połączenie. Liczby przy liniach pokazują stan licznika danego komputera w tym miejscu:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Przejdź przez czerwony ciąg liczb:

1. Klient zaczyna od `SEQ=0`. Jego `SYN` zużywa jeden numer — serwer potwierdza przez `ACK=1`.
2. Wiadomość zaczyna się od `SEQ=1` i ma długość 13 bajtów (bajty od 1 do 13). Serwer potwierdza przez `ACK=14`: „Jako następny oczekuję bajtu 14."
3. Dlatego `FIN` klienta ma `SEQ=14` i jest potwierdzany przez `ACK=15`.

Niebieski ciąg liczb serwera działa dokładnie tak samo.

:::tip Zapamiętaj
**Numer sekwencyjny** (`SEQ`) to numer pierwszego bajtu w pakiecie. **Numer potwierdzenia** (`ACK`) to numer następnego bajtu, którego oczekuje odbiorca — wszystko przed nim dotarło. Obowiązuje zasada: **ACK = SEQ + długość** odebranych danych; `SYN` i `FIN` liczą się jak jeden bajt. Każda strona liczy własne bajty.
:::

:::tip Wypróbuj
Nawiąż połączenie w **Prostym kliencie TCP** jeszcze raz i wyślij dwie wiadomości jedna po drugiej. Powiedz wcześniej, jakie wartości `Seq` i `Ack` pojawią się w kolumnie **Info** — i sprawdź to w śladzie.
:::

:::note
W prawdziwych sieciach liczenie nie zaczyna się od 0: każda strona wybiera **losowy numer początkowy** (*Initial Sequence Number*, ISN) z zakresu od 0 do około 4,3 miliarda. Gdy osiągnięty zostanie najwyższy numer, liczenie zaczyna się znowu od 0. Tracer odejmuje numer początkowy i pokazuje numery **względne** — tak samo jak Wireshark. Dlatego widzisz `Seq=0` i `Seq=1`.

Poza tym w każdym pakiecie znajduje się `Win=` — **rozmiar okna**: tyle bajtów odbiorca jest w stanie w danym momencie przyjąć. W ten sposób hamuje zbyt szybkiego nadawcę (*kontrola przepływu*). W BeaverTracer okno ma zawsze ten sam rozmiar.
:::
