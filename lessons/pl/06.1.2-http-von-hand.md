# HTTP ręcznie

:::sim

:::

Skoro HTTP to zwykły tekst — czy można samemu porozmawiać z serwerem WWW, zupełnie bez przeglądarki? Tak: za pomocą `telnet` nawiązujesz połączenie TCP z dowolnym portem i sam wpisujesz tekst.

## Eksperyment

1. Przełącz się w tryb uruchamiania :fa-play: **Uruchom** i otwórz :fa-terminal: **Terminal** na komputerze **Client-PC**.
2. Połącz się z portem 80 serwera:
   ```
   $ telnet 192.168.0.20 80
   ```
3. Wpisuj zapytanie wiersz po wierszu — i zakończ je **pustym wierszem** (po prostu naciśnij jeszcze raz **Enter**):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

Serwer odpowiada wierszem statusu, nagłówkami i stroną kontaktową — jako tekst, dokładnie tak, jak otrzymuje ją przeglądarka.

- [x] Po pustym wierszu

:::

## Wywoływanie błędów

Wygodniejszym narzędziem jest `curl`: wysyła zapytanie za Ciebie. Z opcją `-v` (*verbose*, czyli szczegółowo) pokazuje przy tym wszystko, co jest wysyłane w obie strony — wiersze z `>` wysłał `curl`, a wiersze z `<` przyszły z serwera.

Wypróbuj:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::quiz short
Jaki kod statusu otrzymujesz dla `/gibtsnicht.html`?
= 404
:::

:::quiz short
A jaki dla zapytania z metodą `POST`?

:::

:::note
Serwer WWW w BeaverTracer potrafi tylko udostępniać pliki — dlatego dopuszcza wyłącznie `GET` i `HEAD`. Prawdziwe serwery WWW przyjmują za pomocą `POST` na przykład formularze i przekazują dane do programu.
:::

:::tip Zapamiętaj
Wiele protokołów warstwy aplikacji jest **tekstowych** — HTTP, ale także SMTP, POP3 i IMAP. Dlatego możesz „rozmawiać” nimi ręcznie za pomocą `telnet` i podglądać je w Tracerze. Jest to praktyczne przy diagnozowaniu błędów — ale też stanowi problem dla bezpieczeństwa: każdy, kto przechwytuje ruch, może wszystko przeczytać. Jak pomaga szyfrowanie (HTTPS), dowiesz się w rozdziale 8.
:::
