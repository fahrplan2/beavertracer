# Jak zorganizowany jest DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Żaden pojedynczy serwer nie może znać wszystkich nazw na świecie. Dlatego DNS ma budowę **hierarchiczną** — tak samo jak same nazwy. Czyta się je od prawej do lewej:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Serwer, który odpowiada za daną domenę i naprawdę zna odpowiedź, nazywa się **autorytatywnym**. Drogę do niego pokonuje za komputer **resolver** — tutaj jest nim komputer **DNS-Resolver**.

## Eksperyment

1. Przełącz się w :fa-play: tryb uruchamiania (**Uruchom**) i wpisz na **Client-PC** w :fa-terminal: **Terminalu**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. W trybie :fa-magnifying-glass: **Ślad** otwórz ślad dla **DNS-Resolver**.

Resolver wysłał za ciebie całą serię zapytań. Przyporządkuj, kto udzielił której odpowiedzi:

:::quiz match
Root-Server (192.168.0.101) -> Odesłanie: Za .de odpowiada ns.nic.de
de-Server (192.168.0.102) -> Odesłanie: Za beaver-schule.de odpowiada ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Odpowiedź: www.beaver-schule.de ma adres 192.168.0.20
:::

:::quiz mc
Kogo resolver pyta jako pierwszego?
- [x] Serwer główny (root)
- [ ] Schul-DNS
- [ ] Client-PC
:::

:::evaluate
Sprawdź odpowiedzi
:::

:::note
Po drodze resolver pyta też o adresy serwerów, do których został odesłany (`A ns.nic.de`). Prawdziwe serwery DNS zwykle dołączają te adresy od razu do odpowiedzi. Ponadto resolvery zapamiętują każdą odpowiedź na jakiś czas (**cache**) — na kolejne zapytanie o tę samą nazwę odpowiadają od razu same. Jak długo, podaje wpis jako **TTL** (*Time to Live*) w sekundach.
:::

## Najważniejsze typy wpisów

| Typ | Znaczenie | Przykład |
|---|---|---|
| **A** | nazwa → adres IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | nazwa → adres IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | nazwa → inna nazwa (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | serwer pocztowy odpowiedzialny za domenę | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | serwer DNS odpowiedzialny za domenę | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Zapamiętaj
DNS jest **hierarchiczny**: **serwery główne (root)** odsyłają do serwerów **domen najwyższego poziomu** (np. `.de`), te z kolei do serwerów poszczególnych **domen**. Właściwy serwer **autorytatywny** zna odpowiedź. **Resolver** pokonuje tę drogę za komputer i zapamiętuje odpowiedzi (**cache**). Ważne typy wpisów: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Dodawanie wpisu

Szkoła chce, aby jej strona internetowa była dodatkowo dostępna pod adresem `intranet.beaver-schule.de`.

1. W :fa-play: trybie uruchamiania (**Uruchom**) kliknij **Schul-DNS** i otwórz aplikację **DNS-Server**.
2. Otwórz kartę **A**. Kliknij **+** i wpisz w nowym wierszu nazwę `intranet.beaver-schule.de` oraz adres `192.168.0.20`.
3. Przetestuj na Client-PC poleceniem `nslookup intranet.beaver-schule.de`.

:::task
title: Czy nowa nazwa jest wpisana?
Sprawdza, czy Client-PC rozwiązuje nazwę intranet.beaver-schule.de na adres serwera WWW. Symulacja musi być w tym celu uruchomiona w trybie uruchamiania.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
