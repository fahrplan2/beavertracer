## Eksperyment

1. Przełącz się w tryb uruchamiania :fa-play: **Uruchom**, kliknij **Client-PC** i otwórz :fa-globe: **Przeglądarka**. Wejdź na `http://192.168.0.20/`.
2. Kliknij u góry okna **Zurück**, otwórz **Prosty klient TCP** i połącz go z `192.168.0.20`, port `5000`. Pozostaw połączenie otwarte.
3. Przełącz się w tryb :fa-magnifying-glass: **Ślad**, otwórz trace dla **Client-PC** i kliknij pakiet z `[SYN]`. Rozwiń **Transmission Control Protocol**.

Na samej górze nagłówka TCP znajdują się dwa porty: **Source Port** (port źródłowy) i **Destination Port** (port docelowy).

| Połączenie | Port źródłowy | Port docelowy |
|---|---|---|
| Przeglądarka → serwer WWW | {49152} | {80} |
| Klient TCP → usługa echa | {49153} | {5000} |

## Dwa rodzaje portów

**Port docelowy — usługa:** Program serwerowy oczekuje na połączenia na stałym porcie — mówi się, że tam **nasłuchuje**. Dla znanych usług numery są ustalone globalnie — to tzw. **porty powszechnie znane** (*well-known ports*, od 0 do 1023). Dlatego przeglądarka wie bez pytania: serwery WWW nasłuchują na porcie 80.

**Port źródłowy — nadawca:** Port po stronie klienta system operacyjny wybiera sam dla każdego nowego połączenia z wysokiego zakresu (w BeaverTracer od 49152). Dzięki niemu klient rozpoznaje, do którego z jego połączeń należy odpowiedź.

Połączenie jest więc jednoznacznie określone przez cztery wartości: **adres IP i port po obu stronach**. Parę złożoną z adresu IP i portu nazywa się **gniazdem** (*socket*), np. `192.168.0.20:80`.

## Rzut oka na serwer

Wróć do trybu uruchamiania :fa-play: **Uruchom**, otwórz na **Server** :fa-terminal: **Terminal** i wpisz:

```
$ ss
```

`ss` pokazuje wszystkie gniazda komputera. Wiersze z `LISTEN` to programy nasłuchujące na porcie. Wiersze z `ESTABLISHED` to istniejące połączenia — z własnym gniazdem (*Local Address:Port*) i gniazdem drugiej strony (*Peer Address:Port*).

:::quiz multi

- [x] 80
- [x] 5000
- [ ] 49152
- [ ] 443
:::

:::quiz mc

- [ ] `192.168.0.20:80` z `192.168.0.10:49152` — połączenie przeglądarki
- [ ] Oba
:::

:::note
Połączenie przeglądarki zostało już zakończone — po załadowaniu strony zamknięto je za pomocą `FIN`. `ss` pokazuje je jeszcze przez chwilę jako `TIME-WAIT`: serwer czeka jakiś czas, czy nie nadejdą jeszcze opóźnione pakiety tego połączenia. Połączenie klienta TCP jest natomiast nadal otwarte, ponieważ nie kliknąłeś jeszcze **Rozłącz**.
:::

## Najważniejsze porty powszechnie znane

| Port | Protokół | Usługa |
|---|---|---|
| 22 | SSH | bezpieczne zdalne zarządzanie (szyfrowany wiersz poleceń) |
| 25 | SMTP | wysyłanie e-maili |
| 53 | DNS | tłumaczenie nazw na adresy IP (najczęściej przez UDP) |
| 80 | HTTP | strony internetowe |
| 110 | POP3 | pobieranie e-maili |
| 143 | IMAP | zarządzanie e-mailami na serwerze |
| 443 | HTTPS | szyfrowane strony internetowe |

:::tip Zapamiętaj
**Porty** (od 0 do 65535) pozwalają rozróżniać połączenia na jednym komputerze. Usługi serwerowe **nasłuchują** na stałych **portach powszechnie znanych** (np. HTTP 80, HTTPS 443), a klienci dostają dla każdego połączenia wolny, wysoki **port źródłowy**. Połączenie jest jednoznacznie określone przez **adres IP i port obu stron**.
:::

:::quiz match
22 -> SSH
25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
