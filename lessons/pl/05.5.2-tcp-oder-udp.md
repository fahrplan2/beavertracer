# TCP czy UDP?

| | TCP | UDP |
|---|---|---|
| Połączenie | nawiązywanie z trójetapowym uzgadnianiem (three-way handshake), uporządkowane zamykanie | brak — każdy datagram jest niezależny |
| Potwierdzenia | tak (`ACK`) | nie |
| Utracone dane | są wysyłane ponownie | pozostają utracone |
| Kolejność | jest odtwarzana | nie jest gwarantowana |
| Nagłówek | co najmniej 20 bajtów | 8 bajtów |
| Szybkość | nieco wolniejszy, więcej pakietów | szybki, mały narzut |

Kiedy mniej znaczy więcej?

- **Czas rzeczywisty:** przy rozmowach wideo, telefonii internetowej czy grach online liczy się każda milisekunda. Utracony fragment dźwięku, który dotarłby sekundę później, nikomu się już nie przyda — lepiej usłyszeć krótki trzask niż mieć opóźnienie.
- **Krótkie zapytania:** zapytanie **DNS** („Jaki adres IP ma `www.beispiel.de`?") mieści się w jednym datagramie, odpowiedź zresztą też. Nawiązywanie połączenia potroiłoby nakład pracy. Jeśli odpowiedź nie nadejdzie, program po prostu pyta jeszcze raz.

Wszędzie tam, gdzie musi dotrzeć każdy bajt — strony internetowe, e-maile, pobieranie plików — właściwym wyborem jest natomiast TCP.

:::tip Zapamiętaj
**TCP** jest niezawodny, ale bardziej kosztowny — dla wszystkiego, co musi dotrzeć **w całości** (web, e-mail, pliki). **UDP** jest szybki i lekki, ale bez gwarancji — dla **czasu rzeczywistego** (telefonia, wideo, gry) i **krótkich zapytań**, takich jak DNS.
:::

Znasz już narzędzia warstwy transportowej. W następnym rozdziale przyjrzysz się protokołom, które na niej bazują: HTTP, DNS, e-mail i DHCP.
