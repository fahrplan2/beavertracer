# Atak: fałszowanie DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

Anna chce otworzyć na **Client-PC** swoje konto w bankowości internetowej w **Biberbank**. Nie wie jednak, że ktoś uzyskał dostęp do **DNS-Server** i zmienił jeden wpis.

Na obszarze roboczym widzisz prawdziwy serwer WWW **www.biberbank.de** oraz komputer **atakującego**. Działa na nim kopia strony internetowej banku.

## Część 1: bez szyfrowania

Przełącz się w tryb uruchamiania :fa-play: **Uruchom** i na **Client-PC** otwórz w :fa-globe: **Przeglądarka** adres `http://www.biberbank.de/`.

:::quiz mc
Co widzisz?
- [x] Stronę logowania Biberbank, bez żadnego ostrzeżenia
- [ ] Ostrzeżenie, że strona jest fałszywa
- [ ] Komunikat o błędzie
:::

:::evaluate
Sprawdź odpowiedź
:::

Wszystko wygląda normalnie. Ale z którym serwerem przeglądarka naprawdę się łączy? Otwórz na Client-PC :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Jaki adres IP zwraca serwer DNS dla `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
Do kogo należy ten adres? (Kliknij urządzenia w trybie edycji lub zajrzyj do ich :fa-gear: **Ustawienia IP**.)
- [ ] Do prawdziwego serwera WWW Biberbank
- [x] Do atakującego
- [ ] Do serwera DNS
:::

:::evaluate
Sprawdź odpowiedzi
:::

Gdyby Anna wpisała teraz numer konta i PIN, trafiłyby one prosto do atakującego. Przy **HTTP** nie ma **żadnych szans**, by zauważyć oszustwo: pasek adresu pokazuje właściwą nazwę, a strona wygląda autentycznie.

## Część 2: z HTTPS

Otwórz teraz `https://www.biberbank.de/`.

:::quiz mc
Co się dzieje?
- [ ] Pojawia się fałszywa strona z kłódką
- [x] Przeglądarka ostrzega: certyfikat został wystawiony dla innej nazwy
- [ ] Pojawia się prawdziwa strona Biberbank
:::

:::quiz short
Dla jakiej nazwy został wystawiony certyfikat atakującego (bez `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Sprawdź odpowiedzi
:::

Atakujący ma nawet **prawdziwy** certyfikat zaufanego CA — ale dla swojej własnej domeny `www.biber-gewinnspiel.de`. Certyfikatu dla `www.biberbank.de` nie dostanie od żadnego CA, ponieważ ta domena do niego nie należy. A bez **klucza prywatnego** Biberbank nie może też użyć jej prawdziwego certyfikatu: podczas uzgadniania połączenia (handshake) musiałby nim podpisać Server Key Exchange.

:::quiz multi
Przed czym HTTPS chroni w tym przypadku — a przed czym nie?
- [x] HTTPS ujawnia, że serwer nie jest prawdziwy
- [ ] HTTPS zapobiega sfałszowaniu serwera DNS
- [x] HTTPS pomaga tylko wtedy, gdy użytkownik poważnie traktuje ostrzeżenie
- [ ] Przy HTTPS fałszywa strona jest w ogóle nieosiągalna
:::

:::evaluate
Sprawdź odpowiedzi
:::

## Część 3: naprawa serwera DNS

Otwórz **DNS-Server** i popraw wpis dla `www.biberbank.de`. Właściwy adres znajdziesz w :fa-gear: **Ustawienia IP** serwera WWW **www.biberbank.de**. Nie zapomnij kliknąć **Zapisz**.

:::note
Client-PC zapamiętuje odpowiedzi DNS na jakiś czas, aby nie musiał pytać przy każdym otwarciu strony (**pamięć podręczna DNS**). Jak długo, podaje kolumna **TTL** (*Time to Live*) w sekundach. Jeśli `nslookup` zaraz po twojej poprawce nadal zwraca stary adres, poczekaj, aż upłynie TTL, i spróbuj jeszcze raz.
:::

:::task
title: Biberbank znowu prawdziwy?
Sprawdza, czy Client-PC rozwiązuje www.biberbank.de na właściwy adres i czy może pobrać stronę przez HTTPS bez ostrzeżenia.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
W rzeczywistości atakujący rzadko fałszuje sam serwer DNS. Częściej podsuwa swoje odpowiedzi w publicznej sieci Wi-Fi, zmienia ustawienia routera domowego albo wabi podobnie wyglądającym adresem, takim jak `www.biberbank-login.de` (**phishing**). Przed podobnie brzmiącą nazwą HTTPS również nie chroni — atakujący dostanie dla niej ważny certyfikat. Dlatego: czytaj adres dokładnie!
:::

:::tip Zapamiętaj
Przy **fałszowaniu DNS** serwer DNS zwraca dla danej nazwy adres atakującego. Przy **HTTP** nic się nie zauważa. Przy **HTTPS** certyfikat atakującego nie pasuje do wywołanej nazwy, a przeglądarka **ostrzega** — żadne CA nie wystawia bowiem certyfikatu dla cudzych domen, a klucza prywatnego prawdziwego serwera atakujący nie ma.
:::
