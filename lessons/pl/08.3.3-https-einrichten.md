# Konfiguracja HTTPS

:::sim
url=/sims/lesson-8.3.3.btsim

Tutaj kontynuujemy od miejsca, w którym skończył się podrozdział 8.2.2: na serwerze WWW **www.beaver-schule.de** znajdują się **Schul-CA** oraz wystawiony przez nią certyfikat serwera, a **Client-PC** ufa Schul-CA. Tylko że serwer WWW jeszcze nie obsługuje HTTPS.

## Przed konfiguracją

Przełącz się w tryb uruchamiania :fa-play: **Uruchom** i na **Client-PC** otwórz w :fa-globe: **Przeglądarce** adres `https://www.beaver-schule.de/`.

:::quiz mc
Co się stanie?
- [x] Połączenie nie zostanie nawiązane — na porcie 443 nie nasłuchuje żadna usługa
- [ ] Przeglądarka ostrzeże przed niezaufanym certyfikatem
- [ ] Strona zostanie wyświetlona bez kłódki
:::

Sprawdź odpowiedź

## Włączanie HTTPS

1. Otwórz na serwerze WWW **Serwer HTTP** i kliknij **Zatrzymaj** — dopóki serwer działa, nie można zmieniać ustawień.
2. Przejdź na kartę **HTTPS**:
    - Zaznacz **Włącz HTTPS**, **Port HTTPS** `443`
    - W polu **Certyfikat** wybierz certyfikat serwera `www.beaver-schule.de` — nie Schul-CA!
    - Kliknij **Użyj**
3. Kliknij **Uruchom**.

Otwórz stronę na Client-PC ponownie, tym razem przez `https://`. Kliknij kłódkę i sprawdź wystawcę oraz okres ważności.

:::task
title: HTTPS skonfigurowane?
Sprawdza, czy Client-PC może pobrać https://www.beaver-schule.de/ bez ostrzeżenia o certyfikacie. Symulacja musi w tym celu działać w trybie uruchamiania.
check: httpsOk(2, "https://www.beaver-schule.de/")
:::

:::quiz mc
Dlaczego w Serwerze HTTP nie wolno wybrać certyfikatu **Schul-CA**?
- [ ] Ponieważ certyfikaty CA nie potrafią szyfrować
- [x] Ponieważ jest wystawiony dla nazwy `Schul-CA`, a nie dla `www.beaver-schule.de` — przeglądarka by ostrzegła
- [ ] Ponieważ Schul-CA nie ma klucza prywatnego
:::

:::quiz mc
Co zobaczy urządzenie, które **nie** ufa Schul-CA, np. telefon gościa?
- [ ] Stronę całkiem normalnie, z kłódką
- [x] Ostrzeżenie o certyfikacie, ponieważ nie może prześledzić łańcucha zaufania aż do znanego urzędu certyfikacji (CA)
- [ ] Nic, ponieważ połączenie zostanie odrzucone
:::

:::note
Publiczne strony internetowe potrzebują certyfikatu wystawionego przez CA, która jest preinstalowana we wszystkich przeglądarkach. Od 2015 roku istnieje **Let's Encrypt** — CA, która wystawia takie certyfikaty bezpłatnie i automatycznie. To jeden z głównych powodów, dla których dziś niemal wszystkie strony używają HTTPS.
:::

:::tip Zapamiętaj
Do **HTTPS** serwer WWW potrzebuje **certyfikatu serwera z kluczem prywatnym**, którego nazwa pasuje do adresu, oraz musi nasłuchiwać na **porcie 443**. Klient ufa stronie tylko wtedy, gdy zna wystawiającą ją **CA**.
:::
