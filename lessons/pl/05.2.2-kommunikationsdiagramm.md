# Diagram komunikacji

:::sim
url=/sims/lesson-5.1.btsim
:::

Przebieg połączenia rysuje się jako **diagram komunikacji**: klient i serwer otrzymują po jednej pionowej linii, a czas płynie z góry na dół. Każda strzałka to jeden pakiet. Jest narysowana ukośnie, ponieważ każdy pakiet jakiś czas jest w drodze.

Tak wygląda twoje połączenie z poprzedniej strony — porównaj je wiersz po wierszu ze śladem:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Nad każdą strzałką znajdują się **flagi**, pod nią numery `SEQ` i `ACK`. **DATA** oznacza pakiety z danymi użytkowymi. Czerwone liczby należą do klienta, niebieskie do serwera — co oznaczają, wyjaśnia następna strona.

## Flagi

| Flaga | skrót od | Znaczenie |
|---|---|---|
| **SYN** | *synchronize* | nawiązanie połączenia, ustalenie numeru początkowego |
| **ACK** | *acknowledge* | potwierdza odebrane dane |
| **PSH** | *push* | natychmiastowe przekazanie danych do programu |
| **FIN** | *finish* | „Skończyłem” — zakończenie połączenia |
| **RST** | *reset* | przerwanie lub odrzucenie połączenia (więcej w 5.3.2) |

## Trzy fazy

**Nawiązanie:** klient wysyła `SYN`, serwer odpowiada `SYN, ACK`, klient potwierdza pakietem `ACK`. Ponieważ potrzebne są dokładnie trzy pakiety, nazywa się to **trójetapowym uzgadnianiem** (ang. *three-way handshake*).

**Dane:** każdy pakiet z danymi jest potwierdzany przez odbiorcę pakietem `ACK`. Tutaj serwer odsyła echo — klient również je potwierdza.

**Zakończenie:** każda ze stron osobno kończy swój kierunek wysyłania: `FIN` od klienta, `ACK` od serwera — następnie `FIN` od serwera, `ACK` od klienta. To cztery pakiety.

:::tip Zapamiętaj
Połączenie TCP przebiega w trzech fazach: **nawiązanie** za pomocą **trójetapowego uzgadniania** (`SYN` → `SYN, ACK` → `ACK`), **przesyłanie danych** (każdy pakiet z danymi jest potwierdzany pakietem `ACK`) i **zakończenie** (każda strona wysyła `FIN` i otrzymuje `ACK`).
:::
