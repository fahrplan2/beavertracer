# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) to zwykły HTTP — tylko że nie działa bezpośrednio nad TCP, lecz przez szyfrowaną warstwę pośrednią: **TLS** (*Transport Layer Security*). Poprzednik TLS nazywał się **SSL**; dlatego nadal często mówi się o „certyfikatach SSL”.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP nic o tym nie wie: wysyła swoje zapytania jak zwykle, TLS je szyfruje, a TCP je transportuje. W modelu OSI TLS znajduje się między warstwą transportową a warstwą aplikacji, czyli w warstwie 4/5 — opiera się na TCP i zarządza zabezpieczoną sesją.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adres | `http://…` | `https://…` |
| Zawartość czytelna w Tracerze? | tak | nie |
| Przeglądarka pokazuje | „niezabezpieczona” | kłódkę |

Podczas nawiązywania połączenia TLS robi wszystko, czego nauczyłeś(-aś) się w tym rozdziale:

- Serwer potwierdza swoją tożsamość za pomocą **certyfikatu** (**autentyczność**).
- Obie strony uzgadniają za pomocą **Diffiego-Hellmana** **klucz sesyjny** — serwer **podpisuje** swoją część.
- Potem wszystkie dane są szyfrowane za pomocą **AES** (**poufność**) i zabezpieczone przed modyfikacją (**integralność**).

Ta zasada nie ogranicza się do sieci WWW: również poczta e-mail (podrozdział 8.4) i wiele innych protokołów działa w ten sam sposób przez TLS.

W kolejnych podrozdziałach zaobserwujesz HTTPS w Tracerze, sam(a) go skonfigurujesz i sprawdzisz, kiedy przeglądarka ostrzega — i dlaczego.
