# Obserwowanie UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

Na **Serwerze** działa tym razem **Serwer Echo UDP** na porcie `5000`. Także tutaj kabel jest przygotowany: **drugi datagram** wysłany z Client-PC do Serwera ginie.

## Eksperyment

1. Przełącz się do trybu :fa-play: **Uruchom** i otwórz na **Client-PC** :fa-terminal: **Terminal**.
2. Za pomocą `nc` rozpocznij „połączenie” UDP z serwerem (`-u` oznacza UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Wpisz kolejno `eins`, `zwei` i `drei` i za każdym razem naciśnij **Enter**. Każda linia, która wróci, jest echem z serwera.
4. Odczekaj kilka sekund, a następnie w trybie :fa-magnifying-glass: **Ślad** otwórz trace dla **Client-PC**.

:::quiz mc
Które echa wrócą?
- [ ] Wszystkie trzy, `zwei` nieco później
- [x] Tylko `eins` i `drei` — `zwei` brakuje i nie jest też wysyłane ponownie
- [ ] Żadne
:::

:::quiz multi
Których pakietów, które znasz z TCP, całkowicie brakuje w UDP?
- [x] Nawiązywanie połączenia (`SYN`)
- [x] Potwierdzenia (`ACK`)
- [x] Zamykanie połączenia (`FIN`)
- [ ] Pakiety z numerami portów
:::

:::evaluate
Sprawdź odpowiedzi
:::

Kliknij jeden z pakietów UDP i rozwiń **User Datagram Protocol**. W porównaniu z nagłówkiem TCP nagłówek UDP jest malutki: **Source Port**, **Destination Port**, **Length** (długość) i **Checksum** (suma kontrolna) — razem tylko 8 bajtów. Nagłówek TCP ma co najmniej 20 bajtów, z numerem sekwencyjnym i numerem potwierdzenia, flagami i rozmiarem okna.

:::quiz mc
Które zadanie z sekcji 5.1 UDP mimo wszystko realizuje?
- [x] Multipleksowanie — za pomocą portów
- [ ] Nawiązywanie połączenia
- [ ] Niezawodną transmisję
:::

:::tip Zapamiętaj
**UDP** jest **bezpołączeniowy**: brak nawiązywania połączenia, brak potwierdzeń, brak retransmisji, brak zachowania kolejności. Oferuje tylko **porty** (multipleksowanie) i **sumę kontrolną**. Za to jest szybki i lekki — nagłówek UDP ma tylko 8 bajtów. Jeśli datagram zginie, program musi sam sobie z tym poradzić — albo jest mu to obojętne.
:::
