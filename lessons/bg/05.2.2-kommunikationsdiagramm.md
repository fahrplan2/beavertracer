# Диаграмата на комуникацията

:::sim
url=/sims/lesson-5.1.btsim
:::

Протичането на една връзка се чертае като **диаграма на комуникацията**: клиентът и сървърът получават по една вертикална линия, а времето тече отгоре надолу. Всяка стрелка е един пакет. Тя е начертана наклонено, защото всеки пакет известно време е на път.

Ето как изглежда твоята връзка от предишната страница — сравни я ред по ред с трасето:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Над всяка стрелка стоят **флаговете**, а под нея — номерата `SEQ` и `ACK`. **DATA** маркира пакетите с полезни данни. Червените числа принадлежат на клиента, сините — на сървъра; какво означават, ще разгледаме на следващата страница.

## Флаговете

| Флаг | означава | Значение |
|---|---|---|
| **SYN** | *synchronize* | установяване на връзка, определяне на начален номер |
| **ACK** | *acknowledge* | потвърждава получени данни |
| **PSH** | *push* | предава данните веднага на програмата |
| **FIN** | *finish* | „Свърших“ — прекратяване на връзката |
| **RST** | *reset* | прекъсва или отхвърля връзка (повече за това в 5.3.2) |

## Три фази

**Установяване:** Клиентът изпраща `SYN`, сървърът отговаря със `SYN, ACK`, а клиентът потвърждава с `ACK`. Тъй като са необходими точно три пакета, това се нарича **тристранно ръкостискане** (three-way handshake).

**Данни:** Всеки пакет с данни се потвърждава от получателя с `ACK`. Тук сървърът връща ехото — и него клиентът го потвърждава.

**Прекратяване:** Всяка страна приключва своята посока на изпращане поотделно: `FIN` от клиента, `ACK` от сървъра — после `FIN` от сървъра, `ACK` от клиента. Това са четири пакета.

:::tip Запомни
Една TCP връзка протича на три фази: **установяване** с **тристранното ръкостискане** (`SYN` → `SYN, ACK` → `ACK`), **предаване на данни** (всеки пакет с данни се потвърждава с `ACK`) и **прекратяване** (всяка страна изпраща `FIN` и получава `ACK`).
:::

## Сега ти

Този път клиентът изпраща само `Hi` (4 байта заедно с края на реда). Попълни липсващите флагове — редът в рамките на едно поле няма значение.

:::quiz seq
hide: counters
Client-PC -> Server: ? SYN
Server -> Client-PC: ? SYN, ACK
Client-PC -> Server: ? ACK
Client-PC -> Server: PSH, ACK "Hi" len=4
Server -> Client-PC: ? ACK
Client-PC -> Server: ? FIN, ACK
Server -> Client-PC: ? ACK
Server -> Client-PC: ? FIN, ACK
Client-PC -> Server: ? ACK
:::
