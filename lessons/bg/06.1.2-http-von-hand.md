# HTTP на ръка

:::sim
url=/sims/lesson-6.1.btsim
:::

Ако HTTP е чист текст — може ли тогава сам да разговаряш с уеб сървър, без изобщо да използваш браузър? Да: с `telnet` установяваш TCP връзка към произволен порт и сам въвеждаш текста.

## Експериментът

1. Премини в режим на изпълнение :fa-play: **Стартиране** и отвори :fa-terminal: **Терминал** на **Client-PC**.
2. Свържи се с порт 80 на сървъра:
   ```
   $ telnet 192.168.0.20 80
   ```
3. Въведи заявката ред по ред — и я завърши с **празен ред** (просто натисни още веднъж **Enter**):
   ```
   GET /kontakt.html HTTP/1.1
   Host: 192.168.0.20

   ```

Сървърът отговаря със статус ред, хедъри и страницата за контакти — като текст, точно както я получава и браузърът.

## Предизвикване на грешки

По-удобен инструмент е `curl`: той изпраща заявката вместо теб. С `-v` (*verbose*, подробен изход) показва всичко, което се разменя в двете посоки — редовете с `>` са изпратени от `curl`, а редовете с `<` идват от сървъра.

Опитай:

```
$ curl -v http://192.168.0.20/gibtsnicht.html
$ curl -X POST -d name=Anna http://192.168.0.20/
```

:::note
Уеб сървърът в BeaverTracer може само да предоставя файлове — затова позволява само `GET` и `HEAD`. Истинските уеб сървъри приемат с `POST`, например, формуляри и предават данните на програма.
:::

:::tip Запомни
Много протоколи от приложния слой са **текстово базирани** — HTTP, но също SMTP, POP3 и IMAP. Затова можеш да разговаряш с тях на ръка чрез `telnet` и да ги четеш в Tracer. Това е полезно за откриване и отстраняване на неизправности — но е и проблем за сигурността: всеки, който прихваща трафика, може да прочете всичко. Как помага криптирането (HTTPS), ще научиш в глава 8.
:::
