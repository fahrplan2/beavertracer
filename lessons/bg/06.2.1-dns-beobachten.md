## Експериментът

1. Премини в режим на изпълнение :fa-play: **Стартиране**, кликни върху **Client-PC** и отвори :fa-globe: **Браузър**.
2. Този път отвори `http://www.beaver-schule.de/` — с име вместо IP адрес.
3. Премини в режим :fa-magnifying-glass: **Проследяване** и отвори трейс за **Client-PC**.

Най-отпред — още преди установяването на връзка с `[SYN]` — има два пакета с протокол **DNS**.

:::

:::

Едва след като Client-PC научи IP адреса, той установява TCP връзка с уеб сървъра — точно както в глава 5.

:::seq
mode: text
Client-PC -> DNS-Resolver: DNS-Anfrage | A www.beaver-schule.de?
DNS-Resolver -> Client-PC: DNS-Antwort | A 192.168.0.20
:::

## Откъде PC-то знае DNS сървъра?

Отвори на **Client-PC** :fa-gear: **IP настройки**: в полето **DNS-Server** стои `192.168.0.53` — компютърът **DNS-Resolver**. Към него PC-то изпраща всяка заявка за име.

Можеш да питаш DNS сървъра и директно, без браузър. Отвори :fa-terminal: **Терминал** и въведи:

```
$ nslookup www.beaver-schule.de
```

`nslookup` показва първо кой сървър е попитан, после отговора. За сравнение попитай за име, което не съществува, напр. `nslookup gibtsnicht.beaver-schule.de`.

:::quiz mc
Какво отговаря DNS сървърът на непознатото име?
- [ ] Случаен IP адрес
- [x] `NXDOMAIN` — такова име не съществува
- [ ] Нищо
:::

:::evaluate
Провери отговора
:::

:::tip Запомни
**DNS** преобразува имена (напр. `www.beaver-schule.de`) в IP адреси. Преди един компютър да може да установи връзка с дадено име, той пита **DNS сървъра**, записан в неговите IP настройки — обикновено през **UDP, порт 53**. С `nslookup` можеш да изпращаш DNS заявки ръчно.
:::
