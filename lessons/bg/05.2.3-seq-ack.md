# Пореден номер и номер за потвърждение

:::sim
url=/sims/lesson-5.1.btsim
:::

Откъде TCP знае дали всичко е пристигнало — и в какъв ред? Всяка страна **номерира байтовете**, които изпраща:

- **Поредният номер** (`SEQ`) е номерът на първия байт, който се намира в този пакет.
- **Номерът за потвърждение** (`ACK`) казва: „Дотук съм получил всичко — следващия път очаквам байт №…“

Към това има две правила: `SYN` и `FIN` се броят като един байт, въпреки че не носят данни. И всяка страна брои за себе си — затова има две отделни номерации, на диаграмата в червено (клиент) и в синьо (сървър).

## Проверка с изчисления

Ето отново твоята връзка. Числата върху линиите показват стойността на брояча на съответния компютър в този момент:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Мини през редицата от червени числа:

1. Клиентът започва от `SEQ=0`. Неговият `SYN` използва един номер — сървърът потвърждава с `ACK=1`.
2. Съобщението започва от `SEQ=1` и е с дължина 13 байта (байтове от 1 до 13). Сървърът потвърждава с `ACK=14`: „Следващия път очаквам байт 14.“
3. Затова `FIN` на клиента има `SEQ=14` и се потвърждава с `ACK=15`.

Синята редица на сървъра работи по абсолютно същия начин.

:::tip Запомни
**Поредният номер** (`SEQ`) е номерът на първия байт в пакета. **Номерът за потвърждение** (`ACK`) е номерът на следващия байт, който получателят очаква — всичко преди него е пристигнало. Важи: **ACK = SEQ + дължина** на получените данни; `SYN` и `FIN` се броят като един байт. Всяка страна брои собствените си байтове.
:::

:::tip Пробвай сам
Изгради връзката отново в **Прост TCP клиент** и изпрати две съобщения едно след друго. Кажи предварително какви `Seq` и `Ack` ще се появят в колоната **Info** — и провери в проследяването.
:::

## Упражнения

:::quiz short
Клиентът изпраща пакет със `Seq=1` и `Len=13`. Какъв номер за потвърждение връща сървърът?
= 14
:::

:::quiz short
След това клиентът изпраща следващото си съобщение. С какъв пореден номер започва то?
= 14
:::

:::quiz short
Пристига пакет със `Seq=40` и `Len=25`. Какъв номер за потвърждение изпраща получателят?
= 65
:::

Попълни липсващите номера. Клиентът изпраща `Hallo` и след това `Tschau` (и двете със знак за край на реда):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
Провери диаграмата
:::

:::note
В реалните мрежи броенето не започва от 0: всяка страна избира **случаен начален номер** (*Initial Sequence Number*, ISN) между 0 и около 4,3 милиарда. Когато се достигне най-високият номер, броенето започва отново от 0. Tracer-ът изважда началния номер и показва **относителни** номера — точно като Wireshark. Затова виждаш `Seq=0` и `Seq=1`.

Освен това във всеки пакет има `Win=` — **размерът на прозореца**: толкова байта получателят може да приеме в момента. Така той спира твърде бързия подател (*контрол на потока*). В BeaverTracer прозорецът винаги има един и същ размер.
:::
