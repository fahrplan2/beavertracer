## Как изглежда една заявка

Кликни в трасирането върху пакета `GET / HTTP/1.1` и разгъни **Hypertext Transfer Protocol**. Една HTTP заявка е чист текст:

```
GET / HTTP/1.1              ← Methode, Pfad, Version
Host: 192.168.0.20          ← Header: zusätzliche Angaben
…
                            ← Leerzeile: Ende der Anfrage
```

Отговорът на сървъра е изграден по същия начин — със статусен ред, хедъри, празен ред и след това самия файл:

```
HTTP/1.1 200 OK             ← Version, Statuscode, Text
Content-Type: text/html     ← Header: Art der Datei
Content-Length: 301         ← Header: Größe in Byte
                            ← Leerzeile
<!doctype html> …           ← die Datei selbst
```

:::seq
mode: text
Client-PC -> Server: GET / | HTTP-Anfrage
Server -> Client-PC: 200 OK | index.html
Client-PC -> Server: GET /style.css | HTTP-Anfrage
Server -> Client-PC: 200 OK | style.css
:::

## Методи и кодове на състоянието

**Методът** казва какво иска клиентът:

| Метод | Значение |
|---|---|
| **GET** | изтегляне на файл |
| **POST** | изпращане на данни към сървъра, напр. попълнен формуляр |
| **HEAD** | изтегляне само на хедърите, без файла |

**Кодът на състоянието** казва как е протекла заявката. Първата цифра показва вида на отговора:

| Код | Текст | Значение |
|---|---|---|
| **200** | OK | всичко е наред |
| **301** | Moved Permanently | страницата е преместена за постоянно |
| **404** | Not Found | файлът не съществува |
| **405** | Method Not Allowed | този метод не е позволен тук |
| **500** | Internal Server Error | грешка на сървъра |

`2xx` означава успех, `3xx` пренасочване, `4xx` грешка на клиента (неправилна заявка), `5xx` грешка на сървъра.

:::tip Запомни
**HTTP** работи по **принципа заявка–отговор**: клиентът изпраща **заявка** (метод като `GET`, път, хедъри), а сървърът отговаря с **код на състоянието** (напр. `200 OK`, `404 Not Found`), хедъри и файла. За всеки файл на една уеб страница има отделна заявка.
:::
