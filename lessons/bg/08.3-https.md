# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) е съвсем обикновен HTTP — само че не работи директно върху TCP, а през криптиран слой между тях: **TLS** (*Transport Layer Security*). Предшественикът на TLS се наричал **SSL**; затова често още се говори за „SSL сертификати“.

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP не забелязва нищо от това: изпраща заявките си както обикновено, TLS ги криптира, TCP ги транспортира. В OSI модела TLS се намира между транспортния и приложния слой, т.е. в слой 4/5 — надгражда TCP и управлява защитена сесия.

| | HTTP | HTTPS |
|---|---|---|
| Порт | 80 | **443** |
| Адрес | `http://…` | `https://…` |
| Съдържанието се чете в Tracer? | да | не |
| Браузърът показва | „не е защитено“ | катинар |

При установяването на връзката TLS върши всичко, което научи в тази глава:

- Сървърът се идентифицира със своя **сертификат** (**автентичност**).
- И двете страни договарят със **Diffie-Hellman** **сесиен ключ** — сървърът **подписва** своя дял.
- След това всички данни се криптират с **AES** (**поверителност**) и се защитават срещу промяна (**цялостност**).

Принципът не е ограничен до уеб: и електронната поща (раздел 8.4), и много други протоколи минават по същия начин през TLS.

В следващите раздели ще наблюдаваш HTTPS в Tracer, ще го настроиш сам и ще проучиш кога браузърът предупреждава — и защо.
