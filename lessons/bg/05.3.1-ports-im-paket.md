## Експериментът

1. Премини в режим на изпълнение :fa-play: **Стартиране**, кликни върху **Client-PC** и отвори :fa-globe: **Браузър**. Отвори `http://192.168.0.20/`.
2. Кликни горе в прозореца на **Назад**, отвори **Прост TCP клиент** и го свържи с `192.168.0.20`, порт `5000`. Остави връзката отворена.
3. Премини в режим :fa-magnifying-glass: **Проследяване**, отвори trace за **Client-PC** и кликни върху пакет с `[SYN]`. Разгърни **Transmission Control Protocol**.

Най-горе в TCP хедъра има два порта: **Source Port** (изходен порт) и **Destination Port** (целеви порт).

:::quiz table
| Връзка | Изходен порт | Целеви порт |
|---|---|---|
| Браузър → уеб сървър | {49152} | {80} |
| TCP клиент → Echo услуга | {49153} | {5000} |
:::

## Два вида портове

**Целеви порт — услугата:** Сървърната програма чака връзки на фиксиран порт — казва се, че **слуша** там. За познатите услуги номерата са определени за целия свят — това са **well-known портовете** (от 0 до 1023). Затова браузърът знае, без да пита: уеб сървърите слушат на порт 80.

**Изходен порт — подателят:** Порта от страна на клиента операционната система избира сама за всяка нова връзка от висок диапазон (в BeaverTracer от 49152). По него клиентът разпознава на коя от неговите връзки принадлежи даден отговор.

Така една връзка е еднозначно определена от четири данни: **IP адрес и порт от двете страни**. Двойката от IP адрес и порт се нарича **сокет**, напр. `192.168.0.20:80`.

## Поглед към сървъра

Върни се в режим на изпълнение :fa-play: **Стартиране**, отвори на **Server** :fa-terminal: **Терминал** и въведи:

```
$ ss
```

`ss` показва всички сокети на компютъра. Редовете с `LISTEN` са програми, които слушат на даден порт. Редовете с `ESTABLISHED` са установени връзки — със собствения сокет (*Local Address:Port*) и със сокета на отсрещната страна (*Peer Address:Port*).

- [ ] 443
:::

- [ ] `192.168.0.20:80` с `192.168.0.10:49152` — връзката на браузъра

:::note
Връзката на браузъра вече е прекратена — след зареждането на страницата тя е приключена с `FIN`. `ss` я показва още за кратко като `TIME-WAIT`: сървърът изчаква известно време дали няма да пристигнат закъснели пакети от тази връзка. Връзката на TCP клиента, напротив, все още е отворена, защото още не си кликнал върху **Disconnect**.
:::

## Най-важните well-known портове

| Порт | Протокол | Услуга |
|---|---|---|
| 22 | SSH | сигурно дистанционно управление (криптиран команден ред) |
| 25 | SMTP | изпращане на имейли |
| 53 | DNS | превръщане на имена в IP адреси (най-често през UDP) |
| 80 | HTTP | уеб страници |
| 110 | POP3 | изтегляне на имейли |
| 143 | IMAP | управление на имейли на сървъра |
| 443 | HTTPS | криптирани уеб страници |

:::tip Запомни
**Портовете** (от 0 до 65535) разграничават връзките на един компютър. Сървърните услуги **слушат** на фиксирани **well-known портове** (напр. HTTP 80, HTTPS 443), а клиентите получават за всяка връзка свободен висок **изходен порт**. Една връзка е еднозначно определена от **IP адреса и порта на двете страни**.
:::

:::quiz match

25 -> SMTP
53 -> DNS
80 -> HTTP
110 -> POP3
143 -> IMAP
443 -> HTTPS
:::
