# Как е организиран DNS

:::sim
url=/sims/lesson-6.2.btsim
:::

Нито един сървър не може да познава всички имена в света. Затова DNS е изграден **йерархично** — също като самите имена. Те се четат отдясно наляво:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

Сървърът, който отговаря за даден домейн и наистина знае отговора, се нарича **авторитетен**. Пътя до него изминава вместо компютъра един **резолвър** — тук това е компютърът **DNS-Resolver**.

## Експериментът

1. Превключи в режим на изпълнение :fa-play: **Стартиране** и въведи на **Client-PC** в :fa-terminal: **Терминал**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. В режим :fa-magnifying-glass: **Проследяване** отвори трасиране (trace) за **DNS-Resolver**.

Резолверът е изпратил вместо теб цяла поредица от заявки. Съпостави кой какъв отговор е дал:

:::quiz match
Root-Server (192.168.0.101) -> Препратка: За .de отговаря ns.nic.de
de-Server (192.168.0.102) -> Препратка: За beaver-schule.de отговаря ns.beaver-schule.de
Schul-DNS (192.168.0.103) -> Отговор: www.beaver-schule.de има адрес 192.168.0.20
:::

:::quiz mc
Кого пита резолверът първо?
- [x] Root сървъра
- [ ] Schul-DNS
- [ ] Client-PC
:::

:::evaluate
Провери отговорите
:::

:::note
Между другото резолверът пита и за адресите на сървърите, към които е бил препратен (`A ns.nic.de`). Истинските DNS сървъри обикновено изпращат тези адреси веднага заедно с отговора. Освен това резолверите запомнят всеки отговор за известно време (**кеш**) — на следващата заявка за същото име те отговарят веднага сами. Колко дълго, е записано в записа като **TTL** (*Time to Live*) в секунди.
:::

## Най-важните типове записи

| Тип | Значение | Пример |
|---|---|---|
| **A** | име → IPv4 адрес | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | име → IPv6 адрес | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | име → друго име (псевдоним) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | отговорен пощенски сървър на домейн | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | отговорен DNS сървър на домейн | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Запомни
DNS е **йерархичен**: **root сървърите** препращат към сървърите на **домейните от най-високо ниво** (напр. `.de`), а те — към сървърите на отделните **домейни**. Отговорният **авторитетен** сървър знае отговора. **Резолверът** изминава този път вместо компютъра и запомня отговорите (**кеш**). Важни типове записи: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Създаване на запис

Училището иска уебсайтът му да е достъпен допълнително и на `intranet.beaver-schule.de`.

1. В режим :fa-play: **Стартиране** кликни върху **Schul-DNS** и отвори приложението **DNS-Server**.
2. Отвори раздела **A**. Кликни върху **+** и в новия ред въведи името `intranet.beaver-schule.de` и адреса `192.168.0.20`.
3. Тествай на Client-PC с `nslookup intranet.beaver-schule.de`.

:::task
title: Въведено ли е новото име?
Проверява дали Client-PC разрешава името intranet.beaver-schule.de до адреса на уеб сървъра. За целта симулацията трябва да работи в режим на изпълнение.
check: resolves(2, "intranet.beaver-schule.de", "192.168.0.20")
:::
