# POP3 ou IMAP?

:::sim

Existem dois protocolos para obter o correio. Nesta simulação, a **Anna usa POP3** e o **Ben usa IMAP**.

## A experiência

1. No modo de execução (:fa-play: **Executar**), envia um e-mail do **Ben** para `anna@beaver-schule.de`.
2. Na **Anna**, clica em **Obter** na aplicação **E-Mail**.
3. Abre os traces da **Anna** e do **Ben** e compara os comandos usados para obter o correio.

:::quiz match
USER / PASS -> POP3: iniciar sessão com nome de utilizador e palavra-passe em dois passos
RETR -> POP3: transferir uma mensagem
LOGIN -> IMAP: iniciar sessão com nome de utilizador e palavra-passe
SELECT INBOX -> IMAP: abrir uma pasta no servidor
:::

## A diferença

| | POP3 | IMAP |
|---|---|---|
| Porta | 110 | 143 |
| Ideia base | **transferir** os e-mails — depois, normalmente, apagá-los no servidor | os e-mails **permanecem no servidor** e são geridos aí |
| Pastas, lido/não lido | apenas no próprio dispositivo | no servidor — igual em todo o lado |
| Vários dispositivos (telemóvel, portátil) | pouco prático: cada dispositivo tem um estado diferente | ideal: todos os dispositivos veem a mesma caixa de correio |

:::note
A aplicação de e-mail do BeaverTracer deixa os e-mails no servidor mesmo com POP3. Os programas reais apagam-nos muitas vezes depois da transferência — ou deixam-nos lá apenas durante algum tempo.
:::

:::tip Ponto-chave
O **POP3** transfere os e-mails do servidor para **um** dispositivo. O **IMAP** gere a caixa de correio **no servidor** — com pastas e estado de leitura para todos os dispositivos em simultâneo. Ambos servem apenas para **obter** o correio; o envio é sempre feito com **SMTP**.
:::
