# Quem recebe que pacote?

:::sim
url=/sims/lesson-3.1.2.btsim
:::

Agora a Anna, o Ben e a Clara estão ligados ao switch (portas 1, 2 e 3). Quando a Anna envia um pacote ao Ben: só o Ben o recebe — ou a Clara também?

Pensa um momento no que supões que vai acontecer. Depois experimenta.

## A experiência

1. Muda para o modo de execução :fa-play: **Executar**, abre o :fa-terminal: **Terminal** na **Anna** e faz ping ao Ben:
   ```
   $ ping 192.168.0.11
   ```
2. Muda para o modo :fa-magnifying-glass: **Rastreamento** e abre com **+** um trace para a **Clara**, porta `eth0`.
3. Abre com **+** um segundo trace para o **Ben**, porta `eth0`. Em cima podes alternar entre os dois traces.

:::quiz short
Quantos pacotes chegaram à **Clara**?
= 1
= um
= uma
:::

:::quiz mc
Que pacote foi esse?
- [x] O pedido ARP "Who has 192.168.0.11?" dirigido a todos (broadcast)
- [ ] Um ping (Echo Request) da Anna
- [ ] A resposta ARP do Ben
:::

:::quiz mc
E o que chegou ao **Ben**?
- [ ] Só o pedido ARP
- [ ] Só os pings
- [x] O pedido ARP e todos os pings
:::

:::evaluate
Verificar respostas
:::

## O que está por trás

O pedido ARP tem como destino **broadcast** — é dirigido a *todos*. Por isso, o switch reencaminhou-o para todas as portas, também para a da Clara. Os pings, pelo contrário, eram endereçados apenas ao Ben. O switch enviou-os exclusivamente para a porta do Ben — a Clara não se apercebeu de nada.

:::tip Ponto-chave
Um **broadcast** é dirigido a todos os dispositivos da rede local — o switch distribui-o por todas as portas. Um **unicast** é dirigido a exatamente um dispositivo — o switch envia-o apenas para a porta à qual esse dispositivo está ligado.
:::

## Um olhar ao interior do switch

Mas como sabe o switch a que porta o Ben está ligado? Volta ao modo de execução :fa-play: **Executar** e clica no **Switch**. No separador **SAT** vês a respetiva tabela de endereços com duas colunas: **MAC** e **Port**.

:::quiz mc
Que dispositivos constam da tabela de endereços?
- [ ] Anna, Ben e Clara
- [x] Apenas a Anna e o Ben
- [ ] Apenas o Ben
:::

:::quiz short
A que porta está o Ben ligado, segundo a tabela? Dica: o endereço MAC do Ben encontras no Tracer, na resposta ARP dele `192.168.0.11 is at …`.
= 2
= porta 2
:::

:::quiz mc
Porque é que a Clara não aparece na tabela?
- [ ] O cabo dela está avariado
- [x] Ainda não enviou nenhum pacote
- [ ] O switch guarda no máximo duas entradas
:::

:::evaluate
Verificar respostas
:::

O switch **aprende** à medida que funciona: em cada frame que lhe chega, olha para o endereço MAC do **remetente** e memoriza a que porta esse dispositivo está ligado. Quando chegou o pedido ARP da Anna, registou "Anna → porta 1"; com a resposta do Ben, "Ben → porta 2". A Clara não enviou nada — por isso, ainda não a conhece.

:::tip Ponto-chave
Um switch memoriza na sua **tabela de endereços** (**SAT**, *Source Address Table*) sob que endereço MAC cada dispositivo é alcançável e em que porta — aprende isso a partir dos endereços de origem. Se conhece o destino de uma frame, envia-a apenas para essa porta. Se não o conhece (ou se for um broadcast), envia-a para todas as portas.
:::
