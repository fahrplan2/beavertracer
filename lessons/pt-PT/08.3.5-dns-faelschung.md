# Ataque: falsificação de DNS

:::sim
url=/sims/lesson-8.3.5.btsim
:::

A Anna quer abrir o homebanking do **Biberbank** no **Client-PC**. O que ela não sabe: alguém obteve acesso ao **DNS-Server** e alterou uma entrada.

Na área de trabalho vês o verdadeiro servidor web **www.biberbank.de** e o computador de um **Angreifer**. Nele está a correr uma cópia do site do banco.

## Parte 1: sem encriptação

Muda para o modo de execução :fa-play: **Executar** e, no **Client-PC**, abre `http://www.biberbank.de/` no :fa-globe: **Navegador**.

:::quiz mc
O que vês?
- [x] A página de início de sessão do Biberbank, sem qualquer aviso
- [ ] Um aviso de que a página é falsa
- [ ] Uma mensagem de erro
:::

:::evaluate
Verificar resposta
:::

Parece tudo normal. Mas com que servidor está o navegador realmente a comunicar? No Client-PC, abre o :fa-terminal: **Terminal**:

```
$ nslookup www.biberbank.de
```

:::quiz short
Que endereço IP devolve o servidor DNS para `www.biberbank.de`?
= 192.168.0.66
:::

:::quiz mc
A quem pertence este endereço? (No modo de edição, clica nos dispositivos ou consulta as respetivas :fa-gear: **Definições de IP**.)
- [ ] Ao verdadeiro servidor web do Biberbank
- [x] Ao atacante
- [ ] Ao servidor DNS
:::

:::evaluate
Verificar respostas
:::

Se a Anna tivesse introduzido agora o número da conta e o PIN, estes teriam ido parar diretamente ao atacante. Com **HTTP**, ela **não tem hipótese** de detetar a fraude: a barra de endereço mostra o nome correto e a página parece autêntica.

## Parte 2: com HTTPS

Agora abre `https://www.biberbank.de/`.

:::quiz mc
O que acontece?
- [ ] A página falsa aparece com cadeado
- [x] O navegador avisa: o certificado foi emitido para outro nome
- [ ] Aparece a verdadeira página do Biberbank
:::

:::quiz short
Para que nome foi emitido o certificado do atacante (sem `CN=`)?
= www.biber-gewinnspiel.de
:::

:::evaluate
Verificar respostas
:::

O atacante tem até um certificado **autêntico** de uma CA de confiança — mas para o seu próprio domínio `www.biber-gewinnspiel.de`. Nenhuma CA lhe emite um certificado para `www.biberbank.de`, porque esse domínio não lhe pertence. E sem a **chave privada** do Biberbank, também não pode usar o certificado verdadeiro do banco: no handshake teria de assinar com ela o Server Key Exchange.

:::quiz multi
Contra o que protege o HTTPS aqui — e contra o que não protege?
- [x] O HTTPS revela que o servidor não é o verdadeiro
- [ ] O HTTPS impede que o servidor DNS seja falsificado
- [x] O HTTPS só ajuda se o utilizador levar o aviso a sério
- [ ] Com HTTPS, a página falsa nem sequer é acessível
:::

:::evaluate
Verificar respostas
:::

## Parte 3: reparar o servidor DNS

Abre o **DNS-Server** e corrige a entrada de `www.biberbank.de`. O endereço correto encontras nas :fa-gear: **Definições de IP** do servidor web **www.biberbank.de**. Não te esqueças de clicar em **Guardar**.

:::note
O Client-PC memoriza as respostas DNS durante algum tempo, para não ter de perguntar de novo a cada acesso (**cache DNS**). A duração está na coluna **TTL** (*Time to Live*), em segundos. Se o `nslookup` devolver ainda o endereço antigo logo após a tua correção, espera pelo fim do TTL e tenta outra vez.
:::

:::task
title: O Biberbank voltou a ser autêntico?
Verifica se o Client-PC resolve www.biberbank.de para o endereço correto e consegue obter a página por HTTPS sem aviso.
check: resolves(2, "www.biberbank.de", "192.168.0.30")
check: httpsOk(2, "https://www.biberbank.de/")
:::

:::note
Na realidade, um atacante raramente falsifica o próprio servidor DNS. É mais frequente introduzir as suas respostas numa rede Wi-Fi pública, alterar as definições de um router doméstico ou atrair a vítima com um endereço de aspeto semelhante, como `www.biberbank-login.de` (**phishing**). Contra um nome de som semelhante, nem o HTTPS ajuda — o atacante consegue obter um certificado válido para ele. Por isso: lê o endereço com atenção!
:::

:::tip Ponto-chave
Numa **falsificação de DNS**, o servidor DNS devolve, para um nome, o endereço de um atacante. Com **HTTP** não se nota nada. Com **HTTPS**, o certificado do atacante não corresponde ao nome acedido e o navegador **avisa** — porque nenhuma CA emite certificados para domínios alheios, e o atacante não possui a chave privada do servidor verdadeiro.
:::
