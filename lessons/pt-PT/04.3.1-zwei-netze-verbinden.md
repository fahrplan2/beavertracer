O router tem duas interfaces:

| Interface | Endereço IP | Rede |
|---|---|---|
| `eth0` | `192.168.0.1/24` | Firma A |
| `eth1` | `172.16.0.1/24` | Firma B |

Para que os PCs utilizem o router, cada um deles tem um **gateway** configurado: no Anna e no Ben é `192.168.0.1`, no Clara e no David é `172.16.0.1`. Encontras o gateway nas :fa-gear: **Definições de IP**, no campo **Gateway**.

:::tip Ponto-chave
O **gateway** (mais exatamente: *gateway predefinido*) é o endereço IP do router **na própria rede**. Um PC envia para o gateway todos os pacotes cujo destino se encontra numa rede externa.
:::

## O que o router faz com o pacote

O router recebe a trama da Anna, desempacota o pacote IP e analisa o **endereço IP de destino**. Por aí reconhece: a Clara encontra-se na rede da `eth1`. Assim, volta a encapsular o pacote numa trama **nova** — com o seu próprio endereço MAC como remetente e o endereço MAC da Clara como destino — e envia-a por essa interface.

| O que acontece no router com … | |
|---|---|
| os endereços MAC (camada 2)? | são definidos **de novo** — só são válidos na respetiva rede |
| os endereços IP (camada 3)? | **mantêm-se** — da Anna até à Clara |
| o Time to Live? | fica **1 unidade menor** |

:::tip Ponto-chave
Um **router** funciona na **camada 3**: encaminha pacotes para outras redes com base no **endereço IP de destino**. Os endereços IP mantêm-se iguais ao longo de todo o caminho, e os endereços MAC são definidos de novo em cada rede. Cada router diminui o **Time to Live (TTL)** em 1 — se chegar a 0, o pacote é descartado. Assim, um pacote não pode andar em círculos para sempre.
:::

:::note
Lembras-te da tempestade de broadcast do capítulo 3.4? As tramas Ethernet não têm TTL — os pacotes IP têm.
:::

## Quem é que a Anna conhece? A cache ARP

Lembras-te do capítulo 1.2.3? Aí, o ARP só aparecia antes do *primeiro* ping, porque o PC memorizou a resposta. Esta lista de memória chama-se **cache ARP** (também *tabela ARP*). O pedido chama-se **ARP Request** e a resposta **ARP Reply** (ou *ARP Response*).

Muda para o modo de execução :fa-play: **Executar**, abre o :fa-terminal: **Terminal** na **Anna** e pede para ver a cache ARP dela:

```
$ arp
```

:::quiz mc
O que consta na cache ARP da Anna?
- [x] Apenas o endereço IP do router (`192.168.0.1`) com o respetivo endereço MAC
- [ ] O endereço IP da Clara com o endereço MAC da Clara
- [ ] Os endereços do router e da Clara
:::

:::evaluate
Verificar resposta
:::

A Anna nunca precisa do endereço MAC da Clara: tudo o que se destina à Firma B é enviado para o router. Só o router conhece o endereço MAC da Clara — foi ele próprio que o pediu via ARP no seu lado.

:::tip Ponto-chave
Na **cache ARP**, um dispositivo memoriza qual endereço MAC corresponde a qual endereço IP — assim não tem de enviar um ARP Request antes de cada pacote. Pode ser apresentada com o comando `arp`. Um PC só conhece endereços MAC da **própria** rede: para todos os destinos em redes externas, utiliza o endereço MAC do router.
:::

:::note
Em redes reais, as entradas na cache ARP são eliminadas ao fim de algum tempo e voltam a ser pedidas quando necessário — por exemplo, se entretanto um dispositivo tiver outra placa de rede. No BeaverTracer, mantêm-se enquanto a simulação estiver em execução.
:::
