# Abrir e observar uma página web

Nesta parte não constróis nada: na área de trabalho está uma simulação preparada com um **Client-PC** e um **Webserver**.

## Abrir a página

1. Muda para o modo de execução :fa-play: **Executar**.
2. No **Client-PC**, abre a aplicação :fa-globe: **Navegador** e acede ao endereço do servidor web: `http://192.168.0.20/`.
3. Muda para o modo :fa-magnifying-glass: **Rastreamento** e abre com **+** um trace para o **Client-PC**, porta `eth0` — tal como no ping.

:::note
Para um único acesso a uma página, são surpreendentemente muitos pacotes — bastante mais do que no ping. Obter uma página web é um processo com vários passos, não uma ação única.
:::

## Ler a lista de pacotes

Ainda não precisas de saber exatamente o que cada protocolo faz. Tudo o que precisas para as perguntas seguintes está nas colunas **Protocolo** e **Info**.

:::quiz mc
Qual é o protocolo que aparece no topo da lista?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Conta: quantos pacotes **TCP** aparecem antes do primeiro pacote **HTTP**?
= 3
= três
:::

:::quiz mc
O que responde o servidor web ao pedido do navegador? Olha para a coluna Info do segundo pacote HTTP.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Verificar respostas
:::

## Identificar os protocolos envolvidos

A partir das tuas observações, já consegues perceber qual foi o protocolo responsável por cada passo.

:::tip Dica
Lê outra vez as colunas **Info**: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` e `200 OK` revelam quase tudo.
:::

:::quiz match
ARP -> Pergunta a todos na rede: «Quem tem o endereço IP 192.168.0.20?»
TCP -> Estabelece uma ligação com três pacotes curtos antes de os dados fluírem
HTTP -> Pede a página web (GET) e devolve-a (200 OK)
:::

:::evaluate
Verificar associação
:::

:::tip Ponto-chave
O acesso a uma página web decorre por fases: primeiro **encontrar** o servidor na rede (ARP), depois **estabelecer** uma ligação (TCP), depois **pedir e entregar** a página (HTTP) — e, por fim, **terminar** a ligação (os pacotes TCP com `[FIN]` no fim da lista).
:::

:::note
Desta vez introduziste diretamente o endereço IP do servidor, por isso o **DNS** (a «tradução» de nomes como `www.beispiel.de` num endereço IP) ainda não foi utilizado. Voltaremos a isso no capítulo 6.
:::

Reparaste que, na estrutura dos pacotes, os protocolos têm marcações coloridas com números? O que isso significa será esclarecido no capítulo 2. Aí vamos ver como classificar sistematicamente os muitos protocolos — com os modelos de referência OSI e TCP/IP. Com isto, o capítulo 1 está concluído.
