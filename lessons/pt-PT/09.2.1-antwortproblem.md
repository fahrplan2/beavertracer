# O problema das respostas

:::sim
url=/sims/lesson-9.2.btsim
:::

A firewall funciona agora segundo o princípio da lista de permissões (whitelist): política predefinida **Alle verwerfen**. Uma única regra permite à rede da escola navegar: **B → A, TCP, porto de destino 80, Zulassen**. O modo está definido como **Stateless**.

## A experiência

1. Muda para o modo de execução :fa-play: **Executar** e, no **Lehrer-PC**, abre no :fa-globe: **Navegador** o endereço `http://203.0.113.80/`.
2. Na **Firewall**, consulta o **Protokoll** e os **Treffer**.

:::quiz mc
O que acontece no navegador?
- [ ] A página de www.beispiel.de aparece
- [x] A página não carrega, o navegador fica à espera e acaba por indicar um erro
:::

:::quiz mc
Que pacotes aparecem no registo da firewall como descartados (`DROP`)?
- [ ] Os pedidos do Lehrer-PC ao porto 80
- [x] As respostas de `203.0.113.80` com **porto de origem 80** para o Lehrer-PC
- [ ] Nenhum
:::

:::quiz short
Em que sentido (A→B ou B→A) circulam os pacotes descartados?
= A→B
= A → B
= AtoB
:::

:::evaluate
Verificar respostas
:::

O pedido do Lehrer-PC pode sair — mas já o `SYN, ACK` do servidor web não consegue voltar, porque para o sentido A → B não existe nenhuma regra adequada, pelo que se aplica **Alle verwerfen**.

## A solução ingénua

Poder-se-ia adicionar uma segunda regra: **A → B, TCP, porto de origem 80, Zulassen** — «tudo o que vem do porto 80 pode entrar». Assim, a navegação passa de facto a funcionar.

:::quiz mc
Porque é que esta regra é perigosa?
- [ ] Porque os servidores web nunca usam o porto 80 como porto de origem
- [x] Um atacante pode simplesmente enviar os seus pacotes com porto de origem 80 — e a firewall deixa-os passar para **qualquer** porto da rede da escola
- [ ] Porque as páginas web passam a carregar mais devagar
:::

:::evaluate
Verificar resposta
:::

O porto de origem é definido pelo próprio remetente — uma firewall não pode confiar nele. No entanto, uma firewall sem estado não sabe se um pacote é a **resposta a um pedido** ou uma **nova tentativa de ligação** vinda do exterior. É precisamente isso que o modo com estado altera.

:::tip Ponto-chave
Um filtro de pacotes **sem estado** analisa cada pacote isoladamente. As respostas precisam então de regras próprias para o sentido contrário — e essas regras (p. ex. «o porto de origem 80 pode entrar») podem ser exploradas por atacantes, porque o remetente pode escolher livremente o porto de origem.
:::
