## Ping do exterior

Muda para o modo de execução :fa-play: **Executar** e faz ping ao servidor da escola a partir do **Internet-PC**:

```
$ ping -c 2 198.51.100.10
```

Depois, abre na firewall o separador **Protokoll**.

:::quiz mc

- [x] `Anfrage abgelaufen` — não volta nada
- [ ] `Paket gefiltert`
- [ ] Duas respostas do servidor da escola
:::

## Análise de portas: descartado ou rejeitado?

Agora analisa cinco portas em concreto. A porta 3306 (uma base de dados) não está de todo em funcionamento no servidor da escola.

```
$ nmap -p 22,25,80,110,3306 198.51.100.10
```

:::quiz match
22 (descartado) -> filtered
25 (permitido, serviço em execução) -> open
110 (rejeitado) -> closed
3306 (permitido, sem serviço) -> closed
:::

:::evaluate
Verificar associação
:::

:::quiz multi
O que pode um atacante concluir a partir do resultado?
- [x] Com `filtered` sabe: ali está uma firewall que engole pacotes
- [x] Com `closed` não consegue distinguir se uma firewall rejeita ou se simplesmente não há nenhum serviço em execução
- [ ] Com `filtered` sabe qual é o serviço que corre por trás da porta
- [ ] Com `closed` o serviço é, ainda assim, acessível
:::

:::evaluate
Verificar respostas
:::

Para terminar, observa a coluna **Treffer** na lista de regras: aí a firewall conta quantos pacotes cada regra já decidiu. O valor ao lado da **Standardrichtlinie** conta todos os pacotes a que nenhuma regra se aplicou.

:::tip Ponto-chave
Os pacotes **descartados** desaparecem sem deixar rasto: o `ping` indica um timeout, o `nmap` indica `filtered`. Os pacotes **rejeitados** são respondidos pela firewall com uma recusa (no caso do TCP, um RST) — do exterior, isto parece uma porta fechada. O **Protokoll** da firewall mostra que pacotes ela travou; a coluna **Treffer** mostra que regra foi aplicada.
:::
