No **Server** corre desta vez um **Servidor UDP Echo** na porta `5000`. Também aqui o cabo está preparado: o **segundo datagrama** do Client-PC para o Server perde-se.

## A experiência

1. Muda para o modo de execução :fa-play: **Executar** e abre o :fa-terminal: **Terminal** no **Client-PC**.
2. Inicia com `nc` uma "ligação" UDP ao servidor (`-u` significa UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Escreve, por esta ordem, `eins`, `zwei` e `drei` e prime **Enter** de cada vez. Cada linha que regressa é um eco do servidor.
4. Espera alguns segundos e, depois, no modo :fa-magnifying-glass: **Rastreamento**, abre um trace para o **Client-PC**.

:::quiz mc
Que ecos regressam?
- [ ] Os três, `zwei` um pouco mais tarde
- [x] Apenas `eins` e `drei` — `zwei` falta e também não é reenviado
- [ ] Nenhum
:::

:::quiz multi
Que pacotes que conheces do TCP faltam por completo no UDP?
- [x] Estabelecimento de ligação (`SYN`)
- [x] Confirmações (`ACK`)
- [x] Terminação da ligação (`FIN`)
- [ ] Pacotes com números de porta
:::

:::evaluate
Verificar respostas
:::

Clica num dos pacotes UDP e expande **User Datagram Protocol**. Em comparação com o cabeçalho TCP, o cabeçalho UDP é minúsculo: **Source Port**, **Destination Port**, **Length** (comprimento) e **Checksum** (soma de verificação) — no total, apenas 8 bytes. Um cabeçalho TCP tem pelo menos 20 bytes, com número de sequência e número de confirmação, flags e tamanho da janela.

:::quiz mc
Que tarefa da secção 5.1 o UDP cumpre, apesar de tudo?
- [x] Multiplexagem — através das portas
- [ ] Estabelecimento de ligação
- [ ] Transmissão fiável
:::

:::evaluate
Verificar resposta
:::

:::tip Ponto-chave
O **UDP** é **não orientado a ligação**: sem estabelecimento, sem confirmação, sem retransmissão, sem ordenação. Oferece apenas **portas** (multiplexagem) e uma **soma de verificação**. Em compensação, é rápido e leve — o cabeçalho UDP tem apenas 8 bytes. Se um datagrama se perde, o programa tem de tratar disso por si próprio — ou então não se importa.
:::
