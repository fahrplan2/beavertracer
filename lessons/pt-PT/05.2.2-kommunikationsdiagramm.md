# O diagrama de sequência

:::sim
url=/sims/lesson-5.1.btsim
:::

O decurso de uma ligação desenha-se como um **diagrama de sequência**: o cliente e o servidor têm cada um uma linha vertical, e o tempo corre de cima para baixo. Cada seta é um pacote. Está desenhada na diagonal porque cada pacote demora um pouco a chegar ao destino.

Eis a tua ligação da página anterior — compara-a linha a linha com o trace:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Por cima de cada seta estão as **flags** e, por baixo, os números `SEQ` e `ACK`. **DATA** assinala pacotes com dados úteis. Os números vermelhos pertencem ao cliente e os azuis ao servidor — o que significam é explicado na página seguinte.

## As flags

| Flag | significa | Significado |
|---|---|---|
| **SYN** | *synchronize* | estabelecer a ligação, definir o número inicial |
| **ACK** | *acknowledge* | confirma os dados recebidos |
| **PSH** | *push* | entregar os dados imediatamente ao programa |
| **FIN** | *finish* | «Já terminei» — terminar a ligação |
| **RST** | *reset* | interromper ou recusar a ligação (mais sobre isto em 5.3.2) |

## Três fases

**Estabelecimento:** o cliente envia `SYN`, o servidor responde com `SYN, ACK` e o cliente confirma com `ACK`. Como são necessários exatamente três pacotes, chama-se **handshake de três vias**.

**Dados:** cada pacote com dados é confirmado pelo destinatário com um `ACK`. Aqui, o servidor devolve o eco — e o cliente também o confirma.

**Terminação:** cada lado termina individualmente o seu sentido de envio: `FIN` do cliente, `ACK` do servidor — depois `FIN` do servidor, `ACK` do cliente. São quatro pacotes.

:::tip Ponto-chave
Uma ligação TCP decorre em três fases: **estabelecimento** com o **handshake de três vias** (`SYN` → `SYN, ACK` → `ACK`), **transferência de dados** (cada pacote de dados é confirmado com `ACK`) e **terminação** (cada lado envia `FIN` e recebe um `ACK`).
:::
