# Inserir rotas estáticas

:::sim
url=/sims/lesson-4.5.2.btsim
:::

Desta vez, entre a Firma A e a Firma B existem **dois** routers. Estão ligados através de uma pequena rede própria, a **rede intermédia** `10.0.0.0/30`:

| Router | Interface | Endereço IP | Rede |
|---|---|---|---|
| Router A | `eth0` | `192.168.0.1/24` | Firma A (Anna) |
| Router A | `eth1` | `10.0.0.1/30` | Rede intermédia |
| Router B | `eth0` | `10.0.0.2/30` | Rede intermédia |
| Router B | `eth1` | `172.16.0.1/24` | Firma B (Clara) |

:::note
Uma rede `/30` tem exatamente dois endereços utilizáveis — perfeito para ligar dois routers (ver secção 4.2.3).
:::

## O problema

Muda para o :fa-play: modo de execução e faz ping da **Anna** à Clara (`ping 172.16.0.10`). A Clara não responde — em vez disso, quem responde é o Router A (`192.168.0.1`) com a mensagem "Rede de destino inacessível".

Observa a **Tabela de Encaminhamento IPv4** do **Router A**.

:::quiz mc
Porque é que o ping da Anna não chega à Clara?
- [ ] A Anna não tem gateway configurado
- [x] O Router A não conhece a rede `172.16.0.0/24` — não está ligada diretamente a ele e não existe nenhuma rota para lá
- [ ] A rede intermédia é demasiado pequena
:::

:::evaluate
Verificar resposta
:::

## Inserir a rota

O Router A tem de aprender: os pacotes para `172.16.0.0/24` vão para o Router B (`10.0.0.2`), através da `eth1`.

1. No **Router A**, abre o separador **Tabela de Encaminhamento IPv4** e clica em **+ hinzufügen**.
2. Na nova linha, introduz: **Ziel** `172.16.0.0`, **Netzmaske** `255.255.255.0`, **Próximo Salto** `10.0.0.2`, **Iface** `eth1`.
3. Guarda a linha com o visto :fa-check:. Na coluna **Quelle** aparece agora **Estático**.

Faz novamente ping à Clara — desta vez chega a resposta.

:::note
O Router B, aliás, já conhece o caminho de volta para a Firma A: na sua tabela de encaminhamento já existe uma rota estática para `192.168.0.0/24` através de `10.0.0.1`. Porque é que este caminho de retorno é igualmente importante, vais ver na página seguinte.
:::

## Seguir o caminho: traceroute

Com o `traceroute` podes ver por que routers passa um pacote. Introduz na **Anna**:

```
$ traceroute 172.16.0.10
```

:::quiz short
Por quantos routers passa o pacote da Anna até à Clara?
= 2
= dois
:::

:::quiz mc
Que endereço mostra o `traceroute` para o Router B?
- [x] `10.0.0.2` — o seu endereço na rede intermédia, por onde o pacote entra
- [ ] `172.16.0.1` — o seu endereço na Firma B
- [ ] `192.168.0.1`
:::

:::evaluate
Verificar respostas
:::

O `traceroute` aproveita um truque com o **Time to Live** da secção 4.3.1: envia primeiro um pacote com TTL 1. O primeiro router subtrai 1, chega a 0, descarta o pacote e comunica-o ao remetente — assim, a Anna fica a conhecer o primeiro router. Depois, TTL 2 para o segundo router, e assim sucessivamente, até o destino responder.

:::tip Ponto-chave
Uma **rota estática** é inserida manualmente pelo administrador: rede de destino, máscara de rede, próximo salto e interface. Com o **traceroute** é possível seguir o caminho de um pacote router a router.
:::
