# Como o DNS está organizado

:::sim
url=/sims/lesson-6.2.btsim
:::

Nenhum servidor individual consegue conhecer todos os nomes do mundo. Por isso, o DNS tem uma estrutura **hierárquica** — tal como os próprios nomes. Lêem-se da direita para a esquerda:

```
www . beaver-schule . de . (Root)
 │          │         │      └─ Root-Server: kennen die Server aller Top-Level-Domains
 │          │         └─ Top-Level-Domain (TLD): der de-Server kennt alle .de-Domains
 │          └─ Domain: der Schul-DNS ist für beaver-schule.de zuständig
 └─ Rechnername innerhalb der Domain
```

O servidor que é responsável por um domínio e que realmente conhece a resposta chama-se **autoritativo**. O caminho até lá é percorrido, em nome do PC, por um **resolver** — aqui o computador **DNS-Resolver**.

## A experiência

1. Muda para o modo de execução :fa-play: **Executar** e, no **Client-PC**, introduz no :fa-terminal: **Terminal**:
   ```
   $ nslookup www.beaver-schule.de
   ```
2. No modo :fa-magnifying-glass: **Rastreamento**, abre um trace para o **DNS-Resolver**.

O resolver fez uma série de pedidos por ti. Associa quem deu cada resposta:

:::quiz match
Root-Server (192.168.0.101) -> Remissão: O servidor ns.nic.de é responsável por .de
de-Server (192.168.0.102) -> Remissão: O servidor ns.beaver-schule.de é responsável por beaver-schule.de
Schul-DNS (192.168.0.103) -> Resposta: www.beaver-schule.de tem o endereço 192.168.0.20
:::

:::quiz mc
A quem pergunta o resolver em primeiro lugar?
- [x] Ao Root-Server
- [ ] Ao Schul-DNS
- [ ] Ao Client-PC
:::

:::evaluate
Verificar respostas
:::

:::note
Pelo caminho, o resolver pergunta também pelos endereços dos servidores para os quais foi remetido (`A ns.nic.de`). Os servidores DNS reais costumam enviar logo esses endereços juntamente com a resposta. Além disso, os resolvers memorizam cada resposta durante algum tempo (**cache**) — o pedido seguinte para o mesmo nome é respondido de imediato por eles próprios. Durante quanto tempo, está indicado no registo como **TTL** (*Time to Live*), em segundos.
:::

## Os tipos de registo mais importantes

| Tipo | Significado | Exemplo |
|---|---|---|
| **A** | Nome → endereço IPv4 | `www.beaver-schule.de` → `192.168.0.20` |
| **AAAA** | Nome → endereço IPv6 | `www.beaver-schule.de` → `2001:db8::20` |
| **CNAME** | Nome → outro nome (alias) | `web.beaver-schule.de` → `www.beaver-schule.de` |
| **MX** | servidor de correio responsável por um domínio | `beaver-schule.de` → `mail.beaver-schule.de` |
| **NS** | servidor DNS responsável por um domínio | `beaver-schule.de` → `ns.beaver-schule.de` |

:::tip Ponto-chave
O DNS é **hierárquico**: os **Root-Servers** remetem para os servidores dos **domínios de topo** (p. ex. `.de`), e estes para os servidores dos **domínios** individuais. O servidor **autoritativo** responsável conhece a resposta. Um **resolver** percorre este caminho em nome do PC e memoriza as respostas (**cache**). Tipos de registo importantes: **A**, **AAAA**, **CNAME**, **MX**, **NS**.
:::

## Criar um registo

A escola quer que o seu site também seja acessível em `intranet.beaver-schule.de`.

1. No modo de execução :fa-play: **Executar**, clica no **Schul-DNS** e abre a aplicação **DNS-Server**.
2. Abre o separador **A**. Clica em **+** e introduz, na nova linha, o nome `intranet.beaver-schule.de` e o endereço `192.168.0.20`.
3. Testa no Client-PC com `nslookup intranet.beaver-schule.de`.
