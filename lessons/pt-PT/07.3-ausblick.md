# Perspetivas: IPv6 e Carrier-Grade NAT

empty
:::

O NAT é uma solução de recurso genial para a falta de endereços IPv4 — mas não deixa de ser uma solução de recurso. Há duas evoluções que deves conhecer.

## IPv6: já não é necessário NAT

No **IPv6** há endereços em abundância (capítulo 4.6). Por isso, o fornecedor de acesso não atribui ao router doméstico apenas um endereço, mas um **prefixo** inteiro — muitas vezes um `/56` ou `/48`, ou seja, milhares de milhões de endereços. A isto chama-se **delegação de prefixo** (DHCPv6-PD). A partir dele, o router doméstico atribui, através de SLAAC, a cada dispositivo um endereço próprio, **único a nível mundial**.

O NAT deixa então de ser necessário: cada dispositivo é diretamente endereçável. Isto é prático, mas exige uma boa **firewall** no router — porque o «efeito secundário» do NAT, o de ninguém conseguir iniciar uma ligação a partir do exterior, desaparece. É disso que trata o capítulo 9.

## Carrier-Grade NAT: NAT no fornecedor de acesso

Muitos fornecedores de acesso não têm eles próprios endereços IPv4 suficientes. Nesse caso, nem sequer o router doméstico recebe um endereço público, mas apenas um de um intervalo especial (`100.64.0.0/10`), e o fornecedor faz **NAT mais uma vez** para muitos clientes em conjunto. Isto chama-se **Carrier-Grade NAT** (CGNAT); muitas vezes, para o IPv4 só existe então este caminho, enquanto para o IPv6 existem endereços públicos reais (*DS-Lite*).

A consequência: um **reencaminhamento de portas** no router próprio já não serve de nada com IPv4 — os pacotes vindos do exterior ficam logo retidos no fornecedor de acesso. Quem quiser pôr um servidor a funcionar em casa precisa então de IPv6 ou de outro tipo de ligação.
