# Tudo junto: o que acontece quando se acede a uma página web?

:::goal
**Objetivo de aprendizagem:** Consegues explicar passo a passo que protocolos de que camada estão envolvidos quando um portátil acabado de ligar acede a uma página web.
:::

:::sim
url=/sims/lesson-6.5.btsim
:::

Agora junta-se tudo o que aprendeste neste curso. Ao switch estão ligados um **DHCP-Server**, um **DNS-Server**, um **Webserver** e um **Laptop** que acabou de ser ligado — ainda não tem endereço IP e está configurado para DHCP.

## A experiência

1. Muda para o modo de execução :fa-play: **Executar** e espera alguns segundos.
2. Clica no **Laptop**, abre o :fa-globe: **Navegador** e acede a `http://www.beaver-schule.de/`.
3. No modo :fa-magnifying-glass: **Rastreamento**, abre um trace para o **Laptop**. Aqui está a história toda — desde o primeiro pacote.

Coloca os passos na ordem correta, tal como aparecem no trace:

:::quiz match
1. Schritt -> DHCP: o portátil obtém endereço IP, gateway e servidor DNS
2. Schritt -> ARP: o portátil pergunta pelo endereço MAC do servidor DNS
3. Schritt -> DNS: o portátil pergunta pelo endereço IP de www.beaver-schule.de
4. Schritt -> ARP: o portátil pergunta pelo endereço MAC do servidor web
5. Schritt -> TCP: handshake de três vias com o servidor web
6. Schritt -> HTTP: GET / e a resposta 200 OK
:::

:::evaluate
Verificar a ordem
:::

E por baixo de tudo estão o **IP** (camada 3), que endereça cada um destes pacotes, e a **Ethernet** (camada 2), que os leva até ao dispositivo seguinte. Se o servidor web estivesse numa outra rede, o **router** também entraria em jogo: nesse caso, o portátil perguntaria pelo endereço MAC do seu **gateway**, e não pelo do servidor web.

:::quiz mc
Porque é que o portátil só pode fazer o pedido DNS depois do DHCP?
- [ ] Porque o DNS só funciona através de TCP
- [x] Porque só através do DHCP obtém um endereço IP próprio e fica a saber qual é o servidor DNS responsável
- [ ] Porque o servidor DNS só arranca depois do servidor DHCP
:::

:::quiz mc
Quantas ligações TCP estabelece o navegador com o servidor web — e porquê?
- [ ] Uma, para tudo em conjunto
- [x] Duas — uma para a página e outra para a folha de estilos
- [ ] Nenhuma, o HTTP não precisa de TCP
:::

:::evaluate
Verificar respostas
:::

:::tip Ponto-chave
Por detrás de um único clique, todas as camadas trabalham em conjunto: o **DHCP** fornece as definições básicas, o **ARP** encontra os endereços MAC na rede local, o **DNS** traduz o nome, o **TCP** estabelece uma ligação fiável e o **HTTP** vai buscar a página — tudo isto empacotado em pacotes **IP** e tramas **Ethernet**.
:::

Com isto, consegues explicar um acesso a uma página web desde o primeiro até ao último pacote. Para terminar o capítulo, segue-se uma breve perspetiva sobre outros protocolos. Nos próximos capítulos, o tema é a rede doméstica com NAT, a segurança e a cifragem — e, com isso, a questão de como impedir que alguém consiga ler todos estes pacotes.
