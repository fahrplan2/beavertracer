No switch estão ligados um **Servidor DHCP** e dois portáteis. Os portáteis ainda têm endereços fixos.

## A experiência

1. Muda para o :fa-play: modo de execução (**Executar**), clica em **Laptop 1** e abre as :fa-gear: **Definições de IP**.
2. Muda o **Modo** de **Estático** para **DHCP** e clica em **Aplicar**.
3. Espera alguns segundos: os campos preenchem-se sozinhos.
4. No modo :fa-magnifying-glass: **Rastreamento**, abre um trace para o **Laptop 1**.

| Gateway | {192.168.0.1} |

## O que está por trás: DORA

Um dispositivo sem endereço não sabe onde está o servidor DHCP, nem tem um endereço de remetente próprio. Por isso, chama por **broadcast** para a rede. O processo tem quatro passos — chamado **DORA** pelas suas iniciais:

:::seq
mode: text
Laptop 1 -> DHCP-Server: DHCP Discover | „Existe aqui algum servidor DHCP?“
DHCP-Server -> Laptop 1: DHCP Offer | „Podes ficar com 192.168.0.100.“
Laptop 1 -> DHCP-Server: DHCP Request | „Fico com 192.168.0.100.“
DHCP-Server -> Laptop 1: DHCP ACK | „Confirmado — válido por 3600 segundos.“
:::

O endereço é apenas **emprestado** (*lease*): depois de terminado o **tempo de lease**, o dispositivo tem de o renovar, caso contrário o servidor pode atribuí-lo novamente. Os endereços que estão emprestados neste momento vês no **Servidor DHCP**, no separador **Leases**.

:::tip Experimenta
Define também o **Laptop 2** para DHCP. Que endereço recebe? Depois, consulta os **Leases** do servidor DHCP.
:::

:::tip Ponto-chave
O **DHCP** distribui automaticamente o endereço IP, a máscara de rede, o gateway e o servidor DNS. O processo chama-se **DORA**: **D**iscover (o cliente procura por broadcast), **O**ffer (o servidor propõe), **R**equest (o cliente aceita), **A**CK (o servidor confirma). O endereço é emprestado durante o **tempo de lease**. O DHCP utiliza **UDP**, porta 67 (servidor) e 68 (cliente).
:::

:::quiz match
Discover -> O cliente procura um servidor DHCP por broadcast
Offer -> O servidor propõe um endereço
Request -> O cliente solicita o endereço proposto
ACK -> O servidor confirma a atribuição
:::
