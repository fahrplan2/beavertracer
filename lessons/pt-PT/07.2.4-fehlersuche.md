# Deteção e resolução de problemas: ontem ainda funcionava

:::sim
url=/sims/lesson-7.2.4.btsim
:::

Ontem o servidor web doméstico estava acessível do exterior — o reencaminhamento de portas `TCP 80 → 192.168.178.10:80` está configurado. Depois de uma falha de energia hoje de manhã cedo, a Clara já não consegue aceder à página. Encontra o erro e corrige-o de forma permanente.

<details>
<summary>Dica 1: Para onde aponta a regra?</summary>

Compara o IP da LAN em **Port FW** do router doméstico com o endereço que o **Heim-Webserver** tem realmente neste momento (:fa-gear: **Definições de IP**).
</details>

<details>
<summary>Dica 2: Porque é que tem um endereço diferente?</summary>

O Heim-Webserver está em **DHCP**? Nesse caso, após cada reinício recebe um endereço livre qualquer do intervalo do router doméstico (no separador **DHCP**). Como podes garantir que ele tem sempre o mesmo endereço?
</details>

:::task
title: Servidor web doméstico acessível novamente?
Verifica se o servidor web doméstico tem o seu endereço fixo e se a Clara lhe consegue aceder através do reencaminhamento de portas. Para isso, a simulação tem de estar a decorrer no modo de execução.
check: ip(11, "192.168.178.10/32")
check: tcpOpen(12, "203.0.113.2", 80)
:::

## O que se passou?

:::quiz multi
Quais das afirmações são verdadeiras?
- [x] O servidor web doméstico obteve o seu endereço por DHCP e, após o reinício, tinha um endereço diferente
- [x] Por isso, o reencaminhamento de portas apontava para um endereço onde já não estava nenhum servidor em execução
- [x] Um endereço fixo fora do intervalo DHCP resolve o problema de forma permanente
- [ ] O fornecedor de serviços tinha bloqueado o endereço WAN
:::

:::evaluate
Verificar resposta
:::

:::tip Ponto-chave
Os dispositivos para os quais aponta um **reencaminhamento de portas** (servidores, impressoras, câmaras) precisam de um **endereço fixo**: ou configurado de forma estática e **fora do intervalo DHCP**, ou como atribuição fixa no Servidor DHCP do router. Caso contrário, após um reinício podem receber um endereço diferente — e a regra fica sem efeito.
:::
