# A tabela NAT

:::sim
url=/sims/lesson-7.1.btsim
:::

Quando o PC e o tablet carregam ao mesmo tempo a mesma página web, ambos os pedidos chegam ao servidor web a partir de `203.0.113.2`. Como é que o router doméstico sabe a quem se destina uma resposta? Ele mantém um registo — na **tabela NAT**.

## A experiência

1. Muda para o modo de execução :fa-play: **Executar** e abre `http://www.beispiel.de/` no **PC** e no **Tablet**.
2. Clica no **Heimrouter** e abre o separador **NAT**.

Cada linha é uma **correspondência**: protocolo, IP LAN e porta LAN do dispositivo na rede doméstica — e a **porta WAN** que o router utiliza para o efeito no seu endereço público.

:::quiz short
Que IP WAN aparece por cima da tabela?
= 203.0.113.2
:::

:::quiz mc
O PC e o tablet estabeleceram ambos uma ligação com a porta LAN `49152`. Que porta WAN recebem?
- [ ] Ambos a mesma, `49152`
- [x] Cada um uma diferente — caso contrário, o router não saberia a quem pertence a resposta
- [ ] Nenhuma, o NAT só altera o endereço IP
:::

:::quiz mc
Uma resposta do servidor web chega a `203.0.113.2` com uma determinada **porta de destino**. O que faz o router doméstico com ela?
- [x] Procura a porta na tabela NAT e envia o pacote para o IP LAN e a porta LAN correspondentes
- [ ] Envia o pacote para todos os dispositivos da rede doméstica
- [ ] Descarta o pacote
:::

:::evaluate
Verificar respostas
:::

Aqui voltam a entrar em jogo as **portas** do capítulo 5: como o NAT também reescreve as portas, centenas de ligações podem partilhar um único endereço. A rigor, isto chama-se por isso **PAT** (*Port Address Translation*) ou *NAT com tradução de portas* — no dia a dia, diz-se mesmo assim simplesmente NAT.

Eis um exemplo de como poderia ser uma tradução deste tipo:

| | Pacote do PC (na rede doméstica) | o mesmo pacote na Internet |
|---|---|---|
| Remetente | `192.168.178.20 : 49152` | `203.0.113.2 : 10001` |
| Destinatário | `192.0.2.80 : 80` | `192.0.2.80 : 80` |

:::tip Ponto-chave
Na **tabela NAT**, o router memoriza, para cada ligação, que dispositivo (**IP LAN e porta LAN**) está por trás de que **porta WAN**. As respostas vindas da Internet são novamente associadas ao dispositivo correto através da porta de destino. Como as portas também são reescritas, fala-se com mais rigor em **PAT**.
:::
