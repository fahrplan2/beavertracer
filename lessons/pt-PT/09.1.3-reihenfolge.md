# Ordem e postura de base

## Primeiro a exceção, depois a regra

Como a **primeira regra que corresponde** é a que prevalece, a ordem é importante. Observa esta lista de regras (todas as regras se aplicam ao sentido A → B, política predefinida: Permitir tudo):

| N.º | Protocolo | Porta de destino | Ação |
|---|---|---|---|
| 1 | TCP | qualquer | Descartar |
| 2 | TCP | 80 | Permitir |

:::quiz mc
Chega um pacote da Internet destinado à porta TCP 80. O que acontece?
- [ ] É permitido, porque a regra 2 permite precisamente a porta 80
- [x] É descartado, porque a regra 1 já corresponde — a regra 2 nunca é alcançada
- [ ] A firewall pergunta ao administrador
:::

:::evaluate
Verificar resposta
:::

Em geral, aplica-se o seguinte: **regras específicas em cima, regras gerais em baixo.** Uma regra que abrange muito "ensombra" todas as regras que estão abaixo dela. A coluna **Correspondências** revela essas regras inúteis: permanecem a 0.

## Lista negra ou lista branca?

Na secção 9.1.2, **proibiste** portas individuais e permitiste tudo o resto. Isto chama-se **lista negra** (*blacklist*). O oposto é a **lista branca** (*whitelist*): só se **permite** o que é necessário e proíbe-se tudo o resto — com uma regra final "descartar tudo" ou com a política predefinida **Descartar tudo**.

| | Lista negra | Lista branca |
|---|---|---|
| Postura de base | tudo permitido, exceções proibidas | tudo proibido, exceções permitidas |
| Política predefinida | Permitir | Descartar |
| Novo serviço no servidor | fica imediatamente acessível a partir do exterior | permanece bloqueado até alguém o libertar |

:::quiz mc
Amanhã, um professor instala no servidor da escola uma base de dados que escuta na porta 3306. O que acontece com a firewall da secção 9.1.2 (lista negra)?
- [x] A base de dados fica imediatamente acessível a partir da Internet
- [ ] A base de dados fica automaticamente bloqueada
- [ ] A firewall comunica o novo serviço
:::

:::evaluate
Verificar resposta
:::

Por isso, as boas firewalls funcionam segundo o **princípio da lista branca** ("Default Deny"): tudo o que não for expressamente permitido é proibido. Uma lista branca para o servidor da escola teria o seguinte aspeto:

:::quiz table
| N.º | Sentido | Protocolo | Porta de destino | Ação |
|---|---|---|---|---|
| 1 | A → B | TCP | {80} | {Permitir} |
| 2 | A → B | TCP | {25} | Permitir |
| 3 | A → B | qualquer | qualquer | {Descartar} |
:::

:::evaluate
Verificar tabela
:::

:::quiz mc
O que acontece se se mover a regra 3 para o topo?
- [ ] Nada, a ordem é indiferente
- [x] Da Internet já não passa absolutamente nada, nem web nem correio eletrónico
- [ ] Passam apenas web e correio eletrónico
:::

:::evaluate
Verificar resposta
:::

:::tip Ponto-chave
Como a **primeira regra que corresponde** é a que prevalece, as **regras específicas devem ficar em cima** e as gerais em baixo. Mais seguro do que uma **lista negra** (tudo permitido exceto …) é uma **lista branca** (tudo proibido exceto …, *Default Deny*): os serviços esquecidos ou novos ficam, assim, automaticamente bloqueados.
:::
