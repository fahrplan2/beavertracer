# Certificados: a quem pertence esta chave?

Com a cifragem assimétrica e as assinaturas, parece que está tudo resolvido: o servidor web do teu banco envia-te a chave pública dele e pronto. Mas como sabes que essa chave pública **pertence mesmo ao banco**?

Um atacante que desvie a tua ligação poderia simplesmente enviar-te a **sua própria** chave pública e afirmar que é o banco. O teu navegador cifraria então, obedientemente, com a chave do atacante — e este lê tudo. Um atacante assim, colocado a meio do caminho, chama-se **Man-in-the-Middle**.

## O certificado: um documento de identificação para chaves

Na vida real, mostras o teu **cartão de cidadão** para provar quem és. Acredita-se no documento porque foi emitido por uma **entidade de confiança** — os serviços públicos — e porque é difícil de falsificar.

Na rede, quem assume essa função é um **certificado**. Contém, entre outros, os seguintes campos:

| Campo | Significado | no cartão de cidadão |
|---|---|---|
| **Assunto** (*Subject*, muitas vezes `CN=…`) | Para quem é o certificado? Nos servidores web: o nome, p. ex. `CN=www.biberbank.de` | Nome do titular |
| **Chave pública** | A chave do titular | Fotografia |
| **Emissor** (*Issuer*) | Quem emitiu o certificado? | entidade emissora |
| **Validade** | de … a … | válido até |
| **Assinatura** do emissor | Prova que o emissor emitiu mesmo o certificado com este conteúdo | Selo, holograma |

`CN` significa *Common Name*.

A entidade que emite certificados chama-se **autoridade de certificação** (*Certificate Authority*, abreviado **CA**). Antes de assinar um certificado para `www.biberbank.de`, verifica se o requerente é realmente o proprietário desse domínio.

## Em quem confia o navegador?

Para cada certificado, o teu navegador verifica:

1. A **assinatura** da CA é autêntica? (Para isso, precisa da chave pública da CA.)
2. O certificado ainda está **válido**?
3. O **nome** no certificado corresponde ao endereço acedido?

Mas como é que o navegador conhece a CA? Em cada sistema operativo e navegador está **pré-instalada** uma lista com cerca de 150 **CAs de raiz** (*Root-CAs*). Os certificados destas são **autoassinados** — confirmam-se a si próprios; confia-se neles porque vêm incluídos no software.

Muitas vezes, uma CA de raiz não assina diretamente, mas através de uma **CA intermédia**. Surge assim uma **cadeia de confiança**:

```
Root-CA (vorinstalliert, vertraut)
  └─ signiert → Zwischen-CA
                  └─ signiert → www.biberbank.de
```

O navegador segue a cadeia de baixo para cima, até chegar a uma CA de raiz em que confia. Se isso não funcionar — ou se a validade ou o nome não estiverem corretos —, mostra um **aviso**.

:::quiz match
Assunto (CN) -> Para que nome o certificado é válido
Emissor -> Que CA assinou o certificado
Chave pública -> É necessária para verificar as assinaturas do servidor
CA de raiz -> Está pré-instalada no navegador e forma o início da cadeia de confiança
:::

:::tip Ponto-chave
Um **certificado** confirma que uma **chave pública** pertence a um determinado **nome**. É assinado por uma **autoridade de certificação (CA)**. O navegador confia num certificado se, através de uma **cadeia de confiança**, chegar a uma **CA de raiz** pré-instalada, se o certificado estiver **válido** e se o **nome** corresponder ao endereço.
:::
