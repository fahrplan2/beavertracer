# Deteção e resolução de problemas: o nome não funciona

:::sim
url=/sims/lesson-6.2.3.btsim
:::

Uma professora comunica: «O `www.beaver-schule.de` não carrega no meu computador. Mas com `http://192.168.0.20` funciona!» Assim é que a rede *deve* estar configurada:

| O quê | Valor esperado |
|---|---|
| Servidor DNS no Client-PC | `192.168.0.53` (DNS-Resolver) |
| Entrada no Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Encontra os erros e corrige-os.

<details>
<summary>Dica 1: O que diz o nslookup?</summary>

Introduz `nslookup www.beaver-schule.de` no Client-PC. Que servidor é que o `nslookup` consultou — e o que foi devolvido? (A resposta demora alguns segundos.)
</details>

<details>
<summary>Dica 2: E agora?</summary>

Se obtiveres uma resposta, compara o endereço com o esquema. Onde está registado este nome?
</details>

:::task
title: Resolução de nomes reparada?
Verifica se o Client-PC resolve www.beaver-schule.de para o endereço correto. Para isso, a simulação tem de estar a decorrer no modo de execução.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## O que se passava?

:::quiz multi
Que afirmações estão corretas?
- [x] No Client-PC estava configurado `192.168.0.35` como servidor DNS — lá ninguém responde
- [x] No Schul-DNS, `www.beaver-schule.de` apontava para `192.168.0.21` em vez de `192.168.0.20`
- [ ] O servidor web estava desligado
- [ ] O servidor raiz não conhecia o domínio `.de`
:::

:::evaluate
Verificar resposta
:::

:::tip Ponto-chave
Se uma ligação funciona com o **endereço IP**, mas não com o **nome**, o problema está no **DNS**. Verifica primeiro o **servidor DNS configurado** (será que responde?) e depois a **entrada** em si (o endereço está certo?). O `nslookup` mostra ambos: que servidor foi consultado e o que respondeu.
:::
