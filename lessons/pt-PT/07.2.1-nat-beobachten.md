## A experiência

1. Muda para o modo de execução :fa-play: **Executar**, clica no **PC** e abre `http://www.beispiel.de/` no :fa-globe: **Navegador**.
2. No modo :fa-magnifying-glass: **Rastreamento**, abre um trace para o **PC** e um segundo para o servidor web **www.beispiel.de**.
3. Compara nos dois traces o pacote `GET / HTTP/1.1`: quem aparece como remetente (**origem**)?

## O que está por trás

Em cada pacote que segue para a Internet, o router doméstico substitui o endereço de origem privado pelo seu próprio **endereço WAN público** — e, na maioria dos casos, também a porta de origem. Para o servidor web, parece que o pedido veio do router doméstico. Quando a resposta volta, o router doméstico volta a trocar o endereço e encaminha o pacote para o PC.

Assim, toda a rede doméstica consegue aceder à Internet com um único endereço público — e os dispositivos na Internet nunca veem os endereços privados.

## O caminho até à Internet

No **PC**, introduz no :fa-terminal: **Terminal**:

```
$ traceroute 192.0.2.80
```

:::quiz short
Quantos routers existem entre o PC e o servidor web? (Conta todas as linhas antes da última.)
= 4
= quatro
:::

:::quiz mc
Que endereço mostra o `traceroute` para o primeiro router?
- [x] `192.168.178.1` — o endereço LAN do router doméstico
- [ ] `203.0.113.2` — o seu endereço WAN
- [ ] `203.0.113.1` — o primeiro router do fornecedor
:::

Verificar respostas
:::

:::tip Ponto-chave
O **NAT** (*Network Address Translation*) substitui, no caminho para a Internet, o endereço de origem **privado** de um dispositivo pelo **endereço WAN público** do router — e, nas respostas, faz o inverso. Assim, todos os dispositivos da rede doméstica partilham **um** endereço IPv4 público. Isto poupa endereços e esconde os endereços privados da Internet.
:::
