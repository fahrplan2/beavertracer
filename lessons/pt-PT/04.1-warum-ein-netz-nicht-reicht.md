# Porque é que uma rede não chega

:::sim
url=/sims/lesson-4.1.btsim
:::

Na área de trabalho vês duas pequenas redes de empresas: a **Firma A** com a Anna (`192.168.0.10`) e o Ben (`192.168.0.11`), a **Firma B** com a Clara (`172.16.0.10`) e o David (`172.16.0.11`). Os dois switches estão até ligados diretamente por um cabo.

## Um ping na própria rede

1. Muda para o modo de execução :fa-play: **Executar**, abre o :fa-terminal: **Terminal** no **Anna** e faz ping ao Ben:
   ```
   $ ping 192.168.0.11
   ```
2. Muda para o modo :fa-magnifying-glass: **Rastreamento**, abre um rastreio para a **Anna** e clica num `Echo (ping) request`.
3. Na árvore de protocolos, abre a linha **Internet Protocol Version 4**. Esta é a parte IP do pacote — a parte de que trata este capítulo.

:::quiz match
Source Address -> Endereço IP do remetente
Destination Address -> Endereço IP do destinatário
Time to Live -> Quantos routers o pacote ainda pode atravessar
Protocol -> Que protocolo vai dentro do pacote (aqui ICMP, ou seja, o ping)
:::

Verificar associação

## Um ping para a outra rede

Volta ao modo de execução :fa-play: **Executar** e, a partir da **Anna**, faz ping à Clara (`ping 172.16.0.10`). Depois, olha novamente para o rastreio da Anna.

:::quiz mc
O que acontece?
- [ ] O ping funciona — afinal, os switches estão ligados
- [x] Nenhum ping chega ao destino e, no rastreio da Anna, não aparece um único pacote para a Clara — nem sequer um pedido ARP
- [ ] A Anna envia um pedido ARP, mas a Clara não responde
:::

:::quiz mc
Porque é que a Anna não envia absolutamente nada?
- [ ] O cabo entre os switches está avariado
- [ ] A Clara está desligada
- [x] A Anna percebe, pelo endereço IP da Clara, que a Clara está noutra rede — e não conhece nenhum caminho até lá
:::

## O que está por trás

Um endereço IP funciona de forma semelhante a uma morada postal: uma parte indica em que **rede** se encontra um dispositivo (como a rua), a outra parte indica qual é o **dispositivo** dentro dessa rede (como o número da porta). A Anna está na rede `192.168.0…`, a Clara na rede `172.16.0…` — duas «ruas» diferentes.

Para dispositivos na *própria* rede, um PC envia os pacotes diretamente (através de ARP e do switch, como já conheces). Para uma rede *estranha*, precisa de um dispositivo que ligue as redes entre si e reencaminhe os pacotes: um **router**. Aqui ainda não existe nenhum — por isso, também o cabo entre os switches não ajuda.

:::tip Ponto-chave
O **Internet Protocol** (**IP**) na camada 3 garante que os pacotes chegam ao destino mesmo entre redes diferentes. Um **endereço IP** é composto por uma **parte de rede** (em que rede?) e uma **parte de anfitrião** (que dispositivo?). Os dispositivos na mesma rede alcançam-se diretamente — para outras redes é necessário um **router**.
:::
