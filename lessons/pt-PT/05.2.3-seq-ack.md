# Números de sequência e de confirmação

:::sim
url=/sims/lesson-5.1.btsim
:::

Como sabe o TCP se tudo chegou — e por que ordem? Cada lado **numera os bytes** que envia:

- O **número de sequência** (`SEQ`) é o número do primeiro byte que vai neste pacote.
- O **número de confirmação** (`ACK`) diz: «Recebi tudo até aqui — a seguir espero o byte n.º …»

Acrescentam-se duas regras: `SYN` e `FIN` contam como um byte, apesar de não transportarem dados. E cada lado conta por si — por isso existem dois intervalos de numeração, no diagrama a vermelho (cliente) e a azul (servidor).

## Fazer as contas

Aqui está mais uma vez a tua ligação. Os números nas linhas mostram o contador do computador nesse ponto:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Percorre a sequência de números vermelhos:

1. O cliente começa em `SEQ=0`. O seu `SYN` consome um número — o servidor confirma com `ACK=1`.
2. A mensagem começa em `SEQ=1` e tem 13 bytes de comprimento (bytes 1 a 13). O servidor confirma com `ACK=14`: «A seguir espero o byte 14.»
3. O `FIN` do cliente tem, por isso, `SEQ=14` e é confirmado com `ACK=15`.

A sequência azul do servidor funciona exatamente da mesma forma.

:::tip Ponto-chave
O **número de sequência** (`SEQ`) é o número do primeiro byte do pacote. O **número de confirmação** (`ACK`) é o número do próximo byte que o destinatário espera — tudo o que vem antes chegou. Aplica-se: **ACK = SEQ + comprimento** dos dados recebidos; `SYN` e `FIN` contam como um byte. Cada lado conta os seus próprios bytes.
:::

:::tip Experimenta
Monta novamente a ligação no **Cliente TCP Simples** e envia duas mensagens seguidas. Antes disso, diz quais serão os valores de `Seq` e `Ack` na coluna **Info** — e confirma-o no rastreio.
:::

## Praticar

:::quiz short
O cliente envia um pacote com `Seq=1` e `Len=13`. Que número de confirmação devolve o servidor?
= 14
:::

:::quiz short
Depois disso, o cliente envia a mensagem seguinte. Com que número de sequência começa?
= 14
:::

:::quiz short

= 65
:::

:::note
Nas redes reais, a contagem não começa em 0: cada lado escolhe um **número inicial aleatório** (*Initial Sequence Number*, ISN) entre 0 e cerca de 4,3 mil milhões. Quando se atinge o número mais alto, a contagem recomeça em 0. O Tracer subtrai o número inicial e mostra números **relativos** — tal como o Wireshark. Por isso vês `Seq=0` e `Seq=1`.

Além disso, cada pacote contém `Win=` — o **tamanho da janela**: é este o número de bytes que o destinatário consegue receber naquele momento. Assim, ele trava um remetente demasiado rápido (*controlo de fluxo*). No BeaverTracer, a janela tem sempre o mesmo tamanho.
:::
