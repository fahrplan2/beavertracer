# O que tem de fazer a camada de transporte?

:::sim
url=/sims/lesson-5.1.btsim
:::

No **Server** correm dois serviços em simultâneo: um **servidor web** e um pequeno **serviço de eco**, que devolve imediatamente todas as mensagens que recebe. Com duas experiências vais descobrir o que o IP, por si só, não consegue fazer.

## Experiência 1: dois programas em simultâneo

1. Muda para o modo de execução :fa-play: **Executar** e clica no **Client-PC**.
2. Abre o :fa-globe: **Navegador** e acede a `http://192.168.0.20/`.
3. Clica em **Zurück** na parte superior da janela e abre o **Cliente TCP Simples**. Em **Host** introduz `192.168.0.20` e em **Port** introduz `5000` e clica em **Ligar**.
4. Muda para o modo :fa-magnifying-glass: **Rastreamento** e, com **+**, abre um trace para o **Client-PC**, porta `eth0`.

Clica num pacote do navegador (p. ex. `GET /`) e num do cliente TCP e expande, em cada um, **Internet Protocol Version 4**.

:::quiz mc
Que endereços IP têm os pacotes do navegador e do cliente TCP?
- [x] Em ambos os mesmos: de `192.168.0.10` para `192.168.0.20`
- [ ] O navegador usa um endereço IP de destino diferente do cliente TCP
- [ ] Os pacotes do cliente TCP não têm endereço IP
:::

:::quiz mc
Então, o endereço IP de destino é suficiente para o servidor saber se um pacote pertence ao servidor web ou ao serviço de eco?
- [ ] Sim
- [x] Não — ambos os pacotes têm o mesmo endereço IP de destino
:::

Algo mais tem de distinguir as duas ligações. Vê a coluna **Info** dos pacotes com `[SYN]` — este é, em cada caso, o primeiro pacote de uma ligação:

:::quiz short
Que número aparece depois da seta `→` no **navegador**?
= 80
:::

:::quiz short
E no **cliente TCP**?
= 5000
:::

:::evaluate
Verificar respostas
:::

Vais saber mais sobre estes números — os **portos** — na secção 5.3. Para já, basta saberes isto: só a camada de transporte permite que vários programas comuniquem em simultâneo através de *um* único endereço IP e que cada pacote vá parar ao programa certo. A isto chama-se **multiplexagem**.

## Experiência 2: quando se perde um pacote

1. Muda para o modo de execução :fa-play: **Executar** e clica no **cabo** entre o Client-PC e o Server.
2. Na janela **Verbindung**, define a **Konfigurierter Paketverlust** como `25%`.
3. No **Client-PC**, abre o :fa-terminal: **Terminal** e envia seis pings:
   ```
   $ ping -c 6 192.168.0.20
   ```
   Isto demora cerca de meio minuto — espera até aparecerem as estatísticas.

:::quiz mc
O que acontece?
- [ ] Os seis pings são todos respondidos
- [x] Alguns pings ficam sem resposta — e ninguém os volta a enviar
- [ ] Os pings perdidos são repetidos automaticamente até chegarem
:::

:::evaluate
Verificar resposta
:::

Num ping isso não é problema — a sua função é precisamente mostrar se algo se perde. Mas numa página web, num e-mail ou numa transferência, a falta de um bocado seria fatal: o ficheiro ficaria danificado.

## As quatro tarefas da camada de transporte

| Tarefa | O que significa |
|---|---|
| **Multiplexagem** | Vários programas e ligações partilham um endereço IP; cada pacote chega ao programa certo. |
| **Estabelecimento de ligação** | Antes de os dados circularem, ambos os lados combinam que vão comunicar entre si. |
| **Transmissão fiável** | O destinatário confirma o que chegou. O que falta é reenviado e a ordem é reposta. |
| **Terminação da ligação** | No fim, ambos os lados terminam a ligação de forma ordenada. |

:::tip Ponto-chave
A **camada de transporte** (camada 4) assegura que os dados chegam ao **programa** certo (**multiplexagem**). O protocolo **TCP** assegura ainda que chegam **completos** e na **ordem correta** — com estabelecimento de ligação, confirmações, retransmissão e terminação da ligação.
:::

:::quiz match
Num PC correm em simultâneo um navegador, um programa de e-mail e um programa de mensagens. -> Multiplexagem
Antes de os dados circularem, ambos os lados verificam que o outro está pronto. -> Estabelecimento de ligação
Uma parte de um ficheiro não chega e é enviada outra vez. -> Transmissão fiável
Após a transferência, ambos os lados libertam a ligação. -> Terminação da ligação
:::
