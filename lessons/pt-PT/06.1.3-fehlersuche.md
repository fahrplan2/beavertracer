# Deteção e resolução de problemas: a página de contacto está em falta

:::sim
url=/sims/lesson-6.1.3.btsim
:::

A secretaria comunica: «No nosso site, a ligação **Kontakt** só leva a uma mensagem de erro.» A página de contacto deve estar acessível em `http://192.168.0.20/kontakt.html`. Encontra o erro e corrige-o.

<details>
<summary>Dica 1: O que comunica o servidor?</summary>

Abre a página de contacto no navegador ou com `curl -v`. Que código de estado é devolvido? A página de erro também revela onde o servidor procurou o ficheiro.
</details>

<details>
<summary>Dica 2: Onde estão os ficheiros?</summary>

O servidor web só fornece ficheiros do seu **Diretório de Documentos** (*Document Root*) — isto aparece na aplicação **Servidor HTTP**. No **Server**, vê no terminal, com `ls`, o que lá está e procura também a página de contacto em `/home`.
</details>

<details>
<summary>Dica 3: Mover o ficheiro</summary>

Com `mv` moves um ficheiro: `mv <origem> <pasta de destino>`.
</details>

:::task
title: Página de contacto reparada?
Verifica se a página de contacto está no diretório de documentos do servidor web.
check: fileExists(2, "/var/www/kontakt.html")
:::

## O que se passou?

:::quiz multi
Que afirmações estão corretas?
- [x] O servidor respondeu com `404 Not Found`
- [x] O ficheiro estava em `/home` em vez de estar no diretório de documentos `/var/www`
- [ ] O servidor web nem sequer estava iniciado
- [ ] O navegador usou o endereço IP errado
:::

:::evaluate
Verificar resposta
:::

:::tip Ponto-chave
Um **404** significa: o servidor web está em funcionamento e acessível, mas o **ficheiro** pedido não existe nesse caminho. O servidor só procura no seu **Diretório de Documentos** (*Document Root*, aqui `/var/www`). Compara: se o servidor não responder de todo ou responder com `RST`, o problema está mais abaixo — na rede ou no próprio serviço (capítulo 5.3.2).
:::
