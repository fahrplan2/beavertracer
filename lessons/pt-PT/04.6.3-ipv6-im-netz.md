# IPv6 na rede

:::sim
url=/sims/lesson-4.6.3.btsim
:::

Ao switch estão ligados a Anna, o Ben e um router. Na Anna e no Ben, o IPv6 está configurado para **SLAAC (automático)** — ninguém lhes atribuiu manualmente um endereço IPv6. O router conhece o prefixo `2001:db8:1::/64`.

## De onde vem o endereço?

1. Muda para o modo de execução :fa-play: **Executar** e aguarda alguns segundos.
2. Abre o :fa-terminal: **Terminal** na **Anna** e escreve `ip a`.

Além do endereço IPv4, vês duas linhas com `inet6`: um endereço com `scope link` e outro com `scope global`.

:::quiz mc
Qual dos dois endereços IPv6 é o endereço link-local?
- [x] O que começa por `fe80::` (`scope link`)
- [ ] O que começa por `2001:db8:1:` (`scope global`)
:::

:::quiz mc
De onde vem o prefixo `2001:db8:1:0` do endereço global?
- [ ] A Anna inventou-o ela própria
- [x] Do router — ele anuncia o prefixo na rede
- [ ] Do switch
:::

:::evaluate
Verificar respostas
:::

Compara o **Interface ID** (os últimos quatro blocos) com o **endereço MAC** da Anna — encontras o endereço MAC nas :fa-gear: **Definições de IP**, bem em baixo. Do endereço MAC `aa:28:39:e2:41:82` resulta, por exemplo, o Interface ID `a828:39ff:fee2:4182`: no meio é inserido `ff:fe` e um bit no início é invertido (por isso `aa` passa a `a8`).

Este procedimento chama-se **SLAAC** (*Stateless Address Autoconfiguration*): o router anuncia o prefixo, e cada dispositivo forma ele próprio o Interface ID.

:::note
Como o endereço MAC identifica um dispositivo de forma inequívoca, seria possível reconhecê-lo em qualquer ponto da Internet através do Interface ID. Por isso, os dispositivos reais costumam usar também Interface IDs aleatórios, que mudam regularmente (*Privacy Extensions*) — um pouco de proteção de dados.
:::

## Encontrar vizinhos — sem ARP

1. No **Ben**, escreve `ip a` e anota o endereço IPv6 **global** dele.
2. A partir da **Anna**, faz ping a esse endereço, por exemplo `ping 2001:db8:1:0:…` (com o endereço completo do Ben).
3. Muda para o modo :fa-magnifying-glass: **Rastreamento** e abre um rastreio para a **Anna**.

Observa os pacotes imediatamente antes do primeiro `Echo (ping) request`.

:::quiz multi
Quais das afirmações são verdadeiras?
- [x] Em vez de um pedido ARP, a Anna envia uma **Neighbor Solicitation** («Quem tem este endereço?»)
- [x] O Ben responde com uma **Neighbor Advertisement** e indica o seu endereço MAC
- [x] O pedido é enviado para um endereço multicast (`ff02::1:ff…`), e não para todos por broadcast
- [ ] A Anna envia um pedido ARP como no IPv4
- [x] O router envia regularmente **Router Advertisements** para `ff02::1` — nelas consta o prefixo
:::

:::evaluate
Verificar respostas
:::

:::tip Ponto-chave
No IPv6, o **NDP** (*Neighbor Discovery Protocol*, parte do ICMPv6) assume as tarefas do ARP: com **Neighbor Solicitation** e **Neighbor Advertisement**, os dispositivos descobrem os endereços MAC dos seus vizinhos. Com **Router Advertisements**, o router anuncia o prefixo — a partir dele, os dispositivos formam o seu próprio endereço através do **SLAAC**.
:::
