# TCP ou UDP?

| | TCP | UDP |
|---|---|---|
| Ligação | estabelecimento com handshake de três vias, encerramento ordenado | nenhuma — cada datagrama é independente |
| Confirmações | sim (`ACK`) | não |
| Dados perdidos | são reenviados | perdem-se |
| Ordem | é restabelecida | não é garantida |
| Cabeçalho | no mínimo 20 bytes | 8 bytes |
| Velocidade | um pouco mais lento, mais pacotes | rápido, pouca sobrecarga |

Quando é que menos é mais?

- **Tempo real:** Em videochamadas, telefonia pela Internet ou jogos online, cada milissegundo conta. Um pedaço de áudio perdido que é entregue um segundo depois já não serve a ninguém — mais vale um pequeno estalido do que um atraso.
- **Pedidos curtos:** Um pedido **DNS** («Que endereço IP tem `www.beispiel.de`?») cabe num único datagrama, e a resposta também. Um estabelecimento de ligação triplicaria o esforço. Se não chegar nenhuma resposta, o programa limita-se a perguntar de novo.

Em todos os casos em que cada byte tem de chegar ao destino — páginas web, e-mails, transferências —, o TCP é, pelo contrário, a escolha certa.

:::tip Ponto-chave
O **TCP** é fiável, mas mais dispendioso — para tudo o que tem de chegar **por completo** (web, e-mail, ficheiros). O **UDP** é rápido e leve, mas sem garantias — para **tempo real** (telefonia, vídeo, jogos) e **pedidos curtos** como o DNS.
:::
