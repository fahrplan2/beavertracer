# Sekvensdiagrammet

:::sim
url=/sims/lesson-5.1.btsim
:::

Forløpet av en forbindelse tegner man som et **sekvensdiagram**: Klient og server får hver sin loddrette linje, og tiden går fra topp til bunn. Hver pil er én pakke. Den er tegnet på skrå fordi hver pakke bruker litt tid underveis.

Slik ser forbindelsen din fra forrige side ut — sammenlign den linje for linje med sporingen:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Over hver pil står **flaggene**, under dem tallene `SEQ` og `ACK`. **DATA** markerer pakker med nyttelast. De røde tallene hører til klienten, de blå til serveren — hva de betyr, forklares på neste side.

## Flaggene

| Flagg | står for | Betydning |
|---|---|---|
| **SYN** | *synchronize* | Opprette forbindelse, fastsette startnummer |
| **ACK** | *acknowledge* | bekrefter mottatte data |
| **PSH** | *push* | Gi dataene umiddelbart videre til programmet |
| **FIN** | *finish* | «Jeg er ferdig» — avslutte forbindelsen |
| **RST** | *reset* | Avbryte eller avvise forbindelse (mer om dette i 5.3.2) |

## Tre faser

**Oppkobling:** Klienten sender `SYN`, serveren svarer med `SYN, ACK`, og klienten bekrefter med `ACK`. Fordi det trengs nøyaktig tre pakker, kalles dette **treveis håndtrykk**.

**Data:** Hver pakke med data bekreftes av mottakeren med en `ACK`. Her sender serveren ekkoet tilbake — også dette bekrefter klienten.

**Nedkobling:** Hver side avslutter sin egen senderetning for seg: `FIN` fra klienten, `ACK` fra serveren — deretter `FIN` fra serveren, `ACK` fra klienten. Det er fire pakker.

:::tip Husk dette
En TCP-forbindelse går gjennom tre faser: **oppkobling** med **treveis håndtrykk** (`SYN` → `SYN, ACK` → `ACK`), **dataoverføring** (hver datapakke bekreftes med `ACK`) og **nedkobling** (hver side sender `FIN` og får en `ACK`).
:::
