# Sekvens- og bekreftelsesnumre

:::sim
url=/sims/lesson-5.1.btsim
:::

Hvordan vet TCP om alt har kommet fram — og i hvilken rekkefølge? Hver side **nummererer bytene** den sender:

- **Sekvensnummeret** (`SEQ`) er nummeret på den første byten i denne pakken.
- **Bekreftelsesnummeret** (`ACK`) sier: «Jeg har fått alt fram til hit — neste byte jeg forventer, er nr. …»

Dessuten gjelder to regler: `SYN` og `FIN` teller som én byte, selv om de ikke bærer data. Og hver side teller for seg — derfor finnes det to nummerrekker, rød (klient) og blå (server) i diagrammet.

## Regn etter

Her ser du forbindelsen din en gang til. Tallene på linjene viser telleren til maskinen på det punktet:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Gå gjennom den røde tallrekken:

1. Klienten begynner på `SEQ=0`. `SYN` bruker opp ett nummer — serveren bekrefter med `ACK=1`.
2. Meldingen begynner på `SEQ=1` og er 13 byte lang (byte 1 til 13). Serveren bekrefter med `ACK=14`: «Neste byte jeg forventer, er byte 14.»
3. Klientens `FIN` har derfor `SEQ=14` og bekreftes med `ACK=15`.

Serverens blå rekke fungerer på akkurat samme måte.

:::tip Husk dette
**Sekvensnummeret** (`SEQ`) er nummeret på den første byten i pakken. **Bekreftelsesnummeret** (`ACK`) er nummeret på den neste byten mottakeren forventer — alt før dette har kommet fram. Det gjelder: **ACK = SEQ + lengden** på de mottatte dataene; `SYN` og `FIN` teller som én byte. Hver side teller sine egne byte.
:::

:::tip Prøv selv
Bygg opp forbindelsen i **Enkel TCP-klient** en gang til, og send to meldinger etter hverandre. Si på forhånd hvilke `Seq` og `Ack` som kommer til å stå i **Info**-kolonnen — og kontroller det i sporingen.
:::

:::note
I virkelige nettverk begynner ikke tellingen på 0: Hver side velger et **tilfeldig startnummer** (*Initial Sequence Number*, ISN) mellom 0 og rundt 4,3 milliarder. Når det høyeste nummeret er nådd, starter tellingen på 0 igjen. Tracer trekker fra startnummeret og viser **relative** numre — akkurat som Wireshark. Derfor ser du `Seq=0` og `Seq=1`.

I tillegg står det `Win=` i hver pakke — **vindusstørrelsen**: Så mange byte kan mottakeren ta imot akkurat nå. Slik bremser den en avsender som sender for raskt (*flytkontroll*). I BeaverTracer er vinduet alltid like stort.
:::
