# HTTPS

:::osi 5
:::

**HTTPS** (*HTTP Secure*) er helt vanlig HTTP — bortsett fra at det ikke går direkte over TCP, men gjennom et kryptert lag imellom: **TLS** (*Transport Layer Security*). Forgjengeren til TLS het **SSL**; derfor snakker man ofte fortsatt om «SSL-sertifikater».

```
ohne Verschlüsselung:   HTTP  →  TCP  →  IP
mit Verschlüsselung:    HTTP  →  TLS  →  TCP  →  IP
```

HTTP merker ingenting av dette: Det sender forespørslene sine som vanlig, TLS krypterer dem, og TCP transporterer dem. I OSI-modellen ligger TLS mellom transportlaget og applikasjonslaget, altså i lag 4/5 — det bygger på TCP og administrerer en sikret økt.

| | HTTP | HTTPS |
|---|---|---|
| Port | 80 | **443** |
| Adresse | `http://…` | `https://…` |
| Innhold lesbart i Tracer? | ja | nei |
| Nettleseren viser | «ikke sikker» | lås |

Under oppkoblingen ordner TLS alt det du har lært i dette kapittelet:

- Serveren legitimerer seg med **sertifikatet** sitt (**autentisitet**).
- Begge sider forhandler seg fram til en **øktnøkkel** med **Diffie-Hellman** — serveren **signerer** sin del.
- Deretter krypteres alle data med **AES** (**konfidensialitet**) og sikres mot endring (**integritet**).

Prinsippet er ikke begrenset til nettet: Også e-post (avsnitt 8.4) og mange andre protokoller går gjennom TLS på samme måte.

I de følgende avsnittene observerer du HTTPS i Tracer, setter det opp selv og undersøker når nettleseren advarer — og hvorfor.
