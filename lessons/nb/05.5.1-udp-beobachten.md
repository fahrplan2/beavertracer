# Observere UDP

:::sim
url=/sims/lesson-5.5.btsim
:::

På **Server** kjører det denne gangen en **UDP Echo-Server** på port `5000`. Også her er kabelen preparert: Det **andre datagrammet** fra Client-PC til Server går tapt.

## Eksperimentet

1. Bytt til :fa-play: **Kjør**-modus og åpne :fa-terminal: **Terminal** på **Client-PC**.
2. Start en UDP-«forbindelse» til serveren med `nc` (`-u` står for UDP):
   ```
   $ nc -u 192.168.0.20 5000
   ```
3. Skriv `eins`, `zwei` og `drei` etter hverandre, og trykk **Enter** hver gang. Hver linje som kommer tilbake, er et ekko fra serveren.
4. Vent noen sekunder, og åpne deretter en trace for **Client-PC** i :fa-magnifying-glass: **Sporing**-modus.

:::quiz mc
Hvilke ekko kommer tilbake?
- [ ] Alle tre, `zwei` litt senere
- [x] Bare `eins` og `drei` — `zwei` mangler og blir heller ikke sendt på nytt
- [ ] Ingen av dem
:::

:::quiz multi
Hvilke pakker du kjenner fra TCP, mangler helt ved UDP?
- [x] Oppkobling (`SYN`)
- [x] Bekreftelser (`ACK`)
- [x] Nedkobling (`FIN`)
- [ ] Pakker med portnumre
:::

:::evaluate
Kontroller svar
:::

Klikk på en av UDP-pakkene og åpne **User Datagram Protocol**. Sammenlignet med TCP-headeren er UDP-headeren liten: **Source Port**, **Destination Port**, **Length** (lengde) og **Checksum** (sjekksum) — til sammen bare 8 byte. En TCP-header er på minst 20 byte, med sekvensnummer og bekreftelsesnummer, flagg og vindusstørrelse.

:::quiz mc
Hvilken oppgave fra avsnitt 5.1 utfører UDP likevel?
- [x] Multipleksing — via portene
- [ ] Oppkobling
- [ ] Pålitelig overføring
:::

:::evaluate
Kontroller svar
:::

:::tip Husk dette
**UDP** er **forbindelsesløst**: ingen oppkobling, ingen bekreftelse, ingen retransmisjon, ingen rekkefølge. Det tilbyr bare **porter** (multipleksing) og en **sjekksum**. Til gjengjeld er det raskt og slankt — UDP-headeren er bare 8 byte. Hvis et datagram går tapt, må programmet selv ta seg av det — eller så bryr det seg ikke.
:::
