# Feilsøking: Tjenesten svarer ikke

:::sim
url=/sims/lesson-5.3.2.btsim
:::

Etter en oppdatering melder skolen: «Echo-tjenesten avviser alle tilkoblinger, og nettsiden lastes heller ikke lenger.» Ifølge planen skal **webserveren** lytte på port `80` og **echo-tjenesten** (TCP Echo-server) på port `5000`. Finn feilene og rett dem.

<details>
<summary>Tips 1: Hva svarer serveren?</summary>

Prøv å koble til `192.168.0.20`, port `5000` med **Enkel TCP-klient**, og åpne en trace for klient-PC-en. Hva svarer serveren på din `[SYN]`?
</details>

<details>
<summary>Tips 2: Hvilke porter er åpne?</summary>

Skriv `nmap -p 80,5000 192.168.0.20` i terminalen på klient-PC-en. `nmap` prøver portene én etter én og viser hvilke som er åpne. Med `ss` på serveren ser du på hvilke porter et program faktisk lytter der.
</details>

<details>
<summary>Tips 3: Hvor stiller man dette inn?</summary>

Åpne appene **TCP Echo-server** og **HTTP-server** på **serveren**. Kjører tjenesten? Og på hvilken port?
</details>

:::task
title: Er tjenestene tilgjengelige?
Kontroller om klient-PC-en når echo-tjenesten på port 5000 og webserveren på port 80. Simuleringen må kjøre i Kjør-modus for dette.
check: tcpOpen(1, 2, 5000)
check: tcpOpen(1, 2, 80)
:::

## Hva var galt?

:::quiz multi
Hvilke utsagn stemmer?
- [x] På `[SYN]` til port 5000 svarte serveren med `[RST, ACK]`
- [x] Echo-tjenesten lyttet på port 5050 i stedet for port 5000
- [x] Webserveren var ikke startet i det hele tatt
- [ ] Kabelen mellom klient-PC-en og serveren var defekt
:::

:::evaluate
Kontroller svar
:::

:::tip Husk dette
Hvis det kommer en **`RST`** tilbake på en `SYN`, lytter **ingen program** på den porten: Maskinen er tilgjengelig, men tjenesten er det ikke. Typiske årsaker: Tjenesten er **ikke startet** eller lytter på en **annen port**. Et blikk på serveren med `ss` viser hvilke porter som faktisk er åpne.
:::
