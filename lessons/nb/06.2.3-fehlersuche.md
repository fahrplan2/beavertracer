# Feilsøking: Navnet fungerer ikke

:::sim
url=/sims/lesson-6.2.3.btsim
:::

En lærer melder: «`www.beaver-schule.de` laster ikke hos meg. Med `http://192.168.0.20` fungerer det derimot!» Slik *skal* det være satt opp:

| Hva | Skal være |
|---|---|
| DNS-server på Client-PC | `192.168.0.53` (DNS-Resolver) |
| Oppføring i Schul-DNS | `www.beaver-schule.de` → `192.168.0.20` |

Finn feilene og rett dem.

<details>
<summary>Tips 1: Hva sier nslookup?</summary>

Skriv inn `nslookup www.beaver-schule.de` på Client-PC. Hvilken server spurte `nslookup` – og hva kom tilbake? (Svaret tar noen sekunder.)
</details>

<details>
<summary>Tips 2: Og nå?</summary>

Hvis du får svar, sammenligner du adressen med planen. Hvor er dette navnet registrert?
</details>

:::task
title: Er navneoppslaget reparert?
Kontrollerer om Client-PC løser opp www.beaver-schule.de til riktig adresse. Simuleringen må kjøre i Kjør-modus for dette.
check: resolves(2, "www.beaver-schule.de", "192.168.0.20")
:::

## Hva var galt?

:::quiz multi
Hvilke utsagn stemmer?
- [x] På Client-PC var `192.168.0.35` oppført som DNS-server – der svarer ingen
- [x] I Schul-DNS pekte `www.beaver-schule.de` på `192.168.0.21` i stedet for `192.168.0.20`
- [ ] Webserveren var slått av
- [ ] Root-serveren kjente ikke domenet `.de`
:::

:::evaluate
Kontroller svaret
:::

:::tip Husk dette
Fungerer en tilkobling med **IP-adressen**, men ikke med **navnet**, ligger problemet hos **DNS**. Kontroller først den **oppførte DNS-serveren** (svarer den i det hele tatt?), og deretter selve **oppføringen** (stemmer adressen?). `nslookup` viser begge deler: hvilken server som ble spurt, og hva den svarte.
:::
