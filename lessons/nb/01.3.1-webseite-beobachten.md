# Åpne og observere en nettside

I denne delen bygger du ingenting selv: På arbeidsområdet ligger en ferdig simulering med en **Client-PC** og en **Webserver**.

## Åpne siden

1. Bytt til :fa-play: **Kjør**-modus.
2. Åpne appen :fa-globe: **Nettleser** på **Client-PC** og gå til adressen til webserveren: `http://192.168.0.20/`.
3. Bytt til :fa-magnifying-glass: **Sporing**-modus og åpne en trace for **Client-PC** med **+**, port `eth0` — akkurat som ved ping.

:::note
For ett enkelt sideoppslag er dette overraskende mange pakker — betydelig flere enn ved ping. Å hente en nettside er en prosess i flere trinn, ikke én enkelt handling.
:::

## Lese pakkelisten

Du trenger ikke å vite nøyaktig hva de enkelte protokollene gjør ennå. Alt du trenger for de følgende spørsmålene, står i kolonnene **Protokoll** og **Info**.

:::quiz mc
Hvilken protokoll står øverst i listen?
- [x] ARP
- [ ] TCP
- [ ] HTTP
:::

:::quiz short
Tell: Hvor mange **TCP**-pakker står før den første **HTTP**-pakken?
= 3
= tre
:::

:::quiz mc
Hva svarer webserveren på forespørselen fra nettleseren? Se i Info-kolonnen til den andre HTTP-pakken.
- [ ] GET / HTTP/1.1
- [x] HTTP/1.1 200 OK
- [ ] 404 Not Found
:::

:::evaluate
Kontroller svar
:::

## Navngi protokollene som er med

Ut fra observasjonene dine kan du nå lese ut hvilken protokoll som var ansvarlig for hva.

:::tip Tips
Les gjennom **Info**-kolonnene en gang til: `Who has …?`, `[SYN]`, `[SYN, ACK]`, `[ACK]`, `GET /` og `200 OK` avslører nesten alt.
:::

:::quiz match
ARP -> Spør alle i nettverket: «Hvem har IP-adressen 192.168.0.20?»
TCP -> Bygger opp en forbindelse med tre korte pakker før data begynner å flyte
HTTP -> Ber om nettsiden (GET) og leverer den tilbake (200 OK)
:::

:::evaluate
Kontroller sammenstilling
:::

:::tip Husk dette
Et sideoppslag på nettet går i trinn: først **finne** serveren i nettverket (ARP), så **koble opp** en forbindelse (TCP), så **be om og levere** siden (HTTP) — og til slutt **avslutte** forbindelsen igjen (TCP-pakkene med `[FIN]` på slutten av listen).
:::

:::note
Denne gangen skrev du inn IP-adressen til serveren direkte, og derfor ble ikke **DNS** («oversettelsen» av navn som `www.beispiel.de` til en IP-adresse) brukt ennå. Det tar vi igjen i kapittel 6.
:::

La du merke til at protokollene i pakkestrukturen har fargede markeringer med tall? Hva det betyr, forklarer vi i kapittel 2. Der ser vi på hvordan man plasserer de mange protokollene systematisk — med OSI-modellen og TCP/IP-referansemodellen. Dermed er kapittel 1 ferdig.
