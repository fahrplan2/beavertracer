# Numri ta' sekwenza u ta' aknowledgement

:::sim
url=/sims/lesson-5.1.btsim
:::

Kif taf TCP jekk wasal kollox — u fi ordni? Kull naħa **tnumera l-bytes** li tibgħat:

- In-**numru ta' sekwenza** (`SEQ`) huwa n-numru tal-ewwel byte f'dan il-packet.
- In-**numru ta' acknowledgement** (`ACK`) jgħid: "Sa hawn irċevejt kollox — il-byte li nistenna wara huwa n-nru …"

Żewġ regoli oħra: `SYN` u `FIN` jgħoddu bħal byte, għalkemm ma jġorru l-ebda data. U kull naħa tgħodd għaliha nnifisha — għalhekk hemm żewġ serje ta' numri, ħamra (client) u blu (server) fid-dijagramma.

## Ikkalkula

Hawn mill-ġdid il-konnessjoni tiegħek. In-numri fuq il-linji juru l-counter tal-kompjuter f'dak il-punt:

:::seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK
Client-PC -> Server: ACK
Client-PC -> Server: PSH, ACK "Hello World" len=13
Server -> Client-PC: ACK
Server -> Client-PC: PSH, ACK len=13
Client-PC -> Server: ACK
Client-PC -> Server: FIN, ACK
Server -> Client-PC: ACK
Server -> Client-PC: FIN, ACK
Client-PC -> Server: ACK
:::

Għaddi mis-serje ħamra ta' numri:

1. Il-client jibda minn `SEQ=0`. Is-`SYN` tiegħu jikkonsma numru — is-server jikkonferma b'`ACK=1`.
2. Il-messaġġ jibda minn `SEQ=1` u huwa twil 13-il byte (bytes 1 sa 13). Is-server jikkonferma b'`ACK=14`: "Il-byte li nistenna wara huwa n-nru 14."
3. Għalhekk il-`FIN` tal-client għandu `SEQ=14` u jiġi kkonfermat b'`ACK=15`.

Is-serje blu tas-server taħdem eżattament bl-istess mod.

:::tip Punt importanti
In-**numru ta' sekwenza** (`SEQ`) huwa n-numru tal-ewwel byte fil-packet. In-**numru ta' acknowledgement** (`ACK`) huwa n-numru tal-byte li jmiss li r-receiver jistenna — dak kollu ta' qablu wasal. Japplika: **ACK = SEQ + tul** tad-data riċevuta; `SYN` u `FIN` jgħoddu bħal byte. Kull naħa tgħodd il-bytes tagħha stess.
:::

:::tip Ipprova
Ibni l-konnessjoni mill-ġdid fis-**Simple TCP Client** u ibgħat żewġ messaġġi wieħed wara l-ieħor. Qabel, għid liema `Seq` u `Ack` se jidhru fil-kolonna **Info** — u ċċekkja fit-traċċa.
:::

## Ipprattika

:::quiz short
Il-client jibgħat packet b'`Seq=1` u `Len=13`. Liema numru ta' acknowledgement jibgħat lura s-server?
= 14
:::

:::quiz short
Imbagħad il-client jibgħat il-messaġġ li jmiss tiegħu. B'liema numru ta' sekwenza jibda?
= 14
:::

:::quiz short
Packet b'`Seq=40` u `Len=25` jasal. Liema numru ta' acknowledgement jibgħat ir-receiver?
= 65
:::

:::evaluate
Iċċekkja t-tweġibiet
:::

Imla n-numri nieqsa. Il-client jibgħat `Hallo` u wara `Tschau` (kull wieħed b'tmiem ta' linja):

:::quiz seq
Client-PC -> Server: SYN
Server -> Client-PC: SYN, ACK ack=?
Client-PC -> Server: ACK seq=? ack=?
Client-PC -> Server: PSH, ACK "Hallo" len=7 seq=?
Server -> Client-PC: ACK ack=?
Client-PC -> Server: PSH, ACK "Tschau" len=8 seq=?
Server -> Client-PC: ACK ack=?
:::

:::evaluate
Iċċekkja d-dijagramma
:::

:::note
Fin-networks reali l-għadd ma jibdiex minn 0: kull naħa tagħżel **numru tal-bidu każwali** (*Initial Sequence Number*, ISN) bejn 0 u madwar 4.3 biljun. Meta jintlaħaq l-ogħla numru, l-għadd jerġa' jkompli minn 0. It-tracer inaqqas in-numru tal-bidu u juri numri **relattivi** — eżattament bħal Wireshark. Għalhekk tara `Seq=0` u `Seq=1`.

Barra minn hekk, f'kull packet hemm `Win=` — id-**daqs tal-window**: dan huwa l-għadd ta' bytes li r-receiver jista' jirċievi bħalissa. B'hekk il-receiver irażżan sender li jibgħat malajr wisq (*flow control*). F'BeaverTracer il-window dejjem ikollha l-istess daqs.
:::
